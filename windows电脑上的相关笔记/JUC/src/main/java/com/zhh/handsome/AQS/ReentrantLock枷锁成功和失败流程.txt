ReentrantLock的lock方法执行的大体流程是这样的

首先，ReentrantLock调用lock方法，本质上调用的是sync这个AbstractQueuedSynchronizer继承类中的lock方法，这个lock方法首先是sync抽象类特有的，其内部直接调用
AbstractQueuedSynchronizer的acquire方法，这个方法内会调用tryAcquire方法来尝试枷锁，而这个方法则必须由我们自己实现，所以sync的两个实现类中就分别重写了
这个方法供acquire方法直接调用

sync的两个实现类是NonfairSync和FairSync，分别对应ReentrantLock的默认非公平锁和公平锁，fair参数控制

NonfairSync和FairSync这两个类主要的不同就是在对tryAquire方法的重写逻辑上有较大的不一样。。。。



一、非公平锁（NonfairSync）加锁流程（默认，最常用）
非公平锁的核心特点是 “先插队抢锁，抢不到再排队”，以下是完整流程（对应源码逐行拆解）：
步骤 1：入口调用（ReentrantLock.lock ()）
java
运行
// ReentrantLock源码
public void lock() {
    sync.lock(); // 委托给NonfairSync的lock()方法
}
步骤 2：执行 NonfairSync.lock ()（核心插队逻辑）
java
运行
// NonfairSync源码
final void lock() {
    // 分支1：CAS尝试将state从0改为1（抢锁）
    if (compareAndSetState(0, 1))
        // 加锁成功：标记当前线程为独占锁持有者
        setExclusiveOwnerThread(Thread.currentThread());
    else
        // 分支2：CAS失败（锁被占用），进入AQS的acquire(1)流程
        acquire(1);
}
分支 1：加锁成功（两种场景）
加锁成功的核心判定是「AQS 的 state 变量被当前线程成功修改」，分两种场景：
场景 1：首次加锁成功（CAS 抢锁成功）
触发条件：当前 AQS 的state=0（无锁），且当前线程通过compareAndSetState(0,1)（CAS）成功修改 state 为 1；
源码动作：调用setExclusiveOwnerThread(Thread.currentThread())，将 AQS 的exclusiveOwnerThread（独占锁持有者）设为当前线程；
结果：线程直接进入临界区执行代码，加锁流程结束。
场景 2：可重入加锁成功（当前线程已持有锁）
若第一步 CAS 失败（state≠0），进入acquire(1)后，会调用NonfairSync.tryAcquire(1)（实际是nonfairTryAcquire(1)）：
java
运行
// NonfairSync源码
protected final boolean tryAcquire(int acquires) {
    return nonfairTryAcquire(acquires);
}

// Sync的nonfairTryAcquire源码（核心可重入逻辑）
final boolean nonfairTryAcquire(int acquires) {
    final Thread current = Thread.currentThread();
    int c = getState(); // 获取AQS的state值

    // 场景1：首次加锁（已在lock()中处理，此处是acquire()中的重试）
    if (c == 0) {
        if (compareAndSetState(0, acquires)) {
            setExclusiveOwnerThread(current);
            return true; // 加锁成功
        }
    }
    // 场景2：可重入加锁（当前线程是锁持有者）
    else if (current == getExclusiveOwnerThread()) {
        int nextc = c + acquires; // state计数+1（比如重入2次→state=2）
        if (nextc < 0) // 溢出保护
            throw new Error("Maximum lock count exceeded");
        setState(nextc); // 更新state
        return true; // 加锁成功
    }
    return false; // 加锁失败
}
触发条件：state≠0但getExclusiveOwnerThread()==当前线程（当前线程已持有锁）；
源码动作：state 值 += acquires（默认 1），更新 state；
结果：返回 true，加锁成功，线程继续执行临界区代码。












分支 2：加锁失败（完整流程，对应源码）
加锁失败的核心判定是「tryAcquire (1) 返回 false」，触发后续入队、阻塞逻辑，流程如下：
子步骤 2.1：执行 AQS.acquire (1)（核心分发逻辑）
java
运行
// AQS源码
public final void acquire(int arg) {
    // 条件：tryAcquire失败（加锁失败） AND 入队并阻塞成功
    if (!tryAcquire(arg) &&
        acquireQueued(addWaiter(Node.EXCLUSIVE), arg))
        selfInterrupt(); // 若线程被中断，补全中断标记
}
关键：!tryAcquire(arg)为 true（加锁失败），进入addWaiter()入队流程。
子步骤 2.2：AQS.addWaiter (Node.EXCLUSIVE)（创建节点并入队）
作用：为当前线程创建「独占式 Node 节点」，加入 AQS 的 CLH 等待队列尾部：
java
运行
// AQS源码
private Node addWaiter(Node mode) {
    // 创建新节点：绑定当前线程，模式为EXCLUSIVE（独占）
    Node node = new Node(Thread.currentThread(), mode);
    // 快速入队（尾节点非空时）
    Node pred = tail;
    if (pred != null) {
        node.prev = pred;
        // CAS将尾节点设为新节点
        if (compareAndSetTail(pred, node)) {
            pred.next = node;
            return node;
        }
    }
    // 快速入队失败（尾节点为空/竞争），自旋入队
    enq(node);
    return node;
}

// AQS.enq()（自旋确保入队）
private Node enq(final Node node) {
    for (;;) { // 死循环，直到入队成功
        Node t = tail;
        if (t == null) { // 队列未初始化，先初始化头节点
            if (compareAndSetHead(new Node()))
                tail = head;
        } else { // 队列已初始化，CAS设为尾节点
            node.prev = t;
            if (compareAndSetTail(t, node)) {
                t.next = node;
                return t;
            }
        }
    }
}
结果：当前线程的 Node 节点成功加入 CLH 队列尾部，返回该节点。
子步骤 2.3：AQS.acquireQueued (Node node, int arg)（入队后阻塞）
作用：当前线程的 Node 节点入队后，自旋尝试抢锁，失败则阻塞：
java
运行
// AQS源码
final boolean acquireQueued(final Node node, int arg) {
    boolean failed = true; // 标记是否获取锁失败
    try {
        boolean interrupted = false; // 标记线程是否被中断
        for (;;) { // 自旋
            // 获取当前节点的前驱节点
            final Node p = node.predecessor();
            // 条件：前驱是头节点 AND 重新tryAcquire抢锁成功
            if (p == head && tryAcquire(arg)) {
                setHead(node); // 将当前节点设为头节点（出队）
                p.next = null; // 原头节点置空，帮助GC
                failed = false;
                return interrupted; // 加锁成功，返回中断标记
            }
            // 条件：抢锁失败 → 判断是否需要阻塞 + 执行阻塞
            if (shouldParkAfterFailedAcquire(p, node) &&
                parkAndCheckInterrupt())
                interrupted = true; // 阻塞中被中断，标记为true
        }
    } finally {
        if (failed)
            cancelAcquire(node); // 异常时取消获取锁，节点出队
    }
}
子步骤 2.3.1：AQS.shouldParkAfterFailedAcquire ()（判断是否该阻塞）
作用：检查前驱节点状态，确保当前线程可以安全阻塞：
java
运行
// AQS源码
private static boolean shouldParkAfterFailedAcquire(Node pred, Node node) {
    int ws = pred.waitStatus; // 前驱节点的等待状态（默认0）
    if (ws == Node.SIGNAL)
        // 前驱节点已标记“唤醒当前节点”，可以安全阻塞
        return true;
    if (ws > 0) {
        // 前驱节点被取消，跳过所有取消的前驱节点
        do {
            node.prev = pred = pred.prev;
        } while (pred.waitStatus > 0);
        pred.next = node;
    } else {
        // 前驱节点状态为0/PROPAGATE，CAS将其设为SIGNAL（标记需要唤醒）
        compareAndSetWaitStatus(pred, ws, Node.SIGNAL);
    }
    return false; // 暂不阻塞，自旋重试
}
结果：返回 true 则进入阻塞，返回 false 则继续自旋抢锁。
子步骤 2.3.2：AQS.parkAndCheckInterrupt ()（阻塞线程）
作用：阻塞当前线程，并检查是否被中断：
java
运行
// AQS源码
private final boolean parkAndCheckInterrupt() {
    LockSupport.park(this); // 阻塞当前线程（暂停执行）
    return Thread.interrupted(); // 清除中断标记并返回是否被中断
}
结果：当前线程被LockSupport.park()阻塞，直到被唤醒（锁释放时的unpark()）或被中断。
加锁失败的最终结果
当前线程进入阻塞状态，暂停执行，直到以下两种情况之一发生：
持有锁的线程释放锁，调用unparkSuccessor()唤醒当前线程，重新自旋抢锁；
其他线程调用当前线程的interrupt()，线程被唤醒并标记中断（acquireQueued返回 true，最终执行selfInterrupt()补全中断）。













二、公平锁（FairSync）加锁流程（核心差异）
公平锁的核心是 “排队不插队”，加锁流程与非公平锁的唯一差异在tryAcquire()方法，其余失败流程完全一致：
步骤 1：FairSync.lock ()（无插队逻辑）
java
运行
// FairSync源码
final void lock() {
    acquire(1); // 直接进入AQS.acquire(1)，无CAS插队
}
步骤 2：FairSync.tryAcquire (int arg)（核心差异：检查队列是否有前驱）
java
运行
// FairSync源码
protected final boolean tryAcquire(int acquires) {
    final Thread current = Thread.currentThread();
    int c = getState();
    if (c == 0) {
        // 关键差异：hasQueuedPredecessors()检查队列是否有等待的前驱线程
        if (!hasQueuedPredecessors() &&
            compareAndSetState(0, acquires)) {
            setExclusiveOwnerThread(current);
            return true; // 加锁成功
        }
    }
    // 可重入逻辑与非公平锁完全一致
    else if (current == getExclusiveOwnerThread()) {
        int nextc = c + acquires;
        if (nextc < 0)
            throw new Error("Maximum lock count exceeded");
        setState(nextc);
        return true;
    }
    return false; // 加锁失败
}

// AQS.hasQueuedPredecessors()（检查是否有前驱线程）
public final boolean hasQueuedPredecessors() {
    Node t = tail;
    Node h = head;
    Node s;
    // 条件：头节点≠尾节点 AND 头节点的后继节点为空 OR 后继节点的线程≠当前线程
    return h != t &&
        ((s = h.next) == null || s.thread != Thread.currentThread());
}
加锁成功条件（首次加锁）：state=0 + 队列无前驱线程（hasQueuedPredecessors()=false） + CAS 改 state 成功；
加锁失败条件：队列有前驱线程（即使 state=0，也不能抢锁，必须排队）；
可重入逻辑、失败入队阻塞流程：与非公平锁完全一致。
