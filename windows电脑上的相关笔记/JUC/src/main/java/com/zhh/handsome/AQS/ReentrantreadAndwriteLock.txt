一、ReentrantReadWriteLock 基础认知
ReentrantReadWriteLock（可重入读写锁）是 JUC 包下的核心锁实现，核心思想是读写分离：
读锁（共享锁）：允许多个线程同时获取，适合读多写少的场景（如缓存、配置中心）；
写锁（独占锁）：同一时间只能有一个线程获取，且读写互斥、写写互斥；
额外特性：可重入、支持公平 / 非公平模式、支持锁降级（写→读）。
对比普通的ReentrantLock（独占锁）：ReentrantLock无论读写都独占，而ReentrantReadWriteLock在读多写少场景下能大幅提升并发性能。
二、核心结构（源码框架）
先看ReentrantReadWriteLock的类结构，核心是 3 个内部类：
java

    // 核心实现：继承AQS，分公平/非公平版本

    // 构造器：默认非公平，可指定公平性
    public ReentrantReadWriteLock() {
        this(false);
    }

}
三、核心设计：AQS 同步状态（state）的拆分
ReentrantReadWriteLock的核心是对 AQS 的state（32 位 int）的巧妙拆分：
低 16 位：存储写锁的重入次数（独占锁，同一时间只有一个线程持有）；
高 16 位：存储读锁的总持有数（共享锁，多个线程可持有）。
3.1 源码中拆分 state 的常量 / 方法
java
运行
abstract static class Sync extends AbstractQueuedSynchronizer {
    // 移位位数：16位（int共32位，高低各16）
    static final int SHARED_SHIFT   = 16;
    // 读锁计数单位：2^16 = 65536（高16位+1等价于state+65536）
    static final int SHARED_UNIT    = (1 << SHARED_SHIFT);
    // 写锁最大重入次数：2^16 -1 = 65535（低16位最大值）
    static final int MAX_COUNT      = (1 << SHARED_SHIFT) - 1;
    // 写锁掩码：低16位全1（用于提取写锁计数）
    static final int EXCLUSIVE_MASK = (1 << SHARED_SHIFT) - 1;

    // 提取读锁总计数（高16位）：右移16位
    static int sharedCount(int c)    { return c >>> SHARED_SHIFT; }
    // 提取写锁重入次数（低16位）：与掩码做与运算
    static int exclusiveCount(int c) { return c & EXCLUSIVE_MASK; }
}







3.2 直观例子理解 state
state 值	低 16 位（写锁）	高 16 位（读锁）	含义
0	0	0	无锁
1	1	0	写锁重入 1 次
65536	0	1	读锁总持有数 1
65537	1	1	不可能（读写互斥）
四、写锁（WriteLock）核心源码分析
写锁是独占锁，核心逻辑在tryAcquire（获取）和tryRelease（释放）。
4.1 写锁的获取（lock ()）
WriteLock 的lock()最终调用 AQS 的acquire(1)，核心是tryAcquire：
java
运行
// Sync重写的tryAcquire（写锁获取核心）
protected final boolean tryAcquire(int acquires) {
    Thread current = Thread.currentThread();
    int c = getState(); // 获取当前state
    int w = exclusiveCount(c); // 提取写锁计数（低16位）

    // 情况1：已有锁（读锁或写锁）
    if (c != 0) {
        // 子情况1：有读锁（w=0） → 读写互斥，获取失败
        // 子情况2：有写锁但不是当前线程 → 写写互斥，获取失败
        if (w == 0 || current != getExclusiveOwnerThread())
            return false;
        // 子情况3：写锁重入，检查是否超过最大次数（65535）
        if (w + exclusiveCount(acquires) > MAX_COUNT)
            throw new Error("Maximum lock count exceeded");
        // 写锁重入：更新state（低16位+1）
        setState(c + acquires);
        return true;
    }

    // 情况2：无锁，尝试抢锁
    // writerShouldBlock：公平/非公平的区别（下文讲）
    if (writerShouldBlock() || !compareAndSetState(c, c + acquires))
        return false;
    // 抢锁成功，标记当前线程为写锁持有者
    setExclusiveOwnerThread(current);
    return true;
}
4.2 写锁的释放（unlock ()）
WriteLock 的unlock()最终调用 AQS 的release(1)，核心是tryRelease：
java
运行
// Sync重写的tryRelease（写锁释放核心）
protected final boolean tryRelease(int releases) {
    // 校验：当前线程必须持有写锁
    if (!isHeldExclusively())
        throw new IllegalMonitorStateException();
    int nextc = getState() - releases; // 写锁计数-1
    // 判断是否完全释放写锁（低16位为0）
    boolean free = exclusiveCount(nextc) == 0;
    if (free)
        setExclusiveOwnerThread(null); // 清空写锁持有者
    setState(nextc); // 更新state
    return free; // 返回是否完全释放
}

// 检查当前线程是否持有写锁
protected final boolean isHeldExclusively() {
    return getExclusiveOwnerThread() == Thread.currentThread();
}
4.3 写锁的关键特性
独占性：读写、写写互斥（tryAcquire中w==0判断）；
可重入：当前线程持有写锁时，可重复获取（w!=0 && current==持有者）；
公平 / 非公平：由writerShouldBlock决定：
非公平（默认）：writerShouldBlock返回 false，直接抢锁；
公平：writerShouldBlock检查队列是否有等待线程，有则排队。
五、读锁（ReadLock）核心源码分析
读锁是共享锁，核心逻辑在tryAcquireShared（获取）和tryReleaseShared（释放）。
5.1 读锁的获取（lock ()）
ReadLock 的lock()最终调用 AQS 的acquireShared(1)，核心是tryAcquireShared：
java
运行
// Sync重写的tryAcquireShared（读锁获取核心）
protected final int tryAcquireShared(int unused) {
    Thread current = Thread.currentThread();
    int c = getState();

    // 关键判断：有写锁且不是当前线程 → 读写互斥，获取失败（返回-1）
    if (exclusiveCount(c) != 0 && getExclusiveOwnerThread() != current)
        return -1;

    int r = sharedCount(c); // 提取读锁总计数（高16位）
    // 读锁获取条件：
    // 1. readerShouldBlock：公平/非公平判断
    // 2. 读锁总数未超最大值
    // 3. CAS更新state（高16位+1）
    if (!readerShouldBlock() && r < MAX_COUNT &&
        compareAndSetState(c, c + SHARED_UNIT)) {

        // 处理读锁重入（核心：用ThreadLocal记录每个线程的重入次数）
        if (r == 0) { // 首次获取读锁
            firstReader = current;
            firstReaderHoldCount = 1;
        } else if (firstReader == current) { // 当前线程是第一个读线程
            firstReaderHoldCount++;
        } else { // 其他读线程：用ThreadLocal<HoldCounter>记录重入次数
            HoldCounter rh = cachedHoldCounter;
            if (rh == null || rh.tid != getThreadId(current))
                cachedHoldCounter = rh = readHolds.get();
            rh.count++;
        }
        return 1; // 获取成功（返回正数）
    }

    // CAS失败/需要阻塞 → 自旋重试（fullTryAcquireShared）
    return fullTryAcquireShared(current);
}
5.2 读锁的释放（unlock ()）
ReadLock 的unlock()最终调用 AQS 的releaseShared(1)，核心是tryReleaseShared：
java
运行
// Sync重写的tryReleaseShared（读锁释放核心）
protected final boolean tryReleaseShared(int unused) {
    Thread current = Thread.currentThread();

    // 1. 更新当前线程的读锁重入次数（ThreadLocal/HoldCounter）
    if (firstReader == current) {
        if (firstReaderHoldCount == 1)
            firstReader = null;
        else
            firstReaderHoldCount--;
    } else {
        HoldCounter rh = cachedHoldCounter;
        if (rh == null || rh.tid != getThreadId(current))
            rh = readHolds.get();
        int count = rh.count;
        if (count <= 1) {
            readHolds.remove(); // 重入次数≤1，移除ThreadLocal
            if (count <= 0) throw new IllegalMonitorStateException();
        }
        rh.count--;
    }

    // 2. 自旋CAS更新state（高16位-1）
    for (;;) {
        int c = getState();
        int nextc = c - SHARED_UNIT;
        if (compareAndSetState(c, nextc))
            return nextc == 0; // 返回是否所有读锁都释放
    }
}
5.3 读锁的关键特性
共享性：无写锁时，多个线程可同时获取读锁；
可重入：通过ThreadLocal<HoldCounter>记录每个线程的重入次数（因为 state 只记录总读锁数）；
读写互斥：tryAcquireShared中判断 “有写锁且不是当前线程” 则返回 - 1。
六、锁降级（WriteLock → ReadLock）
锁降级是ReentrantReadWriteLock的重要特性：持有写锁的线程，可在不释放写锁的情况下获取读锁，再释放写锁。
6.1 源码依据
tryAcquireShared中的关键判断：
java
运行
if (exclusiveCount(c) != 0 && getExclusiveOwnerThread() != current)
    return -1;
当有写锁但当前线程是写锁持有者时，不会返回 - 1，可正常获取读锁。
6.2 锁降级示例
java
运行
ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
WriteLock writeLock = rwLock.writeLock();
ReadLock readLock = rwLock.readLock();

writeLock.lock(); // 获取写锁
try {
    System.out.println("执行写操作");
    readLock.lock(); // 不释放写锁，获取读锁（降级关键）
} finally {
    writeLock.unlock(); // 释放写锁，保留读锁
}

try {
    System.out.println("执行读操作（降级后）");
} finally {
    readLock.unlock(); // 释放读锁
}
6.3 为什么不支持锁升级（ReadLock → WriteLock）
持有读锁的线程尝试获取写锁时，tryAcquire会判断：
java
运行
if (c != 0 && (w == 0 || current != getExclusiveOwnerThread()))
    return false;
此时c≠0（有读锁）且w=0（无写锁），返回 false，获取失败。若多个读线程都尝试升级，会导致死锁。
七、公平 vs 非公平（核心区别）
维度                      	非公平（默认）	                公平
writerShouldBlock	返回 false，直接抢锁	检查队列是否有等待线程，有则排队
readerShouldBlock	检查队列头是否是写线程，是则让行（避免写锁饥饿）	检查队列是否有等待线程，有则排队
性能	高（减少队列切换）	低（每次检查队列）
饥饿问题	写锁几乎不会饥饿（readerShouldBlock 兜底）	无饥饿
总结
ReentrantReadWriteLock将 AQS 的 32 位state拆分为低 16 位（写锁重入次数）和高 16 位（读锁总计数），实现读写分离；
写锁是独占锁，支持重入，与读锁 / 其他写锁互斥；读锁是共享锁，支持重入（通过 ThreadLocal 记录线程重入次数），仅与写锁互斥；
支持锁降级（写→读），不支持锁升级（读→写）；默认非公平模式（性能高），可指定公平模式（无饥饿）。

// Sync重写的tryAcquireShared（读锁获取核心）
protected final int tryAcquireShared(int unused) {
    Thread current = Thread.currentThread();
    int c = getState();

    // 关键判断：有写锁且不是当前线程 → 读写互斥，获取失败（返回-1）
    if (exclusiveCount(c) != 0 && getExclusiveOwnerThread() != current)
        return -1;

    int r = sharedCount(c); // 提取读锁总计数（高16位）
    // 读锁获取条件：
    // 1. readerShouldBlock：公平/非公平判断
    // 2. 读锁总数未超最大值
    // 3. CAS更新state（高16位+1）
    if (!readerShouldBlock() && r < MAX_COUNT &&
        compareAndSetState(c, c + SHARED_UNIT)) {

        // 处理读锁重入（核心：用ThreadLocal记录每个线程的重入次数）
        if (r == 0) { // 首次获取读锁
            firstReader = current;
            firstReaderHoldCount = 1;
        } else if (firstReader == current) { // 当前线程是第一个读线程
            firstReaderHoldCount++;
        } else { // 其他读线程：用ThreadLocal<HoldCounter>记录重入次数
            HoldCounter rh = cachedHoldCounter;
            if (rh == null || rh.tid != getThreadId(current))
                cachedHoldCounter = rh = readHolds.get();
            rh.count++;
        }
        return 1; // 获取成功（返回正数）
    }

    // CAS失败/需要阻塞 → 自旋重试（fullTryAcquireShared）
    return fullTryAcquireShared(current);
}
5.2 读锁的释放（unlock ()）
ReadLock 的unlock()最终调用 AQS 的releaseShared(1)，核心是tryReleaseShared：
java
运行
// Sync重写的tryReleaseShared（读锁释放核心）
protected final boolean tryReleaseShared(int unused) {
    Thread current = Thread.currentThread();

    // 1. 更新当前线程的读锁重入次数（ThreadLocal/HoldCounter）
    if (firstReader == current) {
        if (firstReaderHoldCount == 1)
            firstReader = null;
        else
            firstReaderHoldCount--;
    } else {
        HoldCounter rh = cachedHoldCounter;
        if (rh == null || rh.tid != getThreadId(current))
            rh = readHolds.get();
        int count = rh.count;
        if (count <= 1) {
            readHolds.remove(); // 重入次数≤1，移除ThreadLocal
            if (count <= 0) throw new IllegalMonitorStateException();
        }
        rh.count--;
    }

    // 2. 自旋CAS更新state（高16位-1）
    for (;;) {
        int c = getState();
        int nextc = c - SHARED_UNIT;
        if (compareAndSetState(c, nextc))
            return nextc == 0; // 返回是否所有读锁都释放
    }
}
5.3 读锁的关键特性
共享性：无写锁时，多个线程可同时获取读锁；
可重入：通过ThreadLocal<HoldCounter>记录每个线程的重入次数（因为 state 只记录总读锁数）；
读写互斥：tryAcquireShared中判断 “有写锁且不是当前线程” 则返回 - 1。
六、锁降级（WriteLock → ReadLock）
锁降级是ReentrantReadWriteLock的重要特性：持有写锁的线程，可在不释放写锁的情况下获取读锁，再释放写锁。
6.1 源码依据
tryAcquireShared中的关键判断：
java
运行
if (exclusiveCount(c) != 0 && getExclusiveOwnerThread() != current)
    return -1;
当有写锁但当前线程是写锁持有者时，不会返回 - 1，可正常获取读锁。
6.2 锁降级示例
java
运行
ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
WriteLock writeLock = rwLock.writeLock();
ReadLock readLock = rwLock.readLock();

writeLock.lock(); // 获取写锁
try {
    System.out.println("执行写操作");
    readLock.lock(); // 不释放写锁，获取读锁（降级关键）
} finally {
    writeLock.unlock(); // 释放写锁，保留读锁
}

try {
    System.out.println("执行读操作（降级后）");
} finally {
    readLock.unlock(); // 释放读锁
}
6.3 为什么不支持锁升级（ReadLock → WriteLock）
持有读锁的线程尝试获取写锁时，tryAcquire会判断：
java
运行
if (c != 0 && (w == 0 || current != getExclusiveOwnerThread()))
    return false;
此时c≠0（有读锁）且w=0（无写锁），返回 false，获取失败。若多个读线程都尝试升级，会导致死锁。
七、公平 vs 非公平（核心区别）
维度	非公平（默认）	公平
writerShouldBlock	返回 false，直接抢锁	检查队列是否有等待线程，有则排队
readerShouldBlock	检查队列头是否是写线程，是则让行（避免写锁饥饿）	检查队列是否有等待线程，有则排队
性能	高（减少队列切换）	低（每次检查队列）
饥饿问题	写锁几乎不会饥饿（readerShouldBlock 兜底）	无饥饿
总结
ReentrantReadWriteLock将 AQS 的 32 位state拆分为低 16 位（写锁重入次数）和高 16 位（读锁总计数），实现读写分离；
写锁是独占锁，支持重入，与读锁 / 其他写锁互斥；读锁是共享锁，支持重入（通过 ThreadLocal 记录线程重入次数），仅与写锁互斥；
支持锁降级（写→读），不支持锁升级（读→写）；默认非公平模式（性能高），可指定公平模式（无饥饿）。
