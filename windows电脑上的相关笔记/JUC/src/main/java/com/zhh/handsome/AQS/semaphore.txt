Semaphore（信号量）全解析：核心用法与实战细节
一、Semaphore 基础认知
1.1 核心定义
Semaphore（信号量）是 JUC（java.util.concurrent）包下的同步工具，核心作用是控制同时访问特定资源的线程数量，本质是通过「许可（Permit）」机制实现并发限流：
初始化时指定许可总数（比如 5 个许可）；
线程需要访问资源时，必须获取 1 个（或多个）许可；
许可不足时，线程会阻塞，直到其他线程释放许可；
线程使用完资源后，释放 1 个（或多个）许可，供其他线程使用。
1.2 底层原理（极简版，新手易懂）
Semaphore基于 AQS（AbstractQueuedSynchronizer）实现，核心是将 AQS 的state变量直接作为可用许可数：
state = N：初始化时的总许可数；
线程acquire()：尝试将state-1，成功则获取许可，失败则进入 AQS 等待队列；
线程release()：将state+1，唤醒队列中的等待线程。
与ReentrantReadWriteLock不同，Semaphore默认以共享模式工作（多个线程可同时获取许可，只要许可充足），这也是它能实现 “限流” 的核心原因。
1.3 核心适用场景
Semaphore的核心价值是并发数控制，最典型的场景：
接口限流：控制同时访问接口的线程数，避免服务被压垮；
资源池管理：控制连接池（数据库 / Redis）、线程池、对象池的同时使用数；
并发任务控制：限制同时执行的任务数，比如同时最多 5 个线程处理文件下载。
二、核心 API 与基础用法
2.1 核心 API（必记）
Semaphore的 API 围绕 “许可的获取 / 释放” 展开，核心方法如下：
方法	作用	关键特性
Semaphore(int permits)	创建信号量，指定总许可数（默认非公平）	非公平模式（性能优）
Semaphore(int permits, boolean fair)	创建信号量，指定许可数 + 公平 / 非公平	公平模式：按 FIFO 顺序获取许可
acquire()	获取 1 个许可，无许可则阻塞	可中断（线程被中断时抛InterruptedException）
acquire(int permits)	获取指定数量的许可	同上
acquireUninterruptibly()	获取 1 个许可，无许可则阻塞，不响应中断	避免线程中断导致获取失败
tryAcquire()	尝试获取 1 个许可，立即返回结果（成功true/ 失败false）	非阻塞，不会等待
tryAcquire(long timeout, TimeUnit unit)	超时尝试获取 1 个许可，超时返回false	避免永久阻塞
release()	释放 1 个许可	即使未获取许可，释放也会增加许可数（需避免滥用）
release(int permits)	释放指定数量的许可	同上
availablePermits()	获取当前可用许可数	用于监控 / 调试
drainPermits()	清空所有可用许可，返回清空的数量	紧急限流时使用
2.2 最简使用模板（生产必守）
核心原则：
acquire()尽量放在try外（避免未获取许可却释放）；
release()必须放在finally中（确保许可一定释放，避免泄漏）；
许可的获取和释放数量必须匹配（比如获取 2 个，释放 2 个）。
基础限流示例（控制最多 3 个线程同时执行）
java
运行
import java.util.concurrent.Semaphore;

/**
 * Semaphore基础用法：控制并发数（最多3个线程同时执行）
 */
public class SemaphoreBasicDemo {
    // 1. 创建信号量：3个许可，默认非公平
    private static final Semaphore semaphore = new Semaphore(3);

    // 模拟需要限流的任务
    private static void limitedTask(String taskName) {
        try {
            // 2. 获取1个许可（无许可则阻塞）
            semaphore.acquire();
            System.out.println(Thread.currentThread().getName() + " 获取许可，执行任务：" + taskName);
            // 模拟任务耗时
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt(); // 恢复中断状态
            System.out.println(Thread.currentThread().getName() + " 被中断，放弃任务");
        } finally {
            // 3. 释放1个许可（finally保证必执行）
            semaphore.release();
            System.out.println(Thread.currentThread().getName() + " 释放许可，剩余许可数：" + semaphore.availablePermits());
        }
    }

    public static void main(String[] args) {
        // 创建10个线程，模拟并发请求
        for (int i = 0; i < 10; i++) {
            int taskId = i;
            new Thread(() -> limitedTask("任务" + taskId), "线程" + i).start();
        }
    }
}
运行结果特征：
前 3 个线程会立即获取许可执行任务；
第 4 个及以后线程会阻塞，直到前 3 个线程释放许可；
最终所有线程都会执行，但同一时间最多 3 个线程在运行，实现了并发限流。
三、经典实战场景（生产高频）
3.1 场景 1：接口限流（最核心）
Semaphore是实现接口限流的轻量方案（适合单机限流），比如限制某个接口每秒最多处理 10 个请求：
java
运行
import java.util.concurrent.Semaphore;
import java.util.concurrent.TimeUnit;

/**
 * 基于Semaphore的单机接口限流
 */
public class ApiRateLimitDemo {
    // 限流：最多10个并发请求
    private static final Semaphore API_SEMAPHORE = new Semaphore(10);
    // 超时时间：1秒（1秒内获取不到许可则拒绝请求）
    private static final long TIMEOUT = 1;
    private static final TimeUnit TIME_UNIT = TimeUnit.SECONDS;

    /**
     * 模拟被限流的接口
     * @param requestId 请求ID
     * @return 处理结果
     */
    public String processRequest(String requestId) {
        // 尝试超时获取许可
        try {
            if (!API_SEMAPHORE.tryAcquire(TIMEOUT, TIME_UNIT)) {
                // 限流触发，返回拒绝信息
                return "请求[" + requestId + "]失败：当前接口并发数已达上限，请稍后重试";
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return "请求[" + requestId + "]失败：请求被中断";
        }

        // 执行接口逻辑
        try {
            System.out.println("处理请求：" + requestId);
            // 模拟接口处理耗时
            Thread.sleep(500);
            return "请求[" + requestId + "]处理成功";
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return "请求[" + requestId + "]失败：处理被中断";
        } finally {
            // 释放许可
            API_SEMAPHORE.release();
        }
    }

    // 测试
    public static void main(String[] args) {
        ApiRateLimitDemo demo = new ApiRateLimitDemo();
        // 模拟20个并发请求
        for (int i = 0; i < 20; i++) {
            int reqId = i;
            new Thread(() -> {
                String result = demo.processRequest("REQ-" + reqId);
                System.out.println(result);
            }).start();
        }
    }
}
核心设计亮点：
使用tryAcquire(timeout, unit)而非acquire()，避免线程永久阻塞；
超时获取失败直接返回限流提示，符合接口限流的业务逻辑；
finally中释放许可，确保许可不泄漏。
3.2 场景 2：资源池管理（数据库连接池示例）
Semaphore可用于控制资源池的同时使用数，比如限制最多 5 个数据库连接被同时使用：
java
运行
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.Semaphore;

/**
 * 基于Semaphore的资源池管理（数据库连接池示例）
 */
public class ConnectionPoolDemo {
    // 连接池大小：5个连接
    private static final int POOL_SIZE = 5;
    // 信号量：控制最多5个线程同时获取连接
    private static final Semaphore SEMAPHORE = new Semaphore(POOL_SIZE);
    // 模拟连接池
    private static final List<Connection> CONNECTION_POOL = new ArrayList<>();

    // 初始化连接池
    static {
        for (int i = 0; i < POOL_SIZE; i++) {
            CONNECTION_POOL.add(new Connection("连接" + i));
        }
    }

    /**
     * 获取数据库连接（限流）
     * @return 可用连接
     * @throws InterruptedException 中断异常
     */
    public Connection getConnection() throws InterruptedException {
        // 获取许可（阻塞直到有可用连接）
        SEMAPHORE.acquire();
        // 从池子里取一个连接（简化版，实际需加锁/队列）
        synchronized (CONNECTION_POOL) {
            return CONNECTION_POOL.remove(0);
        }
    }

    /**
     * 释放数据库连接
     * @param conn 要释放的连接
     */
    public void releaseConnection(Connection conn) {
        // 归还连接到池子里
        synchronized (CONNECTION_POOL) {
            CONNECTION_POOL.add(conn);
        }
        // 释放许可
        SEMAPHORE.release();
        System.out.println("释放连接：" + conn.getName() + "，剩余许可数：" + SEMAPHORE.availablePermits());
    }

    // 模拟数据库连接
    static class Connection {
        private final String name;

        public Connection(String name) {
            this.name = name;
        }

        public String getName() {
            return name;
        }
    }

    // 测试
    public static void main(String[] args) {
        ConnectionPoolDemo pool = new ConnectionPoolDemo();
        // 模拟10个线程获取连接
        for (int i = 0; i < 10; i++) {
            new Thread(() -> {
                try {
                    Connection conn = pool.getConnection();
                    System.out.println(Thread.currentThread().getName() + " 获取连接：" + conn.getName());
                    // 模拟使用连接
                    Thread.sleep(1000);
                    pool.releaseConnection(conn);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }, "线程" + i).start();
        }
    }
}
核心设计亮点：
信号量许可数与连接池大小一致，确保最多只有POOL_SIZE个线程能获取连接；
连接的获取 / 归还加synchronized保证线程安全；
许可的释放与连接的归还一一对应，避免资源泄漏。
3.3 场景 3：批量获取 / 释放许可（多许可控制）
Semaphore支持一次获取 / 释放多个许可，适合 “一个任务需要占用多个资源” 的场景，比如一个任务需要 2 个数据库连接：
java
运行
import java.util.concurrent.Semaphore;

/**
 * 多许可获取/释放示例
 */
public class MultiPermitDemo {
    // 总许可数：6（对应6个资源）
    private static final Semaphore SEMAPHORE = new Semaphore(6);

    // 任务需要占用2个许可
    private static void multiPermitTask(String taskName) {
        try {
            // 获取2个许可
            SEMAPHORE.acquire(2);
            System.out.println(Thread.currentThread().getName() + " 获取2个许可，执行任务：" + taskName + "，剩余许可：" + SEMAPHORE.availablePermits());
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            // 释放2个许可（必须和获取数量匹配）
            SEMAPHORE.release(2);
            System.out.println(Thread.currentThread().getName() + " 释放2个许可，剩余许可：" + SEMAPHORE.availablePermits());
        }
    }

    public static void main(String[] args) {
        // 模拟5个任务，每个任务需要2个许可
        for (int i = 0; i < 5; i++) {
            new Thread(() -> multiPermitTask("任务" + i), "线程" + i).start();
        }
    }
}
运行结果特征：
总许可 6 个，每个任务占 2 个，因此同一时间最多 3 个任务执行；
必须保证acquire(n)和release(n)的n一致，否则会导致许可数异常。
四、核心使用细节（面试高频 + 生产必守）
4.1 公平与非公平模式
Semaphore支持公平 / 非公平模式，构造器传入boolean fair指定：
模式	核心规则	性能	适用场景
非公平（默认）	线程尝试直接抢许可，抢不到再排队	高（减少队列切换开销）	绝大多数生产场景（优先保证性能）
公平	严格按线程等待顺序获取许可（FIFO）	低（每次检查队列）	对公平性要求高的场景（避免线程饥饿）
关键细节：非公平模式下，先等待的线程可能后获取许可，但性能更优，是生产首选。
4.2 许可的 “非独占性” 与 “可重复释放”
非独占性：许可不绑定线程，线程 A 获取的许可，线程 B 可以释放（需避免这种操作，易导致许可数异常）；
可重复释放：即使线程未获取许可，调用release()也会增加许可数（比如初始 3 个许可，调用release()后变成 4 个）。
错误示例（禁止使用）：
java
运行
// 错误：重复释放许可，导致许可数异常
public void wrongRelease() {
    semaphore.acquire(); // 获取1个许可
    semaphore.release(); // 正常释放（许可数恢复）
    semaphore.release(); // 非法释放（许可数+1，导致许可数超过初始值）
}
核心原则：许可的获取和释放必须在同一个线程中，且数量严格匹配。
4.3 中断与超时获取许可（进阶用法）
4.3.1 可中断获取（acquireInterruptibly()）
线程在等待获取许可时，若被其他线程中断，会立即抛出InterruptedException，并停止等待：
java
运行
public void interruptibleAcquire() {
    try {
        // 可中断获取许可
        semaphore.acquireInterruptibly();
        try {
            System.out.println("获取许可成功");
        } finally {
            semaphore.release();
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        System.out.println("线程被中断，未获取许可");
    }
}
4.3.2 超时获取（tryAcquire(timeout, unit)）
最常用的生产写法，避免线程永久阻塞，超时后直接返回false，适合接口限流、资源获取等场景（前文接口限流示例已演示）。
4.4 许可数的动态调整
Semaphore未提供直接修改总许可数的方法，但可通过drainPermits()+release(n)实现动态调整：
java
运行
// 动态调整许可数为8
public void adjustPermits(int newPermits) {
    // 清空所有可用许可
    int drain = semaphore.drainPermits();
    // 释放新的许可数
    semaphore.release(newPermits);
    System.out.println("许可数调整为：" + semaphore.availablePermits());
}
五、避坑指南（生产常见错误）
5.1 误区 1：未在 finally 中释放许可
导致许可泄漏，最终所有线程阻塞在acquire()，无法获取许可。
5.2 误区 2：获取 / 释放许可数量不匹配
比如acquire(2)但release(1)，导致许可数逐渐减少，最终无可用许可。
5.3 误区 3：跨线程释放许可
线程 A 获取许可，线程 B 释放许可，导致许可数统计异常，破坏限流规则。
5.4 误区 4：滥用公平模式
公平模式性能低，仅在 “必须保证线程按顺序执行” 的场景使用，绝大多数场景用非公平即可。
5.5 误区 5：用 Semaphore 实现分布式限流
Semaphore是单机级同步工具，无法实现分布式限流（分布式限流需用 Redis / 哨兵等中间件）。
六、Semaphore 与其他 JUC 同步工具的对比（面试高频）
工具	核心作用	核心特性	适用场景
Semaphore	控制并发数（限流 / 资源池）	基于许可、共享模式、可动态调整	接口限流、资源池管理、并发任务控制
ReentrantLock	独占锁（互斥访问）	可重入、公平 / 非公平、可中断	读写均衡 / 写多读少的互斥场景
ReentrantReadWriteLock	读写分离锁	读读共享、读写 / 写写互斥、锁降级	读多写少的缓存 / 配置场景
CountDownLatch	线程等待（一次性）	计数器递减、一次性使用	主线程等待子线程完成（比如初始化）
CyclicBarrier	线程同步（可重复）	计数器递增、可重置、触发屏障动作	多个线程互相等待（比如阶段任务）
总结
核心定位：Semaphore是 JUC 中用于并发限流 / 资源控制的核心工具，通过 “许可” 机制控制同时访问资源的线程数；
核心用法：初始化许可数→acquire()获取许可→finally中release()释放许可，许可获取 / 释放数量必须匹配；
核心场景：单机接口限流、资源池管理（连接池 / 线程池）、多许可资源占用控制；
关键原则：非公平模式优先、超时获取避免阻塞、许可释放必须在 finally 中、禁止跨线程释放许可；
边界限制：仅适用于单机场景，分布式限流需用 Redis 等中间件。
