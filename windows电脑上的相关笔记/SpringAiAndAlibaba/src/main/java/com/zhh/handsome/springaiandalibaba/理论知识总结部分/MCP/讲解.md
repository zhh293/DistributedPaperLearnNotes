一、MCP 客户端 Starter 核心内容总结（吃透 “是什么、能做什么”）
这部分是理解的基础，先明确 Spring AI MCP 客户端 Starter 的核心定位和能力，所有用法都围绕这些核心展开：




核心维度	关键信息
定位	Spring Boot 自动配置组件，帮你一键搭建 MCP 客户端，无需手写底层 MCP 协议通信代码；核心目标是让 Spring 应用能对接你自己部署的 MCP 服务（不管是本地 STDIO 运行的，还是远程 SSE 部署的）。
核心依赖选择	1. 标准 Starter（spring-ai-starter-mcp-client）：支持 STDIO（本地进程通信） + SSE（基于 HttpClient 的远程 HTTP 通信），适合传统阻塞式场景；
2. WebFlux Starter（spring-ai-starter-mcp-client-webflux）：基于 WebFlux 的 SSE 响应式通信，生产环境首选（非阻塞、高并发）。
   核心配置体系	所有配置以 spring.ai.mcp.client 为前缀，分 3 类：
1. 公共属性：控制客户端全局行为（是否启用、同步 / 异步、超时、是否整合 Spring AI 工具调用）；
2. STDIO 传输配置：对接本地进程运行的 MCP 服务（比如你在本地部署的 Python MCP 服务）；
3. SSE 传输配置：对接远程部署的 MCP 服务（比如你部署在云端 / 服务器的 Java/Python MCP 服务）。
   核心特性	1. 同步 / 异步客户端：默认同步（SYNC），响应式场景配 ASYNC；
2. 自定义能力：可定制超时、事件监听（工具 / 资源变更）、日志处理等；
3. 无缝整合 Spring AI：MCP 服务的工具可自动转为 Spring AI 的 ToolCallback，直接在 ChatClient 中使用；
4. 生命周期管理：应用关闭时自动清理连接，避免资源泄漏；
5. 多传输协议：支持本地（STDIO）和远程（SSE）对接你的 MCP 服务。









二、核心用法（部署自己的 MCP 服务时，客户端实操步骤）
你核心需求是 “部署自己的 MCP 服务并通过客户端调用”，以下是从依赖→配置→使用→自定义 的完整实操流程，直接套用即可：
步骤 1：引入依赖（根据你的 MCP 服务部署方式选）
场景 1：对接远程部署的 MCP 服务（生产环境，SSE 通信）
优先选 WebFlux Starter（非阻塞）：
xml
<!-- WebFlux 版 MCP 客户端（推荐生产用） -->
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-mcp-client-webflux</artifactId>
</dependency>
<!-- 若用传统 HttpClient 的 SSE，选标准 Starter -->
<!--
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-mcp-client</artifactId>
</dependency>
-->
场景 2：对接本地进程运行的 MCP 服务（测试环境，STDIO 通信）
选标准 Starter 即可：
xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-mcp-client</artifactId>
</dependency>
步骤 2：配置客户端（对接你自己的 MCP 服务）
配置文件用 application.yml，核心是填你的 MCP 服务地址 / 运行命令：
场景 1：对接远程 SSE 部署的 MCP 服务（最常用）
假设你已把 MCP 服务部署在 http://你的服务器IP:8080，配置如下：
yaml
spring:
  ai:
    mcp:
      client:
        enabled: true  # 启用 MCP 客户端（默认true）
        name: my-custom-mcp-client  # 客户端名称（自定义）
        request-timeout: 30s  # 请求超时（默认20s，根据你的服务调整）
        type: SYNC  # 同步模式（响应式场景改 ASYNC）
        # SSE 传输配置（对接你的远程 MCP 服务）
        sse:
          connections:
            # 给你的 MCP 服务起个名字（自定义，比如 my-mcp-server）
            my-mcp-server:
              url: http://你的服务器IP:8080  # 你的 MCP 服务基础地址
              sse-endpoint: /sse  # MCP 服务的 SSE 端点（默认/sse，按你的服务配置）
场景 2：对接本地 STDIO 运行的 MCP 服务（测试用）
假设你的 MCP 服务是 Python 脚本，运行命令是 python /path/to/your-mcp-server.py，配置如下：
yaml
spring:
  ai:
    mcp:
      client:
        enabled: true
        request-timeout: 30s
        # STDIO 传输配置（对接本地进程 MCP 服务）
        stdio:
          connections:
            my-local-mcp-server:
              command: python  # 运行 MCP 服务的命令
              args:
                - /path/to/your-mcp-server.py  # 你的 MCP 服务脚本路径
              env:  # 给 MCP 服务传环境变量（比如 API 密钥）
                API_KEY: your-api-key
                DEBUG: "true"
步骤 3：使用客户端（两种方式，按需选）
方式 1：直接注入 MCP 客户端调用（底层方式）
适合需要手动控制 MCP 协议交互的场景：
java
运行
import org.springframework.ai.mcp.client.McpSyncClient;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;
import java.util.List;

@Component
public class MyMcpClientService {

    // 注入同步 MCP 客户端列表（ASYNC 场景注入 McpAsyncClient）
    @Autowired
    private List<McpSyncClient> mcpSyncClients;

    // 调用你部署的 MCP 服务的工具
    public String callMyMcpTool() {
        // 找到你配置的 MCP 客户端（对应配置里的 my-mcp-server）
        McpSyncClient myMcpServerClient = mcpSyncClients.stream()
                .filter(client -> client.getConfigurationName().equals("my-mcp-server"))
                .findFirst()
                .orElseThrow(() -> new RuntimeException("未找到你的 MCP 服务客户端"));

        // 调用 MCP 服务的工具（比如你的 MCP 服务提供了 getWeather 工具）
        // 参数按 MCP 协议格式传（通常是 JSON）
        String toolResult = myMcpServerClient.callTool("getWeather", "{\"city\":\"北京\"}");
        return toolResult;
    }
}
方式 2：整合 Spring AI 工具调用（推荐，无缝复用 ChatClient）
MCP 服务的工具会自动转为 Spring AI 的 ToolCallback，直接在 ChatClient 中使用，和你之前写的 @Tool 工具用法完全一致：
java
运行
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.mcp.client.tool.SyncMcpToolCallbackProvider;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

@Component
public class MyMcpChatService {

    private final ChatClient chatClient;

    // 注入 MCP 工具回调提供者（自动加载你配置的 MCP 服务的所有工具）
    @Autowired
    public MyMcpChatService(ChatClient.Builder chatClientBuilder, SyncMcpToolCallbackProvider toolCallbackProvider) {
        // 将 MCP 服务的工具添加到 ChatClient
        this.chatClient = chatClientBuilder
                .defaultTools(toolCallbackProvider.getToolCallbacks())
                .build();
    }

    // 像用本地工具一样，调用你部署的 MCP 服务的工具
    public String askWeather() {
        return chatClient.prompt()
                .user("北京今天的天气怎么样？")
                .call()
                .content();
    }
}
步骤 4：自定义客户端（按需定制，比如超时、事件监听）
如果你的 MCP 服务需要定制超时、监听工具变更（比如你更新了 MCP 服务的工具），写一个定制器即可：
java
运行
import org.springframework.ai.mcp.client.McpSyncClientCustomizer;
import org.springframework.ai.mcp.schema.McpSchema;
import org.springframework.stereotype.Component;
import java.time.Duration;
import java.util.List;

@Component
public class CustomMcpClientConfig implements McpSyncClientCustomizer {

    @Override
    public void customize(String serverName, McpClient.SyncSpec spec) {
        // 只定制你自己的 MCP 服务（对应配置里的 my-mcp-server）
        if ("my-mcp-server".equals(serverName)) {
            // 1. 自定义超时（覆盖配置文件的 30s）
            spec.requestTimeout(Duration.ofSeconds(60));

            // 2. 监听 MCP 服务的工具变更（比如你更新了 MCP 服务的工具）
            spec.toolsChangeConsumer((List<McpSchema.Tool> tools) -> {
                System.out.println("你的 MCP 服务工具更新了：" + tools);
            });

            // 3. 监听 MCP 服务的日志（便于排查部署问题）
            spec.loggingConsumer((McpSchema.LoggingMessageNotification log) -> {
                System.out.println("MCP 服务日志：" + log.getMessage());
            });
        }
    }
}
步骤 5：部署注意事项（生产环境必看）
传输协议选择：远程部署的 MCP 服务优先用 WebFlux 的 SSE（spring-ai-starter-mcp-client-webflux），非阻塞、高并发；
超时配置：根据你的 MCP 服务响应速度调整 request-timeout，避免超时导致调用失败；
工具回调开关：默认 toolcallback.enabled=true，如果不需要整合 Spring AI 工具调用，可设为 false；
资源清理：Spring 会自动管理客户端生命周期，无需手动关闭，但要确保 MCP 服务端是稳定运行的；
环境变量：对接 STDIO 本地 MCP 服务时，敏感信息（如 API 密钥）通过 env 传递，不要硬编码。
三、核心总结（部署自己的 MCP 服务，记住这 3 点）
依赖选对：远程 SSE 用 WebFlux Starter，本地 STDIO 用标准 Starter；
配置填对：SSE 配置填你的 MCP 服务地址，STDIO 配置填运行命令；
使用简化：优先整合 Spring AI 的 ChatClient，像用本地工具一样调用远程 MCP 服务的工具，无需关心底层协议。
这套流程下来，你就能快速搭建 MCP 客户端，对接自己部署的任意 MCP 服务（不管是 Java/Python 写的，本地 / 远程运行的），核心是 Starter 帮你屏蔽了 MCP 协议的复杂性，只需要关注 “对接谁（配置）” 和 “怎么用（调用）”。
