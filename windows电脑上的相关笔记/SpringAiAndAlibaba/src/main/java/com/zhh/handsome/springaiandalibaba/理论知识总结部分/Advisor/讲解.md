Advisor 是 Spring AI 的拦截 / 增强机制，作用是在 AI 模型请求发送前 / 响应返回后，对 Prompt、响应内容、上下文做定制化处理。
核心价值：无需修改业务代码，就能给 AI 交互加通用能力（比如对话记忆、RAG 检索、日志监控）；
核心逻辑：以 “链（Chain）” 的形式执行，每个 Advisor 可修改请求 / 响应，也可阻断请求（比如内容安全校验）。





1. 两类核心 Advisor 接口（按交互方式分）
   日常开发只需关注这两个，对应 “同步非流式” 和 “异步流式” 两种 AI 调用场景：
   接口	适用场景	核心方法	日常使用频率
   CallAroundAdvisor	同步调用（比如简单问答，一次性返回结果）	aroundCall()	✅ 高频（80% 场景用这个）
   StreamAroundAdvisor	流式调用（比如长文本生成，逐字返回）	aroundStream()	✅ 中高频（需要流式响应时用）
   关键规则：
   实现时可同时实现两个接口（支持两种场景）；
   必须调用 chain.nextAroundCall()/chain.nextAroundStream() 才能让请求继续走下一个 Advisor（否则会阻断链）。
2. 执行顺序（最容易踩坑的点）
   Advisor 按 getOrder() 返回值排序执行，核心规则：
   数值越小 → 优先级越高（请求处理时最先执行，响应处理时最后执行）；
   栈式执行：比如有 A（order=1）、B（order=2）两个 Advisor，请求流程是 A → B → 模型，响应流程是 模型 → B → A；
   日常建议：内置 Advisor 用默认 order，自定义的按需求设（比如日志 Advisor 设为 0，RAG 设为 1）。
3. 核心数据载体（AdvisedRequest/AdvisedResponse）
   这两个类封装了 “请求 / 响应的所有信息”，日常用得最多的是：
   AdvisedRequest：包含用户输入文本、系统消息、上下文 Map、Prompt 模板参数等；
   AdvisedResponse：包含模型响应内容、元数据（Token 数）、上下文 Map 等；
   上下文 Map：不可变，需通过 updateContext() 方法修改（比如在 Advisor 间共享数据）。
   三、日常开发「最常用」的内置 Advisor（直接复用，不用自己写）
   这是核心！80% 的场景你不需要自定义 Advisor，直接用 Spring AI 内置的这 3 个就够了：
1. MessageChatMemoryAdvisor（对话记忆，必备）
   用途：解决 AI 模型 “无状态” 问题，自动把对话历史追加到 Prompt 中（比如连续问 “我叫什么？” 能记住）；
   配置方式（高频写法）：
   java
   运行
   // 1. 先创建聊天记忆（内存版，日常测试用）
   ChatMemory chatMemory = new MessageWindowChatMemory(new InMemoryChatMemoryRepository(), 20);

// 2. 配置到 ChatClient 中（默认 Advisor，全局生效）
ChatClient chatClient = ChatClient.builder(chatModel)
.defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
.build();

// 3. 调用时指定会话 ID（区分不同用户的对话）
String response = chatClient.prompt()
.advisors(advisor -> advisor.param(ChatMemory.CONVERSATION_ID, "用户123"))
.user("我叫张三")
.call()
.content();
关键细节：必须传 CONVERSATION_ID，否则不同用户的对话历史会混在一起。
2. QuestionAnswerAdvisor（RAG 检索增强，核心）
   用途：自动从向量库检索和用户问题相关的文档，追加到 Prompt 中（让模型回答基于你的私有数据）；
   配置方式（高频写法）：
   java
   运行
   // 1. 注入向量库（比如 Redis/PGVector）
   @Autowired
   private VectorStore vectorStore;

// 2. 配置到 ChatClient
ChatClient chatClient = ChatClient.builder(chatModel)
.defaultAdvisors(QuestionAnswerAdvisor.builder(vectorStore).build())
.build();

// 3. 调用时自动检索
String response = chatClient.prompt()
.user("我的产品退款政策是什么？") // 自动从向量库查“退款政策”相关文档
.call()
.content();
关键细节：执行顺序要在 “对话记忆 Advisor” 之后（先加历史，再基于历史 + 问题检索），所以 getOrder() 要设更大的值。
3. SimpleLoggerAdvisor（日志调试，必备）
   用途：记录 AI 请求 / 响应的详细信息（Prompt、响应内容、Token 数），用于调试；
   配置方式（最简写法）：
   java
   运行
   // 配置到 ChatClient（建议放 Advisor 链最后）
   ChatClient chatClient = ChatClient.builder(chatModel)
   .defaultAdvisors(new SimpleLoggerAdvisor())
   .build();

// 配置日志级别（application.properties）
logging.level.org.springframework.ai.chat.client.advisor=DEBUG
关键细节：生产环境别开 DEBUG 级别，避免泄露敏感信息（比如用户输入）。
四、自定义 Advisor（仅当内置的满足不了时用，日常低频）
如果需要定制化逻辑（比如给 Prompt 加固定前缀、内容安全校验），按以下最简模板写就行：
示例：给所有用户提问加前缀（常用场景）
java
运行
// 实现 CallAroundAdvisor（同步场景）
public class PrefixAdvisor implements CallAroundAdvisor {
// 1. 必须：唯一名称（日志/监控用）
@Override
public String getName() {
return "PrefixAdvisor";
}

    // 2. 必须：执行顺序（0 是默认，数值越小越先执行）
    @Override
    public int getOrder() {
        return 0;
    }

    // 3. 核心：修改请求/响应
    @Override
    public AdvisedResponse aroundCall(AdvisedRequest advisedRequest, CallAroundAdvisorChain chain) {
        // 步骤1：修改请求（给用户文本加前缀）
        String newUserText = "请用简洁的语言回答：" + advisedRequest.userText();
        AdvisedRequest newRequest = AdvisedRequest.from(advisedRequest)
                .userText(newUserText)
                .build();

        // 步骤2：继续执行下一个 Advisor（必须调，否则阻断）
        AdvisedResponse response = chain.nextAroundCall(newRequest);

        // 步骤3：可选：修改响应（比如过滤敏感词）
        // String newContent = response.getResult().getOutput().getContent().replace("敏感词", "***");
        // AdvisedResponse newResponse = AdvisedResponse.from(response)...

        // 步骤4：返回响应
        return response;
    }
}

// 配置到 ChatClient
ChatClient chatClient = ChatClient.builder(chatModel)
.defaultAdvisors(new PrefixAdvisor())
.build();
关键细节：
修改 AdvisedRequest/AdvisedResponse 必须用 from() 方法（因为是不可变对象）；
一定要调用 chain.nextAroundCall()，否则请求会被阻断，模型不会收到请求。
五、日常使用的最佳实践（避坑指南）
优先用 defaultAdvisors () 配置全局 Advisor：在 ChatClient.Builder 中用 defaultAdvisors() 注册，所有请求都生效，避免重复配置；
Advisor 顺序要合理：对话记忆 → RAG → 日志（先加历史，再检索，最后记录）；
流式场景注意聚合：用 MessageAggregator 聚合 Flux 响应，避免日志只记录单条流数据；
上下文共享用 updateContext ()：不同 Advisor 间共享数据，必须用 advisedRequest.updateContext()（不可直接改 Map）。
总结（核心要点回顾）
核心复用：日常优先用内置的 MessageChatMemoryAdvisor（对话记忆）、QuestionAnswerAdvisor（RAG）、SimpleLoggerAdvisor（日志），覆盖 80% 场景；
核心规则：Advisor 按 getOrder() 栈式执行，数值越小越先处理请求、最后处理响应；
核心写法：配置 Advisor 用 defaultAdvisors()（全局）或 advisors()（单次请求），自定义时实现 CallAroundAdvisor + 重写 3 个核心方法；
