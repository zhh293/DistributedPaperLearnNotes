一、ChatClient 核心定位
ChatClient 是 Spring AI 中调用 AI 大模型的核心客户端，基于 Fluent 流式 API 设计，支持：
构建包含系统消息（引导模型行为）和用户消息（用户输入）的 Prompt
配置模型参数（如 temperature、模型名称）
处理同步 / 异步响应、映射 Java 实体、流式输出
多模型协作、对话记忆、日志监控等增强能力



二 Fluent API构建Prompt



ChatClient 提供 3 种 prompt() 方法构建提示词，支持系统消息、用户消息、参数替换：
方法	用途	示例
prompt()	无参流式构建（最常用）	支持链式添加 system()/user()
prompt(Prompt prompt)	传入预构建的 Prompt 对象	适配非流式构建场景
prompt(String content)	快捷传用户文本	等价于 prompt().user(content)
核心示例
基础系统 + 用户消息
java
运行
String response = chatClient.prompt()
.system("你是一个专业的Java技术顾问，回答简洁") // 系统指令
.user("Spring AI 是什么？") // 用户输入
.call() // 发送请求
.content(); // 获取字符串响应
提示词模板（参数替换）
默认使用 {参数名} 作为占位符，运行时通过 param() 替换：
java
运行
String answer = chatClient.prompt()
.user(u -> u.text("推荐{count}本{type}领域的经典书籍")
.param("count", 5)
.param("type", "微服务"))
.call()
.content();
自定义占位符分隔符
若提示词含 JSON 等冲突内容，可自定义分隔符（如 <>）：
java
运行
String answer = chatClient.prompt()
.user(u -> u.text("推荐<count>本<type>书籍").param("count",3).param("type","AI"))
.templateRenderer(StTemplateRenderer.builder()
.startDelimiterToken('<')
.endDelimiterToken('>').build())
.call()
.content();








响应处理方式


call() 发送同步请求后，支持 4 种响应处理方式；stream() 支持异步流式响应。
1. 同步响应
   方法	用途	示例
   content()	获取纯字符串响应	最常用，快速获取结果
   chatResponse()	获取完整 ChatResponse	包含元数据（Token 数、生成时间等）
   entity(Class<T>)	映射为 Java 实体	自动将 JSON 响应转为 Bean/Record
   entity(ParameterizedTypeReference<T>)	映射泛型集合	如 List<Book> 等复杂类型







实体映射示例
java
运行
// 定义 Record
record Book(String name, String author) {}

// 映射单个实体
Book book = chatClient.prompt()
.user("推荐一本Java书籍，返回JSON格式：{name:书名,author:作者}")
.call()
.entity(Book.class);

// 映射泛型集合（必须用 ParameterizedTypeReference）
List<Book> bookList = chatClient.prompt()
.user("推荐3本Java书籍，返回JSON数组")
.call()
.entity(new ParameterizedTypeReference<List<Book>>() {});
2. 异步流式响应
   使用 stream() 替代 call()，返回 Flux 响应式流，适合大文本生成场景：
   java
   运行
   // 流式获取字符串
   Flux<String> contentStream = chatClient.prompt()
   .user("写一篇关于Spring AI的技术文章")
   .stream() // 流式请求
   .content();

// 订阅消费流
contentStream.subscribe(System.out::print);







五、默认配置简化开发
可在 @Configuration 中为 ChatClient 配置默认参数，避免运行时重复设置：
java
运行
@Configuration
class Config {
@Bean
ChatClient chatClient(ChatClient.Builder builder) {
return builder
// 1. 默认系统消息
.defaultSystem("你是一个简洁的助手，回答不超过50字")
// 2. 默认模型参数（如 temperature、模型名）
.defaultOptions(OpenAiChatOptions.builder()
.temperature(0.3) // 降低随机性
.model("gpt-3.5-turbo").build())
.build();
}
}
运行时可通过链式方法覆盖默认配置：
java
运行
// 覆盖默认系统消息
String response = chatClient.prompt()
.system("你是一个幽默的段子手") // 覆盖默认
.user("讲个笑话")
.call()
.content();











六、Advisor 增强机制
Advisor 是 ChatClient 的拦截增强组件，可在请求发送前 / 后修改提示词、添加上下文、记录日志等。执行顺序由添加顺序决定。
核心内置 Advisor
Advisor	用途	关键说明
MessageChatMemoryAdvisor	添加对话历史	解决模型无状态问题，需配合 ChatMemory
QuestionAnswerAdvisor	实现 RAG 检索增强	从向量库检索相关文档，追加到提示词
SimpleLoggerAdvisor	记录请求 / 响应日志	用于调试，需配置日志级别为 DEBUG
示例：添加日志监控
java
运行
// 1. 添加日志 Advisor（建议放最后）
ChatResponse response = chatClient.prompt()
.advisors(new SimpleLoggerAdvisor())
.user("Spring AI 怎么用？")
.call()
.chatResponse();

// 2. 配置日志级别（application.properties）
logging.level.org.springframework.ai.chat.client.advisor=DEBUG








七、聊天记忆（ChatMemory）
解决 AI 模型无状态问题，维护对话历史上下文。核心接口是 ChatMemory，内置实现为 MessageWindowChatMemory：
特性：维护固定数量的消息窗口（默认 20 条），超出时移除旧消息（系统消息除外）
存储实现：支持内存（默认）、JDBC、Cassandra、Neo4j 等
核心用法
配合 MessageChatMemoryAdvisor 使用：
java
运行
// 1. 创建内存聊天记忆（最多10条消息）
ChatMemory chatMemory = new MessageWindowChatMemory(new InMemoryChatMemoryRepository(), 10);

// 2. 配置 Advisor
ChatClient chatClient = ChatClient.builder(chatModel)
.defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
.build();

// 3. 多次对话，模型会记住历史
chatClient.prompt().user("我叫张三").call().content();
chatClient.prompt().user("我叫什么名字？").call().content(); // 会回答“张三”
