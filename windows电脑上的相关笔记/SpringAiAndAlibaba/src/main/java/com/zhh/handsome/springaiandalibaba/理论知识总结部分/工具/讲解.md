Spring AI 工具调用（Tool Calling）能力 —— 它解决了 AI 模型 “无实时信息”“无执行能力” 的核心痛点，让模型能调用外部工具（如查实时时间、查天气、设闹钟、调用业务接口）完成任务；而 ChatClient 是 Spring AI 中使用工具调用最便捷的入口，支持「声明式 / 编程式 / 动态 Bean」三种工具定义方式，还能灵活配置临时 / 默认工具、传递上下文、处理异常。
下面从「核心定位→关键组件→完整可运行示例→避坑细节→核心总结」逐层讲解，全程聚焦 ChatClient 与工具调用的结合用法，代码可直接落地。
一、工具调用核心定位（先理清核心逻辑）
1. 核心价值
   AI 模型本身的短板：
   无实时信息（如不知道当前时间、实时天气）；
   无执行能力（如不能设闹钟、不能调用业务接口）。
   工具调用的作用：让模型在需要时请求调用外部工具，由应用程序执行工具并返回结果，模型再基于结果生成最终响应。
2. 核心场景
   场景类型	示例	工具作用
   信息检索	查当前时间、查实时天气、查数据库记录	补充模型缺失的实时 / 专属数据
   执行操作	设闹钟、发送邮件、创建数据库记录	执行模型规划的具体动作
3. 核心流程（ChatClient 驱动）

graph TD
A[用户提问] --> B[ChatClient 传递工具给模型]
B --> C[模型判断是否需要调用工具]
C -->|是| D[模型请求调用工具（含参数）]
D --> E[ChatClient 执行工具并返回结果]
E --> F[模型基于工具结果生成响应]
C -->|否| F
F --> G[返回最终响应给用户]



4. 与 ChatClient 的核心结合点
   ChatClient 是工具调用的 “便捷入口”，支持：
   临时工具：仅当前请求可用（tools() 方法）；
   默认工具：所有请求共享（defaultTools() 方法）；
   传递上下文：toolContext() 传递工具执行所需的额外数据（如租户 ID）；
   自动处理工具执行：无需手动解析模型的工具调用请求，框架自动完成。



二、核心组件（提炼高频概念）
组件 / 注解	核心作用	关键说明
@Tool	声明式定义工具（方法级）	核心属性：description（指导模型调用）、returnDirect（是否直接返回结果）、resultConverter（自定义结果转换）
@ToolParam	修饰工具方法参数	核心属性：description（参数说明）、required（是否必填，默认 true）
ToolCallback	工具的核心抽象	所有工具最终都会转为 ToolCallback，包含工具定义（ToolDefinition）和执行逻辑（call() 方法）
ToolDefinition	工具元信息（名称 / 描述 / 参数 Schema）	模型通过它识别工具，名称需全局唯一
ToolContext	工具执行上下文	传递额外数据（如租户 ID），不会发送给模型，仅应用内使用
ToolCallingChatOptions	工具调用配置	用于 ChatModel 级别的工具配置（默认工具、是否手动执行）

步骤 2：基础示例（声明式 @Tool 注解）
最常用的方式，通过 @Tool 注解标记方法为工具，直接传递给 ChatClient。
2.1 定义工具类（时间 + 闹钟）
java
运行
import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.context.i18n.LocaleContextHolder;

import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

// 无需加@Component，仅作为普通类传递给ChatClient
public class DateTimeTools {

    // 工具1：获取当前时间（无参数）
    @Tool(description = "获取用户时区的当前日期和时间，返回ISO-8601格式字符串")
    public String getCurrentDateTime() {
        return LocalDateTime.now()
                .atZone(LocaleContextHolder.getTimeZone().toZoneId())
                .format(DateTimeFormatter.ISO_DATE_TIME);
    }

    // 工具2：设置闹钟（带参数，@ToolParam说明参数格式）
    @Tool(description = "为用户设置指定时间的闹钟，时间参数必须是ISO-8601格式")
    public void setAlarm(
            @ToolParam(description = "闹钟时间，ISO-8601格式（如2026-01-15T10:00:00）") String time) {
        LocalDateTime alarmTime = LocalDateTime.parse(time, DateTimeFormatter.ISO_DATE_TIME);
        System.out.println("✅ 闹钟已设置：" + alarmTime);
    }
}
2.2 结合 ChatClient 使用（临时工具）
java
运行
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.openai.OpenAiChatModel;
import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

@Component
public class ToolCallingDemo implements CommandLineRunner {

    private final ChatClient chatClient;

    // 注入ChatClient（Spring自动配置，基于OpenAI）
    public ToolCallingDemo(OpenAiChatModel openAiChatModel) {
        this.chatClient = ChatClient.builder(openAiChatModel).build();
    }

    @Override
    public void run(String... args) throws Exception {
        // 示例1：调用时间工具，问“明天是几号”
        String timeResponse = chatClient.prompt()
                .user("明天是几号？")
                .tools(new DateTimeTools()) // 传递临时工具（仅当前请求可用）
                .call()
                .content();
        System.out.println("【时间工具响应】：" + timeResponse);

        // 示例2：调用时间+闹钟工具，问“设置10分钟后的闹钟”
        String alarmResponse = chatClient.prompt()
                .user("帮我设置10分钟后的闹钟")
                .tools(new DateTimeTools())
                .call()
                .content();
        System.out.println("【闹钟工具响应】：" + alarmResponse);
    }
}

步骤 3：进阶示例（动态 Bean + 函数式工具）
适合将工具注册为 Spring Bean，通过「工具名称」传递给 ChatClient，无需每次创建实例。
3.1 定义天气工具（函数式 + 动态 Bean）
java
运行
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.annotation.Description;

import java.util.function.Function;

// 1. 定义请求/响应DTO（函数式工具要求POJO，不支持基本类型/集合）
record WeatherRequest(
@ToolParam(description = "城市名称，如北京、上海") String city,
@ToolParam(description = "温度单位，可选C（摄氏度）/F（华氏度），默认C") String unit) {}

record WeatherResponse(String city, double temp, String unit, String desc) {}

// 2. 注册为Spring Bean（动态工具）
@Configuration
public class WeatherToolConfig {

    // 工具名称常量（避免硬编码）
    public static final String WEATHER_TOOL_NAME = "currentWeather";

    // 函数式工具：Function<入参, 出参>
    @Bean(WEATHER_TOOL_NAME)
    @Description("获取指定城市的实时天气，返回温度和天气描述") // 工具描述（指导模型调用）
    public Function<WeatherRequest, WeatherResponse> currentWeather() {
        // 模拟调用天气API，实际可替换为真实接口
        return request -> {
            String unit = request.unit() == null ? "C" : request.unit();
            double temp = switch (request.city()) {
                case "北京" -> -2.5;
                case "上海" -> 5.0;
                default -> 0.0;
            };
            return new WeatherResponse(request.city(), temp, unit, "晴");
        };
    }
}

4.2 自定义结果转换 + 直接返回结果
java
运行
import org.springframework.ai.tool.ToolCallResultConverter;
import org.springframework.ai.tool.annotation.Tool;

// 1. 自定义结果转换器（将对象转为简洁字符串）
class CustomResultConverter implements ToolCallResultConverter {
@Override
public String convert(Object result, java.lang.reflect.Type returnType) {
if (result instanceof String) {
return (String) result;
}
// 简化POJO转换，替代默认的JSON格式
return result.toString().replace("(", "").replace(")", "");
}
}

// 2. 工具：直接返回结果（不传回模型）
public class DirectReturnTools {
@Tool(
description = "查询系统状态，直接返回结果给用户",
returnDirect = true, // 结果直接返回，不传回模型
resultConverter = CustomResultConverter.class // 自定义结果转换
)
public SystemStatus getSystemStatus() {
return new SystemStatus("运行中", "v1.0.0", 99.9);
}

    record SystemStatus(String status, String version, double cpuUsage) {}
}

四、关键细节（避坑 + 最佳实践）
1. 工具命名必须唯一
   同一 ChatClient 请求中，所有工具名称（默认是方法 / Bean 名称）必须全局唯一，否则会覆盖或报错。
2. 类型限制（重点避坑）
   工具类型	支持的参数 / 返回类型	不支持的类型
   方法工具（@Tool）	基本类型、POJO、List/Map、void	Optional、CompletableFuture、Mono/Flux
   函数工具（Function）	仅 POJO（Request/Response）	基本类型、List/Map、Optional、异步 / 响应式类型
3. @ToolParam 注解的重要性
   必须为参数添加 description，模型依赖描述理解参数用法（如 “时间格式为 ISO-8601”）；非必填参数需显式标记 required = false，否则模型会虚构参数值（幻觉）。
4. returnDirect 的使用场景
   returnDirect = true：工具结果直接返回给用户，不传回模型（适合 RAG 检索结果、系统状态查询）；
   若多个工具同时调用，需所有工具都设为 true 才会直接返回。
5. 异常处理
   工具执行失败时，默认会将错误信息返回模型（模型会解释错误）；若需抛出异常，可配置：
   properties
# 工具执行错误时抛出异常（默认false）
spring.ai.tools.throw-exception-on-error=true
五、核心总结（工具调用 + ChatClient 要点）
核心入口：ChatClient 是工具调用最便捷的方式，tools() 传临时工具、defaultTools() 传全局工具，toolContext() 传递额外上下文；
工具定义方式：
声明式：@Tool 注解方法（最简单，适合临时工具）；
编程式：MethodToolCallback/FunctionToolCallback（灵活，适合定制工具元信息）；
动态 Bean：函数式 + @Bean（适合全局复用的工具）；
关键配置：
@ToolParam 必须加描述，指导模型正确传参；
工具名称全局唯一，避免冲突；
returnDirect 可跳过模型后处理，直接返回工具结果；
类型限制：方法工具支持更多类型（基本类型 / 集合），函数工具仅支持 POJO，需根据场景选择。
