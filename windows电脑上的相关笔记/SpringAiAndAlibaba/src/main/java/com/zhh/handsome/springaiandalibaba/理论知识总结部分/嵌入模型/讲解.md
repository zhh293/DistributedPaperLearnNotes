这份文档的核心是 Spring AI 中 Embedding（嵌入）API 的统一抽象 —— 它定义了将文本 / 图像转换为「语义向量」的标准化接口，核心用途是计算文本间的语义相似度（比如 RAG 场景中检索相似文档）。下面帮你提炼「核心概念 + 常用 API + 日常用法」，聚焦开发中最实用的内容：
一、Embedding 核心定位（先搞懂它是干嘛的）
Embedding 是把文本 / 图像 / 视频转换成「浮点数数组（向量）」的技术，核心价值：
向量能捕捉文本的语义特征（比如 “苹果手机” 和 “iPhone” 的向量距离很近，语义相似）；
通过计算向量间的距离（如余弦相似度），可判断原始文本的相似度；
最常用场景：RAG（检索增强生成） —— 先把文档转成向量存入向量库，用户提问时转成向量，检索库中相似文档，再传给 AI 模型生成回答。
二、核心接口：EmbeddingModel（所有嵌入模型的统一抽象）
EmbeddingModel 是 Spring AI 对接所有嵌入模型（如 OpenAI Embedding、Ollama 本地嵌入）的核心接口，日常开发只用关注它的 4 个高频方法：
方法	作用	日常使用频率
float[] embed(String text)	单文本转嵌入向量（最基础）	✅ 最高频
List<float[]> embed(List<String> texts)	批量文本转向量（效率更高）	✅ 高频（处理多文档）
float[] embed(Document document)	结构化文档转向量（带元数据）	✅ 中高频（RAG 场景）
EmbeddingResponse call(EmbeddingRequest request)	核心底层方法（自定义参数）	✅ 中低频（需定制参数时用）
关键说明：
所有快捷方法（如 embed(String)）最终都基于 call(EmbeddingRequest) 实现；
向量的「维度」：不同模型生成的向量长度不同（如 OpenAI 的 text-embedding-3-small 是 1536 维），可通过 dimensions() 方法快速获取。
三、关键核心类：输入 - 输出 结构
和 Chat Model API 类似，Embedding API 也有「输入封装 + 输出解析」的标准化类：
1. 输入：EmbeddingRequest
   封装嵌入请求的输入和参数，核心结构：
   java
   运行
   public class EmbeddingRequest {
   private final List<String> inputs; // 要转向量的文本列表
   private final EmbeddingOptions options; // 嵌入模型参数（如指定模型、维度）
   }
   EmbeddingOptions：嵌入模型的参数（如 OpenAI 可指定 model: text-embedding-3-small）；
   日常简化：大部分场景不用手动构建，直接调用 embed(String) 即可（底层自动封装）。
2. 输出：EmbeddingResponse + Embedding
   解析嵌入模型的响应结果：
   类	核心作用
   EmbeddingResponse	封装批量响应：包含 List<Embedding>（每个文本对应的向量） + 元数据（如 Token 消耗）
   Embedding	单个文本的嵌入结果：核心是 float[] embedding（向量数组） + index（对应输入文本的序号）

Embedding 与 ChatClient 最核心、最紧密的结合场景是 RAG（检索增强生成） —— 简单说：Embedding 负责「检索和用户提问语义相似的私有文档」，ChatClient 负责「把这些文档作为上下文，传给 AI 模型生成基于私有文档的回答」。
下面我会从「核心逻辑→环境准备→完整代码实现→关键细节→优化点」超详细讲解，全程复用你现有的 ChatClient 配置，确保代码能直接融入你的项目。




flowchart TD
A[私有文档库] -->|1. 预处理：Embedding 转向量| B[向量库（如 Redis/PGVector）]
C[用户提问] -->|2. Embedding 转向量| D[提问向量]
D -->|3. 向量库检索| E[相似文档（TopN）]
E -->|4. 拼入 Prompt 上下文| F[ChatClient 构建带文档的 Prompt]
F -->|5. 调用 AI 模型| G[基于私有文档的回答]


核心角色分工：
EmbeddingModel：负责 “文本→向量” 转换（文档入库、用户提问转向量）；
VectorStore：负责向量存储和相似检索（承上启下）；
ChatClient：负责把 “相似文档 + 用户提问” 封装成 Prompt，调用 AI 模型生成回答。

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.embedding.EmbeddingModel;
import org.springframework.ai.openai.OpenAiChatModel;
import org.springframework.ai.redis.store.RedisVectorStore;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.connection.RedisConnectionFactory;

@Configuration
public class AiConfig {

    // 你原有的 ChatClient Bean（复用，仅补充注释）
    @Bean
    public ChatClient chatClient(OpenAiChatModel openAiChatModel) {
        return ChatClient.builder(openAiChatModel)
                .defaultSystem("你是一个基于私有文档回答问题的助手，严格按照提供的文档内容回答，不要编造信息。")
                .defaultOptions(openAiChatModel.getDefaultOptions())
                .build();
    }

    // 配置 VectorStore（Redis 向量库，依赖 EmbeddingModel 做向量转换）
    @Bean
    public VectorStore vectorStore(EmbeddingModel embeddingModel, RedisConnectionFactory redisConnectionFactory) {
        // RedisVectorStore 自动用 EmbeddingModel 处理文本→向量
        return new RedisVectorStore(redisConnectionFactory, embeddingModel);
    }
}
关键说明：
VectorStore 是 Spring AI 封装的向量库抽象，RedisVectorStore 是其实现，只需传入 Redis 连接工厂和 EmbeddingModel 即可；
你的 ChatClient 无需修改，仅补充了「基于私有文档回答」的默认系统提示词（核心！确保 AI 优先用检索到的文档回答）。

步骤 3：核心业务逻辑（检索相似文档 + ChatClient 生成回答）
这是 Embedding 与 ChatClient 结合的核心，封装成工具类 / 接口：
java
运行
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.stream.Collectors;

@Service
public class RagService {

    private final VectorStore vectorStore;
    private final ChatClient chatClient;

    // 注入向量库和你配置的 ChatClient
    public RagService(VectorStore vectorStore, ChatClient chatClient) {
        this.vectorStore = vectorStore;
        this.chatClient = chatClient;
    }

    /**
     * 核心方法：基于 RAG 生成回答
     * @param userQuestion 用户提问
     * @return 基于私有文档的回答
     */
    public String ragAnswer(String userQuestion) {
        // 步骤1：检索相似文档（Embedding 核心作用）
        List<Document> similarDocs = searchSimilarDocuments(userQuestion, 3); // 检索 Top3 相似文档

        // 步骤2：构造 Prompt 上下文（把相似文档拼入 Prompt）
        String context = buildContextFromDocs(similarDocs);

        // 步骤3：调用 ChatClient，传入「上下文+用户提问」生成回答
        return chatClient.prompt()
                // 系统消息：补充检索到的文档上下文（覆盖默认系统消息的不足）
                .system(s -> s.text("以下是回答问题的参考文档：\n" + context))
                // 用户消息：原始提问
                .user(userQuestion)
                // 同步调用，获取回答
                .call()
                .content();
    }

    /**
     * 检索相似文档：用户提问转向量 → 向量库检索 TopN 相似文档
     */
    private List<Document> searchSimilarDocuments(String userQuestion, int topN) {
        // 构建检索请求：指定提问文本、返回数量、相似度阈值（0.7 过滤低相似结果）
        SearchRequest searchRequest = SearchRequest.query(userQuestion)
                .withTopK(topN)
                .withSimilarityThreshold(0.7f);

        // 向量库自动把用户提问转成向量，检索相似文档
        return vectorStore.similaritySearch(searchRequest);
    }

    /**
     * 构造上下文：把检索到的文档拼接成字符串，传给 AI 模型
     */
    private String buildContextFromDocs(List<Document> docs) {
        if (docs.isEmpty()) {
            return "未找到相关参考文档，请基于通用知识回答。";
        }
        // 拼接文档内容（保留元数据，方便调试）
        return docs.stream()
                .map(doc -> String.format("【文档元数据】：%s\n【文档内容】：%s\n",
                        doc.getMetadata(), doc.getContent()))
                .collect(Collectors.joining("\n---\n"));
    }
}
关键说明：
searchSimilarDocuments()：
SearchRequest 是检索请求封装类，query(userQuestion) 会自动把提问转成向量；
withTopK(3)：返回最相似的 3 条文档；withSimilarityThreshold(0.7f)：过滤相似度低于 0.7 的文档（避免无关内容）。
buildContextFromDocs()：把检索到的文档拼接成清晰的上下文，传给 AI 模型，确保模型能看到完整的参考文档。
ChatClient 调用：通过 .system() 把上下文传给 AI，.user() 传原始提问，AI 会基于上下文生成回答。
