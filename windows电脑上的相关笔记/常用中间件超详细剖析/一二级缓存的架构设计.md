# 一二级缓存架构设计 - Spring Boot Redis-Caffeine 实现

## 项目概述

本项目是一个基于Spring Boot的二级缓存解决方案，结合了Caffeine本地缓存和Redis分布式缓存的优势，提供了高性能、高可用的缓存架构。

### 核心特性
- 🚀 **高性能**: Caffeine本地缓存提供纳秒级访问速度
- 🌐 **分布式一致性**: Redis保证多实例间缓存数据一致性
- ⚙️ **灵活配置**: 支持细粒度的缓存策略配置
- 🔄 **自动同步**: 基于Redis Pub/Sub的自动缓存同步机制
- 🛡️ **安全防护**: 内置缓存穿透防护机制
- 📦 **开箱即用**: Spring Boot Starter模式，简单集成

## 架构设计原理

### 二级缓存架构图

```
+----------------+      +-----------------+      +---------------+
|   Application  |      |   L1 Cache      |      |   L2 Cache    |
|    Layer       |      |  (Caffeine)     |      |   (Redis)     |
+----------------+      +-----------------+      +---------------+
        |                      |                      |
        | 1. Cache Request     | 2. Check L1          | 3. Check L2
        |-------------------->|-------------------->|
        |                      |                      |
        | 6. Return Data       | 4.1 Cache Hit        | 4.2 Cache Miss
        |<---------------------|<---------------------|
        |                      |                      |
        |                      | 5.1 Store in L1      | 5.2 Load from DB
        |                      |<---------------------|-----------------> Database
        |                      |                      |
        |                      | 7. Sync Notification | 7. Pub/Sub Message
        |                      |<---------------------|<-----------------+
        |                      |                      |                |
        |                      | 8. Invalidate L1     |                |
        |                      |---------------------->                |
        |                      |                      |                |
        +----------------------+----------------------+----------------+
```

### 核心设计思想

1. **读写策略**: 先读L1，再读L2，最后读DB
2. **写策略**: 写L2，同时清除所有实例的L1缓存
3. **同步策略**: 基于Redis Pub/Sub的发布订阅模式
4. **一致性保证**: 通过消息广播确保多实例缓存一致性

## 核心实现细节

### 1. RedisCaffeineCache - 二级缓存核心实现

#### 类结构
```java
public class RedisCaffeineCache extends AbstractValueAdaptingCache {
    private String cacheName;              // 缓存名称
    private Cache<Object, Object> level1Cache; // Caffeine一级缓存
    private RedisCache level2Cache;        // Redis二级缓存
    private long defaultExpiration;        // 默认过期时间
    private Map<String, Long> expires;     // 各缓存过期时间配置
    private AtomicBoolean openedL1Cache;  // L1缓存开启状态
    private String topic;                  // Redis消息主题
    private Map<String, ReentrantLock> keyLockMap; // 键级别锁
}
```

#### 核心方法实现

##### 缓存查找 (lookup)
```java
@Override
protected Object lookup(Object key) {
    String keyStr = key.toString();
    
    // 1. 首先检查一级缓存
    Object value = level1Cache.getIfPresent(keyStr);
    if (value != null) {
        logger.debug("get cache from level1 cache, the key is : {}", keyStr);
        return value;
    }
    
    // 2. 一级缓存未命中，检查二级缓存
    value = level2Cache.get(keyStr);
    if (value != null) {
        logger.debug("get cache from level2 cache, the key is : {}", keyStr);
        
        // 3. 将二级缓存数据加载到一级缓存
        if (isOpenL1Cache(keyStr)) {
            level1Cache.put(keyStr, value);
            openedL1Cache.set(true);
        }
        return value;
    }
    
    return null;
}
```

##### 缓存获取 (get with valueLoader)
```java
@Override
public <T> T get(Object key, Callable<T> valueLoader) {
    Object value = lookup(key);
    if (value != null) {
        return (T) value;
    }
    
    // 使用键级别锁防止缓存击穿
    ReentrantLock lock = keyLockMap.computeIfAbsent(key.toString(), k -> new ReentrantLock());
    lock.lock();
    
    try {
        // 双重检查锁定模式
        value = lookup(key);
        if (value != null) {
            return (T) value;
        }
        
        // 从数据加载器获取数据
        value = valueLoader.call();
        
        // 将数据写入缓存
        put(key, value);
        
        return (T) value;
    } finally {
        lock.unlock();
        keyLockMap.remove(key.toString());
    }
}
```

##### 缓存写入 (put)
```java
@Override
public void put(Object key, Object value) {
    String keyStr = key.toString();
    
    // 1. 写入二级缓存
    if (expires.containsKey(cacheName)) {
        level2Cache.set(keyStr, value, expires.get(cacheName));
    } else {
        level2Cache.set(keyStr, value, defaultExpiration);
    }
    
    // 2. 清除本地一级缓存
    clearLocal(key);
    
    // 3. 发布缓存更新消息
    publishMessage(keyStr);
}
```

### 2. RedisCaffeineCacheManager - 缓存管理器

#### 缓存创建策略
```java
@Override
public Cache getCache(String name) {
    Cache cache = cacheMap.get(name);
    if (cache != null) {
        return cache;
    }
    
    // 动态缓存创建检查
    if (!dynamic && !cacheNames.contains(name)) {
        return cache;
    }
    
    // 创建新的缓存实例
    cache = new RedisCaffeineCache(name, redisService, caffeineCache(), l2CacheConfig);
    Cache oldCache = cacheMap.putIfAbsent(name, cache);
    
    logger.debug("create cache instance, the cache name is : {}", name);
    return oldCache == null ? cache : oldCache;
}
```

#### Caffeine缓存配置
```java
public com.github.benmanes.caffeine.cache.Cache<Object, Object> caffeineCache() {
    Caffeine<Object, Object> cacheBuilder = Caffeine.newBuilder();
    
    // 灵活的Caffeine配置
    if (l2CacheConfig.getCaffeine().getExpireAfterAccess() > 0) {
        cacheBuilder.expireAfterAccess(
            l2CacheConfig.getCaffeine().getExpireAfterAccess(), 
            TimeUnit.SECONDS
        );
    }
    
    if (l2CacheConfig.getCaffeine().getExpireAfterWrite() > 0) {
        cacheBuilder.expireAfterWrite(
            l2CacheConfig.getCaffeine().getExpireAfterWrite(), 
            TimeUnit.SECONDS
        );
    }
    
    if (l2CacheConfig.getCaffeine().getInitialCapacity() > 0) {
        cacheBuilder.initialCapacity(l2CacheConfig.getCaffeine().getInitialCapacity());
    }
    
    if (l2CacheConfig.getCaffeine().getMaximumSize() > 0) {
        cacheBuilder.maximumSize(l2CacheConfig.getCaffeine().getMaximumSize());
    }
    
    if (l2CacheConfig.getCaffeine().getRefreshAfterWrite() > 0) {
        cacheBuilder.refreshAfterWrite(
            l2CacheConfig.getCaffeine().getRefreshAfterWrite(), 
            TimeUnit.SECONDS
        );
    }
    
    return cacheBuilder.build();
}
```

### 3. 缓存同步机制

#### 消息结构
```java
@Data
@AllArgsConstructor
@NoArgsConstructor
public class CacheMessage implements Serializable {
    private static final long serialVersionUID = 5987219310442078193L;
    
    /** 缓存名称 */
    private String cacheName;
    
    /** 缓存key */
    private Object key;
}
```

#### 消息监听器
```java
@Override
public void onMessage(Message message, byte[] pattern) {
    // 反序列化消息
    CacheMessage cacheMessage = (CacheMessage) redisService.getRedisTemplate()
        .getValueSerializer().deserialize(message.getBody());
    
    logger.debug("recevice a redis topic message, clear local cache, " +
        "the cacheName is {}, the key is {}", 
        cacheMessage.getCacheName(), cacheMessage.getKey());
    
    // 清除本地缓存
    redisCaffeineCacheManager.clearLocal(cacheMessage.getCacheName(), cacheMessage.getKey());
}
```

#### 消息发布
```java
private void publishMessage(String key) {
    CacheMessage message = new CacheMessage(cacheName, key);
    
    // 发布到Redis频道
    redisService.getRedisTemplate().convertAndSend(topic, message);
    
    logger.debug("publish redis topic message, the cacheName is {}, the key is {}", 
        cacheName, key);
}
```

## 自动配置机制

### Spring Boot Starter

#### 自动配置类
```java
@Configuration
@AutoConfigureAfter(RedisAutoConfiguration.class)
@EnableConfigurationProperties(L2CacheProperties.class)
public class CacheRedisCaffeineAutoConfiguration {
    
    @Autowired
    private L2CacheProperties l2CacheProperties;
    
    @Bean
    @ConditionalOnClass(RedisCache.class)
    @Order(2)
    public RedisCaffeineCacheManager cacheManager(RedisCache redisCache) {
        return new RedisCaffeineCacheManager(
            l2CacheProperties.getConfig(), 
            redisCache
        );
    }
    
    @Bean
    @ConditionalOnMissingBean(name = "stringKeyRedisTemplate")
    public RedisTemplate<Object, Object> stringKeyRedisTemplate(
        RedisConnectionFactory redisConnectionFactory) throws UnknownHostException {
        
        RedisTemplate<Object, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(redisConnectionFactory);
        
        // 使用字符串序列化器
        RedisSerializer stringSerializer = new StringRedisSerializer();
        template.setKeySerializer(stringSerializer);
        template.setHashKeySerializer(stringSerializer);
        
        return template;
    }
    
    @Bean
    @ConditionalOnClass(RedisCache.class)
    @Order(3)
    public RedisMessageListenerContainer redisMessageListenerContainer(
        RedisCache redisCache, RedisCaffeineCacheManager cacheManager) {
        
        RedisMessageListenerContainer container = new RedisMessageListenerContainer();
        container.setConnectionFactory(redisCache.getRedisTemplate().getConnectionFactory());
        
        CacheMessageListener listener = new CacheMessageListener(redisCache, cacheManager);
        container.addMessageListener(listener, 
            new ChannelTopic(l2CacheProperties.getConfig().getRedis().getTopic()));
        
        return container;
    }
    
    @Bean
    @ConditionalOnBean(RedisTemplate.class)
    @Order(1)
    public RedisCache redisCache(RedisTemplate<Object, Object> stringKeyRedisTemplate) {
        RedisCache redisCache = new RedisCache();
        redisCache.setRedisTemplate(stringKeyRedisTemplate);
        return redisCache;
    }
}
```

### 3. 代码使用
```java
@Service
public class UserService {
    
    /**
     * 获取用户信息 - 自动使用二级缓存
     */
    @Cacheable(key = "'user_id_' + #userId", value = "userCache")
    public UserDTO getUser(String userId) {
        // 从数据库加载数据
        return userRepository.findById(userId);
    }
    
    /**
     * 更新用户信息 - 自动更新缓存
     */
    @CachePut(key = "'user_id_' + #user.userId", value = "userCache")
    public UserDTO updateUser(UserDTO user) {
        // 更新数据库
        userRepository.update(user);
        return user;
    }
    
    /**
     * 删除用户 - 自动清除缓存
     */
    @CacheEvict(key = "'user_id_' + #userId", value = "userCache")
    public void deleteUser(String userId) {
        userRepository.delete(userId);
    }
}
```

## 性能优化策略

### 1. 缓存命中率优化
- **本地缓存**: Caffeine基于W-TinyLFU算法，提供高命中率
- **内存管理**: 自动淘汰不常用的缓存项
- **容量控制**: 支持设置最大缓存项数量

### 2. 并发性能优化
- **键级别锁**: 防止缓存击穿
- **无锁读取**: 一级缓存读取无需加锁
- **异步操作**: Redis操作使用连接池

### 3. 网络优化
- **本地优先**: 减少网络IO，优先使用本地缓存
- **批量操作**: Redis支持批量操作命令
- **连接池**: 使用连接池管理Redis连接

## 容错与监控

### 1. 异常处理
- **Redis宕机**: 降级为纯本地缓存模式
- **网络异常**: 重试机制和超时控制
- **序列化异常**: 统一的异常处理

### 2. 监控指标
- 缓存命中率（L1/L2）
- 缓存加载时间
- 缓存大小统计
- 同步消息数量

## 最佳实践

### 适用场景
1. **高并发读场景**: 如商品详情、用户信息查询
2. **分布式系统**: 多实例部署需要缓存一致性
3. **热点数据**: 频繁访问的数据适合本地缓存

### 不适用场景
1. **大数据量**: 不适合缓存大量数据
2. **极低命中率**: 命中率低的业务场景
3. **实时性要求极高**: 需要毫秒级数据一致性

### 配置建议
1. **缓存大小**: 根据内存情况合理设置
2. **过期时间**: 根据业务特点设置不同过期策略
3. **监控告警**: 设置缓存命中率告警阈值
