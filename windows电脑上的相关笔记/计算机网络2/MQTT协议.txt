MQTT协议这个名字看起来就跟消息队列有关系，其实跟我们平常所学的AMQP协议是不一样的
AMQP协议是专门跟rabbitmq通信的一种固定协议，就像数据库mysql的协议，redis通信的协议等等，这些我们完全可以使用netty进行编写并完成与中间件的通话





一、MQTT 协议核心讲解
1. 什么是 MQTT？（概念）
MQTT 的全称是Message Queuing Telemetry Transport（消息队列遥测传输），你可以把它理解成物联网界的 “轻量快递系统”：
它是一种基于发布 / 订阅模式的通信协议，专门为「低带宽、网络不稳定、设备算力弱」的场景设计（比如传感器、智能家居设备）；
核心特点：报文极小（最小固定头部仅 2 字节）、低功耗、双向通信、支持断网重连；
对比理解：如果说 HTTP 是 “打电话（一问一答）”，那 MQTT 就是 “微信群（一人发，多人收）”，更适合设备间的实时消息推送。



2. MQTT 工作原理（核心架构 + 关键机制）
（1）核心角色（3 个）
用 “快递” 比喻帮你理解：

角色	类比	作用
Publisher（发布者）	寄快递的人	发送消息的一方（比如温湿度传感器、手机 APP）
Subscriber（订阅者）	收快递的人	接收消息的一方（比如服务器、智能灯、APP）
Broker（代理）	快递站	中间中转站，接收发布者消息并转发给订阅者




    A[发布者（传感器）] -->|发送消息到「主题」| B[MQTT Broker（快递站）]
    C[订阅者（APP）] -->|订阅「主题」| B
    D[订阅者（服务器）] -->|订阅「主题」| B
    B -->|转发消息| C
    B -->|转发消息| D




通俗解释：
传感器（发布者）把 “温度 25℃” 的消息，发到 Broker 的 “home/bedroom/temp” 地址（主题）；
你的手机 APP 和家里的服务器（订阅者）都提前订阅了 “home/bedroom/temp” 这个地址；
Broker 自动把 “温度 25℃” 的消息转发给这两个订阅者。




（3）关键机制（新手必懂）
这些机制是 MQTT 的核心优势，用场景化解释：
主题（Topic）：消息的 “地址”，支持层级划分（比如home/bedroom/temp、home/livingroom/light），订阅者可以用通配符（+匹配单层、#匹配多层），比如home/+/temp能订阅所有房间的温度；
QoS（服务质量）：消息投递的 “保障级别”，按需选择：
QoS 0：最多一次（发了不管收没收到）→ 适合实时数据（比如温度、心率，丢一条不影响）；
QoS 1：至少一次（确保送到，可能重复）→ 适合设备指令（比如 “打开空调”，必须到，重复也能处理）；
QoS 2：恰好一次（确保只到一次）→ 适合支付、计费等敏感场景（避免重复扣费）；
遗嘱消息（Will Message）：设备 “临终遗言”→ 设备和 Broker 断开时（比如断电），Broker 自动替设备发消息（比如 “传感器 1 号离线了”）；
保留消息：Broker 保存某个主题的最后一条消息→ 新订阅者一上线就能收到（比如新打开 APP，直接看到当前温度，不用等传感器下次发）。
3. MQTT 的用处（实际场景）
MQTT 的核心价值是「轻量、实时、低功耗」，主要用在这些场景：
智能家居：传感器发温湿度→服务器存数据→APP 订阅查看；手机发 “开灯” 指令→智能灯订阅执行；
物联网监控：工业机床、农业大棚传感器实时上报运行 / 环境数据，后台监控异常；
车联网：车载设备上报位置、油耗→后台下发导航 / 告警指令；
移动应用：轻量即时通讯、APP 推送通知（比 WebSocket 更省流量）；
偏远地区设备通信：山区气象站、海洋监测设备（卫星网络带宽低，MQTT 报文小更适配）。









二、SpringBoot 整合 MQTT（实战步骤）
1. 前置准备
首先需要一个 MQTT Broker（快递站），推荐用轻量免费的Eclipse Mosquitto：
（1）安装 Mosquitto（以 Windows 为例）
下载地址：https://mosquitto.org/download/
安装后修改mosquitto.conf，注释掉# allow_anonymous false（允许匿名连接，新手简化）；
启动 Mosquitto：mosquitto -c mosquitto.conf；
验证：用可视化工具MQTTX（免费）连接tcp://localhost:1883，能连接就说明 Broker 正常。

  mqtt:
    # Broker地址（tcp协议，默认端口1883）
    broker-url: tcp://localhost:1883
    # 客户端ID（唯一，建议加随机数避免冲突）
    client-id: springboot-mqtt-client-${random.value}
    # 用户名/密码（如果Mosquitto没配置则留空）
    username: 
    password: 
    # 默认订阅主题（可多个，用逗号分隔）

    # QoS级别（默认1）
    qos: 1
    # 连接超时时间（秒）
    timeout: 30
    # 遗嘱消息配置
    will:
      topic: home/device/status
      message: springboot-client-offline
      qos: 1
      retained: true






步骤 3：编写 MQTT 配置类（核心）
这个类负责创建 MQTT 连接、发送 / 接收消息的组件：



import org.eclipse.paho.client.mqttv3.MqttConnectOptions;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.integration.annotation.ServiceActivator;
import org.springframework.integration.channel.DirectChannel;
import org.springframework.integration.core.MessageProducer;
import org.springframework.integration.mqtt.core.DefaultMqttPahoClientFactory;
import org.springframework.integration.mqtt.core.MqttPahoClientFactory;
import org.springframework.integration.mqtt.inbound.MqttPahoMessageDrivenChannelAdapter;
import org.springframework.integration.mqtt.outbound.MqttPahoMessageHandler;
import org.springframework.integration.mqtt.support.DefaultPahoMessageConverter;
import org.springframework.messaging.MessageChannel;
import org.springframework.messaging.MessageHandler;

/**
 * MQTT核心配置类
 */
@Configuration
public class MqttConfig {

    // 从配置文件读取参数
    @Value("${spring.mqtt.broker-url}")
    private String brokerUrl;
    @Value("${spring.mqtt.client-id}")
    private String clientId;
    @Value("${spring.mqtt.username}")
    private String username;
    @Value("${spring.mqtt.password}")
    private String password;
    @Value("${spring.mqtt.default-topic}")
    private String defaultTopic;
    @Value("${spring.mqtt.qos}")
    private int qos;
    @Value("${spring.mqtt.timeout}")
    private int timeout;
    @Value("${spring.mqtt.will.topic}")
    private String willTopic;
    @Value("${spring.mqtt.will.message}")
    private String willMessage;
    @Value("${spring.mqtt.will.qos}")
    private int willQos;
    @Value("${spring.mqtt.will.retained}")
    private boolean willRetained;

    /**
     * 1. 创建MQTT连接配置
     */
    @Bean
    public MqttConnectOptions mqttConnectOptions() {
        MqttConnectOptions options = new MqttConnectOptions();
        // 设置Broker地址
        options.setServerURIs(new String[]{brokerUrl});
        // 设置用户名密码（如果有）
        if (username != null && !username.isEmpty()) {
            options.setUserName(username);
        }
        if (password != null && !password.isEmpty()) {
            options.setPassword(password.toCharArray());
        }
        // 设置连接超时时间
        options.setConnectionTimeout(timeout);
        // 设置自动重连
        options.setAutomaticReconnect(true);
        // 设置遗嘱消息
        options.setWill(willTopic, willMessage.getBytes(), willQos, willRetained);
        return options;
    }

    /**
     * 2. 创建MQTT客户端工厂
     */
    @Bean
    public MqttPahoClientFactory mqttClientFactory() {
        DefaultMqttPahoClientFactory factory = new DefaultMqttPahoClientFactory();
        factory.setConnectionOptions(mqttConnectOptions());
        return factory;
    }

    /**
     * 3. 消息接收通道（用于接收MQTT消息）
     */
    @Bean
    public MessageChannel mqttInputChannel() {
        return new DirectChannel();
    }

    /**
     * 4. 消息驱动适配器（监听MQTT主题，接收消息）
     */
    @Bean
    public MessageProducer inbound() {
        // 监听默认主题
        MqttPahoMessageDrivenChannelAdapter adapter =
                new MqttPahoMessageDrivenChannelAdapter(clientId + "-in", mqttClientFactory(),
                        defaultTopic.split(","));
        // 设置消息转换器（指定QoS）
        adapter.setConverter(new DefaultPahoMessageConverter(qos));
        // 设置消息接收通道
        adapter.setOutputChannel(mqttInputChannel());
        return adapter;
    }

    /**
     * 5. 消息发送通道（用于发送MQTT消息）
     */
    @Bean
    public MessageChannel mqttOutputChannel() {
        return new DirectChannel();
    }

    /**
     * 6. 消息发送处理器（发送MQTT消息）
     */
    @Bean
    @ServiceActivator(inputChannel = "mqttOutputChannel")
    public MessageHandler mqttOutbound() {
        MqttPahoMessageHandler handler =
                new MqttPahoMessageHandler(clientId + "-out", mqttClientFactory());
        // 设置默认QoS
        handler.setDefaultQos(qos);
        // 保留消息默认关闭
        handler.setDefaultRetained(false);
        return handler;
    }
}





步骤 4：编写消息接收处理器（处理收到的 MQTT 消息）


import org.springframework.integration.annotation.MessageEndpoint;
import org.springframework.integration.annotation.ServiceActivator;
import org.springframework.messaging.Message;
import org.springframework.messaging.MessageHeaders;

/**
 * MQTT消息接收处理器
 */
@MessageEndpoint
public class MqttMessageReceiver {

    /**
     * 处理接收到的MQTT消息
     * @param message 消息体（包含内容和头部信息）
     */
    @ServiceActivator(inputChannel = "mqttInputChannel")
    public void handleMqttMessage(Message<?> message) {
        // 获取消息内容
        String payload = message.getPayload().toString();
        // 获取消息头部（包含主题、QoS等信息）
        MessageHeaders headers = message.getHeaders();
        String topic = headers.get("mqtt_receivedTopic").toString();
        int qos = (int) headers.get("mqtt_receivedQos");

        // 业务处理：打印、入库、调用接口等
        System.out.println("=====================");
        System.out.println("收到MQTT消息：");
        System.out.println("主题：" + topic);
        System.out.println("QoS：" + qos);
        System.out.println("内容：" + payload);
        System.out.println("=====================");

        // 示例：如果是“开灯”指令，调用业务逻辑
        if ("home/bedroom/light".equals(topic) && "on".equals(payload)) {
            System.out.println("执行业务逻辑：打开卧室灯");
        }
    }
}



步骤 5：编写 MQTT 工具类（发送消息）
封装发送消息的方法，方便业务调用：

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.integration.support.MessageBuilder;
import org.springframework.messaging.MessageChannel;
import org.springframework.stereotype.Component;

/**
 * MQTT消息发送工具类
 */
@Component
public class MqttMessageSender {

    @Autowired
    private MessageChannel mqttOutputChannel;

    /**
     * 发送MQTT消息（默认QoS=1，不保留）
     * @param topic 主题
     * @param payload 消息内容
     */
    public void sendMessage(String topic, String payload) {
        sendMessage(topic, payload, 1, false);
    }

    /**
     * 发送MQTT消息（自定义QoS和保留）
     * @param topic 主题
     * @param payload 消息内容
     * @param qos QoS级别
     * @param retained 是否保留消息
     */
    public void sendMessage(String topic, String payload, int qos, boolean retained) {
        // 构建消息（包含主题、QoS、保留标识）
        mqttOutputChannel.send(MessageBuilder.withPayload(payload)
                .setHeader("mqtt_topic", topic)
                .setHeader("mqtt_qos", qos)
                .setHeader("mqtt_retained", retained)
                .build());
        System.out.println("发送MQTT消息成功：主题=" + topic + "，内容=" + payload);
    }
}

三、SpringBoot+MQTT 能做什么？
整合后，你可以基于 MQTT 实现这些实际业务功能：
物联网数据采集：接收传感器（温湿度、电量、位置）的实时数据，存入数据库 / Redis，供前端展示或数据分析；
远程设备控制：通过 HTTP 接口下发指令（比如 “打开空调”“调整灯光亮度”），设备订阅主题后执行指令；
设备状态监控：利用遗嘱消息，实时监控设备是否在线，离线则触发告警（比如推钉钉 / 短信给运维人员）；
多端消息推送：给多个 APP / 小程序 / 设备推送通知（比如 “家里漏水了”），只需往指定主题发一条消息，所有订阅者都能收到；
跨系统 / 微服务通信：轻量场景下，替代 Kafka/RabbitMQ，实现微服务间的异步消息通信（比如订单系统发消息给库存系统）；
日志上报：嵌入式设备 / 边缘节点的日志，通过 MQTT 上报到服务器，统一存储和分析。
总结
MQTT 核心：基于发布 / 订阅模式的轻量协议，核心是 Broker（中转站）、Topic（主题）、QoS（消息保障），适合物联网 / 低带宽场景；
SpringBoot 整合关键：配置连接参数→创建发送 / 接收通道→编写消息处理器，核心依赖是spring-integration-mqtt；
整合后价值：实现设备数据采集、远程控制、状态监控、多端推送等功能，是物联网项目的核心通信方案。




举个生活化例子（瞬间理解）
假设你要给两类 “终端” 发消息：
给手机 / 服务器发消息：用 Kafka/RabbitMQ 没问题 —— 它们算力足、带宽够，能处理复杂报文和高并发；
给山区的太阳能气象传感器发消息：
传感器：算力只有几 KB，靠太阳能供电，网络是 2G 窄带，每天只能醒 10 分钟上报数据；
若用 Kafka：传感器连 Kafka 的客户端都装不上（客户端体积几十 MB），报文头部就占了几百字节，2G 网络发一次就耗光电量，断网后直接丢连接；
若用 MQTT：MQTT 客户端（如 Paho）体积只有几十 KB，报文头部 2 字节，断网后自动重连，传感器一次发送仅耗几毫安电量，完美适配。
三、为什么物联网场景不能直接用传统消息队列？
结合你之前提到的 “物联网数据采集、远程设备控制” 场景，具体说 3 个核心原因：
1. 设备硬件撑不住
传统消息队列的客户端（如 Kafka 的 Java 客户端、RabbitMQ 的 AMQP 客户端）：
体积大：动辄几十 MB，而物联网设备（如 ESP8266 单片机）的闪存只有 1MB，根本装不下；
算力要求高：需要 JVM / 高级语言运行环境，而单片机连操作系统都没有，只能跑裸机代码；
MQTT 客户端：C 语言编写的 MQTT 客户端（如 Eclipse Paho C）体积仅几十 KB，能直接跑在单片机上，无需操作系统。
2. 网络带宽 / 功耗扛不住
传统消息队列的报文：包含大量元数据（如分区、offset、事务 ID），一条简单的 “温度 25℃” 消息，封装后可能几百字节；
MQTT 报文：“温度 25℃” 封装后仅十几字节，在 2G / 蓝牙 / 卫星等窄带网络中，传输效率提升 10 倍以上；
功耗：物联网设备多为电池 / 太阳能供电，MQTT 的 “休眠 - 唤醒” 机制能把功耗降到 μA 级，而传统 MQ 客户端持续占用网络 / CPU，电池几小时就耗光。
3. 设备离线场景适配不了
物联网设备离线是常态（断电、断网、信号差）：
MQTT 的遗嘱消息：设备断电时，Broker 自动替设备发 “传感器离线”，后台能实时感知；
MQTT 的保留消息：设备重新上线后，能立即拿到主题的最后一条消息（比如传感器上线后直接拿到最新的控制指令）；
传统消息队列：无原生的 “设备离线感知”“断网重连后补消息” 机制，需要额外开发大量代码适配，且效果差。
四、两者的正确使用姿势（不是二选一，而是互补）
实际项目中，MQTT 和传统消息队列往往是配合使用，而非替代：



典型流程：
传感器（MQTT 发布者）→ Mosquitto（MQTT Broker）→ SpringBoot（订阅者）：接收设备的轻量消息；
SpringBoot 将消息清洗、格式化后，转发到 Kafka：供大数据平台做批量分析、存储（Kafka 擅长高吞吐）；
微服务集群（如告警系统）从 Kafka 消费消息，生成 “设备离线告警” 指令；
SpringBoot 将告警指令通过 MQTT 发送到 Mosquitto，转发给运维 APP / 网关设备。


总结
核心差异：MQTT 和传统消息队列虽同属发布订阅模式，但 MQTT 为「物联网小设备、弱网络」设计，传统 MQ 为「服务器 / 微服务、强网络」设计；
不可替代原因：物联网设备的硬件、功耗、网络特性，决定了传统 MQ 无法适配，而 MQTT 的轻量化、低功耗、离线适配特性是刚需；
最佳实践：物联网场景中，MQTT 负责 “设备端通信”，传统 MQ 负责 “服务器端高吞吐处理”，两者配合实现端到云的完整链路。
