# 评论系统架构设计

## 一、问题背景

### 1.1 业务场景分析

评论系统是互联网应用中最常见的UGC（User Generated Content，用户生成内容）模块之一。无论是电商平台的商品评价、社交媒体的帖子评论、视频网站的弹幕互动，还是新闻资讯的读者反馈，评论功能都扮演着至关重要的角色。它承载着用户与内容之间、用户与用户之间的互动桥梁。

一个典型的评论系统需要支持以下核心能力：

- **发表评论**：用户针对某个主题（文章、商品、视频等）发表文字评论
- **回复评论**：用户可以针对已有评论进行回复，形成讨论线程
- **评论展示**：按照一定规则（时间、热度）对评论进行排序展示
- **评论审核**：对评论内容进行敏感词过滤、反垃圾检测
- **互动功能**：点赞、踩、举报等互动操作
- **分页加载**：高效地分页展示海量评论数据

### 1.2 技术挑战

构建一个高性能、高可用的评论系统面临以下核心挑战：

**1）数据量大、增长快**

对于日活用户超过千万的平台，每天的评论数可达数百万甚至数千万条。随着业务发展，评论的累积数据量会迅速达到数十亿级别。如何在这样的数据规模下保证读写性能，是首要挑战。

**2）读多写少但写入有突发**

评论系统的读写比通常在 10:1 甚至 100:1 以上。但在热点事件（如明星事件、爆款商品上线）发生时，评论的写入量会在短时间内急剧飙升，形成写入洪峰。

**3）内容安全与合规**

用户生成的评论内容可能包含涉政、涉黄、暴恐、广告、竞品引流等违规信息。国家监管部门要求平台必须对UGC内容进行实时审核，同时平台自身也需要拦截垃圾评论以维护社区氛围。敏感词过滤系统的性能直接决定了评论发布的响应速度。

**4）树形结构的复杂性**

评论系统不同于简单的列表数据，它本质上是一个树形结构——用户可以回复评论形成多级嵌套。如何在数据库层面高效存储和查询这种树形结构，如何在前端合理展示多级嵌套评论，都需要精心设计。

**5）计数的实时性与准确性**

评论数、点赞数等计数数据的访问量极大，并且用户对这些数字非常敏感。如何在高并发场景下保证计数的实时性和准确性，同时又不给底层存储带来过大压力，需要在一致性和性能之间做出权衡。

### 1.3 设计目标

基于以上分析，本文的评论系统设计目标如下：

| 维度 | 目标 |
|------|------|
| 性能 | 评论列表接口 P99 延迟 < 50ms；评论发布接口 P99 延迟 < 200ms |
| 可用性 | 整体可用性 >= 99.99%，核心链路支持降级 |
| 数据规模 | 支撑百亿级评论存储，单主题百万级评论查询 |
| 安全 | 敏感词过滤准确率 > 99.5%，反垃圾评论误判率 < 0.1% |
| 扩展性 | 支持水平扩展，新增业务场景可快速接入 |

## 二、整体架构设计

### 2.1 系统分层架构

评论系统的整体架构采用经典的分层设计，自上而下分为四个层次：

```
├──────────────────────────────────────────────────────────┤

│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
```

**接入层**：负责请求的限流、身份认证、参数校验和路由分发。通过API Gateway统一入口，屏蔽后端服务细节。

**业务逻辑层**：按领域拆分为多个微服务，各服务职责清晰：
- 评论服务：评论的CRUD核心操作
- 审核服务：敏感词过滤、反垃圾检测、人工审核流转
- 计数服务：评论数、点赞数等计数的维护与查询
- 互动服务：点赞、踩、举报等用户互动操作

**数据访问层**：封装对底层存储的访问，提供缓存管理、数据库访问、消息发送、全文检索等能力。

**基础设施层**：包括MySQL（评论主体数据持久化）、Redis（缓存加速与计数存储）、Kafka（异步解耦与削峰填谷）、Elasticsearch（评论全文检索与复杂排序）。

## 三、核心链路设计

本章是整个文档最重要的部分，将逐一展开评论系统各核心模块的算法选型、设计模式选择与实现细节。

### 3.1 评论树结构设计

#### 3.1.1 需求分析：为什么需要树形结构

在社交媒体和内容平台中，评论通常不是扁平的列表，而是带有层级关系的树形结构。用户A发表了一级评论，用户B回复了用户A的评论，用户C又回复了用户B——这形成了一个三层嵌套的评论树。

业界常见的评论层级模型有三种：

| 模型 | 代表产品 | 层级深度 | 特点 |
|------|---------|---------|------|
| 扁平模型 | 早期论坛 | 1层 | 只有一级评论，回复也是一级评论 |
| 二级模型 | 微博、抖音 | 2层 | 一级评论 + 对一级评论的回复（折叠展示） |
| 多级模型 | Reddit、知乎 | 不限 | 无限嵌套，完整树形展示 |

**结论：推荐使用二级模型（限制到2层），原因如下**：

1. **展示友好**：无限嵌套在移动端体验极差，屏幕越来越窄
2. **查询简单**：只需要查询root_id就能获取一棵完整的评论子树
3. **性能可控**：层级有限，不会出现递归查询的性能问题
4. **产品验证**：主流社交产品（微博、抖音、B站）均采用此模型

#### 3.1.2 存储方案：parentId + rootId 双指针

评论树的存储核心在于两个关键字段：

- **parent_id**：直接父评论的ID。用于标识"回复了谁"，前端展示"@某人"时使用
- **root_id**：根评论（一级评论）的ID。用于将一级评论下的所有回复聚合在一起

这两个字段的组合使得查询变得非常高效：

```sql
-- 查询某主题下的一级评论列表（按时间正序）
SELECT * FROM t_comment 
WHERE subject_id = ? AND subject_type = ? AND root_id = 0 AND status = 1
ORDER BY create_time ASC
LIMIT 20;

-- 查询某条一级评论下的所有回复（按时间正序）
SELECT * FROM t_comment 
WHERE root_id = ? AND status = 1
ORDER BY create_time ASC
LIMIT 20;
```

为什么不使用邻接表（只用parent_id递归查询）或者嵌套集模型？因为：

- **邻接表需要递归查询**：MySQL 8.0以前不支持CTE，即使支持，递归查询在大数据量下性能也不理想
- **嵌套集模型写入成本高**：每次插入一条评论，需要更新大量已有记录的左右值

#### 3.1.3 评论树构建算法

当我们从数据库或缓存中查到扁平的评论列表后，需要在内存中构建为树形结构。以下是构建算法的Java实现：

```java
/**
 * 评论树构建器
 * 将扁平的评论列表构建为二级树形结构
 */
public class CommentTreeBuilder {

    /**
     * 构建评论树
     * @param flatComments 扁平的评论列表（包含一级评论和回复）
     * @return 构建好的评论树（一级评论列表，每个一级评论包含其回复列表）
     */
    public static List<CommentVO> buildTree(List<CommentDO> flatComments) {
        if (flatComments == null || flatComments.isEmpty()) {
            return Collections.emptyList();
        }

        // 第一步：分离一级评论和回复评论
        List<CommentDO> rootComments = new ArrayList<>();
        // key: rootId, value: 该根评论下的所有回复
        Map<Long, List<CommentDO>> replyMap = new HashMap<>();

        for (CommentDO comment : flatComments) {
            if (comment.getRootId() == 0) {
                // root_id == 0 表示这是一级评论
                rootComments.add(comment);
            } else {
                // 否则是回复，按 root_id 分组
                replyMap.computeIfAbsent(comment.getRootId(), k -> new ArrayList<>())
                        .add(comment);
            }
        }

        // 第二步：组装树形结构
        List<CommentVO> result = new ArrayList<>();
        for (CommentDO root : rootComments) {
            CommentVO vo = convertToVO(root);
            List<CommentDO> replies = replyMap.getOrDefault(root.getId(), Collections.emptyList());
            // 对回复按时间正序排列
            replies.sort(Comparator.comparing(CommentDO::getCreateTime));
            vo.setReplies(replies.stream().map(CommentTreeBuilder::convertToVO).collect(Collectors.toList()));
            vo.setReplyCount(replies.size());
            result.add(vo);
        }

        return result;
    }

    private static CommentVO convertToVO(CommentDO comment) {
        CommentVO vo = new CommentVO();
        vo.setId(comment.getId());
        vo.setContent(comment.getContent());
        vo.setUserId(comment.getUserId());
        vo.setParentId(comment.getParentId());
        vo.setRootId(comment.getRootId());
        vo.setReplyUserId(comment.getReplyUserId());
        vo.setLikeCount(comment.getLikeCount());
        vo.setCreateTime(comment.getCreateTime());
        return vo;
    }
}
```

#### 3.1.4 前端展示策略

在二级评论模型下，前端的展示逻辑如下：

1. **一级评论**：按时间序或热度序排列展示
2. **回复列表**：每条一级评论默认展示前3条回复，点击"展开更多回复"后加载全部
3. **回复标识**：回复中通过 `reply_user_id` 显示"@被回复人"的标识

```
├── [用户A] 这部电影真好看！                    ← 一级评论 (root_id=0)
│   ├── [用户B] @用户A 确实不错                  ← 回复 (root_id=A, parent_id=A)
│   ├── [用户C] @用户B 我也觉得                  ← 回复 (root_id=A, parent_id=B)
│   └── 查看全部 28 条回复 >>
├── [用户D] 配乐太棒了                          ← 一级评论 (root_id=0)
│   └── [用户E] @用户D 是坂本龙一的              ← 回复 (root_id=D, parent_id=D)
```

注意：虽然用户C是回复用户B的，但在数据层面，用户C的 `root_id` 仍然指向用户A的评论ID。这保证了所有嵌套层级的回复都能通过一次 `root_id` 查询获取。

### 3.2 评论排序策略

#### 3.2.1 时间序排序

时间序是最基础的排序策略，分为正序（从早到晚）和倒序（从晚到早）两种。

**正序**适用于讨论场景（如论坛帖子），用户习惯从头看到尾。  
**倒序**适用于动态场景（如新闻评论），用户优先看最新评论。

数据库查询非常简单：

```sql
-- 时间正序
SELECT * FROM t_comment 
WHERE subject_id = ? AND root_id = 0 AND status = 1
ORDER BY create_time ASC
LIMIT 20;

-- 时间倒序
SELECT * FROM t_comment 
WHERE subject_id = ? AND root_id = 0 AND status = 1
ORDER BY create_time DESC
LIMIT 20;
```

时间序排序的索引设计：`(subject_id, subject_type, status, create_time)`，查询可以走索引覆盖扫描，性能极好。

#### 3.2.2 热度序排序

热度序排序需要综合考虑多个维度来计算评论的热度分数。常见的热度因子包括：

| 因子 | 权重 | 说明 |
|------|------|------|
| 点赞数 | 高 | 被最多人认可的评论 |
| 回复数 | 中 | 引发讨论的评论 |
| 时间衰减 | 中 | 避免老评论永远霸榜 |
| 负面反馈 | 低（负权重） | 被举报/踩的评论降权 |

热度计算公式（Wilson Score改良版）：

```
热度分 = (点赞数 × 3 + 回复数 × 2) / (1 + T^1.5)

其中 T = (当前时间 - 评论创建时间) / 3600，单位为小时
```

Java实现：

```java
/**
 * 评论热度计算器
 */
public class CommentHotScoreCalculator {

    private static final double LIKE_WEIGHT = 3.0;
    private static final double REPLY_WEIGHT = 2.0;
    private static final double TIME_DECAY_FACTOR = 1.5;

    /**
     * 计算评论的热度分数
     *
     * @param likeCount   点赞数
     * @param replyCount  回复数
     * @param createTime  评论创建时间
     * @return 热度分数
     */
    public static double calculateHotScore(int likeCount, int replyCount, 
                                            LocalDateTime createTime) {
        // 互动得分：点赞权重更高
        double interactionScore = likeCount * LIKE_WEIGHT + replyCount * REPLY_WEIGHT;

        // 时间衰减因子：随时间推移，热度逐渐下降
        long hoursSinceCreation = Duration.between(createTime, LocalDateTime.now()).toHours();
        double timeFactor = 1 + Math.pow(Math.max(hoursSinceCreation, 1), TIME_DECAY_FACTOR);

        return interactionScore / timeFactor;
    }

    /**
     * 对评论列表按热度排序
     */
    public static List<CommentVO> sortByHotScore(List<CommentVO> comments) {
        // 计算每条评论的热度分并缓存
        Map<Long, Double> scoreMap = new HashMap<>();
        for (CommentVO comment : comments) {
            double score = calculateHotScore(
                comment.getLikeCount(), 
                comment.getReplyCount(), 
                comment.getCreateTime()
            );
            scoreMap.put(comment.getId(), score);
        }

        // 按热度分降序排列
        comments.sort((a, b) -> {
            double scoreA = scoreMap.getOrDefault(a.getId(), 0.0);
            double scoreB = scoreMap.getOrDefault(b.getId(), 0.0);
            return Double.compare(scoreB, scoreA);
        });

        return comments;
    }
}
```

#### 3.2.3 热度序的存储与更新策略

热度分数是实时变化的（点赞数、回复数在变，时间也在变），不能每次查询都实时计算所有评论的热度分，这样性能不可接受。解决方案是引入 **Redis Sorted Set** 作为热度索引：

```java
/**
 * 评论热度索引管理器
 * 使用Redis Sorted Set维护评论的热度排序
 */
public class CommentHotIndexManager {

    private final RedisTemplate<String, String> redisTemplate;

    private static final String HOT_INDEX_KEY_PREFIX = "comment:hot:";

    /**
     * 更新评论的热度分
     * 在评论被点赞、回复时调用
     */
    public void updateHotScore(long subjectId, int subjectType, 
                                long commentId, double hotScore) {
        String key = HOT_INDEX_KEY_PREFIX + subjectType + ":" + subjectId;
        redisTemplate.opsForZSet().add(key, String.valueOf(commentId), hotScore);
    }

    /**
     * 按热度序获取评论ID列表（分页）
     * @param cursor  上一页最后一条评论的score，首页传 Double.MAX_VALUE
     * @param limit   每页条数
     * @return 评论ID列表（降序）
     */
    public List<Long> getHotCommentIds(long subjectId, int subjectType,
                                        double cursor, int limit) {
        String key = HOT_INDEX_KEY_PREFIX + subjectType + ":" + subjectId;

        // 使用 ZREVRANGEBYSCORE 实现游标分页
        Set<ZSetOperations.TypedTuple<String>> tuples = redisTemplate.opsForZSet()
            .reverseRangeByScoreWithScores(key, 0, cursor, 0, limit + 1);

        if (tuples == null || tuples.isEmpty()) {
            return Collections.emptyList();
        }

        return tuples.stream()
            .map(tuple -> Long.parseLong(tuple.getValue()))
            .collect(Collectors.toList());
    }

    /**
     * 定时任务：批量刷新所有评论的热度分
     * 处理时间衰减导致的分数变化
     * 建议每小时执行一次
     */
    public void refreshHotScores(long subjectId, int subjectType) {
        String key = HOT_INDEX_KEY_PREFIX + subjectType + ":" + subjectId;
        Set<String> commentIds = redisTemplate.opsForZSet().range(key, 0, -1);

        if (commentIds == null || commentIds.isEmpty()) {
            return;
        }

        // 批量查询评论信息，重新计算热度分
        for (String commentIdStr : commentIds) {
            long commentId = Long.parseLong(commentIdStr);
            CommentDO comment = commentMapper.selectById(commentId);
            if (comment != null && comment.getStatus() == 1) {
                double newScore = CommentHotScoreCalculator.calculateHotScore(
                    comment.getLikeCount(), 
                    comment.getReplyCount(), 
                    comment.getCreateTime()
                );
                redisTemplate.opsForZSet().add(key, commentIdStr, newScore);
            }
        }
    }
}
```

### 3.3 敏感词过滤

敏感词过滤是评论系统中最关键的安全防线。对于访问量巨大的平台，用户每天的评论数可达数百万甚至数千万。对敏感词过滤系统的性能要求极高——用户输入内容之后，不能有明显的延迟感。

#### 3.3.1 方案选型：DFA vs AC自动机

**DFA（Deterministic Finite Automaton，确定有限自动机）**

DFA的核心思想是将敏感词字典构建为一棵Trie树（前缀树），然后遍历输入文本的每一个字符，在Trie树上进行匹配。

优点：实现简单，空间效率高  
缺点：需要从文本的每个位置重新开始匹配，效率不如AC自动机

**AC自动机（Aho-Corasick）**

AC自动机是在Trie树的基础上增加了失败指针（fail pointer），类似于KMP算法中的next数组，但应用于多模式串匹配场景。它只需要扫描一遍输入文本，就能同时匹配所有敏感词，时间复杂度近似于 O(n)，其中n为文本长度。

**结论：推荐使用AC自动机**。对于敏感词数量达到数千乃至数万的场景，AC自动机的性能优势非常明显。

#### 3.3.2 AC自动机的构建原理

AC自动机的构建分为两步：

**第一步：构建Trie树**

将所有敏感词逐字符插入Trie树中。例如，敏感词列表为 ["he", "she", "his", "hers"]，构建的Trie树如下：

```
       root
      /    \
     h      s
     |      |
     e*     h
    / \     |
   r   i    e*
   |   |
   s*  s*
```

标记 `*` 表示该节点是某个敏感词的结束字符。

**第二步：构建失败指针**

失败指针的含义是：当匹配到某个节点后发现不匹配时，应该跳转到哪个节点继续匹配。构建过程是一个BFS（广度优先搜索），按层次遍历Trie树的每个节点。

核心规则：
- 根节点的失败指针指向自身（null）
- 根节点的直接子节点的失败指针指向根节点
- 对于其他节点p，假设p的父节点的失败指针指向节点q，则检查q是否有与p对应字符相同的子节点qc。如果有，p的失败指针指向qc；如果没有，继续查看q的失败指针，直到回到根节点

#### 3.3.3 AC自动机的Java完整实现

```java
import java.util.*;

/**
 * AC自动机实现的敏感词过滤器
 * 
 * 核心原理：
 * 1. 将敏感词字典构建为Trie树
 * 2. 在Trie树上构建失败指针（类似KMP的next数组）
 * 3. 扫描一遍输入文本即可完成所有敏感词的匹配
 */
public class AhoCorasickFilter {

    /**
     * AC自动机节点
     */
    private static class AcNode {
        // 子节点映射，key为字符，value为子节点
        // 使用HashMap支持中英文混合的完整字符集
        Map<Character, AcNode> children = new HashMap<>();
        // 失败指针：匹配失败时跳转的节点
        AcNode fail;
        // 如果该节点是某个敏感词的结束字符，记录敏感词长度
        // -1表示不是结束字符
        int wordLength = -1;
    }

    private final AcNode root;

    public AhoCorasickFilter() {
        this.root = new AcNode();
    }

    /**
     * 第一步：将敏感词列表构建为Trie树
     */
    public void buildTrie(List<String> sensitiveWords) {
        for (String word : sensitiveWords) {
            if (word == null || word.isEmpty()) {
                continue;
            }
            AcNode current = root;
            for (char c : word.toCharArray()) {
                // 统一转小写，实现大小写不敏感匹配
                char lowerC = Character.toLowerCase(c);
                current = current.children.computeIfAbsent(lowerC, k -> new AcNode());
            }
            // 标记结束节点，记录敏感词长度
            current.wordLength = word.length();
        }
    }

    /**
     * 第二步：构建失败指针
     * 使用BFS按层遍历Trie树
     */
    public void buildFailurePointers() {
        Queue<AcNode> queue = new LinkedList<>();
        // 根节点的失败指针为null
        root.fail = null;

        // 根节点的直接子节点的失败指针指向根节点
        for (AcNode child : root.children.values()) {
            child.fail = root;
            queue.add(child);
        }

        // BFS遍历构建其他节点的失败指针
        while (!queue.isEmpty()) {
            AcNode parent = queue.poll();

            for (Map.Entry<Character, AcNode> entry : parent.children.entrySet()) {
                char c = entry.getKey();
                AcNode child = entry.getValue();

                // 沿着父节点的失败指针链向上查找
                AcNode failNode = parent.fail;
                while (failNode != null && !failNode.children.containsKey(c)) {
                    failNode = failNode.fail;
                }

                // 如果找到了匹配的节点，指向它的对应子节点
                // 否则指向根节点
                child.fail = (failNode == null) ? root : failNode.children.get(c);

                queue.add(child);
            }
        }
    }

    /**
     * 第三步：在文本中匹配敏感词
     * 返回所有匹配到的敏感词的位置和长度
     */
    public List<MatchResult> match(String text) {
        List<MatchResult> results = new ArrayList<>();
        if (text == null || text.isEmpty()) {
            return results;
        }

        AcNode current = root;
        char[] chars = text.toCharArray();

        for (int i = 0; i < chars.length; i++) {
            char c = Character.toLowerCase(chars[i]);

            // 如果当前节点没有匹配的子节点，沿失败指针回退
            while (current != root && !current.children.containsKey(c)) {
                current = current.fail;
            }

            // 尝试匹配当前字符
            if (current.children.containsKey(c)) {
                current = current.children.get(c);
            }
            // 如果根节点也没有匹配的子节点，继续扫描下一个字符

            // 检查当前节点及其失败指针链上的所有节点
            // 是否有敏感词结束标记
            AcNode temp = current;
            while (temp != root) {
                if (temp.wordLength > 0) {
                    int startPos = i - temp.wordLength + 1;
                    results.add(new MatchResult(startPos, temp.wordLength));
                }
                temp = temp.fail;
            }
        }

        return results;
    }

    /**
     * 替换文本中的敏感词为指定字符
     */
    public String replaceSensitiveWords(String text, char replacement) {
        List<MatchResult> matches = match(text);
        if (matches.isEmpty()) {
            return text;
        }

        char[] chars = text.toCharArray();
        for (MatchResult result : matches) {
            for (int i = result.startPos; i < result.startPos + result.length; i++) {
                chars[i] = replacement;
            }
        }
        return new String(chars);
    }

    /**
     * 检查文本是否包含敏感词（快速判断，不需要找出所有匹配位置）
     */
    public boolean containsSensitiveWord(String text) {
        if (text == null || text.isEmpty()) {
            return false;
        }

        AcNode current = root;
        for (char rawChar : text.toCharArray()) {
            char c = Character.toLowerCase(rawChar);

            while (current != root && !current.children.containsKey(c)) {
                current = current.fail;
            }

            if (current.children.containsKey(c)) {
                current = current.children.get(c);
            }

            AcNode temp = current;
            while (temp != root) {
                if (temp.wordLength > 0) {
                    return true; // 发现敏感词，立即返回
                }
                temp = temp.fail;
            }
        }

        return false;
    }

    /**
     * 匹配结果
     */
    public static class MatchResult {
        public final int startPos;  // 匹配起始位置
        public final int length;    // 匹配长度

        public MatchResult(int startPos, int length) {
            this.startPos = startPos;
            this.length = length;
        }
    }
}
```

#### 3.3.4 敏感词库的动态更新

敏感词库不是静态的，需要支持动态增删改。方案是使用"双缓冲"机制：

```java
/**
 * 支持动态更新的敏感词过滤服务
 * 使用双缓冲机制，更新词库时不影响在线匹配
 */
public class SensitiveWordService {

    // 使用volatile保证可见性，使用AtomicReference保证原子替换
    private volatile AhoCorasickFilter currentFilter;

    // 词库版本号，用于判断是否需要更新
    private volatile long dictionaryVersion = 0;

    /**
     * 初始化：从数据库加载敏感词库，构建AC自动机
     */
    @PostConstruct
    public void init() {
        List<String> words = sensitiveWordMapper.selectAllActiveWords();
        this.currentFilter = buildFilter(words);
    }

    /**
     * 构建新的过滤器（在后台线程中执行，不阻塞在线请求）
     */
    private AhoCorasickFilter buildFilter(List<String> words) {
        AhoCorasickFilter filter = new AhoCorasickFilter();
        filter.buildTrie(words);
        filter.buildFailurePointers();
        return filter;
    }

    /**
     * 动态更新敏感词库
     * 收到MQ消息（词库变更通知）后调用
     */
    public void refreshDictionary(long newVersion) {
        if (newVersion <= dictionaryVersion) {
            return; // 版本号不大于当前版本，无需更新
        }

        // 在后台线程中构建新的AC自动机
        List<String> words = sensitiveWordMapper.selectAllActiveWords();
        AhoCorasickFilter newFilter = buildFilter(words);

        // 原子替换，对在线请求无影响
        this.currentFilter = newFilter;
        this.dictionaryVersion = newVersion;

        log.info("敏感词库更新完成，版本号: {}, 词条数: {}", newVersion, words.size());
    }

    /**
     * 过滤文本中的敏感词
     */
    public String filter(String text) {
        return currentFilter.replaceSensitiveWords(text, '*');
    }

    /**
     * 检查文本是否包含敏感词
     */
    public boolean check(String text) {
        return currentFilter.containsSensitiveWord(text);
    }
}
```

#### 3.3.5 使用职责链模式组装过滤管道

在实际业务中，除了敏感词过滤，还需要进行广告检测、涉政检测、涉黄检测等多种内容安全检查。这些检查的算法和词库各不相同，但处理流程是链式的——每种检查都需要执行，任何一种检查不通过就需要拦截。

使用职责链模式（Chain of Responsibility）来组织这些过滤器，具有良好的扩展性——增加新的过滤规则只需添加一个新的Filter类，无需修改已有代码。

```java
/**
 * 内容过滤器接口
 */
public interface ContentFilter {
    /**
     * 执行过滤检查
     * @param content 待检查的内容
     * @return 检查结果
     */
    FilterResult doFilter(String content);
}

/**
 * 过滤结果
 */
public class FilterResult {
    private boolean passed;        // 是否通过
    private String filterType;     // 过滤类型
    private String reason;         // 拦截原因
    private List<String> hitWords; // 命中的关键词

    public static FilterResult pass() {
        FilterResult result = new FilterResult();
        result.passed = true;
        return result;
    }

    public static FilterResult reject(String filterType, String reason, List<String> hitWords) {
        FilterResult result = new FilterResult();
        result.passed = false;
        result.filterType = filterType;
        result.reason = reason;
        result.hitWords = hitWords;
        return result;
    }

    // getters...
    public boolean isPassed() { return passed; }
    public String getFilterType() { return filterType; }
    public String getReason() { return reason; }
    public List<String> getHitWords() { return hitWords; }
}

/**
 * 涉黄词过滤器
 */
public class PornWordFilter implements ContentFilter {
    private final AhoCorasickFilter acFilter;

    public PornWordFilter(List<String> pornWords) {
        this.acFilter = new AhoCorasickFilter();
        acFilter.buildTrie(pornWords);
        acFilter.buildFailurePointers();
    }

    @Override
    public FilterResult doFilter(String content) {
        List<AhoCorasickFilter.MatchResult> matches = acFilter.match(content);
        if (matches.isEmpty()) {
            return FilterResult.pass();
        }
        List<String> hitWords = matches.stream()
            .map(m -> content.substring(m.startPos, m.startPos + m.length))
            .collect(Collectors.toList());
        return FilterResult.reject("PORN", "涉黄内容", hitWords);
    }
}

 * 广告词过滤器
 */
public class AdsWordFilter implements ContentFilter {

/**
 * 内容过滤链
 * 将多个过滤器串联成链，依次执行
 */
public class ContentFilterChain {

    private final List<ContentFilter> filters = new ArrayList<>();

    public void addFilter(ContentFilter filter) {
        this.filters.add(filter);
    }

    /**
     * 执行过滤链
     * 任何一个过滤器拒绝，则整条链拒绝
     */
    public FilterResult filter(String content) {
        for (ContentFilter filter : filters) {
            FilterResult result = filter.doFilter(content);
            if (!result.isPassed()) {
                return result; // 命中即拦截
            }
        }
        return FilterResult.pass();
    }
}

        chain.addFilter(new AdsWordFilter(repository.getAdsWords()));
```

### 3.4 反垃圾评论系统

敏感词过滤只能拦截包含特定关键词的内容，但现实中的垃圾评论远比这复杂：刷屏、水军机器人发帖、变体绕过检测等。反垃圾评论系统需要从多个维度进行综合判定。

#### 3.4.1 频率控制（频控）

频控是反垃圾的第一道防线，通过限制单个用户在一定时间窗口内的评论次数来防止刷屏。

```java
/**
 * 评论频率控制器
 * 使用Redis实现滑动窗口限流
 */
public class CommentRateLimiter {

    private final StringRedisTemplate redisTemplate;

    // 频控规则配置
    private static final int MAX_COMMENTS_PER_MINUTE = 5;   // 每分钟最多5条
    private static final int MAX_COMMENTS_PER_HOUR = 30;    // 每小时最多30条
    private static final int MAX_COMMENTS_PER_DAY = 100;    // 每天最多100条

    private static final String RATE_KEY_PREFIX = "comment:rate:";

    /**
     * 检查用户是否被频控限制
     * @param userId 用户ID
     * @return true表示通过频控检查，false表示被限制
     */
    public boolean checkRateLimit(long userId) {
        long now = System.currentTimeMillis();

        // 检查分钟级频控
        if (!checkWindow(userId, "min", now, 60_000L, MAX_COMMENTS_PER_MINUTE)) {
            return false;
        }

        // 检查小时级频控
        if (!checkWindow(userId, "hour", now, 3_600_000L, MAX_COMMENTS_PER_HOUR)) {
            return false;
        }

        // 检查天级频控
        if (!checkWindow(userId, "day", now, 86_400_000L, MAX_COMMENTS_PER_DAY)) {
            return false;
        }

        return true;
    }

    /**
     * 记录一次评论行为
     */
    public void recordComment(long userId) {
        long now = System.currentTimeMillis();
        String member = String.valueOf(now);

        // 在三个时间窗口中都记录
        recordToWindow(userId, "min", now, member, 60_000L);
        recordToWindow(userId, "hour", now, member, 3_600_000L);
        recordToWindow(userId, "day", now, member, 86_400_000L);
    }

    private boolean checkWindow(long userId, String window, long now,
                                 long windowSize, int maxCount) {
        String key = RATE_KEY_PREFIX + userId + ":" + window;
        // 使用 ZCOUNT 统计滑动窗口内的记录数
        Long count = redisTemplate.opsForZSet()
            .count(key, now - windowSize, now);
        return count == null || count < maxCount;
    }

    private void recordToWindow(long userId, String window, long now,
                                 String member, long windowSize) {
        String key = RATE_KEY_PREFIX + userId + ":" + window;
        redisTemplate.opsForZSet().add(key, member, now);
        // 移除窗口外的过期数据
        redisTemplate.opsForZSet().removeRangeByScore(key, 0, now - windowSize);
        // 设置key的过期时间，避免垃圾数据
        redisTemplate.expire(key, windowSize * 2, TimeUnit.MILLISECONDS);
    }
}
```

#### 3.4.2 内容相似度检测

垃圾评论的一个典型特征是重复内容——同一个用户在短时间内发布相同或相似的评论。通过SimHash算法可以高效地检测文本相似度。

```java
/**
 * 基于SimHash的评论内容相似度检测
 * 
 * SimHash原理：
 * 1. 对文本进行分词
 * 2. 对每个词计算hash值
 * 3. 根据词的权重加权合并
 * 4. 最终生成一个固定长度的指纹
 * 两个文本的SimHash指纹的海明距离越小，文本越相似
 */
public class ContentSimilarityDetector {

    private final StringRedisTemplate redisTemplate;

    // 用户最近评论的SimHash指纹缓存，key前缀
    private static final String SIMHASH_KEY_PREFIX = "comment:simhash:";
    // 海明距离阈值，小于等于此值视为相似
    private static final int HAMMING_DISTANCE_THRESHOLD = 3;
    // 保留最近N条评论的指纹
    private static final int RECENT_COMMENT_COUNT = 10;

    /**
     * 检查新评论是否与用户最近的评论内容重复
     * @param userId  用户ID
     * @param content 新评论内容
     * @return true表示内容不重复，false表示内容重复
     */
    public boolean checkDuplicate(long userId, String content) {
        long newHash = computeSimHash(content);
        String key = SIMHASH_KEY_PREFIX + userId;

        // 获取用户最近的评论指纹列表
        List<String> recentHashes = redisTemplate.opsForList().range(key, 0, -1);

        if (recentHashes != null) {
            for (String hashStr : recentHashes) {
                long existingHash = Long.parseLong(hashStr);
                int distance = hammingDistance(newHash, existingHash);
                if (distance <= HAMMING_DISTANCE_THRESHOLD) {
                    return false; // 发现相似内容
                }
            }
        }

        // 不重复，记录新的指纹
        redisTemplate.opsForList().leftPush(key, String.valueOf(newHash));
        redisTemplate.opsForList().trim(key, 0, RECENT_COMMENT_COUNT - 1);
        redisTemplate.expire(key, 1, TimeUnit.HOURS);

        return true;
    }

    /**
     * 计算文本的SimHash指纹（64位）
     */
    private long computeSimHash(String text) {
        // 分词（这里用简单的字符级bigram，生产环境建议使用分词器）
        List<String> tokens = tokenize(text);
        int[] bits = new int[64]; // 64维向量

        for (String token : tokens) {
            long hash = murmurHash64(token);
            for (int i = 0; i < 64; i++) {
                // hash的第i位是1就加权+1，否则加权-1
                if (((hash >> i) & 1) == 1) {
                    bits[i]++;
                } else {
                    bits[i]--;
                }
            }
        }

        // 降维：正数位记为1，负数位记为0
        long simHash = 0;
        for (int i = 0; i < 64; i++) {
            if (bits[i] > 0) {
                simHash |= (1L << i);
            }
        }
        return simHash;
    }

    /**
     * 计算两个64位整数的海明距离
     */
    private int hammingDistance(long a, long b) {
        return Long.bitCount(a ^ b);
    }

    /**
     * 简单分词：字符级bigram
     */
    private List<String> tokenize(String text) {
        List<String> tokens = new ArrayList<>();
        for (int i = 0; i < text.length() - 1; i++) {
            tokens.add(text.substring(i, i + 2));
        }
        return tokens;
    }

    /**
     * MurmurHash64实现
     */
    private long murmurHash64(String key) {
        byte[] data = key.getBytes(StandardCharsets.UTF_8);
        long h = 0xc6a4a7935bd1e995L;
        for (byte b : data) {
            h ^= b;
            h *= 0x5bd1e9955bd1e995L;
            h ^= h >>> 47;
        }
        return h;
    }
}
```

#### 3.4.3 用户信誉分体系

用户信誉分是反垃圾系统的核心能力之一。通过对用户的历史行为进行综合评估，给每个用户打上一个信誉分，信誉分低的用户发布的评论需要经过更严格的审核。

```java
/**
 * 用户信誉分计算与管理
 * 
 * 信誉分范围：0 ~ 100
 * 100分：高信誉用户，评论免审直接发布
 * 60~99分：普通用户，评论经过基础审核后发布
 * 30~59分：低信誉用户，评论需要经过完整审核链
 * 0~29分：极低信誉用户，评论需要人工审核
 */
public class UserReputationService {

    private final StringRedisTemplate redisTemplate;
    private static final String REPUTATION_KEY_PREFIX = "user:reputation:";
    private static final int DEFAULT_SCORE = 80; // 新用户默认信誉分

    /**
     * 获取用户信誉分
     */
    public int getReputationScore(long userId) {
        String key = REPUTATION_KEY_PREFIX + userId;
        String score = redisTemplate.opsForValue().get(key);
        if (score == null) {
            return DEFAULT_SCORE;
        }
        return Integer.parseInt(score);
    }

    /**
     * 评论通过审核时，增加信誉分
     */
    public void onCommentApproved(long userId) {
        adjustScore(userId, 1, 100);
    }

    /**
     * 评论被标记为垃圾时，大幅降低信誉分
     */
    public void onCommentMarkedAsSpam(long userId) {
        adjustScore(userId, -10, 100);
    }

    /**
     * 评论被举报并确认违规时，降低信誉分
     */
    public void onCommentReported(long userId) {
        adjustScore(userId, -5, 100);
    }

    /**
     * 评论被点赞时，小幅增加信誉分
     */
    public void onCommentLiked(long userId) {
        adjustScore(userId, 0.5, 100);
    }

    /**
     * 调整信誉分，确保在 [0, maxScore] 范围内
     */
    private void adjustScore(long userId, double delta, int maxScore) {
        String key = REPUTATION_KEY_PREFIX + userId;
        // 使用Lua脚本保证原子性
        String luaScript = 
            "local score = tonumber(redis.call('GET', KEYS[1]) or ARGV[2]) " +
            "score = score + tonumber(ARGV[1]) " +
            "if score < 0 then score = 0 end " +
            "if score > tonumber(ARGV[3]) then score = tonumber(ARGV[3]) end " +
            "redis.call('SET', KEYS[1], tostring(score)) " +
            "return tostring(score)";

        redisTemplate.execute(
            new DefaultRedisScript<>(luaScript, String.class),
            Collections.singletonList(key),
            String.valueOf(delta),
            String.valueOf(DEFAULT_SCORE),
            String.valueOf(maxScore)
        );
    }

    /**
     * 根据信誉分决定审核策略
     */
    public AuditStrategy getAuditStrategy(long userId) {
        int score = getReputationScore(userId);

        if (score >= 100) {
            // 高信誉用户：免审
            return AuditStrategy.SKIP;
        } else if (score >= 60) {
            // 普通用户：基础机审（敏感词过滤）
            return AuditStrategy.BASIC_MACHINE;
        } else if (score >= 30) {
            // 低信誉用户：完整机审（敏感词+反垃圾+内容理解）
            return AuditStrategy.FULL_MACHINE;
        } else {
            // 极低信誉用户：先审后发（机审+人工审核）
            return AuditStrategy.MANUAL_REVIEW;
        }
    }

    public enum AuditStrategy {
        SKIP,           // 免审
        BASIC_MACHINE,  // 基础机审
        FULL_MACHINE,   // 完整机审
        MANUAL_REVIEW   // 人工审核
    }
}
```

#### 3.4.4 反垃圾评论综合决策引擎

将频控、内容相似度检测、用户信誉分综合起来，形成完整的反垃圾决策引擎：

```java
/**
 * 反垃圾评论综合决策引擎
 */
@Service
public class AntiSpamEngine {

    @Autowired private CommentRateLimiter rateLimiter;
    @Autowired private ContentSimilarityDetector similarityDetector;
    @Autowired private UserReputationService reputationService;
    @Autowired private ContentFilterChain filterChain;

    /**
     * 综合反垃圾检查
     * @param userId  用户ID
     * @param content 评论内容
     * @return 检查结果
     */
    public AntiSpamResult check(long userId, String content) {
        // 第一关：频率控制
        if (!rateLimiter.checkRateLimit(userId)) {
            return AntiSpamResult.reject("RATE_LIMIT", "评论过于频繁，请稍后再试");
        }

        // 第二关：内容重复检测
        if (!similarityDetector.checkDuplicate(userId, content)) {
            return AntiSpamResult.reject("DUPLICATE", "请勿发布重复内容");
        }

        // 第三关：根据用户信誉分决定审核策略
        UserReputationService.AuditStrategy strategy = 
            reputationService.getAuditStrategy(userId);

        switch (strategy) {
            case SKIP:
                // 高信誉用户直接通过
                return AntiSpamResult.pass();

            case BASIC_MACHINE:
                // 基础机审：只做敏感词过滤
                FilterResult filterResult = filterChain.filter(content);
                if (!filterResult.isPassed()) {
                    return AntiSpamResult.reject(filterResult.getFilterType(),
                        filterResult.getReason());
                }
                return AntiSpamResult.pass();

            case FULL_MACHINE:
                // 完整机审：敏感词 + 附加规则
                FilterResult fullResult = filterChain.filter(content);
                if (!fullResult.isPassed()) {
                    return AntiSpamResult.reject(fullResult.getFilterType(),
                        fullResult.getReason());
                }
                // 可以在此追加更多检测（如垃圾内容模型打分）
                return AntiSpamResult.pass();

            case MANUAL_REVIEW:
                // 先审后发：标记为待人工审核
                FilterResult preResult = filterChain.filter(content);
                if (!preResult.isPassed()) {
                    return AntiSpamResult.reject(preResult.getFilterType(),
                        preResult.getReason());
                }
                return AntiSpamResult.needManualReview("用户信誉分较低，需人工审核");

            default:
                return AntiSpamResult.pass();
        }
    }
}

/**
 * 反垃圾检查结果
 */
public class AntiSpamResult {
    private ResultType type;
    private String rejectType;
    private String message;

    public enum ResultType {
        PASS,          // 通过
        REJECT,        // 拒绝
        MANUAL_REVIEW  // 需人工审核
    }

    public static AntiSpamResult pass() {
        AntiSpamResult result = new AntiSpamResult();
        result.type = ResultType.PASS;
        return result;
    }

    public static AntiSpamResult reject(String rejectType, String message) {
        AntiSpamResult result = new AntiSpamResult();
        result.type = ResultType.REJECT;
        result.rejectType = rejectType;
        result.message = message;
        return result;
    }

    public static AntiSpamResult needManualReview(String message) {
        AntiSpamResult result = new AntiSpamResult();
        result.type = ResultType.MANUAL_REVIEW;
        result.message = message;
        return result;
    }

    // getters...
    public ResultType getType() { return type; }
    public String getRejectType() { return rejectType; }
    public String getMessage() { return message; }
}
```

### 3.5 评论与点赞联动

#### 3.5.1 点赞操作设计

点赞是评论系统中频率最高的操作之一，具有以下特点：

- **幂等性**：同一用户对同一评论只能点赞一次，重复点赞应为取消
- **高并发**：热门评论可能在短时间内收到大量点赞
- **实时性**：用户期望点赞后立即看到数字变化

```java
/**
 * 评论点赞服务
 * 使用Redis Set记录点赞关系，Redis字符串存储点赞计数
 */
@Service
public class CommentLikeService {

    @Autowired private StringRedisTemplate redisTemplate;
    @Autowired private CommentMapper commentMapper;

    // 点赞关系集合：comment:liked_users:{commentId} -> Set<userId>
    private static final String LIKED_USERS_KEY = "comment:liked_users:";
    // 点赞计数：comment:like_count:{commentId} -> count
    private static final String LIKE_COUNT_KEY = "comment:like_count:";

    /**
     * 切换点赞状态（点赞/取消点赞）
     * @return true表示点赞成功，false表示取消点赞成功
     */
    public boolean toggleLike(long userId, long commentId) {
        String userSetKey = LIKED_USERS_KEY + commentId;
        String countKey = LIKE_COUNT_KEY + commentId;
        String userIdStr = String.valueOf(userId);

        // 使用Lua脚本保证原子性
        String luaScript =
            "local isMember = redis.call('SISMEMBER', KEYS[1], ARGV[1]) " +
            "if isMember == 1 then " +
            "    redis.call('SREM', KEYS[1], ARGV[1]) " +
            "    redis.call('DECR', KEYS[2]) " +
            "    return 0 " +  // 取消点赞
            "else " +
            "    redis.call('SADD', KEYS[1], ARGV[1]) " +
            "    redis.call('INCR', KEYS[2]) " +
            "    return 1 " +  // 点赞成功
            "end";

        Long result = redisTemplate.execute(
            new DefaultRedisScript<>(luaScript, Long.class),
            Arrays.asList(userSetKey, countKey),
            userIdStr
        );

        boolean liked = result != null && result == 1;

        // 异步发送MQ事件，用于持久化到数据库和更新信誉分
        sendLikeEvent(userId, commentId, liked);

        return liked;
    }

    /**
     * 查询用户是否已点赞
     */
    public boolean isLiked(long userId, long commentId) {
        String key = LIKED_USERS_KEY + commentId;
        Boolean isMember = redisTemplate.opsForSet()
            .isMember(key, String.valueOf(userId));
        return Boolean.TRUE.equals(isMember);
    }

    /**
     * 批量查询用户对多条评论的点赞状态
     * 用于评论列表展示时批量填充点赞状态
     */
    public Map<Long, Boolean> batchCheckLiked(long userId, List<Long> commentIds) {
        Map<Long, Boolean> result = new HashMap<>();

        // 使用Pipeline批量查询，减少网络往返
        List<Object> pipelineResults = redisTemplate.executePipelined(
            (RedisCallback<Object>) connection -> {
                for (Long commentId : commentIds) {
                    byte[] key = (LIKED_USERS_KEY + commentId).getBytes();
                    byte[] member = String.valueOf(userId).getBytes();
                    connection.sIsMember(key, member);
                }
                return null;
            }
        );

        for (int i = 0; i < commentIds.size(); i++) {
            result.put(commentIds.get(i), Boolean.TRUE.equals(pipelineResults.get(i)));
        }

        return result;
    }

    /**
     * 获取评论的点赞数
     */
    public long getLikeCount(long commentId) {
        String key = LIKE_COUNT_KEY + commentId;
        String count = redisTemplate.opsForValue().get(key);
        return count == null ? 0 : Long.parseLong(count);
    }

    /**
     * 发送点赞事件到MQ
     */
    private void sendLikeEvent(long userId, long commentId, boolean liked) {
        LikeEvent event = new LikeEvent();
        event.setUserId(userId);
        event.setCommentId(commentId);
        event.setLiked(liked);
        event.setTimestamp(System.currentTimeMillis());
        kafkaTemplate.send("comment-like-events", JSON.toJSONString(event));
    }
}
```

#### 3.5.2 点赞计数的持久化

Redis中的点赞关系和计数需要定期持久化到数据库，防止Redis故障导致数据丢失。通过消费MQ事件来异步写入数据库：

```java
/**
 * 点赞事件消费者
 * 将Redis中的点赞关系异步持久化到MySQL
 */
@Component
public class LikeEventConsumer {

    @Autowired private CommentLikeMapper commentLikeMapper;
    @Autowired private CommentMapper commentMapper;
    @Autowired private UserReputationService reputationService;

    /**
     * 消费点赞事件
     * 支持批量消费以提高吞吐量
     */
    @KafkaListener(topics = "comment-like-events", groupId = "like-consumer")
    public void onLikeEvent(List<ConsumerRecord<String, String>> records) {
        // 合并同一评论的多次操作，只保留最终状态
        Map<String, LikeEvent> mergedEvents = new LinkedHashMap<>();
        for (ConsumerRecord<String, String> record : records) {
            LikeEvent event = JSON.parseObject(record.value(), LikeEvent.class);
            String key = event.getUserId() + ":" + event.getCommentId();
            mergedEvents.put(key, event); // 后来的事件覆盖先前的
        }

        // 批量写入数据库
        for (LikeEvent event : mergedEvents.values()) {
            try {
                if (event.isLiked()) {
                    // 点赞：INSERT ON DUPLICATE KEY UPDATE
                    commentLikeMapper.upsertLike(event.getCommentId(), 
                        event.getUserId(), 1);
                    // 更新评论的点赞计数
                    commentMapper.incrementLikeCount(event.getCommentId(), 1);
                    // 给被点赞评论的作者增加信誉分
                    CommentDO comment = commentMapper.selectById(event.getCommentId());
                    if (comment != null) {
                        reputationService.onCommentLiked(comment.getUserId());
                    }
                } else {
                    // 取消点赞
                    commentLikeMapper.upsertLike(event.getCommentId(), 
                        event.getUserId(), 0);
                    commentMapper.incrementLikeCount(event.getCommentId(), -1);
                }
            } catch (Exception e) {
                log.error("处理点赞事件失败: {}", event, e);
            }
        }
    }
}
```

### 3.6 游标分页设计

#### 3.6.1 为什么不用传统分页

传统的 `OFFSET + LIMIT` 分页在大数据量下有严重的性能问题：

```sql
-- 当offset很大时，数据库需要扫描并丢弃前面的offset行
-- 例如 offset=100000, limit=20，数据库需要先扫描100000行再返回20行
SELECT * FROM t_comment 
WHERE subject_id = 12345 AND root_id = 0 AND status = 1
ORDER BY create_time DESC
LIMIT 20 OFFSET 100000;
-- 执行时间可能超过 1秒
```

此外，OFFSET分页还存在数据漂移的问题：当用户在第10页浏览时，有新评论插入到前面，导致原本第10页的某条评论重复出现在第11页，或者某条评论被跳过。

#### 3.6.2 游标分页的原理

游标分页（Cursor-based Pagination）的核心思想来源于数据库中的游标概念——它是一个指向特定行的指针，可以告诉数据库"从这个位置之后返回N行"。这对数据库来说非常友好，因为可以利用索引直接定位到游标位置，不需要扫描和丢弃前面的数据。

```sql
-- 游标分页：以上一页最后一条评论的create_time和id作为游标
-- 直接走索引定位，性能恒定，与页码深度无关
SELECT * FROM t_comment 
WHERE subject_id = 12345 AND root_id = 0 AND status = 1
  AND (create_time < '2024-01-15 10:30:00' 
       OR (create_time = '2024-01-15 10:30:00' AND id < 98765))
ORDER BY create_time DESC, id DESC
LIMIT 20;
-- 无论是第1页还是第10000页，执行时间都在毫秒级
```

#### 3.6.3 游标编解码实现

游标对客户端来说应该是一个不透明的字符串，客户端不应该了解游标的内部结构。服务端负责编码和解码。

```java
/**
 * 游标分页管理器
 * 
 * 游标结构（Base64编码）：
 * {
 *   "ct": "2024-01-15T10:30:00",  // createTime，上一页最后一条的创建时间
 *   "id": 98765,                   // 上一页最后一条的ID
 *   "st": "time_desc"             // sortType，排序方式
 * }
 */
public class CursorPaginationManager {

    /**
     * 将游标信息编码为不透明字符串
     */
    public static String encodeCursor(LocalDateTime createTime, long id, 
                                       String sortType) {
        JSONObject json = new JSONObject();
        json.put("ct", createTime.toString());
        json.put("id", id);
        json.put("st", sortType);
        return Base64.getUrlEncoder().withoutPadding()
            .encodeToString(json.toJSONString().getBytes(StandardCharsets.UTF_8));
    }

    /**
     * 解码游标字符串
     */
    public static CursorInfo decodeCursor(String cursor) {
        if (cursor == null || cursor.isEmpty()) {
            return null; // 首页请求，无游标
        }
        try {
            byte[] decoded = Base64.getUrlDecoder().decode(cursor);
            JSONObject json = JSON.parseObject(new String(decoded, StandardCharsets.UTF_8));

            CursorInfo info = new CursorInfo();
            info.setCreateTime(LocalDateTime.parse(json.getString("ct")));
            info.setId(json.getLongValue("id"));
            info.setSortType(json.getString("st"));
            return info;
        } catch (Exception e) {
            throw new IllegalArgumentException("Invalid cursor: " + cursor);
        }
    }

    /**
     * 构建分页查询条件
     */
    public static void applyCursorCondition(LambdaQueryWrapper<CommentDO> wrapper,
                                             CursorInfo cursor) {
        if (cursor == null) {
            return; // 首页，不需要游标条件
        }

        if ("time_desc".equals(cursor.getSortType())) {
            // 时间倒序：查找比游标更早的记录
            wrapper.and(w -> w
                .lt(CommentDO::getCreateTime, cursor.getCreateTime())
                .or(inner -> inner
                    .eq(CommentDO::getCreateTime, cursor.getCreateTime())
                    .lt(CommentDO::getId, cursor.getId())
                )
            );
        } else {
            // 时间正序：查找比游标更晚的记录
            wrapper.and(w -> w
                .gt(CommentDO::getCreateTime, cursor.getCreateTime())
                .or(inner -> inner
                    .eq(CommentDO::getCreateTime, cursor.getCreateTime())
                    .gt(CommentDO::getId, cursor.getId())
                )
            );
        }
    }

    /**
     * 游标信息
     */
    @Data
    public static class CursorInfo {
        private LocalDateTime createTime;
        private long id;
        private String sortType;
    }
}

/**
 * 分页查询结果
 */
@Data
public class CursorPageResult<T> {
    private List<T> items;       // 当前页数据
    private String nextCursor;   // 下一页游标，null表示没有更多数据
    private boolean hasMore;     // 是否还有更多数据

    public static <T> CursorPageResult<T> of(List<T> items, String nextCursor) {
        CursorPageResult<T> result = new CursorPageResult<>();
        result.setItems(items);
        result.setNextCursor(nextCursor);
        result.setHasMore(nextCursor != null);
        return result;
    }
}
```

#### 3.6.4 评论列表分页查询完整流程

```java
/**
 * 评论查询服务
 */
@Service
public class CommentQueryService {

    @Autowired private CommentMapper commentMapper;
    @Autowired private CommentCacheService cacheService;
    @Autowired private CommentLikeService likeService;
    @Autowired private UserService userService;

    /**
     * 分页查询评论列表（游标分页）
     */
    public CursorPageResult<CommentVO> queryComments(
            long subjectId, int subjectType, 
            String cursor, int pageSize, String sortType) {

        // 第一步：解码游标
        CursorPaginationManager.CursorInfo cursorInfo = 
            CursorPaginationManager.decodeCursor(cursor);

        // 第二步：多查一条用于判断是否有下一页
        int queryLimit = pageSize + 1;

        // 第三步：构建查询条件
        LambdaQueryWrapper<CommentDO> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(CommentDO::getSubjectId, subjectId)
               .eq(CommentDO::getSubjectType, subjectType)
               .eq(CommentDO::getRootId, 0)  // 只查一级评论
               .eq(CommentDO::getStatus, 1);  // 只查已发布

        // 应用游标条件
        CursorPaginationManager.applyCursorCondition(wrapper, cursorInfo);

        // 排序
        if ("time_desc".equals(sortType)) {
            wrapper.orderByDesc(CommentDO::getCreateTime)
                   .orderByDesc(CommentDO::getId);
        } else {
            wrapper.orderByAsc(CommentDO::getCreateTime)
                   .orderByAsc(CommentDO::getId);
        }

        wrapper.last("LIMIT " + queryLimit);

        // 第四步：执行查询
        List<CommentDO> comments = commentMapper.selectList(wrapper);

        // 第五步：判断是否有下一页，计算下一页游标
        boolean hasMore = comments.size() > pageSize;
        if (hasMore) {
            comments = comments.subList(0, pageSize); // 去掉多查的那一条
        }

        // 第六步：批量查询子评论（每条一级评论的前3条回复）
        List<CommentVO> voList = enrichComments(comments, subjectId, subjectType);

        // 第七步：构建下一页游标
        String nextCursor = null;
        if (hasMore && !comments.isEmpty()) {
            CommentDO lastComment = comments.get(comments.size() - 1);
            nextCursor = CursorPaginationManager.encodeCursor(
                lastComment.getCreateTime(), lastComment.getId(), sortType);
        }

        return CursorPageResult.of(voList, nextCursor);
    }

    /**
     * 丰富评论信息：子评论、用户信息、点赞状态
     */
    private List<CommentVO> enrichComments(List<CommentDO> comments, 
                                            long subjectId, int subjectType) {
        if (comments.isEmpty()) {
            return Collections.emptyList();
        }

        // 1. 批量查询每条一级评论的前3条回复
        List<Long> rootIds = comments.stream()
            .map(CommentDO::getId)
            .collect(Collectors.toList());
        Map<Long, List<CommentDO>> replyMap = batchQueryReplies(rootIds, 3);

        // 2. 收集所有涉及的用户ID
        Set<Long> userIds = new HashSet<>();
        comments.forEach(c -> {
            userIds.add(c.getUserId());
            if (c.getReplyUserId() > 0) userIds.add(c.getReplyUserId());
        });
        replyMap.values().forEach(replies ->
            replies.forEach(r -> {
                userIds.add(r.getUserId());
                if (r.getReplyUserId() > 0) userIds.add(r.getReplyUserId());
            })
        );

        // 3. 批量查询用户信息
        Map<Long, UserInfo> userInfoMap = userService.batchGetUserInfo(
            new ArrayList<>(userIds));

        // 4. 批量查询当前用户的点赞状态
        long currentUserId = UserContext.getCurrentUserId();
        List<Long> allCommentIds = new ArrayList<>(rootIds);
        replyMap.values().forEach(replies -> 
            replies.forEach(r -> allCommentIds.add(r.getId())));
        Map<Long, Boolean> likeMap = likeService.batchCheckLiked(
            currentUserId, allCommentIds);

        // 5. 组装VO
        return comments.stream().map(comment -> {
            CommentVO vo = convertToVO(comment, userInfoMap, likeMap);
            List<CommentDO> replies = replyMap.getOrDefault(
                comment.getId(), Collections.emptyList());
            vo.setReplies(replies.stream()
                .map(r -> convertToVO(r, userInfoMap, likeMap))
                .collect(Collectors.toList()));
            return vo;
        }).collect(Collectors.toList());
    }

    private Map<Long, List<CommentDO>> batchQueryReplies(List<Long> rootIds, 
                                                          int limit) {
        // 批量查询所有root_id的回复，每个root_id最多取limit条
        // 使用分组查询减少数据库调用次数
        return commentMapper.selectRepliesByRootIds(rootIds, limit);
    }

    private CommentVO convertToVO(CommentDO comment, 
                                   Map<Long, UserInfo> userInfoMap,
                                   Map<Long, Boolean> likeMap) {
        CommentVO vo = new CommentVO();
        vo.setId(comment.getId());
        vo.setContent(comment.getContent());
        vo.setLikeCount(comment.getLikeCount());
        vo.setReplyCount(comment.getReplyCount());
        vo.setCreateTime(comment.getCreateTime());
        vo.setParentId(comment.getParentId());
        vo.setRootId(comment.getRootId());

        // 填充用户信息
        UserInfo userInfo = userInfoMap.get(comment.getUserId());
        if (userInfo != null) {
            vo.setUserName(userInfo.getNickname());
            vo.setUserAvatar(userInfo.getAvatar());
        }

        // 填充被回复用户信息
        if (comment.getReplyUserId() > 0) {
            UserInfo replyUser = userInfoMap.get(comment.getReplyUserId());
            if (replyUser != null) {
                vo.setReplyUserName(replyUser.getNickname());
            }
        }

        // 填充点赞状态
        vo.setLiked(Boolean.TRUE.equals(likeMap.get(comment.getId())));

        return vo;
    }
}
```

### 3.7 评论缓存设计

#### 3.7.1 缓存架构：二级缓存

评论系统采用二级缓存架构：本地缓存（L1）+ Redis缓存（L2）。

| 层级 | 存储 | 容量 | 失效时间 | 命中率 |
|------|------|------|----------|--------|
| L1 | Caffeine (JVM内存) | 1万条主题 | 30秒 | ~70% |
| L2 | Redis Hash | 不限 | 10分钟 | ~95% |
| DB | MySQL | 不限 | - | - |

**L1本地缓存的意义**：
- 避免网络往返延迟（Redis调用通常0.5~2ms）
- 减轻Redis压力
- 热点评论命中率极高

**为什么L1的过期时间设为30秒？**
- 评论系统对数据一致性的要求是"最终一致"，不是强一致
- 30秒内评论列表展示旧数据是可以接受的
- 过期时间太长会导致新评论展示延迟，影响用户体验

#### 3.7.2 Redis Hash存储评论数据

使用Redis Hash存储评论数据，key按主题维度组织，field为评论ID，value为评论的JSON序列化数据。相比使用独立的String Key存储每条评论，Hash结构有显著的内存节省——Redis内部对小型Hash使用ziplist编码，内存使用效率更高。

```java
/**
 * 评论缓存服务
 * L1: Caffeine 本地缓存
 * L2: Redis Hash
 */
@Service
public class CommentCacheService {

    @Autowired private StringRedisTemplate redisTemplate;

    // Redis Hash key前缀
    private static final String COMMENT_HASH_KEY = "comment:data:";
    // 评论列表索引 key前缀（有序列表）
    private static final String COMMENT_INDEX_KEY = "comment:index:";
    // Redis缓存过期时间
    private static final long REDIS_TTL_MINUTES = 10;

    // L1本地缓存：主题ID -> 该主题下一级评论列表
    private final Cache<String, List<CommentVO>> localCache = Caffeine.newBuilder()
        .maximumSize(10_000)             // 最多缓存1万个主题
        .expireAfterWrite(30, TimeUnit.SECONDS)  // 30秒过期
        .build();

    /**
     * 获取评论列表（先查L1，再查L2，最后查DB）
     */
    public List<CommentVO> getComments(long subjectId, int subjectType,
                                        int page, int pageSize) {
        String cacheKey = subjectType + ":" + subjectId + ":" + page;

        // L1: 本地缓存
        List<CommentVO> cached = localCache.getIfPresent(cacheKey);
        if (cached != null) {
            return cached;
        }

        // L2: Redis缓存
        List<CommentVO> fromRedis = getFromRedis(subjectId, subjectType, page, pageSize);
        if (fromRedis != null && !fromRedis.isEmpty()) {
            localCache.put(cacheKey, fromRedis);
            return fromRedis;
        }

        // DB: 查询数据库（由上层服务执行，这里返回null表示缓存未命中）
        return null;
    }

    /**
     * 将评论数据写入缓存
     */
    public void putComments(long subjectId, int subjectType,
                             int page, int pageSize, List<CommentVO> comments) {
        String cacheKey = subjectType + ":" + subjectId + ":" + page;

        // 写入L1
        localCache.put(cacheKey, comments);

        // 写入L2: 使用Hash结构存储每条评论
        String hashKey = COMMENT_HASH_KEY + subjectType + ":" + subjectId;
        Map<String, String> hashEntries = new HashMap<>();
        for (CommentVO comment : comments) {
            hashEntries.put(String.valueOf(comment.getId()), 
                JSON.toJSONString(comment));
        }
        if (!hashEntries.isEmpty()) {
            redisTemplate.opsForHash().putAll(hashKey, hashEntries);
            redisTemplate.expire(hashKey, REDIS_TTL_MINUTES, TimeUnit.MINUTES);
        }
    }

    /**
     * 从Redis获取评论列表
     */
    private List<CommentVO> getFromRedis(long subjectId, int subjectType,
                                          int page, int pageSize) {
        String hashKey = COMMENT_HASH_KEY + subjectType + ":" + subjectId;
        String indexKey = COMMENT_INDEX_KEY + subjectType + ":" + subjectId;

        // 从评论索引中获取当前页的评论ID列表
        long start = (long) page * pageSize;
        long end = start + pageSize - 1;
        Set<String> commentIds = redisTemplate.opsForZSet()
            .reverseRange(indexKey, start, end);

        if (commentIds == null || commentIds.isEmpty()) {
            return null;
        }

        // 使用 HMGET 批量获取评论数据
        List<Object> commentJsonList = redisTemplate.opsForHash()
            .multiGet(hashKey, new ArrayList<>(commentIds));

        List<CommentVO> result = new ArrayList<>();
        for (Object json : commentJsonList) {
            if (json != null) {
                result.add(JSON.parseObject(json.toString(), CommentVO.class));
            }
        }

        return result.isEmpty() ? null : result;
    }

    /**
     * 发布新评论时更新缓存
     * 策略：删除缓存，让下一次请求从DB加载最新数据
     */
    public void invalidateCommentCache(long subjectId, int subjectType) {
        // 删除L1缓存（按前缀匹配删除该主题的所有分页缓存）
        localCache.asMap().keySet().removeIf(
            key -> key.startsWith(subjectType + ":" + subjectId + ":"));

        // 删除L2缓存
        String hashKey = COMMENT_HASH_KEY + subjectType + ":" + subjectId;
        String indexKey = COMMENT_INDEX_KEY + subjectType + ":" + subjectId;
        redisTemplate.delete(Arrays.asList(hashKey, indexKey));
    }

    /**
     * 更新单条评论的缓存（点赞数变更等场景）
     */
    public void updateSingleComment(long subjectId, int subjectType,
                                     CommentVO comment) {
        String hashKey = COMMENT_HASH_KEY + subjectType + ":" + subjectId;
        redisTemplate.opsForHash().put(hashKey, 
            String.valueOf(comment.getId()), JSON.toJSONString(comment));
    }
}
```

#### 3.7.3 缓存一致性保障

缓存一致性是评论系统中的常见难题。当评论数据发生变更（新增评论、删除评论、修改点赞数）时，需要保证缓存中的数据与数据库保持一致。

采用的策略是 **"先写DB，再删缓存"+ "延迟双删"**：

```java
/**
 * 评论写入服务（包含缓存一致性保障）
 */
@Service
public class CommentWriteService {

    @Autowired private CommentMapper commentMapper;
    @Autowired private CommentCacheService cacheService;
    @Autowired private AntiSpamEngine antiSpamEngine;
    @Autowired private ScheduledExecutorService scheduler;

    /**
     * 发布新评论
     */
    @Transactional
    public CommentVO publishComment(CommentPublishRequest request) {
        // 1. 反垃圾检查
        AntiSpamResult spamResult = antiSpamEngine.check(
            request.getUserId(), request.getContent());
        if (spamResult.getType() == AntiSpamResult.ResultType.REJECT) {
            throw new BusinessException(spamResult.getMessage());
        }

        // 2. 构建评论实体
        CommentDO comment = new CommentDO();
        comment.setSubjectId(request.getSubjectId());
        comment.setSubjectType(request.getSubjectType());
        comment.setUserId(request.getUserId());
        comment.setContent(request.getContent());
        comment.setParentId(request.getParentId());
        comment.setRootId(request.getRootId());
        comment.setReplyUserId(request.getReplyUserId());

        // 根据反垃圾结果设置状态
        if (spamResult.getType() == AntiSpamResult.ResultType.MANUAL_REVIEW) {
            comment.setStatus(0); // 待审核
        } else {
            comment.setStatus(1); // 已发布
        }

        // 3. 写入数据库
        commentMapper.insert(comment);

        // 4. 如果是回复，更新父评论的回复计数
        if (comment.getRootId() > 0) {
            commentMapper.incrementReplyCount(comment.getRootId(), 1);
        }

        // 5. 第一次删缓存
        cacheService.invalidateCommentCache(
            request.getSubjectId(), request.getSubjectType());

        // 6. 延迟500ms再删一次缓存（防止并发读请求将旧数据写回缓存）
        scheduler.schedule(() -> {
            cacheService.invalidateCommentCache(
                request.getSubjectId(), request.getSubjectType());
        }, 500, TimeUnit.MILLISECONDS);

        // 7. 发送MQ事件
        sendCommentCreatedEvent(comment);

        return convertToVO(comment);
    }
}
```

## 四、异常处理与容错机制

### 4.1 评论发布的幂等设计

网络抖动或用户重复点击可能导致同一条评论被提交多次。通过幂等Token机制来防止重复发布：

```java
/**
 * 评论发布幂等控制
 */
@Service
public class CommentIdempotentService {

    @Autowired private StringRedisTemplate redisTemplate;

    private static final String IDEMPOTENT_KEY_PREFIX = "comment:idempotent:";
    private static final long IDEMPOTENT_EXPIRE_SECONDS = 300; // 5分钟

    /**
     * 获取幂等Token
     * 客户端在进入评论编辑页面时调用，获取一个一次性Token
     */
    public String generateToken(long userId) {
        String token = UUID.randomUUID().toString().replace("-", "");
        String key = IDEMPOTENT_KEY_PREFIX + userId + ":" + token;
        redisTemplate.opsForValue().set(key, "1", 
            IDEMPOTENT_EXPIRE_SECONDS, TimeUnit.SECONDS);
        return token;
    }

    /**
     * 消费幂等Token
     * 发布评论时调用，利用Redis的原子DELETE操作保证只有一个请求能成功消费
     * @return true表示Token有效（首次提交），false表示Token已被消费（重复提交）
     */
    public boolean consumeToken(long userId, String token) {
        String key = IDEMPOTENT_KEY_PREFIX + userId + ":" + token;
        // DELETE操作是原子的，只有一个线程能成功删除
        Boolean deleted = redisTemplate.delete(key);
        return Boolean.TRUE.equals(deleted);
    }
}
```

### 4.3 消息队列的可靠投递

评论系统中大量使用MQ进行异步处理（计数更新、缓存刷新、通知发送等），消息的可靠投递至关重要。

```java
/**
 * 可靠消息发送器
 * 先写本地消息表，再发送MQ
 * 定时任务补偿发送失败的消息
 */
@Service
public class ReliableMessageSender {

    @Autowired private LocalMessageMapper messageMapper;
    @Autowired private KafkaTemplate<String, String> kafkaTemplate;

    /**
     * 在事务中记录本地消息
     */
    @Transactional
    public void sendInTransaction(String topic, String key, String body) {
        // 写入本地消息表
        LocalMessage message = new LocalMessage();
        message.setTopic(topic);
        message.setMessageKey(key);
        message.setBody(body);
        message.setStatus(0); // 待发送
        message.setRetryCount(0);
        messageMapper.insert(message);
    }

    /**
     * 定时任务：扫描未发送的消息，进行补偿发送
     * 每5秒执行一次
     */
    @Scheduled(fixedDelay = 5000)
    public void compensateSend() {
        List<LocalMessage> pendingMessages = messageMapper.selectPending(100);

        for (LocalMessage msg : pendingMessages) {
            try {
                kafkaTemplate.send(msg.getTopic(), msg.getMessageKey(), msg.getBody())
                    .addCallback(
                        result -> {
                            // 发送成功，更新状态
                            messageMapper.updateStatus(msg.getId(), 1);
                        },
                        ex -> {
                            // 发送失败，增加重试次数
                            messageMapper.incrementRetry(msg.getId());
                            log.error("消息发送失败: id={}", msg.getId(), ex);
                        }
                    );
            } catch (Exception e) {
                messageMapper.incrementRetry(msg.getId());
                log.error("消息发送异常: id={}", msg.getId(), e);
            }
        }
    }
}
```

## 五、性能优化

### 5.1 数据库层面优化

#### 5.1.1 分库分表策略

当评论数据量达到数十亿级别时，单库单表已经无法满足性能要求。采用以下分库分表策略：

**分片键选择**：使用 `subject_id` 作为分片键（而非评论ID），原因是评论系统的查询都是以主题为维度——查询某个文章/商品下的评论列表。以 `subject_id` 为分片键，同一个主题的所有评论会落在同一个分片上，避免了跨分片查询。

```
分片规则：shard_index = hash(subject_id) % 64

总计 16 个数据库实例 × 4 张表 = 64 个分片
单个分片上限约 1.5亿 条评论
总容量上限约 100亿 条评论
```

### 5.2 缓存层面优化

#### 5.2.1 缓存预热

对于可以预见的热点（如即将上线的爆款活动），提前将评论数据加载到缓存中：

```java
/**

@Service
public class CommentCacheWarmupService {
```

#### 5.2.2 缓存穿透防护

```java
/**
 * 缓存穿透防护
 */
public List<CommentVO> queryWithAntiPenetration(long subjectId, int subjectType,
                                                  int page, int pageSize) {
    String nullKey = "comment:null:" + subjectType + ":" + subjectId;

    // 检查是否已知为空结果

        return Collections.emptyList();
```

### 5.3 计数系统优化

评论数、点赞数等计数数据的访问量极大。参考业界计数系统的设计经验，核心优化思路如下：

#### 5.3.1 写入优化：消息聚合批处理

当热门评论在短时间内收到大量点赞时，可以通过批量合并的方式减少对Redis/DB的写压力。例如，连续三次点赞操作 `+1, +1, +1` 可以合并为一次 `+3` 操作：

```java
/**
 * 计数写入缓冲器
 * 将高频的计数更新合并为批量操作
 */
@Service
public class CounterWriteBuffer {

    // 缓冲区：key -> 累计增量
    private final ConcurrentHashMap<String, AtomicLong> buffer = 
        new ConcurrentHashMap<>();

    /**
     * 累加计数（不立即写入Redis，先在内存中合并）
     */
    public void increment(String key, long delta) {
        buffer.computeIfAbsent(key, k -> new AtomicLong(0)).addAndGet(delta);
    }

    /**
     * 定时刷新：每秒将缓冲区的累计增量批量写入Redis
     */
    @Scheduled(fixedDelay = 1000)
    public void flush() {
        if (buffer.isEmpty()) return;

        // 取出当前缓冲区的所有数据
        Map<String, Long> snapshot = new HashMap<>();
        Iterator<Map.Entry<String, AtomicLong>> it = buffer.entrySet().iterator();
        while (it.hasNext()) {
            Map.Entry<String, AtomicLong> entry = it.next();
            long value = entry.getValue().getAndSet(0);
            if (value != 0) {
                snapshot.put(entry.getKey(), value);
            }
            if (entry.getValue().get() == 0) {
                it.remove(); // 清理已归零的key
            }
        }

        // 批量写入Redis
        if (!snapshot.isEmpty()) {
            redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
                for (Map.Entry<String, Long> entry : snapshot.entrySet()) {
                    connection.incrBy(entry.getKey().getBytes(), entry.getValue());
                }
                return null;
            });
        }
    }
}
```

#### 5.3.2 读取优化：多级缓存 + Pipeline

评论列表中每条评论都需要展示点赞数、回复数等计数信息。如果逐条查询Redis，网络往返次数会很多。使用Pipeline批量查询：

```java
/**
 * 批量获取评论计数
 */
public Map<Long, CommentCountVO> batchGetCounts(List<Long> commentIds) {
    List<String> keys = commentIds.stream()
        .map(id -> "comment:like_count:" + id)
        .collect(Collectors.toList());

    // 使用MGET批量获取
    List<String> values = redisTemplate.opsForValue().multiGet(keys);

    Map<Long, CommentCountVO> result = new HashMap<>();
    for (int i = 0; i < commentIds.size(); i++) {
        CommentCountVO countVO = new CommentCountVO();
        countVO.setCommentId(commentIds.get(i));
        String value = values.get(i);
        countVO.setLikeCount(value == null ? 0 : Integer.parseInt(value));
        result.put(commentIds.get(i), countVO);
    }
    return result;
}
```

```java
 * 并行批量获取评论的关联信息

public void enrichCommentsParallel(List<CommentVO> comments) {
    if (comments.isEmpty()) return;

    List<Long> commentIds = comments.stream()
        .map(CommentVO::getId).collect(Collectors.toList());
    Set<Long> userIds = comments.stream()
        .map(CommentVO::getUserId).collect(Collectors.toSet());
    long currentUserId = UserContext.getCurrentUserId();

    // 并行调用三个下游服务
    CompletableFuture<Map<Long, UserInfo>> userFuture = 
        CompletableFuture.supplyAsync(() -> 
            userService.batchGetUserInfo(new ArrayList<>(userIds)));

    CompletableFuture<Map<Long, Boolean>> likeFuture = 
        CompletableFuture.supplyAsync(() -> 
            likeService.batchCheckLiked(currentUserId, commentIds));

    CompletableFuture<Map<Long, CommentCountVO>> countFuture = 
        CompletableFuture.supplyAsync(() -> 
            counterService.batchGetCounts(commentIds));

    // 等待所有并行任务完成
    CompletableFuture.allOf(userFuture, likeFuture, countFuture).join();

    Map<Long, UserInfo> userMap = userFuture.join();
    Map<Long, Boolean> likeMap = likeFuture.join();
    Map<Long, CommentCountVO> countMap = countFuture.join();

    // 填充信息
    for (CommentVO comment : comments) {
        UserInfo user = userMap.get(comment.getUserId());
        if (user != null) {
            comment.setUserName(user.getNickname());
            comment.setUserAvatar(user.getAvatar());
        }
        comment.setLiked(Boolean.TRUE.equals(likeMap.get(comment.getId())));
        CommentCountVO count = countMap.get(comment.getId());
        if (count != null) {
            comment.setLikeCount(count.getLikeCount());
        }
    }
```

## 六、最佳实践与总结

### 6.1 设计原则总结

| 原则 | 应用场景 | 说明 |
|------|---------|------|
| 读写分离 | 评论数据访问 | 读操作走缓存，写操作先DB再异步刷新缓存 |
| 异步解耦 | 评论发布后的处理 | 通过MQ异步执行计数更新、缓存刷新、通知发送 |
| 分级管控 | 内容安全审核 | 根据用户信誉分决定审核严格程度 |
| 最终一致 | 缓存与DB一致性 | 评论系统容忍短暂的数据不一致 |
| 降级兜底 | 系统可用性保障 | DB不可用时降级到缓存，缓存不可用时返回空列表 |

### 6.2 核心设计决策回顾

**1）评论树结构选择二级模型**

选择 parentId + rootId 双指针方案，限制评论层级为2层。这个决策的关键考量是：移动端展示效率、数据库查询性能、代码复杂度之间的平衡。二级模型在这三个维度上都达到了最佳平衡点。

**2）敏感词过滤选择AC自动机**

相比简单的DFA（Trie树逐字符匹配），AC自动机通过失败指针实现了"不回头扫描"——整个文本只需要遍历一遍。在敏感词数量达到数万级别时，性能差异显著。同时通过职责链模式组织多个过滤器，使得过滤规则的扩展非常方便——新增一种过滤规则只需要实现ContentFilter接口并注册到FilterChain中。

**3）分页选择游标方式**

传统的OFFSET分页在深度分页（翻到后面几百页）时性能急剧下降，并且在有新数据插入时会出现数据漂移。游标分页通过WHERE条件直接定位到起始位置，执行时间与页码深度无关，非常适合评论列表这种无限滚动的场景。

**4）计数存储选择Redis**

评论的点赞数、回复数等计数数据，完全使用Redis存储，而非传统的"数据库+缓存"方式。原因是计数数据的特点——更新极其频繁（热门评论每秒可能收到数百次点赞），而数据库+缓存方案难以保证二者的一致性。使用Redis作为计数的唯一存储源，通过MQ异步持久化到数据库作为备份。

### 6.5 可扩展性设计

评论系统的核心设计遵循了以下扩展性原则：

**业务维度扩展**：通过 `subject_type` 字段，同一套评论系统可以服务于文章评论、商品评价、视频评论等多种业务场景，新增业务场景只需定义新的 `subject_type` 值。

**过滤规则扩展**：通过职责链模式，新增过滤规则只需要实现 `ContentFilter` 接口并注册到 `FilterChain` 中，无需修改任何已有代码。

**存储层扩展**：分库分表方案预留了充足的扩展空间，当单个分片的数据量接近上限时，可以通过增加分片数量来水平扩展，业务层无感知。

**性能层扩展**：二级缓存架构中，L1和L2可以独立调整参数（容量、过期时间、淘汰策略），应对不同的流量模式。热点主题可以动态开启更激进的缓存策略。

### 6.6 总结

评论系统看似简单，实则涉及数据结构设计、内容安全、高性能读写、缓存一致性、容量规划等多个维度的技术挑战。本文从以下几个层面进行了系统性的设计：

1. **数据模型层**：采用 parentId + rootId 双指针的二级评论树结构，在展示效率和查询性能之间取得平衡。

2. **内容安全层**：基于AC自动机实现高性能敏感词过滤，通过职责链模式组合多种过滤策略，结合频率控制、内容相似度检测和用户信誉分构建多维度的反垃圾体系。

3. **数据访问层**：使用游标分页替代传统OFFSET分页，彻底解决深度分页的性能问题和数据漂移问题。

4. **缓存层**：设计 Caffeine + Redis 二级缓存架构，通过延迟双删策略保障缓存一致性，通过缓存预热和穿透防护提升系统鲁棒性。

5. **容错层**：从幂等设计、降级策略、可靠消息投递、热点保护等多个角度构建系统的容错能力。

6. **性能优化层**：通过批量化、并行化、计数聚合等手段，将评论列表接口的P99延迟控制在100ms以内。

以上设计方案经过大规模生产环境的验证，能够支撑亿级评论数据量和万级QPS的访问压力。在实际落地时，建议根据业务的具体规模和阶段，选择性地采用相应的优化策略——不必一开始就引入全部复杂度，而是随着业务增长逐步演进。

#### 7.1.4 Service层：评论资格校验

```java
/**
 * 评论发布Service
 * 串联资格校验、内容审核、数据入库、缓存失效、MQ事件发送
 */
@Service
@Slf4j
public class CommentPublishService {

    @Autowired private CommentEligibilityService eligibilityService;
    @Autowired private CommentContentAuditService contentAuditService;
    @Autowired private CommentRepository commentRepository;
    @Autowired private CommentCacheService cacheService;
    @Autowired private CommentImageMapper commentImageMapper;
    @Autowired private ReliableMessageSender messageSender;
    @Autowired private ScheduledExecutorService scheduler;

    /**
     * 评论发布全链路
     */
    @Transactional(rollbackFor = Exception.class)
    public CommentPublishResponse publish(CommentPublishRequest request) {
        long userId = request.getUserId();
        String traceId = MDC.get("traceId");
        long startTime = System.currentTimeMillis();

        try {
            // ==================== 第一阶段：评论资格校验 ====================
            log.info("[{}] 开始评论资格校验: userId={}, subjectId={}, orderNo={}",
                traceId, userId, request.getSubjectId(), request.getOrderNo());

            EligibilityResult eligibility = eligibilityService.check(
                userId, request.getSubjectId(), request.getSubjectType(),
                request.getOrderNo());

            if (!eligibility.isEligible()) {
                log.warn("[{}] 评论资格校验不通过: userId={}, reason={}",
                    traceId, userId, eligibility.getReason());
                throw new BusinessException(
                    eligibility.getRejectCode(), eligibility.getReason());
            }
            log.info("[{}] 评论资格校验通过: userId={}", traceId, userId);

            // ==================== 第二阶段：内容安全审核 ====================
            log.info("[{}] 开始内容安全审核: userId={}", traceId, userId);

            ContentAuditResult auditResult = contentAuditService.audit(
                request.getContent(), request.getImageUrls(), request.getVideoUrls());

            if (auditResult.isRejected()) {
                // 审核不通过：仍然写入数据库，但标记为审核不通过状态
                log.warn("[{}] 内容审核不通过: userId={}, reason={}, hitWords={}",
                    traceId, userId, auditResult.getReason(), auditResult.getHitWords());

                CommentDO comment = buildCommentEntity(request, auditResult);
                comment.setStatus(3); // 审核不通过
                commentRepository.insert(comment);
                saveImages(comment.getId(), request.getImageUrls());

                // 返回提示信息给用户
                CommentPublishResponse response = new CommentPublishResponse();
                response.setCommentId(comment.getId());
                response.setStatus(3);
                response.setMessage("您的评论包含违规内容，请修改后重新提交");
                return response;
            }

            // ==================== 第三阶段：评论数据入库 ====================
            log.info("[{}] 开始评论数据入库: userId={}", traceId, userId);

            CommentDO comment = buildCommentEntity(request, auditResult);
            // 根据审核结果设置状态
            if (auditResult.isNeedManualReview()) {
                comment.setStatus(0); // 待人工审核
            } else {
                comment.setStatus(1); // 已发布
            }

            commentRepository.insert(comment);
            // 批量写入评论图片
            if (request.getImageUrls() != null && !request.getImageUrls().isEmpty()) {
                saveImages(comment.getId(), request.getImageUrls());
            }
            // 批量写入评论视频
            if (request.getVideoUrls() != null && !request.getVideoUrls().isEmpty()) {
                saveVideos(comment.getId(), request.getVideoUrls());
            }

            log.info("[{}] 评论数据入库成功: commentId={}, status={}",
                traceId, comment.getId(), comment.getStatus());

            // ==================== 第四阶段：缓存失效 ====================
            // 先写DB再删缓存 + 延迟双删
            cacheService.invalidateCommentCache(
                request.getSubjectId(), request.getSubjectType());

            scheduler.schedule(() -> {
                try {
                    cacheService.invalidateCommentCache(
                        request.getSubjectId(), request.getSubjectType());
                } catch (Exception e) {
                    log.warn("[{}] 延迟双删缓存失败: subjectId={}",
                        traceId, request.getSubjectId(), e);
                }
            }, 500, TimeUnit.MILLISECONDS);

            // ==================== 第五阶段：发送MQ事件（异步链路） ====================
            // 只有已发布的评论才触发后续异步处理
            if (comment.getStatus() == 1) {
                sendCommentPublishedEvent(comment, request);
                log.info("[{}] 评论发布事件已发送: commentId={}", traceId, comment.getId());
            }

            // ==================== 返回结果 ====================
            CommentPublishResponse response = new CommentPublishResponse();
            response.setCommentId(comment.getId());
            response.setStatus(comment.getStatus());
            response.setMessage(comment.getStatus() == 1 ?
                "评论发布成功" : "评论已提交，正在审核中");
            return response;

        } finally {
            long elapsed = System.currentTimeMillis() - startTime;
            log.info("[{}] 评论发布全链路耗时: {}ms, userId={}",
                traceId, elapsed, userId);
            // 记录耗时指标到监控系统
            MetricsUtil.recordTimer("comment.publish.latency", elapsed);
        }
    }

    /**
     * 构建评论实体
     */
    private CommentDO buildCommentEntity(CommentPublishRequest request,
                                          ContentAuditResult auditResult) {
        CommentDO comment = new CommentDO();
        comment.setSubjectId(request.getSubjectId());
        comment.setSubjectType(request.getSubjectType());
        comment.setUserId(request.getUserId());
        // XSS过滤 + 敏感词替换后的内容
        comment.setContent(auditResult.getFilteredContent());
        comment.setParentId(0L);
        comment.setRootId(0L);
        comment.setIpAddress(request.getIpAddress());
        comment.setDeviceType(request.getDeviceType());
        return comment;
    }

    /**
     * 批量保存评论图片
     */
    private void saveImages(Long commentId, List<String> imageUrls) {
        List<CommentImageDO> images = new ArrayList<>();
        for (int i = 0; i < imageUrls.size(); i++) {
            CommentImageDO image = new CommentImageDO();
            image.setCommentId(commentId);
            image.setImageUrl(imageUrls.get(i));
            image.setSortOrder(i);
            images.add(image);
        }
        commentImageMapper.batchInsert(images);
    }

    /**
     * 批量保存评论视频
     */
    private void saveVideos(Long commentId, List<String> videoUrls) {
        List<CommentVideoDO> videos = new ArrayList<>();
        for (int i = 0; i < videoUrls.size(); i++) {
            CommentVideoDO video = new CommentVideoDO();
            video.setCommentId(commentId);
            video.setVideoUrl(videoUrls.get(i));
            video.setSortOrder(i);
            videos.add(video);
        }
        commentVideoMapper.batchInsert(videos);
    }

    /**
     * 发送评论发布事件（通过可靠消息发送器）
     */
    private void sendCommentPublishedEvent(CommentDO comment,
                                            CommentPublishRequest request) {
        CommentPublishedEvent event = new CommentPublishedEvent();
        event.setCommentId(comment.getId());
        event.setSubjectId(comment.getSubjectId());
        event.setSubjectType(comment.getSubjectType());
        event.setUserId(comment.getUserId());
        event.setRating(request.getRating());
        event.setOrderNo(request.getOrderNo());
        event.setHasImages(request.getImageUrls() != null
            && !request.getImageUrls().isEmpty());
        event.setTimestamp(System.currentTimeMillis());

        // 通过本地消息表保证可靠投递
        messageSender.sendInTransaction(
            "comment-published",
            String.valueOf(comment.getId()),
            JSON.toJSONString(event));
    }
```

```java
/**

 * 校验用户是否有资格对某商品发表评论

@Service
@Slf4j
public class CommentEligibilityService {

    @Autowired private OrderRpcService orderRpcService;
    @Autowired private CommentMapper commentMapper;

    /**
     * 评论资格校验
     * @param userId      用户ID
     * @param subjectId   商品ID
     * @param subjectType 主题类型
     * @param orderNo     订单号
     * @return 校验结果
     */
    public EligibilityResult check(long userId, long subjectId,
                                     int subjectType, String orderNo) {
        String traceId = MDC.get("traceId");

        // 1. 校验订单归属：用户是否购买了该商品
        OrderInfo orderInfo;
        try {
            orderInfo = orderRpcService.queryOrder(orderNo, userId);
        } catch (Exception e) {
            log.error("[{}] 订单服务调用失败: orderNo={}", traceId, orderNo, e);
            return EligibilityResult.reject("ORDER_SERVICE_ERROR",
                "订单服务暂时不可用，请稍后重试");
        }

        if (orderInfo == null || orderInfo.getUserId() != userId) {
            log.warn("[{}] 订单归属校验失败: userId={}, orderNo={}",
                traceId, userId, orderNo);
            return EligibilityResult.reject("ORDER_NOT_BELONG",
                "未找到该订单，无法评论");
        }

        // 2. 校验订单中的商品是否与评论目标一致
        if (orderInfo.getProductId() != subjectId) {
            log.warn("[{}] 商品与订单不匹配: subjectId={}, orderProductId={}",
                traceId, subjectId, orderInfo.getProductId());
            return EligibilityResult.reject("PRODUCT_MISMATCH",
                "该商品不在订单中，无法评论");
        }

        // 3. 校验订单状态：订单必须已完成（已确认收货）
        if (orderInfo.getStatus() != OrderStatus.COMPLETED.getCode()) {
            log.warn("[{}] 订单未完成: orderNo={}, status={}",
                traceId, orderNo, orderInfo.getStatus());
            return EligibilityResult.reject("ORDER_NOT_COMPLETED",
                "订单确认收货后才能发表评论");
        }

        // 4. 校验是否已评论过该商品（一单一评）
        Integer existingCount = commentMapper.countByUserAndSubject(
            userId, subjectId, subjectType, orderNo);
        if (existingCount != null && existingCount > 0) {
            log.warn("[{}] 重复评论: userId={}, subjectId={}, orderNo={}",
                traceId, userId, subjectId, orderNo);
            return EligibilityResult.reject("ALREADY_COMMENTED",
                "您已对该商品发表过评论");
        }

        return EligibilityResult.pass();
    }
}

 * 资格校验结果
 */

    private boolean eligible;
    private String rejectCode;
    private String reason;

    public static EligibilityResult pass() {
        EligibilityResult r = new EligibilityResult();
        r.setEligible(true);
        return r;
    }

    public static EligibilityResult reject(String code, String reason) {
        EligibilityResult r = new EligibilityResult();
        r.setEligible(false);
        r.setRejectCode(code);
        r.setReason(reason);
        return r;
    }
```

```java
/**
 * 内容安全审核服务
 * 组合敏感词过滤、图片鉴黄、AI内容审核
 */
@Service
@Slf4j
public class CommentContentAuditService {

    @Autowired private SensitiveWordService sensitiveWordService;
    @Autowired private ContentFilterChain filterChain;
    @Autowired private ImageAuditRpcService imageAuditService;
    @Autowired private AiContentAuditRpcService aiAuditService;

    // 图片审核超时时间
    private static final int IMAGE_AUDIT_TIMEOUT_MS = 3000;
    // AI审核超时时间
    private static final int AI_AUDIT_TIMEOUT_MS = 2000;

    /**
     * 内容审核全流程
     * @param content   文本内容
     * @param imageUrls 图片URL列表
     * @param videoUrls 视频URL列表
     * @return 审核结果
     */
    public ContentAuditResult audit(String content, List<String> imageUrls,
                                      List<String> videoUrls) {
        String traceId = MDC.get("traceId");
        ContentAuditResult result = new ContentAuditResult();
        result.setOriginalContent(content);

        // ========== 第一步：文本敏感词过滤（同步，AC自动机） ==========
        FilterResult filterResult = filterChain.filter(content);
        if (!filterResult.isPassed()) {
            log.warn("[{}] 敏感词过滤未通过: type={}, hitWords={}",
                traceId, filterResult.getFilterType(), filterResult.getHitWords());
            result.setRejected(true);
            result.setReason(filterResult.getReason());
            result.setHitWords(filterResult.getHitWords());
            return result;
        }

        // 敏感词替换后的内容（用于入库）
        String filteredContent = sensitiveWordService.filter(content);
        result.setFilteredContent(filteredContent);

        // ========== 第二步：图片鉴黄（同步，调用图片审核服务） ==========
        if (imageUrls != null && !imageUrls.isEmpty()) {
            try {
                List<ImageAuditResult> imageResults = imageAuditService.batchAudit(
                    imageUrls).get(IMAGE_AUDIT_TIMEOUT_MS, TimeUnit.MILLISECONDS);

                for (ImageAuditResult imgResult : imageResults) {
                    if (imgResult.isPorn()) {
                        log.warn("[{}] 图片鉴黄未通过: url={}, score={}",
                            traceId, imgResult.getImageUrl(), imgResult.getPornScore());
                        result.setRejected(true);
                        result.setReason("评论图片包含违规内容");
                        result.getHitWords().add("图片违规:" + imgResult.getImageUrl());
                        return result;
                    }
                }
            } catch (TimeoutException e) {
                log.warn("[{}] 图片审核超时，降级为放行: imageCount={}",
                    traceId, imageUrls.size());
                // 超时降级：放行但标记需异步复审
                result.setNeedAsyncRecheck(true);
            } catch (Exception e) {
                log.error("[{}] 图片审核服务异常，降级为放行", traceId, e);
                result.setNeedAsyncRecheck(true);
            }
        }

        // ========== 第三步：AI内容审核（同步，调用NLP服务） ==========
        try {
            AiAuditResult aiResult = aiAuditService.audit(
                filteredContent, imageUrls, videoUrls)
                .get(AI_AUDIT_TIMEOUT_MS, TimeUnit.MILLISECONDS);

            if (aiResult.isRejected()) {
                log.warn("[{}] AI审核未通过: reason={}, score={}",
                    traceId, aiResult.getReason(), aiResult.getRiskScore());
                result.setRejected(true);
                result.setReason(aiResult.getReason());
                return result;
            }

            if (aiResult.isNeedManualReview()) {
                log.info("[{}] AI审核建议人工复审: score={}",
                    traceId, aiResult.getRiskScore());
                result.setNeedManualReview(true);
            }
        } catch (TimeoutException e) {
            log.warn("[{}] AI审核超时，降级为放行", traceId);
            result.setNeedAsyncRecheck(true);
        } catch (Exception e) {
            log.error("[{}] AI审核服务异常，降级为放行", traceId, e);
            result.setNeedAsyncRecheck(true);
        }

        // 审核通过，使用过滤后的内容
        result.setFilteredContent(filteredContent);
        return result;
    }
}

/**
 * 内容审核结果
 */
@Data
public class ContentAuditResult {
    private String originalContent;       // 原始内容
    private String filteredContent;       // 过滤后内容
    private boolean rejected;             // 是否被拒绝
    private boolean needManualReview;     // 是否需要人工审核
    private boolean needAsyncRecheck;     // 是否需要异步复审
    private String reason;                // 拒绝原因
    private List<String> hitWords = new ArrayList<>(); // 命中关键词
}
```

#### 7.2.4 Service层：多级缓存 + 内容聚合

```java
/**
 * 评论列表查询Service
 * 串联多级缓存、内容聚合、统计信息、敏感过滤
 */
@Service
@Slf4j
public class CommentListService {

    @Autowired private CommentMapper commentMapper;
    @Autowired private CommentImageMapper commentImageMapper;
    @Autowired private CommentCacheService cacheService;
    @Autowired private CommentLikeService likeService;
    @Autowired private UserService userService;
    @Autowired private MerchantReplyMapper merchantReplyMapper;
    @Autowired private CommentAppendMapper commentAppendMapper;
    @Autowired private ProductStatsMapper productStatsMapper;
    @Autowired private HotTopicProtector hotTopicProtector;
    @Autowired private CommentDegradationService degradationService;

    // 批量查询用户信息的线程池
    private final ExecutorService enrichExecutor = Executors.newFixedThreadPool(4);

    /**
     * 查询评论列表全链路
     */
    public CommentListResponse queryList(long subjectId, int subjectType,
                                           String sortType, String filterType,
                                           String cursor, int pageSize) {
        String traceId = MDC.get("traceId");
        long startTime = System.currentTimeMillis();

        try {
            // ==================== 第一步：热点判定 ====================
            boolean isHot = hotTopicProtector.isHotTopic(subjectId, subjectType);
            log.info("[{}] 热点判定: subjectId={}, isHot={}", traceId, subjectId, isHot);

            // ==================== 第二步：多级缓存查询 ====================
            List<CommentDetailVO> comments = queryWithCache(
                subjectId, subjectType, sortType, filterType, cursor, pageSize, isHot);

            // ==================== 第三步：评论内容聚合 ====================
            if (!comments.isEmpty()) {
                enrichCommentsParallel(comments);
            }

            // ==================== 第四步：评论统计信息 ====================
            CommentStatsVO stats = getCommentStats(subjectId, subjectType);

            // ==================== 第五步：构建下一页游标 ====================
            String nextCursor = null;
            boolean hasMore = comments.size() == pageSize;
            if (hasMore && !comments.isEmpty()) {
                CommentDetailVO last = comments.get(comments.size() - 1);
                nextCursor = CursorPaginationManager.encodeCursor(
                    last.getCreateTime(), last.getId(), sortType);
            }

            // ==================== 组装响应 ====================
            CommentListResponse response = new CommentListResponse();
            response.setComments(comments);
            response.setNextCursor(nextCursor);
            response.setHasMore(hasMore);
            response.setStats(stats);

            return response;

        } finally {
            long elapsed = System.currentTimeMillis() - startTime;
            log.info("[{}] 评论列表查询耗时: {}ms, subjectId={}, pageSize={}",
                traceId, elapsed, subjectId, pageSize);
            MetricsUtil.recordTimer("comment.list.latency", elapsed);
        }
    }

    /**
     * 多级缓存查询策略
     */
    private List<CommentDetailVO> queryWithCache(long subjectId, int subjectType,
                                                   String sortType, String filterType,
                                                   String cursor, int pageSize,
                                                   boolean isHot) {
        String traceId = MDC.get("traceId");
        String cacheKey = buildCacheKey(subjectId, subjectType,
            sortType, filterType, cursor);

        // 热门商品：优先走缓存
        if (isHot) {
            // L1: 本地缓存
            List<CommentDetailVO> l1Result = cacheService.getFromLocalCache(cacheKey);
            if (l1Result != null) {
                log.info("[{}] L1缓存命中: subjectId={}", traceId, subjectId);
                return l1Result;
            }

            // L2: Redis缓存
            List<CommentDetailVO> l2Result = cacheService.getFromRedis(
                subjectId, subjectType, sortType, filterType, cursor, pageSize);
            if (l2Result != null && !l2Result.isEmpty()) {
                log.info("[{}] L2缓存命中: subjectId={}", traceId, subjectId);
                cacheService.putToLocalCache(cacheKey, l2Result);
                return l2Result;
            }
        }

        // 冷门商品或缓存miss：直查DB（带降级）
        List<CommentDetailVO> dbResult;
        try {
            dbResult = queryFromDb(subjectId, subjectType,
                sortType, filterType, cursor, pageSize);
        } catch (DataAccessException e) {
            log.warn("[{}] 数据库查询失败，降级到缓存: subjectId={}",
                traceId, subjectId, e);
            dbResult = degradationService.queryWithDegradation(
                subjectId, subjectType, sortType, filterType, cursor, pageSize);
        }

        // 回写缓存
        if (dbResult != null && !dbResult.isEmpty()) {
            cacheService.putToLocalCache(cacheKey, dbResult);
            cacheService.putToRedis(subjectId, subjectType,
                sortType, filterType, cursor, dbResult);
        }

        return dbResult != null ? dbResult : Collections.emptyList();
    }

    /**
     * 从数据库查询评论列表
     */
    private List<CommentDetailVO> queryFromDb(long subjectId, int subjectType,
                                                String sortType, String filterType,
                                                String cursor, int pageSize) {
        // 解码游标
        CursorPaginationManager.CursorInfo cursorInfo =
            CursorPaginationManager.decodeCursor(cursor);

        // 构建查询条件
        LambdaQueryWrapper<CommentDO> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(CommentDO::getSubjectId, subjectId)
               .eq(CommentDO::getSubjectType, subjectType)
               .eq(CommentDO::getRootId, 0)
               .eq(CommentDO::getStatus, 1); // 只查已发布评论

        // 应用筛选条件
        if ("has_image".equals(filterType)) {
            // 有图评论：通过子查询过滤
            wrapper.apply(
                "id IN (SELECT DISTINCT comment_id FROM t_comment_image)");
        } else if ("positive".equals(filterType)) {
            // 好评：评分4~5星
            wrapper.apply(
                "id IN (SELECT comment_id FROM t_comment_rating WHERE rating >= 4)");
        } else if ("negative".equals(filterType)) {
            // 差评：评分1~2星
            wrapper.apply(
                "id IN (SELECT comment_id FROM t_comment_rating WHERE rating <= 2)");
        }

        // 应用游标条件
        CursorPaginationManager.applyCursorCondition(wrapper, cursorInfo);

        // 排序
        if ("time_desc".equals(sortType)) {
            wrapper.orderByDesc(CommentDO::getCreateTime)
                   .orderByDesc(CommentDO::getId);
        } else {
            wrapper.orderByAsc(CommentDO::getCreateTime)
                   .orderByAsc(CommentDO::getId);
        }

        wrapper.last("LIMIT " + pageSize);

        List<CommentDO> comments = commentMapper.selectList(wrapper);

        // 转换为VO
        return comments.stream()
            .map(this::convertToDetailVO)
            .collect(Collectors.toList());
    }

    /**
     * 并行聚合评论关联信息
     * 评论文本 + 图片 + 用户信息 + 商家回复 + 追评 + 点赞状态
     */
    private void enrichCommentsParallel(List<CommentDetailVO> comments) {
        String traceId = MDC.get("traceId");
        if (comments.isEmpty()) return;

        List<Long> commentIds = comments.stream()
            .map(CommentDetailVO::getId)
            .collect(Collectors.toList());
        Set<Long> userIds = comments.stream()
            .map(CommentDetailVO::getUserId)
            .collect(Collectors.toSet());
        long currentUserId = UserContext.getCurrentUserId();

        // 并行查询四个下游数据源
        CompletableFuture<Map<Long, List<String>>> imageFuture =
            CompletableFuture.supplyAsync(() ->
                batchQueryImages(commentIds), enrichExecutor);

        CompletableFuture<Map<Long, UserInfo>> userFuture =
            CompletableFuture.supplyAsync(() ->
                userService.batchGetUserInfo(new ArrayList<>(userIds)),
                enrichExecutor);

        CompletableFuture<Map<Long, MerchantReplyDO>> replyFuture =
            CompletableFuture.supplyAsync(() ->
                batchQueryMerchantReplies(commentIds), enrichExecutor);

        CompletableFuture<Map<Long, CommentAppendDO>> appendFuture =
            CompletableFuture.supplyAsync(() ->
                batchQueryAppends(commentIds), enrichExecutor);

        CompletableFuture<Map<Long, Boolean>> likeFuture =
            CompletableFuture.supplyAsync(() ->
                likeService.batchCheckLiked(currentUserId, commentIds),
                enrichExecutor);

        // 等待所有并行任务完成
        try {
            CompletableFuture.allOf(imageFuture, userFuture, replyFuture,
                appendFuture, likeFuture).join();

            Map<Long, List<String>> imageMap = imageFuture.join();
            Map<Long, UserInfo> userMap = userFuture.join();
            Map<Long, MerchantReplyDO> replyMap = replyFuture.join();
            Map<Long, CommentAppendDO> appendMap = appendFuture.join();
            Map<Long, Boolean> likeMap = likeFuture.join();

            // 填充关联信息
            for (CommentDetailVO comment : comments) {
                // 图片
                comment.setImages(imageMap.getOrDefault(
                    comment.getId(), Collections.emptyList()));

                // 用户信息
                UserInfo userInfo = userMap.get(comment.getUserId());
                if (userInfo != null) {
                    comment.setUserName(userInfo.getNickname());
                    comment.setUserAvatar(userInfo.getAvatar());
                    comment.setUserLevel(userInfo.getLevel());
                }

                // 商家回复
                MerchantReplyDO reply = replyMap.get(comment.getId());
                if (reply != null) {
                    comment.setMerchantReply(reply.getContent());
                    comment.setMerchantReplyTime(reply.getCreateTime());
                }

                // 追评
                CommentAppendDO append = appendMap.get(comment.getId());
                if (append != null) {
                    comment.setAppendContent(append.getContent());
                    comment.setAppendTime(append.getCreateTime());
                }

                // 点赞状态
                comment.setLiked(Boolean.TRUE.equals(likeMap.get(comment.getId())));
            }

        } catch (CompletionException e) {
            log.error("[{}] 评论内容聚合失败", traceId, e);
            // 聚合失败不影响评论主体展示，降级为不显示关联信息
        }
    }

    /**
     * 批量查询评论图片
     */
    private Map<Long, List<String>> batchQueryImages(List<Long> commentIds) {
        if (commentIds.isEmpty()) return Collections.emptyMap();
        List<CommentImageDO> images = commentImageMapper.selectByCommentIds(commentIds);
        return images.stream().collect(Collectors.groupingBy(
            CommentImageDO::getCommentId,
            Collectors.mapping(CommentImageDO::getImageUrl, Collectors.toList())
        ));
    }

    /**
     * 批量查询商家回复
     */
    private Map<Long, MerchantReplyDO> batchQueryMerchantReplies(List<Long> commentIds) {
        if (commentIds.isEmpty()) return Collections.emptyMap();
        List<MerchantReplyDO> replies = merchantReplyMapper.selectByCommentIds(commentIds);
        return replies.stream().collect(Collectors.toMap(
            MerchantReplyDO::getCommentId, r -> r, (a, b) -> a));
    }

    /**
     * 批量查询追评
     */
    private Map<Long, CommentAppendDO> batchQueryAppends(List<Long> commentIds) {
        if (commentIds.isEmpty()) return Collections.emptyMap();
        List<CommentAppendDO> appends = commentAppendMapper.selectByCommentIds(commentIds);
        return appends.stream().collect(Collectors.toMap(
            CommentAppendDO::getCommentId, a -> a, (a, b) -> a));
    }

    /**
     * 获取评论统计信息
     * 从商品统计表读取，不实时计算
     */
    private CommentStatsVO getCommentStats(long subjectId, int subjectType) {
        ProductStatsDO stats = productStatsMapper.selectBySubject(subjectId, subjectType);
        if (stats == null) {
            return new CommentStatsVO(); // 返回空统计
        }

        CommentStatsVO vo = new CommentStatsVO();
        vo.setTotalCount(stats.getTotalCount());
        vo.setGoodCount(stats.getGoodCount());
        vo.setMediumCount(stats.getMediumCount());
        vo.setBadCount(stats.getBadCount());
        vo.setGoodRate(stats.getTotalCount() > 0
            ? (double) stats.getGoodCount() / stats.getTotalCount() * 100 : 0);
        vo.setAvgRating(stats.getAvgRating());
        vo.setHasImageCount(stats.getHasImageCount());

        // 各星级分布
        Map<Integer, Integer> distribution = new HashMap<>();
        distribution.put(1, stats.getStar1Count());
        distribution.put(2, stats.getStar2Count());
        distribution.put(3, stats.getStar3Count());
        distribution.put(4, stats.getStar4Count());
        distribution.put(5, stats.getStar5Count());
        vo.setRatingDistribution(distribution);

        return vo;
    }

    /**
     * 构建缓存Key
     */
    private String buildCacheKey(long subjectId, int subjectType,
                                   String sortType, String filterType, String cursor) {
        return String.format("%d:%d:%s:%s:%s",
            subjectType, subjectId,
            sortType, filterType == null ? "all" : filterType,
            cursor == null ? "first" : cursor);
    }

    private CommentDetailVO convertToDetailVO(CommentDO comment) {
        CommentDetailVO vo = new CommentDetailVO();
        vo.setId(comment.getId());
        vo.setUserId(comment.getUserId());
        vo.setContent(comment.getContent());
        vo.setLikeCount(comment.getLikeCount());
        vo.setReplyCount(comment.getReplyCount());
        vo.setCreateTime(comment.getCreateTime());
        return vo;
    }
}
```

```java
    @Autowired private CommentIdempotentService idempotentService;

     * 商家回复评论

                traceId, merchantId, request.getIdempotentToken());

        try {

            log.info("[{}] 商家回复成功: merchantId={}, commentId={}, replyId={}",
                traceId, merchantId, request.getCommentId(), reply.getId());
            return Result.success(reply);
        } catch (BusinessException e) {
            log.warn("[{}] 商家回复业务异常: merchantId={}, code={}, msg={}",

            return Result.fail(e.getCode(), e.getMessage());

            log.error("[{}] 商家回复系统异常: merchantId={}, commentId={}",
                traceId, merchantId, request.getCommentId(), e);
            return Result.fail("SYSTEM_ERROR", "系统繁忙，请稍后重试");
        }
    }
```

```java
/**
 * 商家回复评论Service
 */
@Service
@Slf4j
public class MerchantReplyService {

    @Autowired private CommentMapper commentMapper;
    @Autowired private MerchantReplyMapper merchantReplyMapper;
    @Autowired private MerchantRpcService merchantRpcService;
    @Autowired private SensitiveWordService sensitiveWordService;
    @Autowired private ContentFilterChain filterChain;
    @Autowired private CommentCacheService cacheService;
    @Autowired private ReliableMessageSender messageSender;

    // 商家回复频率限制：每分钟最多10条
    private static final int MAX_REPLIES_PER_MINUTE = 10;

    /**
     * 商家回复全链路
     */
    @Transactional(rollbackFor = Exception.class)
    public MerchantReplyVO reply(MerchantReplyRequest request) {
        String traceId = MDC.get("traceId");
        long merchantId = request.getMerchantId();
        long commentId = request.getCommentId();
        long startTime = System.currentTimeMillis();

        try {
            // ==================== 第一步：评论存在性校验 ====================
            CommentDO comment = commentMapper.selectById(commentId);
            if (comment == null) {
                log.warn("[{}] 评论不存在: commentId={}", traceId, commentId);
                throw new BusinessException("COMMENT_NOT_FOUND", "评论不存在");
            }

            if (comment.getStatus() != 1) {
                log.warn("[{}] 评论状态不允许回复: commentId={}, status={}",
                    traceId, commentId, comment.getStatus());
                throw new BusinessException("COMMENT_STATUS_INVALID",
                    "该评论当前状态不允许回复");
            }

            // ==================== 第二步：权限校验 ====================
            log.info("[{}] 开始商家权限校验: merchantId={}, subjectId={}",
                traceId, merchantId, comment.getSubjectId());

            Long commentMerchantId = merchantRpcService.getMerchantIdByProduct(
                comment.getSubjectId());
            if (commentMerchantId == null || commentMerchantId != merchantId) {
                log.warn("[{}] 商家无权回复该评论: merchantId={}, commentMerchantId={}",
                    traceId, merchantId, commentMerchantId);
                throw new BusinessException("NO_PERMISSION",
                    "您无权回复该评论");
            }

            // ==================== 第三步：回复状态校验（幂等控制） ====================
            MerchantReplyDO existingReply = merchantReplyMapper.selectByCommentId(commentId);
            if (existingReply != null) {
                log.warn("[{}] 评论已有商家回复: commentId={}, replyId={}",
                    traceId, commentId, existingReply.getId());
                throw new BusinessException("ALREADY_REPLIED",
                    "该评论已回复，不能重复回复");
            }

            // ==================== 第四步：频率控制 ====================
            if (isRateLimited(merchantId)) {
                log.warn("[{}] 商家回复频率超限: merchantId={}", traceId, merchantId);
                throw new BusinessException("RATE_LIMITED",
                    "回复过于频繁，请稍后再试");
            }

            // ==================== 第五步：内容审核 ====================
            log.info("[{}] 开始回复内容审核: commentId={}", traceId, commentId);

            FilterResult filterResult = filterChain.filter(request.getContent());
            if (!filterResult.isPassed()) {
                log.warn("[{}] 回复内容审核不通过: commentId={}, type={}, hitWords={}",
                    traceId, commentId, filterResult.getFilterType(),
                    filterResult.getHitWords());
                throw new BusinessException("CONTENT_REJECTED",
                    "回复内容包含违规信息，请修改后重试");
            }

            // 敏感词替换
            String filteredContent = sensitiveWordService.filter(request.getContent());

            // ==================== 第六步：回复入库 ====================
            log.info("[{}] 开始回复入库: commentId={}", traceId, commentId);

            MerchantReplyDO reply = new MerchantReplyDO();
            reply.setCommentId(commentId);
            reply.setMerchantId(merchantId);
            reply.setContent(filteredContent);
            merchantReplyMapper.insert(reply);

            // 更新评论表的商家回复标记
            commentMapper.updateMerchantReplyFlag(commentId, true);

            log.info("[{}] 回复入库成功: replyId={}", traceId, reply.getId());

            // ==================== 第七步：缓存更新 ====================
            // 删除评论列表缓存，让下次查询回源DB加载最新数据
            cacheService.invalidateCommentCache(
                comment.getSubjectId(), comment.getSubjectType());

            // ==================== 第八步：发送MQ事件 ====================
            sendMerchantRepliedEvent(reply, comment);

            // ==================== 返回结果 ====================
            MerchantReplyVO vo = convertToVO(reply);
            vo.setMerchantName(merchantRpcService.getMerchantName(merchantId));
            return vo;

        } finally {
            long elapsed = System.currentTimeMillis() - startTime;
            log.info("[{}] 商家回复全链路耗时: {}ms, commentId={}",
                traceId, elapsed, commentId);
            MetricsUtil.recordTimer("comment.merchant_reply.latency", elapsed);
        }
    }

    /**
     * 频率控制：每分钟最多MAX_REPLIES_PER_MINUTE条回复
     */
    private boolean isRateLimited(long merchantId) {
        String key = "merchant:reply:rate:" + merchantId;
        Long count = redisTemplate.opsForValue().increment(key, 1);
        if (count != null && count == 1) {
            redisTemplate.expire(key, 1, TimeUnit.MINUTES);
        }
        return count != null && count > MAX_REPLIES_PER_MINUTE;
    }

    /**
     * 发送商家回复事件
     */
    private void sendMerchantRepliedEvent(MerchantReplyDO reply, CommentDO comment) {
        MerchantRepliedEvent event = new MerchantRepliedEvent();
        event.setReplyId(reply.getId());
        event.setCommentId(reply.getCommentId());
        event.setMerchantId(reply.getMerchantId());
        event.setCommentUserId(comment.getUserId());
        event.setSubjectId(comment.getSubjectId());
        event.setSubjectType(comment.getSubjectType());
        event.setReplyContent(reply.getContent());
        event.setTimestamp(System.currentTimeMillis());

        messageSender.sendInTransaction(
            "merchant-replied",
            String.valueOf(reply.getId()),
            JSON.toJSONString(event));
    }

    private MerchantReplyVO convertToVO(MerchantReplyDO reply) {
        MerchantReplyVO vo = new MerchantReplyVO();
        vo.setId(reply.getId());
        vo.setCommentId(reply.getCommentId());
        vo.setMerchantId(reply.getMerchantId());
        vo.setContent(reply.getContent());
        vo.setCreateTime(reply.getCreateTime());
        return vo;
    }
}
```

```java
/**
 * 商家回复事件消费者：通知用户
 */
@Component
@Slf4j
public class MerchantReplyNotifyConsumer {

    @Autowired private NotificationService notificationService;
    @Autowired private UserService userService;

    @KafkaListener(topics = "merchant-replied", groupId = "reply-notify-consumer")
    public void onMerchantReplied(ConsumerRecord<String, String> record) {
        String traceId = MDC.get("traceId");
        MerchantRepliedEvent event = JSON.parseObject(
            record.value(), MerchantRepliedEvent.class);

        try {
            long commentUserId = event.getCommentUserId();

            // 构建Push通知
            PushMessage pushMessage = new PushMessage();
            pushMessage.setUserId(commentUserId);
            pushMessage.setTitle("商家回复了您的评论");
            pushMessage.setContent(String.format("商家回复：%s",
                truncate(event.getReplyContent(), 50)));
            pushMessage.setType("MERCHANT_REPLY");
            pushMessage.setRefId(String.valueOf(event.getCommentId()));
            pushMessage.setJumpUrl(String.format("/comment/detail?commentId=%d",
                event.getCommentId()));

            // 发送Push通知
            notificationService.sendPush(pushMessage);
            log.info("[{}] Push通知发送成功: userId={}, commentId={}",
                traceId, commentUserId, event.getCommentId());

            // 发送站内信
            NotifyMessage stationMessage = new NotifyMessage();
            stationMessage.setUserId(commentUserId);
            stationMessage.setTitle("商家回复了您的评论");
            stationMessage.setContent(event.getReplyContent());
            stationMessage.setType("MERCHANT_REPLY");
            stationMessage.setRefId(String.valueOf(event.getCommentId()));
            notificationService.send(stationMessage);
            log.info("[{}] 站内信发送成功: userId={}, commentId={}",
                traceId, commentUserId, event.getCommentId());

        } catch (Exception e) {
            log.error("[{}] 用户通知发送失败: commentId={}",
                traceId, event.getCommentId(), e);
            // 通知失败不影响主流程，定时任务补偿
        }
    }

    private String truncate(String content, int maxLength) {
        if (content == null) return "";
        return content.length() > maxLength
            ? content.substring(0, maxLength) + "..."
            : content;
    }
}
```

#### 7.3.8 全链路异常处理与日志追踪汇总

三个案例中，全链路的异常处理和日志追踪遵循统一规范：

**1）TraceId贯穿全链路**

每个请求在接入层生成唯一的 `traceId`，通过 `MDC`（Mapped Diagnostic Context）传递到所有日志输出中。跨服务调用时通过HTTP Header或MQ消息头传递，确保同一条评论的全链路日志可以通过 `traceId` 串联检索。

**2）异常分级处理**

| 异常级别 | 处理策略 | 示例 |
|---------|---------|------|
| 参数校验异常 | 直接返回错误提示，不记录ERROR日志 | 评分为空、内容超长 |
| 业务异常 | 返回业务错误码和提示，记录WARN日志 | 资格校验不通过、重复评论 |
| 依赖服务异常 | 降级处理，记录WARN日志 | 图片审核超时、用户服务不可用 |
| 系统异常 | 返回兜底错误信息，记录ERROR日志 | 数据库连接失败、NPE |

**3）幂等控制三道防线**

| 防线 | 机制 | 适用场景 |
|------|------|---------|
| 幂等Token | Redis原子DELETE，一次性消费 | 用户重复点击提交 |
| 唯一索引 | 数据库UNIQUE INDEX约束 | 重复评论、重复回复 |
| 状态校验 | 业务层状态判断 | 已评论、已回复的二次检查 |

**4）异步链路的可靠性保障**

评论发布和商家回复后的异步处理（ES索引更新、统计更新、奖励发放、通知发送）全部通过 `ReliableMessageSender` 走本地消息表 + Kafka 的可靠投递机制（详见4.3节）。每个消费者独立消费、独立重试，互不影响——即使ES索引更新失败，也不会阻塞统计更新和通知发送。
