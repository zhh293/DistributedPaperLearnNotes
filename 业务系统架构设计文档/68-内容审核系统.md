# 内容审核系统架构设计

> 本文部分内容参考学城文档整理（《UAP-统一审核平台》相关内容），并结合内容安全领域的通用工程实践进行系统性梳理和扩展。文中不涉及任何企业内部产品名称，示例代码为通用Java实现，可直接迁移到任意后端技术栈。

## 一、问题背景

### 1.1 统一审核平台的定义

学城文档对统一审核平台给出了清晰的概念定义：

> "UAP（Unified Audit Platform，统一审核平台）是一款集人审、机审一体的内容审核平台，提供文字、图片、音频、视频等内容的审核，底层集成了OCR、NLP等服务，支持敏感词校验、机审业务规则自定义、审核流程配置、人审表单、版本对比、实时报表等能力，提供风控安全、品控质量、行业资质证照、业务产品规则等类型的审核服务。"

这段定义揭示了一个成熟内容审核系统必须具备的三个核心特征：

1. **人机一体**：机器审核（机审）负责处理大批量、规则明确的内容，人工审核（人审）负责处理机器无法确定或高风险的内容，两者协同构成完整的审核闭环，而不是二选一。
2. **多模态覆盖**：文字、图片、音频、视频四种内容形态都需要被覆盖，且底层依赖专门的内容识别能力（如OCR文字识别、NLP文本分类等）作为审核引擎的支撑。
3. **平台化能力**：不是针对单一业务场景写死的审核逻辑，而是提供可配置的审核规则、可配置的审核流程、可复用的人审表单，使得不同业务方都能够基于同一套底层能力快速接入自己的审核需求。

### 1.2 平台架构定位

学城文档进一步说明了平台的工作模式：

> "UAP适用于各种需要审核的业务，业务方将需要审核的数据提交到审核平台，审核平台经过机审和人审后，将审核结果异步通知给业务方。"

这句话点出了统一审核平台的核心交互模式：**审核平台是一个独立于业务系统之外的中台能力，业务方以"提交任务 - 异步获取结果"的方式接入，审核逻辑本身与业务系统解耦**。这种设计使得同一套审核平台可以同时服务多个业务线，而不需要每个业务线各自重复建设审核能力。

### 1.3 适用场景与不适用场景

学城文档明确划定了平台的能力边界，这对于理解系统设计的取舍非常关键：

**适用场景**：

- C端展示物料（包括图片、文本、视频和音频等在内的多媒体）进行内容风控安全和品控质量审核，如展示图片、商家相册等。
- 产品上线发布前对是否符合业务规则进行审核，如资质证照、产品配置、预付产品等。
- 自建审核页面，底层复用平台提供的审核能力。

**不适用场景**：

- UGC、IM等业务场景（这类场景消息量极大、实时性要求极高，通常需要更轻量级的前置过滤机制，而不是走完整的审核工作流）。
- 请假单、入职流程、离职流程等流程审批类场景（这类场景本质是工作流审批，而非内容安全审核，业务语义完全不同）。

这个边界划分体现了一个重要的架构设计原则：**审核平台聚焦于"内容安全与合规"这一垂直领域，不试图成为通用的工作流引擎**。理解这一点有助于我们在设计审核系统时保持职责单一，避免功能范围无限膨胀。

### 1.4 核心挑战

| 挑战维度 | 具体问题 |
|---------|---------|
| 多模态审核 | 文字、图片、音频、视频四种内容形态，审核手段和判定逻辑各不相同 |
| 机审准确率 | 漏审违规内容导致合规风险，误判正常内容影响用户体验 |
| 审核成本 | 全量人工审核成本极高，需要机审尽可能过滤掉大部分明确案例 |
| 流程可配置 | 不同业务方的审核流程、审核规则、审核表单需求差异很大 |
| 版本追溯 | 内容多次修改后需要对比不同版本审核结果的差异 |
| 实时性与吞吐 | 部分场景要求审核结果尽快出结果，部分场景可接受异步处理 |
| 审核结果异步通知 | 业务方提交后不阻塞等待，审核完成后异步回调通知 |

## 二、整体架构设计

### 2.1 能力全景

学城文档对平台的核心能力做了完整罗列：

> "UAP目前核心的业务能力有敏感词校验、内容安全、图片亮度、图片水印、图片尺寸、图片二维码检测、图片OCR、自定义规则等机审能力，自定义分单、动态表单、搜索查询、版本对比、系统字段、精细化驳回、自动下一单等人审能力。"

这份能力清单可以清晰地划分为两大类：

**机审能力**（自动化、高吞吐、判定明确的部分优先执行）：
- 敏感词校验
- 内容安全（涉黄、涉暴、涉政等风险内容识别）
- 图片亮度检测
- 图片水印检测
- 图片尺寸校验
- 图片二维码检测（防止图片携带引流二维码）
- 图片OCR（识别图片中的文字并二次走文本审核）
- 自定义规则（业务方可配置的规则引擎）

**人审能力**（面向审核员的工作台能力，处理机审无法确定的内容）：
- 自定义分单（按规则将待审任务分配给合适的审核员）
- 动态表单（不同业务方可以自定义审核信息展示和录入表单）
- 搜索查询（审核员检索历史任务）
- 版本对比（对比内容修改前后的差异）
- 系统字段（结构化展示待审内容的关键信息）
- 精细化驳回（区分驳回原因，给业务方明确的整改指引）
- 自动下一单（审核员完成当前任务后自动派发下一条，提升审核效率）

## 三、核心链路设计

### 3.1 审核流编排：机审规则 → AI审核 → 人审

审核流编排引擎是整个平台的核心调度中枢，负责按照业务方配置的审核流程，依次调用机审规则引擎、AI审核服务，并根据综合结果决定是否需要转人审。

```java
/**
 * 审核任务实体
 */
public class AuditTask implements Serializable {
    private Long taskId;
    private String bizCode;      // 业务方标识
    private String bizType;      // TEXT/IMAGE/AUDIO/VIDEO
    private String bizContentId; // 业务方内容ID
    private String content;      // 文本内容或资源URL
    private String processCode;  // 匹配到的审核流程编码
    private Integer status;
    private Integer riskLevel;
    private Integer version;
    // getter/setter省略
}

/**
 * 审核流编排引擎
 *
 * 遵循学城文档描述的核心流程：
 * 1. 机审规则引擎（敏感词、正则、图片检测等）→ 确定性违规直接拒绝
 * 2. AI审核（NLP文本分类、CV图像识别）→ 概率化判断
 * 3. 综合决策：
 *    a. 规则+AI都通过 → 机审自动通过
 *    b. 规则或AI明确拒绝 → 机审自动拒绝
 *    c. AI判断落在不确定区间 → 转人审
 */
@Service
public class AuditOrchestrator {

    @Autowired
    private AuditRuleEngine ruleEngine;

    @Autowired
    private AIAuditService aiAuditService;

    @Autowired
    private ManualAuditService manualAuditService;

    @Autowired
    private AuditProcessConfigRepository processConfigRepository;

    @Autowired
    private AuditResultNotifyService notifyService;

    /**
     * 执行审核主流程
     */
    public AuditResult execute(AuditTask task) {

        AuditProcessConfig config = processConfigRepository.getByCode(task.getProcessCode());

        // 1. 机审规则引擎：快速、确定性强的规则优先执行
        RuleResult ruleResult = ruleEngine.execute(task, config);
        if (ruleResult.getAction() == RuleAction.REJECT) {
            AuditResult result = AuditResult.machineReject(ruleResult.getReason());
            finish(task, result);
            return result;
        }

        // 2. AI审核服务：文本分类/图像识别，输出风险概率
        AIAuditResult aiResult = aiAuditService.review(task, config);

        // 3. 综合决策
        if (ruleResult.getAction() == RuleAction.PASS && aiResult.isPass()) {
            AuditResult result = AuditResult.machinePass();
            finish(task, result);
            return result;
        }

        if (aiResult.isReject()) {
            AuditResult result = AuditResult.machineReject(aiResult.getReason());
            finish(task, result);
            return result;
        }

        // 4. AI判断不确定，转人审
        task.setStatus(AuditStatus.TO_MANUAL.getCode());
        task.setRiskLevel(aiResult.getRiskLevel());
        manualAuditService.submitToManualQueue(task);
        return AuditResult.pendingManual();
    }

    /**
     * 审核完成后（无论机审还是人审），统一收口：更新状态 + 异步通知业务方
     */
    private void finish(AuditTask task, AuditResult result) {
        // 更新任务状态（略）
        notifyService.notifyAsync(task, result);
    }
}
```

### 3.2 机审规则引擎

学城文档中列出的机审能力清单——敏感词校验、内容安全、图片亮度、图片水印、图片尺寸、图片二维码检测、图片OCR、自定义规则——本质上是一条**规则链**，每种规则各司其职、按优先级依次执行。规则引擎的设计目标是让业务方能够通过配置而非代码开发的方式，自由组合这些原子能力。

```java
/**
 * 机审规则引擎
 *
 * 按照 audit_process_config.rule_chain 配置的规则链顺序依次执行
 * 支持的规则类型覆盖学城文档列出的机审能力：
 * KEYWORD / IMAGE_SECURITY / IMAGE_BRIGHTNESS / IMAGE_WATERMARK /
 * IMAGE_SIZE / IMAGE_QRCODE / OCR / CUSTOM
 */
@Service
public class AuditRuleEngine {

    @Autowired
    private Map<String, AuditRuleHandler> ruleHandlers; // Spring按类型自动注入所有Handler实现

    public RuleResult execute(AuditTask task, AuditProcessConfig config) {
        List<RuleChainItem> ruleChain = config.getRuleChain();

        // 按优先级排序后依次执行
        ruleChain.sort(Comparator.comparingInt(RuleChainItem::getPriority));

        for (RuleChainItem item : ruleChain) {
            AuditRuleHandler handler = ruleHandlers.get(item.getRuleType());
            if (handler == null) {
                continue;
            }
            RuleResult result = handler.handle(task, item.getRuleParams());
            if (result.getAction() == RuleAction.REJECT) {
                // 命中确定性拒绝规则，短路返回，无需继续执行后续规则
                return result;
            }
        }

        return RuleResult.pass();
    }
}

/**
 * 规则处理器统一接口
 */
public interface AuditRuleHandler {
    RuleResult handle(AuditTask task, Map<String, Object> ruleParams);
}

/**
 * 敏感词校验规则处理器
 */
@Component("KEYWORD")
public class KeywordRuleHandler implements AuditRuleHandler {

    @Autowired
    private SensitiveWordFilter sensitiveWordFilter;

    @Override
    public RuleResult handle(AuditTask task, Map<String, Object> ruleParams) {
        if (!"TEXT".equals(task.getBizType())) {
            return RuleResult.pass(); // 非文本类型跳过该规则
        }
        if (sensitiveWordFilter.contains(task.getContent())) {
            return RuleResult.reject("命中敏感词库");
        }
        return RuleResult.pass();
    }
}

/**
 * 图片亮度检测规则处理器
 *
 * 检测图片是否过暗/过曝，用于品控质量审核场景（如展示图片质量把关）
 */
@Component("IMAGE_BRIGHTNESS")
public class ImageBrightnessRuleHandler implements AuditRuleHandler {

    @Autowired
    private ImageAnalysisClient imageAnalysisClient;

    @Override
    public RuleResult handle(AuditTask task, Map<String, Object> ruleParams) {
        if (!"IMAGE".equals(task.getBizType())) {
            return RuleResult.pass();
        }
        double brightness = imageAnalysisClient.detectBrightness(task.getContent());
        double minBrightness = getDoubleParam(ruleParams, "minBrightness", 30.0);
        double maxBrightness = getDoubleParam(ruleParams, "maxBrightness", 220.0);

        if (brightness < minBrightness || brightness > maxBrightness) {
            return RuleResult.reject("图片亮度不符合要求: " + brightness);
        }
        return RuleResult.pass();
    }

    private double getDoubleParam(Map<String, Object> params, String key, double defaultValue) {
        Object v = params.get(key);
        return v == null ? defaultValue : Double.parseDouble(v.toString());
    }
}

/**
 * 图片水印检测规则处理器
 *
 * 检测图片是否包含第三方水印，用于品控场景过滤盗图/搬运内容
 */
@Component("IMAGE_WATERMARK")
public class ImageWatermarkRuleHandler implements AuditRuleHandler {

    @Autowired
    private ImageAnalysisClient imageAnalysisClient;

    @Override
    public RuleResult handle(AuditTask task, Map<String, Object> ruleParams) {
        if (!"IMAGE".equals(task.getBizType())) {
            return RuleResult.pass();
        }
        boolean hasWatermark = imageAnalysisClient.detectWatermark(task.getContent());
        boolean rejectOnWatermark = Boolean.parseBoolean(
            String.valueOf(ruleParams.getOrDefault("rejectOnWatermark", "true")));

        if (hasWatermark && rejectOnWatermark) {
            return RuleResult.reject("图片含第三方水印");
        }
        return RuleResult.pass();
    }
}

/**
 * 图片尺寸校验规则处理器
 */
@Component("IMAGE_SIZE")
public class ImageSizeRuleHandler implements AuditRuleHandler {

    @Autowired
    private ImageAnalysisClient imageAnalysisClient;

    @Override
    public RuleResult handle(AuditTask task, Map<String, Object> ruleParams) {
        if (!"IMAGE".equals(task.getBizType())) {
            return RuleResult.pass();
        }
        ImageSize size = imageAnalysisClient.getSize(task.getContent());
        int minWidth = Integer.parseInt(String.valueOf(ruleParams.getOrDefault("minWidth", "300")));
        int minHeight = Integer.parseInt(String.valueOf(ruleParams.getOrDefault("minHeight", "300")));

        if (size.getWidth() < minWidth || size.getHeight() < minHeight) {
            return RuleResult.reject("图片尺寸过小: " + size.getWidth() + "x" + size.getHeight());
        }
        return RuleResult.pass();
    }
}

/**
 * 图片二维码检测规则处理器
 *
 * 防止图片携带引流二维码（如广告二维码、私域导流二维码等）
 */
@Component("IMAGE_QRCODE")
public class ImageQrCodeRuleHandler implements AuditRuleHandler {

    @Autowired
    private ImageAnalysisClient imageAnalysisClient;

    @Override
    public RuleResult handle(AuditTask task, Map<String, Object> ruleParams) {
        if (!"IMAGE".equals(task.getBizType())) {
            return RuleResult.pass();
        }
        boolean hasQrCode = imageAnalysisClient.detectQrCode(task.getContent());
        if (hasQrCode) {
            return RuleResult.reject("图片含二维码，疑似违规引流");
        }
        return RuleResult.pass();
    }
}

/**
 * 图片OCR规则处理器
 *
 * 识别图片中的文字后，复用文本审核链路二次检测，
 * 解决"图片本身安全但文字内容违规"的漏审场景
 */
@Component("OCR")
public class ImageOcrRuleHandler implements AuditRuleHandler {

    @Autowired
    private OcrClient ocrClient;

    @Autowired
    private SensitiveWordFilter sensitiveWordFilter;

    @Override
    public RuleResult handle(AuditTask task, Map<String, Object> ruleParams) {
        if (!"IMAGE".equals(task.getBizType())) {
            return RuleResult.pass();
        }
        String ocrText = ocrClient.recognize(task.getContent());
        if (StringUtils.isBlank(ocrText)) {
            return RuleResult.pass();
        }
        if (sensitiveWordFilter.contains(ocrText)) {
            return RuleResult.reject("图片OCR识别文字命中敏感词: " + ocrText);
        }
        return RuleResult.pass();
    }
}

/**
 * 自定义规则处理器
 *
 * 支持业务方通过正则表达式、URL/IP黑名单等方式自定义机审规则，
 * 对应学城文档中"自定义规则"能力
 */
@Component("CUSTOM")
public class CustomRuleHandler implements AuditRuleHandler {

    @Override
    public RuleResult handle(AuditTask task, Map<String, Object> ruleParams) {
        String regex = (String) ruleParams.get("regex");
        if (StringUtils.isNotBlank(regex)) {
            Pattern pattern = Pattern.compile(regex);
            if (pattern.matcher(task.getContent()).find()) {
                return RuleResult.reject("命中自定义正则规则: " + regex);
            }
        }

        List<String> urlBlacklist = (List<String>) ruleParams.get("urlBlacklist");
        if (urlBlacklist != null) {
            for (String url : extractUrls(task.getContent())) {
                if (urlBlacklist.contains(url)) {
                    return RuleResult.reject("命中URL黑名单: " + url);
                }
            }
        }

        return RuleResult.pass();
    }

    private List<String> extractUrls(String content) {
        List<String> urls = new ArrayList<>();
        Pattern urlPattern = Pattern.compile("https?://[\\w./?=&%-]+");
        Matcher matcher = urlPattern.matcher(content);
        while (matcher.find()) {
            urls.add(matcher.group());
        }
        return urls;
    }
}
```

```java

public class AIAuditResult {

/**
 * AI审核服务
 *
 * 覆盖文本、图片、音频、视频四种模态的AI审核能力，
 * 与学城文档"提供文字、图片、音频、视频等内容的审核"的能力描述一致
 */
@Service
public class AIAuditService {

    @Autowired
    private NlpClient nlpClient;

    @Autowired
    private CvClient cvClient;

    @Autowired
    private AsrClient asrClient; // 语音转文字

    @Autowired
    private VideoFrameExtractor videoFrameExtractor;

    public AIAuditResult review(AuditTask task, AuditProcessConfig config) {
        switch (task.getBizType()) {
            case "TEXT":
                return reviewText(task.getContent(), config);
            case "IMAGE":
                return reviewImage(task.getContent(), config);
            case "AUDIO":
                return reviewAudio(task.getContent(), config);
            case "VIDEO":
                return reviewVideo(task.getContent(), config);
            default:
                return AIAuditResult.uncertain("未知审核类型", 2);
        }
    }

    /**
     * 文本审核：NLP多标签分类
     */
    private AIAuditResult reviewText(String text, AuditProcessConfig config) {
        NlpClassifyResult classifyResult = nlpClient.classify(text);

        double maxRiskScore = classifyResult.getMaxRiskScore(); // 色情/暴力/政治/广告等风险类目的最高概率

        double passThreshold = config.getAutoPassScore();   // 例如 0.9
        double rejectThreshold = config.getAutoRejectScore(); // 例如 0.8

        if (maxRiskScore < (1 - passThreshold)) {
            return AIAuditResult.pass();
        }
        if (maxRiskScore > rejectThreshold) {
            return AIAuditResult.reject("AI文本分类检测到违规内容: " + classifyResult.getMaxRiskCategory());
        }
        return AIAuditResult.uncertain(classifyResult.getMaxRiskCategory(),
            resolveRiskLevel(maxRiskScore));
    }

    /**
     * 图片审核：CV图像识别 + OCR文字二次审核
     */
    private AIAuditResult reviewImage(String imageUrl, AuditProcessConfig config) {
        CvDetectResult cvResult = cvClient.detect(imageUrl);

        double rejectThreshold = config.getAutoRejectScore();
        double passThreshold = config.getAutoPassScore();

        if (cvResult.getPornScore() > rejectThreshold) {
            return AIAuditResult.reject("图片含色情内容");
        }
        if (cvResult.getViolenceScore() > rejectThreshold) {
            return AIAuditResult.reject("图片含暴力内容");
        }
        if (cvResult.getPornScore() > (1 - passThreshold)
            || cvResult.getViolenceScore() > (1 - passThreshold)) {
            return AIAuditResult.uncertain("图片风险内容待人工确认",
                resolveRiskLevel(Math.max(cvResult.getPornScore(), cvResult.getViolenceScore())));
        }

        return AIAuditResult.pass();
    }

    /**
     * 音频审核：语音转文字后走文本审核
     */
    private AIAuditResult reviewAudio(String audioUrl, AuditProcessConfig config) {
        String transcript = asrClient.transcribe(audioUrl);
        if (StringUtils.isBlank(transcript)) {
            return AIAuditResult.pass();
        }
        return reviewText(transcript, config);
    }

    /**
     * 视频审核：抽帧图片审核 + 音轨语音转文字审核
     */
    private AIAuditResult reviewVideo(String videoUrl, AuditProcessConfig config) {
        // 1. 按固定间隔抽帧
        List<String> frameUrls = videoFrameExtractor.extract(videoUrl, 1); // 每秒抽1帧

        for (String frameUrl : frameUrls) {
            AIAuditResult frameResult = reviewImage(frameUrl, config);
            if (frameResult.isReject()) {
                return frameResult;
            }
        }

        // 2. 音轨转文字审核
        String transcript = asrClient.transcribe(videoUrl);
        if (StringUtils.isNotBlank(transcript)) {
            AIAuditResult textResult = reviewText(transcript, config);
            if (textResult.isReject()) {
                return textResult;
            }
        }

        return AIAuditResult.pass();
    }

    private int resolveRiskLevel(double score) {
        if (score > 0.6) return 3;
        if (score > 0.4) return 2;
        return 1;
    }
}
```

### 3.5 审核结果异步通知

学城文档明确指出平台的工作模式是"将审核结果异步通知给业务方"，这是平台与业务方之间解耦的关键机制——业务方提交审核任务后无需同步阻塞等待，而是通过消息通知或回调的方式异步获取最终结果。

```java
/**
 * 审核结果异步通知服务
 *
 * 支持两种通知方式：
 * 1. 消息队列广播（业务方订阅对应Topic）
 * 2. HTTP回调（业务方注册Webhook地址）
 */
@Service
public class AuditResultNotifyService {

    @Autowired
    private KafkaTemplate<String, AuditNotifyMessage> kafkaTemplate;

    @Autowired
    private BizCallbackConfigRepository callbackConfigRepository;

    @Autowired
    private RestTemplate restTemplate;

    private static final String NOTIFY_TOPIC = "audit-result-notify-topic";

    /**
     * 异步通知入口：审核完成（机审或人审）后统一调用
     */
    public void notifyAsync(AuditTask task, AuditResult result) {
        AuditNotifyMessage message = buildMessage(task, result);

        // 方式一：写入消息队列，业务方按bizCode订阅对应Topic或消费同一Topic自行过滤
        kafkaTemplate.send(NOTIFY_TOPIC, task.getBizCode(), message);

        // 方式二：如果业务方配置了HTTP回调地址，同时发起回调（失败自动重试）
        BizCallbackConfig callbackConfig = callbackConfigRepository.getByBizCode(task.getBizCode());
        if (callbackConfig != null && StringUtils.isNotBlank(callbackConfig.getWebhookUrl())) {
            sendWebhookWithRetry(callbackConfig.getWebhookUrl(), message, 3);
        }
    }

    private AuditNotifyMessage buildMessage(AuditTask task, AuditResult result) {
        AuditNotifyMessage message = new AuditNotifyMessage();
        message.setTaskId(task.getTaskId());
        message.setBizContentId(task.getBizContentId());
        message.setPass(result.isPass());
        message.setSource(result.getSource()); // MACHINE / MANUAL
        message.setReason(result.getReason());
        message.setNotifyTime(System.currentTimeMillis());
        return message;
    }

    /**
     * Webhook回调，失败按指数退避重试
     */
    private void sendWebhookWithRetry(String url, AuditNotifyMessage message, int maxRetry) {
        int attempt = 0;
        while (attempt < maxRetry) {
            try {
                ResponseEntity<String> response = restTemplate.postForEntity(url, message, String.class);
                if (response.getStatusCode().is2xxSuccessful()) {
                    return;
                }
            } catch (Exception e) {
                // 记录失败日志，继续重试
            }
            attempt++;
            sleepBackoff(attempt);
        }
        // 超过最大重试次数后，记录到失败补偿表，由定时任务兜底重试
    }

    private void sleepBackoff(int attempt) {
        try {
            Thread.sleep((long) Math.pow(2, attempt) * 1000);
        } catch (InterruptedException ignored) {
            Thread.currentThread().interrupt();
        }
    }
}
```

## 四、敏感词过滤：DFA算法

敏感词校验是学城文档列出的第一项机审能力，也是所有文本类内容审核的第一道防线。与其他审核规则相比，敏感词校验要求毫秒级响应且必须支持海量词库，因此算法效率至关重要。

### 4.1 DFA树构建与匹配

```java
/**
 * 敏感词过滤器（DFA算法实现）
 *
 * 使用多叉树结构存储敏感词库，实现O(n)时间复杂度的单遍扫描匹配
 * n为待检测文本长度，与词库规模无关
 */
@Component
public class SensitiveWordFilter {

    private final Map<Character, Object> sensitiveTree = new HashMap<>();
    private static final String END_FLAG = "isEnd";

    @Autowired
    private SensitiveWordRepository wordRepository;

    @PostConstruct
    public void init() {
        List<String> words = wordRepository.loadAll();
        for (String word : words) {
            addWord(word);
        }
    }

    @SuppressWarnings("unchecked")
    private void addWord(String word) {
        Map<Character, Object> current = sensitiveTree;
        for (int i = 0; i < word.length(); i++) {
            char c = word.charAt(i);
            Map<Character, Object> next = (Map<Character, Object>) current.get(c);
            if (next == null) {
                next = new HashMap<>();
                current.put(c, next);
            }
            current = next;
            if (i == word.length() - 1) {
                current.put(END_FLAG, Boolean.TRUE);
            }
        }
    }

    public synchronized void addWordAtRuntime(String word) {
        addWord(word);
    }

    /**
     * 过滤敏感词：命中位置替换为等长 * 号，采用最长匹配策略
     */
    @SuppressWarnings("unchecked")
    public String filter(String text) {
        if (text == null || text.isEmpty()) {
            return text;
        }
        StringBuilder result = new StringBuilder(text.length());
        int i = 0;
        while (i < text.length()) {
            int matchLength = matchLongestFrom(text, i);
            if (matchLength > 0) {
                for (int k = 0; k < matchLength; k++) {
                    result.append('*');
                }
                i += matchLength;
            } else {
                result.append(text.charAt(i));
                i++;
            }
        }
        return result.toString();
    }

    @SuppressWarnings("unchecked")
    private int matchLongestFrom(String text, int start) {
        Map<Character, Object> current = sensitiveTree;
        int matchEnd = -1;
        int j = start;
        while (j < text.length()) {
            char c = text.charAt(j);
            Object node = current.get(c);
            if (node == null) {
                break;
            }
            current = (Map<Character, Object>) node;
            if (Boolean.TRUE.equals(current.get(END_FLAG))) {
                matchEnd = j;
            }
            j++;
        }
        return matchEnd >= 0 ? (matchEnd - start + 1) : 0;
    }

    /**
     * 判断是否包含敏感词（用于机审规则引擎快速拒绝判断）
     */
    public boolean contains(String text) {
        if (text == null || text.isEmpty()) {
            return false;
        }
        for (int i = 0; i < text.length(); i++) {
            if (matchLongestFrom(text, i) > 0) {
                return true;
            }
        }
        return false;
    }

    /**
     * 提取所有命中的敏感词及位置，用于人审台展示命中详情
     */
    public List<SensitiveHit> detectAll(String text) {
        List<SensitiveHit> hits = new ArrayList<>();
        if (text == null || text.isEmpty()) {
            return hits;
        }
        int i = 0;
        while (i < text.length()) {
            int matchLength = matchLongestFrom(text, i);
            if (matchLength > 0) {
                hits.add(new SensitiveHit(text.substring(i, i + matchLength), i, matchLength));
                i += matchLength;
            } else {
                i++;
            }
        }
        return hits;
    }
}
```

### 4.2 词库分级管理

不同业务场景（风控安全 vs 品控质量 vs 资质证照）需要的敏感词库粒度不同，学城文档中提到平台"提供风控安全、品控质量、行业资质证照、业务产品规则等类型的审核服务"，因此词库需要支持分类管理：

```java
/**
```

```java
/**
 * 审核流程配置管理服务
 *
 * 支持业务方在管理后台自助配置审核流程，
 * 配置变更后实时生效（通过配置中心推送或轮询刷新）

@Service
public class AuditProcessConfigService {

    @Autowired
    private AuditProcessConfigRepository repository;

    private final Map<String, AuditProcessConfig> localCache = new ConcurrentHashMap<>();

    @PostConstruct
    public void loadAll() {
        List<AuditProcessConfig> configs = repository.selectAll();
        configs.forEach(c -> localCache.put(c.getProcessCode(), c));
    }

    /**
     * 保存/更新流程配置
     */
    @Transactional(rollbackFor = Exception.class)
    public void saveConfig(AuditProcessConfig config) {
        validateRuleChain(config.getRuleChain());
        repository.upsert(config);
        localCache.put(config.getProcessCode(), config);
    }

    /**
     * 校验规则链配置合法性：优先级不能重复、规则类型必须存在对应Handler
     */
    private void validateRuleChain(List<RuleChainItem> ruleChain) {
        Set<Integer> priorities = new HashSet<>();
        for (RuleChainItem item : ruleChain) {
            if (!priorities.add(item.getPriority())) {
                throw new BizException("规则链优先级重复: " + item.getPriority());
            }
        }
    }

    public AuditProcessConfig getByCode(String processCode) {
        AuditProcessConfig config = localCache.get(processCode);
        if (config == null) {
            config = repository.getByCode(processCode);
            if (config != null) {
                localCache.put(processCode, config);
            }
        }
        return config;
    }

    /**
     * 配置中心变更事件监听，实时刷新本地缓存
     */
    @EventListener
    public void onConfigChanged(ProcessConfigChangedEvent event) {
        AuditProcessConfig latest = repository.getByCode(event.getProcessCode());
        if (latest != null) {
            localCache.put(event.getProcessCode(), latest);
        }
    }
}
```

## 六、版本对比

### 6.1 应用场景

学城文档将"版本对比"列为核心人审能力之一。在实际业务中，内容审核通常不是一次性的——业务方修改了资质材料、更新了商品图片或调整了文案后会重新提交审核，人工审核员需要快速看出"这次改了什么"，而不必从头审阅整份内容，这就是版本对比能力存在的意义。

### 6.2 内容版本管理

```java
/**
 * 内容版本管理服务
 *
 * 每次业务方提交审核任务时，如果检测到同一biz_content_id内容发生变化，
 * 自动生成新版本记录，供人审台做版本对比展示
 */
@Service
public class ContentVersionService {

    @Autowired
    private AuditContentVersionMapper versionMapper;

    /**
     * 提交审核时记录版本
     */
    @Transactional(rollbackFor = Exception.class)
    public int recordVersion(String bizContentId, String content, Long taskId) {
        String contentHash = DigestUtils.md5Hex(content);

        AuditContentVersion latest = versionMapper.selectLatest(bizContentId);
        if (latest != null && latest.getContentHash().equals(contentHash)) {
            return latest.getVersion(); // 内容未变化，复用已有版本号
        }

        int newVersion = (latest == null) ? 1 : latest.getVersion() + 1;

        AuditContentVersion version = new AuditContentVersion();
        version.setBizContentId(bizContentId);
        version.setVersion(newVersion);
        version.setContent(content);
        version.setContentHash(contentHash);
        version.setTaskId(taskId);
        version.setCreateTime(new Date());
        versionMapper.insert(version);

        return newVersion;
    }

    /**
     * 版本对比：返回两个版本之间的文本差异
     *
     * 文本类内容使用行级Diff算法，图片类内容展示两张图并列供人工肉眼对比
     */
    public VersionDiffResult compare(String bizContentId, int versionA, int versionB) {
        AuditContentVersion a = versionMapper.selectByVersion(bizContentId, versionA);
        AuditContentVersion b = versionMapper.selectByVersion(bizContentId, versionB);

        if (a == null || b == null) {
            throw new BizException("指定版本不存在");
        }

        VersionDiffResult result = new VersionDiffResult();
        result.setVersionA(versionA);
        result.setVersionB(versionB);
        result.setDiffLines(computeLineDiff(a.getContent(), b.getContent()));
        return result;
    }

    /**
     * 简化版行级Diff：基于最长公共子序列思想标记增删行
     */
    private List<DiffLine> computeLineDiff(String textA, String textB) {
        String[] linesA = textA.split("\n");
        String[] linesB = textB.split("\n");

        int m = linesA.length, n = linesB.length;
        int[][] lcs = new int[m + 1][n + 1];

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (linesA[i - 1].equals(linesB[j - 1])) {
                    lcs[i][j] = lcs[i - 1][j - 1] + 1;
                } else {
                    lcs[i][j] = Math.max(lcs[i - 1][j], lcs[i][j - 1]);
                }
            }
        }

        List<DiffLine> diffLines = new ArrayList<>();
        int i = m, j = n;
        LinkedList<DiffLine> stack = new LinkedList<>();
        while (i > 0 && j > 0) {
            if (linesA[i - 1].equals(linesB[j - 1])) {
                stack.addFirst(new DiffLine(DiffType.EQUAL, linesA[i - 1]));
                i--; j--;
            } else if (lcs[i - 1][j] >= lcs[i][j - 1]) {
                stack.addFirst(new DiffLine(DiffType.REMOVED, linesA[i - 1]));
                i--;
            } else {
                stack.addFirst(new DiffLine(DiffType.ADDED, linesB[j - 1]));
                j--;
            }
        }
        while (i > 0) { stack.addFirst(new DiffLine(DiffType.REMOVED, linesA[--i])); }
        while (j > 0) { stack.addFirst(new DiffLine(DiffType.ADDED, linesB[--j])); }

        diffLines.addAll(stack);
        return diffLines;
    }
}
```

## 七、性能优化：内容指纹去重

### 7.1 去重的必要性

在实际业务场景中，大量内容存在重复提交或高度相似的情况（如同一张图片被多个商家使用、同一段文案被批量复制）。如果每次都执行完整的机审+人审流程，会造成巨大的资源浪费，尤其是AI审核服务通常涉及外部调用，存在明显的延迟和成本。因此内容指纹去重是审核平台一项重要的性能优化手段。

### 7.2 内容指纹去重实现

```java
/**
 * 内容指纹去重服务
 *
 * 通过内容MD5哈希判断是否为完全相同的内容，
 * 相同内容直接复用历史审核结果，避免重复审核
 */
@Service
public class ContentDedupService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final String CACHE_KEY_PREFIX = "audit:dedup:";
    private static final long CACHE_TTL_DAYS = 7;

    public boolean isAlreadyReviewed(String content) {
        String hash = DigestUtils.md5Hex(content);
        return Boolean.TRUE.equals(redisTemplate.hasKey(CACHE_KEY_PREFIX + hash));
    }

    public void cacheReviewResult(String content, AuditResult result) {
        String hash = DigestUtils.md5Hex(content);
        redisTemplate.opsForValue().set(CACHE_KEY_PREFIX + hash,
            JSON.toJSONString(result), CACHE_TTL_DAYS, TimeUnit.DAYS);
    }

    public AuditResult getCachedResult(String content) {
        String hash = DigestUtils.md5Hex(content);
        String cached = redisTemplate.opsForValue().get(CACHE_KEY_PREFIX + hash);
        return cached == null ? null : JSON.parseObject(cached, AuditResult.class);
    }
}

/**
 * 图片指纹去重：使用感知哈希（pHash）识别"高度相似但非完全一致"的图片
 *
 * 相比MD5仅能识别完全相同的文件，pHash可以识别经过轻微裁剪、
 * 压缩、加水印等变换后仍然视觉相似的图片，进一步扩大去重覆盖面
 */
@Service
public class ImagePerceptualHashService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final int HAMMING_DISTANCE_THRESHOLD = 5; // 汉明距离阈值，越小越严格

    /**
     * 计算图片感知哈希（简化实现：缩放至8x8灰度图，比较均值生成64位指纹）
     */
    public String computePHash(BufferedImage image) {
        BufferedImage resized = resize(image, 8, 8);
        int[][] gray = toGrayScale(resized);

        double avg = Arrays.stream(gray).flatMapToInt(Arrays::stream).average().orElse(0);

        StringBuilder hash = new StringBuilder();
        for (int[] row : gray) {
            for (int pixel : row) {
                hash.append(pixel >= avg ? '1' : '0');
            }
        }
        return hash.toString();
    }

    /**
     * 判断新图片是否与已审核图片高度相似
     */
    public AuditResult findSimilarReviewedResult(String pHash) {
        // 实际生产实现通常借助向量检索引擎做近似最近邻搜索，
        // 此处以遍历近期指纹库做简化示例
        Set<String> recentHashes = redisTemplate.opsForZSet()
            .range("audit:phash:recent", 0, -1);

        if (recentHashes == null) {
            return null;
        }

        for (String existingHash : recentHashes) {
            if (hammingDistance(pHash, existingHash) <= HAMMING_DISTANCE_THRESHOLD) {
                String resultKey = "audit:phash:result:" + existingHash;
                String cached = redisTemplate.opsForValue().get(resultKey);
                if (cached != null) {
                    return JSON.parseObject(cached, AuditResult.class);
                }
            }
        }
        return null;
    }

    private int hammingDistance(String a, String b) {
        int distance = 0;
        for (int i = 0; i < Math.min(a.length(), b.length()); i++) {
            if (a.charAt(i) != b.charAt(i)) {
                distance++;
            }
        }
        return distance;
    }

    private BufferedImage resize(BufferedImage src, int width, int height) {
        BufferedImage resized = new BufferedImage(width, height, BufferedImage.TYPE_INT_RGB);
        Graphics2D g = resized.createGraphics();
        g.drawImage(src, 0, 0, width, height, null);
        g.dispose();
        return resized;
    }

    private int[][] toGrayScale(BufferedImage image) {
        int width = image.getWidth();
        int height = image.getHeight();
        int[][] gray = new int[height][width];
        for (int y = 0; y < height; y++) {
            for (int x = 0; x < width; x++) {
                int rgb = image.getRGB(x, y);
                int r = (rgb >> 16) & 0xFF;
                int g = (rgb >> 8) & 0xFF;
                int b = rgb & 0xFF;
                gray[y][x] = (r + g + b) / 3;
            }
        }
        return gray;
    }
}
```

### 7.3 审核入口整合去重逻辑

```java
/**
 * 审核入口：先查内容指纹缓存，命中则直接复用历史结果
 */
@Service
public class AuditEntryService {

    @Autowired
    private ContentDedupService dedupService;

    @Autowired
    private AuditOrchestrator auditOrchestrator;

    public AuditResult submit(AuditTask task) {
        // 1. 完全相同内容直接复用缓存结果
        AuditResult cached = dedupService.getCachedResult(task.getContent());
        if (cached != null) {
            return cached;
        }

        // 2. 执行完整审核流程
        AuditResult result = auditOrchestrator.execute(task);

        // 3. 仅缓存机审明确结论（人审转派中的任务不缓存，避免污染后续判断）
        if (result.getSource() == ResultSource.MACHINE) {
            dedupService.cacheReviewResult(task.getContent(), result);
        }

        return result;
    }
}
```

## 八、最佳实践与总结

### 8.1 核心设计决策

| 决策点 | 选择 | 理由（关联学城文档描述） |
|--------|------|------------------------|
| 平台定位 | 人审机审一体的独立中台 | "集人审、机审一体的内容审核平台" |
| 交互模式 | 业务方提交任务，异步通知结果 | "业务方将需要审核的数据提交到审核平台...将审核结果异步通知给业务方" |
| 审核流程 | 机审规则引擎 → AI审核 → 人审兜底 | 规则处理确定性场景，AI处理概率化场景，人审处理不确定场景，逐层收敛 |
| 机审规则 | 敏感词/内容安全/图片亮度水印尺寸二维码/OCR/自定义规则组合 | 对应学城文档列出的核心机审能力清单 |
| 人审能力 | 自定义分单/动态表单/版本对比/精细化驳回/自动下一单 | 对应学城文档列出的核心人审能力清单 |
| 敏感词算法 | DFA算法 | O(n)时间复杂度，满足高并发文本审核需求 |
| 流程可配置 | 数据库驱动的规则链+阈值配置 | 对应"审核流程配置"能力，业务方自助配置无需代码发布 |
| 版本管理 | 内容哈希+行级Diff | 对应"版本对比"能力，帮助人审快速定位内容变化 |
| 去重优化 | MD5精确去重 + pHash相似图片去重 | 避免重复内容反复消耗机审/人审资源 |
| 能力边界 | 不覆盖UGC/IM及流程审批场景 | 学城文档明确划定的不适用场景，保持平台职责单一 |

### 8.2 容易踩的坑

1. **只依赖机审，没有人审兜底**：AI模型存在天然的误判率，尤其对于语义模糊、新型违规变体（谐音、隐喻）识别能力有限，高风险内容类目必须保留人审通道作为最后防线。
2. **敏感词库不做分类管理，所有业务共用一套词库**：不同审核类型（风控安全/品控质量/资质证照）关注点差异很大，共用词库容易造成误杀或漏审，应按类别拆分词库并允许流程配置按需组合。
3. **图片审核忽略OCR环节**：图片本身可能通过CV安全检测，但图片内嵌的文字（如广告语、联系方式）可能违规，必须将OCR识别结果二次送入文本审核链路。
4. **审核结果不做缓存，相同内容反复走完整流程**：AI审核通常涉及外部服务调用，存在延迟和成本，完全相同或高度相似的内容应通过指纹去重直接复用历史结果。
5. **审核流程写死在代码里**：不同业务方的规则组合、阈值设定差异很大，如果每次调整都需要发版，会严重拖慢业务接入和策略迭代速度，应将规则链和阈值配置化。
6. **审核结果同步返回，阻塞业务方主流程**：审核（尤其涉及人审）耗时不可控，应采用"先接收任务、异步通知结果"的模式，避免业务方接口因审核耗时被拖慢。
7. **审核员质量缺乏监控机制**：人工审核容易因疲劳、经验不足产生漏审，需要建立常态化的随机抽检机制，及时发现审核质量异常。
8. **版本变更后审核员从零开始审阅**：如果不做版本对比，审核员每次都要重新审阅完整内容，效率低下，应通过Diff高亮内容变化部分，让审核员聚焦在改动点上。

### 8.3 总结

统一内容审核平台的核心价值在于把"审核能力"从各业务系统中剥离出来，形成一套可复用、可配置的中台服务。其架构设计的关键在于：机审规则引擎负责处理确定性强、成本低的检测逻辑，AI审核服务处理概率化的语义/图像识别判断，人工审核作为最终兜底防线处理机器无法确定的内容；同时通过流程可配置、动态表单、版本对比等能力，使得平台既能保持核心链路的通用性，又能灵活适配不同业务方千差万别的审核诉求。这种"机审优先过滤、人审兜底把关、异步解耦通知"的架构模式，是当前内容安全领域的主流工程实践。

## 九、全链路实战案例

前面章节分别拆解了审核平台的各个子能力模块，本章通过三个完整的端到端案例，把这些模块串联起来，还原真实业务场景下请求从发起到落地的完整路径，并补充生产环境中不可或缺的异常处理、日志记录与幂等控制细节。

### 9.1 案例一：UGC内容提交审核全链路

#### 9.1.1 场景说明

UGC（评论、动态、弹幕、图文笔记等）场景的特点是内容形态多样（文本+图片+视频混排）、提交量大、来源分散（App、小程序、开放接口等多端）。虽然学城文档将纯粹的UGC/IM实时场景划为"不适用"范围（详见1.3节），但绝大多数UGC内容在发布后仍需要走一次完整的**发布前置审核**（区别于聊天场景的实时拦截），本案例演示的正是这种"提交-机审-人审-回调-申诉"的完整闭环，与9.2节的实时流场景形成互补。

#### 9.1.2 全链路流程图

```
┌────────────────────────────────────────────────────────────────────────────┐
│                       UGC内容提交审核全链路                                    │
├────────────────────────────────────────────────────────────────────────────┤
```

#### 9.1.3 统一接入层：内容提交与幂等控制

多个业务入口（评论、动态、弹幕、图文笔记）汇聚到同一个提交接口，接入层的首要职责是做好幂等和请求收敛，避免客户端重试或网络抖动导致同一条内容被重复审核、重复计费。

```java
/**
 * UGC内容统一提交请求
 */
public class UgcSubmitRequest implements Serializable {
    private String submitId;      // 客户端生成的幂等键（如 UUID），同一条内容重复提交必须携带同一个submitId
    private String bizCode;       // COMMENT / FEED / DANMU / NOTE
    private Long userId;
    private String textContent;   // 文本片段，可为空
    private List<String> imageUrls;  // 图片URL列表，可为空
    private String videoUrl;         // 视频URL，可为空
    // getter/setter省略
}

/**
 * UGC内容提交接入层
 *
 * 职责：
 * 1. 参数校验（至少包含一种内容形态）
 * 2. 幂等控制：基于submitId的分布式锁 + 唯一索引兜底，防止重复提交生成多条审核任务
 * 3. 内容落库为PENDING状态，快速返回，真正的审核动作异步执行
 */
@RestController
@RequestMapping("/api/ugc/audit")
public class UgcSubmitController {

    private static final Logger log = LoggerFactory.getLogger(UgcSubmitController.class);

    @Autowired
    private UgcSubmitService submitService;

    @PostMapping("/submit")
    public ApiResponse<UgcSubmitResultVO> submit(@RequestBody UgcSubmitRequest request) {
        try {
            validate(request);
            UgcSubmitResultVO result = submitService.submit(request);
            return ApiResponse.success(result);
        } catch (DuplicateSubmitException e) {
            // 幂等命中不是异常场景，直接把首次提交的结果原样返回给调用方
            log.info("UGC提交幂等命中, submitId={}, existingTaskId={}",
                request.getSubmitId(), e.getExistingTaskId());
            return ApiResponse.success(new UgcSubmitResultVO(e.getExistingTaskId(), "DUPLICATE_IGNORED"));
        } catch (IllegalArgumentException e) {
            log.warn("UGC提交参数非法, submitId={}, reason={}", request.getSubmitId(), e.getMessage());
            return ApiResponse.fail("PARAM_INVALID", e.getMessage());
        } catch (Exception e) {
            log.error("UGC提交处理异常, submitId={}", request.getSubmitId(), e);
            return ApiResponse.fail("SYSTEM_ERROR", "提交失败，请稍后重试");
        }
    }

    private void validate(UgcSubmitRequest request) {
        if (StringUtils.isBlank(request.getSubmitId())) {
            throw new IllegalArgumentException("submitId不能为空");
        }
        boolean hasContent = StringUtils.isNotBlank(request.getTextContent())
            || CollectionUtils.isNotEmpty(request.getImageUrls())
            || StringUtils.isNotBlank(request.getVideoUrl());
        if (!hasContent) {
            throw new IllegalArgumentException("提交内容不能全部为空");
        }
    }
}

/**
 * UGC提交服务：负责幂等落库 + 派发到机审流水线
 */
@Service
public class UgcSubmitService {

    private static final Logger log = LoggerFactory.getLogger(UgcSubmitService.class);

    @Autowired
    private UgcAuditTaskMapper ugcTaskMapper;

    @Autowired
    private RedissonClient redissonClient;

    @Autowired
    private KafkaTemplate<String, UgcAuditTaskMessage> kafkaTemplate;

    private static final String LOCK_KEY_PREFIX = "ugc:submit:lock:";
    private static final String SUBMIT_TOPIC = "ugc-audit-submit-topic";

    /**
     * 提交内容，保证幂等：
     * 1. 分布式锁防止并发重复提交的竞态窗口
     * 2. submit_id唯一索引作为数据库层最终兜底
     */
    @Transactional(rollbackFor = Exception.class)
    public UgcSubmitResultVO submit(UgcSubmitRequest request) {
        RLock lock = redissonClient.getLock(LOCK_KEY_PREFIX + request.getSubmitId());
        boolean locked = false;
        try {
            locked = lock.tryLock(3, 10, TimeUnit.SECONDS);
            if (!locked) {
                throw new BizException("SUBMIT_BUSY", "提交处理中，请勿重复点击");
            }

            UgcAuditTask existing = ugcTaskMapper.selectBySubmitId(request.getSubmitId());
            if (existing != null) {
                throw new DuplicateSubmitException(existing.getTaskId());
            }

            UgcAuditTask task = buildTask(request);
            try {
                ugcTaskMapper.insert(task);
            } catch (DuplicateKeyException e) {
                // 极端并发下分布式锁失效（如Redis主从切换），唯一索引兜底幂等
                UgcAuditTask raced = ugcTaskMapper.selectBySubmitId(request.getSubmitId());
                if (raced != null) {
                    throw new DuplicateSubmitException(raced.getTaskId());
                }
                throw e;
            }

            // 落库成功后再发MQ，避免"MQ已发但事务回滚"导致的任务丢失或悬空消费
            sendToMachineAuditQueue(task);

            log.info("UGC内容提交成功, submitId={}, taskId={}, bizCode={}",
                request.getSubmitId(), task.getTaskId(), request.getBizCode());

            return new UgcSubmitResultVO(task.getTaskId(), "PENDING");
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BizException("SYSTEM_ERROR", "提交处理被中断");
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    private void sendToMachineAuditQueue(UgcAuditTask task) {
        UgcAuditTaskMessage message = UgcAuditTaskMessage.from(task);
        try {
            // 使用taskId作为分区键，保证同一内容的审核消息顺序消费，避免乱序导致状态覆盖
            kafkaTemplate.send(SUBMIT_TOPIC, String.valueOf(task.getTaskId()), message).get(3, TimeUnit.SECONDS);
        } catch (Exception e) {
            log.error("UGC审核任务入队失败, taskId={}, 将由补偿任务扫描重发", task.getTaskId(), e);
            // 不向上抛异常导致事务回滚：任务已经落库为PENDING，由定时补偿任务扫描长时间处于PENDING的记录重新入队
            ugcTaskMapper.markEnqueueFailed(task.getTaskId());
        }
    }

    private UgcAuditTask buildTask(UgcSubmitRequest request) {
        UgcAuditTask task = new UgcAuditTask();
        task.setSubmitId(request.getSubmitId());
        task.setTaskId(SnowflakeIdGenerator.nextId());
        task.setBizCode(request.getBizCode());
        task.setUserId(request.getUserId());
        task.setTextContent(request.getTextContent());
        task.setImageUrls(JSON.toJSONString(request.getImageUrls()));
        task.setVideoUrl(request.getVideoUrl());
        task.setStatus(UgcAuditStatus.PENDING.getCode());
        task.setSubmitTime(new Date());
        return task;
    }
}

/**
 * 补偿任务：扫描长时间处于PENDING但未成功入队的任务，重新投递
 * 兜底解决MQ瞬时不可用导致的任务卡死问题
 */
@Component
public class UgcAuditCompensationJob {

    private static final Logger log = LoggerFactory.getLogger(UgcAuditCompensationJob.class);

    @Autowired
    private UgcAuditTaskMapper ugcTaskMapper;

    @Autowired
    private KafkaTemplate<String, UgcAuditTaskMessage> kafkaTemplate;

    @Scheduled(fixedDelay = 60_000)
    public void retryEnqueueFailed() {
        List<UgcAuditTask> stuckTasks = ugcTaskMapper.selectStuckPending(5, 200); // 超过5分钟未处理的最多200条
        for (UgcAuditTask task : stuckTasks) {
            try {
                kafkaTemplate.send("ugc-audit-submit-topic", String.valueOf(task.getTaskId()),
                    UgcAuditTaskMessage.from(task)).get(3, TimeUnit.SECONDS);
                ugcTaskMapper.clearEnqueueFailedFlag(task.getTaskId());
                log.info("补偿重发成功, taskId={}", task.getTaskId());
            } catch (Exception e) {
                log.error("补偿重发仍然失败, taskId={}, 等待下一轮重试", task.getTaskId(), e);
            }
        }
    }
}
```

#### 9.1.4 机审流水线：文本+图片+视频多模态并行审核

真实的UGC内容往往是"文本+图片"或"文本+视频"的混合体，机审消费者需要对每种模态分别执行专属流水线，再汇总为综合决策。为了控制端到端延迟，不同模态的审核可以并行执行。

```java
/**
 * UGC机审消费者：从提交队列消费任务，执行多模态机审流水线
 */
@Component
public class UgcMachineAuditConsumer {

    private static final Logger log = LoggerFactory.getLogger(UgcMachineAuditConsumer.class);

    @Autowired
    private UgcMultiModalAuditService multiModalAuditService;

    @Autowired
    private UgcAuditTaskMapper ugcTaskMapper;

    @Autowired
    private UgcManualQueueService manualQueueService;

    @Autowired
    private UgcResultNotifyService notifyService;

    /**
     * 消费UGC提交消息，执行机审。
     * 消费者本身具备幂等性：通过任务当前状态判断是否需要重复处理，
     * 避免MQ重复投递（at-least-once语义）导致同一任务被审核两次。
     */
    @KafkaListener(topics = "ugc-audit-submit-topic", groupId = "ugc-machine-audit-group", concurrency = "8")
    public void onMessage(UgcAuditTaskMessage message, Acknowledgment ack) {
        Long taskId = message.getTaskId();
        try {
            UgcAuditTask task = ugcTaskMapper.selectByTaskId(taskId);
            if (task == null) {
                log.warn("消费到不存在的UGC审核任务, taskId={}, 可能是脏数据，直接ack丢弃", taskId);
                ack.acknowledge();
                return;
            }
            if (task.getStatus() != UgcAuditStatus.PENDING.getCode()) {
                // 幂等短路：任务已经被处理过（重复消费），直接ack跳过，不重复扣减机审资源
                log.info("UGC任务已处理，跳过重复消费, taskId={}, currentStatus={}", taskId, task.getStatus());
                ack.acknowledge();
                return;
            }

            MultiModalAuditResult result = multiModalAuditService.auditAll(task);
            handleResult(task, result);

            ack.acknowledge();
        } catch (Exception e) {
            // 机审异常不能吞掉，也不能无限重试阻塞消费进度：
            // 记录异常并ack，由独立的失败重试表兜底，避免"毒消息"卡死整个消费组
            log.error("UGC机审处理异常, taskId={}", taskId, e);
            ugcTaskMapper.markMachineAuditError(taskId, e.getMessage());
            ack.acknowledge();
        }
    }

    private void handleResult(UgcAuditTask task, MultiModalAuditResult result) {
        switch (result.getDecision()) {
            case PASS:
                ugcTaskMapper.updateStatus(task.getTaskId(), UgcAuditStatus.MACHINE_PASS.getCode(),
                    JSON.toJSONString(result));
                notifyService.notify(task, AuditDecision.PASS, "MACHINE", null);
                log.info("UGC机审通过, taskId={}", task.getTaskId());
                break;
            case REJECT:
                ugcTaskMapper.updateStatus(task.getTaskId(), UgcAuditStatus.MACHINE_REJECT.getCode(),
                    JSON.toJSONString(result));
                notifyService.notify(task, AuditDecision.REJECT, "MACHINE", result.getRejectReason());
                log.info("UGC机审拒绝, taskId={}, reason={}", task.getTaskId(), result.getRejectReason());
                break;
            case TO_MANUAL:
            default:
                ugcTaskMapper.updateStatus(task.getTaskId(), UgcAuditStatus.TO_MANUAL.getCode(),
                    JSON.toJSONString(result));
                manualQueueService.enqueue(task, result.getRiskLevel());
                log.info("UGC机审不确定，转人审, taskId={}, riskLevel={}", task.getTaskId(), result.getRiskLevel());
                break;
        }
    }
}

/**
 * 多模态审核汇总服务
 *
 * 文本、图片、视频三种模态并行审核后汇总决策：
 * - 任一模态明确REJECT，整体判定为REJECT（短路，不必等待其他模态完成）
 * - 全部模态PASS，整体判定为PASS
 * - 其余情况（含超时、异常）转人审兜底
 */
@Service
public class UgcMultiModalAuditService {

    private static final Logger log = LoggerFactory.getLogger(UgcMultiModalAuditService.class);

    @Autowired
    private TextAuditPipeline textAuditPipeline;

    @Autowired
    private ImageAuditPipeline imageAuditPipeline;

    @Autowired
    private VideoAuditPipeline videoAuditPipeline;

    @Autowired
    @Qualifier("auditPipelineExecutor")
    private ExecutorService auditExecutor;

    private static final long MODAL_TIMEOUT_SECONDS = 8;

    public MultiModalAuditResult auditAll(UgcAuditTask task) {
        List<Future<ModalAuditResult>> futures = new ArrayList<>();

        if (StringUtils.isNotBlank(task.getTextContent())) {
            futures.add(auditExecutor.submit(() -> textAuditPipeline.audit(task.getTextContent())));
        }
        List<String> imageUrls = parseImageUrls(task.getImageUrls());
        if (CollectionUtils.isNotEmpty(imageUrls)) {
            for (String imageUrl : imageUrls) {
                futures.add(auditExecutor.submit(() -> imageAuditPipeline.audit(imageUrl)));
            }
        }
        if (StringUtils.isNotBlank(task.getVideoUrl())) {
            futures.add(auditExecutor.submit(() -> videoAuditPipeline.audit(task.getVideoUrl())));
        }

        List<ModalAuditResult> results = new ArrayList<>();
        boolean hasTimeoutOrError = false;

        for (Future<ModalAuditResult> future : futures) {
            try {
                ModalAuditResult r = future.get(MODAL_TIMEOUT_SECONDS, TimeUnit.SECONDS);
                results.add(r);
            } catch (TimeoutException e) {
                future.cancel(true);
                log.warn("UGC某模态审核超时, taskId={}", task.getTaskId());
                hasTimeoutOrError = true;
            } catch (Exception e) {
                log.error("UGC某模态审核异常, taskId={}", task.getTaskId(), e);
                hasTimeoutOrError = true;
            }
        }

        return aggregate(results, hasTimeoutOrError);
    }

    private MultiModalAuditResult aggregate(List<ModalAuditResult> results, boolean hasTimeoutOrError) {
        for (ModalAuditResult r : results) {
            if (r.isReject()) {
                return MultiModalAuditResult.reject(r.getReason(), r.getRiskLevel());
            }
        }
        if (hasTimeoutOrError) {
            // 存在模态审核失败或超时，无法确认内容完全安全，保守转人审而非直接放行
            return MultiModalAuditResult.toManual("部分模态审核超时或异常，转人工复核", 2);
        }
        boolean anyUncertain = results.stream().anyMatch(ModalAuditResult::isUncertain);
        if (anyUncertain) {
            int maxRisk = results.stream().mapToInt(ModalAuditResult::getRiskLevel).max().orElse(1);
            return MultiModalAuditResult.toManual("存在模态判定不确定", maxRisk);
        }
        return MultiModalAuditResult.pass();
    }

    private List<String> parseImageUrls(String imageUrlsJson) {
        if (StringUtils.isBlank(imageUrlsJson)) {
            return Collections.emptyList();
        }
        try {
            return JSON.parseArray(imageUrlsJson, String.class);
        } catch (Exception e) {
            log.warn("图片URL列表解析失败, raw={}", imageUrlsJson, e);
            return Collections.emptyList();
        }
    }
}

/**
 * 文本审核流水线：敏感词DFA（快速短路）+ NLP语义分类
 */
@Component
public class TextAuditPipeline {

    private static final Logger log = LoggerFactory.getLogger(TextAuditPipeline.class);

    @Autowired
    private SensitiveWordFilter sensitiveWordFilter;

    @Autowired
    private NlpClient nlpClient;

    public ModalAuditResult audit(String text) {
        try {
            // 第一层：DFA敏感词，命中即拒绝，无需调用成本更高的NLP服务
            if (sensitiveWordFilter.contains(text)) {
                return ModalAuditResult.reject("命中敏感词库", 3);
            }
            // 第二层：AI语义分类，识别隐喻、谐音等敏感词无法覆盖的违规表达
            NlpClassifyResult classifyResult = nlpClient.classify(text);
            if (classifyResult.getMaxRiskScore() > 0.8) {
                return ModalAuditResult.reject("AI语义分类判定违规: " + classifyResult.getMaxRiskCategory(), 3);
            }
            if (classifyResult.getMaxRiskScore() > 0.3) {
                return ModalAuditResult.uncertain("语义风险分数处于灰度区间", 2);
            }
            return ModalAuditResult.pass();
        } catch (Exception e) {
            log.error("文本审核流水线异常, text.length={}", text == null ? 0 : text.length(), e);
            // 单点异常不吞没，向上抛出由汇总层统一按"超时或异常"逻辑转人审
            throw new AuditPipelineException("文本审核异常", e);
        }
    }
}

/**
 * 图片审核流水线：鉴黄CV模型 + OCR文字二次审核 + 人脸检测（涉政敏感人物比对）
 */
@Component
public class ImageAuditPipeline {

    private static final Logger log = LoggerFactory.getLogger(ImageAuditPipeline.class);

    @Autowired
    private CvClient cvClient;

    @Autowired
    private OcrClient ocrClient;

    @Autowired
    private FaceRecognitionClient faceRecognitionClient;

    @Autowired
    private SensitiveWordFilter sensitiveWordFilter;

    public ModalAuditResult audit(String imageUrl) {
        try {
            // 1. 鉴黄/暴恐CV检测
            CvDetectResult cvResult = cvClient.detect(imageUrl);
            if (cvResult.getPornScore() > 0.8 || cvResult.getViolenceScore() > 0.8) {
                return ModalAuditResult.reject("图片鉴黄/暴恐检测未通过", 3);
            }

            // 2. OCR识别图片文字，复用文本敏感词库二次检测
            String ocrText = ocrClient.recognize(imageUrl);
            if (StringUtils.isNotBlank(ocrText) && sensitiveWordFilter.contains(ocrText)) {
                return ModalAuditResult.reject("图片OCR文字命中敏感词: " + ocrText, 3);
            }

            // 3. 人脸检测：比对涉政/涉黑敏感人物库，命中直接拒绝
            List<FaceMatchResult> faceMatches = faceRecognitionClient.detectAndMatch(imageUrl);
            for (FaceMatchResult match : faceMatches) {
                if (match.isSensitivePerson() && match.getSimilarity() > 0.85) {
                    return ModalAuditResult.reject("人脸比对命中敏感人物库", 3);
                }
            }

            if (cvResult.getPornScore() > 0.3 || cvResult.getViolenceScore() > 0.3) {
                return ModalAuditResult.uncertain("图片风险分数处于灰度区间", 2);
            }
            return ModalAuditResult.pass();
        } catch (Exception e) {
            log.error("图片审核流水线异常, imageUrl={}", imageUrl, e);
            throw new AuditPipelineException("图片审核异常", e);
        }
    }
}

/**
 * 视频审核流水线：抽帧复用图片审核 + 音轨ASR复用文本审核
 */
@Component
public class VideoAuditPipeline {

    private static final Logger log = LoggerFactory.getLogger(VideoAuditPipeline.class);

    @Autowired
    private VideoFrameExtractor videoFrameExtractor;

    @Autowired
    private ImageAuditPipeline imageAuditPipeline;

    @Autowired
    private AsrClient asrClient;

    @Autowired
    private TextAuditPipeline textAuditPipeline;

    private static final int MAX_FRAMES_TO_CHECK = 10; // 控制单视频最大抽帧审核数量，避免长视频拖慢整体耗时

    public ModalAuditResult audit(String videoUrl) {
        try {
            List<String> frameUrls = videoFrameExtractor.extract(videoUrl, 1);
            if (frameUrls.size() > MAX_FRAMES_TO_CHECK) {
                frameUrls = samplingFrames(frameUrls, MAX_FRAMES_TO_CHECK);
            }

            for (String frameUrl : frameUrls) {
                ModalAuditResult frameResult = imageAuditPipeline.audit(frameUrl);
                if (frameResult.isReject()) {
                    return ModalAuditResult.reject("视频抽帧检测违规: " + frameResult.getReason(), 3);
                }
            }

            String transcript = asrClient.transcribe(videoUrl);
            if (StringUtils.isNotBlank(transcript)) {
                ModalAuditResult audioTextResult = textAuditPipeline.audit(transcript);
                if (audioTextResult.isReject()) {
                    return ModalAuditResult.reject("视频音轨文字违规: " + audioTextResult.getReason(), 3);
                }
            }
            return ModalAuditResult.pass();
        } catch (Exception e) {
            log.error("视频审核流水线异常, videoUrl={}", videoUrl, e);
            throw new AuditPipelineException("视频审核异常", e);
        }
    }

    /** 均匀抽样，避免只审核视频开头几秒导致后段违规内容漏审 */
    private List<String> samplingFrames(List<String> frames, int targetCount) {
        List<String> sampled = new ArrayList<>();
        double step = (double) frames.size() / targetCount;
        for (int i = 0; i < targetCount; i++) {
            sampled.add(frames.get((int) (i * step)));
        }
        return sampled;
    }
}
```

#### 9.1.5 人工审核队列分配与回调通知

机审判定"不确定"的任务进入人审队列，按风险等级和业务类型分单；无论最终结论来自机审还是人审，都要经过统一的回调通知出口，并且通知本身必须支持幂等去重（业务方可能收到重复回调）。

```java
/**
 * UGC人审队列服务：按风险等级分级入队，高风险任务由资深审核员优先处理
 */
@Service
public class UgcManualQueueService {

    private static final Logger log = LoggerFactory.getLogger(UgcManualQueueService.class);

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final String QUEUE_KEY_PREFIX = "ugc:manual:queue:risk:";

    /**
     * 入队：使用Redis ZSet按提交时间排序，riskLevel决定使用哪个优先级队列
     * 幂等：以taskId为member，重复入队不会产生重复元素
     */
    public void enqueue(UgcAuditTask task, int riskLevel) {
        try {
            String queueKey = QUEUE_KEY_PREFIX + riskLevel;
            redisTemplate.opsForZSet().add(queueKey, String.valueOf(task.getTaskId()),
                System.currentTimeMillis());
            log.info("UGC任务转入人审队列, taskId={}, riskLevel={}, queue={}",
                task.getTaskId(), riskLevel, queueKey);
        } catch (Exception e) {
            // Redis队列写入失败不代表任务丢失：任务在DB中的状态已经是TO_MANUAL，
            // 由定时对账任务扫描TO_MANUAL但未在任何Redis队列中的任务，重新入队
            log.error("UGC任务写入人审队列失败, taskId={}, 等待对账任务兜底", task.getTaskId(), e);
        }
    }

    /**
     * 审核员领取任务：优先从高风险队列取，保证高风险内容优先被资深审核员处理
     */
    public Long claimNext(Long reviewerId, boolean isSenior) {
        List<Integer> queueOrder = isSenior
            ? Arrays.asList(3, 2, 1)
            : Arrays.asList(1, 2, 3);

        for (Integer riskLevel : queueOrder) {
            String queueKey = QUEUE_KEY_PREFIX + riskLevel;
            Set<String> candidates = redisTemplate.opsForZSet().range(queueKey, 0, 0);
            if (CollectionUtils.isEmpty(candidates)) {
                continue;
            }
            String taskIdStr = candidates.iterator().next();
            // 用ZREM的返回值判断是否抢占成功，天然具备互斥语义，防止多个审核员领取同一任务
            Long removed = redisTemplate.opsForZSet().remove(queueKey, taskIdStr);
            if (removed != null && removed > 0) {
                return Long.valueOf(taskIdStr);
            }
        }
        return null;
    }
}

     * 通知业务方审核结论。
     * 幂等控制：同一taskId+decision的组合在TTL内只通知一次，
     * 防止机审/人审流程重复触发（如消息重复消费）导致业务方收到多条重复回调。
     */
    public void notify(UgcAuditTask task, AuditDecision decision, String source, String reason) {
        String dedupKey = NOTIFY_DEDUP_KEY_PREFIX + task.getTaskId() + ":" + decision.name();
        Boolean firstTime = redisTemplate.opsForValue()
            .setIfAbsent(dedupKey, "1", DEDUP_TTL_HOURS, TimeUnit.HOURS);

        if (Boolean.FALSE.equals(firstTime)) {
            log.info("UGC审核结果通知去重命中，跳过重复通知, taskId={}, decision={}",
                task.getTaskId(), decision);
            return;
        }

        UgcNotifyMessage message = new UgcNotifyMessage();
        message.setTaskId(task.getTaskId());
        message.setBizCode(task.getBizCode());
        message.setUserId(task.getUserId());
        message.setDecision(decision.name());
        message.setSource(source);
        message.setReason(reason);
        message.setNotifyTime(System.currentTimeMillis());

        try {
            kafkaTemplate.send("ugc-audit-result-topic", task.getBizCode(), message).get(3, TimeUnit.SECONDS);
            log.info("UGC审核结果通知成功, taskId={}, decision={}, source={}",
                task.getTaskId(), decision, source);
        } catch (Exception e) {
            log.error("UGC审核结果通知发送失败, taskId={}, 释放去重标记以便下次重试", task.getTaskId(), e);
            // 发送失败要撤销去重标记，否则该次结果将永远无法成功通知
            redisTemplate.delete(dedupKey);
            throw new BizException("NOTIFY_FAILED", "审核结果通知发送失败");
        }
    }
```

```java
/**
 * 申诉记录实体与表结构

/**
 * 申诉处理服务
 *
 * 限制：
 * 1. 只有机审/人审拒绝的任务才能申诉，且同一任务只能申诉一次（唯一索引兜底）
 * 2. 申诉复核由独立队列处理，避免与常规人审队列争抢资源、被普通任务淹没
 * 3. 复核改判后需要重新触发一次结果通知，并将原任务标记为最终态
 */
@Service
public class AuditAppealService {

    private static final Logger log = LoggerFactory.getLogger(AuditAppealService.class);

    @Autowired
    private AuditAppealMapper appealMapper;

    @Autowired
    private UgcAuditTaskMapper ugcTaskMapper;

    @Autowired
    private UgcResultNotifyService notifyService;

    @Autowired
    private RedissonClient redissonClient;

    private static final int MAX_APPEAL_PER_USER_PER_DAY = 5;

    /**
     * 提交申诉
     */
    @Transactional(rollbackFor = Exception.class)
    public Long submitAppeal(Long taskId, Long userId, String appealReason) {
        UgcAuditTask task = ugcTaskMapper.selectByTaskId(taskId);
        if (task == null) {
            throw new BizException("TASK_NOT_FOUND", "审核任务不存在");
        }
        if (!Objects.equals(task.getUserId(), userId)) {
            throw new BizException("NO_PERMISSION", "无权对他人内容发起申诉");
        }
        if (!isRejectedStatus(task.getStatus())) {
            throw new BizException("INVALID_STATUS", "仅拒绝状态的内容可以申诉");
        }

        // 简单的申诉频次限流，防止恶意用户批量刷申诉消耗人力复核资源
        String rateLimitKey = "ugc:appeal:rate:" + userId + ":" + LocalDate.now();
        RAtomicLong counter = redissonClient.getAtomicLong(rateLimitKey);
        long count = counter.incrementAndGet();
        if (count == 1) {
            counter.expire(Duration.ofDays(1));
        }
        if (count > MAX_APPEAL_PER_USER_PER_DAY) {
            throw new BizException("RATE_LIMITED", "今日申诉次数已达上限");
        }

        try {
            AuditAppeal appeal = new AuditAppeal();
            appeal.setAppealId(SnowflakeIdGenerator.nextId());
            appeal.setTaskId(taskId);
            appeal.setUserId(userId);
            appeal.setAppealReason(appealReason);
            appeal.setStatus(AppealStatus.PENDING.getCode());
            appeal.setCreateTime(new Date());
            appealMapper.insert(appeal);

            log.info("用户提交申诉成功, taskId={}, userId={}, appealId={}",
                taskId, userId, appeal.getAppealId());
            return appeal.getAppealId();
        } catch (DuplicateKeyException e) {
            // 唯一索引兜底：同一任务已存在申诉记录
            log.warn("重复申诉被拦截, taskId={}, userId={}", taskId, userId);
            throw new BizException("ALREADY_APPEALED", "该内容已提交过申诉，请勿重复提交");
        }
    }

    /**
     * 申诉复核：由专职复核审核员操作
     */
    @Transactional(rollbackFor = Exception.class)
    public void resolveAppeal(Long appealId, Long reviewerId, boolean overturn, String reviewComment) {
        AuditAppeal appeal = appealMapper.selectByAppealId(appealId);
        if (appeal == null) {
            throw new BizException("APPEAL_NOT_FOUND", "申诉单不存在");
        }
        if (appeal.getStatus() != AppealStatus.PENDING.getCode()) {
            // 幂等保护：申诉单已处理过，避免重复提交复核结果
            log.info("申诉单已处理，忽略重复复核请求, appealId={}, currentStatus={}",
                appealId, appeal.getStatus());
            return;
        }

        AppealStatus finalStatus = overturn ? AppealStatus.OVERTURNED : AppealStatus.UPHELD;
        appealMapper.updateResult(appealId, finalStatus.getCode(),
            JSON.toJSONString(new AppealReviewResult(reviewerId, reviewComment)), new Date());

        UgcAuditTask task = ugcTaskMapper.selectByTaskId(appeal.getTaskId());
        if (overturn) {
            // 改判为通过：更新原任务终态，并重新通知业务方
            ugcTaskMapper.updateStatus(task.getTaskId(), UgcAuditStatus.APPEAL_PASS.getCode(), null);
            notifyService.notify(task, AuditDecision.PASS, "APPEAL", "申诉复核改判通过: " + reviewComment);
            log.info("申诉复核改判通过, appealId={}, taskId={}", appealId, task.getTaskId());
        } else {
            log.info("申诉复核维持原判, appealId={}, taskId={}, comment={}",
                appealId, task.getTaskId(), reviewComment);
            // 维持原判无需重新通知业务方（业务方状态未变化），仅记录复核结论供用户查询
        }
    }

    private boolean isRejectedStatus(int status) {
        return status == UgcAuditStatus.MACHINE_REJECT.getCode()
            || status == UgcAuditStatus.MANUAL_REJECT.getCode();
    }
}
```

### 9.2 案例二：实时内容审核（直播/聊天场景）全链路

#### 9.2.1 场景说明

直播弹幕、IM聊天这类场景的核心矛盾在于：**内容必须在极短时间内（通常要求100ms～1s级别）做出放行/拦截决策，但高精度的AI审核模型往往需要几百毫秒甚至秒级耗时**，二者存在天然冲突。这正是学城文档中把"UGC、IM等业务场景"列为统一审核平台"不适用场景"的原因（详见1.3节）——完整走一遍机审+人审工作流的延迟无法满足实时性要求。因此实时场景需要一套独立的、以"轻量前置拦截 + 重度异步兜底"为核心思想的架构。

#### 9.2.3 实时流接入：WebSocket网关

```java
/**
 * 实时消息网关：直播弹幕/IM聊天消息的统一接入点
 *
 * 核心约束：接入层处理耗时必须控制在毫秒级，任何审核相关的重逻辑
 * 都不能放在这一层同步执行，只做鉴权、限流和消息初步封装
 */
@Component
public class RealtimeMessageGateway {

    private static final Logger log = LoggerFactory.getLogger(RealtimeMessageGateway.class);

    @Autowired
    private LightweightAuditFilter lightweightAuditFilter;

    @Autowired
    private MessageBroadcastService broadcastService;

    @Autowired
    private RateLimiterService rateLimiterService;

    /**
     * WebSocket消息处理入口（伪代码风格，聚焦审核相关逻辑）
     */
    public void onMessage(WebSocketSession session, RealtimeMessage message) {
        long startTime = System.currentTimeMillis();
        try {
            Long userId = resolveUserId(session);
            message.setUserId(userId);
            message.setMsgId(SnowflakeIdGenerator.nextId());
            message.setReceiveTime(startTime);

            // 1. 单用户发言频率限流，防止刷屏攻击拖垮下游审核链路
            if (!rateLimiterService.tryAcquire(userId, message.getRoomId())) {
                sendErrorToSender(session, "发言过于频繁，请稍后再试");
                log.warn("用户发言被限流, userId={}, roomId={}", userId, message.getRoomId());
                return;
            }

            // 2. 同步执行轻量级审核（要求控制在50ms内完成）
            LightAuditResult lightResult = lightweightAuditFilter.filter(message);

            if (lightResult.isBlocked()) {
                sendErrorToSender(session, "消息包含违规内容，已被拦截");
                log.info("轻量审核拦截, userId={}, msgId={}, reason={}, cost={}ms",
                    userId, message.getMsgId(), lightResult.getReason(),
                    System.currentTimeMillis() - startTime);
                // 拦截的消息仍然记录审计日志，但不下发、不进入异步重度审核（本身已确定违规）
                return;
            }

            // 3. 轻量审核放行，立即广播给房间内其他用户（不等待重度审核结果）
            broadcastService.broadcast(message);

            // 4. 异步投递到重度审核队列做事后精细化审核
            dispatchToAsyncAudit(message);

            log.info("实时消息处理完成, userId={}, msgId={}, cost={}ms",
                userId, message.getMsgId(), System.currentTimeMillis() - startTime);
        } catch (Exception e) {
            // 网关层异常必须兜底，避免单条消息异常导致WebSocket连接断开影响其他用户
            log.error("实时消息处理异常, roomId={}", message.getRoomId(), e);
            sendErrorToSender(session, "消息发送失败，请重试");
        }
    }

    private void dispatchToAsyncAudit(RealtimeMessage message) {
        try {
            AsyncAuditProducer.send(message);
        } catch (Exception e) {
            // 异步审核投递失败不影响消息已下发的事实，但必须记录日志，
            // 由本地降级队列或补偿机制兜底，避免违规内容"漏检"
            log.error("重度审核任务投递失败, msgId={}, 已启用本地降级队列兜底", message.getMsgId(), e);
            LocalFallbackQueue.offer(message);
        }
    }

    private Long resolveUserId(WebSocketSession session) {
        return (Long) session.getAttributes().get("userId");
    }

    private void sendErrorToSender(WebSocketSession session, String errMsg) {
        try {
            session.sendMessage(new TextMessage(JSON.toJSONString(ApiResponse.fail("BLOCKED", errMsg))));
        } catch (IOException e) {
            log.warn("向客户端下发拦截提示失败, session={}", session.getId(), e);
        }
    }
}
```

#### 9.2.4 轻量级实时审核：内存态敏感词+简单规则

轻量级审核层不允许有任何网络IO（不能调用远程AI服务），只依赖进程内存中的数据结构做判断，这是实现毫秒级响应的前提。

```java
/**
 * 轻量级实时审核过滤器
 *
 * 设计原则：
 * 1. 全部基于本地内存计算，杜绝远程调用（网络IO是实时性最大的敌人）
 * 2. 敏感词库定期热加载到本地，不实时查询DB/Redis
 * 3. 只做"确定性拦截"判断，不做模糊语义分析（那是重度审核的职责）
 */
@Component
public class LightweightAuditFilter {

    private static final Logger log = LoggerFactory.getLogger(LightweightAuditFilter.class);

    @Autowired
    private SensitiveWordFilter sensitiveWordFilter; // 复用4.1节DFA实现，纯内存结构，无IO

    @Autowired
    private DuplicateMessageDetector duplicateMessageDetector;

    @Autowired
    private LocalUrlBlacklistCache urlBlacklistCache;

    private static final Pattern URL_PATTERN = Pattern.compile("https?://[\\w./?=&%-]+");

    public LightAuditResult filter(RealtimeMessage message) {
        String content = message.getContent();
        if (StringUtils.isBlank(content)) {
            return LightAuditResult.pass();
        }

        try {
            // 规则1：敏感词DFA匹配，O(n)时间复杂度，可预测的低延迟
            if (sensitiveWordFilter.contains(content)) {
                return LightAuditResult.block("命中敏感词库");
            }

            // 规则2：URL黑名单正则匹配，拦截已知的违规引流链接
            Matcher matcher = URL_PATTERN.matcher(content);
            while (matcher.find()) {
                String url = matcher.group();
                if (urlBlacklistCache.contains(url)) {
                    return LightAuditResult.block("命中URL黑名单: " + url);
                }
            }

            // 规则3：短时间内重复刷同一条消息，判定为刷屏骚扰
            if (duplicateMessageDetector.isDuplicate(message.getUserId(), message.getRoomId(), content)) {
                return LightAuditResult.block("重复刷屏消息");
            }

            return LightAuditResult.pass();
        } catch (Exception e) {
            // 轻量审核本身出现异常是极端情况（本地内存计算不应该失败），
            // 出于安全兜底考虑，异常时选择拦截而非放行，避免因组件故障导致审核失效
            log.error("轻量级审核异常，按拦截兜底处理, msgId={}", message.getMsgId(), e);
            return LightAuditResult.block("审核组件异常，安全兜底拦截");
        }
    }
}

/**
 * 重复消息检测器：基于滑动窗口判断同一用户是否在短时间内重复发送相同/高度相似内容
 */
@Component
public class DuplicateMessageDetector {

    // 本地缓存：key为 userId+roomId，value为最近N条消息内容的哈希滑动窗口
    private final Cache<String, Deque<String>> recentMessageCache = Caffeine.newBuilder()
        .expireAfterWrite(10, TimeUnit.SECONDS)
        .maximumSize(100_000)
        .build();

    private static final int WINDOW_SIZE = 5;
    private static final int DUPLICATE_THRESHOLD = 3;

    public boolean isDuplicate(Long userId, Long roomId, String content) {
        String key = userId + ":" + roomId;
        String contentHash = DigestUtils.md5Hex(content);

        Deque<String> window = recentMessageCache.get(key, k -> new ConcurrentLinkedDeque<>());
        long sameCount = window.stream().filter(h -> h.equals(contentHash)).count();

        synchronized (window) {
            window.addLast(contentHash);
            while (window.size() > WINDOW_SIZE) {
                window.pollFirst();
            }
        }
        return sameCount + 1 >= DUPLICATE_THRESHOLD;
    }
}

/**
 * URL黑名单本地缓存：定期从配置中心/DB拉取全量黑名单到本地内存，
 * 查询时不产生任何网络IO
 */
@Component
public class LocalUrlBlacklistCache {

    private static final Logger log = LoggerFactory.getLogger(LocalUrlBlacklistCache.class);

    private volatile Set<String> blacklistSnapshot = Collections.emptySet();

    @Autowired
    private UrlBlacklistRepository repository;

    @PostConstruct
    @Scheduled(fixedDelay = 30_000) // 每30秒热更新一次，兼顾实时性与DB压力
    public void refresh() {
        try {
            Set<String> latest = new HashSet<>(repository.loadAll());
            this.blacklistSnapshot = latest; // 引用替换是原子操作，读取方不会读到中间状态
            log.debug("URL黑名单本地缓存刷新完成, size={}", latest.size());
        } catch (Exception e) {
            // 刷新失败不影响正在使用的旧快照继续生效，只记录日志告警
            log.error("URL黑名单缓存刷新失败，继续使用上一次快照", e);
        }
    }

    public boolean contains(String url) {
        return blacklistSnapshot.contains(url);
    }
}
```

#### 9.2.5 重度审核异步化与违规内容实时拦截

轻量审核放行的消息会立即展示给其他用户，但这只是"临时放行"——异步的重度AI审核仍会对内容做精细化复核，一旦发现违规，需要立刻触发撤回/下架，并联动用户处罚。

```java
/**
 * 重度审核异步消费者：NLP语义分类 + CV图像识别（针对弹幕表情包/直播截帧）
 */
@Component
public class AsyncHeavyAuditConsumer {

    private static final Logger log = LoggerFactory.getLogger(AsyncHeavyAuditConsumer.class);

    @Autowired
    private NlpClient nlpClient;

    @Autowired
    private CvClient cvClient;

    @Autowired
    private RealtimeAuditLogMapper auditLogMapper;

    @Autowired
    private MessageRevokeService revokeService;

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final String PROCESSED_KEY_PREFIX = "realtime:audit:processed:";

    @KafkaListener(topics = "realtime-audit-async-topic", groupId = "realtime-heavy-audit-group", concurrency = "16")
    public void onMessage(RealtimeMessage message, Acknowledgment ack) {
        try {
            // 幂等控制：同一msgId只做一次重度审核，防止MQ重复投递导致重复撤回操作
            String processedKey = PROCESSED_KEY_PREFIX + message.getMsgId();
            Boolean firstTime = redisTemplate.opsForValue().setIfAbsent(processedKey, "1", 1, TimeUnit.HOURS);
            if (Boolean.FALSE.equals(firstTime)) {
                log.info("重度审核幂等命中，跳过重复处理, msgId={}", message.getMsgId());
                ack.acknowledge();
                return;
            }

            HeavyAuditResult result = doHeavyAudit(message);
            auditLogMapper.insert(buildLog(message, result));

            if (result.isViolation()) {
                log.warn("重度审核发现事后违规, msgId={}, roomId={}, reason={}",
                    message.getMsgId(), message.getRoomId(), result.getReason());
                revokeService.revokeAndPunish(message, result.getReason());
            }

            ack.acknowledge();
        } catch (Exception e) {
            log.error("重度审核处理异常, msgId={}", message.getMsgId(), e);
            // 重度审核失败属于"漏检风险"，不能简单ack丢弃：记录失败明细供人工/定时任务补审
            auditLogMapper.insertFailedRecord(message.getMsgId(), message.getRoomId(), e.getMessage());
            ack.acknowledge();
        }
    }

    private HeavyAuditResult doHeavyAudit(RealtimeMessage message) {
        // 文本语义分类
        if (StringUtils.isNotBlank(message.getContent())) {
            NlpClassifyResult classifyResult = nlpClient.classify(message.getContent());
            if (classifyResult.getMaxRiskScore() > 0.7) {
                return HeavyAuditResult.violation("语义分类判定违规: " + classifyResult.getMaxRiskCategory());
            }
        }
        // 弹幕内嵌图片/表情包审核
        if (StringUtils.isNotBlank(message.getImageUrl())) {
            CvDetectResult cvResult = cvClient.detect(message.getImageUrl());
            if (cvResult.getPornScore() > 0.7 || cvResult.getViolenceScore() > 0.7) {
                return HeavyAuditResult.violation("图片检测判定违规");
            }
        }
        return HeavyAuditResult.pass();
    }

    private RealtimeAuditLog buildLog(RealtimeMessage message, HeavyAuditResult result) {
        RealtimeAuditLog logEntry = new RealtimeAuditLog();
        logEntry.setMsgId(message.getMsgId());
        logEntry.setRoomId(message.getRoomId());
        logEntry.setUserId(message.getUserId());
        logEntry.setViolation(result.isViolation());
        logEntry.setReason(result.getReason());
        logEntry.setAuditTime(new Date());
        return logEntry;
    }
}

/**
 * 违规内容实时拦截/下架服务
 *
 * 事后发现违规时需要执行的动作：
 * 1. 向房间内所有在线客户端下发"消息撤回"事件，前端收到后从聊天记录UI中移除
 * 2. 联动用户处罚（累计违规次数触发禁言/封禁）
 * 3. 记录处罚流水，便于申诉时追溯
 */
@Service
public class MessageRevokeService {

    private static final Logger log = LoggerFactory.getLogger(MessageRevokeService.class);

    @Autowired
    private MessageBroadcastService broadcastService;

    @Autowired
    private UserPunishmentService punishmentService;

    @Autowired
    private RealtimeAuditLogMapper auditLogMapper;

    @Transactional(rollbackFor = Exception.class)
    public void revokeAndPunish(RealtimeMessage message, String reason) {
        try {
            // 1. 下发撤回事件（幂等：客户端按msgId去重处理撤回指令，重复下发不会有副作用）
            RevokeEvent event = new RevokeEvent(message.getMsgId(), message.getRoomId(), reason);
            broadcastService.broadcastRevoke(event);

            // 2. 累计违规计数，触发阶梯式处罚（如3次禁言10分钟，5次禁言1天，10次永久封禁）
            int violationCount = punishmentService.incrementViolationCount(message.getUserId());
            PunishmentLevel level = punishmentService.resolvePunishmentLevel(violationCount);
            if (level != PunishmentLevel.NONE) {
                punishmentService.applyPunishment(message.getUserId(), level, reason);
                log.warn("用户违规触发处罚, userId={}, violationCount={}, level={}",
                    message.getUserId(), violationCount, level);
            }

            auditLogMapper.markRevoked(message.getMsgId(), new Date());
            log.info("违规消息已撤回并完成处罚联动, msgId={}, userId={}", message.getMsgId(), message.getUserId());
        } catch (Exception e) {
            // 撤回/处罚任一环节异常都要记录，避免"重度审核判定违规但未真正处置"的静默失败
            log.error("违规消息撤回或处罚执行失败, msgId={}, userId={}",
                message.getMsgId(), message.getUserId(), e);
            throw new BizException("REVOKE_FAILED", "违规内容处置失败，需人工介入");
        }
    }
}
```

#### 9.2.6 审核延迟优化策略

实时场景的架构设计几乎全部围绕"如何在保证安全性的前提下压缩延迟"展开，核心策略汇总如下：

| 优化策略 | 具体做法 | 收益 |
|---------|---------|------|
| 本地内存计算 | DFA敏感词树、URL黑名单、重复消息检测器全部常驻本地内存 | 消除网络IO延迟，单次判断可控制在1ms以内 |
| 词库/黑名单热更新 | 定时任务后台异步拉取最新数据，原子替换本地快照，不阻塞在线请求 | 规则更新不需要重启服务，且不影响读取性能 |
| 先放行后复核 | 轻量审核通过后立即广播，重度AI审核异步兜底 | 用户感知延迟仅取决于轻量审核耗时（通常个位数毫秒） |
| 决策短路 | 规则链命中确定性拦截后立即返回，不继续执行后续规则 | 减少平均处理耗时 |
| 异常兜底策略 | 本地组件异常时默认拦截（fail-close），远程重度审核异常时记录待补审（不阻断已放行消息） | 保证"宁可误杀不可漏放"的安全底线，同时不影响实时性 |
| 背压保护 | 重度审核队列积压超过阈值时，对非首次违规用户的消息临时降级为"更严格的轻量规则"直接同步拦截 | 防止下游AI服务过载雪崩，同时提升高风险用户的拦截时效 |
| 分级处罚替代逐条人审 | 重度审核发现的违规通过累计计数+阶梯处罚自动化处置，减少对人审资源的依赖 | 实时场景消息量远超人审吞吐能力，自动化处置是唯一可行路径 |

```java
/**
 * 审核规则配置实体：涵盖黑名单、白名单、正则规则、AI模型阈值四类可配置项

public class AuditRuleConfig implements Serializable {
    private String ruleGroupCode;
    private List<String> blacklist;      // 黑名单词汇/URL/ID等
    private List<String> whitelist;      // 白名单（豁免审核或降低风险等级）

    private Map<String, Double> aiModelThresholds; // 如 {"pornScore": 0.8, "violenceScore": 0.75}
    private int version;
    // getter/setter省略

/**
 * 审核规则配置管理服务
 *
 * 职责：
 * 1. 配置合法性校验（避免误配置导致规则失效或大面积误杀）
 * 2. 版本化保存，每次保存生成新版本而非覆盖，支持追溯和回滚
 * 3. 发布配置变更事件，驱动热更新机制
 */
@Service
public class AuditRuleConfigService {

    private static final Logger log = LoggerFactory.getLogger(AuditRuleConfigService.class);

    @Autowired
    private AuditRuleConfigVersionMapper versionMapper;

    @Autowired
    private ApplicationEventPublisher eventPublisher;

    @Autowired
    private ConfigCenterClient configCenterClient;

    /**
     * 提交新版本规则配置
     */
    @Transactional(rollbackFor = Exception.class)
    public int publishConfig(String ruleGroupCode, AuditRuleConfig config, String operator) {
        try {
            validateConfig(config);
        } catch (IllegalArgumentException e) {
            log.warn("规则配置校验失败, ruleGroupCode={}, operator={}, reason={}",
                ruleGroupCode, operator, e.getMessage());
            throw new BizException("CONFIG_INVALID", e.getMessage());
        }

        AuditRuleConfigVersion latest = versionMapper.selectLatestVersion(ruleGroupCode);
        int newVersion = (latest == null) ? 1 : latest.getVersion() + 1;

        AuditRuleConfigVersion versionRecord = new AuditRuleConfigVersion();
        versionRecord.setRuleGroupCode(ruleGroupCode);
        versionRecord.setVersion(newVersion);
        versionRecord.setConfigContent(JSON.toJSONString(config));
        versionRecord.setChangeType("UPDATE");
        versionRecord.setOperator(operator);
        versionRecord.setStatus(RuleConfigStatus.GRAY.getCode()); // 先灰度，不直接全量
        versionRecord.setCreateTime(new Date());

        try {
            versionMapper.insert(versionRecord);
        } catch (DuplicateKeyException e) {
            // 并发发布冲突（同一规则组被两个人同时提交），要求调用方重新拉取最新版本后重试
            log.warn("规则配置版本冲突，可能存在并发发布, ruleGroupCode={}", ruleGroupCode, e);
            throw new BizException("VERSION_CONFLICT", "配置已被他人更新，请刷新后重试");
        }

        // 推送到配置中心，由热更新机制感知变更（推送失败不影响DB记录，由轮询兜底）
        try {
            configCenterClient.publish(ruleGroupCode, JSON.toJSONString(config));
        } catch (Exception e) {
            log.error("配置中心推送失败, ruleGroupCode={}, version={}, 将由轮询机制在下个周期兜底同步",
                ruleGroupCode, newVersion, e);
        }

        eventPublisher.publishEvent(new RuleConfigChangedEvent(ruleGroupCode, newVersion));
        log.info("规则配置发布成功, ruleGroupCode={}, version={}, operator={}",
            ruleGroupCode, newVersion, operator);

        return newVersion;
    }

    /**
     * 灰度验证通过后，全量生效
     */
    @Transactional(rollbackFor = Exception.class)
    public void promoteToFull(String ruleGroupCode, int version) {
        int updated = versionMapper.updateStatus(ruleGroupCode, version,
            RuleConfigStatus.GRAY.getCode(), RuleConfigStatus.FULL.getCode());
        if (updated == 0) {
            throw new BizException("STATE_INVALID", "当前版本非灰度状态，无法全量发布");
        }
        log.info("规则配置全量生效, ruleGroupCode={}, version={}", ruleGroupCode, version);
    }

    /**
     * 一键回滚到指定历史版本
     */
    @Transactional(rollbackFor = Exception.class)
    public int rollback(String ruleGroupCode, int targetVersion, String operator) {
        AuditRuleConfigVersion target = versionMapper.selectByVersion(ruleGroupCode, targetVersion);
        if (target == null) {
            throw new BizException("VERSION_NOT_FOUND", "目标版本不存在");
        }
        AuditRuleConfig rollbackConfig = JSON.parseObject(target.getConfigContent(), AuditRuleConfig.class);

        // 回滚本质是发布一个内容等同于历史版本的新版本，保持版本号单调递增，便于审计追溯
        return publishConfig(ruleGroupCode, rollbackConfig, operator + "(回滚至v" + targetVersion + ")");
    }

    private void validateConfig(AuditRuleConfig config) {
        if (config.getAiModelThresholds() != null) {
            for (Map.Entry<String, Double> entry : config.getAiModelThresholds().entrySet()) {
                if (entry.getValue() < 0 || entry.getValue() > 1) {
                    throw new IllegalArgumentException("AI模型阈值必须在[0,1]区间: " + entry.getKey());
                }
            }
        }
        if (config.getRegexRules() != null) {
            for (RegexRuleItem item : config.getRegexRules()) {
                try {
                    Pattern.compile(item.getPattern());
                } catch (PatternSyntaxException e) {
                    throw new IllegalArgumentException("正则表达式语法错误: " + item.getPattern());
                }
            }
        }
    }
}
```

#### 9.3.4 规则热更新机制：不停服生效

```java
/**
 * 规则热更新监听器
 *
 * 双通道保证配置一定能生效：
 * 1. 配置中心推送（实时，秒级生效）
 * 2. 定时轮询兜底（防止推送通道故障导致配置僵死，最多延迟30秒）
 */
@Component
public class RuleHotReloadListener {

    private static final Logger log = LoggerFactory.getLogger(RuleHotReloadListener.class);

    // 使用volatile保证多线程可见性：规则引擎读取时始终拿到最新的完整快照，不会读到半更新状态
    private volatile Map<String, AuditRuleConfig> ruleConfigSnapshot = new ConcurrentHashMap<>();

    @Autowired
    private AuditRuleConfigVersionMapper versionMapper;

    @Autowired
    private ConfigCenterClient configCenterClient;

    @PostConstruct
    public void init() {
        loadAllFromDb();
        // 订阅配置中心推送通道
        configCenterClient.subscribe(this::onConfigPushed);
    }

    /**
     * 配置中心推送回调：单个规则组变更时只替换该规则组，不影响其他规则组的服务能力
     */
    private void onConfigPushed(String ruleGroupCode, String configJson) {
        try {
            AuditRuleConfig newConfig = JSON.parseObject(configJson, AuditRuleConfig.class);
            // Map本身是不可变替换：先构建新Map整体替换引用，避免读取方在遍历过程中遇到并发修改异常
            Map<String, AuditRuleConfig> newSnapshot = new ConcurrentHashMap<>(ruleConfigSnapshot);
            newSnapshot.put(ruleGroupCode, newConfig);
            this.ruleConfigSnapshot = newSnapshot;

            log.info("规则热更新生效（推送通道）, ruleGroupCode={}, version={}",
                ruleGroupCode, newConfig.getVersion());
        } catch (Exception e) {
            // 单次推送解析失败不影响当前生效的规则继续工作，只记录告警，等待下次轮询兜底纠正
            log.error("规则热更新解析失败（推送通道）, ruleGroupCode={}, rawConfig={}",
                ruleGroupCode, configJson, e);
        }
    }

    /**
     * 定时轮询兜底：每30秒全量比对一次DB中的最新生效版本，防止推送丢失导致配置长期不一致
     */
    @Scheduled(fixedDelay = 30_000)
    public void pollingReload() {
        try {
            loadAllFromDb();
        } catch (Exception e) {
            log.error("规则配置定时轮询刷新失败，继续沿用当前内存快照", e);
        }
    }

    private void loadAllFromDb() {
        List<AuditRuleConfigVersion> fullVersions = versionMapper.selectAllFullEffective();
        Map<String, AuditRuleConfig> newSnapshot = new ConcurrentHashMap<>();
        for (AuditRuleConfigVersion v : fullVersions) {
            try {
                AuditRuleConfig config = JSON.parseObject(v.getConfigContent(), AuditRuleConfig.class);
                config.setVersion(v.getVersion());
                newSnapshot.put(v.getRuleGroupCode(), config);
            } catch (Exception e) {
                log.error("规则配置反序列化失败，跳过该规则组本次刷新, ruleGroupCode={}",
                    v.getRuleGroupCode(), e);
            }
        }
        if (!newSnapshot.isEmpty()) {
            this.ruleConfigSnapshot = newSnapshot;
            log.debug("规则配置全量轮询刷新完成, ruleGroupCount={}", newSnapshot.size());
        }
    }

    public AuditRuleConfig getConfig(String ruleGroupCode) {
        AuditRuleConfig config = ruleConfigSnapshot.get(ruleGroupCode);
        if (config == null) {
            log.warn("规则组配置未找到，可能是新规则组尚未同步, ruleGroupCode={}", ruleGroupCode);
        }
        return config;
    }
}
```

```java
/**
 * 审核结果采样与人工标注服务
 *
 * 按比例从机审结果中抽样，交由专职标注团队给出Ground Truth，
 * 是效果度量体系能够成立的数据基础
 */
@Service
public class SampleLabelingService {

    private static final Logger log = LoggerFactory.getLogger(SampleLabelingService.class);

    @Autowired
    private AuditSampleLabelMapper sampleLabelMapper;

    private static final double SAMPLING_RATE = 0.05; // 5%抽样率，可按规则组差异化配置

    /**
     * 机审完成后按比例抽样入库，等待人工标注
     * 幂等：同一taskId只会被抽样一次（唯一索引兜底）
     */
    public void sampleIfNeeded(AuditTask task, RuleResult ruleResult) {
        if (ThreadLocalRandom.current().nextDouble() > SAMPLING_RATE) {
            return;
        }
        try {
            AuditSampleLabel sample = new AuditSampleLabel();
            sample.setTaskId(task.getTaskId());
            sample.setRuleGroupCode(task.getProcessCode());
            sample.setMachineDecision(ruleResult.getAction() == RuleAction.REJECT ? 2 : 1);
            sample.setLabelSource("SAMPLING");
            sample.setCreateTime(new Date());
            sampleLabelMapper.insert(sample);
        } catch (DuplicateKeyException e) {
            log.debug("样本已存在，跳过重复抽样, taskId={}", task.getTaskId());
        } catch (Exception e) {
            log.error("样本抽样入库失败, taskId={}", task.getTaskId(), e);
        }
    }

    /**
     * 标注团队提交人工标注结果
     */
    @Transactional(rollbackFor = Exception.class)
    public void submitLabel(Long taskId, int groundTruth, String labelSource) {
        int updated = sampleLabelMapper.updateGroundTruth(taskId, groundTruth, labelSource, new Date());
        if (updated == 0) {
            log.warn("标注提交失败，样本记录不存在, taskId={}", taskId);
            throw new BizException("SAMPLE_NOT_FOUND", "样本记录不存在");
        }
        log.info("样本标注完成, taskId={}, groundTruth={}, source={}", taskId, groundTruth, labelSource);
    }
}

/**
 * 审核准确率/召回率统计服务
 *
 * 基于混淆矩阵计算标准的Precision/Recall/F1指标：
 * - TP（True Positive）：机审判定违规，实际也违规
 * - FP（False Positive）：机审判定违规，实际合规（误杀）
 * - FN（False Negative）：机审判定通过，实际违规（漏放）
 * - TN（True Negative）：机审判定通过，实际也合规
 */
@Service
public class AuditMetricsService {

    private static final Logger log = LoggerFactory.getLogger(AuditMetricsService.class);

    @Autowired
    private AuditSampleLabelMapper sampleLabelMapper;

    @Autowired
    private AuditMetricsReportMapper metricsReportMapper;

    /**
     * 按规则组维度统计准确率/召回率，每日定时执行生成报表
     */
    @Scheduled(cron = "0 30 1 * * ?")
    public void generateDailyMetricsReport() {
        List<String> ruleGroupCodes = sampleLabelMapper.selectDistinctRuleGroups();
        for (String ruleGroupCode : ruleGroupCodes) {
            try {
                AuditMetrics metrics = computeMetrics(ruleGroupCode);
                metricsReportMapper.insert(buildReport(ruleGroupCode, metrics));
                log.info("规则组效果统计完成, ruleGroupCode={}, precision={}, recall={}, f1={}",
                    ruleGroupCode, metrics.getPrecision(), metrics.getRecall(), metrics.getF1Score());

                // 准确率或召回率跌破阈值时主动告警，提示策略团队介入排查
                if (metrics.getPrecision() < 0.85 || metrics.getRecall() < 0.85) {
                    log.warn("规则组效果指标异常告警, ruleGroupCode={}, precision={}, recall={}",
                        ruleGroupCode, metrics.getPrecision(), metrics.getRecall());
                    AlertNotifier.notifyMetricsAbnormal(ruleGroupCode, metrics);
                }
            } catch (Exception e) {
                // 单个规则组统计失败不应中断整体报表生成任务
                log.error("规则组效果统计失败, ruleGroupCode={}", ruleGroupCode, e);
            }
        }
    }

    private AuditMetrics computeMetrics(String ruleGroupCode) {
        List<AuditSampleLabel> labeledSamples = sampleLabelMapper.selectLabeledByRuleGroup(ruleGroupCode);

        long tp = 0, fp = 0, fn = 0, tn = 0;
        for (AuditSampleLabel sample : labeledSamples) {
            boolean machineReject = sample.getMachineDecision() == 2;
            boolean actualViolation = sample.getGroundTruth() != null && sample.getGroundTruth() == 2;

            if (machineReject && actualViolation) tp++;
            else if (machineReject && !actualViolation) fp++;
            else if (!machineReject && actualViolation) fn++;
            else tn++;
        }

        double precision = (tp + fp) == 0 ? 0 : (double) tp / (tp + fp);
        double recall = (tp + fn) == 0 ? 0 : (double) tp / (tp + fn);
        double f1 = (precision + recall) == 0 ? 0 : 2 * precision * recall / (precision + recall);

        AuditMetrics metrics = new AuditMetrics();
        metrics.setTruePositive(tp);
        metrics.setFalsePositive(fp);
        metrics.setFalseNegative(fn);
        metrics.setTrueNegative(tn);
        metrics.setPrecision(precision);
        metrics.setRecall(recall);
        metrics.setF1Score(f1);
        return metrics;
    }

    private AuditMetricsReport buildReport(String ruleGroupCode, AuditMetrics metrics) {
        AuditMetricsReport report = new AuditMetricsReport();
        report.setRuleGroupCode(ruleGroupCode);
        report.setStatDate(new Date());
        report.setTruePositive(metrics.getTruePositive());
        report.setFalsePositive(metrics.getFalsePositive());
        report.setFalseNegative(metrics.getFalseNegative());
        report.setTrueNegative(metrics.getTrueNegative());
        report.setPrecision(BigDecimal.valueOf(metrics.getPrecision()).setScale(4, RoundingMode.HALF_UP));
        report.setRecall(BigDecimal.valueOf(metrics.getRecall()).setScale(4, RoundingMode.HALF_UP));
        report.setF1Score(BigDecimal.valueOf(metrics.getF1Score()).setScale(4, RoundingMode.HALF_UP));
        return report;
    }
}
```

#### 9.3.6 误杀/漏放反馈闭环

统计出来的问题样本（误杀FP、漏放FN）如果不能回流到规则调优和模型训练环节，效果度量就只是"看个数字"而已。反馈闭环的核心是把这些样本系统化地收集起来，驱动下一轮规则迭代。

```java
/**
 * 误杀/漏放反馈闭环服务
 *
 * 样本来源：
 * 1. 误杀（FP）：用户申诉改判（对应9.1.6节的申诉复核结果）、人工标注样本中的FP
 * 2. 漏放（FN）：人工巡检发现、外部舆情反馈、人工标注样本中的FN
 *
 * 处理动作：
 * 1. 归因到具体触发的规则/模型维度，定位问题根因
 * 2. 高频误杀的规则自动降级告警，提示策略团队人工复核该规则
 * 3. 高置信度漏放样本回流至模型再训练数据集，供算法团队下一轮迭代使用
 */
@Service
public class FeedbackLoopService {

    private static final Logger log = LoggerFactory.getLogger(FeedbackLoopService.class);

    @Autowired
    private AuditFeedbackSampleMapper feedbackSampleMapper;

    @Autowired
    private AuditRuleConfigVersionMapper versionMapper;

    private static final int HIGH_FREQUENCY_FP_THRESHOLD = 20; // 单条规则单日误杀次数阈值

    /**
     * 用户申诉改判为"确实误杀"时，回流入误杀样本库
     */
    @Transactional(rollbackFor = Exception.class)
    public void recordFalsePositive(Long taskId, String ruleGroupCode, String hitDetail, String operator) {
        try {
            AuditFeedbackSample sample = new AuditFeedbackSample();
            sample.setTaskId(taskId);
            sample.setRuleGroupCode(ruleGroupCode);
            sample.setFeedbackType("FALSE_POSITIVE");
            sample.setHitDetail(hitDetail);
            sample.setOperator(operator);
            sample.setCreateTime(new Date());
            feedbackSampleMapper.insert(sample);

            long todayCount = feedbackSampleMapper.countTodayByTypeAndGroup("FALSE_POSITIVE", ruleGroupCode);
            if (todayCount >= HIGH_FREQUENCY_FP_THRESHOLD) {
                log.warn("规则组误杀高频告警, ruleGroupCode={}, todayCount={}, 建议人工复核该规则",
                    ruleGroupCode, todayCount);
                AlertNotifier.notifyHighFrequencyFalsePositive(ruleGroupCode, todayCount);
            }
        } catch (Exception e) {
            log.error("误杀样本回流失败, taskId={}, ruleGroupCode={}", taskId, ruleGroupCode, e);
            throw new BizException("FEEDBACK_RECORD_FAILED", "误杀样本记录失败");
        }
    }

    /**
     * 人工巡检/舆情反馈发现漏放内容时，回流入漏放样本库并驱动模型再训练数据集更新
     */
    @Transactional(rollbackFor = Exception.class)
    public void recordFalseNegative(Long taskId, String ruleGroupCode, String content,
                                     String violationType, String operator) {
        try {
            AuditFeedbackSample sample = new AuditFeedbackSample();
            sample.setTaskId(taskId);
            sample.setRuleGroupCode(ruleGroupCode);
            sample.setFeedbackType("FALSE_NEGATIVE");
            sample.setHitDetail(violationType);
            sample.setOperator(operator);
            sample.setCreateTime(new Date());
            feedbackSampleMapper.insert(sample);

            // 漏放样本直接进入模型再训练数据集队列，供算法团队下一轮迭代使用
            ModelRetrainDatasetProducer.send(new RetrainSample(content, violationType, "FALSE_NEGATIVE"));
            log.info("漏放样本已回流至模型再训练数据集, taskId={}, ruleGroupCode={}, violationType={}",
                taskId, ruleGroupCode, violationType);
        } catch (Exception e) {
            // 回流失败不能静默丢弃，否则同类违规会持续漏放，记录失败明细供定时任务补偿重试
            log.error("漏放样本回流失败, taskId={}, ruleGroupCode={}", taskId, ruleGroupCode, e);
            feedbackSampleMapper.insertRetryQueue(taskId, ruleGroupCode, content, violationType);
        }
    }

    /**
     * 定时生成反馈闭环处理报表：统计误杀/漏放样本的处理进度
     */
    @Scheduled(cron = "0 0 9 * * MON") // 每周一9点生成周报
    public void generateWeeklyFeedbackReport() {
        try {
            List<FeedbackSummary> summaries = feedbackSampleMapper.summarizeLastWeek();
            for (FeedbackSummary summary : summaries) {
                log.info("反馈闭环周报, ruleGroupCode={}, falsePositiveCount={}, falseNegativeCount={}, " +
                        "ruleAdjusted={}",
                    summary.getRuleGroupCode(), summary.getFalsePositiveCount(),
                    summary.getFalseNegativeCount(), summary.isRuleAdjusted());
            }
        } catch (Exception e) {
            log.error("反馈闭环周报生成失败", e);
        }
    }
}
```

## 十、全链路案例最佳实践总结

### 10.1 三个案例的适用边界

| 案例 | 适用场景 | 核心诉求 | 不适用场景 |
|------|---------|---------|-----------|
| UGC内容提交审核 | 评论、动态、商品图文、资质材料等非实时提交内容 | 审核尽可能全面准确，允许分钟级甚至更长延迟 | 强实时交互场景（会造成明显的体验卡顿） |
| 实时内容审核 | 直播弹幕、IM聊天、语音房发言 | 毫秒级响应，先放行后补审 | 对准确性要求极高、可以接受延迟的高风险内容（如资质证照） |
| 规则管理与效果度量 | 所有审核场景的规则运营与质量保障 | 规则可运营、效果可衡量、问题可闭环 | 一次性、不需要长期迭代维护的临时审核需求 |

### 10.2 新增的关键实现要点

1. **幂等设计贯穿全链路**：无论是业务方重复提交（内容指纹去重）、消息队列重复投递（Redis SETNX标记）、还是并发配置发布（唯一索引+版本号），幂等控制是保证系统正确性的底线要求，不能省略。
2. **异常处理遵循"安全优先"原则**：轻量审核组件异常时选择拦截而非放行（fail-close），机审不确定时转人审而非直接放行，这是内容安全领域区别于一般业务系统的重要设计取舍——宁可误杀增加人工复核成本，也不可放行导致合规风险。
3. **日志记录服务于可追溯性**：每个关键决策节点（机审判定、人审操作、申诉改判、规则变更、违规处罚）都应记录结构化日志，这既是问题排查的基础，也是效果度量和责任追溯的数据来源。
4. **实时与非实时场景的架构取舍不同**：非实时场景可以做完整的多级审核流水线追求准确率，实时场景必须做"轻量同步拦截+重度异步复核"的分层设计，两者不能用同一套架构简单应付了事。
5. **规则管理不是一次性配置，而是持续运营**：热更新机制解决"规则如何快速生效"的问题，效果度量解决"规则是否有效"的问题，反馈闭环解决"规则如何持续变好"的问题，三者缺一不可，共同构成规则治理的完整闭环。
