+# 消息通知中心系统架构设计
+
+## 一、系统概述
+
+消息通知中心是企业级统一消息推送平台，负责将业务消息通过多种通道（App Push、短信、站内信、邮件、WebSocket实时推送等）精准送达目标用户。系统基于多通道适配器架构，支持通道智能选择、证书生命周期管理、频率管控、模板化发送等核心能力。
+
+### 1.1 核心挑战
+
+消息推送面临以下核心技术挑战：
+
+第一，通道碎片化。移动端推送通道高度碎片化，Apple APNS、华为Push、小米Push、OPPO Push、VIVO Push、魅族Push各有不同的SDK和协议，同时还需要维护自建长连接通道作为兜底。每个通道的认证方式、消息格式、限流策略各不相同。
+
+第二，Token管理复杂。Push Token是设备唯一标识，存在环境区分（线上环境Token以特定前缀开头，测试环境Token以另一前缀开头）、Token失效（用户卸载重装后Token变更）、Token与App匹配校验等问题。错误的环境或App匹配会导致"无通道"推送失败。
+
+第三，证书过期风险。APNS证书有有效期，证书过期后iOS推送完全不可用，需要建立证书到期监控和自动预警机制。
+
+第四，送达率保障。不同通道的送达率差异大，自建通道依赖App前台在线状态，第三方通道依赖厂商通道可用性。需要设计通道选择策略和降级方案。
+
+### 1.2 设计目标
+
+系统设计目标包括：多通道统一接入，业务方只需调用统一API即可完成多通道推送；通道智能路由，根据设备类型、通道可用性、消息优先级自动选择最优通道；Token全生命周期管理，包括注册、更新、失效检测；证书自动监控预警；送达率可追踪，全链路Trace追踪每条消息的推送状态。
+

+
+## 二、整体架构
+
+### 2.1 架构分层
+
+系统采用五层架构设计：
+
+```
+┌─────────────────────────────────────────────────────┐
+│                    业务接入层                         │
+│    统一推送API │ 批量推送 │ 模板管理 │ 频率管控        │
+├─────────────────────────────────────────────────────┤
+│                    路由决策层                         │
+│    通道选择 │ 优先级排序 │ 降级策略 │ A/B测试          │
+├─────────────────────────────────────────────────────┤
+│                    通道适配层                         │
+│  APNS │ 华为Push │ 小米Push │ OPPO │ VIVO │ 自建通道   │
+├─────────────────────────────────────────────────────┤
+│                    数据管理层                         │
+│  Token管理 │ 证书管理 │ 推送记录 │ 设备状态            │
+├─────────────────────────────────────────────────────┤
+│                    基础设施层                         │
+│  消息队列 │ 缓存集群 │ 监控告警 │ 配置中心             │
+└─────────────────────────────────────────────────────┘
+```
+
+业务接入层提供统一的推送API，业务方通过SDK或HTTP接口提交推送请求，系统封装了通道差异，业务方无需关心底层通道选择逻辑。路由决策层是核心，根据设备类型、Token有效性、通道可用性、消息优先级等因素，决定使用哪个通道发送。通道适配层将统一消息格式转换为各厂商特定的协议格式。数据管理层负责Token存储、证书管理、推送记录持久化。基础设施层提供消息队列削峰、缓存加速、监控告警等基础能力。
+
+### 2.2 推送流程
+
+完整的推送流程如下：业务方调用统一推送API提交推送请求，请求包含目标用户ID（或Push Token）、消息标题、消息内容、业务类型、优先级等参数。系统接收到请求后，首先进行频率管控检查，如果用户在该周期内已接收过多消息则进行限流或合并。然后查询用户的Push Token和设备信息，根据设备类型选择合适的推送通道。消息通过消息队列异步处理，通道适配器将消息转换为对应通道的协议格式并调用厂商API。推送结果（成功/失败/无通道）记录到推送记录表，支持通过Push Token或消息ID查询推送链路。

+## 三、Token管理系统
+
+### 3.1 Token模型设计
+
+Push Token是设备在推送系统中的唯一标识，其设计参考了实际推送平台的Token管理方案。Token具有以下特性：环境区分，不同环境使用不同前缀标识，线上环境和测试环境的Token互不通用；App绑定，每个Token绑定到特定的App，不同App的Token不能混用；有效期管理，Token可能因用户卸载重装、设备重置等原因失效。
+
+```java
+/**
+ * Push Token实体
+ * 存储设备推送令牌及其关联信息
+ */
+public class PushToken {
+    /** Token唯一标识 */
+    private String token;
+    
+    /** Token前缀，区分环境：线上环境使用特定前缀，测试环境使用另一前缀 */
+    private String envPrefix;
+    
+    /** App名称，Token与App必须匹配 */
+    private String appName;
+    
+    /** 用户ID */
+    private String userId;
+    
+    /** 设备ID */
+    private String deviceId;
+    
+    /** 设备类型：iOS/Android */
+    private String deviceType;
+    
+    /** 设备品牌：华为/小米/OPPO/VIVO/魅族/三星等 */
+    private String deviceBrand;
+    
+    /** 第三方通道Token（厂商通道） */
+    private String thirdPartyToken;
+    
+    /** 自建通道连接ID */
+    private String connectionId;
+    
+    /** 自建通道IP地址 */
+    private String clientIp;
+    
+    /** Token状态：ACTIVE/INACTIVE/INVALID */
+    private TokenStatus status;
+    
+    /** Token注册时间 */
+    private Long registerTime;
+    
+    /** Token最后更新时间 */
+    private Long updateTime;
+    
+    /** Token过期时间 */
+    private Long expireTime;
+    
+    public enum TokenStatus {
+        ACTIVE,      // 活跃
+        INACTIVE,    // 未激活（App未打开）
+        INVALID      // 已失效（卸载或重置）
+    }
+}
+```
+
+### 3.2 Token注册与绑定
+
+设备首次打开App时，客户端SDK向推送服务注册Token。注册流程包括：客户端获取厂商Push Token（如华为Push Token、小米Push Token等），然后调用推送服务的注册接口，将厂商Token、设备信息、App信息一起上报。推送服务生成内部Push Token，建立Token与设备、App、用户的绑定关系。
+
+```java
+/**
+ * Token注册服务
+ * 处理设备Token的注册、绑定和更新
+ * 
+ * 使用策略模式：不同设备品牌使用不同的Token注册策略
+ */
+@Service
+public class TokenRegisterService {
+    
+    @Resource
+    private PushTokenRepository tokenRepository;
+    
+    @Resource
+    private DeviceChannelManager channelManager;
+    
+    @Resource
+    private RedisTemplate<String, PushToken> redisTemplate;
+    
+    /**
+     * 注册Push Token
+     * 
+     * 算法说明：
+     * 1. 生成内部Token（环境前缀 + UUID）
+     * 2. 查询厂商通道Token，建立绑定关系
+     * 3. 检查是否已存在同一设备的Token，如存在则更新
+     * 4. 写入Redis缓存和MySQL持久化
+     * 
+     * @param request 注册请求
+     * @return 生成的Push Token
+     */
+    public String registerToken(TokenRegisterRequest request) {
+        // 1. 环境前缀校验
+        String envPrefix = determineEnvPrefix(request.getEnv());
+        if (envPrefix == null) {
+            throw new BusinessException("Invalid environment");
+        }
+        
+        // 2. 生成Push Token
+        String pushToken = generatePushToken(envPrefix);
+        
+        // 3. 检查同一设备是否已有Token
+        PushToken existingToken = tokenRepository.findByDeviceIdAndAppName(
+            request.getDeviceId(), request.getAppName());
+        
+        PushToken token;
+        if (existingToken != null) {
+            // 已存在Token，执行更新（设备重装场景）
+            token = existingToken;
+            token.setThirdPartyToken(request.getThirdPartyToken());
+            token.setStatus(TokenStatus.ACTIVE);
+            token.setUpdateTime(System.currentTimeMillis());
+        } else {
+            // 新注册
+            token = new PushToken();
+            token.setToken(pushToken);
+            token.setEnvPrefix(envPrefix);
+            token.setAppName(request.getAppName());
+            token.setUserId(request.getUserId());
+            token.setDeviceId(request.getDeviceId());
+            token.setDeviceType(request.getDeviceType());
+            token.setDeviceBrand(request.getDeviceBrand());
+            token.setThirdPartyToken(request.getThirdPartyToken());
+            token.setStatus(TokenStatus.ACTIVE);
+            token.setRegisterTime(System.currentTimeMillis());
+            token.setUpdateTime(System.currentTimeMillis());
+        }
+        
+        // 4. 写入存储
+        tokenRepository.save(token);
+        
+        // 5. 更新Redis缓存，Key格式：token:{pushToken} -> PushToken
+        redisTemplate.opsForValue().set(
+            "token:" + pushToken, token, 7, TimeUnit.DAYS);
+        
+        // 6. 注册设备到通道管理器
+        channelManager.registerDevice(token);
+        
+        return pushToken;
+    }
+    
+    /**
+     * 生成Push Token
+     * 算法：环境前缀 + Base62编码的UUID
+     * 线上环境前缀和测试环境前缀不同，避免跨环境误用
+     */
+    private String generatePushToken(String envPrefix) {
+        String uuid = UUID.randomUUID().toString().replace("-", "");
+        String encoded = Base62.encode(uuid.getBytes());
+        return envPrefix + encoded;
+    }
+    
+    /**
+     * 确定环境前缀
+     * 线上环境和测试环境使用不同前缀，防止跨环境Token误用
+     */
+    private String determineEnvPrefix(String env) {
+        if ("production".equals(env)) {
+            return "dpsh";  // 线上环境前缀
+        } else if ("test".equals(env)) {
+            return "dpst";  // 测试环境前缀
+        }
+        return null;
+    }
+    
+    /**
+     * Token失效处理
+     * 当厂商通道返回Token无效时，标记Token为INVALID
+     * 
+     * @param pushToken 失效的Token
+     */
+    public void invalidateToken(String pushToken) {
+        PushToken token = tokenRepository.findByToken(pushToken);
+        if (token != null) {
+            token.setStatus(TokenStatus.INVALID);
+            token.setUpdateTime(System.currentTimeMillis());
+            tokenRepository.save(token);
+            
+            // 从缓存中删除
+            redisTemplate.delete("token:" + pushToken);
+            
+            // 通道管理器注销设备
+            channelManager.unregisterDevice(token);
+        }
+    }
+}
+```

+### 3.3 Token有效性检测
+
+Token可能因用户卸载App、设备重置等原因失效。系统通过以下机制检测Token有效性：厂商通道推送返回无效Token错误时，自动标记Token失效；定期批量检测，向厂商API查询Token状态；自建通道心跳检测，超时未心跳的Token标记为INACTIVE。
+
+```java
+/**
+ * Token健康检测服务
+ * 定期检测Token有效性，清理无效Token
+ * 
+ * 使用定时任务+批量检测模式，避免频繁单条查询
+ */
+@Service
+public class TokenHealthCheckService {
+    
+    @Resource
+    private PushTokenRepository tokenRepository;
+    
+    @Resource
+    private List<ChannelAdapter> channelAdapters;
+    
+    /**
+     * 定期健康检测
+     * 每6小时执行一次，检测活跃Token的有效性
+     * 
+     * 算法说明：
+     * 1. 分批查询活跃Token（每批500条）
+     * 2. 按通道分组，批量调用厂商API检测
+     * 3. 无效Token标记为INVALID
+     * 4. 统计检测结果，生成健康报告
+     */
+    @Scheduled(cron = "0 0 0/6 * * ?")
+    public void healthCheck() {
+        int batchSize = 500;
+        int offset = 0;
+        
+        while (true) {
+            List<PushToken> tokens = tokenRepository.findActiveTokens(offset, batchSize);
+            if (tokens.isEmpty()) {
+                break;
+            }
+            
+            // 按通道分组
+            Map<String, List<PushToken>> channelGroups = tokens.stream()
+                .collect(Collectors.groupingBy(PushToken::getDeviceBrand));
+            
+            for (Map.Entry<String, List<PushToken>> entry : channelGroups.entrySet()) {
+                String brand = entry.getKey();
+                List<PushToken> brandTokens = entry.getValue();
+                
+                ChannelAdapter adapter = findAdapter(brand);
+                if (adapter != null) {
+                    // 批量检测Token有效性
+                    List<String> validTokens = adapter.batchCheckToken(
+                        brandTokens.stream()
+                            .map(PushToken::getThirdPartyToken)
+                            .collect(Collectors.toList())
+                    );
+                    
+                    // 标记无效Token
+                    Set<String> validSet = new HashSet<>(validTokens);
+                    for (PushToken token : brandTokens) {
+                        if (!validSet.contains(token.getThirdPartyToken())) {
+                            token.setStatus(TokenStatus.INVALID);
+                            token.setUpdateTime(System.currentTimeMillis());
+                        }
+                    }
+                    
+                    tokenRepository.saveAll(brandTokens);
+                }
+            }
+            
+            offset += batchSize;
+        }
+    }
+}
+```

+## 四、多通道适配器架构
+
+### 4.1 通道适配器设计
+
+系统使用策略模式+工厂模式实现多通道适配。每个推送通道实现统一的ChannelAdapter接口，通道选择逻辑封装在工厂中。这种设计的好处是新增通道时只需实现接口并注册到工厂，不影响现有代码，符合开闭原则。
+
+```java
+/**
+ * 通道适配器接口
+ * 定义统一的推送协议，各厂商通道实现此接口
+ * 
+ * 设计模式：策略模式
+ * 每个通道是一个策略，通道选择器根据设备信息选择策略
+ */
+public interface ChannelAdapter {
+    
+    /**
+     * 获取通道类型
+     */
+    String getChannelType();
+    
+    /**
+     * 获取支持的设备品牌
+     */
+    List<String> getSupportedBrands();
+    
+    /**
+     * 发送推送消息
+     * 
+     * @param message 推送消息
+     * @param token 设备Token
+     * @return 推送结果
+     */
+    PushResult push(PushMessage message, PushToken token);
+    
+    /**
+     * 批量发送推送消息
+     */
+    List<PushResult> batchPush(List<PushMessage> messages, List<PushToken> tokens);
+    
+    /**
+     * 批量检测Token有效性
+     */
+    List<String> batchCheckToken(List<String> thirdPartyTokens);
+    
+    /**
+     * 检查证书状态
+     */
+    CertificateStatus checkCertificate();
+    
+    /**
+     * 通道是否可用
+     */
+    boolean isAvailable();
+}
+```
+
+### 4.2 APNS通道适配器
+
+Apple APNS通道是iOS设备的核心推送通道。APNS使用Token-based认证（JWT），需要定期更新证书。APNS适配器维护与APNS服务器的HTTP/2长连接，支持批量推送。
+
+```java
+/**
+ * APNS通道适配器
+ * 负责iOS设备的推送
+ * 
+ * 技术要点：
+ * 1. 使用HTTP/2协议与APNS通信
+ * 2. Token-based认证（JWT），需要定期刷新
+ * 3. 证书过期会导致所有iOS推送失败
+ * 4. 支持静默推送（content-available）
+ */
+@Component
+public class ApnsChannelAdapter implements ChannelAdapter {
+    
+    private ApnsClient<PushNotificationResponse> apnsClient;
+    
+    private String teamId;
+    private String keyId;
+    private PrivateKey privateKey;
+    private volatile String jwtToken;
+    private volatile long jwtTokenExpireTime;
+    
+    @Resource
+    private CertificateMonitor certificateMonitor;
+    
+    /**
+     * 初始化APNS客户端
+     * 使用TLS双向认证建立HTTP/2连接
+     */
+    @PostConstruct
+    public void init() throws Exception {
+        // 加载APNS证书私钥
+        privateKey = loadPrivateKey("apns_auth_key.p8");
+        
+        // 构建APNS客户端，连接APNS生产环境
+        apnsClient = new ApnsClientBuilder<PushNotificationResponse>()
+            .setApnsServer(ApnsClientBuilder.PRODUCTION_APNS_HOST)
+            .setConnectionTimeout(Duration.ofSeconds(10))
+            .setIdlePingInterval(Duration.ofSeconds(30))
+            .setConcurrentConnections(10)
+            .build();
+        
+        // 初始生成JWT Token
+        refreshJwtToken();
+        
+        // 注册证书监控
+        certificateMonitor.register("APNS", this::checkCertificate);
+    }
+    
+    @Override
+    public String getChannelType() {
+        return "APNS";
+    }
+    
+    @Override
+    public List<String> getSupportedBrands() {
+        return Collections.singletonList("Apple");
+    }
+    
+    /**
+     * APNS推送
+     * 
+     * 算法说明：
+     * 1. 检查JWT Token是否过期，过期则刷新
+     * 2. 构建APNS推送Payload（aps字典）
+     * 3. 设置推送优先级（10=立即推送，5=省电模式）
+     * 4. 发送推送，处理响应
+     * 5. 如果Token无效，返回INVALID_TOKEN状态
+     */
+    @Override
+    public PushResult push(PushMessage message, PushToken token) {
+        try {
+            // 检查JWT Token
+            if (System.currentTimeMillis() >= jwtTokenExpireTime) {
+                refreshJwtToken();
+            }
+            
+            // 构建APNS Payload
+            SimpleApnsPushNotification notification = buildNotification(message, token);
+            
+            // 发送推送
+            final PushNotificationResponse<PushNotificationResponse> response = 
+                apnsClient.sendNotification(notification).get();
+            
+            if (response.isAccepted()) {
+                return PushResult.success(token.getToken(), getChannelType());
+            } else {
+                // 处理APNS拒绝
+                String rejectionReason = response.getRejectionReason();
+                if ("BadDeviceToken".equals(rejectionReason) || 
+                    "Unregistered".equals(rejectionReason)) {
+                    // Token无效，需要标记失效
+                    return PushResult.invalidToken(token.getToken());
+                }
+                return PushResult.fail(token.getToken(), rejectionReason);
+            }
+        } catch (Exception e) {
+            log.error("APNS push failed, token={}", token.getToken(), e);
+            return PushResult.fail(token.getToken(), e.getMessage());
+        }
+    }
+    
+    /**
+     * 构建APNS推送通知
+     * 
+     * 关键参数说明：
+     * - alert: 通知内容（标题+正文）
+     * - badge: App图标角标数
+     * - sound: 通知铃声
+     * - content-available: 1表示静默推送（后台唤醒）
+     * - mutable-content: 1表示支持Notification Service Extension
+     * - priority: 10=立即推送，5=省电模式延迟推送
+     */
+    private SimpleApnsPushNotification buildNotification(PushMessage message, PushToken token) {
+        ApnsPayloadBuilder payloadBuilder = new ApnsPayloadBuilder();
+        payloadBuilder.setAlertTitle(message.getTitle());
+        payloadBuilder.setAlertBody(message.getContent());
+        
+        // 角标数
+        if (message.getBadge() != null) {
+            payloadBuilder.setBadgeNumber(message.getBadge());
+        }
+        
+        // 通知铃声
+        payloadBuilder.setSound("default");
+        
+        // 业务自定义数据
+        if (message.getExtraData() != null) {
+            for (Map.Entry<String, String> entry : message.getExtraData().entrySet()) {
+                payloadBuilder.addCustomProperty(entry.getKey(), entry.getValue());
+            }
+        }
+        
+        // 静默推送标志
+        if (message.isSilent()) {
+            payloadBuilder.setContentAvailable(true);
+        } else {
+            payloadBuilder.setMutableContent(true);
+        }
+        
+        // 推送优先级
+        DeliveryPriority priority = message.isHighPriority() 
+            ? DeliveryPriority.IMMEDIATE : DeliveryPriority.CONSERVE_POWER;
+        
+        String payload = payloadBuilder.buildWithDefaultImage();
+        
+        return new SimpleApnsPushNotification(
+            token.getThirdPartyToken(),  // APNS Token
+            message.getBundleId(),        // App Bundle ID
+            payload,
+            null,                          // 过期时间
+            priority,
+            PushType.ALERT
+        );
+    }
+    
+    /**
+     * 刷新JWT Token
+     * APNS JWT Token有效期最长1小时，提前5分钟刷新
+     */
+    private synchronized void refreshJwtToken() {
+        long now = System.currentTimeMillis();
+        long expireAt = now + 55 * 60 * 1000;  // 55分钟后过期
+        
+        String jwt = Jwts.builder()
+            .setHeaderParam("kid", keyId)
+            .setIssuer(teamId)
+            .setIssuedAt(new Date(now))
+            .setExpiration(new Date(expireAt))
+            .signWith(privateKey, SignatureAlgorithm.ES256)
+            .compact();
+        
+        this.jwtToken = jwt;
+        this.jwtTokenExpireTime = expireAt;
+    }
+    
+    /**
+     * 检查证书状态
+     * APNS认证密钥文件有有效期，需要定期检查
+     */
+    @Override
+    public CertificateStatus checkCertificate() {
+        File keyFile = new File("apns_auth_key.p8");
+        if (!keyFile.exists()) {
+            return CertificateStatus.missing("APNS auth key file not found");
+        }
+        
+        // 检查密钥文件最后修改时间
+        long lastModified = keyFile.lastModified();
+        long age = System.currentTimeMillis() - lastModified;
+        
+        // APNS密钥建议每年更新
+        if (age > 365L * 24 * 60 * 60 * 1000) {
+            return CertificateStatus.expiringSoon(
+                "APNS auth key is older than 1 year, please update");
+        }
+        
+        return CertificateStatus.ok();
+    }
+    
+    @Override
+    public boolean isAvailable() {
+        return apnsClient != null && jwtToken != null;
+    }
+}

+### 4.4 自建通道适配器
+
+自建通道是基于WebSocket长连接实现的推送通道，作为厂商通道的补充。当设备无法使用厂商通道时（如三星等非大厂设备，或App在前台时），使用自建通道推送。
+
+```java
+/**
+ * 自建长连接通道适配器
+ * 
+ * 技术要点：
+ * 1. 基于WebSocket长连接，App前台时建立连接
+ * 2. 心跳保活：30秒一次心跳
+ * 3. 连接超时：90秒未心跳则断开
+ * 4. 仅App前台可用，后台无法接收
+ * 5. 作为厂商通道的补充和降级方案
+ */
+@Component
+public class SelfBuiltChannelAdapter implements ChannelAdapter {
+    
+    @Resource
+    private WebSocketSessionManager sessionManager;
+    
+    @Override
+    public String getChannelType() {
+        return "SELF_BUILT";
+    }
+    
+    @Override
+    public List<String> getSupportedBrands() {
+        // 支持所有品牌
+        return Collections.singletonList("*");
+    }
+    
+    /**
+     * 自建通道推送
+     * 
+     * 算法说明：
+     * 1. 通过connectionId查找WebSocket连接
+     * 2. 检查连接是否活跃
+     * 3. 发送推送消息到WebSocket
+     * 4. 等待ACK确认
+     */
+    @Override
+    public PushResult push(PushMessage message, PushToken token) {
+        // 检查设备是否有自建通道连接
+        if (StringUtils.isBlank(token.getConnectionId()) 
+            || StringUtils.isBlank(token.getClientIp())) {
+            // 无自建通道连接（App未打开）
+            return PushResult.noChannel(token.getToken());
+        }
+        
+        WebSocketSession session = sessionManager.getSession(token.getConnectionId());
+        if (session == null || !session.isOpen()) {
+            // 连接已断开
+            return PushResult.noChannel(token.getToken());
+        }
+        
+        try {
+            // 构建推送消息
+            JSONObject pushData = new JSONObject();
+            pushData.put("type", "push");
+            pushData.put("messageId", message.getMessageId());
+            pushData.put("title", message.getTitle());
+            pushData.put("content", message.getContent());
+            pushData.put("timestamp", System.currentTimeMillis());
+            
+            if (message.getExtraData() != null) {
+                pushData.put("extra", message.getExtraData());
+            }
+            
+            // 发送WebSocket消息
+            session.sendMessage(new TextMessage(pushData.toJSONString()));
+            
+            return PushResult.success(token.getToken(), getChannelType());
+        } catch (Exception e) {
+            log.error("Self-built channel push failed", e);
+            return PushResult.fail(token.getToken(), e.getMessage());
+        }
+    }
+    
+    @Override
+    public boolean isAvailable() {
+        return true;  // 自建通道始终可用
+    }
+}

+## 五、通道选择与路由
+
+### 5.1 通道选择策略
+
+通道选择是推送系统的核心决策逻辑。系统根据设备品牌、Token有效性、通道可用性等因素，选择最优推送通道。通道选择的优先级为：厂商通道优先（送达率高，支持后台推送）> 自建通道（仅前台可用）> 无通道（消息进入待推送队列，App打开后补推）。
+
+```java
+/**
+ * 通道选择器
+ * 根据设备信息和通道状态选择最优推送通道
+ * 
+ * 设计模式：责任链模式
+ * 通道选择按优先级链式执行，第一个可用的通道即为最终选择
+ */
+@Service
+public class ChannelSelector {
+    
+    @Resource
+    private List<ChannelAdapter> channelAdapters;
+    
+    @Resource
+    private SelfBuiltChannelAdapter selfBuiltChannelAdapter;
+    
+    /**
+     * 通道优先级映射
+     * 大厂设备（华为/小米/OPPO/VIVO/魅族/Apple）使用厂商通道
+     * 非大厂设备（三星等）使用自建通道
+     */
+    private static final Map<String, String> BRAND_CHANNEL_MAP = new HashMap<>();
+    
+    static {
+        BRAND_CHANNEL_MAP.put("Apple", "APNS");
+        BRAND_CHANNEL_MAP.put("HUAWEI", "HUAWEI");
+        BRAND_CHANNEL_MAP.put("Xiaomi", "XIAOMI");
+        BRAND_CHANNEL_MAP.put("OPPO", "OPPO");
+        BRAND_CHANNEL_MAP.put("VIVO", "VIVO");
+        BRAND_CHANNEL_MAP.put("Meizu", "MEIZU");
+    }
+    
+    /**
+     * 大厂设备列表
+     * 大厂设备通常有厂商Push通道
+     * 非大厂设备（三星、锤子等）需要依赖自建通道
+     */
+    private static final Set<String> MAJOR_BRANDS = new HashSet<>(Arrays.asList(
+        "Apple", "HUAWEI", "Xiaomi", "OPPO", "VIVO", "Meizu"
+    ));
+    
+    /**
+     * 选择推送通道
+     * 
+     * 算法说明：
+     * 1. 如果是大厂设备且厂商Token有效，选择厂商通道
+     * 2. 如果自建通道可用（App前台在线），选择自建通道
+     * 3. 如果以上都不可用，返回无通道状态
+     * 4. 无通道消息进入待推送队列，App打开后补推
+     * 
+     * @param token 设备Token信息
+     * @return 选中的通道适配器，或null表示无可用通道
+     */
+    public ChannelAdapter selectChannel(PushToken token) {
+        // 1. 大厂设备优先使用厂商通道
+        if (MAJOR_BRANDS.contains(token.getDeviceBrand())) {
+            String channelType = BRAND_CHANNEL_MAP.get(token.getDeviceBrand());
+            ChannelAdapter adapter = findAdapter(channelType);
+            
+            if (adapter != null && adapter.isAvailable()) {
+                // 检查厂商Token是否有效
+                if (StringUtils.isNotBlank(token.getThirdPartyToken())) {
+                    return adapter;
+                }
+            }
+        }
+        
+        // 2. 降级到自建通道
+        if (StringUtils.isNotBlank(token.getConnectionId()) 
+            && StringUtils.isNotBlank(token.getClientIp())) {
+            return selfBuiltChannelAdapter;
+        }
+        
+        // 3. 无可用通道
+        // 可能原因：
+        // a. 非大厂设备且App未打开（无自建通道）
+        // b. 大厂设备但厂商Token无效（绑定失败）
+        // c. Token已失效（用户卸载重装）
+        return null;
+    }
+    
+    /**
+     * 通道降级策略
+     * 当首选通道推送失败时，尝试降级到其他通道
+     * 
+     * @param token 设备Token
+     * @param failedChannel 失败的通道
+     * @return 降级通道
+     */
+    public ChannelAdapter fallbackChannel(PushToken token, String failedChannel) {
+        // 厂商通道失败，降级到自建通道
+        if (!"SELF_BUILT".equals(failedChannel)) {
+            if (StringUtils.isNotBlank(token.getConnectionId())) {
+                return selfBuiltChannelAdapter;
+            }
+        }
+        return null;
+    }
+    
+    private ChannelAdapter findAdapter(String channelType) {
+        return channelAdapters.stream()
+            .filter(a -> a.getChannelType().equals(channelType))
+            .findFirst()
+            .orElse(null);
+    }
+}
+```

+### 5.2 无通道消息处理
+
+当设备没有可用推送通道时（非大厂设备且App未打开，或Token已失效），消息进入"无通道"状态。系统将这类消息暂存在待推送队列中，设置消息有效期（默认24小时）。当App重新打开并建立自建通道连接时，系统补推暂存消息。
+
+```java
+/**
+ * 无通道消息处理器
+ * 处理无可用通道的推送消息
+ * 
+ * 算法说明：
+ * 1. 无通道消息写入Redis有序集合，Score为过期时间戳
+ * 2. 客户端建立自建通道连接时，触发补推
+ * 3. 定时清理过期消息
+ */
+@Service
+public class NoChannelMessageHandler {
+    
+    @Resource
+    private RedisTemplate<String, String> redisTemplate;
+    
+    /** 无通道消息队列Key前缀 */
+    private static final String PENDING_QUEUE_PREFIX = "pending:push:";
+    
+    /** 消息默认有效期：24小时 */
+    private static final long DEFAULT_EXPIRE = 24 * 60 * 60 * 1000;
+    
+    /**
+     * 暂存无通道消息
+     */
+    public void pendingMessage(String pushToken, PushMessage message) {
+        String queueKey = PENDING_QUEUE_PREFIX + pushToken;
+        long expireScore = System.currentTimeMillis() + DEFAULT_EXPIRE;
+        
+        // 使用ZSet存储，Score为过期时间
+        redisTemplate.opsForZSet().add(
+            queueKey, JSON.toJSONString(message), expireScore);
+        
+        // 设置队列过期时间
+        redisTemplate.expire(queueKey, DEFAULT_EXPIRE + 60000, TimeUnit.MILLISECONDS);
+    }
+    
+    /**
+     * 补推待推送消息
+     * 当设备建立自建通道连接时调用
+     * 
+     * @param token 设备Token
+     * @param channelAdapter 自建通道适配器
+     * @return 补推的消息数量
+     */
+    public int flushPendingMessages(PushToken token, ChannelAdapter channelAdapter) {
+        String queueKey = PENDING_QUEUE_PREFIX + token.getToken();
+        
+        // 获取未过期的待推送消息
+        long now = System.currentTimeMillis();
+        Set<String> messages = redisTemplate.opsForZSet()
+            .rangeByScore(queueKey, 0, now);
+        
+        if (messages == null || messages.isEmpty()) {
+            return 0;
+        }
+        
+        int count = 0;
+        for (String msgJson : messages) {
+            PushMessage message = JSON.parseObject(msgJson, PushMessage.class);
+            PushResult result = channelAdapter.push(message, token);
+            if (result.isSuccess()) {
+                count++;
+                redisTemplate.opsForZSet().remove(queueKey, msgJson);
+            }
+        }
+        
+        return count;
+    }
+    
+    /**
+     * 定时清理过期的无通道消息
+     */
+    @Scheduled(cron = "0 0/30 * * * ?")
+    public void cleanExpiredMessages() {
+        // 扫描所有待推送队列，删除过期消息
+        Set<String> keys = redisTemplate.keys(PENDING_QUEUE_PREFIX + "*");
+        if (keys != null) {
+            for (String key : keys) {
+                redisTemplate.opsForZSet().removeRangeByScore(key, 0, System.currentTimeMillis());
+            }
+        }
+    }
+}
+```

+## 六、证书监控与管理
+
+### 6.1 证书生命周期管理
+
+APNS证书和各厂商通道的认证密钥都有有效期。证书过期会导致对应通道完全不可用，严重影响推送送达率。系统通过证书监控服务，提前预警证书过期，确保运维团队有足够时间更新证书。
+
+```java
+/**
+ * 证书监控服务
+ * 监控所有推送通道的证书状态，提前预警过期
+ * 
+ * 设计模式：观察者模式
+ * 各通道适配器注册为被观察者，证书状态变化时通知观察者
+ */
+@Service
+public class CertificateMonitor {
+    
+    private final Map<String, Supplier<CertificateStatus>> monitors = new ConcurrentHashMap<>();
+    
+    @Resource
+    private NotificationService notificationService;
+    
+    /**
+     * 注册证书监控
+     * 
+     * @param channelType 通道类型
+     * @param checker 证书状态检查函数
+     */
+    public void register(String channelType, Supplier<CertificateStatus> checker) {
+        monitors.put(channelType, checker);
+    }
+    
+    /**
+     * 定时检查所有证书状态
+     * 每小时执行一次
+     */
+    @Scheduled(fixedRate = 3600000)
+    public void checkAllCertificates() {
+        for (Map.Entry<String, Supplier<CertificateStatus>> entry : monitors.entrySet()) {
+            String channelType = entry.getKey();
+            try {
+                CertificateStatus status = entry.getValue().get();
+                
+                if (!status.isOk()) {
+                    // 证书异常，发送告警
+                    String alertMessage = String.format(
+                        "推送通道[%s]证书异常: %s", channelType, status.getMessage());
+                    
+                    notificationService.sendAlert("PUSH_CERT_ALERT", alertMessage);
+                    
+                    log.warn("Certificate issue detected: channel={}, status={}", 
+                        channelType, status);
+                }
+            } catch (Exception e) {
+                log.error("Certificate check failed: channel={}", channelType, e);
+            }
+        }
+    }
+    
+    /**
+     * 获取所有通道证书状态
+     */
+    public Map<String, CertificateStatus> getAllStatus() {
+        Map<String, CertificateStatus> result = new HashMap<>();
+        for (Map.Entry<String, Supplier<CertificateStatus>> entry : monitors.entrySet()) {
+            try {
+                result.put(entry.getKey(), entry.getValue().get());
+            } catch (Exception e) {
+                result.put(entry.getKey(), CertificateStatus.error(e.getMessage()));
+            }
+        }
+        return result;
+    }
+}
+
+/**
+ * 证书状态
+ */
+@Data
+public class CertificateStatus {
+    private boolean ok;
+    private String message;
+    private StatusLevel level;
+    
+    public enum StatusLevel {
+        OK,           // 正常
+        WARNING,      // 即将过期
+        EXPIRED,      // 已过期
+        MISSING,      // 未配置
+        ERROR         // 检查异常
+    }
+    
+    public static CertificateStatus ok() {
+        CertificateStatus s = new CertificateStatus();
+        s.setOk(true);
+        s.setLevel(StatusLevel.OK);
+        s.setMessage("OK");
+        return s;
+    }
+    
+    public static CertificateStatus expiringSoon(String message) {
+        CertificateStatus s = new CertificateStatus();
+        s.setOk(false);
+        s.setLevel(StatusLevel.WARNING);
+        s.setMessage(message);
+        return s;
+    }
+    
+    public static CertificateStatus missing(String message) {
+        CertificateStatus s = new CertificateStatus();
+        s.setOk(false);
+        s.setLevel(StatusLevel.MISSING);
+        s.setMessage(message);
+        return s;
+    }
+    
+    public static CertificateStatus error(String message) {
+        CertificateStatus s = new CertificateStatus();
+        s.setOk(false);
+        s.setLevel(StatusLevel.ERROR);
+        s.setMessage(message);
+        return s;
+    }
+}

+## 七、消息推送核心服务
+
+### 7.1 推送服务
+
+推送服务是消息通知中心的核心入口，负责接收业务方的推送请求，执行频率管控、通道选择、消息发送的全流程。
+
+```java
+/**
+ * 消息推送服务
+ * 统一推送入口，协调各组件完成消息推送
+ * 
+ * 核心流程：
+ * 1. 接收推送请求
+ * 2. 频率管控检查
+ * 3. 查询设备Token
+ * 4. 通道选择
+ * 5. 异步发送
+ * 6. 记录推送结果
+ */
+@Service
+public class PushService {
+    
+    @Resource
+    private TokenRegisterService tokenService;
+    
+    @Resource
+    private ChannelSelector channelSelector;
+    
+    @Resource
+    private NoChannelMessageHandler noChannelHandler;
+    
+    @Resource
+    private FrequencyControlService frequencyControl;
+    
+    @Resource
+    private PushRecordService pushRecordService;
+    
+    @Resource
+    private RocketMQTemplate mqTemplate;
+    
+    /**
+     * 发送推送消息
+     * 
+     * @param request 推送请求
+     * @return 推送结果
+     */
+    public PushResult sendPush(PushRequest request) {
+        // 1. 查询Push Token
+        PushToken token = tokenService.getToken(request.getPushToken());
+        if (token == null || token.getStatus() == TokenStatus.INVALID) {
+            // Token无效（可能已卸载重装，或使用了错误环境的Token）
+            return PushResult.invalidToken(request.getPushToken());
+        }
+        
+        // 2. 频率管控检查
+        FrequencyCheckResult freqResult = frequencyControl.check(
+            token.getUserId(), request.getBizType());
+        if (!freqResult.isAllowed()) {
+            return PushResult.rateLimited(request.getPushToken(), 
+                freqResult.getReason());
+        }
+        
+        // 3. 构建推送消息
+        PushMessage message = buildPushMessage(request);
+        
+        // 4. 异步发送（通过消息队列削峰）
+        PushTask task = new PushTask();
+        task.setMessage(message);
+        task.setToken(token);
+        
+        mqTemplate.asyncSend("push-topic", task, new SendCallback() {
+            @Override
+            public void onSuccess(SendResult sendResult) {
+                log.info("Push task sent to MQ, messageId={}", message.getMessageId());
+            }
+            
+            @Override
+            public void onException(Throwable e) {
+                log.error("Push task send to MQ failed", e);
+            }
+        });
+        
+        return PushResult.pending(request.getPushToken(), message.getMessageId());
+    }
+    
+    /**
+     * 消息队列消费者：处理推送任务
+     */
+    @RocketMQMessageListener(topic = "push-topic", consumerGroup = "push-consumer")
+    public class PushTaskListener implements RocketMQListener<PushTask> {
+        
+        @Override
+        public void onMessage(PushTask task) {
+            PushMessage message = task.getMessage();
+            PushToken token = task.getToken();
+            
+            // 1. 选择推送通道
+            ChannelAdapter adapter = channelSelector.selectChannel(token);
+            
+            PushResult result;
+            if (adapter == null) {
+                // 无可用通道，暂存消息
+                noChannelHandler.pendingMessage(token.getToken(), message);
+                result = PushResult.noChannel(token.getToken());
+            } else {
+                // 2. 发送推送
+                result = adapter.push(message, token);
+                
+                // 3. 如果失败且可降级，尝试降级通道
+                if (!result.isSuccess() && !"SELF_BUILT".equals(adapter.getChannelType())) {
+                    ChannelAdapter fallback = channelSelector.fallbackChannel(
+                        token, adapter.getChannelType());
+                    if (fallback != null) {
+                        result = fallback.push(message, token);
+                    }
+                }
+            }
+            
+            // 4. 记录推送结果
+            pushRecordService.record(message.getMessageId(), token.getToken(), result);
+            
+            // 5. Token无效处理
+            if (result.isInvalidToken()) {
+                tokenService.invalidateToken(token.getToken());
+            }
+        }
+    }
+    
+    /**
+     * 构建推送消息
+     */
+    private PushMessage buildPushMessage(PushRequest request) {
+        PushMessage message = new PushMessage();
+        message.setMessageId(IdGenerator.nextId());
+        message.setTitle(request.getTitle());
+        message.setContent(request.getContent());
+        message.setBizType(request.getBizType());
+        message.setHighPriority(request.isHighPriority());
+        message.setSilent(request.isSilent());
+        message.setPassThrough(request.isPassThrough());
+        message.setExtraData(request.getExtraData());
+        message.setExpireTime(System.currentTimeMillis() 
+            + request.getExpireSeconds() * 1000);
+        return message;
+    }
+}
+```

+### 7.2 频率管控
+
+频率管控防止用户被过多消息打扰。系统支持多种频率限制策略：按用户限制（单用户每天最多N条）、按业务类型限制（同一业务类型每小时最多N条）、按通道限制（单通道每分钟最多N条）。
+
+```java
+/**
+ * 频率管控服务
+ * 多维度频率限制，防止消息轰炸
+ * 
+ * 算法：基于Redis的滑动窗口计数器
+ * 使用ZSet实现滑动窗口，每次推送前检查窗口内消息数量
+ */
+@Service
+public class FrequencyControlService {
+    
+    @Resource
+    private RedisTemplate<String, String> redisTemplate;
+    
+    /** 用户每日推送上限 */
+    @Value("${push.freq.daily.user.limit:20}")
+    private int dailyUserLimit;
+    
+    /** 同业务类型每小时上限 */
+    @Value("${push.freq.hourly.bizType.limit:5}")
+    private int hourlyBizTypeLimit;
+    
+    /**
+     * 频率检查
+     * 
+     * @param userId 用户ID
+     * @param bizType 业务类型
+     * @return 检查结果
+     */
+    public FrequencyCheckResult check(String userId, String bizType) {
+        long now = System.currentTimeMillis();
+        
+        // 1. 用户日频率检查
+        String dailyKey = "freq:daily:" + userId + ":" + DateUtil.format(new Date(), "yyyyMMdd");
+        Long dailyCount = redisTemplate.opsForValue().increment(dailyKey);
+        if (dailyCount == 1) {
+            redisTemplate.expire(dailyKey, 1, TimeUnit.DAYS);
+        }
+        if (dailyCount > dailyUserLimit) {
+            return FrequencyCheckResult.denied("用户日推送超限: " + dailyCount + "/" + dailyUserLimit);
+        }
+        
+        // 2. 业务类型小时频率检查
+        String hourlyKey = "freq:hourly:" + bizType + ":" + userId 
+            + ":" + (now / 3600000);
+        Long hourlyCount = redisTemplate.opsForValue().increment(hourlyKey);
+        if (hourlyCount == 1) {
+            redisTemplate.expire(hourlyKey, 1, TimeUnit.HOURS);
+        }
+        if (hourlyCount > hourlyBizTypeLimit) {
+            return FrequencyCheckResult.denied("业务类型小时推送超限: " 
+                + hourlyCount + "/" + hourlyBizTypeLimit);
+        }
+        
+        return FrequencyCheckResult.allowed();
+    }
+}
+```

+## 九、模板管理
+
+### 9.1 消息模板引擎
+
+系统支持模板化推送，业务方预先配置消息模板，推送时只需传入模板ID和变量参数，系统自动渲染消息内容。模板管理支持变量替换、多语言、A/B测试等能力。
+
+```java
+/**
+ * 消息模板
+ * 支持变量替换、多语言、A/B测试
+ */
+@Data
+public class MessageTemplate {
+    private String templateId;
+    private String templateName;
+    private String bizType;
+    private String titleTemplate;
+    private String contentTemplate;
+    private PushMessageType messageType;
+    private Integer priority;
+    private List<TemplateVariable> variables;
+    private String approvalStatus;
+    private Long createTime;
+    private Long updateTime;
+}
+
+/**
+ * 模板变量定义
+ */
+@Data
+public class TemplateVariable {
+    private String variableName;
+    private String variableType;
+    private String defaultValue;
+    private boolean required;
+}
+
+/**
+ * 消息类型枚举
+ * 参考推送平台的消息分类标准
+ * 功能型消息：用户订单、交易、账号、日程等服务状态变动通知
+ * 营销型消息：不依赖用户前置行为，向用户发送的推广活动内容
+ */
+public enum PushMessageType {
+    PURE_FUNCTION("纯功能", "用户订单、交易、账号等服务状态变动的必要通知，不限制条数"),
+    WEAK_FUNCTION("弱功能", "用户主动参与后触发的提醒，如卡券核销、活动参与提醒"),
+    MARKETING("营销", "不依赖用户前置行为，向用户发送的推广活动内容，受条数频控");
+    
+    private String typeName;
+    private String description;
+    
+    PushMessageType(String typeName, String description) {
+        this.typeName = typeName;
+        this.description = description;
+    }
+}
+
+/**
+ * 模板渲染服务
+ * 使用Freemarker模板引擎渲染消息内容
+ */
+@Service
+public class TemplateRenderService {
+    
+    private final Configuration freemarkerConfig;
+    
+    @Resource
+    private TemplateRepository templateRepository;
+    
+    public TemplateRenderService() {
+        this.freemarkerConfig = new Configuration(Configuration.VERSION_2_3_31);
+        this.freemarkerConfig.setDefaultEncoding("UTF-8");
+    }
+    
+    /**
+     * 渲染消息模板
+     * 
+     * 算法说明：
+     * 1. 查询模板配置
+     * 2. 校验必填变量
+     * 3. 使用Freemarker渲染标题和内容
+     * 4. 返回渲染后的消息
+     */
+    public PushMessage render(String templateId, Map<String, String> variables) {
+        MessageTemplate template = templateRepository.findById(templateId);
+        if (template == null) {
+            throw new BusinessException("Template not found: " + templateId);
+        }
+        
+        // 校验必填变量
+        if (template.getVariables() != null) {
+            for (TemplateVariable var : template.getVariables()) {
+                if (var.isRequired() && !variables.containsKey(var.getVariableName())) {
+                    throw new BusinessException("Missing required variable: " + var.getVariableName());
+                }
+            }
+        }
+        
+        // 渲染标题
+        String title = renderTemplate(template.getTitleTemplate(), variables);
+        String content = renderTemplate(template.getContentTemplate(), variables);
+        
+        PushMessage message = new PushMessage();
+        message.setTitle(title);
+        message.setContent(content);
+        message.setBizType(template.getBizType());
+        message.setHighPriority(template.getPriority() != null && template.getPriority() >= 8);
+        return message;
+    }
+    
+    private String renderTemplate(String templateStr, Map<String, String> variables) {
+        try {
+            Template temp = new Template("inline", templateStr, freemarkerConfig);
+            StringWriter writer = new StringWriter();
+            temp.process(variables, writer);
+            return writer.toString();
+        } catch (Exception e) {
+            log.error("Template render failed: {}", templateStr, e);
+            return templateStr;
+        }
+    }
+}
+```

+### 9.2 Push消息分类与管控规则
+
+参考推送平台的管控规则体系，系统将Push消息按性质分为功能型和营销型两大类，不同类型适用不同的频控规则和静默期策略。
+
+```java
+/**
+ * Push管控规则引擎
+ * 根据消息类型执行不同的频控和静默期策略
+ *
+ * 管控规则参考推送平台标准：
+ * - 纯功能：无条数限制，无静默期
+ * - 弱功能：日3条，静默期22:00~08:00
+ * - 营销：日2~5条（视厂商通道限制），静默期22:00~09:00
+ */
+@Service
+public class PushControlRuleEngine {
+    
+    @Resource
+    private RedisTemplate<String, String> redisTemplate;
+    
+    /**
+     * 管控规则配置
+     */
+    private static final Map<PushMessageType, ControlRule> RULE_MAP = new HashMap<>();
+    
+    static {
+        RULE_MAP.put(PushMessageType.PURE_FUNCTION, new ControlRule(
+            Integer.MAX_VALUE,  // 无条数限制
+            null,               // 无静默期
+            0                   // 无发送间隔限制
+        ));
+        RULE_MAP.put(PushMessageType.WEAK_FUNCTION, new ControlRule(
+            3,                  // 日3条
+            new int[]{22, 8},   // 静默期22:00~08:00
+            5 * 60 * 1000       // 5分钟发送间隔
+        ));
+        RULE_MAP.put(PushMessageType.MARKETING, new ControlRule(
+            5,                  // 日2~5条
+            new int[]{22, 9},   // 静默期22:00~09:00
+            15 * 60 * 1000      // 15分钟发送间隔
+        ));
+    }
+    
+    /**
+     * 管控规则检查
+     * 
+     * 算法说明：
+     * 1. 检查静默期：营销类消息在静默期不可发送
+     * 2. 检查条数频控：按用户+消息类型维度计数
+     * 3. 检查发送间隔：同一用户两次推送最小间隔
+     */
+    public ControlCheckResult check(String userId, PushMessageType messageType) {
+        ControlRule rule = RULE_MAP.get(messageType);
+        if (rule == null) {
+            return ControlCheckResult.allowed();
+        }
+        
+        // 1. 静默期检查
+        if (rule.silentHours != null) {
+            int hour = LocalTime.now().getHour();
+            int start = rule.silentHours[0];
+            int end = rule.silentHours[1];
+            if (start > end) {
+                // 跨天静默期，如22:00~08:00
+                if (hour >= start || hour < end) {
+                    return ControlCheckResult.denied("静默期不可发送: " + start + ":00~" + end + ":00");
+                }
+            } else {
+                if (hour >= start && hour < end) {
+                    return ControlCheckResult.denied("静默期不可发送: " + start + ":00~" + end + ":00");
+                }
+            }
+        }
+        
+        // 2. 条数频控检查
+        String dailyKey = "push:freq:" + userId + ":" + messageType.name() 
+            + ":" + LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE);
+        Long count = redisTemplate.opsForValue().increment(dailyKey);
+        if (count == 1) {
+            redisTemplate.expire(dailyKey, 1, TimeUnit.DAYS);
+        }
+        if (count > rule.dailyLimit) {
+            return ControlCheckResult.denied("日推送条数超限: " + count + "/" + rule.dailyLimit);
+        }
+        
+        // 3. 发送间隔检查
+        if (rule.minIntervalMs > 0) {
+            String intervalKey = "push:interval:" + userId;
+            String lastTimeStr = redisTemplate.opsForValue().get(intervalKey);
+            if (lastTimeStr != null) {
+                long lastTime = Long.parseLong(lastTimeStr);
+                long elapsed = System.currentTimeMillis() - lastTime;
+                if (elapsed < rule.minIntervalMs) {
+                    return ControlCheckResult.denied(
+                        "发送间隔不足: " + (rule.minIntervalMs - elapsed) / 1000 + "秒后可发送");
+                }
+            }
+            redisTemplate.opsForValue().set(intervalKey, 
+                String.valueOf(System.currentTimeMillis()), 
+                rule.minIntervalMs * 2, TimeUnit.MILLISECONDS);
+        }
+        
+        return ControlCheckResult.allowed();
+    }
+    
+    /**
+     * 管控规则
+     */
+    @Data
+    @AllArgsConstructor
+    private static class ControlRule {
+        private int dailyLimit;
+        private int[] silentHours;
+        private long minIntervalMs;
+    }
+}
+```

+### 9.3 效率评估与低效驳回
+
+参考推送平台的低效管控机制，系统对营销类Push按天维度进行效率评估。评估指标包括CTR（点击率）和转化率，低于阈值的模板将被自动驳回，业务方优化后可重新提交审核。
+
+```java
+/**
+ * Push效率评估服务
+ * 按天维度评估营销Push的CTR和转化率
+ *
+ * 评估规则参考推送平台标准：
+ * - 日发送量 >= 10000的模板参与评估
+ * - CTR低于阈值则驳回模板
+ * - 驳回后业务方可优化后重新提交审核
+ */
+@Service
+public class PushEfficiencyEvaluator {
+    
+    @Resource
+    private PushRecordRepository pushRecordRepository;
+    
+    @Resource
+    private TemplateRepository templateRepository;
+    
+    /** CTR最低阈值 */
+    @Value("${push.efficiency.ctr.threshold:0.02}")
+    private double ctrThreshold;
+    
+    /** 最小评估发送量 */
+    @Value("${push.efficiency.min.volume:10000}")
+    private long minVolume;
+    
+    /**
+     * 每日效率评估
+     * 凌晨2点执行，评估前一天的营销Push数据
+     */
+    @Scheduled(cron = "0 0 2 * * ?")
+    public void dailyEvaluation() {
+        LocalDate yesterday = LocalDate.now().minusDays(1);
+        
+        // 查询昨日所有营销类Push发送记录
+        List<PushStats> statsList = pushRecordRepository.aggregateDailyStats(
+            yesterday, PushMessageType.MARKETING);
+        
+        for (PushStats stats : statsList) {
+            if (stats.getSendVolume() < minVolume) {
+                continue;  // 发送量不足，跳过评估
+            }
+            
+            double ctr = (double) stats.getClickCount() / stats.getSendVolume();
+            
+            if (ctr < ctrThreshold) {
+                // CTR低于阈值，驳回模板
+                MessageTemplate template = templateRepository.findById(stats.getTemplateId());
+                if (template != null) {
+                    template.setApprovalStatus("REJECTED_LOW_CTR");
+                    template.setUpdateTime(System.currentTimeMillis());
+                    templateRepository.save(template);
+                    
+                    // 发送驳回通知
+                    log.warn("Template rejected due to low CTR: templateId={}, CTR={}, threshold={}",
+                        stats.getTemplateId(), ctr, ctrThreshold);
+                }
+            }
+        }
+    }
+}
+```

+## 十、Push审批流程
+
+参考推送平台的审批流程，Push消息发送前需要经过审批。功能一类和功能二类Push需要线下提报评估后审核，营销类Push需要经过更严格的审批流程。
+
+```java
+/**
+ * Push审批服务
+ * 管理Push模板和发送任务的审批流程
+ *
+ * 审批流程参考推送平台标准：
+ * 1. 功能一类/二类：线下提报→评估→审核→上线
+ * 2. 营销一类：线下提报→评估→审核→上线（免费）
+ * 3. 营销二类：提报→审核→投放（0.8元/CPM）
+ */
+@Service
+public class PushApprovalService {
+    
+    @Resource
+    private TemplateRepository templateRepository;
+    
+    @Resource
+    private PushApprovalRepository approvalRepository;
+    
+    /**
+     * 提交审批申请
+     */
+    public String submitApproval(PushApprovalRequest request) {
+        PushApproval approval = new PushApproval();
+        approval.setApprovalId(IdGenerator.nextId());
+        approval.setTemplateId(request.getTemplateId());
+        approval.setMessageType(request.getMessageType());
+        approval.setApplicant(request.getApplicant());
+        approval.setStatus(ApprovalStatus.PENDING);
+        approval.setSubmitTime(System.currentTimeMillis());
+        
+        // 营销二类需要设置计费信息
+        if (request.getMessageType() == PushMessageType.MARKETING) {
+            approval.setBillingType("CPM");
+            approval.setBillingRate(0.8);  // 0.8元/CPM
+        }
+        
+        approvalRepository.save(approval);
+        return approval.getApprovalId();
+    }
+    
+    /**
+     * 审批处理
+     */
+    public void processApproval(String approvalId, ApprovalResult result) {
+        PushApproval approval = approvalRepository.findById(approvalId);
+        if (approval == null) {
+            throw new BusinessException("Approval not found: " + approvalId);
+        }
+        
+        approval.setStatus(result.isApproved() ? ApprovalStatus.APPROVED : ApprovalStatus.REJECTED);
+        approval.setApprover(result.getApprover());
+        approval.setApproveTime(System.currentTimeMillis());
+        approval.setComment(result.getComment());
+        
+        approvalRepository.save(approval);
+        
+        if (result.isApproved()) {
+            // 审批通过，更新模板状态
+            MessageTemplate template = templateRepository.findById(approval.getTemplateId());
+            if (template != null) {
+                template.setApprovalStatus("APPROVED");
+                template.setUpdateTime(System.currentTimeMillis());
+                templateRepository.save(template);
+            }
+        }
+    }
+    
+    public enum ApprovalStatus {
+        PENDING,     // 待审批
+        APPROVED,    // 已通过
+        REJECTED     // 已驳回
+    }
+}

+```java
+/**

+    public DeviceStatus queryDeviceStatus(String appName, String pushToken) {

+            return DeviceStatus.notFound(pushToken);
+        }
+        
+        // 校验appName与Token匹配

+        status.setMiRegId(token.getDeviceBrand().equals("Xiaomi") ? token.getThirdPartyToken() : null);
+        status.setApnsToken(token.getDeviceBrand().equals("Apple") ? token.getThirdPartyToken() : null);
+        status.setOppoRegId(token.getDeviceBrand().equals("OPPO") ? token.getThirdPartyToken() : null);
+        status.setVivoRegId(token.getDeviceBrand().equals("VIVO") ? token.getThirdPartyToken() : null);

+        // 自建通道状态
+        status.setClientIp(token.getClientIp());
+        status.setConnectionId(token.getConnectionId());
+        
+        // 通道可用性
+        List<String> availableChannels = new ArrayList<>();
+        if (StringUtils.isNotBlank(token.getThirdPartyToken()) 
+            && token.getStatus() == TokenStatus.ACTIVE) {

+            && StringUtils.isBlank(token.getConnectionId())) {
+            return "设备无厂商通道且App未打开，请打开App后重试";
+        }
+        return "未知原因";
+    }

+## 十三、系统总结
+
+消息通知中心系统的核心设计包括以下方面。多通道适配器架构方面，系统使用策略模式将Apple APNS、华为Push、小米Push、OPPO Push、VIVO Push、魅族Push和自建通道统一抽象为ChannelAdapter接口，新增通道只需实现接口并注册，符合开闭原则。通道选择使用责任链模式，按优先级链式选择：大厂设备优先使用厂商通道（送达率高、支持后台推送），其次降级到自建通道（仅前台可用），最后进入无通道暂存队列等待补推。Token管理方面，Push Token具有环境区分（线上dpsh前缀、线下dpst前缀，防止跨环境误用）、App绑定（Token与App必须匹配，不匹配会导致无通道）、生命周期管理（注册、更新、失效检测、注销）三个核心机制。证书监控方面，APNS证书和各厂商通道认证密钥都有有效期，系统使用观察者模式监控证书状态，发现异常自动告警。频控管控方面，系统实现了按消息类型管控（纯功能无限制、弱功能日3条、营销日2~5条）、静默期管控、发送间隔管控等多维度频率控制，同时按天维度对营销Push进行效率评估，CTR低于阈值的模板自动驳回。

+## 十四、全链路实战案例
+
+本章通过三个完整的全链路实战案例，展示消息通知中心从业务接入到消息送达的全流程。每个案例包含完整的Java代码实现，覆盖异常处理、日志记录、幂等控制等生产级要素。

+### 14.1 案例一：业务方发送通知全链路
+
+业务方调用通知中心统一API发送一条通知消息，完整链路包括：业务方调用通知API -> 模板渲染 -> 用户偏好查询 -> 多渠道分发 -> 结果记录。该链路覆盖了消息通知中心最核心的日常发送场景。
+
+```java
+/**
+ * 通知发送全链路服务
+ * 从业务方调用API到消息送达的完整流程
+ *
+ * 链路节点：
+ * 1. 接收业务方推送请求，幂等校验
+ * 2. 模板渲染（变量替换）
+ * 3. 用户偏好查询（渠道订阅状态）
+ * 4. 多渠道分发（Push / 站内信 / 短信 / 邮件）
+ * 5. 推送结果记录与链路追踪
+ */
+@Service
+@Slf4j
+public class NotificationSendService {
+
+    @Resource
+    private RedisTemplate<String, String> redisTemplate;
+
+    @Resource
+    private TemplateRenderService templateRenderService;
+
+    @Resource
+    private UserPreferenceService userPreferenceService;
+
+    @Resource
+    private ChannelSelector channelSelector;
+
+    @Resource
+    private PushRecordService pushRecordService;
+
+    @Resource
+    private InboxMessageService inboxMessageService;
+
+    @Resource
+    private SmsChannelAdapter smsChannelAdapter;
+
+    @Resource
+    private EmailChannelAdapter emailChannelAdapter;
+
+    @Resource
+    private PushTraceService pushTraceService;
+
+    /** 幂等Key前缀 */
+    private static final String IDEMPOTENT_KEY_PREFIX = "notify:idem:";
+
+    /** 幂等Key过期时间 */
+    private static final long IDEMPOTENT_EXPIRE_HOURS = 24L;
+
+    /**
+     * 发送通知全链路入口
+     *
+     * @param request 通知发送请求
+     * @return 发送结果
+     */
+    public NotificationSendResult sendNotification(NotificationSendRequest request) {
+        String traceId = Tracer.generateTraceId();
+        long startTime = System.currentTimeMillis();
+
+        try {
+            log.info("[通知发送] traceId={}, bizId={}, templateCode={}, userId={}",
+                traceId, request.getBizId(), request.getTemplateCode(), request.getUserId());
+
+            // ========== 第1步：幂等控制 ==========
+            // 使用 bizId 作为幂等键，防止业务方重复调用导致重复发送
+            String idempotentKey = IDEMPOTENT_KEY_PREFIX + request.getBizId();
+            Boolean setSuccess = redisTemplate.opsForValue()
+                .setIfAbsent(idempotentKey, traceId, IDEMPOTENT_EXPIRE_HOURS, TimeUnit.HOURS);
+
+            if (setSuccess == null || !setSuccess) {
+                // 幂等拦截：同一bizId的请求已经处理过
+                String existTraceId = redisTemplate.opsForValue().get(idempotentKey);
+                log.warn("[通知发送] 幂等拦截, bizId={}, existTraceId={}",
+                    request.getBizId(), existTraceId);
+                return NotificationSendResult.duplicate(request.getBizId(), existTraceId);
+            }
+
+            pushTraceService.recordTraceNode(traceId, "IDEMPOTENT_CHECK", "PASS",
+                "bizId=" + request.getBizId());
+
+            // ========== 第2步：模板渲染 ==========
+            // 根据模板Code加载模板，替换变量占位符
+            RenderedMessage renderedMessage;
+            try {
+                renderedMessage = templateRenderService.render(
+                    request.getTemplateCode(), request.getTemplateParams());
+                log.info("[通知发送] 模板渲染完成, traceId={}, templateCode={}, title={}",
+                    traceId, request.getTemplateCode(), renderedMessage.getTitle());
+            } catch (TemplateNotFoundException e) {
+                log.error("[通知发送] 模板不存在, traceId={}, templateCode={}",
+                    traceId, request.getTemplateCode(), e);
+                rollbackIdempotentKey(idempotentKey);
+                return NotificationSendResult.fail("TEMPLATE_NOT_FOUND", "模板不存在: " + request.getTemplateCode());
+            } catch (TemplateRenderException e) {
+                log.error("[通知发送] 模板渲染失败, traceId={}, templateCode={}",
+                    traceId, request.getTemplateCode(), e);
+                rollbackIdempotentKey(idempotentKey);
+                return NotificationSendResult.fail("TEMPLATE_RENDER_ERROR", e.getMessage());
+            }
+
+            pushTraceService.recordTraceNode(traceId, "TEMPLATE_RENDER", "SUCCESS",
+                "title=" + renderedMessage.getTitle());
+
+            // ========== 第3步：用户偏好查询 ==========
+            // 查询用户对各渠道的订阅偏好，决定哪些渠道可用
+            UserPreference preference;
+            try {
+                preference = userPreferenceService.getPreference(request.getUserId());
+                log.info("[通知发送] 用户偏好查询完成, traceId={}, userId={}, pushEnabled={}, smsEnabled={}, inboxEnabled={}",
+                    traceId, request.getUserId(),
+                    preference.isPushEnabled(), preference.isSmsEnabled(), preference.isInboxEnabled());
+            } catch (Exception e) {
+                log.error("[通知发送] 用户偏好查询失败, traceId={}, userId={}",
+                    traceId, request.getUserId(), e);
+                // 偏好查询失败时使用默认偏好（全部渠道可用），保证消息不丢
+                preference = UserPreference.defaultAllEnabled();
+                log.warn("[通知发送] 使用默认偏好, traceId={}, userId={}", traceId, request.getUserId());
+            }
+
+            pushTraceService.recordTraceNode(traceId, "USER_PREFERENCE", "SUCCESS",
+                "pushEnabled=" + preference.isPushEnabled() + ", smsEnabled=" + preference.isSmsEnabled());
+
+            // ========== 第4步：多渠道分发 ==========
+            NotificationSendResult result = new NotificationSendResult();
+            result.setTraceId(traceId);
+            result.setBizId(request.getBizId());
+
+            // 4.1 站内信（同步发送，保证可靠送达）
+            if (preference.isInboxEnabled()) {
+                try {
+                    inboxMessageService.sendInboxMessage(
+                        request.getUserId(),
+                        renderedMessage.getTitle(),
+                        renderedMessage.getContent(),
+                        request.getBizType(),
+                        traceId);
+                    result.setInboxResult("SUCCESS");
+                    log.info("[通知发送] 站内信发送成功, traceId={}, userId={}", traceId, request.getUserId());
+                } catch (Exception e) {
+                    log.error("[通知发送] 站内信发送失败, traceId={}, userId={}",
+                        traceId, request.getUserId(), e);
+                    result.setInboxResult("FAIL: " + e.getMessage());
+                }
+            }
+
+            // 4.2 Push推送（异步发送，通过MQ削峰）
+            if (preference.isPushEnabled()) {
+                try {
+                    PushRequest pushRequest = buildPushRequest(request, renderedMessage, traceId);
+                    PushResult pushResult = pushService.sendPush(pushRequest);
+                    result.setPushResult(pushResult.getStatus().name());
+                    log.info("[通知发送] Push推送已提交, traceId={}, userId={}, pushStatus={}",
+                        traceId, request.getUserId(), pushResult.getStatus());
+                } catch (Exception e) {
+                    log.error("[通知发送] Push推送提交失败, traceId={}, userId={}",
+                        traceId, request.getUserId(), e);
+                    result.setPushResult("FAIL: " + e.getMessage());
+                }
+            }
+
+            // 4.3 短信（仅高优先级消息触发）
+            if (preference.isSmsEnabled() && request.isHighPriority()) {
+                try {
+                    SmsResult smsResult = smsChannelAdapter.sendSms(
+                        request.getPhone(), renderedMessage.getSmsContent());
+                    result.setSmsResult(smsResult.getStatus());
+                    log.info("[通知发送] 短信发送完成, traceId={}, phone={}, smsStatus={}",
+                        traceId, maskPhone(request.getPhone()), smsResult.getStatus());
+                } catch (Exception e) {
+                    log.error("[通知发送] 短信发送失败, traceId={}, userId={}",
+                        traceId, request.getUserId(), e);
+                    result.setSmsResult("FAIL: " + e.getMessage());
+                }
+            }
+
+            // ========== 第5步：结果记录 ==========
+            try {
+                pushRecordService.recordNotification(traceId, request, result);
+                pushTraceService.recordTraceNode(traceId, "RESULT_RECORD", "SUCCESS",
+                    "inbox=" + result.getInboxResult() + ", push=" + result.getPushResult());
+            } catch (Exception e) {
+                // 结果记录失败不影响主流程，仅记录日志
+                log.error("[通知发送] 结果记录失败, traceId={}", traceId, e);
+            }
+
+            long costMs = System.currentTimeMillis() - startTime;
+            log.info("[通知发送] 全链路完成, traceId={}, bizId={}, cost={}ms",
+                traceId, request.getBizId(), costMs);
+
+            result.setSuccess(true);
+            result.setCostMs(costMs);
+            return result;
+
+        } catch (Exception e) {
+            log.error("[通知发送] 全链路异常, traceId={}, bizId={}",
+                traceId, request.getBizId(), e);
+            NotificationSendResult failResult = NotificationSendResult.fail(
+                "SYSTEM_ERROR", e.getMessage());
+            failResult.setTraceId(traceId);
+            return failResult;
+        }
+    }
+
+    /**
+     * 回滚幂等Key
+     * 当后续流程失败且需要允许业务方重试时，删除幂等Key
+     */
+    private void rollbackIdempotentKey(String idempotentKey) {
+        try {
+            redisTemplate.delete(idempotentKey);
+        } catch (Exception e) {
+            log.error("[通知发送] 幂等Key回滚失败, key={}", idempotentKey, e);
+        }
+    }
+
+    /**
+     * 构建Push请求
+     */
+    private PushRequest buildPushRequest(NotificationSendRequest request,
+            RenderedMessage renderedMessage, String traceId) {
+        PushRequest pushRequest = new PushRequest();
+        pushRequest.setUserId(request.getUserId());
+        pushRequest.setTitle(renderedMessage.getTitle());
+        pushRequest.setContent(renderedMessage.getContent());
+        pushRequest.setBizType(request.getBizType());
+        pushRequest.setHighPriority(request.isHighPriority());
+        pushRequest.setExtraData(request.getExtraData());
+        pushRequest.setExpireSeconds(3600);
+        return pushRequest;
+    }
+
+    /**
+     * 手机号脱敏
+     */
+    private String maskPhone(String phone) {
+        if (phone == null || phone.length() < 7) {
+            return "***";
+        }
+        return phone.substring(0, 3) + "****" + phone.substring(phone.length() - 4);
+    }
+}
+```

+### 14.2 案例二：用户查看站内信全链路
+
+用户打开App后查看站内信列表，完整链路包括：消息列表查询 -> 未读计数 -> 已读更新 -> 分页加载。该链路覆盖了站内信的读侧全流程，对查询性能和数据一致性有较高要求。
+
+```java
+/**
+ * 站内信查询与阅读服务
+ * 处理用户站内信的列表查询、未读计数、已读标记等读侧操作
+ *
+ * 链路节点：
+ * 1. 消息列表查询（分页+游标加载）
+ * 2. 未读消息计数（Redis缓存+DB兜底）
+ * 3. 已读状态更新（乐观锁+幂等控制）
+ * 4. 分页加载（游标分页，避免深度分页问题）
+ */
+@Service
+@Slf4j
+public class InboxQueryService {
+
+    @Resource
+    private InboxMessageRepository inboxMessageRepository;
+
+    @Resource
+    private RedisTemplate<String, Object> redisTemplate;
+
+    @Resource
+    private PushTraceService pushTraceService;
+
+    /** 未读计数缓存Key前缀 */
+    private static final String UNREAD_COUNT_KEY_PREFIX = "inbox:unread:";
+
+    /** 未读计数缓存过期时间（秒） */
+    private static final long UNREAD_COUNT_TTL = 300L;
+
+    /** 已读标记幂等Key前缀 */
+    private static final String READ_MARK_KEY_PREFIX = "inbox:read:";
+
+    /** 默认每页消息数 */
+    private static final int DEFAULT_PAGE_SIZE = 20;
+
+    /** 最大每页消息数 */
+    private static final int MAX_PAGE_SIZE = 50;
+
+    /**
+     * 查询站内信列表（首页加载）
+     *
+     * @param userId 用户ID
+     * @param pageSize 每页条数
+     * @return 站内信列表
+     */
+    public InboxListResult queryInboxList(String userId, Integer pageSize) {
+        String traceId = Tracer.generateTraceId();
+        long startTime = System.currentTimeMillis();
+
+        try {
+            log.info("[站内信查询] traceId={}, userId={}, pageSize={}",
+                traceId, userId, pageSize);
+
+            // 参数校验与默认值处理
+            int actualPageSize = (pageSize == null || pageSize <= 0)
+                ? DEFAULT_PAGE_SIZE : Math.min(pageSize, MAX_PAGE_SIZE);
+
+            // ========== 第1步：消息列表查询 ==========
+            // 使用游标分页（基于消息ID），避免传统OFFSET深度分页性能问题
+            List<InboxMessage> messages;
+            try {
+                messages = inboxMessageRepository.queryByUserIdWithCursor(
+                    userId, null, actualPageSize + 1); // 多查1条用于判断是否有下一页
+                log.info("[站内信查询] 列表查询完成, traceId={}, userId={}, msgCount={}",
+                    traceId, userId, messages.size());
+            } catch (Exception e) {
+                log.error("[站内信查询] 列表查询失败, traceId={}, userId={}",
+                    traceId, userId, e);
+                return InboxListResult.fail("QUERY_ERROR", "消息列表查询失败");
+            }
+
+            // 判断是否有下一页
+            boolean hasNext = messages.size() > actualPageSize;
+            String nextCursor = null;
+            if (hasNext) {
+                messages = messages.subList(0, actualPageSize);
+                nextCursor = messages.get(actualPageSize - 1).getMessageId();
+            }
+
+            // ========== 第2步：未读消息计数 ==========
+            int unreadCount = getUnreadCount(userId, traceId);
+
+            // ========== 第3步：组装返回结果 ==========
+            InboxListResult result = new InboxListResult();
+            result.setTraceId(traceId);
+            result.setMessages(messages.stream()
+                .map(this::convertToVO)
+                .collect(Collectors.toList()));
+            result.setUnreadCount(unreadCount);
+            result.setHasNext(hasNext);
+            result.setNextCursor(nextCursor);
+            result.setSuccess(true);
+
+            long costMs = System.currentTimeMillis() - startTime;
+            log.info("[站内信查询] 首页加载完成, traceId={}, userId={}, unreadCount={}, cost={}ms",
+                traceId, userId, unreadCount, costMs);
+
+            return result;
+
+        } catch (Exception e) {
+            log.error("[站内信查询] 首页加载异常, traceId={}, userId={}",
+                traceId, userId, e);
+            return InboxListResult.fail("SYSTEM_ERROR", e.getMessage());
+        }
+    }
+
+    /**
+     * 分页加载更多消息（游标分页）
+     *
+     * @param userId 用户ID
+     * @param cursor 上一页最后一条消息的ID
+     * @param pageSize 每页条数
+     * @return 下一页站内信列表
+     */
+    public InboxListResult loadMore(String userId, String cursor, Integer pageSize) {
+        String traceId = Tracer.generateTraceId();
+        long startTime = System.currentTimeMillis();
+
+        try {
+            log.info("[站内信查询] 加载更多, traceId={}, userId={}, cursor={}",
+                traceId, userId, cursor);
+
+            if (StringUtils.isBlank(cursor)) {
+                log.warn("[站内信查询] cursor为空, 回退到首页查询, traceId={}", traceId);
+                return queryInboxList(userId, pageSize);
+            }
+
+            int actualPageSize = (pageSize == null || pageSize <= 0)
+                ? DEFAULT_PAGE_SIZE : Math.min(pageSize, MAX_PAGE_SIZE);
+
+            List<InboxMessage> messages;
+            try {
+                messages = inboxMessageRepository.queryByUserIdWithCursor(
+                    userId, cursor, actualPageSize + 1);
+            } catch (Exception e) {
+                log.error("[站内信查询] 分页查询失败, traceId={}, userId={}, cursor={}",
+                    traceId, userId, cursor, e);
+                return InboxListResult.fail("QUERY_ERROR", "分页查询失败");
+            }
+
+            boolean hasNext = messages.size() > actualPageSize;
+            String nextCursor = null;
+            if (hasNext) {
+                messages = messages.subList(0, actualPageSize);
+                nextCursor = messages.get(actualPageSize - 1).getMessageId();
+            }
+
+            InboxListResult result = new InboxListResult();
+            result.setTraceId(traceId);
+            result.setMessages(messages.stream()
+                .map(this::convertToVO)
+                .collect(Collectors.toList()));
+            result.setHasNext(hasNext);
+            result.setNextCursor(nextCursor);
+            result.setSuccess(true);
+
+            long costMs = System.currentTimeMillis() - startTime;
+            log.info("[站内信查询] 分页加载完成, traceId={}, userId={}, msgCount={}, cost={}ms",
+                traceId, userId, messages.size(), costMs);
+
+            return result;
+
+        } catch (Exception e) {
+            log.error("[站内信查询] 分页加载异常, traceId={}, userId={}, cursor={}",
+                traceId, userId, cursor, e);
+            return InboxListResult.fail("SYSTEM_ERROR", e.getMessage());
+        }
+    }
+
+    /**
+     * 标记消息已读
+     * 使用幂等控制防止重复标记，使用乐观锁保证并发安全
+     *
+     * @param userId 用户ID
+     * @param messageId 消息ID
+     * @return 操作结果
+     */
+    public ReadMarkResult markAsRead(String userId, String messageId) {
+        String traceId = Tracer.generateTraceId();
+
+        try {
+            log.info("[站内信已读] traceId={}, userId={}, messageId={}",
+                traceId, userId, messageId);
+
+            // ========== 幂等控制 ==========
+            // 使用Redis SET NX实现幂等，同一用户同一消息的已读标记只处理一次
+            String readMarkKey = READ_MARK_KEY_PREFIX + userId + ":" + messageId;
+            Boolean isFirstMark = redisTemplate.opsForValue()
+                .setIfAbsent(readMarkKey, "1", 7, TimeUnit.DAYS);
+
+            if (isFirstMark != null && !isFirstMark) {
+                // 已经标记过已读，直接返回成功（幂等）
+                log.info("[站内信已读] 幂等拦截（已标记过）, traceId={}, userId={}, messageId={}",
+                    traceId, userId, messageId);
+                return ReadMarkResult.success(true);
+            }
+
+            // ========== 已读状态更新 ==========
+            // 使用乐观锁更新：UPDATE inbox_message SET status='READ', read_time=NOW()
+            //   WHERE message_id=? AND user_id=? AND status='UNREAD'
+            int updatedRows;
+            try {
+                updatedRows = inboxMessageRepository.updateToRead(
+                    messageId, userId, System.currentTimeMillis());
+            } catch (Exception e) {
+                log.error("[站内信已读] DB更新失败, traceId={}, userId={}, messageId={}",
+                    traceId, userId, messageId, e);
+                // DB失败时回滚幂等Key，允许重试
+                redisTemplate.delete(readMarkKey);
+                return ReadMarkResult.fail("DB_ERROR", "已读状态更新失败");
+            }
+
+            if (updatedRows == 0) {
+                // 更新0行：消息可能已被其他请求标记为已读，或消息不存在
+                log.info("[站内信已读] 更新0行（已读或不存在）, traceId={}, userId={}, messageId={}",
+                    traceId, userId, messageId);
+                return ReadMarkResult.success(true);
+            }
+
+            // ========== 未读计数减1 ==========
+            // 失效缓存，下次查询时重新从DB加载
+            try {
+                String unreadKey = UNREAD_COUNT_KEY_PREFIX + userId;
+                redisTemplate.opsForValue().decrement(unreadKey);
+                log.info("[站内信已读] 未读计数-1, traceId={}, userId={}", traceId, userId);
+            } catch (Exception e) {
+                log.warn("[站内信已读] 未读计数缓存更新失败, traceId={}, userId={}",
+                    traceId, userId, e);
+                // 缓存更新失败不影响主流程，下次查询会从DB重新加载
+            }
+
+            log.info("[站内信已读] 标记已读成功, traceId={}, userId={}, messageId={}",
+                traceId, userId, messageId);
+
+            ReadMarkResult result = ReadMarkResult.success(false);
+            result.setTraceId(traceId);
+            return result;
+
+        } catch (Exception e) {
+            log.error("[站内信已读] 标记已读异常, traceId={}, userId={}, messageId={}",
+                traceId, userId, messageId, e);
+            return ReadMarkResult.fail("SYSTEM_ERROR", e.getMessage());
+        }
+    }
+
+    /**
+     * 获取未读消息计数
+     * 优先读Redis缓存，缓存未命中时查DB并回填缓存
+     *
+     * @param userId 用户ID
+     * @param traceId 链路追踪ID
+     * @return 未读计数
+     */
+    private int getUnreadCount(String userId, String traceId) {
+        String unreadKey = UNREAD_COUNT_KEY_PREFIX + userId;
+
+        try {
+            // 1. 先查缓存
+            Object cached = redisTemplate.opsForValue().get(unreadKey);
+            if (cached != null) {
+                int count = Integer.parseInt(cached.toString());
+                log.info("[站内信查询] 未读计数命中缓存, traceId={}, userId={}, unreadCount={}",
+                    traceId, userId, count);
+                return count;
+            }
+        } catch (Exception e) {
+            log.warn("[站内信查询] 未读计数缓存读取失败, traceId={}, userId={}",
+                traceId, userId, e);
+        }
+
+        // 2. 缓存未命中，查DB
+        int unreadCount;
+        try {
+            unreadCount = inboxMessageRepository.countUnreadByUserId(userId);
+        } catch (Exception e) {
+            log.error("[站内信查询] 未读计数DB查询失败, traceId={}, userId={}",
+                traceId, userId, e);
+            return 0; // 降级返回0，不影响列表查询主流程
+        }
+
+        // 3. 回填缓存
+        try {
+            redisTemplate.opsForValue().set(unreadKey, unreadCount,
+                UNREAD_COUNT_TTL, TimeUnit.SECONDS);
+        } catch (Exception e) {
+            log.warn("[站内信查询] 未读计数缓存回填失败, traceId={}, userId={}",
+                traceId, userId, e);
+        }
+
+        log.info("[站内信查询] 未读计数DB查询完成, traceId={}, userId={}, unreadCount={}",
+            traceId, userId, unreadCount);
+
+        return unreadCount;
+    }
+
+    /**
+     * 消息实体转VO
+     */
+    private InboxMessageVO convertToVO(InboxMessage message) {
+        InboxMessageVO vo = new InboxMessageVO();
+        vo.setMessageId(message.getMessageId());
+        vo.setTitle(message.getTitle());
+        vo.setContent(message.getContent());
+        vo.setBizType(message.getBizType());
+        vo.setStatus(message.getStatus());
+        vo.setCreateTime(message.getCreateTime());
+        vo.setReadTime(message.getReadTime());
+        return vo;
+    }
+}

+### 14.3 案例三：批量推送全链路
+
+运营人员配置一个批量推送任务，系统自动完成人群圈选、分批推送、到达率统计。完整链路包括：运营配置推送任务 -> 人群圈选 -> 分批推送 -> 到达率统计。该链路覆盖了运营批量推送场景，对吞吐量、幂等性和可观测性有较高要求。
+
+```java
+/**
+ * 批量推送任务服务
+ * 处理运营批量推送任务的全生命周期
+ *
+ * 链路节点：
+ * 1. 运营配置推送任务（模板、人群标签、推送时间）
+ * 2. 人群圈选（根据标签查询目标用户群）
+ * 3. 分批推送（按批次拆分，通过MQ异步分发）
+ * 4. 到达率统计（推送结果聚合分析）
+ */
+@Service
+@Slf4j
+public class BatchPushTaskService {
+
+    @Resource
+    private BatchPushTaskRepository taskRepository;
+
+    @Resource
+    private UserSegmentService userSegmentService;
+
+    @Resource
+    private RedisTemplate<String, String> redisTemplate;
+
+    @Resource
+    private RocketMQTemplate mqTemplate;
+
+    @Resource
+    private PushRecordService pushRecordService;
+
+    @Resource
+    private PushTraceService pushTraceService;
+
+    @Resource
+    private TemplateRenderService templateRenderService;
+
+    @Resource
+    private ChannelSelector channelSelector;
+
+    /** 批量推送每批次大小 */
+    private static final int BATCH_SIZE = 500;
+
+    /** 批次幂等Key前缀 */
+    private static final String BATCH_IDEMPOTENT_PREFIX = "batch:push:";
+
+    /** 批次幂等Key过期时间（小时） */
+    private static final long BATCH_IDEMPOTENT_HOURS = 72L;
+
+    /** 批量推送统计Key前缀 */
+    private static final String BATCH_STATS_PREFIX = "batch:stats:";
+
+    /**
+     * 创建批量推送任务
+     * 运营人员配置推送任务参数，系统创建任务并等待定时调度或立即执行
+     *
+     * @param request 批量推送请求
+     * @return 任务ID
+     */
+    public String createBatchPushTask(BatchPushRequest request) {
+        String traceId = Tracer.generateTraceId();
+
+        try {
+            log.info("[批量推送] 创建任务, traceId={}, taskName={}, templateCode={}, segmentId={}",
+                traceId, request.getTaskName(), request.getTemplateCode(), request.getSegmentId());
+
+            // 参数校验
+            if (StringUtils.isBlank(request.getTaskName())) {
+                throw new BusinessException("任务名称不能为空");
+            }
+            if (StringUtils.isBlank(request.getTemplateCode())) {
+                throw new BusinessException("模板编码不能为空");
+            }
+            if (StringUtils.isBlank(request.getSegmentId())) {
+                throw new BusinessException("人群包ID不能为空");
+            }
+
+            // 创建任务记录
+            BatchPushTask task = new BatchPushTask();
+            task.setTaskId(IdGenerator.nextId());
+            task.setTaskName(request.getTaskName());
+            task.setTemplateCode(request.getTemplateCode());
+            task.setSegmentId(request.getSegmentId());
+            task.setBizType(request.getBizType());
+            task.setStatus(BatchTaskStatus.CREATED);
+            task.setScheduledTime(request.getScheduledTime());
+            task.setCreateTime(System.currentTimeMillis());
+            task.setCreateBy(request.getOperator());
+            task.setTraceId(traceId);
+
+            taskRepository.save(task);
+
+            log.info("[批量推送] 任务创建成功, traceId={}, taskId={}, taskName={}",
+                traceId, task.getTaskId(), task.getTaskName());
+
+            // 如果是立即执行，触发调度
+            if (request.getScheduledTime() == null
+                || request.getScheduledTime() <= System.currentTimeMillis()) {
+                executeBatchPushTask(task.getTaskId(), traceId);
+            }
+
+            return task.getTaskId();
+
+        } catch (BusinessException e) {
+            log.error("[批量推送] 创建任务参数错误, traceId={}", traceId, e);
+            throw e;
+        } catch (Exception e) {
+            log.error("[批量推送] 创建任务异常, traceId={}", traceId, e);
+            throw new BusinessException("创建批量推送任务失败: " + e.getMessage());
+        }
+    }
+
+    /**
+     * 执行批量推送任务
+     * 全链路：人群圈选 -> 分批拆分 -> MQ异步推送 -> 结果统计
+     *
+     * @param taskId 任务ID
+     * @param traceId 链路追踪ID
+     */
+    public void executeBatchPushTask(String taskId, String traceId) {
+        long startTime = System.currentTimeMillis();
+
+        try {
+            BatchPushTask task = taskRepository.findByTaskId(taskId);
+            if (task == null) {
+                log.error("[批量推送] 任务不存在, traceId={}, taskId={}", traceId, taskId);
+                return;
+            }
+
+            // 幂等控制：检查任务状态，只有CREATED状态才能执行
+            if (task.getStatus() != BatchTaskStatus.CREATED) {
+                log.warn("[批量推送] 任务状态非CREATED，幂等拦截, traceId={}, taskId={}, status={}",
+                    traceId, taskId, task.getStatus());
+                return;
+            }
+
+            // 更新任务状态为执行中
+            task.setStatus(BatchTaskStatus.RUNNING);
+            task.setStartTime(System.currentTimeMillis());
+            taskRepository.save(task);
+
+            pushTraceService.recordTraceNode(traceId, "BATCH_TASK_START", "RUNNING",
+                "taskId=" + taskId);
+
+            // ========== 第1步：人群圈选 ==========
+            List<String> userIds;
+            try {
+                userIds = userSegmentService.queryUsersBySegment(
+                    task.getSegmentId(), task.getTraceId());
+                log.info("[批量推送] 人群圈选完成, traceId={}, taskId={}, segmentId={}, userCount={}",
+                    traceId, taskId, task.getSegmentId(), userIds.size());
+
+                pushTraceService.recordTraceNode(traceId, "USER_SEGMENT", "SUCCESS",
+                    "segmentId=" + task.getSegmentId() + ", userCount=" + userIds.size());
+            } catch (Exception e) {
+                log.error("[批量推送] 人群圈选失败, traceId={}, taskId={}, segmentId={}",
+                    traceId, taskId, task.getSegmentId(), e);
+                task.setStatus(BatchTaskStatus.FAILED);
+                task.setErrorMessage("人群圈选失败: " + e.getMessage());
+                task.setEndTime(System.currentTimeMillis());
+                taskRepository.save(task);
+                return;
+            }
+
+            if (userIds.isEmpty()) {
+                log.warn("[批量推送] 人群圈选结果为空, traceId={}, taskId={}", traceId, taskId);
+                task.setStatus(BatchTaskStatus.COMPLETED);
+                task.setTotalCount(0);
+                task.setSuccessCount(0);
+                task.setFailCount(0);
+                task.setEndTime(System.currentTimeMillis());
+                taskRepository.save(task);
+                return;
+            }
+
+            // ========== 第2步：模板预渲染 ==========
+            RenderedMessage renderedMessage;
+            try {
+                // 批量推送使用统一模板，无个性化变量
+                renderedMessage = templateRenderService.render(task.getTemplateCode(), null);
+            } catch (Exception e) {
+                log.error("[批量推送] 模板渲染失败, traceId={}, taskId={}, templateCode={}",
+                    traceId, taskId, task.getTemplateCode(), e);
+                task.setStatus(BatchTaskStatus.FAILED);
+                task.setErrorMessage("模板渲染失败: " + e.getMessage());
+                task.setEndTime(System.currentTimeMillis());
+                taskRepository.save(task);
+                return;
+            }
+
+            // ========== 第3步：分批推送 ==========
+            // 初始化统计计数器
+            String statsKey = BATCH_STATS_PREFIX + taskId;
+            redisTemplate.opsForValue().set(statsKey + ":total", String.valueOf(userIds.size()));
+            redisTemplate.opsForValue().set(statsKey + ":success", "0");
+            redisTemplate.opsForValue().set(statsKey + ":fail", "0");
+            redisTemplate.opsForValue().set(statsKey + ":delivered", "0");
+
+            int totalBatches = (userIds.size() + BATCH_SIZE - 1) / BATCH_SIZE;
+            log.info("[批量推送] 开始分批推送, traceId={}, taskId={}, totalUsers={}, totalBatches={}",
+                traceId, taskId, userIds.size(), totalBatches);
+
+            for (int batchIndex = 0; batchIndex < totalBatches; batchIndex++) {
+                int fromIndex = batchIndex * BATCH_SIZE;
+                int toIndex = Math.min(fromIndex + BATCH_SIZE, userIds.size());
+                List<String> batchUserIds = userIds.subList(fromIndex, toIndex);
+
+                // 批次幂等控制：每个批次使用独立的幂等Key
+                String batchIdempotentKey = BATCH_IDEMPOTENT_PREFIX + taskId + ":" + batchIndex;
+                Boolean batchIdempotent = redisTemplate.opsForValue()
+                    .setIfAbsent(batchIdempotentKey, "1", BATCH_IDEMPOTENT_HOURS, TimeUnit.HOURS);
+
+                if (batchIdempotent != null && !batchIdempotent) {
+                    log.warn("[批量推送] 批次幂等拦截, traceId={}, taskId={}, batchIndex={}",
+                        traceId, taskId, batchIndex);
+                    continue;
+                }
+
+                // 构建批次推送任务，发送到MQ异步处理
+                BatchPushItem batchItem = new BatchPushItem();
+                batchItem.setTaskId(taskId);
+                batchItem.setBatchIndex(batchIndex);
+                batchItem.setTraceId(traceId);
+                batchItem.setUserIds(batchUserIds);
+                batchItem.setTitle(renderedMessage.getTitle());
+                batchItem.setContent(renderedMessage.getContent());
+                batchItem.setBizType(task.getBizType());
+                batchItem.setStatsKey(statsKey);
+
+                try {
+                    mqTemplate.asyncSend("batch-push-topic", batchItem, new SendCallback() {
+                        @Override
+                        public void onSuccess(SendResult sendResult) {
+                            log.info("[批量推送] 批次发送MQ成功, traceId={}, taskId={}, batchIndex={}",
+                                traceId, taskId, batchIndex);
+                        }
+
+                        @Override
+                        public void onException(Throwable e) {
+                            log.error("[批量推送] 批次发送MQ失败, traceId={}, taskId={}, batchIndex={}",
+                                traceId, taskId, batchIndex, e);
+                            // MQ发送失败，回滚幂等Key，允许重试
+                            redisTemplate.delete(batchIdempotentKey);
+                        }
+                    });
+                } catch (Exception e) {
+                    log.error("[批量推送] 批次MQ发送异常, traceId={}, taskId={}, batchIndex={}",
+                        traceId, taskId, batchIndex, e);
+                    redisTemplate.delete(batchIdempotentKey);
+                }
+            }
+
+            log.info("[批量推送] 所有批次已提交MQ, traceId={}, taskId={}, totalBatches={}",
+                traceId, taskId, totalBatches);
+
+        } catch (Exception e) {
+            log.error("[批量推送] 任务执行异常, traceId={}, taskId={}", traceId, taskId, e);
+            // 更新任务状态为失败
+            try {
+                BatchPushTask task = taskRepository.findByTaskId(taskId);
+                if (task != null && task.getStatus() == BatchTaskStatus.RUNNING) {
+                    task.setStatus(BatchTaskStatus.FAILED);
+                    task.setErrorMessage(e.getMessage());
+                    task.setEndTime(System.currentTimeMillis());
+                    taskRepository.save(task);
+                }
+            } catch (Exception ex) {
+                log.error("[批量推送] 任务状态更新失败, traceId={}, taskId={}", traceId, taskId, ex);
+            }
+        }
+    }
+
+    /**
+     * 批量推送MQ消费者
+     * 消费批次推送消息，执行实际推送并更新统计
+     */
+    @RocketMQMessageListener(topic = "batch-push-topic", consumerGroup = "batch-push-consumer")
+    public class BatchPushListener implements RocketMQListener<BatchPushItem> {
+
+        @Override
+        public void onMessage(BatchPushItem item) {
+            String taskId = item.getTaskId();
+            String traceId = item.getTraceId();
+            String statsKey = item.getStatsKey();
+
+            try {
+                log.info("[批量推送] 批次消费开始, traceId={}, taskId={}, batchIndex={}, userCount={}",
+                    traceId, taskId, item.getBatchIndex(), item.getUserIds().size());
+
+                int batchSuccess = 0;
+                int batchFail = 0;
+                int batchDelivered = 0;
+
+                for (String userId : item.getUserIds()) {
+                    try {
+                        // 查询用户Token
+                        PushToken token = tokenService.getTokenByUserId(userId);
+
+                        if (token == null || token.getStatus() == TokenStatus.INVALID) {
+                            batchFail++;
+                            log.debug("[批量推送] 用户Token无效, traceId={}, userId={}",
+                                traceId, userId);
+                            continue;
+                        }
+
+                        // 选择通道并推送
+                        ChannelAdapter adapter = channelSelector.selectChannel(token);
+                        if (adapter == null) {
+                            batchFail++;
+                            log.debug("[批量推送] 无可用通道, traceId={}, userId={}",
+                                traceId, userId);
+                            continue;
+                        }
+
+                        PushMessage pushMessage = new PushMessage();
+                        pushMessage.setMessageId(IdGenerator.nextId());
+                        pushMessage.setTitle(item.getTitle());
+                        pushMessage.setContent(item.getContent());
+                        pushMessage.setBizType(item.getBizType());
+
+                        PushResult pushResult = adapter.push(pushMessage, token);
+
+                        if (pushResult.isSuccess()) {
+                            batchSuccess++;
+                            batchDelivered++;
+                        } else {
+                            batchFail++;
+                            // 通道降级尝试
+                            if (!"SELF_BUILT".equals(adapter.getChannelType())) {
+                                ChannelAdapter fallback = channelSelector.fallbackChannel(
+                                    token, adapter.getChannelType());
+                                if (fallback != null) {
+                                    PushResult fallbackResult = fallback.push(pushMessage, token);
+                                    if (fallbackResult.isSuccess()) {
+                                        batchSuccess++;
+                                        batchFail--;
+                                        batchDelivered++;
+                                    }
+                                }
+                            }
+                        }
+
+                        // 记录推送结果
+                        pushRecordService.record(
+                            pushMessage.getMessageId(), token.getToken(), pushResult);
+
+                    } catch (Exception e) {
+                        batchFail++;
+                        log.error("[批量推送] 单用户推送异常, traceId={}, userId={}",
+                            traceId, userId, e);
+                    }
+                }
+
+                // 更新统计计数器
+                redisTemplate.opsForValue().increment(statsKey + ":success", batchSuccess);
+                redisTemplate.opsForValue().increment(statsKey + ":fail", batchFail);
+                redisTemplate.opsForValue().increment(statsKey + ":delivered", batchDelivered);
+
+                log.info("[批量推送] 批次消费完成, traceId={}, taskId={}, batchIndex={}, success={}, fail={}, delivered={}",
+                    traceId, taskId, item.getBatchIndex(), batchSuccess, batchFail, batchDelivered);
+
+                // 检查是否所有批次已完成
+                checkBatchTaskCompletion(taskId, traceId);
+
+            } catch (Exception e) {
+                log.error("[批量推送] 批次消费异常, traceId={}, taskId={}, batchIndex={}",
+                    traceId, taskId, item.getBatchIndex(), e);
+            }
+        }
+    }
+
+    /**
+     * 检查批量任务是否全部完成
+     * 当所有批次消费完成后，更新任务状态并生成到达率统计
+     *
+     * @param taskId 任务ID
+     * @param traceId 链路追踪ID
+     */
+    private void checkBatchTaskCompletion(String taskId, String traceId) {
+        try {
+            BatchPushTask task = taskRepository.findByTaskId(taskId);
+            if (task == null || task.getStatus() != BatchTaskStatus.RUNNING) {
+                return;
+            }
+
+            String statsKey = BATCH_STATS_PREFIX + taskId;
+
+            // 读取统计计数
+            int total = Integer.parseInt(
+                redisTemplate.opsForValue().get(statsKey + ":total") != null
+                ? redisTemplate.opsForValue().get(statsKey + ":total") : "0");
+            int success = Integer.parseInt(
+                redisTemplate.opsForValue().get(statsKey + ":success") != null
+                ? redisTemplate.opsForValue().get(statsKey + ":success") : "0");
+            int fail = Integer.parseInt(
+                redisTemplate.opsForValue().get(statsKey + ":fail") != null
+                ? redisTemplate.opsForValue().get(statsKey + ":fail") : "0");
+            int delivered = Integer.parseInt(
+                redisTemplate.opsForValue().get(statsKey + ":delivered") != null
+                ? redisTemplate.opsForValue().get(statsKey + ":delivered") : "0");
+
+            int processed = success + fail;
+
+            // 判断是否全部处理完成
+            if (processed >= total) {
+                // ========== 第4步：到达率统计 ==========
+                double deliveryRate = total > 0 ? (double) delivered / total * 100 : 0;
+                double successRate = total > 0 ? (double) success / total * 100 : 0;
+
+                task.setStatus(BatchTaskStatus.COMPLETED);
+                task.setTotalCount(total);
+                task.setSuccessCount(success);
+                task.setFailCount(fail);
+                task.setDeliveredCount(delivered);
+                task.setDeliveryRate(deliveryRate);
+                task.setSuccessRate(successRate);
+                task.setEndTime(System.currentTimeMillis());
+                taskRepository.save(task);
+
+                log.info("[批量推送] 任务全部完成, traceId={}, taskId={}, total={}, success={}, fail={}, delivered={}, deliveryRate={}%",
+                    traceId, taskId, total, success, fail, delivered,
+                    String.format("%.2f", deliveryRate));
+
+                pushTraceService.recordTraceNode(traceId, "BATCH_TASK_COMPLETE", "SUCCESS",
+                    String.format("total=%d, success=%d, fail=%d, deliveryRate=%.2f%%",
+                        total, success, fail, deliveryRate));
+            }
+        } catch (Exception e) {
+            log.error("[批量推送] 完成检查异常, traceId={}, taskId={}", traceId, taskId, e);
+        }
+    }
+
+    /**
+     * 查询批量推送任务统计结果
+     *
+     * @param taskId 任务ID
+     * @return 任务统计信息
+     */
+    public BatchPushStatistics queryStatistics(String taskId) {
+        String traceId = Tracer.generateTraceId();
+
+        try {
+            log.info("[批量推送] 查询统计, traceId={}, taskId={}", traceId, taskId);
+
+            BatchPushTask task = taskRepository.findByTaskId(taskId);
+            if (task == null) {
+                log.warn("[批量推送] 任务不存在, traceId={}, taskId={}", traceId, taskId);
+                return null;
+            }
+
+            BatchPushStatistics stats = new BatchPushStatistics();
+            stats.setTaskId(taskId);
+            stats.setTaskName(task.getTaskName());
+            stats.setStatus(task.getStatus());
+            stats.setTotalCount(task.getTotalCount());
+            stats.setSuccessCount(task.getSuccessCount());
+            stats.setFailCount(task.getFailCount());
+            stats.setDeliveredCount(task.getDeliveredCount());
+            stats.setDeliveryRate(task.getDeliveryRate());
+            stats.setSuccessRate(task.getSuccessRate());
+            stats.setStartTime(task.getStartTime());
+            stats.setEndTime(task.getEndTime());
+
+            // 如果任务还在执行中，从Redis读取实时统计
+            if (task.getStatus() == BatchTaskStatus.RUNNING) {
+                String statsKey = BATCH_STATS_PREFIX + taskId;
+                String realTimeSuccess = redisTemplate.opsForValue().get(statsKey + ":success");
+                String realTimeFail = redisTemplate.opsForValue().get(statsKey + ":fail");
+                String realTimeDelivered = redisTemplate.opsForValue().get(statsKey + ":delivered");
+
+                if (realTimeSuccess != null) {
+                    stats.setSuccessCount(Integer.parseInt(realTimeSuccess));
+                }
+                if (realTimeFail != null) {
+                    stats.setFailCount(Integer.parseInt(realTimeFail));
+                }
+                if (realTimeDelivered != null) {
+                    stats.setDeliveredCount(Integer.parseInt(realTimeDelivered));
+                }
+
+                int processed = stats.getSuccessCount() + stats.getFailCount();
+                if (stats.getTotalCount() > 0) {
+                    stats.setDeliveryRate(
+                        (double) stats.getDeliveredCount() / stats.getTotalCount() * 100);
+                    stats.setSuccessRate(
+                        (double) stats.getSuccessCount() / stats.getTotalCount() * 100);
+                }
+
+                log.info("[批量推送] 实时统计, traceId={}, taskId={}, processed={}, total={}",
+                    traceId, taskId, processed, stats.getTotalCount());
+            }
+
+            return stats;
+
+        } catch (Exception e) {
+            log.error("[批量推送] 查询统计异常, traceId={}, taskId={}", traceId, taskId, e);
+            return null;
+        }
+    }
