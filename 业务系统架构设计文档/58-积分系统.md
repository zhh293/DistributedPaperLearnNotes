# 积分系统架构设计

## 一、问题背景

### 1.1 业务场景

积分系统是用户忠诚度运营的核心工具。用户通过消费、签到、评价等行为获取积分，积分可以在下单时抵扣现金、兑换商品或参与活动。积分本质上是平台发行的"虚拟货币"，因此资金安全和并发一致性是核心关注点。

一个完整的积分生命周期：用户行为触发积分发放 → 积分入账（可用积分增加）→ 用户使用积分（抵扣/兑换）→ 积分扣减 → 过期积分清零。

### 1.2 核心挑战

| 挑战维度 | 具体问题 |
|---------|---------|
| 并发安全 | 多笔订单同时抵扣积分，如何防超扣 |
| 资金安全 | 积分等价于现金，不能多发、不能少扣 |
| 过期清零 | 大量积分同时过期，如何平滑处理 |
| 高性能 | 每次下单都要查积分余额，QPS极高 |
| 幂等 | 积分发放和扣减都要防重 |
| 对账 | 积分流水必须与余额一致 |

### 2.2 积分账户模型

采用"批次"模型而非"余额"模型——每次发放的积分作为一个独立批次，有独立的过期时间。扣减时按批次FIFO扣减。

```sql
-- 积分账户表
CREATE TABLE point_account (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL UNIQUE,
    total_points BIGINT DEFAULT 0 COMMENT '累计获得积分',
    available_points BIGINT DEFAULT 0 COMMENT '可用积分',
    frozen_points BIGINT DEFAULT 0 COMMENT '冻结积分（预扣）',
    used_points BIGINT DEFAULT 0 COMMENT '已使用积分',
    expired_points BIGINT DEFAULT 0 COMMENT '已过期积分',
    create_time DATETIME,
    update_time DATETIME,
    UNIQUE KEY uk_user (user_id)
) ENGINE=InnoDB;

-- 积分批次表（每次发放一个批次）
CREATE TABLE point_batch (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    batch_id VARCHAR(32) NOT NULL,
    source VARCHAR(32) NOT NULL COMMENT '来源: ORDER/SIGNIN/REVIEW/ACTIVITY',
    biz_id VARCHAR(64) NOT NULL COMMENT '业务单号',
    total_points BIGINT NOT NULL COMMENT '批次总积分',
    remaining_points BIGINT NOT NULL COMMENT '批次剩余积分',
    expire_time DATETIME NOT NULL COMMENT '过期时间',
    status TINYINT DEFAULT 1 COMMENT '1有效 0已过期 2已用完',
    create_time DATETIME,
    UNIQUE KEY uk_batch (batch_id),
    INDEX idx_user_expire (user_id, expire_time, status)
) ENGINE=InnoDB;

-- 积分流水表
CREATE TABLE point_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    log_type VARCHAR(16) NOT NULL COMMENT 'EARN(获得) DEDUCT(扣减) FREEZE(冻结) UNFREEZE(解冻) EXPIRE(过期)',
    points BIGINT NOT NULL COMMENT '积分数量（正数）',
    before_points BIGINT NOT NULL,
    after_points BIGINT NOT NULL,
    source VARCHAR(32) NOT NULL COMMENT '来源',
    biz_id VARCHAR(64) NOT NULL COMMENT '业务单号',
    batch_id VARCHAR(32) COMMENT '关联批次ID（扣减时）',
    create_time DATETIME,
    UNIQUE KEY uk_biz (source, biz_id, log_type),
    INDEX idx_user (user_id)
) ENGINE=InnoDB;
```

## 三、核心链路设计

### 3.1 积分发放

```java
/**
 * 积分发放服务
 *
 * 完整链路：
 * 1. 接收发放请求（订单完成/签到/评价等）
 * 2. 流水防重检查
 * 3. 创建积分批次
 * 4. 更新积分账户余额
 * 5. 异步通知用户
 */
@Service
public class PointEarnService {

    @Autowired
    private PointAccountMapper accountMapper;

    @Autowired
    private PointBatchMapper batchMapper;

    @Autowired
    private PointLogMapper logMapper;

    /**
     * 发放积分
     */
    @Transactional(rollbackFor = Exception.class)
    public void earn(EarnRequest request) {
        // 1. 流水防重
        PointLog existLog = logMapper.selectByBiz(
            request.getSource(), request.getBizId(), "EARN");
        if (existLog != null) {
            return; // 已处理
        }

        // 2. 查询账户
        PointAccount account = accountMapper.selectByUserId(request.getUserId());
        if (account == null) {
            account = createAccount(request.getUserId());
        }

        // 3. 创建积分批次
        String batchId = "PB" + idGenerator.nextId();
        PointBatch batch = new PointBatch();
        batch.setUserId(request.getUserId());
        batch.setBatchId(batchId);
        batch.setSource(request.getSource());
        batch.setBizId(request.getBizId());
        batch.setTotalPoints(request.getPoints());
        batch.setRemainingPoints(request.getPoints());
        batch.setExpireTime(calculateExpireTime(request.getSource()));
        batch.setStatus(1);
        batch.setCreateTime(new Date());
        batchMapper.insert(batch);

        // 4. 更新账户余额（乐观锁）
        long beforePoints = account.getAvailablePoints();
        long afterPoints = beforePoints + request.getPoints();
        int updated = accountMapper.updateAvailablePoints(
            request.getUserId(), afterPoints, beforePoints);

        if (updated == 0) {
            throw new RuntimeException("积分发放并发冲突，重试");
        }

        // 5. 记录流水
        PointLog log = new PointLog();
        log.setUserId(request.getUserId());
        log.setLogType("EARN");
        log.setPoints(request.getPoints());
        log.setBeforePoints(beforePoints);
        log.setAfterPoints(afterPoints);
        log.setSource(request.getSource());
        log.setBizId(request.getBizId());
        log.setBatchId(batchId);
        log.setCreateTime(new Date());
        logMapper.insert(log);

        log.info("积分发放成功, userId={}, points={}, source={}",
            request.getUserId(), request.getPoints(), request.getSource());
    }

    /**
     * 计算过期时间
     * 订单积分：1年过期
     * 签到积分：当月过期
     * 活动积分：按活动配置
     */
    private Date calculateExpireTime(String source) {
        switch (source) {
            case "ORDER":
                return DateUtils.addYears(new Date(), 1);
            case "SIGNIN":
                return DateUtils.addMonths(new Date(), 1);
            case "ACTIVITY":
                return DateUtils.addDays(new Date(), 90);
            default:
                return DateUtils.addYears(new Date(), 1);
        }
    }
}
```

### 3.2 积分扣减（下单抵扣）

**问题**：用户下单用1000积分抵扣10元，如何保证不超扣？如何处理多批次积分？

**方案**：预扣 → 确认扣减 / 取消解冻。扣减时按批次FIFO（先进先出）扣减，优先扣减快过期的批次。

```java
/**
 * 积分扣减服务
 *
 * 完整链路：
 * 1. 下单时预扣（冻结）
 *    a. 检查可用积分是否充足
 *    b. 按批次FIFO冻结积分
 *    c. 更新账户：可用减少，冻结增加
 * 2. 支付成功后确认扣减
 *    a. 将冻结积分转为已使用
 *    b. 扣减批次剩余积分
 * 3. 取消订单时解冻
 *    a. 将冻结积分恢复为可用
 *    b. 恢复批次剩余积分
 */
@Service
public class PointDeductService {

    /**
     * 预扣积分（下单时冻结）
     */
    @Transactional(rollbackFor = Exception.class)
    public FreezeResult freeze(Long userId, int points, Long orderId) {
        // 1. 流水防重
        PointLog existLog = logMapper.selectByBiz("ORDER", String.valueOf(orderId), "FREEZE");
        if (existLog != null) {
            return FreezeResult.alreadyFrozen();
        }

        // 2. 查询账户
        PointAccount account = accountMapper.selectByUserId(userId);
        if (account.getAvailablePoints() < points) {
            return FreezeResult.fail("积分不足");
        }

        // 3. 查询可用批次（按过期时间排序，优先扣快过期的）
        List<PointBatch> batches = batchMapper.selectAvailableByUser(userId);
        int remainingToFreeze = points;
        List<BatchFreezeDetail> freezeDetails = new ArrayList<>();

        for (PointBatch batch : batches) {
            if (remainingToFreeze <= 0) break;

            int freezeFromBatch = Math.min(
                batch.getRemainingPoints(), remainingToFreeze);

            // 扣减批次剩余积分
            batchMapper.deductRemaining(
                batch.getBatchId(), freezeFromBatch, batch.getRemainingPoints());

            freezeDetails.add(new BatchFreezeDetail(
                batch.getBatchId(), freezeFromBatch));
            remainingToFreeze -= freezeFromBatch;
        }

        if (remainingToFreeze > 0) {
            throw new RuntimeException("积分批次扣减不完整，数据异常");
        }

        // 4. 更新账户（乐观锁）
        long beforeAvailable = account.getAvailablePoints();
        long afterAvailable = beforeAvailable - points;
        long afterFrozen = account.getFrozenPoints() + points;
        accountMapper.freezePoints(userId, afterAvailable, afterFrozen,
            beforeAvailable);

        // 5. 记录冻结流水
        PointLog log = new PointLog();
        log.setUserId(userId);
        log.setLogType("FREEZE");
        log.setPoints(points);
        log.setBeforePoints(beforeAvailable);
        log.setAfterPoints(afterAvailable);
        log.setSource("ORDER");
        log.setBizId(String.valueOf(orderId));
        log.setCreateTime(new Date());
        logMapper.insert(log);

        // 6. 记录冻结明细（用于解冻时恢复）
        for (BatchFreezeDetail detail : freezeDetails) {
            freezeDetailMapper.insert(new PointFreezeDetail(
                userId, orderId, detail.getBatchId(), detail.getPoints()));
        }

        return FreezeResult.success();
    }

    /**
     * 确认扣减（支付成功后）
     */
    @Transactional(rollbackFor = Exception.class)
    public void confirmDeduct(Long userId, int points, Long orderId) {
        // 1. 流水防重
        PointLog existLog = logMapper.selectByBiz("ORDER",
            String.valueOf(orderId), "DEDUCT");
        if (existLog != null) {
            return;
        }

        // 2. 更新账户：冻结减少，已使用增加
        PointAccount account = accountMapper.selectByUserId(userId);
        long afterFrozen = account.getFrozenPoints() - points;
        long afterUsed = account.getUsedPoints() + points;
        accountMapper.confirmDeduct(userId, afterFrozen, afterUsed,
            account.getFrozenPoints());

        // 3. 记录扣减流水
        PointLog log = new PointLog();
        log.setUserId(userId);
        log.setLogType("DEDUCT");
        log.setPoints(points);
        log.setBeforePoints(account.getAvailablePoints());
        log.setAfterPoints(account.getAvailablePoints());
        log.setSource("ORDER");
        log.setBizId(String.valueOf(orderId));
        log.setCreateTime(new Date());
        logMapper.insert(log);
    }

    /**
     * 解冻（取消订单时）
     */
    @Transactional(rollbackFor = Exception.class)
    public void unfreeze(Long userId, int points, Long orderId) {
        // 1. 流水防重
        PointLog existLog = logMapper.selectByBiz("ORDER",
            String.valueOf(orderId), "UNFREEZE");
        if (existLog != null) {
            return;
        }

        // 2. 查询冻结明细
        List<PointFreezeDetail> details = freezeDetailMapper
            .selectByOrder(orderId);

        // 3. 恢复批次剩余积分
        for (PointFreezeDetail detail : details) {
            batchMapper.restoreRemaining(detail.getBatchId(), detail.getPoints());
        }

        // 4. 更新账户：冻结减少，可用增加
        PointAccount account = accountMapper.selectByUserId(userId);
        long afterFrozen = account.getFrozenPoints() - points;
        long afterAvailable = account.getAvailablePoints() + points;
        accountMapper.unfreezePoints(userId, afterAvailable, afterFrozen,
            account.getFrozenPoints());

        // 5. 记录解冻流水
        PointLog log = new PointLog();
        log.setUserId(userId);
        log.setLogType("UNFREEZE");
        log.setPoints(points);
        log.setBeforePoints(account.getAvailablePoints());
        log.setAfterPoints(afterAvailable);
        log.setSource("ORDER");
        log.setBizId(String.valueOf(orderId));
        log.setCreateTime(new Date());
        logMapper.insert(log);
    }
}
```

### 3.3 积分过期清零

**问题**：大量积分批次同时过期，直接处理会导致DB压力骤增。

**方案**：分批扫描 + 分批处理。

```java
/**
 * 积分过期清零服务
 *
 * 策略：
 * 1. 每小时扫描已过期但状态仍为有效的批次
 * 2. 分批处理（每批100个）
 * 3. 更新批次状态 + 扣减账户余额
 */
@Service
public class PointExpireService {

    @Scheduled(cron = "0 0 * * * ?")  // 每小时
    public void processExpiredPoints() {
        int pageSize = 100;
        int offset = 0;

        while (true) {
            List<PointBatch> expired = batchMapper.selectExpired(
                new Date(), offset, pageSize);
            if (expired.isEmpty()) break;

            for (PointBatch batch : expired) {
                try {
                    expireBatch(batch);
                } catch (Exception e) {
                    log.error("积分过期处理失败, batchId={}",
                        batch.getBatchId(), e);
                }
            }

            offset += pageSize;
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void expireBatch(PointBatch batch) {
        // 1. 更新批次状态
        batchMapper.updateStatus(batch.getBatchId(), 0); // 过期

        // 2. 扣减账户可用积分
        PointAccount account = accountMapper.selectByUserId(batch.getUserId());
        long afterAvailable = account.getAvailablePoints() - batch.getRemainingPoints();
        long afterExpired = account.getExpiredPoints() + batch.getRemainingPoints();
        accountMapper.expirePoints(batch.getUserId(),
            afterAvailable, afterExpired, account.getAvailablePoints());

        // 3. 记录过期流水
        PointLog log = new PointLog();
        log.setUserId(batch.getUserId());
        log.setLogType("EXPIRE");
        log.setPoints(batch.getRemainingPoints());
        log.setBeforePoints(account.getAvailablePoints());
        log.setAfterPoints(afterAvailable);
        log.setSource("EXPIRE");
        log.setBizId(batch.getBatchId());
        log.setCreateTime(new Date());
        logMapper.insert(log);
    }
}
```

### 3.4 积分余额查询

```java
/**
 * 积分查询服务
 *
 * 高频查询，走Redis缓存
 */
@Service
public class PointQueryService {

    public PointAccountVO queryAccount(Long userId) {
        // 1. 查缓存
        String key = "point:account:" + userId;
        String cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return JSON.parseObject(cached, PointAccountVO.class);
        }

        // 2. 查DB
        PointAccount account = accountMapper.selectByUserId(userId);
        if (account == null) {
            return PointAccountVO.empty();
        }

        PointAccountVO vo = new PointAccountVO();
        vo.setAvailablePoints(account.getAvailablePoints());
        vo.setFrozenPoints(account.getFrozenPoints());
        vo.setTotalPoints(account.getTotalPoints());
        vo.setUsedPoints(account.getUsedPoints());

        // 3. 查询即将过期的积分
        int expiringSoon = batchMapper.sumExpiringSoon(
            userId, DateUtils.addDays(new Date(), 30));
        vo.setExpiringSoon(expiringSoon);

        // 4. 回填缓存
        redisTemplate.opsForValue().set(key,
            JSON.toJSONString(vo), 5, TimeUnit.MINUTES);

        return vo;
    }
}
```

## 四、积分抵扣规则引擎

```java
/**
 * 积分抵扣规则
 *
 * 规则配置：
 * 1. 兑换比例：100积分 = 1元
 * 2. 最低使用数量：100积分起用
 * 3. 最大抵扣比例：订单金额的50%
 * 4. 会员倍率：金卡x1.2, 白金x1.5, 钻石x2（抵扣时更划算）
 */
@Service
public class PointDeductRuleEngine {

    @Autowired
    private MemberCacheService memberService;

    /**
     * 计算可用积分抵扣金额
     */
    public DeductCalculation calculate(Long userId, int userPoints,
                                        BigDecimal orderAmount) {
        // 1. 获取会员等级倍率
        MemberLevelInfo levelInfo = memberService.getLevelInfo(userId);
        BigDecimal memberRate = levelInfo.getPointDeductRate();

        // 2. 计算最大可抵扣金额（订单金额 × 最大比例）
        BigDecimal maxDeductAmount = orderAmount.multiply(
            new BigDecimal("0.5")); // 最多抵50%

        // 3. 计算用户积分可抵扣金额
        // 基础比例：100积分=1元，乘以会员倍率
        BigDecimal userPointsValue = new BigDecimal(userPoints)
            .divide(new BigDecimal("100"), 2, RoundingMode.DOWN)
            .multiply(memberRate);

        // 4. 取最小值
        BigDecimal actualDeductAmount = userPointsValue.min(maxDeductAmount);

        // 5. 反算需要扣减的积分
        int needPoints = actualDeductAmount
            .divide(memberRate, 2, RoundingMode.DOWN)
            .multiply(new BigDecimal("100"))
            .intValue();

        // 6. 最低使用数量校验
        if (needPoints < 100) {
            return DeductCalculation.empty();
        }

        DeductCalculation result = new DeductCalculation();
        result.setDeductPoints(needPoints);
        result.setDeductAmount(actualDeductAmount);
        result.setMemberRate(memberRate);
        return result;
    }
}
```

## 五、异常处理与对账

### 5.1 积分对账

```java
/**
 * 积分对账定时任务
 *
 * 对账公式：
 * 可用积分 = sum(有效批次.remaining_points)
 * 冻结积分 = sum(冻结明细.points where status=FROZEN)
 * 已用积分 = sum(流水.points where log_type=DEDUCT)
 */
@Scheduled(cron = "0 0 4 * * ?")
public void reconcile() {
    int pageSize = 1000;
    int offset = 0;

    while (true) {
        List<PointAccount> accounts = accountMapper.selectBatch(offset, pageSize);
        if (accounts.isEmpty()) break;

        for (PointAccount account : accounts) {
            // 可用积分校验
            Long batchSum = batchMapper.sumAvailableByUser(account.getUserId());
            if (batchSum == null) batchSum = 0L;

            if (!batchSum.equals(account.getAvailablePoints())) {
                log.error("积分不一致! userId={}, account={}, batchSum={}",
                    account.getUserId(), account.getAvailablePoints(), batchSum);

                // 以批次合计为准修正
                accountMapper.updateAvailablePoints(
                    account.getUserId(), batchSum,
                    account.getAvailablePoints());
            }
        }
        offset += pageSize;
    }
}
```

## 六、最佳实践与总结

### 6.1 核心设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 积分模型 | 批次模型 | 支持分批过期、FIFO扣减 |
| 扣减策略 | FIFO + 优先快过期 | 减少用户积分过期损失 |
| 预扣机制 | 冻结→确认/解冻 | 与订单状态联动 |
| 并发安全 | 乐观锁 | 高并发场景 |
| 防重 | 流水表唯一索引 | 幂等保证 |
| 过期处理 | 分批定时扫描 | 避免集中处理压力 |

### 6.2 容易踩的坑

1. **批次扣减不完整**：多批次扣减时部分成功部分失败，需要事务保证
2. **解冻恢复错误**：解冻时没有恢复到原始批次，导致批次数据错乱
3. **过期积分未扣余额**：只更新了批次状态但忘记扣减账户余额
4. **并发超扣**：预扣和确认之间用户又用了积分，需要冻结机制隔离
5. **对账遗漏**：只对余额不对批次明细，无法发现批次级别的不一致

## 七、全链路实战案例

前面章节介绍了积分系统的核心组件与算法，本章通过三个贴近真实生产环境的全链路案例，串联"发放→抵扣→过期"三大主链路的完整代码实现，覆盖MQ消费、幂等控制、分布式锁、批量处理与对账等工程细节。

### 7.1 案例一：用户消费获得积分全链路

#### 7.1.2 积分计算规则引擎（品类倍率）

不同品类的积分倍率、以及大促期间的加权倍率，通过规则引擎统一计算，避免倍率逻辑散落在各处。

```java
/**
 * 积分计算规则引擎
 *
 * 规则来源（优先级从高到低，可叠加）：
 * 1. 基础规则：消费金额(元) × 基础倍率(1倍/元 = 1积分)
 * 2. 品类倍率：不同品类设置不同的加权倍率
 * 3. 活动倍率：大促期间品类倍率可叠加活动加权
 * 4. 会员倍率：不同会员等级享受额外倍率加成
 *
 * 最终积分 = floor(金额 × 品类倍率 × 活动倍率 × 会员倍率)
 */
@Service
public class PointCalculateRuleEngine {

    private static final Logger log = LoggerFactory.getLogger(PointCalculateRuleEngine.class);

    /** 品类倍率配置，实际应从配置中心/DB加载，此处示例硬编码默认值 */
    private static final Map<String, BigDecimal> CATEGORY_RATE = new ConcurrentHashMap<>();
    static {
        CATEGORY_RATE.put("3C_DIGITAL", new BigDecimal("1.0"));   // 3C数码：1倍
        CATEGORY_RATE.put("FRESH_FOOD", new BigDecimal("2.0"));   // 生鲜：2倍（引流品类）
        CATEGORY_RATE.put("BEAUTY", new BigDecimal("1.5"));       // 美妆：1.5倍
        CATEGORY_RATE.put("DEFAULT", new BigDecimal("1.0"));      // 默认：1倍
    }

    @Autowired
    private ActivityRateService activityRateService;

    @Autowired
    private MemberCacheService memberService;

    /**
     * 计算订单应得积分
     *
     * @param userId    用户ID
     * @param orderId   订单ID
     * @param itemList  订单明细（每个明细独立品类，分别计算后累加，更贴近真实场景）
     * @return 应得积分（向下取整，避免小数积分）
     */
    public PointCalculateResult calculate(Long userId, Long orderId, List<OrderItem> itemList) {
        if (CollectionUtils.isEmpty(itemList)) {
            log.warn("订单明细为空，无法计算积分, orderId={}", orderId);
            return PointCalculateResult.zero(orderId);
        }

        try {
            // 会员倍率对整单生效
            MemberLevelInfo levelInfo = memberService.getLevelInfo(userId);
            BigDecimal memberRate = levelInfo != null ? levelInfo.getPointEarnRate() : BigDecimal.ONE;

            long totalPoints = 0;
            List<PointCalculateDetail> details = new ArrayList<>();

            for (OrderItem item : itemList) {
                // 1. 品类基础倍率
                BigDecimal categoryRate = CATEGORY_RATE.getOrDefault(
                    item.getCategory(), CATEGORY_RATE.get("DEFAULT"));

                // 2. 活动加权倍率（大促期间可能返回1.0以外的值，查询失败降级为1.0，不影响主流程）
                BigDecimal activityRate;
                try {
                    activityRate = activityRateService.getPointActivityRate(item.getCategory());
                } catch (Exception e) {
                    log.warn("查询活动倍率失败，降级为默认倍率1.0, category={}", item.getCategory(), e);
                    activityRate = BigDecimal.ONE;
                }

                // 3. 单品应得积分 = 实付金额 × 品类倍率 × 活动倍率 × 会员倍率
                BigDecimal itemPoints = item.getPayAmount()
                    .multiply(categoryRate)
                    .multiply(activityRate)
                    .multiply(memberRate)
                    .setScale(0, RoundingMode.DOWN); // 向下取整，防止平台超发

                totalPoints += itemPoints.longValue();

                details.add(new PointCalculateDetail(
                    item.getItemId(), item.getCategory(), categoryRate,
                    activityRate, memberRate, itemPoints.longValue()));
            }

            log.info("积分计算完成, orderId={}, userId={}, totalPoints={}, memberRate={}",
                orderId, userId, totalPoints, memberRate);

            return PointCalculateResult.of(orderId, totalPoints, details);
        } catch (Exception e) {
            // 规则引擎异常不应阻塞主流程发放兜底积分，记录告警由人工介入
            log.error("积分计算异常，进入兜底逻辑, orderId={}, userId={}", orderId, userId, e);
            return PointCalculateResult.zero(orderId);
        }
    }
}
```

#### 7.1.3 MQ消费触发积分发放（幂等 + Redis/DB双写）

```java
/**
 * 订单支付成功 -> 积分发放 MQ消费者
 *
 * 幂等设计（三层保障）：
 * 1. MQ消费幂等表：按 messageId 去重，防止MQ重复投递
 * 2. 业务幂等：积分流水表 (source, biz_id, log_type) 唯一索引，防止重复发放
 * 3. Redis分布式锁：防止同一订单被并发消费（多消费者实例场景）
 */
@Component
@RocketMQMessageListener(topic = "order-pay-success", consumerGroup = "point-earn-consumer")
public class OrderPaySuccessListener implements RocketMQListener<OrderPayMessage> {

    private static final Logger log = LoggerFactory.getLogger(OrderPaySuccessListener.class);

    @Autowired
    private MqConsumeRecordMapper consumeRecordMapper;

    @Autowired
    private PointCalculateRuleEngine ruleEngine;

    @Autowired
    private PointEarnService pointEarnService;

    @Autowired
    private OrderQueryService orderQueryService;

    @Autowired
    private RedissonClient redissonClient;

    @Autowired
    private PointNotifyService notifyService;

    @Override
    public void onMessage(OrderPayMessage message) {
        String messageId = message.getMessageId();
        Long orderId = message.getOrderId();
        Long userId = message.getUserId();

        // 第1层幂等：MQ消息级别去重
        if (consumeRecordMapper.exists(messageId)) {
            log.info("消息已消费过，忽略, messageId={}, orderId={}", messageId, orderId);
            return;
        }

        // 第3层：分布式锁防止同一订单被并发消费者同时处理
        RLock lock = redissonClient.getLock("lock:point:earn:order:" + orderId);
        boolean locked = false;
        try {
            locked = lock.tryLock(3, 10, TimeUnit.SECONDS);
            if (!locked) {
                // 拿不到锁说明有其他线程正在处理，抛异常触发MQ重试
                throw new BizRetryableException("获取积分发放锁失败，触发重试, orderId=" + orderId);
            }

            // 幂等：加锁后二次确认，防止等锁期间已被处理完
            if (consumeRecordMapper.exists(messageId)) {
                log.info("加锁后二次确认消息已消费, messageId={}", messageId);
                return;
            }

            doEarnPoints(orderId, userId, messageId);

        } catch (BizRetryableException e) {
            log.warn(e.getMessage());
            throw e; // 让MQ框架按重试策略重投
        } catch (Exception e) {
            log.error("积分发放消费异常, orderId={}, messageId={}", orderId, messageId, e);
            // 未知异常也交给MQ重试机制，重试N次后进入死信队列，由人工/补偿任务处理
            throw new RuntimeException("积分发放失败", e);
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    /**
     * 执行积分发放核心逻辑，Redis预更新 + DB事务写，保证最终一致
     */
    private void doEarnPoints(Long orderId, Long userId, String messageId) {
        // 1. 查询订单明细（品类、实付金额）
        List<OrderItem> items = orderQueryService.queryOrderItems(orderId);
        if (CollectionUtils.isEmpty(items)) {
            log.warn("订单明细为空，跳过积分发放, orderId={}", orderId);
            markMessageConsumed(messageId, orderId, "SKIP_NO_ITEMS");
            return;
        }

        // 2. 规则引擎计算积分
        PointCalculateResult result = ruleEngine.calculate(userId, orderId, items);
        if (result.getTotalPoints() <= 0) {
            log.info("计算积分为0，跳过发放, orderId={}", orderId);
            markMessageConsumed(messageId, orderId, "SKIP_ZERO_POINT");
            return;
        }

        // 3. 调用发放服务（DB事务内完成：批次创建 + 账户更新 + 流水记录）
        EarnRequest request = new EarnRequest();
        request.setUserId(userId);
        request.setSource("ORDER");
        request.setBizId(String.valueOf(orderId));
        request.setPoints(result.getTotalPoints());
        pointEarnService.earn(request);

        // 4. Redis 余额缓存双写：DB提交成功后再更新缓存，避免脏读窗口过长
        //    采用"先更新DB，再删缓存"（Cache-Aside），下一次查询时自然回源加载最新值
        try {
            redisTemplate.delete("point:account:" + userId);
        } catch (Exception e) {
            // Redis异常不影响主流程，缓存会因TTL过期自动兜底一致
            log.warn("清理积分余额缓存失败，等待TTL自然过期兜底, userId={}", userId, e);
        }

        // 5. 记录MQ消费成功标记（业务幂等表），确保消费记录与积分发放在逻辑上绑定
        markMessageConsumed(messageId, orderId, "SUCCESS");

        // 6. 异步通知用户积分到账（失败不影响主流程，走独立异常捕获）
        try {
            notifyService.notifyPointEarned(userId, result.getTotalPoints(), orderId);
        } catch (Exception e) {
            log.error("积分到账通知发送失败，不影响积分发放结果, userId={}, orderId={}",
                userId, orderId, e);
        }

        log.info("订单积分发放全链路完成, orderId={}, userId={}, points={}",
            orderId, userId, result.getTotalPoints());
    }

    private void markMessageConsumed(String messageId, Long orderId, String result) {
        try {
            MqConsumeRecord record = new MqConsumeRecord();
            record.setMessageId(messageId);
            record.setBizId(String.valueOf(orderId));
            record.setConsumeResult(result);
            record.setConsumeTime(new Date());
            consumeRecordMapper.insert(record);
        } catch (DuplicateKeyException e) {
            // 并发写入幂等表冲突，说明已被其他线程标记，忽略即可
            log.info("消费记录已存在，忽略重复插入, messageId={}", messageId);
        }
    }
}
```

#### 7.1.4 退款时积分扣回

用户退款时，已发放的积分需要按"原路扣回"。若用户已将这部分积分消费掉（余额不足），则不能强行扣成负数，而是记录"积分欠款"，后续用户再获得积分时优先冲抵欠款。

```java
/**
 * 订单退款 -> 积分扣回 MQ消费者
 *
 * 核心难点：退款时积分可能已被用户花掉了，此时不能简单地扣减，
 * 需要引入"欠款"机制：能扣多少扣多少，扣不够的部分记为负债，
 * 后续该用户新增积分时优先偿还负债。
 */
@Component
@RocketMQMessageListener(topic = "order-refund-success", consumerGroup = "point-refund-consumer")
public class OrderRefundListener implements RocketMQListener<OrderRefundMessage> {

    private static final Logger log = LoggerFactory.getLogger(OrderRefundListener.class);

    @Autowired
    private MqConsumeRecordMapper consumeRecordMapper;

    @Autowired
    private PointAccountMapper accountMapper;

    @Autowired
    private PointBatchMapper batchMapper;

    @Autowired
    private PointLogMapper logMapper;

    @Autowired
    private PointDebtMapper debtMapper;

    @Override
    public void onMessage(OrderRefundMessage message) {
        String messageId = message.getMessageId();
        Long orderId = message.getOrderId();

        if (consumeRecordMapper.exists(messageId)) {
            log.info("退款扣回消息已处理，忽略, messageId={}", messageId);
            return;
        }

        try {
            // 幂等：查是否已对该订单执行过扣回（防止MQ重复投递导致重复扣回）
            PointLog existLog = logMapper.selectByBiz("ORDER_REFUND",
                String.valueOf(orderId), "DEDUCT_BACK");
            if (existLog != null) {
                log.info("该订单已执行过积分扣回，跳过, orderId={}", orderId);
                markConsumed(messageId, orderId);
                return;
            }

            deductBack(message.getUserId(), orderId, message.getRefundPoints());
            markConsumed(messageId, orderId);

        } catch (Exception e) {
            log.error("积分退款扣回处理异常, orderId={}", orderId, e);
            throw new RuntimeException("积分扣回失败，触发MQ重试", e);
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void deductBack(Long userId, Long orderId, long refundPoints) {
        PointAccount account = accountMapper.selectByUserId(userId);
        if (account == null) {
            log.warn("用户积分账户不存在，无法扣回, userId={}, orderId={}", userId, orderId);
            return;
        }

        // 实际可扣回的积分 = min(该订单发放的积分, 当前账户可用积分)
        long actualDeduct = Math.min(refundPoints, account.getAvailablePoints());
        long debtPoints = refundPoints - actualDeduct; // 扣不够的部分转为欠款

        if (actualDeduct > 0) {
            // 按FIFO从批次中扣减（复用积分扣减批次逻辑）
            List<PointBatch> batches = batchMapper.selectAvailableByUser(userId);
            long remaining = actualDeduct;
            for (PointBatch batch : batches) {
                if (remaining <= 0) break;
                long deductFromBatch = Math.min(batch.getRemainingPoints(), remaining);
                int updated = batchMapper.deductRemaining(
                    batch.getBatchId(), deductFromBatch, batch.getRemainingPoints());
                if (updated == 0) {
                    // 批次被并发修改，跳过本批次尝试下一个，最终若仍扣不完计入欠款而非抛异常阻塞退款
                    continue;
                }
                remaining -= deductFromBatch;
            }
            actualDeduct -= remaining; // 若并发冲突导致部分未扣成功，差额同样计入欠款
            debtPoints += remaining;

            long beforeAvailable = account.getAvailablePoints();
            long afterAvailable = beforeAvailable - actualDeduct;
            int updated = accountMapper.updateAvailablePoints(userId, afterAvailable, beforeAvailable);
            if (updated == 0) {
                throw new RuntimeException("积分扣回账户更新并发冲突，触发重试, userId=" + userId);
            }

            PointLog log0 = new PointLog();
            log0.setUserId(userId);
            log0.setLogType("DEDUCT_BACK");
            log0.setPoints(actualDeduct);
            log0.setBeforePoints(beforeAvailable);
            log0.setAfterPoints(afterAvailable);
            log0.setSource("ORDER_REFUND");
            log0.setBizId(String.valueOf(orderId));
            log0.setCreateTime(new Date());
            logMapper.insert(log0);
        }

        // 扣不够的部分记为积分欠款，等待后续积分发放时自动冲抵
        if (debtPoints > 0) {
            PointDebt debt = new PointDebt();
            debt.setUserId(userId);
            debt.setBizId(String.valueOf(orderId));
            debt.setDebtPoints(debtPoints);
            debt.setRemainingDebt(debtPoints);
            debt.setStatus(1); // 未结清
            debt.setCreateTime(new Date());
            debtMapper.insert(debt);

            log.warn("用户积分不足以全额扣回，记录积分欠款, userId={}, orderId={}, debtPoints={}",
                userId, orderId, debtPoints);
        }

        log.info("退款积分扣回完成, userId={}, orderId={}, actualDeduct={}, debtPoints={}",
            userId, orderId, actualDeduct, debtPoints);
    }

    private void markConsumed(String messageId, Long orderId) {
        try {
            MqConsumeRecord record = new MqConsumeRecord();
            record.setMessageId(messageId);
            record.setBizId(String.valueOf(orderId));
            record.setConsumeResult("SUCCESS");
            record.setConsumeTime(new Date());
            consumeRecordMapper.insert(record);
        } catch (DuplicateKeyException e) {
            log.info("消费记录重复插入，忽略, messageId={}", messageId);
        }
    }
}
```

```sql
-- 积分欠款表（退款扣回不足时使用）
CREATE TABLE point_debt (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    biz_id VARCHAR(64) NOT NULL COMMENT '触发欠款的业务单号（退款订单号）',
    debt_points BIGINT NOT NULL COMMENT '欠款积分总额',
    remaining_debt BIGINT NOT NULL COMMENT '剩余未偿还欠款',
    status TINYINT DEFAULT 1 COMMENT '1未结清 0已结清',
    create_time DATETIME,
    INDEX idx_user_status (user_id, status)
) ENGINE=InnoDB;
```

> **说明**：在 `PointEarnService.earn()` 中，实际生产实现会在积分发放事务开始前先查询 `point_debt` 表，若用户存在未结清欠款，则本次发放积分优先偿还欠款，仅将净额计入可用积分，此处不再展开重复代码。

### 7.2 案例二：用户使用积分抵扣全链路

#### 7.2.1 链路概览

```
用户下单页勾选"使用积分抵扣"
    │
    ▼
查询积分余额 + 规则引擎试算抵扣金额
    │
    ▼
提交订单 ──► 积分冻结(预扣减，分布式锁防超扣)
    │              │
    │              ├─ 冻结成功 ──► 创建订单(携带冻结流水号)
    │              └─ 冻结失败 ──► 下单失败，提示积分不足/余额变化
    │
    ▼
用户支付
    ├─ 支付成功 ──► MQ通知 ──► 积分正式扣减(冻结→已使用)
    └─ 支付超时/取消 ──► MQ通知 ──► 积分解冻(冻结→可用，归还)
```

#### 7.2.2 下单时积分抵扣试算

```java
/**
 * 下单前置：积分抵扣试算接口
 *
 * 仅做只读校验和计算，不产生任何积分状态变更，
 * 真正的冻结动作在订单创建时才执行。
 */
@Service
public class PointDeductPreviewService {

    private static final Logger log = LoggerFactory.getLogger(PointDeductPreviewService.class);

    @Autowired
    private PointQueryService pointQueryService;

    @Autowired
    private PointDeductRuleEngine ruleEngine;

    public DeductPreviewResult preview(Long userId, BigDecimal orderAmount) {
        try {
            PointAccountVO account = pointQueryService.queryAccount(userId);
            if (account.getAvailablePoints() <= 0) {
                return DeductPreviewResult.unavailable("暂无可用积分");
            }

            DeductCalculation calc = ruleEngine.calculate(
                userId, (int) account.getAvailablePoints(), orderAmount);

            if (calc.getDeductPoints() <= 0) {
                return DeductPreviewResult.unavailable("积分不足最低使用门槛");
            }

            return DeductPreviewResult.success(calc.getDeductPoints(), calc.getDeductAmount());
        } catch (Exception e) {
            log.error("积分抵扣试算异常, userId={}", userId, e);
            // 试算失败不阻塞下单，默认不可用积分抵扣
            return DeductPreviewResult.unavailable("积分服务暂不可用");
        }
    }
}
```

#### 7.2.3 积分冻结（预扣减，并发安全防超扣）

这是本案例的核心难点：用户可能在多个设备/多个标签页同时提交订单，或者重复点击提交按钮，必须保证同一批可用积分不会被两笔订单同时冻结导致超扣。方案是"分布式锁 + DB乐观锁 + 流水唯一索引"三重防护。

```java
/**
 * 积分冻结服务（下单时预扣减）
 *
 * 并发安全设计：
 * 1. 分布式锁：以 userId 维度加锁，同一用户的积分操作串行化，避免多笔订单同时冻结时的竞态条件
 * 2. DB乐观锁：账户更新使用 before值 作为 where 条件，CAS失败则重试
 * 3. 流水唯一索引：(source, biz_id, log_type) 防止同一订单重复冻结
 * 4. 冻结明细表：记录冻结来源批次，供解冻/确认扣减时精确回溯
 */
@Service
public class PointFreezeService {

    private static final Logger log = LoggerFactory.getLogger(PointFreezeService.class);

    private static final int MAX_RETRY = 3;

    @Autowired
    private RedissonClient redissonClient;

    @Autowired
    private PointAccountMapper accountMapper;

    @Autowired
    private PointBatchMapper batchMapper;

    @Autowired
    private PointLogMapper logMapper;

    @Autowired
    private PointFreezeDetailMapper freezeDetailMapper;

    /**
     * 冻结积分（下单预扣）
     *
     * @param userId  用户ID
     * @param points  拟抵扣积分数量
     * @param orderId 订单ID（幂等键）
     */
    public FreezeResult freeze(Long userId, long points, Long orderId) {
        String lockKey = "lock:point:account:" + userId;
        RLock lock = redissonClient.getLock(lockKey);
        boolean locked = false;
        try {
            // 等待2秒获取锁，下单场景对响应时间敏感，不宜等待过久
            locked = lock.tryLock(2, 5, TimeUnit.SECONDS);
            if (!locked) {
                log.warn("获取积分冻结锁超时，可能存在并发下单, userId={}, orderId={}", userId, orderId);
                return FreezeResult.fail("系统繁忙，请稍后重试");
            }

            return doFreezeWithRetry(userId, points, orderId);

        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            log.error("积分冻结加锁被中断, userId={}, orderId={}", userId, orderId, e);
            return FreezeResult.fail("系统异常，请重试");
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    /**
     * 乐观锁CAS更新可能因并发而失败，做有限次数重试
     */
    private FreezeResult doFreezeWithRetry(Long userId, long points, Long orderId) {
        for (int attempt = 1; attempt <= MAX_RETRY; attempt++) {
            try {
                return doFreeze(userId, points, orderId);
            } catch (OptimisticLockException e) {
                log.warn("积分冻结乐观锁冲突，第{}次重试, userId={}, orderId={}", attempt, userId, orderId);
                if (attempt == MAX_RETRY) {
                    log.error("积分冻结重试耗尽，放弃处理, userId={}, orderId={}", userId, orderId, e);
                    return FreezeResult.fail("积分余额变化频繁，请重新下单");
                }
            }
        }
        return FreezeResult.fail("积分冻结失败");
    }

    @Transactional(rollbackFor = Exception.class)
    public FreezeResult doFreeze(Long userId, long points, Long orderId) {
        // 1. 幂等校验：同一订单已冻结过则直接返回成功（防止重复提交/MQ重试）
        PointLog existLog = logMapper.selectByBiz("ORDER", String.valueOf(orderId), "FREEZE");
        if (existLog != null) {
            log.info("订单已完成积分冻结，幂等返回, orderId={}", orderId);
            return FreezeResult.success();
        }

        // 2. 校验账户余额是否充足（此处读到的余额在加锁保护下是准确的）
        PointAccount account = accountMapper.selectByUserId(userId);
        if (account == null || account.getAvailablePoints() < points) {
            log.info("积分余额不足，冻结失败, userId={}, need={}, available={}",
                userId, points, account == null ? 0 : account.getAvailablePoints());
            return FreezeResult.fail("积分不足");
        }

        // 3. 按批次FIFO冻结（优先扣快过期批次，减少用户损失）
        List<PointBatch> batches = batchMapper.selectAvailableByUser(userId);
        long remainingToFreeze = points;
        List<BatchFreezeDetail> freezeDetails = new ArrayList<>();

        for (PointBatch batch : batches) {
            if (remainingToFreeze <= 0) break;

            long freezeFromBatch = Math.min(batch.getRemainingPoints(), remainingToFreeze);
            int updated = batchMapper.deductRemaining(
                batch.getBatchId(), freezeFromBatch, batch.getRemainingPoints());

            if (updated == 0) {
                // 理论上在userId级别加锁后不应发生批次级并发冲突，出现则说明有旁路写入，记录告警
                log.error("批次扣减遭遇未预期的并发冲突, batchId={}", batch.getBatchId());
                throw new OptimisticLockException("批次扣减冲突: " + batch.getBatchId());
            }

            freezeDetails.add(new BatchFreezeDetail(batch.getBatchId(), freezeFromBatch));
            remainingToFreeze -= freezeFromBatch;
        }

        if (remainingToFreeze > 0) {
            // 批次汇总与账户余额不一致，属于严重数据异常，回滚并告警而非静默处理
            log.error("积分批次总量与账户余额不一致，数据异常, userId={}, shortfall={}",
                userId, remainingToFreeze);
            throw new IllegalStateException("积分批次数据异常，冻结中止");
        }

        // 4. 更新账户余额（乐观锁：以查询到的beforeAvailable作为CAS条件）
        long beforeAvailable = account.getAvailablePoints();
        long afterAvailable = beforeAvailable - points;
        long afterFrozen = account.getFrozenPoints() + points;
        int updated = accountMapper.freezePoints(userId, afterAvailable, afterFrozen, beforeAvailable);
        if (updated == 0) {
            throw new OptimisticLockException("账户冻结CAS更新失败: " + userId);
        }

        // 5. 记录冻结流水（唯一索引兜底防重）
        try {
            PointLog log0 = new PointLog();
            log0.setUserId(userId);
            log0.setLogType("FREEZE");
            log0.setPoints(points);
            log0.setBeforePoints(beforeAvailable);
            log0.setAfterPoints(afterAvailable);
            log0.setSource("ORDER");
            log0.setBizId(String.valueOf(orderId));
            log0.setCreateTime(new Date());
            logMapper.insert(log0);
        } catch (DuplicateKeyException e) {
            // 理论上加了分布式锁+幂等前置校验不会走到这里，双保险防止唯一索引冲突导致事务异常退出
            log.warn("冻结流水唯一索引冲突，视为已冻结, orderId={}", orderId);
            throw new RuntimeException("冻结流水重复写入", e);
        }

        // 6. 记录批次冻结明细，供解冻/确认扣减时精确回溯到具体批次
        for (BatchFreezeDetail detail : freezeDetails) {
            PointFreezeDetail freezeDetail = new PointFreezeDetail();
            freezeDetail.setUserId(userId);
            freezeDetail.setOrderId(orderId);
            freezeDetail.setBatchId(detail.getBatchId());
            freezeDetail.setPoints(detail.getPoints());
            freezeDetail.setCreateTime(new Date());
            freezeDetailMapper.insert(freezeDetail);
        }

        log.info("积分冻结成功, userId={}, orderId={}, points={}, batchCount={}",
            userId, orderId, points, freezeDetails.size());

        return FreezeResult.success();
    }
}
```

#### 7.2.4 支付成功后正式扣减 / 订单取消后解冻归还

```java
/**
 * 积分确认扣减 & 解冻服务
 *
 * 分别对应订单支付成功（正式扣减）和订单取消/超时（解冻归还）两个终态，
 * 二者互斥：一笔冻结记录最终只会走向"确认扣减"或"解冻"其中一个结果，
 * 通过流水唯一索引保证不会重复执行，也不会同时执行两者。
 */
@Service
public class PointConfirmService {

    private static final Logger log = LoggerFactory.getLogger(PointConfirmService.class);

    @Autowired
    private RedissonClient redissonClient;

    @Autowired
    private PointAccountMapper accountMapper;

    @Autowired
    private PointBatchMapper batchMapper;

    @Autowired
    private PointLogMapper logMapper;

    @Autowired
    private PointFreezeDetailMapper freezeDetailMapper;

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    /**
     * 支付成功后确认扣减：冻结积分 -> 正式使用
     */
    @RocketMQMessageListener(topic = "order-pay-success", consumerGroup = "point-confirm-consumer")
    public void onPaySuccess(Long userId, long points, Long orderId) {
        if (points <= 0) {
            return; // 该订单未使用积分抵扣
        }

        String lockKey = "lock:point:account:" + userId;
        RLock lock = redissonClient.getLock(lockKey);
        try {
            if (!lock.tryLock(3, 10, TimeUnit.SECONDS)) {
                throw new BizRetryableException("获取确认扣减锁失败，触发重试, orderId=" + orderId);
            }
            confirmDeduct(userId, points, orderId);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new RuntimeException("确认扣减加锁被中断", e);
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void confirmDeduct(Long userId, long points, Long orderId) {
        // 幂等：已确认扣减过直接返回
        PointLog deductLog = logMapper.selectByBiz("ORDER", String.valueOf(orderId), "DEDUCT");
        if (deductLog != null) {
            log.info("订单积分已确认扣减，幂等跳过, orderId={}", orderId);
            return;
        }

        // 校验：必须先有冻结记录才能确认扣减，防止乱序消息导致的非法操作
        PointLog freezeLog = logMapper.selectByBiz("ORDER", String.valueOf(orderId), "FREEZE");
        if (freezeLog == null) {
            log.error("订单无冻结记录却触发确认扣减，消息乱序或数据异常, orderId={}", orderId);
            throw new IllegalStateException("缺少冻结记录，无法确认扣减: " + orderId);
        }

        PointAccount account = accountMapper.selectByUserId(userId);
        long beforeFrozen = account.getFrozenPoints();
        if (beforeFrozen < points) {
            log.error("账户冻结积分不足以确认扣减，数据不一致, userId={}, frozen={}, need={}",
                userId, beforeFrozen, points);
            throw new IllegalStateException("冻结积分不足，数据异常: " + userId);
        }

        long afterFrozen = beforeFrozen - points;
        long afterUsed = account.getUsedPoints() + points;
        int updated = accountMapper.confirmDeduct(userId, afterFrozen, afterUsed, beforeFrozen);
        if (updated == 0) {
            throw new RuntimeException("确认扣减CAS更新冲突，触发重试, userId=" + userId);
        }

        PointLog log0 = new PointLog();
        log0.setUserId(userId);
        log0.setLogType("DEDUCT");
        log0.setPoints(points);
        log0.setBeforePoints(account.getAvailablePoints());
        log0.setAfterPoints(account.getAvailablePoints()); // 可用积分在冻结阶段已扣减，此处不再变化
        log0.setSource("ORDER");
        log0.setBizId(String.valueOf(orderId));
        log0.setCreateTime(new Date());
        logMapper.insert(log0);

        // 批次的remaining_points在冻结阶段已经扣减完毕，此处仅需将批次标记为"已用完"（若已耗尽）
        batchMapper.markExhaustedIfZero(userId);

        try {
            redisTemplate.delete("point:account:" + userId);
        } catch (Exception e) {
            log.warn("清理积分缓存失败，等待TTL过期兜底, userId={}", userId, e);
        }

        log.info("积分确认扣减完成, userId={}, orderId={}, points={}", userId, orderId, points);
    }

    /**
     * 订单取消/支付超时后解冻归还：冻结积分 -> 恢复为可用
     */
    @RocketMQMessageListener(topic = "order-cancel", consumerGroup = "point-unfreeze-consumer")
    public void onOrderCancel(Long userId, long points, Long orderId) {
        if (points <= 0) {
            return;
        }
        String lockKey = "lock:point:account:" + userId;
        RLock lock = redissonClient.getLock(lockKey);
        try {
            if (!lock.tryLock(3, 10, TimeUnit.SECONDS)) {
                throw new BizRetryableException("获取解冻锁失败，触发重试, orderId=" + orderId);
            }
            unfreeze(userId, points, orderId);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new RuntimeException("解冻加锁被中断", e);
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void unfreeze(Long userId, long points, Long orderId) {
        // 幂等：已解冻过直接返回
        PointLog unfreezeLog = logMapper.selectByBiz("ORDER", String.valueOf(orderId), "UNFREEZE");
        if (unfreezeLog != null) {
            log.info("订单积分已解冻，幂等跳过, orderId={}", orderId);
            return;
        }

        // 互斥校验：已经确认扣减的订单不能再解冻，防止"支付成功"和"订单取消"消息乱序并发处理
        PointLog deductLog = logMapper.selectByBiz("ORDER", String.valueOf(orderId), "DEDUCT");
        if (deductLog != null) {
            log.warn("订单已确认扣减积分，忽略迟到的解冻消息, orderId={}", orderId);
            return;
        }

        List<PointFreezeDetail> details = freezeDetailMapper.selectByOrder(orderId);
        if (CollectionUtils.isEmpty(details)) {
            log.warn("未找到冻结明细，可能该订单未使用积分抵扣，跳过解冻, orderId={}", orderId);
            return;
        }

        // 按明细恢复各批次剩余积分（精确回溯，而非笼统加回，避免批次数据错乱）
        for (PointFreezeDetail detail : details) {
            batchMapper.restoreRemaining(detail.getBatchId(), detail.getPoints());
        }

        PointAccount account = accountMapper.selectByUserId(userId);
        long beforeFrozen = account.getFrozenPoints();
        long afterFrozen = beforeFrozen - points;
        long afterAvailable = account.getAvailablePoints() + points;
        int updated = accountMapper.unfreezePoints(userId, afterAvailable, afterFrozen, beforeFrozen);
        if (updated == 0) {
            throw new RuntimeException("解冻CAS更新冲突，触发重试, userId=" + userId);
        }

        PointLog log0 = new PointLog();
        log0.setUserId(userId);
        log0.setLogType("UNFREEZE");
        log0.setPoints(points);
        log0.setBeforePoints(account.getAvailablePoints());
        log0.setAfterPoints(afterAvailable);
        log0.setSource("ORDER");
        log0.setBizId(String.valueOf(orderId));
        log0.setCreateTime(new Date());
        logMapper.insert(log0);

        try {
            redisTemplate.delete("point:account:" + userId);
        } catch (Exception e) {
            log.warn("清理积分缓存失败，等待TTL过期兜底, userId={}", userId, e);
        }

        log.info("积分解冻归还完成, userId={}, orderId={}, points={}", userId, orderId, points);
    }
}
```

> **并发安全小结**：本案例通过"Redisson分布式锁（用户维度）+ DB乐观锁CAS + 流水唯一索引幂等 + 冻结明细精确回溯"四层机制，确保了高并发下单场景中积分既不会被超扣，也不会因消息乱序（先取消后支付/先支付后取消）导致状态错乱。DEDUCT 和 UNFREEZE 两条流水互斥校验是关键，任何一方先落库，另一方会自动放弃执行。

### 7.3 案例三：积分过期清零全链路

#### 7.3.1 链路概览

```
每日00:30 定时任务
    │
    ▼
扫描"T+7天内即将过期"的批次 ──► 批量推送过期提醒(站内信/Push/短信)
    │
    ▼
每日01:00 定时任务
    │
    ▼
扫描"已过期但状态仍为有效"的批次(分页游标，避免大事务)
    │
    ▼
分片处理(每片100条，独立事务提交，失败不影响其他分片)
    │
    ├─► 批次状态置为已过期
    ├─► 扣减账户可用积分(乐观锁CAS)
    ├─► 写入过期流水(防重)
    │
    ▼
处理完成后触发对账任务
    │
    ▼
对账：过期前总积分 = 过期后总积分 + 本次过期积分
    │
    ├─ 一致 ──► 对账通过
    └─ 不一致 ──► 告警 + 生成差异报告，人工介入
```

#### 7.3.2 过期前T-7天通知用户

```java
/**
 * 积分即将过期提醒任务
 *
 * 每日凌晨扫描7天内即将过期的批次，聚合到用户维度后统一推送一条提醒，
 * 避免同一用户多个批次分别过期导致重复打扰。
 */
@Component
public class PointExpireNotifyJob {

    private static final Logger log = LoggerFactory.getLogger(PointExpireNotifyJob.class);

    private static final int PAGE_SIZE = 200;

    @Autowired
    private PointBatchMapper batchMapper;

    @Autowired
    private PointNotifyService notifyService;

    @Autowired
    private ExpireNotifyRecordMapper notifyRecordMapper;

    @Scheduled(cron = "0 30 0 * * ?")
    public void notifyExpiringSoon() {
        Date deadline = DateUtils.addDays(new Date(), 7);
        String batchDate = DateFormatUtils.format(new Date(), "yyyyMMdd");
        long cursor = 0L;
        int totalNotified = 0;
        int totalFailed = 0;

        while (true) {
            // 使用ID游标分页代替offset分页，避免深分页导致的性能劣化
            List<PointBatch> batches;
            try {
                batches = batchMapper.selectExpiringSoonByCursor(cursor, deadline, PAGE_SIZE);
            } catch (Exception e) {
                log.error("查询即将过期批次失败，cursor={}", cursor, e);
                break; // 查询本身失败则终止本轮任务，下次调度重试
            }

            if (CollectionUtils.isEmpty(batches)) {
                break;
            }

            // 按用户聚合，避免一个用户因多个批次收到多条重复通知
            Map<Long, Long> userExpiringPoints = batches.stream()
                .collect(Collectors.groupingBy(PointBatch::getUserId,
                    Collectors.summingLong(PointBatch::getRemainingPoints)));

            for (Map.Entry<Long, Long> entry : userExpiringPoints.entrySet()) {
                Long userId = entry.getKey();
                Long expiringPoints = entry.getValue();

                // 幂等：同一用户同一天只通知一次，防止定时任务重跑/多实例部署重复发送
                String notifyKey = userId + "_" + batchDate;
                try {
                    if (notifyRecordMapper.exists(notifyKey)) {
                        continue;
                    }
                    notifyService.notifyPointExpiringSoon(userId, expiringPoints, deadline);
                    notifyRecordMapper.insert(notifyKey, userId, expiringPoints);
                    totalNotified++;
                } catch (DuplicateKeyException e) {
                    // 并发场景下幂等键冲突，说明已被处理，忽略
                } catch (Exception e) {
                    totalFailed++;
                    log.error("积分过期提醒发送失败, userId={}", userId, e);
                    // 单个用户通知失败不影响其他用户，继续处理
                }
            }

            cursor = batches.get(batches.size() - 1).getId();
            if (batches.size() < PAGE_SIZE) {
                break; // 已到最后一页
            }
        }

        log.info("积分过期提醒任务完成, notified={}, failed={}", totalNotified, totalFailed);
    }
}
```

#### 7.3.3 批量过期处理（大数据量分批扣减）

```java
/**
 * 积分过期批处理任务
 *
 * 大数据量处理要点：
 * 1. 游标分页替代offset分页，避免深分页扫描全表
 * 2. 小事务：每个批次独立事务提交，避免大事务长时间占用锁、拖慢主库
 * 3. 单条失败不影响整批：捕获异常后记录失败清单，任务结束后重试或告警
 * 4. 幂等：批次状态CAS + 流水唯一索引，任务重复执行不会重复扣减
 * 5. 限流：分片间sleep短暂时间，避免瞬时QPS冲击DB
 */
@Component
public class PointExpireBatchJob {

    private static final Logger log = LoggerFactory.getLogger(PointExpireBatchJob.class);

    private static final int PAGE_SIZE = 100;
    private static final long THROTTLE_MS = 50; // 分片间限流间隔

    @Autowired
    private PointBatchMapper batchMapper;

    @Autowired
    private PointAccountMapper accountMapper;

    @Autowired
    private PointLogMapper logMapper;

    @Autowired
    private PointExpireReconcileService reconcileService;

    @Scheduled(cron = "0 0 1 * * ?")
    public void processExpiredPoints() {
        Date now = new Date();
        long cursor = 0L;
        int successCount = 0;
        int failCount = 0;
        long totalExpiredPoints = 0L;
        List<String> failedBatchIds = new ArrayList<>();

        // 记录本轮任务开始前的账户总积分快照，供事后对账使用
        long beforeTotalAvailable = accountMapper.sumAllAvailablePoints();

        log.info("积分过期批处理任务开始, beforeTotalAvailable={}", beforeTotalAvailable);

        while (true) {
            List<PointBatch> expired;
            try {
                expired = batchMapper.selectExpiredByCursor(cursor, now, PAGE_SIZE);
            } catch (Exception e) {
                log.error("扫描过期批次失败，cursor={}，任务提前终止，等待下次调度补偿", cursor, e);
                break;
            }

            if (CollectionUtils.isEmpty(expired)) {
                break;
            }

            for (PointBatch batch : expired) {
                try {
                    long expiredPoints = expireBatchWithRetry(batch);
                    totalExpiredPoints += expiredPoints;
                    successCount++;
                } catch (Exception e) {
                    failCount++;
                    failedBatchIds.add(batch.getBatchId());
                    log.error("积分批次过期处理失败, batchId={}, userId={}",
                        batch.getBatchId(), batch.getUserId(), e);
                    // 不抛出异常，继续处理下一个批次，保证单点失败不影响整体任务
                }
            }

            cursor = expired.get(expired.size() - 1).getId();

            // 限流：避免连续处理大量分片对DB造成瞬时压力
            try {
                Thread.sleep(THROTTLE_MS);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                log.warn("过期批处理任务限流休眠被中断，继续执行");
            }

            if (expired.size() < PAGE_SIZE) {
                break;
            }
        }

        log.info("积分过期批处理任务完成, success={}, fail={}, totalExpiredPoints={}",
            successCount, failCount, totalExpiredPoints);

        if (!failedBatchIds.isEmpty()) {
            log.error("以下批次过期处理失败，需人工排查或等待补偿任务重试: {}", failedBatchIds);
            // 生产环境这里应写入失败清单表，由独立补偿任务定时重试，直至成功或人工介入
        }

        // 触发对账：过期前总积分 = 过期后总积分 + 本次过期积分
        reconcileService.reconcileAfterExpire(beforeTotalAvailable, totalExpiredPoints);
    }

    /**
     * 单批次过期处理，带乐观锁冲突重试
     */
    private long expireBatchWithRetry(PointBatch batch) {
        int maxRetry = 3;
        for (int attempt = 1; attempt <= maxRetry; attempt++) {
            try {
                return expireBatch(batch);
            } catch (OptimisticLockException e) {
                log.warn("批次过期处理乐观锁冲突，第{}次重试, batchId={}", attempt, batch.getBatchId());
                if (attempt == maxRetry) {
                    throw e;
                }
            }
        }
        return 0L;
    }

    @Transactional(rollbackFor = Exception.class)
    public long expireBatch(PointBatch batch) {
        // 幂等：流水表已有该批次的过期记录则跳过，防止任务重复调度导致重复扣减
        PointLog existLog = logMapper.selectByBiz("EXPIRE", batch.getBatchId(), "EXPIRE");
        if (existLog != null) {
            log.info("批次已处理过过期，幂等跳过, batchId={}", batch.getBatchId());
            return 0L;
        }

        // 1. 批次状态CAS更新：仅当状态仍为"有效(1)"时才置为"已过期(0)"，防止并发重复处理
        int statusUpdated = batchMapper.updateStatusCas(batch.getBatchId(), 0, 1);
        if (statusUpdated == 0) {
            log.info("批次状态已被其他线程更新，跳过, batchId={}", batch.getBatchId());
            return 0L;
        }

        long expirePoints = batch.getRemainingPoints();
        if (expirePoints <= 0) {
            return 0L; // 批次已无剩余积分，无需扣减账户，仅需状态流转
        }

        // 2. 扣减账户可用积分（乐观锁CAS，冲突交由上层重试）
        PointAccount account = accountMapper.selectByUserId(batch.getUserId());
        if (account == null) {
            log.error("批次对应账户不存在，数据异常, batchId={}, userId={}",
                batch.getBatchId(), batch.getUserId());
            return 0L;
        }

        long beforeAvailable = account.getAvailablePoints();
        if (beforeAvailable < expirePoints) {
            // 账户余额小于批次应过期积分，说明存在数据不一致，记录告警但仍按实际可扣数量处理，避免负数
            log.error("账户可用积分不足以扣减过期批次，数据不一致, userId={}, available={}, expirePoints={}",
                batch.getUserId(), beforeAvailable, expirePoints);
            expirePoints = beforeAvailable;
        }

        long afterAvailable = beforeAvailable - expirePoints;
        long afterExpired = account.getExpiredPoints() + expirePoints;
        int updated = accountMapper.expirePoints(
            batch.getUserId(), afterAvailable, afterExpired, beforeAvailable);
        if (updated == 0) {
            throw new OptimisticLockException("账户过期扣减CAS冲突: " + batch.getUserId());
        }

        // 3. 记录过期流水（唯一索引兜底防重）
        try {
            PointLog log0 = new PointLog();
            log0.setUserId(batch.getUserId());
            log0.setLogType("EXPIRE");
            log0.setPoints(expirePoints);
            log0.setBeforePoints(beforeAvailable);
            log0.setAfterPoints(afterAvailable);
            log0.setSource("EXPIRE");
            log0.setBizId(batch.getBatchId());
            log0.setBatchId(batch.getBatchId());
            log0.setCreateTime(new Date());
            logMapper.insert(log0);
        } catch (DuplicateKeyException e) {
            log.warn("过期流水唯一索引冲突，视为已处理, batchId={}", batch.getBatchId());
            // 流水已存在但前面状态/余额更新已生效，不回滚，直接返回，避免重复处理死循环
        }

        log.info("积分批次过期处理完成, batchId={}, userId={}, expirePoints={}",
            batch.getBatchId(), batch.getUserId(), expirePoints);

        return expirePoints;
    }
}
```

#### 7.3.4 过期对账（过期前总积分 = 过期后总积分 + 过期积分）

```java
/**
 * 积分过期对账服务
 *
 * 对账公式：
 * 过期前全平台可用积分总额 = 过期后全平台可用积分总额 + 本次批处理任务过期的积分总额
 *
 * 若不相等，说明过期批处理期间存在并发的正常发放/抵扣操作干扰了统计口径，
 * 或者过期处理逻辑本身存在bug，需要精确到用户级别的二次核对。
 */
@Service
public class PointExpireReconcileService {

    private static final Logger log = LoggerFactory.getLogger(PointExpireReconcileService.class);

    @Autowired
    private PointAccountMapper accountMapper;

    @Autowired
    private PointBatchMapper batchMapper;

    @Autowired
    private ExpireReconcileReportMapper reportMapper;

    @Autowired
    private AlarmService alarmService;

    /**
     * @param beforeTotalAvailable 过期批处理任务执行前的全平台可用积分总额快照
     * @param totalExpiredPoints   本次批处理任务实际过期扣减的积分总额
     */
    public void reconcileAfterExpire(long beforeTotalAvailable, long totalExpiredPoints) {
        try {
            long afterTotalAvailable = accountMapper.sumAllAvailablePoints();

            // 注意：过期任务执行期间，正常的积分发放(EARN)和抵扣确认(DEDUCT)仍在并发发生，
            // 严格意义上的对账公式应为：
            // before + 期间发放 - 期间抵扣 - 本次过期 = after
            // 此处为简化说明核心过期对账逻辑，实际生产实现需要按时间窗口叠加发放/抵扣流水的净变化量。
            long periodEarned = sumLogPointsBetween("EARN", beforeSnapshotTime(), new Date());
            long periodDeducted = sumLogPointsBetween("DEDUCT", beforeSnapshotTime(), new Date());

            long expected = beforeTotalAvailable + periodEarned - periodDeducted - totalExpiredPoints;
            long diff = afterTotalAvailable - expected;

            ExpireReconcileReport report = new ExpireReconcileReport();
            report.setReconcileDate(new Date());
            report.setBeforeTotalAvailable(beforeTotalAvailable);
            report.setPeriodEarned(periodEarned);
            report.setPeriodDeducted(periodDeducted);
            report.setTotalExpiredPoints(totalExpiredPoints);
            report.setAfterTotalAvailable(afterTotalAvailable);
            report.setExpectedTotalAvailable(expected);
            report.setDiff(diff);
            report.setStatus(diff == 0 ? "MATCH" : "MISMATCH");
            reportMapper.insert(report);

            if (diff == 0) {
                log.info("积分过期对账通过, beforeTotal={}, expired={}, afterTotal={}",
                    beforeTotalAvailable, totalExpiredPoints, afterTotalAvailable);
            } else {
                log.error("积分过期对账不一致! beforeTotal={}, periodEarned={}, periodDeducted={}, "
                        + "expired={}, expected={}, actual={}, diff={}",
                    beforeTotalAvailable, periodEarned, periodDeducted,
                    totalExpiredPoints, expected, afterTotalAvailable, diff);

                // 差异超过阈值，触发人工告警；小额差异（如并发时间窗口误差）先记录观察
                if (Math.abs(diff) > 1000) {
                    alarmService.sendAlarm("积分过期对账严重不一致，diff=" + diff);
                }

                // 进一步做用户级别精确核对，定位问题账户，为人工修复提供依据
                drillDownUserLevelDiff();
            }
        } catch (Exception e) {
            // 对账本身异常不应影响过期批处理已完成的结果，仅记录告警由人工介入排查
            log.error("积分过期对账任务执行异常", e);
            alarmService.sendAlarm("积分过期对账任务异常: " + e.getMessage());
        }
    }

    /**
     * 用户级别精确核对：账户可用积分 应等于 该用户所有有效批次剩余积分之和
     * 用于在全局对账发现差异后，定位到具体是哪些用户的数据存在问题
     */
    private void drillDownUserLevelDiff() {
        int pageSize = 500;
        long cursor = 0L;
        int mismatchCount = 0;

        while (true) {
            List<PointAccount> accounts = accountMapper.selectByCursor(cursor, pageSize);
            if (CollectionUtils.isEmpty(accounts)) {
                break;
            }

            for (PointAccount account : accounts) {
                try {
                    Long batchSum = batchMapper.sumAvailableByUser(account.getUserId());
                    if (batchSum == null) batchSum = 0L;

                    if (!batchSum.equals(account.getAvailablePoints())) {
                        mismatchCount++;
                        log.error("用户级积分对账不一致, userId={}, accountAvailable={}, batchSum={}",
                            account.getUserId(), account.getAvailablePoints(), batchSum);
                        // 记录到差异明细表，供人工审核后决定是否以批次汇总值为准进行修正
                        reportMapper.insertUserDiff(account.getUserId(),
                            account.getAvailablePoints(), batchSum);
                    }
                } catch (Exception e) {
                    log.error("用户级对账核对异常, userId={}", account.getUserId(), e);
                }
            }

            cursor = accounts.get(accounts.size() - 1).getId();
            if (accounts.size() < pageSize) {
                break;
            }
        }

        log.info("用户级积分对账核对完成，发现{}个不一致账户", mismatchCount);
    }

    private long sumLogPointsBetween(String logType, Date start, Date end) {
        Long sum = accountMapper.sumLogPointsBetween(logType, start, end);
        return sum == null ? 0L : sum;
    }

    private Date beforeSnapshotTime() {
        // 与批处理任务开始时间对齐，简化示例中直接取当天任务调度时间点
        return DateUtils.setHours(new Date(), 1);
    }
}
```

### 7.4 三个案例的通用工程模式总结

| 通用模式 | 案例一 | 案例二 | 案例三 |
|---------|--------|--------|--------|
| 幂等控制 | MQ消息表 + 流水唯一索引 + 二次确认 | 流水唯一索引 + DEDUCT/UNFREEZE互斥校验 | 批次状态CAS + 流水唯一索引 |
| 并发安全 | 订单维度分布式锁 | 用户维度分布式锁 + 乐观锁CAS重试 | 批次状态CAS，天然按批次粒度隔离 |
| 异常隔离 | 规则引擎异常降级、通知失败不阻塞主流程 | 分布式锁超时快速失败，不长时间阻塞下单链路 | 单批次失败不影响其他批次，失败清单交由补偿任务 |
