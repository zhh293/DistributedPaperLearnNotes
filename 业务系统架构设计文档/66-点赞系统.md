# 点赞系统架构设计

## 一、问题背景

在社交类、内容类应用中，点赞是用户最高频的互动行为之一。一个日活千万级别的内容平台，点赞请求的峰值QPS可以达到数十万甚至百万级别。点赞系统看似简单——用户点一下按钮，计数加一——但实际上面临着大量的工程挑战：

1. **高并发写入**：热门内容（如明星动态、热点事件）在短时间内可能收到百万级别的点赞，单条内容的写入QPS极高，数据库无法直接承受。
2. **去重要求**：同一用户对同一内容只能点赞一次，需要高效的去重机制。在高并发场景下，去重判断本身就是性能瓶颈。
3. **双向关系维护**：不仅需要知道"某内容被哪些人点赞了"，还需要知道"某用户点赞了哪些内容"，用于个人中心展示。
4. **实时性与一致性平衡**：用户点赞后希望立即看到点赞数变化（实时性），但热点内容的点赞计数无法在数据库层面做到强一致（性能瓶颈）。
5. **点赞与Feed流联动**：用户点赞某内容后，可能需要将该行为推送到其粉丝的Feed流中（"你的好友XXX点赞了这条内容"）。
6. **取消点赞的幂等性**：用户快速连续点击点赞/取消按钮时，需要保证最终状态的正确性。
7. **存储成本**：海量的点赞关系数据（数十亿条记录）需要合理的存储方案来平衡成本和查询性能。

本文将从实际工程出发，详细设计一套能够支撑千万级DAU的点赞系统。

## 二、整体架构设计

整体架构采用**分层设计**，从上到下分为：接入层、服务层、缓存层、消息队列层、存储层。

**核心设计原则**：
- **写请求**：先写Redis缓存（保证实时性），再通过消息队列异步写入MySQL（保证持久化）。
- **读请求**：优先从Redis读取，Redis不存在时回源MySQL并回填缓存。
- **计数服务**：独立于点赞关系服务，使用Redis Hash维护点赞计数，定期与MySQL对账。

## 三、核心链路设计

### 3.1 数据模型设计

#### 3.1.1 MySQL表结构设计

点赞系统需要两张核心表：点赞关系表和点赞计数表。

**点赞关系表**：记录用户与内容之间的点赞关系，是系统的基础数据。

```sql
CREATE TABLE `t_like_relation` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '自增主键',
    `user_id` BIGINT UNSIGNED NOT NULL COMMENT '点赞用户ID',
    `target_id` BIGINT UNSIGNED NOT NULL COMMENT '被点赞的内容ID',
    `target_type` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '内容类型: 1-帖子 2-评论 3-视频',
    `status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态: 0-已取消 1-已点赞',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_target` (`user_id`, `target_id`, `target_type`),
    KEY `idx_target_id` (`target_id`, `target_type`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='点赞关系表';
```

为什么使用`status`字段而不是直接删除记录？因为：
- 取消点赞是高频操作，物理删除会导致频繁的B+树页分裂和碎片化。
- 逻辑删除便于做数据统计和行为分析。
- 便于幂等处理，重复取消只需判断`status`即可。

**点赞计数表**：维护每条内容的点赞总数。

```sql
CREATE TABLE `t_like_count` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '自增主键',
    `target_id` BIGINT UNSIGNED NOT NULL COMMENT '内容ID',
    `target_type` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '内容类型',
    `like_count` BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '点赞总数',
    `version` BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_target` (`target_id`, `target_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='点赞计数表';
```

#### 3.1.2 分库分表策略

当点赞关系数据量超过单表5000万行时，需要进行分库分表。分库分表的核心问题是**选择分片键**。

点赞关系有两个核心查询维度：
- 按`user_id`查询：用户的点赞列表（个人中心）
- 按`target_id`查询：内容的点赞用户列表

这两个维度存在矛盾——按`user_id`分片则`target_id`查询需要扫描所有分片，反之亦然。

**解决方案：双写+双表**。维护两套分片表：
- `t_like_relation_by_user`：按`user_id`分片，服务于"用户的点赞列表"查询
- `t_like_relation_by_target`：按`target_id`分片，服务于"内容的点赞列表"查询

```java
/**
 * 分库分表路由策略
 * 采用 user_id % 1024 确定分片位置
 * 1024个逻辑分片映射到16个物理库，每个库64张表
 */
public class LikeShardingStrategy {
    
    private static final int TOTAL_SHARDS = 1024;
    private static final int DB_COUNT = 16;
    private static final int TABLE_COUNT_PER_DB = 64;
    
    public ShardingResult routeByUserId(long userId) {
        int shardIndex = (int) (userId % TOTAL_SHARDS);
        int dbIndex = shardIndex / TABLE_COUNT_PER_DB;
        int tableIndex = shardIndex % TABLE_COUNT_PER_DB;
        return new ShardingResult(dbIndex, tableIndex);
    }
    
    public ShardingResult routeByTargetId(long targetId) {
        int shardIndex = (int) (targetId % TOTAL_SHARDS);
        int dbIndex = shardIndex / TABLE_COUNT_PER_DB;
        int tableIndex = shardIndex % TABLE_COUNT_PER_DB;
        return new ShardingResult(dbIndex, tableIndex);
    }
}
```

双写的一致性通过消息队列保证——写入时先写`by_user`表，成功后发消息异步写`by_target`表。如果异步写失败，由定时对账任务补偿。

#### 3.1.3 Redis数据结构设计

Redis中需要维护三种数据结构：

**1. 点赞去重判断 — Bitmap**

使用Redis Bitmap判断某用户是否已点赞某内容。对于每条内容维护一个Bitmap，用户ID作为偏移量。

```
Key: like:bitmap:{targetType}:{targetId}
Value: Bitmap，第N位表示userId=N的用户是否点赞
```

Bitmap的优势是内存占用极低——1亿个用户的点赞关系只需要约12MB。但缺点是当用户ID空间很大且稀疏时（如用户ID为雪花算法生成的64位整数），直接用用户ID做偏移量会浪费大量内存。

**解决方案**：对用户ID做哈希映射，将其映射到一个合理的范围内，同时使用Bloom Filter做第一层快速判断。

```java
/**
 * 点赞去重判断服务
 * 使用Redis Bitmap + 本地BloomFilter双层判断
 */
public class LikeDeduplicationService {
    
    private static final int BITMAP_SIZE = 10_000_000; // 1000万位
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    /**
     * 判断用户是否已经点赞
     * @return true-已点赞，false-未点赞
     */
    public boolean hasLiked(long userId, long targetId, int targetType) {
        String key = buildBitmapKey(targetId, targetType);
        int offset = mapUserIdToOffset(userId);
        Boolean result = redisTemplate.opsForValue().getBit(key, offset);
        return Boolean.TRUE.equals(result);
    }
    
    /**
     * 设置点赞标记
     */
    public void markLiked(long userId, long targetId, int targetType) {
        String key = buildBitmapKey(targetId, targetType);
        int offset = mapUserIdToOffset(userId);
        redisTemplate.opsForValue().setBit(key, offset, true);
    }
    
    /**
     * 取消点赞标记
     */
    public void unmarkLiked(long userId, long targetId, int targetType) {
        String key = buildBitmapKey(targetId, targetType);
        int offset = mapUserIdToOffset(userId);
        redisTemplate.opsForValue().setBit(key, offset, false);
    }
    
    /**
     * 将用户ID映射到Bitmap的偏移量
     * 使用MurmurHash保证均匀分布
     */
    private int mapUserIdToOffset(long userId) {
        return (int) (Math.abs(MurmurHash.hash64(userId)) % BITMAP_SIZE);
    }
    
    private String buildBitmapKey(long targetId, int targetType) {
        return String.format("like:bitmap:%d:%d", targetType, targetId);
    }
}
```

**注意**：Bitmap的哈希映射存在碰撞可能。当Bitmap判断为"已点赞"时，需要再回查MySQL做精确判断。Bitmap在这里起到的是**快速否定**的作用——如果Bitmap显示"未点赞"，那一定是未点赞；如果显示"已点赞"，有极小概率是误判。

**2. 点赞计数 — Hash**

使用Redis Hash存储点赞计数，Key为内容类型，Field为内容ID，Value为点赞数。

```
Key: like:count:{targetType}
Field: {targetId}
Value: 点赞数
```

```java
/**
 * 点赞计数缓存服务
 */
public class LikeCountCacheService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    /**
     * 增加点赞计数
     */
    public Long incrementCount(long targetId, int targetType) {
        String key = buildCountKey(targetType);
        return redisTemplate.opsForHash().increment(key, String.valueOf(targetId), 1);
    }
    
    /**
     * 减少点赞计数
     */
    public Long decrementCount(long targetId, int targetType) {
        String key = buildCountKey(targetType);
        return redisTemplate.opsForHash().increment(key, String.valueOf(targetId), -1);
    }
    
    /**
     * 获取点赞计数
     */
    public long getCount(long targetId, int targetType) {
        String key = buildCountKey(targetType);
        Object value = redisTemplate.opsForHash().get(key, String.valueOf(targetId));
        return value != null ? Long.parseLong(value.toString()) : 0L;
    }
    
    /**
     * 批量获取点赞计数
     */
    public Map<Long, Long> batchGetCount(List<Long> targetIds, int targetType) {
        String key = buildCountKey(targetType);
        List<Object> fields = targetIds.stream()
                .map(id -> (Object) String.valueOf(id))
                .collect(Collectors.toList());
        List<Object> values = redisTemplate.opsForHash().multiGet(key, fields);
        
        Map<Long, Long> result = new HashMap<>();
        for (int i = 0; i < targetIds.size(); i++) {
            Object val = values.get(i);
            result.put(targetIds.get(i), val != null ? Long.parseLong(val.toString()) : 0L);
        }
        return result;
    }
    
    private String buildCountKey(int targetType) {
        return "like:count:" + targetType;
    }
}
```

**3. 用户点赞列表 — Sorted Set**

使用Redis Sorted Set存储用户的点赞列表，Score为点赞时间戳，便于按时间排序分页查询。

```
Key: like:user:{userId}:{targetType}
Score: 点赞时间戳
Member: targetId
```

### 3.2 点赞写入核心链路

点赞写入是整个系统最核心、最复杂的链路。完整的写入流程如下：

```
用户点赞请求
    │
    ▼
[1] 参数校验 + 频率限制
    │
    ▼
[2] Redis Bitmap 去重判断
    │  ├── 已点赞 → 返回"已点赞"
    │  └── 未点赞 → 继续
    ▼
[3] Redis Bitmap 标记点赞
    │
    ▼
[4] Redis Hash 点赞计数 +1
    │
    ▼
[5] Redis Sorted Set 写入用户点赞列表
    │
    ▼
[6] 返回客户端"点赞成功"
    │
    ▼ (异步)
[7] 发送MQ消息 → 消费者批量写入MySQL
    │
    ▼ (异步)
[8] 发送Feed流推送消息
```

**关键设计：步骤[3][4][5]使用Redis Pipeline + Lua脚本保证原子性。**

```java
/**
 * 点赞核心写入服务
 */
@Service
public class LikeWriteService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private LikeDeduplicationService deduplicationService;
    
    @Autowired
    private LikeCountCacheService countCacheService;
    
    @Autowired
    private LikeMqProducer mqProducer;
    
    @Autowired
    private RateLimiter rateLimiter;
    
    /**
     * 执行点赞操作
     * @param userId 点赞用户ID
     * @param targetId 被点赞内容ID
     * @param targetType 内容类型
     * @return 操作结果
     */
    public LikeResult doLike(long userId, long targetId, int targetType) {
        // 步骤1：参数校验 + 频率限制
        if (!rateLimiter.tryAcquire(userId, "like", 10, 1)) {
            // 每秒最多10次点赞请求，防止恶意刷赞
            return LikeResult.fail("操作过于频繁，请稍后再试");
        }
        
        // 步骤2：去重判断
        if (deduplicationService.hasLiked(userId, targetId, targetType)) {
            return LikeResult.fail("您已经点赞过了");
        }
        
        // 步骤3-5：使用Lua脚本原子执行三个Redis操作
        String luaScript = buildLikeLuaScript();
        Long result = executeLuaScript(luaScript, userId, targetId, targetType);
        
        if (result == null || result != 1) {
            return LikeResult.fail("点赞失败，请重试");
        }
        
        // 步骤6：立即返回成功（异步落库）
        
        // 步骤7：异步发送MQ消息落库
        LikeEvent event = new LikeEvent();
        event.setUserId(userId);
        event.setTargetId(targetId);
        event.setTargetType(targetType);
        event.setAction(LikeAction.LIKE);
        event.setTimestamp(System.currentTimeMillis());
        event.setEventId(generateEventId(userId, targetId, targetType));
        mqProducer.sendLikeEvent(event);
        
        // 步骤8：异步发送Feed流推送消息
        mqProducer.sendFeedEvent(event);
        
        return LikeResult.success(countCacheService.getCount(targetId, targetType));
    }
    
    /**
     * 构建点赞Lua脚本
     * 原子执行：Bitmap标记 + 计数增加 + 用户列表写入
     */
    private String buildLikeLuaScript() {
        return "-- 参数：KEYS[1]=bitmap_key, KEYS[2]=count_key, KEYS[3]=user_list_key\n" +
               "-- ARGV[1]=bitmap_offset, ARGV[2]=target_id, ARGV[3]=score(时间戳)\n" +
               "-- 检查是否已点赞\n" +
               "local already = redis.call('GETBIT', KEYS[1], ARGV[1])\n" +
               "if already == 1 then\n" +
               "    return 0\n" +
               "end\n" +
               "-- 标记Bitmap\n" +
               "redis.call('SETBIT', KEYS[1], ARGV[1], 1)\n" +
               "-- 增加计数\n" +
               "redis.call('HINCRBY', KEYS[2], ARGV[2], 1)\n" +
               "-- 写入用户点赞列表\n" +
               "redis.call('ZADD', KEYS[3], ARGV[3], ARGV[2])\n" +
               "return 1";
    }
    
    /**
     * 执行Lua脚本
     */
    private Long executeLuaScript(String script, long userId, long targetId, int targetType) {
        String bitmapKey = String.format("like:bitmap:%d:%d", targetType, targetId);
        String countKey = "like:count:" + targetType;
        String userListKey = String.format("like:user:%d:%d", userId, targetType);
        
        int bitmapOffset = (int) (Math.abs(MurmurHash.hash64(userId)) % 10_000_000);
        long timestamp = System.currentTimeMillis();
        
        DefaultRedisScript<Long> redisScript = new DefaultRedisScript<>(script, Long.class);
        return redisTemplate.execute(redisScript,
                Arrays.asList(bitmapKey, countKey, userListKey),
                String.valueOf(bitmapOffset),
                String.valueOf(targetId),
                String.valueOf(timestamp));
    }
    
    /**
     * 生成幂等事件ID
     * 格式：userId:targetId:targetType:action
     * 用于MQ消费端去重
     */
    private String generateEventId(long userId, long targetId, int targetType) {
        return String.format("%d:%d:%d:LIKE", userId, targetId, targetType);
    }
}
```

### 3.3 取消点赞的幂等处理

取消点赞与点赞操作是对称的，但需要特别注意幂等性问题。用户快速双击点赞按钮时，可能在短时间内发出"点赞"和"取消点赞"两个请求，且请求到达服务端的顺序可能与用户操作顺序不一致。

**幂等设计方案**：

1. **客户端防抖**：点赞按钮点击后300ms内忽略后续点击，最终状态再发请求。
2. **服务端幂等**：基于Redis Bitmap的当前状态判断，如果当前已经是"未点赞"状态，则取消点赞操作直接返回成功。
3. **MQ消费端幂等**：使用`eventId`（由userId+targetId+targetType+action组成）做幂等判断。

```java
/**
 * 取消点赞服务
 */
@Service
public class LikeUndoService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private LikeDeduplicationService deduplicationService;
    
    @Autowired
    private LikeMqProducer mqProducer;
    
    /**
     * 执行取消点赞
     */
    public LikeResult undoLike(long userId, long targetId, int targetType) {
        // 幂等判断：如果当前就是未点赞状态，直接返回成功
        if (!deduplicationService.hasLiked(userId, targetId, targetType)) {
            return LikeResult.success("已取消点赞");
        }
        
        // 使用Lua脚本原子执行：Bitmap清除 + 计数减少 + 用户列表移除
        String luaScript = buildUndoLikeLuaScript();
        Long result = executeUndoLuaScript(luaScript, userId, targetId, targetType);
        
        if (result == null || result != 1) {
            return LikeResult.fail("取消失败，请重试");
        }
        
        // 异步发送MQ消息
        LikeEvent event = new LikeEvent();
        event.setUserId(userId);
        event.setTargetId(targetId);
        event.setTargetType(targetType);
        event.setAction(LikeAction.UNLIKE);
        event.setTimestamp(System.currentTimeMillis());
        event.setEventId(generateEventId(userId, targetId, targetType));
        mqProducer.sendLikeEvent(event);
        
        return LikeResult.success("取消点赞成功");
    }
    
    private String buildUndoLikeLuaScript() {
        return "local already = redis.call('GETBIT', KEYS[1], ARGV[1])\n" +
               "if already == 0 then\n" +
               "    return 0\n" +
               "end\n" +
               "redis.call('SETBIT', KEYS[1], ARGV[1], 0)\n" +
               "redis.call('HINCRBY', KEYS[2], ARGV[2], -1)\n" +
               "redis.call('ZREM', KEYS[3], ARGV[2])\n" +
               "return 1";
    }
    
    private Long executeUndoLuaScript(String script, long userId, long targetId, int targetType) {
        String bitmapKey = String.format("like:bitmap:%d:%d", targetType, targetId);
        String countKey = "like:count:" + targetType;
        String userListKey = String.format("like:user:%d:%d", userId, targetType);
        int bitmapOffset = (int) (Math.abs(MurmurHash.hash64(userId)) % 10_000_000);
        
        DefaultRedisScript<Long> redisScript = new DefaultRedisScript<>(script, Long.class);
        return redisTemplate.execute(redisScript,
                Arrays.asList(bitmapKey, countKey, userListKey),
                String.valueOf(bitmapOffset),
                String.valueOf(targetId));
    }
    
    private String generateEventId(long userId, long targetId, int targetType) {
        return String.format("%d:%d:%d:UNLIKE", userId, targetId, targetType);
    }
}
```

### 3.4 异步落库：消息队列 + 批量写入

点赞/取消点赞操作先写Redis返回客户端，然后通过消息队列异步落库到MySQL。消费端采用**批量聚合写入**策略，将多条点赞记录合并为一次批量INSERT/UPDATE操作，大幅降低数据库压力。

```java
/**
 * 点赞消息消费者
 * 从MQ批量消费点赞事件，聚合后批量写入MySQL
 */
@Component
public class LikeEventConsumer {
    
    private static final int BATCH_SIZE = 500;
    private static final long BATCH_TIMEOUT_MS = 1000; // 最多等待1秒
    
    @Autowired
    private LikeRelationMapper likeRelationMapper;
    
    @Autowired
    private LikeCountMapper likeCountMapper;
    
    @Autowired
    private IdempotentService idempotentService;
    
    /**
     * 批量消费点赞事件
     * 采用"满N条或超时"的策略触发批量写入
     */
    @KafkaListener(topics = "like_event_topic", groupId = "like_consumer_group")
    public void consumeBatch(List<ConsumerRecord<String, String>> records) {
        // 1. 反序列化并过滤已处理的事件（幂等）
        List<LikeEvent> events = new ArrayList<>();
        for (ConsumerRecord<String, String> record : records) {
            LikeEvent event = JSON.parseObject(record.value(), LikeEvent.class);
            // 幂等检查：同一个eventId只处理一次
            if (idempotentService.isProcessed(event.getEventId())) {
                continue;
            }
            events.add(event);
        }
        
        if (events.isEmpty()) {
            return;
        }
        
        // 2. 按action分组
        Map<LikeAction, List<LikeEvent>> grouped = events.stream()
                .collect(Collectors.groupingBy(LikeEvent::getAction));
        
        // 3. 批量处理点赞事件
        List<LikeEvent> likeEvents = grouped.getOrDefault(LikeAction.LIKE, Collections.emptyList());
        if (!likeEvents.isEmpty()) {
            batchInsertLikeRelations(likeEvents);
            batchIncrementCounts(likeEvents);
        }
        
        // 4. 批量处理取消点赞事件
        List<LikeEvent> unlikeEvents = grouped.getOrDefault(LikeAction.UNLIKE, Collections.emptyList());
        if (!unlikeEvents.isEmpty()) {
            batchUpdateUnlikeRelations(unlikeEvents);
            batchDecrementCounts(unlikeEvents);
        }
        
        // 5. 标记事件已处理
        events.forEach(event -> idempotentService.markProcessed(event.getEventId()));
    }
    
    /**
     * 批量插入点赞关系
     * 使用INSERT ... ON DUPLICATE KEY UPDATE实现幂等写入
     */
    private void batchInsertLikeRelations(List<LikeEvent> events) {
        // 分批处理，每批500条
        Lists.partition(events, BATCH_SIZE).forEach(batch -> {
            List<LikeRelation> relations = batch.stream()
                    .map(event -> {
                        LikeRelation relation = new LikeRelation();
                        relation.setUserId(event.getUserId());
                        relation.setTargetId(event.getTargetId());
                        relation.setTargetType(event.getTargetType());
                        relation.setStatus(1); // 已点赞
                        return relation;
                    })
                    .collect(Collectors.toList());
            
            // INSERT ... ON DUPLICATE KEY UPDATE status=1
            // 如果记录已存在（之前取消过点赞），则将status更新为1
            likeRelationMapper.batchUpsert(relations);
        });
    }
    
    /**
     * 批量更新取消点赞关系
     */
    private void batchUpdateUnlikeRelations(List<LikeEvent> events) {
        Lists.partition(events, BATCH_SIZE).forEach(batch -> {
            List<LikeRelation> relations = batch.stream()
                    .map(event -> {
                        LikeRelation relation = new LikeRelation();
                        relation.setUserId(event.getUserId());
                        relation.setTargetId(event.getTargetId());
                        relation.setTargetType(event.getTargetType());
                        relation.setStatus(0); // 已取消
                        return relation;
                    })
                    .collect(Collectors.toList());
            likeRelationMapper.batchUpdateStatus(relations);
        });
    }
    
    /**
     * 批量增加点赞计数
     * 先按targetId聚合计数，再批量更新
     */
    private void batchIncrementCounts(List<LikeEvent> events) {
        // 按targetId聚合：统计每个target被点赞了几次
        Map<String, Long> countMap = events.stream()
                .collect(Collectors.groupingBy(
                        e -> e.getTargetId() + ":" + e.getTargetType(),
                        Collectors.counting()
                ));
        
        countMap.forEach((key, count) -> {
            String[] parts = key.split(":");
            long targetId = Long.parseLong(parts[0]);
            int targetType = Integer.parseInt(parts[1]);
            likeCountMapper.incrementCount(targetId, targetType, count.intValue());
        });
    }
    
    /**
     * 批量减少点赞计数
     */
    private void batchDecrementCounts(List<LikeEvent> events) {
        Map<String, Long> countMap = events.stream()
                .collect(Collectors.groupingBy(
                        e -> e.getTargetId() + ":" + e.getTargetType(),
                        Collectors.counting()
                ));
        
        countMap.forEach((key, count) -> {
            String[] parts = key.split(":");
            long targetId = Long.parseLong(parts[0]);
            int targetType = Integer.parseInt(parts[1]);
            likeCountMapper.decrementCount(targetId, targetType, count.intValue());
        });
    }
}
```

### 3.5 点赞与Feed流联动

当用户点赞某内容后，该行为可能需要推送到其粉丝的Feed流中，展示为"你的好友XXX点赞了这条内容"。这个推送链路是独立于点赞核心链路的异步过程。

```java
/**
 * Feed流点赞推送消费者
 * 消费点赞事件，将点赞行为写入粉丝的Feed流
 */
@Component
public class LikeFeedConsumer {
    
    @Autowired
    private FollowService followService;
    
    @Autowired
    private FeedService feedService;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    // 粉丝数阈值：超过此值使用"拉模式"，不超过使用"推模式"
    private static final int FAN_THRESHOLD = 10000;
    
    @KafkaListener(topics = "like_feed_topic", groupId = "like_feed_group")
    public void onLikeEvent(ConsumerRecord<String, String> record) {
        LikeEvent event = JSON.parseObject(record.value(), LikeEvent.class);
        
        // 只处理点赞事件，不处理取消点赞
        if (event.getAction() != LikeAction.LIKE) {
            return;
        }
        
        long userId = event.getUserId();
        
        // 获取粉丝数
        long fanCount = followService.getFanCount(userId);
        
        if (fanCount <= FAN_THRESHOLD) {
            // 推模式：直接写入每个粉丝的Feed收件箱
            pushToFans(userId, event);
        } else {
            // 拉模式：大V用户不推送到粉丝Feed，粉丝读取Feed时主动拉取大V的点赞行为
            writeToOutbox(userId, event);
        }
    }
    
    /**
     * 推模式：将点赞行为写入粉丝的Feed收件箱
     */
    private void pushToFans(long userId, LikeEvent event) {
        List<Long> fanIds = followService.getFanIds(userId);
        
        // 构建Feed项
        FeedItem feedItem = new FeedItem();
        feedItem.setType(FeedType.LIKE);
        feedItem.setActorId(userId);
        feedItem.setTargetId(event.getTargetId());
        feedItem.setTargetType(event.getTargetType());
        feedItem.setTimestamp(event.getTimestamp());
        
        String feedItemJson = JSON.toJSONString(feedItem);
        
        // 批量写入粉丝的Feed收件箱（Redis Sorted Set）
        for (Long fanId : fanIds) {
            String feedKey = "feed:inbox:" + fanId;
            redisTemplate.opsForZSet().add(feedKey, feedItemJson, event.getTimestamp());
            // 控制Feed列表长度，最多保留1000条
            redisTemplate.opsForZSet().removeRange(feedKey, 0, -1001);
        }
    }
    
    /**
     * 拉模式：将点赞行为写入用户的发件箱
     * 粉丝读取Feed时会主动合并大V发件箱中的内容
     */
    private void writeToOutbox(long userId, LikeEvent event) {
        String outboxKey = "feed:outbox:" + userId;
        FeedItem feedItem = new FeedItem();
        feedItem.setType(FeedType.LIKE);
        feedItem.setActorId(userId);
        feedItem.setTargetId(event.getTargetId());
        feedItem.setTargetType(event.getTargetType());
        feedItem.setTimestamp(event.getTimestamp());
        
        redisTemplate.opsForZSet().add(outboxKey, JSON.toJSONString(feedItem), event.getTimestamp());
        redisTemplate.opsForZSet().removeRange(outboxKey, 0, -501);
    }
}
```

### 3.6 热点内容点赞倾斜处理

当某条热门内容在短时间内收到大量点赞时（如明星官宣、重大新闻），会出现以下问题：

1. **Redis热Key**：所有点赞请求都集中到同一个Redis Key，单节点QPS可能达到几十万。
2. **MySQL热点行**：计数表中该内容对应的行被高频UPDATE，行锁竞争严重。

**解决方案一：Redis计数分片**

将单个内容的点赞计数分散到多个Redis Key上，读取时求和。

```java
/**
 * 热点内容点赞计数分片服务
 * 将单个内容的计数分散到N个分片，降低单Key压力
 */
public class HotLikeCountService {
    
    // 分片数量，根据预估QPS设定
    private static final int SHARD_COUNT = 100;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private HotContentDetector hotContentDetector;
    
    /**
     * 增加点赞计数（热点内容走分片逻辑）
     */
    public void increment(long targetId, int targetType, long userId) {
        if (hotContentDetector.isHot(targetId, targetType)) {
            // 热点内容：随机选择一个分片
            int shard = (int) (userId % SHARD_COUNT);
            String key = String.format("like:hot_count:%d:%d:%d", targetType, targetId, shard);
            redisTemplate.opsForValue().increment(key);
        } else {
            // 普通内容：直接操作原计数Key
            String key = "like:count:" + targetType;
            redisTemplate.opsForHash().increment(key, String.valueOf(targetId), 1);
        }
    }
    
    /**
     * 获取热点内容的点赞总数
     * 汇总所有分片的计数
     */
    public long getHotCount(long targetId, int targetType) {
        List<String> keys = new ArrayList<>();
        for (int i = 0; i < SHARD_COUNT; i++) {
            keys.add(String.format("like:hot_count:%d:%d:%d", targetType, targetId, i));
        }
        
        // 使用Pipeline批量获取所有分片的计数
        List<Object> results = redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
            for (String key : keys) {
                connection.stringCommands().get(key.getBytes());
            }
            return null;
        });
        
        long total = 0;
        for (Object result : results) {
            if (result != null) {
                total += Long.parseLong(result.toString());
            }
        }
        return total;
    }
}

/**
 * 热点内容检测器
 * 使用滑动窗口计数判断内容是否为热点
 */
@Component
public class HotContentDetector {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    // 1分钟内超过1000次点赞即判定为热点
    private static final int HOT_THRESHOLD = 1000;
    private static final int WINDOW_SECONDS = 60;
    
    /**
     * 判断内容是否为热点
     */
    public boolean isHot(long targetId, int targetType) {
        String key = String.format("like:hot_detect:%d:%d", targetType, targetId);
        Long count = redisTemplate.opsForValue().increment(key);
        if (count != null && count == 1) {
            redisTemplate.expire(key, WINDOW_SECONDS, TimeUnit.SECONDS);
        }
        return count != null && count > HOT_THRESHOLD;
    }
}
```

**解决方案二：本地缓存聚合**

在应用服务器本地使用Caffeine缓存聚合点赞计数，每秒定时将本地聚合结果刷入Redis，减少Redis的写入QPS。

```java
/**
 * 本地缓存聚合点赞计数
 * 在应用本地聚合计数，定时批量刷入Redis
 */
@Component
public class LocalLikeCountAggregator {
    
    // 本地聚合缓存：key=targetType:targetId, value=增量计数
    private final ConcurrentHashMap<String, AtomicLong> localCountMap = new ConcurrentHashMap<>();
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    /**
     * 本地增加计数
     */
    public void localIncrement(long targetId, int targetType) {
        String key = targetType + ":" + targetId;
        localCountMap.computeIfAbsent(key, k -> new AtomicLong(0)).incrementAndGet();
    }
    
    /**
     * 定时任务：每秒将本地聚合的计数刷入Redis
     */
    @Scheduled(fixedRate = 1000)
    public void flushToRedis() {
        if (localCountMap.isEmpty()) {
            return;
        }
        
        // 原子替换，获取当前聚合数据
        Map<String, AtomicLong> snapshot = new HashMap<>(localCountMap);
        localCountMap.clear();
        
        // 使用Pipeline批量写入Redis
        redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
            for (Map.Entry<String, AtomicLong> entry : snapshot.entrySet()) {
                String[] parts = entry.getKey().split(":");
                int targetType = Integer.parseInt(parts[0]);
                String targetId = parts[1];
                long delta = entry.getValue().get();
                
                String hashKey = "like:count:" + targetType;
                connection.hashCommands().hIncrBy(
                        hashKey.getBytes(),
                        targetId.getBytes(),
                        delta
                );
            }
            return null;
        });
    }
}
```

### 3.7 点赞数据一致性：最终一致 + 对账

由于点赞系统采用"先写缓存、异步写数据库"的架构，Redis和MySQL之间可能出现数据不一致的情况。需要通过**定时对账**机制来发现和修复不一致。

```java
/**
 * 点赞数据对账服务
 * 定时比对Redis中的点赞计数与MySQL中的实际计数
 * 发现不一致时以MySQL为准进行修正
 */
@Component
public class LikeReconciliationService {
    
    @Autowired
    private LikeCountMapper likeCountMapper;
    
    @Autowired
    private LikeRelationMapper likeRelationMapper;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private AlertService alertService;
    
    /**
     * 全量对账任务（每天凌晨执行）
     * 扫描MySQL点赞计数表，与Redis比对
     */
    @Scheduled(cron = "0 0 3 * * ?")
    public void fullReconciliation() {
        int pageSize = 1000;
        long lastId = 0;
        int totalChecked = 0;
        int totalFixed = 0;
        
        while (true) {
            // 分页扫描MySQL计数表
            List<LikeCount> dbCounts = likeCountMapper.scanByPage(lastId, pageSize);
            if (dbCounts.isEmpty()) {
                break;
            }
            
            for (LikeCount dbCount : dbCounts) {
                // 从Redis获取缓存计数
                long redisCount = getRedisCount(dbCount.getTargetId(), dbCount.getTargetType());
                
                // 从MySQL关系表中实际统计点赞数
                long actualCount = likeRelationMapper.countByTarget(
                        dbCount.getTargetId(), dbCount.getTargetType());
                
                // 比对三方数据
                boolean dbCountCorrect = (dbCount.getLikeCount() == actualCount);
                boolean redisCountCorrect = (redisCount == actualCount);
                
                if (!dbCountCorrect) {
                    // MySQL计数表与实际关系不一致，修正计数表
                    likeCountMapper.updateCount(
                            dbCount.getTargetId(), dbCount.getTargetType(), actualCount);
                    totalFixed++;
                }
                
                if (!redisCountCorrect) {
                    // Redis计数与实际关系不一致，修正Redis
                    setRedisCount(dbCount.getTargetId(), dbCount.getTargetType(), actualCount);
                    totalFixed++;
                }
                
                totalChecked++;
            }
            
            lastId = dbCounts.get(dbCounts.size() - 1).getId();
        }
        
        // 对账结果报告
        if (totalFixed > 0) {
            alertService.warn(String.format(
                    "点赞对账完成：检查%d条，修正%d条", totalChecked, totalFixed));
        }
    }
    
    /**
     * 增量对账任务（每小时执行）
     * 只检查最近一小时有变更的内容
     */
    @Scheduled(cron = "0 0 * * * ?")
    public void incrementalReconciliation() {
        Date oneHourAgo = new Date(System.currentTimeMillis() - 3600_000);
        List<LikeCount> recentChanges = likeCountMapper.findRecentlyUpdated(oneHourAgo);
        
        for (LikeCount dbCount : recentChanges) {
            long actualCount = likeRelationMapper.countByTarget(
                    dbCount.getTargetId(), dbCount.getTargetType());
            long redisCount = getRedisCount(dbCount.getTargetId(), dbCount.getTargetType());
            
            if (dbCount.getLikeCount() != actualCount) {
                likeCountMapper.updateCount(
                        dbCount.getTargetId(), dbCount.getTargetType(), actualCount);
            }
            
            if (redisCount != actualCount) {
                setRedisCount(dbCount.getTargetId(), dbCount.getTargetType(), actualCount);
            }
        }
    }
    
    private long getRedisCount(long targetId, int targetType) {
        String key = "like:count:" + targetType;
        Object value = redisTemplate.opsForHash().get(key, String.valueOf(targetId));
        return value != null ? Long.parseLong(value.toString()) : 0L;
    }
    
    private void setRedisCount(long targetId, int targetType, long count) {
        String key = "like:count:" + targetType;
        redisTemplate.opsForHash().put(key, String.valueOf(targetId), String.valueOf(count));
    }
}
```

### 3.8 点赞查询服务

点赞系统的读请求主要有三种场景：

1. 查询某内容的点赞数。
2. 查询当前用户是否已点赞某内容（或批量查询多个内容的点赞状态）。
3. 查询用户的点赞列表。

```java
/**
 * 点赞查询服务
 */
@Service
public class LikeQueryService {
    
    @Autowired
    private LikeDeduplicationService deduplicationService;
    
    @Autowired
    private LikeCountCacheService countCacheService;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private LikeRelationMapper likeRelationMapper;
    
    @Autowired
    private LikeCountMapper likeCountMapper;
    
    /**
     * 查询内容的点赞数
     */
    public long getLikeCount(long targetId, int targetType) {
        // 先查Redis缓存
        long count = countCacheService.getCount(targetId, targetType);
        if (count > 0) {
            return count;
        }
        
        // 缓存未命中，回源MySQL
        LikeCount dbCount = likeCountMapper.findByTarget(targetId, targetType);
        if (dbCount != null) {
            // 回填缓存
            countCacheService.setCount(targetId, targetType, dbCount.getLikeCount());
            return dbCount.getLikeCount();
        }
        
        return 0;
    }
    
    /**
     * 批量查询用户是否已点赞（用于Feed列表展示）
     * @param userId 当前用户
     * @param targetIds 内容ID列表
     * @param targetType 内容类型
     * @return Map<内容ID, 是否已点赞>
     */
    public Map<Long, Boolean> batchCheckLiked(long userId, List<Long> targetIds, int targetType) {
        Map<Long, Boolean> result = new HashMap<>();
        
        // 使用Pipeline批量查询Bitmap
        List<Object> bitmapResults = redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
            for (Long targetId : targetIds) {
                String key = String.format("like:bitmap:%d:%d", targetType, targetId);
                int offset = (int) (Math.abs(MurmurHash.hash64(userId)) % 10_000_000);
                connection.stringCommands().getBit(key.getBytes(), offset);
            }
            return null;
        });
        
        for (int i = 0; i < targetIds.size(); i++) {
            Boolean liked = (Boolean) bitmapResults.get(i);
            result.put(targetIds.get(i), Boolean.TRUE.equals(liked));
        }
        
        return result;
    }
    
    /**
     * 查询用户的点赞列表（分页）
     * @param userId 用户ID
     * @param targetType 内容类型
     * @param cursor 游标（上一页最后一条的score）
     * @param pageSize 每页数量
     */
    public List<Long> getUserLikeList(long userId, int targetType, double cursor, int pageSize) {
        String key = String.format("like:user:%d:%d", userId, targetType);
        
        // 从Redis Sorted Set中按score倒序分页查询
        Set<Object> members;
        if (cursor <= 0) {
            // 首页
            members = redisTemplate.opsForZSet().reverseRange(key, 0, pageSize - 1);
        } else {
            // 非首页，使用cursor定位
            members = redisTemplate.opsForZSet().reverseRangeByScore(
                    key, 0, cursor - 1, 0, pageSize);
        }
        
        if (members == null || members.isEmpty()) {
            // Redis中没有数据，可能是缓存过期，回源MySQL
            return loadUserLikeListFromDB(userId, targetType, cursor, pageSize);
        }
        
        return members.stream()
                .map(m -> Long.parseLong(m.toString()))
                .collect(Collectors.toList());
    }
    
    private List<Long> loadUserLikeListFromDB(long userId, int targetType, double cursor, int pageSize) {
        Date beforeTime = cursor > 0 ? new Date((long) cursor) : new Date();
        return likeRelationMapper.findUserLikeList(userId, targetType, beforeTime, pageSize);
    }
}
```

## 四、异常处理与容错机制

### 4.1 Redis故障降级

当Redis出现故障（如主从切换、网络抖动）时，点赞系统需要有降级策略：

1. **写降级**：Redis不可用时，直接将点赞事件写入消息队列，由消费端直接写MySQL。同时在返回客户端时，标记为"操作成功，数据可能延迟展示"。
2. **读降级**：Redis不可用时，直接从MySQL读取点赞数据。为防止MySQL被击穿，开启本地缓存（Caffeine）并设置合理的TTL。

```java
/**
 * Redis降级处理
 */
@Component
public class LikeDegradationHandler {
    
    @Autowired
    private LikeCountMapper likeCountMapper;
    
    private final Cache<String, Long> localCache = Caffeine.newBuilder()
            .maximumSize(100_000)
            .expireAfterWrite(30, TimeUnit.SECONDS)
            .build();
    
    /**
     * 降级获取点赞数
     */
    public long getCountWithDegradation(long targetId, int targetType) {
        String cacheKey = targetType + ":" + targetId;
        return localCache.get(cacheKey, key -> {
            LikeCount dbCount = likeCountMapper.findByTarget(targetId, targetType);
            return dbCount != null ? dbCount.getLikeCount() : 0L;
        });
    }
}
```

### 4.2 消息队列消费失败处理

MQ消费失败时的处理策略：

1. **自动重试**：消费失败后，消息回到队列等待重试。设置最大重试次数为3次，每次间隔递增（1s、5s、30s）。
2. **死信队列**：超过最大重试次数后，消息进入死信队列（DLQ），由人工或定时任务处理。
3. **补偿机制**：定时对账任务会发现并修复因消费失败导致的数据不一致。

### 4.3 并发安全

对于同一用户对同一内容的并发点赞/取消点赞请求：

1. **Redis层**：通过Lua脚本保证原子性，不会出现部分操作成功的情况。
2. **MySQL层**：通过唯一索引`uk_user_target`防止重复插入，通过`INSERT ON DUPLICATE KEY UPDATE`保证幂等。

## 五、性能优化

### 5.1 缓存预热

对于新发布的热门内容（如大V的帖子），可以在内容发布时预先创建Redis Key，避免冷启动时的缓存穿透。

### 5.2 读写分离

MySQL层面使用读写分离：
- 写请求（异步落库）走主库。
- 读请求（对账、回源查询）走从库，容忍秒级延迟。

### 5.3 批量查询优化

Feed列表展示时需要批量查询多条内容的点赞数和点赞状态。使用Redis Pipeline将多次网络请求合并为一次，减少网络RTT。

### 5.4 冷数据归档

超过一定时间（如6个月）未被访问的点赞关系数据，可以从MySQL热数据库迁移到HBase等冷存储中，降低MySQL存储成本和查询负担。

### 5.5 连接池优化

## 六、最佳实践与总结

### 6.1 核心设计决策总结

| 设计问题 | 方案选择 | 选择理由 |
|---------|---------|---------|
| 点赞去重 | Redis Bitmap + Lua脚本 | 内存占用小，O(1)时间复杂度，原子操作 |
| 点赞计数 | Redis Hash + 异步对账 | 高性能自增，批量查询友好 |
| 数据持久化 | 消息队列 + 批量写入MySQL | 削峰填谷，批量操作减少DB压力 |
| 热点内容 | 计数分片 + 本地聚合 | 分散热Key压力，减少Redis写入QPS |
| Feed联动 | 推拉结合模式 | 小V推模式实时性好，大V拉模式降低扇出 |
| 幂等保证 | eventId + Redis状态判断 | 多层幂等，防止重复操作 |

### 6.2 容量评估参考

以日活1000万、人均日点赞5次为例：

- **写QPS**：5000万 / 86400 ≈ 580 QPS（均值），峰值按10倍估算约 5800 QPS。
- **Redis内存**：每条内容Bitmap 1.2MB（1000万用户），10万条活跃内容约 120GB。但考虑到大部分内容点赞用户很少，实际按稀疏存储远低于此值。
- **MySQL存储**：每条关系记录约 50 字节，1亿条约 5GB。

### 6.3 架构演进建议

1. **初创期**（日点赞量 < 100万）：单Redis + 单MySQL，同步写入。
2. **成长期**（日点赞量 100万 ~ 5000万）：Redis集群 + MQ异步落库 + MySQL分库。
3. **成熟期**（日点赞量 > 5000万）：多级缓存 + 热点分片 + 分库分表 + 冷热数据分离。

### 6.4 关键监控指标

| 指标 | 告警阈值 | 含义 |
|-----|---------|-----|
| Redis Bitmap操作P99延迟 | > 5ms | 去重判断性能异常 |
| MQ消费延迟 | > 30s | 异步落库积压 |
| Redis-MySQL计数差异率 | > 1% | 数据不一致超标 |
| 单Key QPS | > 10万 | 出现热Key，需要分片 |
| MQ死信队列堆积数 | > 100 | 存在无法处理的消息 |

### 6.5 总结

点赞系统的核心挑战在于**高并发写入**和**数据一致性**之间的平衡。通过"Redis缓存扛读写 + 消息队列异步落库 + 定时对账修复"的三层架构，可以在保证用户体验的同时实现数据的最终一致性。热点内容的处理需要额外的计数分片和本地聚合策略。整个系统的设计遵循了"快速响应用户、异步保证一致、定时兜底修复"的原则，是典型的"先缓存后持久化"架构模式的实践。

### 7.1 案例一：用户点赞全链路

#### 7.1.1 链路概述

用户在App上点击"点赞"按钮后，请求从客户端发出，经过API网关、点赞服务、Redis缓存、消息队列，最终异步落库到MySQL，并通知被点赞用户。完整的链路如下：

```
用户点击点赞按钮
    │
    ▼
[1] Controller接收请求，参数校验（targetId、targetType、userId）
    │
    ▼
[2] 重复点赞校验（Redis Set SISMEMBER判断）
    │  ├── 已点赞 → 返回"已点赞"，链路终止

    │
    ▼ (异步)
[6] 发送通知MQ消息 → 通知被点赞用户
    │
    ▼
[7] 取消点赞的逆向流程：SREM + DECR + ZREM
```

#### 7.1.3 重复点赞校验（Redis Set + SISMEMBER）

在核心写入服务中，使用Redis Set进行精确去重判断。Bitmap用于快速否定（判断未点赞），Set用于精确确认（判断已点赞），两层校验兼顾性能与准确性。

```java
/**
 * 点赞去重服务（增强版）
 * 双层校验：Bitmap快速否定 + Set精确确认
 */
@Service
@Slf4j
public class LikeDeduplicationEnhancedService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Autowired
    private LikeRelationMapper likeRelationMapper;

    private static final int BITMAP_SIZE = 10_000_000;

    /**
     * 精确判断用户是否已点赞
     * 第一层：Bitmap快速判断（可能有误判）
     * 第二层：Redis Set精确判断（SISMEMBER）
     *
     * @return true-已点赞，false-未点赞
     */
    public boolean hasLiked(long userId, long targetId, int targetType) {
        String traceId = MDC.get("traceId");

        // 第一层：Bitmap快速否定
        String bitmapKey = String.format("like:bitmap:%d:%d", targetType, targetId);
        int offset = (int) (Math.abs(MurmurHash.hash64(userId)) % BITMAP_SIZE);
        try {
            Boolean bitmapResult = redisTemplate.opsForValue().getBit(bitmapKey, offset);
            if (!Boolean.TRUE.equals(bitmapResult)) {
                // Bitmap显示未点赞，那一定是未点赞
                return false;
            }
        } catch (Exception e) {
            log.warn("[去重] Bitmap查询异常, 降级走Set查询, userId={}, targetId={}, traceId={}",
                    userId, targetId, traceId, e);
        }

        // 第二层：Redis Set精确确认
        // Key: like:set:{targetType}:{targetId}，Value: 点赞用户的userId集合
        String setKey = String.format("like:set:%d:%d", targetType, targetId);
        try {
            Boolean isMember = redisTemplate.opsForSet().isMember(setKey, String.valueOf(userId));
            return Boolean.TRUE.equals(isMember);
        } catch (Exception e) {
            log.error("[去重] Set查询异常, userId={}, targetId={}, traceId={}",
                    userId, targetId, traceId, e);
            // 降级：查询MySQL
            return checkFromDatabase(userId, targetId, targetType);
        }
    }

    /**
     * 降级查数据库
     */
    private boolean checkFromDatabase(long userId, long targetId, int targetType) {
        try {
            LikeRelation relation = likeRelationMapper.findByUserAndTarget(userId, targetId, targetType);
            return relation != null && relation.getStatus() == 1;
        } catch (Exception e) {
            log.error("[去重] 数据库降级查询也失败, userId={}, targetId={}", userId, targetId, e);
            // 查询全部失败，保守策略：返回false允许写入，由数据库唯一索引兜底
            return false;
        }
    }
}
```

#### 7.1.4 Redis原子操作：SADD + INCR + ZADD

核心写入使用Lua脚本保证原子性。在原有Bitmap方案基础上，增加Redis Set的SADD操作，确保去重判断的精确性。

```java
/**
 * 点赞核心写入服务（全链路版）
 */
@Service
@Slf4j
public class LikeWriteFullService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Autowired
    private LikeDeduplicationEnhancedService deduplicationService;

    @Autowired
    private LikeCountCacheService countCacheService;

    @Autowired
    private LikeMqProducer mqProducer;

    @Autowired
    private RateLimiter rateLimiter;

    @Autowired
    private LikeChangeTracker changeTracker;

    // Lua脚本：原子执行 Set标记 + 计数+1 + 用户列表写入 + Set去重
    private static final String LIKE_LUA_SCRIPT =
        "-- KEYS[1]=set_key, KEYS[2]=count_hash_key, KEYS[3]=user_zset_key, KEYS[4]=bitmap_key\n" +
        "-- ARGV[1]=userId, ARGV[2]=targetId, ARGV[3]=timestamp, ARGV[4]=bitmap_offset\n" +
        "local already = redis.call('SISMEMBER', KEYS[1], ARGV[1])\n" +
        "if already == 1 then\n" +
        "    return 0  -- 已点赞\n" +
        "end\n" +
        "redis.call('SADD', KEYS[1], ARGV[1])\n" +
        "redis.call('HINCRBY', KEYS[2], ARGV[2], 1)\n" +
        "redis.call('ZADD', KEYS[3], ARGV[3], ARGV[1])\n" +
        "redis.call('SETBIT', KEYS[4], ARGV[4], 1)\n" +
        "return 1";

    private final DefaultRedisScript<Long> likeScript;

    public LikeWriteFullService() {
        likeScript = new DefaultRedisScript<>(LIKE_LUA_SCRIPT, Long.class);
    }

    /**
     * 执行点赞操作
     */
    public LikeResult doLike(long userId, long targetId, int targetType) {
        String traceId = MDC.get("traceId");

        // 步骤1：频率限制
        if (!rateLimiter.tryAcquire(userId, "like", 10, 1)) {
            log.warn("[点赞] 触发频率限制, userId={}, traceId={}", userId, traceId);
            return LikeResult.fail("操作过于频繁，请稍后再试");
        }

        // 步骤2：重复点赞校验（SISMEMBER）
        if (deduplicationService.hasLiked(userId, targetId, targetType)) {
            log.info("[点赞] 用户已点赞, userId={}, targetId={}, traceId={}", userId, targetId, traceId);
            long currentCount = countCacheService.getCount(targetId, targetType);
            return LikeResult.alreadyLiked(currentCount);
        }

        // 步骤3：Lua脚本原子操作
        String setKey = String.format("like:set:%d:%d", targetType, targetId);
        String countKey = "like:count:" + targetType;
        String userListKey = String.format("like:user:%d:%d", userId, targetType);
        String bitmapKey = String.format("like:bitmap:%d:%d", targetType, targetId);
        int bitmapOffset = (int) (Math.abs(MurmurHash.hash64(userId)) % 10_000_000);
        long timestamp = System.currentTimeMillis();

        Long result;
        try {
            result = redisTemplate.execute(likeScript,
                    Arrays.asList(setKey, countKey, userListKey, bitmapKey),
                    String.valueOf(userId),
                    String.valueOf(targetId),
                    String.valueOf(timestamp),
                    String.valueOf(bitmapOffset));
        } catch (Exception e) {
            log.error("[点赞] Redis Lua脚本执行异常, userId={}, targetId={}, traceId={}",
                    userId, targetId, traceId, e);
            // 降级：直接发MQ消息，由消费端直接写MySQL
            sendFallbackMqMessage(userId, targetId, targetType, LikeAction.LIKE);
            return LikeResult.success("操作成功，数据可能延迟展示");
        }

        if (result == null || result != 1) {
            log.warn("[点赞] Lua脚本返回非1, result={}, userId={}, targetId={}, traceId={}",
                    result, userId, targetId, traceId);
            long currentCount = countCacheService.getCount(targetId, targetType);
            return LikeResult.alreadyLiked(currentCount);
        }

        log.info("[点赞] Redis写入成功, userId={}, targetId={}, targetType={}, traceId={}",
                userId, targetId, targetType, traceId);

        // 步骤4：获取最新点赞数
        long latestCount = countCacheService.getCount(targetId, targetType);

        // 步骤5：记录变更，供定时同步任务消费
        changeTracker.trackChange(targetId, targetType);

        // 步骤6：异步发送MQ消息落库
        LikeEvent event = new LikeEvent();
        event.setUserId(userId);
        event.setTargetId(targetId);
        event.setTargetType(targetType);
        event.setAction(LikeAction.LIKE);
        event.setTimestamp(timestamp);
        event.setEventId(generateEventId(userId, targetId, targetType, LikeAction.LIKE));

        try {
            mqProducer.sendLikeEvent(event);
            log.info("[点赞] MQ消息发送成功, eventId={}, traceId={}", event.getEventId(), traceId);
        } catch (Exception e) {
            log.error("[点赞] MQ发送失败, eventId={}, traceId={}", event.getEventId(), traceId, e);
            // MQ发送失败不影响用户体验，由对账任务补偿
        }

        // 步骤7：异步发送通知MQ消息
        try {
            mqProducer.sendNotificationEvent(event);
        } catch (Exception e) {
            log.warn("[点赞] 通知MQ发送失败, userId={}, targetId={}, traceId={}",
                    userId, targetId, traceId, e);
        }

        return LikeResult.success(latestCount);
    }

    /**
     * 降级：Redis不可用时直接发MQ
     */
    private void sendFallbackMqMessage(long userId, long targetId, int targetType, LikeAction action) {
        String traceId = MDC.get("traceId");
        LikeEvent event = new LikeEvent();
        event.setUserId(userId);
        event.setTargetId(targetId);
        event.setTargetType(targetType);
        event.setAction(action);
        event.setTimestamp(System.currentTimeMillis());
        event.setEventId(generateEventId(userId, targetId, targetType, action));
        event.setFallback(true); // 标记为降级消息，消费端需额外处理

        try {
            mqProducer.sendLikeEvent(event);
```

#### 7.1.6 取消点赞的逆向流程

取消点赞是点赞的逆操作，使用SREM移除Set中的用户、DECR减少计数、ZREM移除用户点赞列表中的记录。

```java
/**
 * 取消点赞服务（全链路版）
 */
@Service
@Slf4j
public class LikeUndoFullService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Autowired
    private LikeDeduplicationEnhancedService deduplicationService;

    @Autowired
    private LikeCountCacheService countCacheService;

    @Autowired
    private LikeMqProducer mqProducer;

    @Autowired
    private LikeChangeTracker changeTracker;

    // Lua脚本：原子执行 Set移除 + 计数-1 + 用户列表移除 + Bitmap清除
    private static final String UNDO_LIKE_LUA_SCRIPT =
        "-- KEYS[1]=set_key, KEYS[2]=count_hash_key, KEYS[3]=user_zset_key, KEYS[4]=bitmap_key\n" +
        "-- ARGV[1]=userId, ARGV[2]=targetId, ARGV[3]=bitmap_offset\n" +
        "local already = redis.call('SISMEMBER', KEYS[1], ARGV[1])\n" +
        "if already == 0 then\n" +
        "    return 0  -- 未点赞，无需取消\n" +
        "end\n" +
        "redis.call('SREM', KEYS[1], ARGV[1])\n" +
        "redis.call('HINCRBY', KEYS[2], ARGV[2], -1)\n" +
        "redis.call('ZREM', KEYS[3], ARGV[1])\n" +
        "redis.call('SETBIT', KEYS[4], ARGV[3], 0)\n" +
        "return 1";

    private final DefaultRedisScript<Long> undoScript;

    public LikeUndoFullService() {
        undoScript = new DefaultRedisScript<>(UNDO_LIKE_LUA_SCRIPT, Long.class);
    }

    /**
     * 执行取消点赞
     */
    public LikeResult undoLike(long userId, long targetId, int targetType) {
        String traceId = MDC.get("traceId");

        // 幂等判断：如果当前就是未点赞状态，直接返回成功
        if (!deduplicationService.hasLiked(userId, targetId, targetType)) {
            log.info("[取消点赞] 用户未点赞，幂等返回, userId={}, targetId={}, traceId={}",
                    userId, targetId, traceId);
            long currentCount = countCacheService.getCount(targetId, targetType);
            return LikeResult.success(currentCount);
        }

        // Lua脚本原子操作
        String setKey = String.format("like:set:%d:%d", targetType, targetId);
        String countKey = "like:count:" + targetType;
        String userListKey = String.format("like:user:%d:%d", userId, targetType);
        String bitmapKey = String.format("like:bitmap:%d:%d", targetType, targetId);
        int bitmapOffset = (int) (Math.abs(MurmurHash.hash64(userId)) % 10_000_000);

        Long result;
        try {
            result = redisTemplate.execute(undoScript,
                    Arrays.asList(setKey, countKey, userListKey, bitmapKey),
                    String.valueOf(userId),
                    String.valueOf(targetId),
                    String.valueOf(bitmapOffset));
        } catch (Exception e) {
            log.error("[取消点赞] Redis Lua脚本执行异常, userId={}, targetId={}, traceId={}",
                    userId, targetId, traceId, e);
            // 降级：直接发MQ消息
            sendFallbackMqMessage(userId, targetId, targetType, LikeAction.UNLIKE);
            return LikeResult.success("操作成功，数据可能延迟展示");
        }

        if (result == null || result != 1) {
            log.warn("[取消点赞] Lua脚本返回非1, result={}, userId={}, targetId={}, traceId={}",
                    result, userId, targetId, traceId);
            long currentCount = countCacheService.getCount(targetId, targetType);
            return LikeResult.success(currentCount);
        }

        log.info("[取消点赞] Redis操作成功, userId={}, targetId={}, targetType={}, traceId={}",
                userId, targetId, targetType, traceId);

        // 获取最新点赞数
        long latestCount = countCacheService.getCount(targetId, targetType);

        // 记录变更
        changeTracker.trackChange(targetId, targetType);

        // 异步发送MQ消息落库
        LikeEvent event = new LikeEvent();
        event.setUserId(userId);
        event.setTargetId(targetId);
        event.setTargetType(targetType);
        event.setAction(LikeAction.UNLIKE);
        event.setTimestamp(System.currentTimeMillis());
        event.setEventId(generateEventId(userId, targetId, targetType, LikeAction.UNLIKE));

        try {
            mqProducer.sendLikeEvent(event);
            log.info("[取消点赞] MQ消息发送成功, eventId={}, traceId={}", event.getEventId(), traceId);
        } catch (Exception e) {
            log.error("[取消点赞] MQ发送失败, eventId={}, traceId={}", event.getEventId(), traceId, e);
        }

        return LikeResult.success(latestCount);
    }

    /**
     * 降级发送MQ
     */
    private void sendFallbackMqMessage(long userId, long targetId, int targetType, LikeAction action) {
        LikeEvent event = new LikeEvent();
        event.setUserId(userId);
        event.setTargetId(targetId);
        event.setTargetType(targetType);
        event.setAction(action);
        event.setTimestamp(System.currentTimeMillis());
        event.setEventId(generateEventId(userId, targetId, targetType, action));
        event.setFallback(true);
        try {
            mqProducer.sendLikeEvent(event);
        } catch (Exception e) {
            log.error("[取消点赞] 降级MQ也失败, userId={}, targetId={}", userId, targetId, e);
        }
    }

    private String generateEventId(long userId, long targetId, int targetType, LikeAction action) {
        return String.format("%d:%d:%d:%s:%d", userId, targetId, targetType, action.name(),
                System.currentTimeMillis() / 1000);
    }
}
```

#### 7.1.7 幂等控制全链路

幂等控制贯穿整个链路，分为三层：

```
请求层 → Redis层 → MQ消费层

[请求层] 客户端防抖300ms + 服务端频率限制
    │
    ▼
[Redis层] Lua脚本内SISMEMBER判断，原子保证不重复写入
    │
    ▼
[MQ消费层] eventId去重 + MySQL唯一索引兜底
```

```java
/**
 * 幂等服务
 * 基于Redis实现幂等判断，TTL为24小时
 */
@Service
@Slf4j
public class IdempotentServiceImpl implements IdempotentService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    private static final String IDEMPOTENT_KEY_PREFIX = "like:idempotent:";
    private static final long TTL_HOURS = 24;

    /**
     * 判断事件是否已处理
     * 使用SETNX实现原子性的"检查+标记"
     *
     * @return true-已处理，false-未处理
     */
    @Override
    public boolean isProcessed(String eventId) {
        String key = IDEMPOTENT_KEY_PREFIX + eventId;
        try {
            Boolean result = redisTemplate.opsForValue().setIfAbsent(key, "1", TTL_HOURS, TimeUnit.HOURS);
            // setIfAbsent返回true表示设置成功（即之前不存在），返回false表示已存在
            return !Boolean.TRUE.equals(result);
        } catch (Exception e) {
            log.warn("[幂等] Redis异常, 降级放行, eventId={}", eventId, e);
            // 降级：Redis不可用时放行，由数据库唯一索引兜底
            return false;
        }
    }

    /**
     * 标记事件已处理
     */
    @Override
    public void markProcessed(String eventId) {
        String key = IDEMPOTENT_KEY_PREFIX + eventId;
        try {
            redisTemplate.opsForValue().set(key, "1", TTL_HOURS, TimeUnit.HOURS);
        } catch (Exception e) {
            log.warn("[幂等] 标记处理失败, eventId={}", eventId, e);
        }
    }

    /**
     * 批量判断事件是否已处理
     */
    @Override
    public Map<String, Boolean> batchCheckProcessed(List<String> eventIds) {
        Map<String, Boolean> result = new HashMap<>();
        for (String eventId : eventIds) {
            result.put(eventId, isProcessed(eventId));
        }
        return result;
    }
}
```

### 7.2 案例二：点赞状态批量查询全链路

#### 7.2.1 链路概述

用户打开Feed流或评论列表时，需要批量查询当前用户对这些内容的点赞状态以及每条内容的点赞数。这条链路的核心挑战在于**低延迟批量查询**。

```
用户打开Feed流
    │
    ▼
[1] Feed服务返回内容列表（N条内容）
    │
    ▼
[2] 批量查询点赞状态：Redis Pipeline批量SISMEMBER
    │  ├── 缓存命中 → 直接返回点赞状态
    │  └── 缓存未命中 → 数据库回源 + 回填缓存
    ▼
[3] 批量查询点赞计数：Redis Hash批量HGET
    │  ├── 缓存命中 → 直接返回计数
    │  └── 缓存未命中 → 数据库回源 + 回填缓存
    ▼
[4] 组装结果返回客户端
```

#### 7.2.2 批量查询点赞状态

```java
/**
 * 点赞批量查询服务（全链路版）
 */
@Service
@Slf4j
public class LikeBatchQueryService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Autowired
    private LikeRelationMapper likeRelationMapper;

    @Autowired
    private LikeCountMapper likeCountMapper;

    private static final int BITMAP_SIZE = 10_000_000;

    /**
     * 批量查询用户对多条内容的点赞状态 + 点赞数
     * 一次调用返回完整数据，避免多次网络往返
     *
     * @param userId     当前用户ID
     * @param targetIds  内容ID列表
     * @param targetType 内容类型
     * @return 点赞状态与计数结果
     */
    public LikeBatchResult batchQuery(long userId, List<Long> targetIds, int targetType) {
        String traceId = MDC.get("traceId");
        long startTime = System.currentTimeMillis();

        if (targetIds == null || targetIds.isEmpty()) {
            return LikeBatchResult.empty();
        }

        log.info("[批量查询] 开始, userId={}, targetIds.size={}, targetType={}, traceId={}",
                userId, targetIds.size(), targetType, traceId);

        // 并行执行：批量查询点赞状态 + 批量查询点赞计数
        Map<Long, Boolean> likedStatus;
        Map<Long, Long> likeCounts;

        try {
            likedStatus = batchCheckLiked(userId, targetIds, targetType);
        } catch (Exception e) {
            log.error("[批量查询] 点赞状态查询异常, userId={}, traceId={}", userId, traceId, e);
            likedStatus = targetIds.stream().collect(Collectors.toMap(id -> id, id -> false));
        }

        try {
            likeCounts = batchGetCounts(targetIds, targetType);
        } catch (Exception e) {
            log.error("[批量查询] 点赞计数查询异常, userId={}, traceId={}", userId, traceId, e);
            likeCounts = targetIds.stream().collect(Collectors.toMap(id -> id, id -> 0L));
        }

        long costMs = System.currentTimeMillis() - startTime;
        log.info("[批量查询] 完成, userId={}, size={}, costMs={}, traceId={}",
                userId, targetIds.size(), costMs, traceId);

        return new LikeBatchResult(likedStatus, likeCounts);
    }

    /**
     * 批量查询用户是否已点赞（Pipeline + SISMEMBER）
     * 使用Redis Pipeline一次性发送所有SISMEMBER命令，减少网络RTT
     */
    public Map<Long, Boolean> batchCheckLiked(long userId, List<Long> targetIds, int targetType) {
        String traceId = MDC.get("traceId");
        Map<Long, Boolean> result = new HashMap<>();
        List<Long> missedTargetIds = new ArrayList<>();

        // 第一层：Redis Pipeline批量SISMEMBER
        try {
            List<Object> pipelineResults = redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
                for (Long targetId : targetIds) {
                    String setKey = String.format("like:set:%d:%d", targetType, targetId);
                    connection.setCommands().sIsMember(setKey.getBytes(), String.valueOf(userId).getBytes());
                }
                return null;
            });

            for (int i = 0; i < targetIds.size(); i++) {
                Boolean isMember = (Boolean) pipelineResults.get(i);
                if (Boolean.TRUE.equals(isMember)) {
                    result.put(targetIds.get(i), true);
                } else {
                    // SISMEMBER返回false有两种情况：确实未点赞，或者Set不存在（缓存未命中）
                    // 需要进一步判断Set是否存在
                    missedTargetIds.add(targetIds.get(i));
                    result.put(targetIds.get(i), false);
                }
            }
        } catch (Exception e) {
            log.error("[批量查询] Pipeline SISMEMBER异常, 降级查DB, userId={}, traceId={}",
                    userId, traceId, e);
            // 全量降级查DB
            missedTargetIds = new ArrayList<>(targetIds);
        }

        // 第二层：对未命中的targetId，检查Set是否存在（区分"未点赞"和"缓存未命中"）
        if (!missedTargetIds.isEmpty()) {
            List<Long> dbQueryIds = new ArrayList<>();

            try {
                List<Object> existsResults = redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
                    for (Long targetId : missedTargetIds) {
                        String setKey = String.format("like:set:%d:%d", targetType, targetId);
                        connection.keyCommands().exists(setKey.getBytes());
                    }
                    return null;
                });

                for (int i = 0; i < missedTargetIds.size(); i++) {
                    Long exists = (Long) existsResults.get(i);
                    if (exists == null || exists == 0) {
                        // Set不存在，说明缓存未命中，需要回源数据库
                        dbQueryIds.add(missedTargetIds.get(i));
                    }
                    // Set存在但SISMEMBER返回false，说明确实未点赞，result已经是false，无需处理
                }
            } catch (Exception e) {
                log.warn("[批量查询] EXISTS检查异常, 全部回源DB, traceId={}", traceId, e);
                dbQueryIds = new ArrayList<>(missedTargetIds);
            }

            // 第三层：数据库回源
            if (!dbQueryIds.isEmpty()) {
                Map<Long, Boolean> dbResults = batchCheckLikedFromDB(userId, dbQueryIds, targetType);
                result.putAll(dbResults);

                // 异步回填缓存
                asyncBackfillLikedStatus(userId, dbResults, targetType);
            }
        }

        return result;
    }

    /**
     * 数据库批量回源查询点赞状态
     */
    private Map<Long, Boolean> batchCheckLikedFromDB(long userId, List<Long> targetIds, int targetType) {
        String traceId = MDC.get("traceId");
        try {
            // 批量查询：SELECT target_id, status FROM t_like_relation
            // WHERE user_id = ? AND target_id IN (...) AND target_type = ?
            List<LikeRelation> relations = likeRelationMapper.batchFindByUserAndTargets(
                    userId, targetIds, targetType);

            Set<Long> likedTargetIds = relations.stream()
                    .filter(r -> r.getStatus() == 1)
                    .map(LikeRelation::getTargetId)
                    .collect(Collectors.toSet());

            Map<Long, Boolean> result = new HashMap<>();
            for (Long targetId : targetIds) {
                result.put(targetId, likedTargetIds.contains(targetId));
            }

            log.info("[批量查询] DB回源完成, userId={}, querySize={}, likedCount={}, traceId={}",
                    userId, targetIds.size(), likedTargetIds.size(), traceId);
            return result;

        } catch (Exception e) {
            log.error("[批量查询] DB回源异常, userId={}, traceId={}", userId, traceId, e);
            // 降级：全部返回false
            Map<Long, Boolean> result = new HashMap<>();
            for (Long targetId : targetIds) {
                result.put(targetId, false);
            }
            return result;
        }
    }

    /**
     * 异步回填缓存
     * 将数据库查询结果回填到Redis Set中
     */
    @Async
    public void asyncBackfillLikedStatus(long userId, Map<Long, Boolean> dbResults, int targetType) {
        String traceId = MDC.get("traceId");
        try {
            for (Map.Entry<Long, Boolean> entry : dbResults.entrySet()) {
                if (entry.getValue()) {
                    // 用户已点赞，回填Set
                    String setKey = String.format("like:set:%d:%d", targetType, entry.getKey());
                    redisTemplate.opsForSet().add(setKey, String.valueOf(userId));
                }
                // 未点赞的不回填，Set在首次有人点赞时自动创建
            }
            log.info("[批量查询] 缓存回填完成, userId={}, targetType={}, traceId={}",
                    userId, targetType, traceId);
        } catch (Exception e) {
            log.warn("[批量查询] 缓存回填失败, userId={}, traceId={}", userId, traceId, e);
        }
    }

    /**
     * 批量查询点赞计数（Pipeline + HGET）
     */
    public Map<Long, Long> batchGetCounts(List<Long> targetIds, int targetType) {
        String traceId = MDC.get("traceId");
        String countKey = "like:count:" + targetType;

        // Redis Pipeline批量HGET
        List<Object> pipelineResults;
        try {
            pipelineResults = redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
                for (Long targetId : targetIds) {
                    connection.hashCommands().hGet(countKey.getBytes(), String.valueOf(targetId).getBytes());
                }
                return null;
            });
        } catch (Exception e) {
            log.error("[批量查询] Pipeline HGET异常, 降级查DB, traceId={}", traceId, e);
            return batchGetCountsFromDB(targetIds, targetType);
        }

        Map<Long, Long> result = new HashMap<>();
        List<Long> missedIds = new ArrayList<>();

        for (int i = 0; i < targetIds.size(); i++) {
            Object value = pipelineResults.get(i);
            if (value != null) {
                result.put(targetIds.get(i), Long.parseLong(value.toString()));
            } else {
                missedIds.add(targetIds.get(i));
                result.put(targetIds.get(i), 0L); // 暂时设为0，后续回源修正
            }
        }

        // 缓存未命中的，回源数据库
        if (!missedIds.isEmpty()) {
            Map<Long, Long> dbCounts = batchGetCountsFromDB(missedIds, targetType);
            result.putAll(dbCounts);

            // 异步回填缓存
            asyncBackfillCounts(dbCounts, targetType);
        }

        return result;
    }

    /**
     * 数据库批量回源查询点赞计数
     */
    private Map<Long, Long> batchGetCountsFromDB(List<Long> targetIds, int targetType) {
        String traceId = MDC.get("traceId");
        try {
            // SELECT target_id, like_count FROM t_like_count
            // WHERE target_id IN (...) AND target_type = ?
            List<LikeCount> counts = likeCountMapper.batchFindByTargets(targetIds, targetType);

            Map<Long, Long> result = new HashMap<>();
            Set<Long> foundIds = new HashSet<>();
            for (LikeCount lc : counts) {
                result.put(lc.getTargetId(), lc.getLikeCount());
                foundIds.add(lc.getTargetId());
            }
            // 未找到的设为0
            for (Long targetId : targetIds) {
                if (!foundIds.contains(targetId)) {
                    result.put(targetId, 0L);
                }
            }

            log.info("[批量查询] 计数DB回源完成, querySize={}, found={}, traceId={}",
                    targetIds.size(), foundIds.size(), traceId);
            return result;

        } catch (Exception e) {
            log.error("[批量查询] 计数DB回源异常, traceId={}", traceId, e);
            Map<Long, Long> result = new HashMap<>();
            for (Long targetId : targetIds) {
                result.put(targetId, 0L);
            }
            return result;
        }
    }

    /**
     * 异步回填点赞计数缓存
     */
    @Async
    public void asyncBackfillCounts(Map<Long, Long> counts, int targetType) {
        String countKey = "like:count:" + targetType;
        try {
            redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
                for (Map.Entry<Long, Long> entry : counts.entrySet()) {
                    if (entry.getValue() > 0) {
                        connection.hashCommands().hSet(
                                countKey.getBytes(),
                                String.valueOf(entry.getKey()).getBytes(),
                                String.valueOf(entry.getValue()).getBytes());
                    }
                }
                return null;
            });
        } catch (Exception e) {
            log.warn("[批量查询] 计数缓存回填失败", e);
        }
    }
```

### 7.3 案例三：点赞数据定时同步全链路

#### 7.3.1 链路概述

由于点赞系统采用"先写Redis、异步写MySQL"的架构，Redis和MySQL之间存在数据延迟。定时同步任务负责将Redis中的增量变更同步到MySQL，并进行一致性对账。完整链路如下：

```
定时任务触发（每5分钟）
    │
    ▼
[1] 扫描Redis变更集合（like:changed Set）
    │
    ▼
[2] 批量读取Redis中的点赞计数和关系
    │
    ▼
[3] 批量写入MySQL（INSERT ON DUPLICATE KEY UPDATE）
    │
    ▼
[4] 一致性对账：Redis计数 vs MySQL计数 vs MySQL实际关系统计
    │  ├── 一致 → 清除变更标记
    │  └── 不一致 → 修正 + 告警
    ▼
[5] 生成对账报告
```

#### 7.3.2 Redis变更集合设计

在点赞写入时，同步将变更的targetId写入一个Redis Set，定时任务扫描此Set获取需要同步的内容列表。

```java
/**
 * 点赞变更追踪服务
 * 使用Redis Set记录有变更的targetId，供定时同步任务消费
 */
@Service
@Slf4j
public class LikeChangeTracker {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    private static final String CHANGED_SET_KEY = "like:changed:targets";
    private static final String CHANGED_DETAIL_KEY = "like:changed:detail"; // Hash: targetId -> 变更时间戳

    /**
     * 记录点赞变更
     * 在点赞/取消点赞时调用
     */
    public void trackChange(long targetId, int targetType) {
        String traceId = MDC.get("traceId");
        try {
            String compositeKey = targetType + ":" + targetId;
            redisTemplate.opsForSet().add(CHANGED_SET_KEY, compositeKey);
            redisTemplate.opsForHash().put(CHANGED_DETAIL_KEY, compositeKey,
                    String.valueOf(System.currentTimeMillis()));
        } catch (Exception e) {
            log.warn("[变更追踪] 记录失败, targetId={}, targetType={}, traceId={}",
                    targetId, targetType, traceId, e);
            // 变更追踪失败不影响主流程，对账任务会通过全量扫描兜底
        }
    }

    /**
     * 获取所有变更的targetId
     */
    public Set<String> getChangedTargets() {
        try {
            return redisTemplate.opsForSet().members(CHANGED_SET_KEY);
        } catch (Exception e) {
            log.error("[变更追踪] 获取变更列表失败", e);
            return Collections.emptySet();
        }
    }

    /**
     * 清除已同步的变更标记
     */
    public void clearChangedTargets(Set<String> syncedTargets) {
        String traceId = MDC.get("traceId");
        try {
            if (syncedTargets == null || syncedTargets.isEmpty()) {
                return;
            }
            String[] targets = syncedTargets.toArray(new String[0]);
            redisTemplate.opsForSet().remove(CHANGED_SET_KEY, (Object[]) targets);

            // 清理detail Hash
            for (String target : syncedTargets) {
                redisTemplate.opsForHash().delete(CHANGED_DETAIL_KEY, target);
            }

            log.info("[变更追踪] 清除变更标记, count={}, traceId={}", syncedTargets.size(), traceId);
        } catch (Exception e) {
            log.error("[变更追踪] 清除变更标记失败, traceId={}", traceId, e);
        }
    }
}
```

#### 7.3.3 定时同步任务

```java
/**
 * 点赞数据定时同步任务（全链路版）
 * 每5分钟扫描Redis变更集合，批量同步到MySQL，并执行一致性对账
 */
@Component
@Slf4j
public class LikeSyncTask {

    @Autowired
    private LikeChangeTracker changeTracker;

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Autowired
    private LikeRelationMapper likeRelationMapper;

    @Autowired
    private LikeCountMapper likeCountMapper;

    @Autowired
    private AlertService alertService;

    private static final int BATCH_SIZE = 200;
    private static final int MAX_SYNC_PER_ROUND = 10000; // 每轮最多同步1万条

    /**
     * 定时同步任务：每5分钟执行
     */
    @Scheduled(fixedDelay = 5 * 60 * 1000)
    public void syncLikeData() {
        String traceId = "sync_" + System.currentTimeMillis();
        MDC.put("traceId", traceId);

        long startTime = System.currentTimeMillis();
        log.info("[定时同步] 任务开始, traceId={}", traceId);

        try {
            // 步骤1：获取变更的targetId列表
            Set<String> changedTargets = changeTracker.getChangedTargets();
            if (changedTargets == null || changedTargets.isEmpty()) {
                log.info("[定时同步] 无变更数据, traceId={}", traceId);
                return;
            }

            log.info("[定时同步] 待同步变更数, count={}, traceId={}", changedTargets.size(), traceId);

            // 限制每轮处理数量，防止积压时任务执行时间过长
            List<String> targetList = changedTargets.stream()
                    .limit(MAX_SYNC_PER_ROUND)
                    .collect(Collectors.toList());

            // 步骤2：分批处理
            int totalSynced = 0;
            int totalReconciled = 0;
            int totalErrors = 0;
            Set<String> syncedTargets = new HashSet<>();

            List<List<String>> batches = partition(targetList, BATCH_SIZE);
            for (List<String> batch : batches) {
                try {
                    SyncResult result = syncBatch(batch);
                    totalSynced += result.getSyncedCount();
                    totalReconciled += result.getReconciledCount();
                    totalErrors += result.getErrorCount();
                    syncedTargets.addAll(result.getSyncedTargets());
                } catch (Exception e) {
                    log.error("[定时同步] 批次处理异常, batchSize={}, traceId={}", batch.size(), traceId, e);
                    totalErrors += batch.size();
                }
            }

            // 步骤3：清除已同步的变更标记
            changeTracker.clearChangedTargets(syncedTargets);

            long costMs = System.currentTimeMillis() - startTime;
            log.info("[定时同步] 任务完成, totalSynced={}, totalReconciled={}, totalErrors={}, costMs={}, traceId={}",
                    totalSynced, totalReconciled, totalErrors, costMs, traceId);

            // 异常告警
            if (totalErrors > 0) {
                alertService.warn(String.format(
                        "点赞同步任务存在错误: synced=%d, reconciled=%d, errors=%d, costMs=%d",
                        totalSynced, totalReconciled, totalErrors, costMs));
            }

        } catch (Exception e) {
            log.error("[定时同步] 任务异常, traceId={}", traceId, e);
            alertService.error("点赞定时同步任务异常: " + e.getMessage());
        } finally {
            MDC.remove("traceId");
        }
    }

    /**
     * 同步一个批次
     */
    private SyncResult syncBatch(List<String> batch) {
        String traceId = MDC.get("traceId");
        SyncResult result = new SyncResult();
        List<LikeCountSyncItem> syncItems = new ArrayList<>();

        // 解析批次，读取Redis中的计数
        for (String compositeKey : batch) {
            String[] parts = compositeKey.split(":");
            int targetType = Integer.parseInt(parts[0]);
            long targetId = Long.parseLong(parts[1]);

            try {
                // 读取Redis计数
                String countKey = "like:count:" + targetType;
                Object redisCountObj = redisTemplate.opsForHash().get(countKey, String.valueOf(targetId));
                long redisCount = redisCountObj != null ? Long.parseLong(redisCountObj.toString()) : 0L;

                LikeCountSyncItem item = new LikeCountSyncItem();
                item.setTargetId(targetId);
                item.setTargetType(targetType);
                item.setRedisCount(redisCount);
                syncItems.add(item);

            } catch (Exception e) {
                log.error("[定时同步] 读取Redis计数失败, key={}, traceId={}", compositeKey, traceId, e);
                result.incrementError();
            }
        }

        // 批量写入MySQL计数表
        if (!syncItems.isEmpty()) {
            batchUpsertCounts(syncItems);
        }

        // 一致性对账
        for (LikeCountSyncItem item : syncItems) {
            try {
                boolean consistent = reconcile(item);
                if (consistent) {
                    result.addSyncedTarget(item.getTargetType() + ":" + item.getTargetId());
                    result.incrementSynced();
                } else {
                    result.incrementReconciled();
                    result.addSyncedTarget(item.getTargetType() + ":" + item.getTargetId());
                }
            } catch (Exception e) {
                log.error("[定时同步] 对账失败, targetId={}, traceId={}", item.getTargetId(), traceId, e);
                result.incrementError();
            }
        }

        return result;
    }

    /**
     * 批量写入MySQL计数表
     * 使用 INSERT ... ON DUPLICATE KEY UPDATE
     */
    private void batchUpsertCounts(List<LikeCountSyncItem> items) {
        String traceId = MDC.get("traceId");
        try {
            // 构建批量SQL
            // INSERT INTO t_like_count (target_id, target_type, like_count, version)
            // VALUES (?, ?, ?, 0)
            // ON DUPLICATE KEY UPDATE like_count = VALUES(like_count), update_time = NOW()
            likeCountMapper.batchUpsertCounts(items);
            log.info("[定时同步] 批量写入计数表成功, size={}, traceId={}", items.size(), traceId);
        } catch (Exception e) {
            log.error("[定时同步] 批量写入计数表失败, size={}, traceId={}", items.size(), traceId, e);
            // 降级：逐条写入
            for (LikeCountSyncItem item : items) {
                try {
                    likeCountMapper.upsertCount(item.getTargetId(), item.getTargetType(), item.getRedisCount());
                } catch (Exception ex) {
                    log.error("[定时同步] 单条写入也失败, targetId={}", item.getTargetId(), ex);
                }
            }
        }
    }

    /**
     * 单条对账：Redis计数 vs MySQL计数表 vs MySQL关系表实际统计
     */
    private boolean reconcile(LikeCountSyncItem item) {
        String traceId = MDC.get("traceId");
        long targetId = item.getTargetId();
        int targetType = item.getTargetType();
        long redisCount = item.getRedisCount();

        // 从MySQL计数表读取
        LikeCount dbCountRecord = likeCountMapper.findByTarget(targetId, targetType);
        long dbCount = dbCountRecord != null ? dbCountRecord.getLikeCount() : 0L;

        // 从MySQL关系表统计实际点赞数
        long actualCount = likeRelationMapper.countByTarget(targetId, targetType);

        boolean consistent = true;

        // 对比三方数据
        if (redisCount != actualCount) {
            log.warn("[对账] Redis与实际不一致, targetId={}, redisCount={}, actualCount={}, traceId={}",
                    targetId, redisCount, actualCount, traceId);
            // 以MySQL实际关系为准，修正Redis
            String countKey = "like:count:" + targetType;
            redisTemplate.opsForHash().put(countKey, String.valueOf(targetId), String.valueOf(actualCount));
            consistent = false;
        }

        if (dbCount != actualCount) {
            log.warn("[对账] MySQL计数表与实际不一致, targetId={}, dbCount={}, actualCount={}, traceId={}",
                    targetId, dbCount, actualCount, traceId);
            // 以MySQL实际关系为准，修正计数表
            likeCountMapper.updateCount(targetId, targetType, actualCount);
            consistent = false;
        }

        if (consistent) {
            log.debug("[对账] 数据一致, targetId={}, count={}, traceId={}", targetId, actualCount, traceId);
        }

        return consistent;
    }

    /**
     * 分批工具
     */
    private <T> List<List<T>> partition(List<T> list, int size) {
        List<List<T>> partitions = new ArrayList<>();
        for (int i = 0; i < list.size(); i += size) {
            partitions.add(list.subList(i, Math.min(i + size, list.size())));
        }
        return partitions;
    }
}
```

#### 7.3.4 对账报告生成

```java
/**
 * 点赞数据对账报告
 * 每日全量对账，生成报告用于运维监控
 */
@Component
@Slf4j
public class LikeReconciliationReportService {

    @Autowired
    private LikeCountMapper likeCountMapper;

    @Autowired
    private LikeRelationMapper likeRelationMapper;

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Autowired
    private AlertService alertService;

    /**
     * 每日凌晨3点全量对账
     */
    @Scheduled(cron = "0 0 3 * * ?")
    public void dailyFullReconciliation() {
        String traceId = "reconcile_" + System.currentTimeMillis();
        MDC.put("traceId", traceId);

        long startTime = System.currentTimeMillis();
        log.info("[全量对账] 任务开始, traceId={}", traceId);

        ReconciliationReport report = new ReconciliationReport();
        report.setStartTime(new Date());

        try {
            int pageSize = 1000;
            long lastId = 0;

            while (true) {
                // 分页扫描MySQL计数表
                List<LikeCount> dbCounts = likeCountMapper.scanByPage(lastId, pageSize);
                if (dbCounts == null || dbCounts.isEmpty()) {
                    break;
                }

                for (LikeCount dbCount : dbCounts) {
                    report.incrementTotalChecked();

                    try {
                        // 三方对账
                        long actualCount = likeRelationMapper.countByTarget(
                                dbCount.getTargetId(), dbCount.getTargetType());

                        long redisCount = getRedisCount(dbCount.getTargetId(), dbCount.getTargetType());

                        if (dbCount.getLikeCount() != actualCount) {
                            // MySQL计数表与实际不一致
                            likeCountMapper.updateCount(
                                    dbCount.getTargetId(), dbCount.getTargetType(), actualCount);
                            report.incrementDbFixed();
                            log.warn("[全量对账] 修正MySQL计数, targetId={}, dbCount={}, actualCount={}",
                                    dbCount.getTargetId(), dbCount.getLikeCount(), actualCount);
                        }

                        if (redisCount != actualCount) {
                            // Redis与实际不一致
                            setRedisCount(dbCount.getTargetId(), dbCount.getTargetType(), actualCount);
                            report.incrementRedisFixed();
                            log.warn("[全量对账] 修正Redis计数, targetId={}, redisCount={}, actualCount={}",
                                    dbCount.getTargetId(), redisCount, actualCount);
                        }

                    } catch (Exception e) {
                        report.incrementErrors();
                        log.error("[全量对账] 单条对账异常, targetId={}, traceId={}",
                                dbCount.getTargetId(), traceId, e);
                    }
                }

                lastId = dbCounts.get(dbCounts.size() - 1).getId();

                // 每处理1万条打印一次进度
                if (report.getTotalChecked() % 10000 == 0) {
                    log.info("[全量对账] 进度, checked={}, traceId={}", report.getTotalChecked(), traceId);
                }
            }

        } catch (Exception e) {
            log.error("[全量对账] 任务异常, traceId={}", traceId, e);
            report.setErrorMessage(e.getMessage());
        }

        report.setEndTime(new Date());
        report.setCostMs(System.currentTimeMillis() - startTime);

        // 输出对账报告
        log.info("[全量对账] 任务完成, report={}, traceId={}",
                JSON.toJSONString(report), traceId);

        // 告警
        if (report.getDbFixed() > 0 || report.getRedisFixed() > 0 || report.getErrors() > 0) {
            String alertMsg = String.format(
                    "点赞全量对账报告: 总检查=%d, MySQL修正=%d, Redis修正=%d, 错误=%d, 耗时=%dms",
                    report.getTotalChecked(), report.getDbFixed(),
                    report.getRedisFixed(), report.getErrors(), report.getCostMs());
            alertService.warn(alertMsg);
        }

        MDC.remove("traceId");
    }

    private long getRedisCount(long targetId, int targetType) {
        String key = "like:count:" + targetType;
        Object value = redisTemplate.opsForHash().get(key, String.valueOf(targetId));
        return value != null ? Long.parseLong(value.toString()) : 0L;
    }

    private void setRedisCount(long targetId, int targetType, long count) {
        String key = "like:count:" + targetType;
        redisTemplate.opsForHash().put(key, String.valueOf(targetId), String.valueOf(count));
    }
}
```
