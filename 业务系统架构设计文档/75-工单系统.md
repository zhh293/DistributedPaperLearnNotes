# 工单系统架构设计

## 一、系统概述

工单系统是企业客服平台的核心承载，负责将客户问题工单精确高效地分配给对应客服处理。系统设计参考了百万级工单实时分配系统的实践经验，核心挑战在于如何在每周330万单、170万次分配的规模下，实现99%工单1~5秒内完成分配、可用性99.99%的目标。

### 1.1 核心挑战

工单分配系统面临以下核心技术挑战。第一，扩展性挑战：各业务线的分队规则、排序规则差异大，系统需要支持配置驱动的灵活扩展，而非为每个业务线开发独立代码。第二，效率挑战：工单分配延迟需要控制在1~5秒内，高风险工单需要10~30秒内分完，传统手工分配无法满足。第三，稳定性挑战：系统必须7x24小时可用，不能因单点故障导致分配服务不可用。第四，公平性挑战：工单分配需要保证公平公正，避免某些客服负载过重而另一些空闲。

### 1.2 分配算法选型

订单分配问题在业内有两类方法。第一类方法将订单分配转换为图论中的二分图匹配问题，使用匈牙利算法或KM算法求解。由于标准二分图匹配中一个人只能被分配一项任务，需要先对工单进行打包，将可由一个人完成的多个工单组成一个任务。这种方案的优点是实现简单、计算速度快，缺点是会损失一部分满意解。第二类方法直接采用个性化算法进行订单分配方案优化，优点是不损失满意解的可能性，但实现难度大。

系统借鉴配送团队的分配策略，参考方案一的思路，将工单和客服抽象为两种需要匹配的资源，利用分包思路将分配任务分组并行处理，结合业务所需的平均、比例、先后、统一等策略，实现自己的分配逻辑。

### 1.3 系统目标

扩展性方面，灵活可配，实时生效，针对任意业务线的分队和排序需求可通过配置即时完成，无需开发。效率方面，有资源的情况下99%的工单在1~5秒内完成分配，自动化分配无需人工介入。稳定性方面，7x24小时可用，可用性99.99%，实时监控，分配链路可跟踪，出现问题时实时告警。

## 二、整体架构

系统分为6个模块，按照配置层、接入层、缓冲区、分配区、监控区、工具层进行分层设计。

## 三、工单状态机

### 3.1 状态流转设计

工单从创建到完成经历多个状态，使用状态机模式管理状态流转。每个状态转换都有明确的触发条件和后置操作。

```java
/**
 * 工单状态枚举
 */
public enum TicketStatus {
    CREATED,        // 已创建
    QUEUING,        // 排队中（已进入缓冲区）
    ALLOCATING,     // 分配中（分配区正在处理）
    ASSIGNED,       // 已分配（已分配给客服）
    PROCESSING,     // 处理中（客服正在处理）
    COMPLETED,      // 已完成
    CLOSED,         // 已关闭
    REJECTED,       // 已驳回
    TIMEOUT         // 超时未处理
}

/**
 * 工单状态机
 * 管理工单状态流转，校验转换合法性
 * 
 * 设计模式：状态机模式
 * 每个状态有允许的下一状态集合，非法转换直接拒绝
 */
public class TicketStateMachine {
    
    private static final Map<TicketStatus, Set<TicketStatus>> TRANSITIONS = new HashMap<>();
    
    static {
        TRANSITIONS.put(TicketStatus.CREATED, Set.of(TicketStatus.QUEUING));
        TRANSITIONS.put(TicketStatus.QUEUING, Set.of(TicketStatus.ALLOCATING, TicketStatus.TIMEOUT));
        TRANSITIONS.put(TicketStatus.ALLOCATING, Set.of(TicketStatus.ASSIGNED, TicketStatus.QUEUING));
        TRANSITIONS.put(TicketStatus.ASSIGNED, Set.of(TicketStatus.PROCESSING, TicketStatus.QUEUING));
        TRANSITIONS.put(TicketStatus.PROCESSING, Set.of(TicketStatus.COMPLETED, TicketStatus.REJECTED));
        TRANSITIONS.put(TicketStatus.COMPLETED, Set.of(TicketStatus.CLOSED));
        TRANSITIONS.put(TicketStatus.REJECTED, Set.of(TicketStatus.QUEUING, TicketStatus.CLOSED));
    }
    
    public static boolean canTransition(TicketStatus from, TicketStatus to) {
        return TRANSITIONS.getOrDefault(from, Set.of()).contains(to);
    }
    
    public static void transition(Ticket ticket, TicketStatus target) {
        TicketStatus current = ticket.getStatus();
        if (!canTransition(current, target)) {
            throw new TicketException(
                "Invalid status transition: " + current + " → " + target);
        }
        ticket.setStatus(target);
        ticket.setUpdateTime(System.currentTimeMillis());
    }
}
```

## 四、分队策略与排序策略

### 4.1 特性抽象模型

分单系统的核心扩展性在于特性抽象。系统将工单和客服的所有字段抽象为"特性"（Feature），特性值用于分队策略和排序策略的配置计算。这种设计使得新增字段不需要修改代码，只需配置新的特性即可。

系统支持多种特性获取方式：DTC、Pigeon、Thrift、HTTP四种远程调用方式配置特性，在工单进入分单系统时回调配置的特性获取特性值。有些特性可以从数据对象中直接获取（静态特性），有些需要调用RPC接口获取（动态特性）。

```java
/**
 * 特性定义
 * 工单和客服的所有字段都抽象为特性
 */

    private String featureKey;        // 特性键
    private String featureName;       // 特性名称
    private FeatureType type;         // 特性类型
    private FeatureSourceType source; // 特性来源
    private String sourceConfig;      // 来源配置（RPC接口地址等）
    
    public enum FeatureType {
        STRING, NUMBER, BOOLEAN, ENUM
    }
    
    public enum FeatureSourceType {
        LOCAL,      // 本地字段（从数据对象直接获取）
        RPC,        // 远程调用获取
        COMPUTED    // 计算得出
    }
}

/**
 * 特性注册中心
 * 管理所有已注册的特性，支持运行时动态注册
 * 
 * 设计模式：注册表模式
 */
@Service
public class FeatureRegistry {
    
    private final Map<String, Feature> features = new ConcurrentHashMap<>();
    
    /**
     * 注册特性
     */
    public void register(Feature feature) {
        features.put(feature.getFeatureKey(), feature);
    }
    
    /**
     * 获取特性值
     * 
     * 算法说明：
     * 1. 查询特性定义
     * 2. 根据特性来源获取值：
     *    - LOCAL：从数据对象反射获取
     *    - RPC：调用远程接口获取
     *    - COMPUTED：执行计算逻辑
     * 3. 返回特性值
     */
    public String getFeatureValue(String featureKey, Object dataSource) {
        Feature feature = features.get(featureKey);
        if (feature == null) {
            return null;
        }
        
        switch (feature.getSource()) {
            case LOCAL:
                return getLocalFeature(dataSource, featureKey);
            case RPC:
                return getRpcFeature(feature, dataSource);
            case COMPUTED:
                return getComputedFeature(feature, dataSource);
            default:
                return null;

    private String getLocalFeature(Object dataSource, String fieldName) {
        try {
            Field field = dataSource.getClass().getDeclaredField(fieldName);
            field.setAccessible(true);
            Object value = field.get(dataSource);
            return value != null ? value.toString() : null;
        } catch (Exception e) {
            return null;
        }
    }
```

### 4.2 分队策略

工单进入分单系统后，需要将工单分配到不同的队列中。分队的主要目的是提高系统并行处理能力，合理的分队可以方便系统并行处理不同队列，提高吞吐量并降低平均分配时长。

```java
/**
 * 分队策略
 * 根据工单特性将工单分配到不同队列
 * 
 * 算法说明：
 * 1. 读取分队配置（按哪些特性分队）
 * 2. 获取工单的特性值
 * 3. 根据特性值组合生成队列标识
 * 4. 将工单加入对应队列
 */
@Service
public class QueueDivisionStrategy {
    
    @Resource
    private FeatureRegistry featureRegistry;
    
    @Resource
    private QueueService queueService;
    
    /**
     * 执行分队
     * 
     * @param ticket 待分队工单
     * @param config 分队配置
     */
    public void divideQueue(Ticket ticket, DivisionConfig config) {
        // 1. 获取分队特性值
        StringBuilder queueKeyBuilder = new StringBuilder();
        for (String featureKey : config.getDivisionFeatures()) {
            String value = featureRegistry.getFeatureValue(featureKey, ticket);
            queueKeyBuilder.append(value != null ? value : "default").append(":");
        }
        
        String queueKey = queueKeyBuilder.toString();
        if (queueKey.isEmpty()) {
            queueKey = "default";
        }
        
        // 2. 获取或创建队列
        TicketQueue queue = queueService.getOrCreateQueue(queueKey, ticket.getTenantId());
        
        // 3. 工单入队
        queueService.enqueue(queue.getQueueId(), ticket);
        
        // 4. 更新工单状态
        TicketStateMachine.transition(ticket, TicketStatus.QUEUING);
    }
}

/**
 * 分队配置
 */
@Data
public class DivisionConfig {
    private Long tenantId;
    private List<String> divisionFeatures;  // 分队特性列表
    private boolean enabled;
    
    // 示例：按业务线分队，divisionFeatures = ["bizLine"]
    // 示例：按业务线+紧急程度分队，divisionFeatures = ["bizLine", "urgent"]
}
```

### 4.3 排序策略

工单在队列内按照得分进行排序，得分高的优先分配。排序模板由多个特性组成，每个特性有权重，动态特性（如超时时长）会随时间变化，需要通过延时队列更新。

```java
/**
 * 排序策略
 * 使用排序模板计算工单或客服的队内得分，按得分排序决定优先级
 * 
 * 算法说明：
 * 1. 读取排序模板配置
 * 2. 对每个特性计算得分：feature_score = feature_value * weight
 * 3. 总分 = 所有特性得分之和
 * 4. 按总分排序
 * 
 * 支持两种特性类型：
 * - 静态特性：进入系统后值不变，如业务线、工单类型
 * - 动态特性：值随时间变化，如超时时长，使用延时队列更新
 */
@Service
public class SortStrategy {
    
    @Resource
    private FeatureRegistry featureRegistry;
    
    /**
     * 计算工单排序得分
     */
    public double calculateScore(Ticket ticket, SortTemplate template) {
        double totalScore = 0;
        
        for (SortItem item : template.getSortItems()) {
            String featureValue = featureRegistry.getFeatureValue(
                item.getFeatureKey(), ticket);
            
            double normalizedValue = normalize(featureValue, item);
            double featureScore = normalizedValue * item.getWeight();
            totalScore += featureScore;
        }
        
        return totalScore;
    }
    
    /**
     * 特性值归一化
     * 将不同类型的特性值转换为0~1之间的标准分
     */
    private double normalize(String value, SortItem item) {
        if (value == null) {
            return 0;
        }
        
        try {
            switch (item.getNormalizeType()) {
                case LINEAR:
                    // 线性归一化：(value - min) / (max - min)
                    double v = Double.parseDouble(value);
                    return (v - item.getMinValue()) / 
                        (item.getMaxValue() - item.getMinValue());
                case LOG:
                    // 对数归一化：log(value + 1) / log(max + 1)
                    double logV = Double.parseDouble(value);
                    return Math.log(logV + 1) / Math.log(item.getMaxValue() + 1);
                case RANK:
                    // 等级归一化：直接返回等级分
                    return item.getRankMap().getOrDefault(value, 0.0);
                default:
                    return 0;
            }
        } catch (NumberFormatException e) {
            return 0;
        }
    }
}

/**
 * 排序模板
 */
@Data
public class SortTemplate {
    private String templateId;
    private String templateName;
    private List<SortItem> sortItems;
}

/**
 * 排序项
 */
@Data
public class SortItem {
    private String featureKey;
    private double weight;           // 权重
    private NormalizeType normalizeType;  // 归一化方式
    private double minValue;         // 最小值（线性归一化用）
    private double maxValue;         // 最大值
    private Map<String, Double> rankMap;  // 等级映射（等级归一化用）
    private boolean dynamic;         // 是否动态特性
    
    public enum NormalizeType {
        LINEAR,   // 线性归一化
        LOG,      // 对数归一化
        RANK      // 等级归一化
    }
}
```

### 4.4 动态特性更新

动态特性（如超时时长）的值会随时间变化，系统使用延时队列定期更新工单得分。

```java
/**
 * 动态特性更新服务
 * 使用延时队列定期更新工单的动态特性值和排序得分
 * 
 * 算法说明：
 * 1. 工单入队时创建延时任务
 * 2. 延时任务到期后重新计算动态特性值
 * 3. 更新工单在队列中的位置
 * 4. 创建下一个延时任务
 */
@Service
public class DynamicFeatureUpdater {
    
    @Resource
    private DelayQueue<ScoreUpdateTask> delayQueue;
    
    @Resource
    private SortStrategy sortStrategy;
    
    @Resource
    private QueueService queueService;
    
    /**
     * 创建得分更新延时任务
     */
    public void scheduleScoreUpdate(Ticket ticket, SortTemplate template, 
            long delayMs) {
        ScoreUpdateTask task = new ScoreUpdateTask();
        task.setTicketId(ticket.getTicketId());
        task.setTemplate(template);
        task.setExpireTime(System.currentTimeMillis() + delayMs);
        
        delayQueue.offer(task);
    }
    
    /**
     * 延时任务消费者
     * 定期从延时队列获取到期任务，更新工单得分
     */
    @Scheduled(fixedDelay = 1000)
    public void consumeUpdateTasks() {
        while (!delayQueue.isEmpty()) {
            ScoreUpdateTask task = delayQueue.poll();
            if (task == null || task.getExpireTime() > System.currentTimeMillis()) {
                if (task != null) {
                    delayQueue.offer(task);
                }
                break;
            }
            
            // 重新计算得分
            Ticket ticket = ticketService.findById(task.getTicketId());
            if (ticket == null || ticket.getStatus() != TicketStatus.QUEUING) {
                continue;  // 工单已分配或已关闭，跳过
            }
            
            double newScore = sortStrategy.calculateScore(ticket, task.getTemplate());
            ticket.setSortScore(newScore);
            
            // 更新队列中的位置
            queueService.updateTicketScore(ticket);
            
            // 创建下一次更新任务
            scheduleScoreUpdate(ticket, task.getTemplate(), 5000);  // 5秒后再次更新
        }
    }
}
```

## 五、分配算法核心

### 5.1 分包策略

分包是提高整体性能的关键策略。系统根据配置关系，将有关联关系的工单队列与客服组合成一个包（Package），包内的分配串行执行，各包之间并行执行。原则上没有资源竞争的分配相互独立，可以并发执行。

```java
/**
 * 分包策略
 * 将有关联关系的工单队列与客服组合成包，包间并行，包内串行
 * 
 * 算法说明：
 * 1. 读取队列与客服组的配置关联关系
 * 2. 将有关联的队列和客服组组成一个包
 * 3. 每个包内：队列→队内top1工单→客服组→组内top1客服→匹配
 * 4. 各包并行执行
 * 
 * 设计模式：生产者-消费者模式
 * 每个包是一个独立的消费单元，线程池并行处理
 */
@Service
public class PackageDivisionStrategy {
    
    @Resource
    private AllocationConfigService configService;
    
    @Resource
    private QueueService queueService;
    
    @Resource
    private AgentGroupService agentGroupService;
    
    /**
     * 构建分配包
     * 
     * @param tenantId 租户ID
     * @return 分配包列表
     */
    public List<AllocationPackage> buildPackages(Long tenantId) {
        // 1. 读取队列与客服组的关联配置
        List<QueueGroupMapping> mappings = configService.getQueueGroupMappings(tenantId);
        
        // 2. 按关联关系分包
        Map<String, AllocationPackage> packageMap = new HashMap<>();
        
        for (QueueGroupMapping mapping : mappings) {
            String packageKey = mapping.getPackageKey();
            
            AllocationPackage pkg = packageMap.computeIfAbsent(packageKey, k -> {
                AllocationPackage p = new AllocationPackage();
                p.setPackageKey(k);
                p.setTenantId(tenantId);
                p.setQueues(new ArrayList<>());
                p.setAgentGroups(new ArrayList<>());
                return p;
            });
            
            // 添加队列
            TicketQueue queue = queueService.getQueue(mapping.getQueueKey());
            if (queue != null && queue.size() > 0) {
                pkg.getQueues().add(queue);
            }
            
            // 添加客服组
            AgentGroup group = agentGroupService.getGroup(mapping.getGroupId());
            if (group != null && group.getOnlineAgents().size() > 0) {
                pkg.getAgentGroups().add(group);
            }
        }
        
        return new ArrayList<>(packageMap.values());
    }
}

/**
 * 分配包
 * 包含有关联关系的工单队列和客服组
 */
@Data
public class AllocationPackage {
    private String packageKey;
    private Long tenantId;
    private List<TicketQueue> queues;
    private List<AgentGroup> agentGroups;
}
```

### 5.2 动态压缩

分包策略中根据配置的所有节点做匹配，但实际运行时很多队列和组里没有数据（空节点），属于无效计算。动态压缩将包内无效节点摘除后再进行匹配计算，提高效率。

```java
/**
 * 动态压缩策略
 * 摘除空节点和满库存客服组，减少无效计算
 * 
 * 算法说明：
 * 1. 摘除空节点（无工单的队列、无在线客服的组）
 * 2. 摘除孤岛节点（摘除空节点后产生的无关联节点）
 * 3. 摘除满库存客服组：
 *    - 如果包内全是普通单，摘除普通库存全满的客服组
 *    - 如果包内全是紧急单，摘除紧急库存全满的客服组
 * 4. 得到最少节点的包
 */
@Service
public class DynamicCompressionStrategy {
    
    /**
     * 执行动态压缩
     */
    public AllocationPackage compress(AllocationPackage pkg) {
        AllocationPackage compressed = new AllocationPackage();
        compressed.setPackageKey(pkg.getPackageKey());
        compressed.setTenantId(pkg.getTenantId());
        compressed.setQueues(new ArrayList<>(pkg.getQueues()));
        compressed.setAgentGroups(new ArrayList<>(pkg.getAgentGroups()));
        
        // 1. 摘除空节点
        compressed.getQueues().removeIf(q -> q == null || q.size() == 0);
        compressed.getAgentGroups().removeIf(g -> 
            g == null || g.getOnlineAgents().isEmpty());
        
        // 2. 摘除孤岛节点（摘除空节点后可能产生无关联的节点）
        removeIsolatedNodes(compressed);
        
        // 3. 摘除满库存客服组
        if (!compressed.getQueues().isEmpty()) {
            boolean allUrgent = compressed.getQueues().stream()
                .allMatch(q -> q.peek() != null && q.peek().isUrgent());
            boolean allNormal = compressed.getQueues().stream()
                .allMatch(q -> q.peek() != null && !q.peek().isUrgent());
            
            if (allUrgent) {
                compressed.getAgentGroups().removeIf(g -> 
                    g.getUrgentCapacity() <= 0);
            } else if (allNormal) {
                compressed.getAgentGroups().removeIf(g -> 
                    g.getNormalCapacity() <= 0);
            }
        }
        
        return compressed;
    }
    
    /**
     * 摘除孤岛节点
     * 摘除空节点后，某些客服组可能不再与任何队列关联
     */
    private void removeIsolatedNodes(AllocationPackage pkg) {
        Set<String> linkedGroups = new HashSet<>();
        for (TicketQueue queue : pkg.getQueues()) {
            linkedGroups.addAll(queue.getLinkedGroupIds());
        }
        pkg.getAgentGroups().removeIf(g -> !linkedGroups.contains(g.getGroupId()));
    }
}
```

### 5.3 匹配算法

匹配算法参考匈牙利算法的思路，在包内执行工单与客服的一对一匹配。核心步骤：队列取队内top1工单，客服组取组内top1客服，执行匹配。

```java
/**
 * 匹配算法
 * 在包内执行工单与客服的一对一匹配
 * 
 * 算法说明（参考匈牙利算法思路）：
 * 1. 遍历包内所有队列
 * 2. 每个队列取出得分最高的工单（top1）
 * 3. 找到与该队列关联的客服组
 * 4. 在客服组中选出得分最高的客服（top1）
 * 5. 执行匹配：将工单分配给该客服
 * 6. 更新队列和客服组状态
 * 
 * 策略支持：
 * - 平均策略：优先分配给当前处理量最少的客服
 * - 比例策略：按预设比例分配
 * - 先后策略：按工单时间先后分配
 * - 统一策略：综合多种策略
 */
@Service
public class MatchingAlgorithm {
    
    @Resource
    private SortStrategy sortStrategy;
    
    @Resource
    private AllocationConfigService configService;
    
    /**
     * 执行包内匹配
     */
    public List<AllocationResult> match(AllocationPackage pkg) {
        List<AllocationResult> results = new ArrayList<>();
        
        // 获取分配策略配置
        AllocationStrategyConfig strategyConfig = configService.getStrategyConfig(pkg.getTenantId());
        
        for (TicketQueue queue : pkg.getQueues()) {
            // 1. 取出队内top1工单
            Ticket ticket = queue.poll();
            if (ticket == null) {
                continue;
            }
            
            // 2. 找到关联的客服组
            List<AgentGroup> linkedGroups = pkg.getAgentGroups().stream()
                .filter(g -> queue.getLinkedGroupIds().contains(g.getGroupId()))
                .collect(Collectors.toList());
            
            if (linkedGroups.isEmpty()) {
                // 无可用客服组，工单放回队列
                queue.offer(ticket);
                continue;
            }
            
            // 3. 在客服组中选出最优客服
            Agent selectedAgent = selectAgent(ticket, linkedGroups, strategyConfig);
            if (selectedAgent == null) {
                // 无可用客服，工单放回队列
                queue.offer(ticket);
                continue;
            }
            
            // 4. 执行分配
            AllocationResult result = new AllocationResult();
            result.setTicketId(ticket.getTicketId());
            result.setAgentId(selectedAgent.getAgentId());
            result.setAllocateTime(System.currentTimeMillis());
            results.add(result);
            
            // 5. 更新客服库存
            if (ticket.isUrgent()) {
                selectedAgent.decrementUrgentCapacity();
            } else {
                selectedAgent.decrementNormalCapacity();
            }
            
            // 6. 更新工单状态
            ticket.setAssignedAgentId(selectedAgent.getAgentId());
            ticket.setAssignedTime(System.currentTimeMillis());
            TicketStateMachine.transition(ticket, TicketStatus.ASSIGNED);
        }
        
        return results;
    }
    
    /**
     * 选择最优客服
     * 根据策略配置选择最合适的客服
     */
    private Agent selectAgent(Ticket ticket, List<AgentGroup> groups, 
            AllocationStrategyConfig config) {
        List<Agent> candidates = new ArrayList<>();
        
        for (AgentGroup group : groups) {
            for (Agent agent : group.getOnlineAgents()) {
                // 检查库存
                if (ticket.isUrgent() && agent.getUrgentCapacity() <= 0) {
                    continue;
                }
                if (!ticket.isUrgent() && agent.getNormalCapacity() <= 0) {
                    continue;
                }
                
                // 计算客服得分
                double score = sortStrategy.calculateScore(agent, 
                    config.getAgentSortTemplate());
                agent.setSortScore(score);
                candidates.add(agent);
            }
        }
        
        if (candidates.isEmpty()) {
            return null;
        }
        
        // 按得分排序，取top1
        candidates.sort((a, b) -> Double.compare(b.getSortScore(), a.getSortScore()));
        return candidates.get(0);
    }
}
```

```java
/**
 * 缓冲区降级服务
 * 当Redis不可用时，降级查询MySQL
 * 
 * 算法说明：
 * 1. 正常情况下从Redis读取分配数据
 * 2. Redis异常时降级到MySQL查询
 * 3. Redis恢复后使用MySQL数据还原Redis缓存
 */
@Service
public class BufferFallbackService {
    
    @Resource
    private RedisTemplate<String, String> redisTemplate;
    
    @Resource
    private TicketRepository ticketRepository;
    
    /**
     * 获取待分配工单（带降级）
     */
    public List<Ticket> getPendingTickets(Long tenantId) {
        try {
            // 1. 优先从Redis获取
            String key = "pending:tickets:" + tenantId;
            Set<String> ticketsJson = redisTemplate.opsForZSet()
                .rangeByScore(key, 0, System.currentTimeMillis());
            
            if (ticketsJson != null && !ticketsJson.isEmpty()) {
                return ticketsJson.stream()
                    .map(json -> JSON.parseObject(json, Ticket.class))
                    .collect(Collectors.toList());
            }
        } catch (Exception e) {
            log.warn("Redis unavailable, falling back to MySQL", e);
        }
        
        // 2. 降级到MySQL查询
        return ticketRepository.findPendingByTenantId(tenantId);
    }
    
    /**
     * Redis数据恢复
     * 使用MySQL数据还原Redis缓存
     */
    public void restoreRedisFromMySQL(Long tenantId) {
        List<Ticket> tickets = ticketRepository.findPendingByTenantId(tenantId);
        
        String key = "pending:tickets:" + tenantId;
        for (Ticket ticket : tickets) {
            double score = ticket.getSortScore();
            redisTemplate.opsForZSet().add(key, JSON.toJSONString(ticket), score);
        }
        
        log.info("Redis restored from MySQL, tenantId={}, count={}", 
            tenantId, tickets.size());
    }
}
```

## 七、分配任务调度

### 7.1 Job轮询调度

分配任务的触发采用Job轮询方式。每个租户一个独立调度任务，每次任务间隔1秒。任务开始后按包维度进入线程池并发执行，同一包使用分布式锁串行执行。

```java
/**
 * 分配任务调度器
 * 
 * 算法说明：
 * 1. 每个租户一个独立的定时任务，间隔1秒
 * 2. 任务开始后，按包维度进入线程池并发执行
 * 3. 每个包任务执行完成后，如有剩余时间，间隔n毫秒后继续循环执行
 * 4. 同一个包使用分布式锁串行执行
 * 5. 锁冲突的包跳过本次任务，不冲突的包继续执行
 */
@Service
public class AllocationScheduler {
    
    @Resource
    private PackageDivisionStrategy packageStrategy;
    
    @Resource
    private DynamicCompressionStrategy compressionStrategy;
    
    @Resource
    private MatchingAlgorithm matchingAlgorithm;
    
    @Resource
    private RedisTemplate<String, String> redisTemplate;
    
    @Resource
    private ThreadPoolTaskExecutor allocationExecutor;
    
    /**
     * 租户分配任务
     * 每秒执行一次
     */
    @Scheduled(cron = "*/1 * * * * ?")
    public void executeAllocation() {
        Long tenantId = TenantContext.getTenantId();
        
        // 1. 构建分配包
        List<AllocationPackage> packages = packageStrategy.buildPackages(tenantId);
        
        // 2. 并行执行各包分配
        List<CompletableFuture<List<AllocationResult>>> futures = packages.stream()
            .map(pkg -> CompletableFuture.supplyAsync(() -> executePackage(pkg), allocationExecutor))
            .collect(Collectors.toList());
        
        // 3. 等待所有包完成
        List<AllocationResult> allResults = futures.stream()
            .map(CompletableFuture::join)
            .flatMap(List::stream)
            .collect(Collectors.toList());
        
        // 4. 发送分配结果通知
        if (!allResults.isEmpty()) {
            notifyAllocationResults(tenantId, allResults);
        }
    }
    
    /**
     * 执行单个包的分配
     * 使用分布式锁保证同一包串行执行
     */
    private List<AllocationResult> executePackage(AllocationPackage pkg) {
        String lockKey = "alloc:lock:" + pkg.getPackageKey();
        
        // 尝试获取分布式锁
        Boolean locked = redisTemplate.opsForValue()
            .setIfAbsent(lockKey, "1", 2, TimeUnit.SECONDS);
        
        if (locked == null || !locked) {
            // 锁冲突，跳过本次任务
            log.debug("Package {} skipped due to lock conflict", pkg.getPackageKey());
            return Collections.emptyList();
        }
        
        try {
            // 1. 动态压缩
            AllocationPackage compressed = compressionStrategy.compress(pkg);
            
            if (compressed.getQueues().isEmpty() || compressed.getAgentGroups().isEmpty()) {
                return Collections.emptyList();
            }
            
            // 2. 执行匹配
            return matchingAlgorithm.match(compressed);
        } finally {
            // 释放锁
            redisTemplate.delete(lockKey);
        }
    }
    
    /**
     * 通知分配结果
     * 通过租户独立的MQ Topic发送
     */
    private void notifyAllocationResults(Long tenantId, List<AllocationResult> results) {
        String topic = "allocation-result-" + tenantId;  // 每个租户独立Topic
        for (AllocationResult result : results) {
            mqTemplate.send(topic, result);
        }
    }
}
```

### 8.1 分配Trace设计

参考分布式Trace系统的设计思路，系统将一次分配过程设计为一次Trace，在各个模块采集关键信息并上报，提供可视化查询能力。

```java
/**
 * 分配链路追踪服务
 * 将一次分配过程记录为完整的Trace，支持通过caseId查询
 * 
 * Trace结构：

        trace.setSpans(spans);
        trace.setTotalDuration(spans.stream()

        trace.setSuccess(spans.stream().allMatch(TraceSpan::isSuccess));
        return trace;
    }
```

```java
/**
 * 积压告警服务
 * 监控工单队列积压情况，实时告警

@Service
public class BacklogAlertService {
    
    @Resource
    private QueueService queueService;
    
    @Resource
    private AlertService alertService;
    
    /** 积压阈值 */
    @Value("${alert.backlog.threshold:100}")
    private int backlogThreshold;

    @Value("${alert.backlog.duration.threshold:300}")
    private int backlogDurationThreshold;
    
    /**
     * 每分钟检查积压情况
     */
    @Scheduled(cron = "0 * * * * ?")
    public void checkBacklog() {
        List<TicketQueue> queues = queueService.getAllActiveQueues();
        
        for (TicketQueue queue : queues) {
            int size = queue.size();
            if (size > backlogThreshold) {
                // 检查积压持续时间
                Long firstTicketTime = queue.peekFirstTicketTime();
                if (firstTicketTime != null) {
                    long backlogDuration = (System.currentTimeMillis() - firstTicketTime) / 1000;
                    if (backlogDuration > backlogDurationThreshold) {
                        // 发送积压告警
                        alertService.sendAlert("TICKET_BACKLOG", 
                            String.format("队列%s积压%d单，持续%d秒", 
                                queue.getQueueKey(), size, backlogDuration));
                    }
                }
            }
        }
    }
}
```

## 九、系统总结

工单分配系统的核心设计包括以下方面。整体架构方面，系统分为配置层、接入层、缓冲区、分配区、监控区、工具层六个模块，各模块职责清晰，解耦合设计使得分配区故障不影响缓冲区数据。扩展性方面，通过特性抽象模型将工单和客服的所有字段统一抽象为特性，支持DTC、Pigeon、Thrift、HTTP四种远程调用方式获取特性值，分队策略和排序策略通过配置驱动，无需代码修改即可支持新业务线。分配算法方面，参考匈牙利算法思路，采用分包策略将有关联关系的工单队列与客服组打包，包间并行、包内串行，动态压缩摘除空节点和满库存客服组减少无效计算，匹配算法在包内执行top1工单与top1客服的一对一匹配。高可用方面，接入层无状态横向扩展，缓冲区Redis+MySQL双存储支持降级，分配区与缓冲区隔离，租户SET化硬隔离，数据软隔离，任务调度隔离，MQ隔离四层隔离保障稳定性。监控方面，参考分布式Trace系统设计，将一次分配过程记录为完整Trace，支持通过caseId快速定位问题，积压告警和分配失败告警实时通知。系统经过持续迭代，已接入72条业务线，日均分配26万次，有效支撑了客服平台的工单分配需求。

### 10.1 案例一：用户提交工单全链路（提交 → 自动分配 → 处理 → 回复 → 关闭）

#### 10.1.1 链路概述

#### 10.1.2 工单提交接口

#### 10.1.3 提交服务：幂等控制 + 本地事务 + MQ通知

```java
/**
 * 工单提交服务
 * 核心职责：幂等控制、工单落库、触发自动分配
 *
 * 幂等设计说明：
 * 1. 第一层：Redis SETNX 抢占幂等键，TTL设置为24小时，拦截绝大多数重复请求
 * 2. 第二层：数据库唯一索引（tenant_id + idempotent_key），兜底并发场景下Redis失效的情况
 * 3. 若命中幂等，直接返回已存在工单，不重复创建，不重复发消息
 */
@Service
@Slf4j
public class TicketSubmitService {

    @Resource
    private TicketRepository ticketRepository;

    @Resource
    private RedisTemplate<String, String> redisTemplate;

    @Resource
    private FeatureRegistry featureRegistry;

    @Resource
    private TicketEventPublisher eventPublisher;

    private static final String IDEMPOTENT_KEY_PREFIX = "ticket:submit:idempotent:";
    private static final long IDEMPOTENT_TTL_SECONDS = 24 * 60 * 60;

    /**
     * 提交工单
     * 事务边界：仅覆盖"工单落库 + 本地事件表写入"，MQ发送在事务提交后异步执行，
     * 避免MQ Broker抖动阻塞数据库事务，也避免"事务成功但消息未发出"的不一致
     */
    @Transactional(rollbackFor = Exception.class)
    public String submit(TicketSubmitRequest request) {
        // 1. 参数二次校验（防止绕过Controller层校验的内部调用）
        validate(request);

        // 2. Redis层幂等拦截
        String redisKey = IDEMPOTENT_KEY_PREFIX + request.getTenantId() + ":" + request.getIdempotentKey();
        Boolean acquired = redisTemplate.opsForValue()
            .setIfAbsent(redisKey, "PENDING", IDEMPOTENT_TTL_SECONDS, TimeUnit.SECONDS);

        if (Boolean.FALSE.equals(acquired)) {
            String existTicketId = redisTemplate.opsForValue().get(redisKey);
            if (existTicketId != null && !"PENDING".equals(existTicketId)) {
                throw new DuplicateSubmitException(existTicketId);
            }
            // PENDING状态说明并发请求正在处理中，走数据库兜底查询
            Ticket exist = ticketRepository.findByIdempotentKey(
                request.getTenantId(), request.getIdempotentKey());
            if (exist != null) {
                throw new DuplicateSubmitException(exist.getTicketId());
            }
            // 极端并发下Redis为PENDING但DB还未写入，短暂等待后重试一次
            sleepQuietly(50);
            exist = ticketRepository.findByIdempotentKey(
                request.getTenantId(), request.getIdempotentKey());
            if (exist != null) {
                throw new DuplicateSubmitException(exist.getTicketId());
            }
            throw new TicketValidationException("请求处理中，请勿重复提交");
        }

        try {
            // 3. 数据库唯一索引兜底幂等（tenant_id + idempotent_key唯一索引）
            Ticket ticket = buildTicket(request);
            try {
                ticketRepository.insert(ticket);
            } catch (DuplicateKeyException e) {
                log.warn("[工单提交] 数据库唯一索引拦截重复提交, idempotentKey={}",
                    request.getIdempotentKey());
                Ticket exist = ticketRepository.findByIdempotentKey(
                    request.getTenantId(), request.getIdempotentKey());
                throw new DuplicateSubmitException(
                    exist != null ? exist.getTicketId() : null);
            }

            // 4. 写本地事件表（事务内），保证事务提交与消息发送最终一致
            TicketEvent event = TicketEvent.of(ticket.getTicketId(), TicketEventType.SUBMITTED,
                JSON.toJSONString(ticket));
            eventPublisher.saveEvent(event);

            // 5. 更新Redis幂等键为真实工单ID
            redisTemplate.opsForValue().set(redisKey, ticket.getTicketId(),
                IDEMPOTENT_TTL_SECONDS, TimeUnit.SECONDS);

            log.info("[工单提交] 落库成功, ticketId={}, bizLine={}, ticketType={}",
                ticket.getTicketId(), ticket.getBizLine(), ticket.getTicketType());

            return ticket.getTicketId();
        } catch (DuplicateSubmitException e) {
            throw e;
        } catch (Exception e) {
            // 事务将回滚，释放Redis占位，避免用户永久无法重新提交
            redisTemplate.delete(redisKey);
            log.error("[工单提交] 落库异常, idempotentKey={}", request.getIdempotentKey(), e);
            throw e;
        }
    }

    private void validate(TicketSubmitRequest request) {
        if (StringUtils.isBlank(request.getTitle()) || StringUtils.isBlank(request.getContent())) {
            throw new TicketValidationException("标题和描述不能为空");
        }
        if (request.getPriority() < 0 || request.getPriority() > 3) {
            throw new TicketValidationException("优先级取值范围为0~3");
        }
    }

    private Ticket buildTicket(TicketSubmitRequest request) {
        Ticket ticket = new Ticket();
        ticket.setTicketId(TicketIdGenerator.generate());
        ticket.setTenantId(request.getTenantId());
        ticket.setBizLine(request.getBizLine());
        ticket.setTicketType(request.getTicketType());
        ticket.setPriority(request.getPriority());
        ticket.setStatus(TicketStatus.CREATED);
        ticket.setUrgent(request.getPriority() >= 2);
        ticket.setCreateTime(System.currentTimeMillis());
        ticket.setUpdateTime(System.currentTimeMillis());

        Map<String, String> features = new HashMap<>();
        features.put("userId", String.valueOf(request.getUserId()));
        features.put("bizLine", request.getBizLine());
        features.put("ticketType", request.getTicketType());
        ticket.setFeatures(features);
        return ticket;
    }

    private void sleepQuietly(long millis) {
        try {
            Thread.sleep(millis);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
```

#### 10.1.4 事件表 + 本地消息表投递（保证事务与MQ最终一致）

```java
/**
 * 工单事件发布器
 * 采用本地消息表方案，避免"数据库事务成功但MQ发送失败"导致工单永久停留在CREATED状态
 *
 * 流程：
 * 1. 业务事务内写入事件表（状态为INIT）
 * 2. 事务提交后，监听 TransactionSynchronization 的 afterCommit 回调发送MQ
 * 3. 独立定时任务扫描超过1分钟仍为INIT状态的事件，重新投递（应对进程宕机场景）
 */
@Service
@Slf4j
public class TicketEventPublisher {

    @Resource
    private TicketEventRepository eventRepository;

    @Resource
    private MqProducer mqProducer;

    public void saveEvent(TicketEvent event) {
        eventRepository.insert(event);

        // 事务提交后再发送MQ，避免消息先于数据可见
        if (TransactionSynchronizationManager.isSynchronizationActive()) {
            TransactionSynchronizationManager.registerSynchronization(
                new TransactionSynchronizationAdapter() {
                    @Override
                    public void afterCommit() {
                        publishAsync(event);
                    }
                });
        } else {
            publishAsync(event);
        }
    }

    private void publishAsync(TicketEvent event) {
        try {
            mqProducer.send("ticket-event-topic", event.getTicketId(), JSON.toJSONString(event));
            eventRepository.updateStatus(event.getEventId(), TicketEventStatus.SENT);
            log.info("[事件投递] 发送成功, ticketId={}, eventType={}",
                event.getTicketId(), event.getEventType());
        } catch (Exception e) {
            // 发送失败不抛异常，交由定时补偿任务重试，避免影响主流程
            log.error("[事件投递] 发送失败，等待补偿重试, ticketId={}", event.getTicketId(), e);
        }
    }

    /**
     * 补偿任务：每分钟扫描一次未成功投递的事件
     */
    @Scheduled(fixedDelay = 60000)
    public void retryPendingEvents() {
        List<TicketEvent> pendingEvents = eventRepository.findPendingEvents(
            System.currentTimeMillis() - 60000, 200);

        for (TicketEvent event : pendingEvents) {
            try {
                mqProducer.send("ticket-event-topic", event.getTicketId(), JSON.toJSONString(event));
                eventRepository.updateStatus(event.getEventId(), TicketEventStatus.SENT);
                log.info("[事件补偿] 重试发送成功, ticketId={}", event.getTicketId());
            } catch (Exception e) {
                log.error("[事件补偿] 重试发送仍然失败, ticketId={}, retryCount={}",
                    event.getTicketId(), event.getRetryCount() + 1, e);
                eventRepository.incrementRetryCount(event.getEventId());
                if (event.getRetryCount() >= 10) {
                    // 超过最大重试次数，转人工介入并告警
                    eventRepository.updateStatus(event.getEventId(), TicketEventStatus.FAILED);
                    alertService.sendAlert("TICKET_EVENT_PUBLISH_FAILED",
                        "工单事件投递持续失败，ticketId=" + event.getTicketId());
                }
            }
        }
    }

    @Resource
    private AlertService alertService;
}
```

#### 10.1.5 消费自动分配、处理、回复、关闭全流程

```java
/**
 * 工单全生命周期消费者
 * 消费 ticket-event-topic，驱动工单从CREATED流转到CLOSED
 *
 * 消费幂等：使用消息ID + 本地消费记录表去重，防止MQ重复投递导致状态机重复流转
 */
@Component
@Slf4j
public class TicketLifecycleConsumer {

    @Resource
    private TicketRepository ticketRepository;

    @Resource
    private QueueDivisionStrategy queueDivisionStrategy;

    @Resource
    private ConsumeRecordRepository consumeRecordRepository;

    @MqListener(topic = "ticket-event-topic")
    public void onMessage(MqMessage message) {
        String messageId = message.getMessageId();

        // 消费幂等：INSERT唯一索引拦截重复消费
        try {
            consumeRecordRepository.insert(new ConsumeRecord(messageId, System.currentTimeMillis()));
        } catch (DuplicateKeyException e) {
            log.warn("[工单消费] 消息重复消费，直接忽略, messageId={}", messageId);
            return;
        }

        TicketEvent event = JSON.parseObject(message.getBody(), TicketEvent.class);
        try {
            handleEvent(event);
        } catch (Exception e) {
            log.error("[工单消费] 处理异常, ticketId={}, eventType={}",
                event.getTicketId(), event.getEventType(), e);
            // 抛出异常触发MQ重试机制，由MQ的重试策略和死信队列兜底
            consumeRecordRepository.delete(messageId);
            throw new MqConsumeException("工单事件处理失败", e);
        }
    }

    private void handleEvent(TicketEvent event) {
        switch (event.getEventType()) {
            case SUBMITTED:
                handleSubmitted(event);
                break;
            case ASSIGNED:
                handleAssigned(event);
                break;
            default:
                log.warn("[工单消费] 未知事件类型, eventType={}", event.getEventType());
        }
    }

    /**
     * 工单已提交 → 进入分队缓冲区，等待自动分配调度器处理
     */
    private void handleSubmitted(TicketEvent event) {
        Ticket ticket = ticketRepository.findById(event.getTicketId());
        if (ticket == null) {
            log.warn("[工单消费] 工单不存在，可能已被删除, ticketId={}", event.getTicketId());
            return;
        }
        if (ticket.getStatus() != TicketStatus.CREATED) {
            log.info("[工单消费] 工单状态已流转，跳过重复处理, ticketId={}, status={}",
                ticket.getTicketId(), ticket.getStatus());
            return;
        }

        DivisionConfig config = configService.getDivisionConfig(ticket.getTenantId());
        queueDivisionStrategy.divideQueue(ticket, config);
        ticketRepository.updateStatus(ticket.getTicketId(), TicketStatus.QUEUING);

        log.info("[自动分队] 工单入队成功, ticketId={}, bizLine={}", ticket.getTicketId(), ticket.getBizLine());
    }

    /**
     * 工单已分配 → 通知客服端，进入处理阶段
     */
    private void handleAssigned(TicketEvent event) {
        Ticket ticket = ticketRepository.findById(event.getTicketId());
        if (ticket == null || ticket.getStatus() != TicketStatus.ASSIGNED) {
            return;
        }
        TicketStateMachine.transition(ticket, TicketStatus.PROCESSING);
        ticketRepository.updateStatus(ticket.getTicketId(), TicketStatus.PROCESSING);
        notifyService.notifyAgent(ticket.getAssignedAgentId(), ticket.getTicketId());

        log.info("[进入处理] 工单转入处理中, ticketId={}, agentId={}",
            ticket.getTicketId(), ticket.getAssignedAgentId());
    }

    @Resource
    private AllocationConfigService configService;

    @Resource
    private AgentNotifyService notifyService;
}
```

#### 10.1.6 客服回复与工单关闭（含并发控制）

客服回复和关闭操作可能存在多端并发（客服APP与工作台同时操作），采用乐观锁 + 状态机双重校验防止并发覆盖。

```java
/**
 * 工单回复与关闭服务
 *
 * 并发控制：
 * 1. 更新时携带 version 字段做乐观锁校验（update ... where version = ?）
 * 2. 状态机二次校验，非法状态跳转直接拒绝，避免已关闭工单被重新回复
 */
@Service
@Slf4j
public class TicketReplyService {

    @Resource
    private TicketRepository ticketRepository;

    @Resource
    private TicketReplyRepository replyRepository;

    /**
     * 客服回复工单
     */
    @Transactional(rollbackFor = Exception.class)
    public void reply(String ticketId, String agentId, String replyContent) {
        Ticket ticket = ticketRepository.findById(ticketId);
        if (ticket == null) {
            throw new TicketException("工单不存在: " + ticketId);
        }
        if (!agentId.equals(ticket.getAssignedAgentId())) {
            log.warn("[工单回复] 客服无权限回复该工单, ticketId={}, agentId={}, assignedAgentId={}",
                ticketId, agentId, ticket.getAssignedAgentId());
            throw new TicketPermissionException("无权限回复该工单");
        }
        if (ticket.getStatus() != TicketStatus.PROCESSING) {
            throw new TicketException("工单当前状态不允许回复: " + ticket.getStatus());
        }

        TicketReply reply = new TicketReply();
        reply.setReplyId(TicketIdGenerator.generate());
        reply.setTicketId(ticketId);
        reply.setAgentId(agentId);
        reply.setContent(replyContent);
        reply.setCreateTime(System.currentTimeMillis());
        replyRepository.insert(reply);

        log.info("[工单回复] 回复成功, ticketId={}, agentId={}, replyId={}",
            ticketId, agentId, reply.getReplyId());
    }

    /**
     * 关闭工单
     * 使用乐观锁防止客服端与工作台并发关闭导致的重复扣减统计指标
     */
    @Transactional(rollbackFor = Exception.class)
    public void closeTicket(String ticketId, String operatorId, String closeReason) {
        Ticket ticket = ticketRepository.findById(ticketId);
        if (ticket == null) {
            throw new TicketException("工单不存在: " + ticketId);
        }
        if (ticket.getStatus() == TicketStatus.CLOSED) {
            log.info("[工单关闭] 工单已处于关闭状态，忽略本次操作, ticketId={}", ticketId);
            return;
        }
        if (!TicketStateMachine.canTransition(ticket.getStatus(), TicketStatus.COMPLETED)
                && ticket.getStatus() != TicketStatus.COMPLETED) {
            throw new TicketException("当前状态不允许关闭: " + ticket.getStatus());
        }

        // 先流转到COMPLETED（若尚未完成），再流转到CLOSED
        if (ticket.getStatus() != TicketStatus.COMPLETED) {
            TicketStateMachine.transition(ticket, TicketStatus.COMPLETED);
        }
        TicketStateMachine.transition(ticket, TicketStatus.CLOSED);

        int affected = ticketRepository.updateStatusWithVersion(
            ticketId, TicketStatus.CLOSED, ticket.getVersion());

        if (affected == 0) {
            // 乐观锁未命中，说明存在并发更新，重新读取最新状态判断是否需要重试
            Ticket latest = ticketRepository.findById(ticketId);
            if (latest != null && latest.getStatus() == TicketStatus.CLOSED) {
                log.warn("[工单关闭] 检测到并发关闭，以先到者为准, ticketId={}", ticketId);
                return;
            }
            log.error("[工单关闭] 乐观锁更新失败且状态不一致, ticketId={}", ticketId);
            throw new TicketConcurrentModifyException("工单已被并发修改，请重试");
        }

        log.info("[工单关闭] 关闭成功, ticketId={}, operatorId={}, reason={}",
            ticketId, operatorId, closeReason);

        // 异步回收满意度评价、归档统计指标，失败不影响主流程
        try {
            satisfactionService.sendSurvey(ticketId);
        } catch (Exception e) {
            log.warn("[工单关闭] 满意度问卷发送失败，不影响关闭结果, ticketId={}", ticketId, e);
        }
    }

    @Resource
    private SatisfactionService satisfactionService;
}
```

### 10.2 案例二：工单自动派单全链路（规则引擎匹配 → 技能组路由 → 负载均衡 → 超时转派）

#### 10.2.1 链路概述

#### 10.2.2 规则引擎：条件表达式匹配

```java
/**
 * 派单规则引擎
 * 支持配置化的条件表达式，按优先级从高到低匹配第一条命中的规则
 *
 * 规则示例：
 * bizLine == 'refund' && priority >= 2 → 路由至"退款紧急处理组"
 * ticketType == 'complaint' → 路由至"投诉处理组"
 */
@Service
@Slf4j
public class DispatchRuleEngine {

    @Resource
    private DispatchRuleRepository ruleRepository;

    private final ExpressionParser parser = new SpelExpressionParser();

    /**
     * 匹配派单规则，返回目标技能组ID
     */
    public String matchSkillGroup(Ticket ticket) {
        List<DispatchRule> rules = ruleRepository.findEnabledRulesByTenant(ticket.getTenantId());
        // 按优先级降序排列，优先级数值越大越先匹配
        rules.sort((a, b) -> Integer.compare(b.getPriority(), a.getPriority()));

        StandardEvaluationContext context = new StandardEvaluationContext();
        context.setVariable("bizLine", ticket.getBizLine());
        context.setVariable("ticketType", ticket.getTicketType());
        context.setVariable("priority", ticket.getPriority());
        context.setVariable("urgent", ticket.isUrgent());

        for (DispatchRule rule : rules) {
            try {
                Expression expression = parser.parseExpression(rule.getConditionExpr());
                Boolean matched = expression.getValue(context, Boolean.class);
                if (Boolean.TRUE.equals(matched)) {
                    log.info("[规则匹配] 命中规则, ticketId={}, ruleId={}, skillGroupId={}",
                        ticket.getTicketId(), rule.getRuleId(), rule.getTargetSkillGroupId());
                    return rule.getTargetSkillGroupId();
                }
            } catch (Exception e) {
                // 单条规则表达式异常不应影响其他规则匹配，记录日志后继续
                log.error("[规则匹配] 规则表达式解析异常，跳过该规则, ruleId={}, expr={}",
                    rule.getRuleId(), rule.getConditionExpr(), e);
            }
        }

        // 所有规则均未命中，返回默认技能组
        String defaultGroupId = ruleRepository.findDefaultSkillGroup(ticket.getTenantId());
        if (defaultGroupId == null) {
            log.error("[规则匹配] 未配置默认技能组，工单可能无法分配, ticketId={}", ticket.getTicketId());
            throw new DispatchException("未匹配到任何技能组: " + ticket.getTicketId());
        }
        log.warn("[规则匹配] 未命中任何规则，回退默认技能组, ticketId={}, skillGroupId={}",
            ticket.getTicketId(), defaultGroupId);
        return defaultGroupId;
    }
}
```

#### 10.2.3 技能组路由 + 负载均衡选人

```java
/**
 * 技能组路由与负载均衡服务
 * 在技能组内按"当前处理量最少优先"的策略选择客服，兼顾客服技能等级
 *
 * 算法说明：
 * 1. 过滤技能组内在线、且未达单量上限的客服
 * 2. 按 (当前处理量 / 单量上限) 的负载率升序排序，负载率越低优先级越高
 * 3. 负载率相同时按技能等级降序排列，优先分配给资深客服
 */
@Service
@Slf4j
public class SkillGroupRoutingService {

    @Resource
    private AgentGroupService agentGroupService;

    @Resource
    private RedisTemplate<String, String> redisTemplate;

    public Agent routeToAgent(Ticket ticket, String skillGroupId) {
        AgentGroup group = agentGroupService.getGroup(skillGroupId);
        if (group == null) {
            log.error("[技能组路由] 技能组不存在, skillGroupId={}, ticketId={}",
                skillGroupId, ticket.getTicketId());
            throw new DispatchException("技能组不存在: " + skillGroupId);
        }

        List<Agent> onlineAgents = group.getOnlineAgents().stream()
            .filter(agent -> agent.getCurrentLoad() < agent.getMaxCapacity())
            .collect(Collectors.toList());

        if (onlineAgents.isEmpty()) {
            log.warn("[技能组路由] 技能组内无可用客服, skillGroupId={}, ticketId={}",
                skillGroupId, ticket.getTicketId());
            return null;
        }

        onlineAgents.sort((a, b) -> {
            double loadRateA = (double) a.getCurrentLoad() / a.getMaxCapacity();
            double loadRateB = (double) b.getCurrentLoad() / b.getMaxCapacity();
            int loadCompare = Double.compare(loadRateA, loadRateB);
            if (loadCompare != 0) {
                return loadCompare;
            }
            return Integer.compare(b.getSkillLevel(), a.getSkillLevel());
        });

        Agent selected = onlineAgents.get(0);
        log.info("[负载均衡] 选中客服, ticketId={}, agentId={}, currentLoad={}, maxCapacity={}",
            ticket.getTicketId(), selected.getAgentId(), selected.getCurrentLoad(), selected.getMaxCapacity());
        return selected;
    }

    /**
     * 执行派单：分布式锁防止同一客服被并发分配超过负载上限
     */
    public boolean assignTicket(Ticket ticket, Agent agent) {
        String lockKey = "agent:load:lock:" + agent.getAgentId();
        Boolean locked = redisTemplate.opsForValue()
            .setIfAbsent(lockKey, "1", 3, TimeUnit.SECONDS);

        if (!Boolean.TRUE.equals(locked)) {
            log.warn("[派单执行] 客服负载锁获取失败，可能存在并发派单, agentId={}, ticketId={}",
                agent.getAgentId(), ticket.getTicketId());
            return false;
        }

        try {
            // 锁内二次校验负载，防止TOCTOU竞态
            Agent latest = agentGroupService.getAgent(agent.getAgentId());
            if (latest == null || latest.getCurrentLoad() >= latest.getMaxCapacity()) {
                log.warn("[派单执行] 客服负载已满，放弃本次派单, agentId={}, ticketId={}",
                    agent.getAgentId(), ticket.getTicketId());
                return false;
            }

            agentGroupService.incrementLoad(agent.getAgentId());
            ticket.setAssignedAgentId(agent.getAgentId());
            ticket.setAssignedTime(System.currentTimeMillis());
            TicketStateMachine.transition(ticket, TicketStatus.ASSIGNED);
            ticketRepository.updateAssignment(ticket);

            log.info("[派单执行] 派单成功, ticketId={}, agentId={}", ticket.getTicketId(), agent.getAgentId());
            return true;
        } catch (Exception e) {
            log.error("[派单执行] 派单执行异常, ticketId={}, agentId={}",
                ticket.getTicketId(), agent.getAgentId(), e);
            return false;
        } finally {
            redisTemplate.delete(lockKey);
        }
    }

    @Resource
    private TicketRepository ticketRepository;
}
```

#### 10.2.4 派单主流程编排（含幂等与失败重试）

```java
/**
 * 自动派单主流程编排服务
 * 幂等设计：以 ticketId 作为幂等维度，派单前校验工单状态必须为QUEUING/ALLOCATING，
 * 派单成功后立即流转状态，避免重复调度导致一单多派
 */
@Service
@Slf4j
public class AutoDispatchService {

    @Resource
    private DispatchRuleEngine ruleEngine;

    @Resource
    private SkillGroupRoutingService routingService;

    @Resource
    private TicketRepository ticketRepository;

    @Resource
    private DispatchRetryQueue retryQueue;

    private static final int MAX_RETRY_TIMES = 3;

    public void dispatch(String ticketId) {
        Ticket ticket = ticketRepository.findById(ticketId);
        if (ticket == null) {
            log.warn("[自动派单] 工单不存在，跳过派单, ticketId={}", ticketId);
            return;
        }
        // 幂等校验：仅QUEUING状态的工单允许进入派单流程
        if (ticket.getStatus() != TicketStatus.QUEUING) {
            log.info("[自动派单] 工单状态非QUEUING，可能已被派单，跳过, ticketId={}, status={}",
                ticketId, ticket.getStatus());
            return;
        }

        try {
            TicketStateMachine.transition(ticket, TicketStatus.ALLOCATING);
            ticketRepository.updateStatus(ticketId, TicketStatus.ALLOCATING);

            // 1. 规则引擎匹配技能组
            String skillGroupId = ruleEngine.matchSkillGroup(ticket);

            // 2. 技能组内负载均衡选人
            Agent agent = routingService.routeToAgent(ticket, skillGroupId);
            if (agent == null) {
                handleNoAvailableAgent(ticket);
                return;
            }

            // 3. 执行派单
            boolean success = routingService.assignTicket(ticket, agent);
            if (!success) {
                // 派单竞争失败，放回队列等待下一轮调度
                rollbackToQueuing(ticket, "客服负载竞争失败");
                return;
            }

            // 4. 记录派单日志，供SLA和转派链路追踪
            dispatchLogRepository.insert(DispatchLog.success(ticketId, skillGroupId, agent.getAgentId()));

        } catch (DispatchException e) {
            log.error("[自动派单] 派单业务异常, ticketId={}, reason={}", ticketId, e.getMessage());
            rollbackToQueuing(ticket, e.getMessage());
        } catch (Exception e) {
            log.error("[自动派单] 派单系统异常, ticketId={}", ticketId, e);
            handleDispatchFailure(ticket, e);
        }
    }

    private void handleNoAvailableAgent(Ticket ticket) {
        log.warn("[自动派单] 无可用客服，放回队列等待下一轮调度, ticketId={}", ticket.getTicketId());
        rollbackToQueuing(ticket, "无可用客服");
    }

    private void rollbackToQueuing(Ticket ticket, String reason) {
        TicketStateMachine.transition(ticket, TicketStatus.QUEUING);
        ticketRepository.updateStatus(ticket.getTicketId(), TicketStatus.QUEUING);
        dispatchLogRepository.insert(DispatchLog.fail(ticket.getTicketId(), reason));
    }

    /**
     * 派单系统异常时的重试兜底
     * 使用独立重试队列，避免异常工单反复占用主调度线程
     */
    private void handleDispatchFailure(Ticket ticket, Exception e) {
        int retryCount = retryQueue.getRetryCount(ticket.getTicketId());
        if (retryCount < MAX_RETRY_TIMES) {
            retryQueue.scheduleRetry(ticket.getTicketId(), retryCount + 1, (retryCount + 1) * 5000L);
            log.warn("[自动派单] 触发第{}次重试, ticketId={}", retryCount + 1, ticket.getTicketId());
            rollbackToQueuing(ticket, "系统异常触发重试: " + e.getMessage());
        } else {
            // 超过最大重试次数，转人工介入并告警
            TicketStateMachine.transition(ticket, TicketStatus.QUEUING);
            ticketRepository.updateStatus(ticket.getTicketId(), TicketStatus.QUEUING);
            ticketRepository.markNeedManualIntervention(ticket.getTicketId());
            alertService.sendAlert("DISPATCH_RETRY_EXHAUSTED",
                "工单自动派单重试耗尽，需人工介入, ticketId=" + ticket.getTicketId());
            log.error("[自动派单] 重试次数耗尽，标记人工介入, ticketId={}", ticket.getTicketId());
        }
    }

    @Resource
    private DispatchLogRepository dispatchLogRepository;

    @Resource
    private AlertService alertService;
}
```

#### 10.2.5 超时转派兜底

客服在规定时间内未响应工单（如5分钟未点击"开始处理"），系统需要自动转派给其他客服，避免工单积压在无响应客服名下。

```java
/**
 * 超时转派服务
 * 定时扫描已分配但客服长时间未响应的工单，自动转派
 *
 * 转派幂等：转派前使用分布式锁锁定工单，防止定时任务多实例并发扫描时重复转派同一工单
 */
@Service
@Slf4j
public class DispatchTimeoutService {

    @Resource
    private TicketRepository ticketRepository;

    @Resource
    private AutoDispatchService autoDispatchService;

    @Resource
    private AgentGroupService agentGroupService;

    @Resource
    private RedisTemplate<String, String> redisTemplate;

    @Value("${dispatch.timeout.response.seconds:300}")
    private int responseTimeoutSeconds;

    @Value("${dispatch.transfer.max.times:3}")
    private int maxTransferTimes;

    /**
     * 每30秒扫描一次超时未响应的工单
     */
    @Scheduled(fixedDelay = 30000)
    public void scanTimeoutTickets() {
        long deadline = System.currentTimeMillis() - responseTimeoutSeconds * 1000L;
        List<Ticket> timeoutTickets = ticketRepository.findAssignedBefore(deadline);

        log.info("[超时转派] 本轮扫描到{}个超时未响应工单", timeoutTickets.size());

        for (Ticket ticket : timeoutTickets) {
            try {
                transferIfNeeded(ticket);
            } catch (Exception e) {
                // 单个工单转派失败不应影响其他工单的扫描处理
                log.error("[超时转派] 工单转派处理异常, ticketId={}", ticket.getTicketId(), e);
            }
        }
    }

    private void transferIfNeeded(Ticket ticket) {
        String lockKey = "dispatch:transfer:lock:" + ticket.getTicketId();
        Boolean locked = redisTemplate.opsForValue().setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS);
        if (!Boolean.TRUE.equals(locked)) {
            log.debug("[超时转派] 工单转派锁获取失败，可能被其他实例处理, ticketId={}", ticket.getTicketId());
            return;
        }

        try {
            // 锁内重新读取最新状态，避免转派已经被处理过的工单
            Ticket latest = ticketRepository.findById(ticket.getTicketId());
            if (latest == null || latest.getStatus() != TicketStatus.ASSIGNED) {
                log.info("[超时转派] 工单状态已变化，无需转派, ticketId={}, status={}",
                    ticket.getTicketId(), latest == null ? "NOT_FOUND" : latest.getStatus());
                return;
            }

            int transferCount = ticketRepository.getTransferCount(latest.getTicketId());
            if (transferCount >= maxTransferTimes) {
                // 转派次数超限，升级为人工主管介入，不再自动转派
                ticketRepository.markNeedSupervisorIntervention(latest.getTicketId());
                alertService.sendAlert("DISPATCH_TRANSFER_EXHAUSTED",
                    String.format("工单转派次数已达上限%d次，需主管介入, ticketId=%s",
                        maxTransferTimes, latest.getTicketId()));
                log.warn("[超时转派] 转派次数达到上限，升级主管介入, ticketId={}, transferCount={}",
                    latest.getTicketId(), transferCount);
                return;
            }

            // 释放原客服的负载占用
            if (StringUtils.isNotBlank(latest.getAssignedAgentId())) {
                agentGroupService.decrementLoad(latest.getAssignedAgentId());
            }

            // 记录转派日志，回退状态到QUEUING，重新触发自动派单
            String previousAgentId = latest.getAssignedAgentId();
            latest.setAssignedAgentId(null);
            TicketStateMachine.transition(latest, TicketStatus.QUEUING);
            ticketRepository.updateStatus(latest.getTicketId(), TicketStatus.QUEUING);
            ticketRepository.incrementTransferCount(latest.getTicketId());

            transferLogRepository.insert(TransferLog.of(latest.getTicketId(), previousAgentId,
                "客服超时未响应自动转派", System.currentTimeMillis()));

            log.info("[超时转派] 工单转派完成, ticketId={}, previousAgentId={}, transferCount={}",
                latest.getTicketId(), previousAgentId, transferCount + 1);

            // 重新触发一次派单，尽快分配给下一位客服
            autoDispatchService.dispatch(latest.getTicketId());

        } finally {
            redisTemplate.delete(lockKey);
        }
    }

    @Resource
    private TransferLogRepository transferLogRepository;

    @Resource
    private AlertService alertService;
}
```

### 10.3 案例三：工单SLA监控全链路（首响超时检测 → 处理时长监控 → 升级策略 → 告警通知）

#### 10.3.1 链路概述

SLA（服务水平协议）监控是保障工单处理时效的最后防线，覆盖首次响应时长（First Response Time）、整体处理时长（Resolution Time）两个核心指标，通过分级升级策略在SLA临近超时和已超时两个阶段分别采取不同的处理动作。

```java
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ SLA规则  │──▶│ 定时扫描  │──▶│ 阈值判断  │──▶│ 升级策略  │──▶│ 告警通知  │
│ 配置加载  │   │ 首响/时长 │   │ 临期/超时 │   │ 逐级升级  │   │ 多渠道触达│
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

#### 10.3.2 SLA规则模型

#### 10.3.3 首响超时检测

```java
/**
 * 首响SLA监控服务
 * 首次响应时长 = 客服第一次回复时间 - 工单分配时间
 *
 * 检测策略：
 * 1. 定时任务每15秒扫描一次已分配但尚未首次回复的工单
 * 2. 达到预警比例（默认80%）触发临期提醒，仅通知责任客服
 * 3. 超过阈值触发超时升级，进入升级策略链
 * 4. 使用Redis记录已发送的告警级别，防止重复告警
 */
@Service
@Slf4j
public class FirstResponseSlaMonitor {

    @Resource
    private TicketRepository ticketRepository;

    @Resource
    private TicketReplyRepository replyRepository;

    @Resource
    private SlaRuleService slaRuleService;

    @Resource
    private EscalationService escalationService;

    @Resource
    private RedisTemplate<String, String> redisTemplate;

    @Scheduled(fixedDelay = 15000)
    public void scanFirstResponseSla() {
        List<Ticket> assignedTickets = ticketRepository.findByStatus(TicketStatus.PROCESSING);
        log.info("[SLA监控-首响] 本轮扫描{}个处理中工单", assignedTickets.size());

        int warningCount = 0;
        int timeoutCount = 0;

        for (Ticket ticket : assignedTickets) {
            try {
                boolean hasReplied = replyRepository.existsByTicketId(ticket.getTicketId());
                if (hasReplied) {
                    continue; // 已首次回复，无需再监控首响SLA
                }

                SlaRule rule = slaRuleService.matchRule(ticket);
                if (rule == null) {
                    log.warn("[SLA监控-首响] 未匹配到SLA规则，跳过, ticketId={}", ticket.getTicketId());
                    continue;
                }

                long elapsedSeconds = (System.currentTimeMillis() - ticket.getAssignedTime()) / 1000;
                long warningThreshold = (long) (rule.getFirstResponseTimeoutSeconds() * rule.getWarningRatio());

                if (elapsedSeconds >= rule.getFirstResponseTimeoutSeconds()) {
                    handleTimeout(ticket, rule, elapsedSeconds);
                    timeoutCount++;
                } else if (elapsedSeconds >= warningThreshold) {
                    handleWarning(ticket, elapsedSeconds, rule.getFirstResponseTimeoutSeconds());
                    warningCount++;
                }
            } catch (Exception e) {
                // 单个工单SLA检测异常不能中断整体扫描
                log.error("[SLA监控-首响] 检测异常, ticketId={}", ticket.getTicketId(), e);
            }
        }

        log.info("[SLA监控-首响] 本轮完成, warning={}, timeout={}", warningCount, timeoutCount);
    }

    /**
     * 临期预警：仅通知责任客服本人，使用Redis去重，同一工单同一天只提醒一次
     */
    private void handleWarning(Ticket ticket, long elapsedSeconds, long timeoutSeconds) {
        String dedupKey = "sla:warning:frt:" + ticket.getTicketId() + ":" + getTodayStr();
        Boolean isFirst = redisTemplate.opsForValue().setIfAbsent(dedupKey, "1", 24, TimeUnit.HOURS);
        if (!Boolean.TRUE.equals(isFirst)) {
            return; // 今天已经提醒过，避免重复打扰
        }

        log.info("[SLA预警-首响] 工单临近首响超时, ticketId={}, elapsed={}s, threshold={}s",
            ticket.getTicketId(), elapsedSeconds, timeoutSeconds);

        notifyService.notifyAgent(ticket.getAssignedAgentId(),
            String.format("工单%s即将首响超时，请尽快处理", ticket.getTicketId()));
    }

    /**
     * 超时处理：记录SLA违约事件，触发升级策略链
     * 幂等：Redis记录已触发的最高升级级别，避免同级别重复升级通知
     */
    private void handleTimeout(Ticket ticket, SlaRule rule, long elapsedSeconds) {
        slaViolationRepository.recordIfAbsent(SlaViolation.of(
            ticket.getTicketId(), "FIRST_RESPONSE", elapsedSeconds, System.currentTimeMillis()));

        log.warn("[SLA违约-首响] 工单首响超时, ticketId={}, elapsed={}s, threshold={}s",
            ticket.getTicketId(), elapsedSeconds, rule.getFirstResponseTimeoutSeconds());

        escalationService.escalate(ticket, rule, elapsedSeconds - rule.getFirstResponseTimeoutSeconds());
    }

    private String getTodayStr() {
        return new SimpleDateFormat("yyyyMMdd").format(new Date());
    }

    @Resource
    private AgentNotifyService notifyService;

    @Resource
    private SlaViolationRepository slaViolationRepository;
}
```

#### 10.3.4 处理时长监控

```java
/**
 * 整体处理时长SLA监控服务
 * 处理时长 = 当前时间 - 工单创建时间（用于COMPLETED之前的所有工单）
 * 与首响监控相互独立，一个工单可能首响未超时但整体处理时长超时
 */
@Service
@Slf4j
public class ResolutionSlaMonitor {

    @Resource
    private TicketRepository ticketRepository;

    @Resource
    private SlaRuleService slaRuleService;

    @Resource
    private EscalationService escalationService;

    private static final Set<TicketStatus> MONITORING_STATUSES = Set.of(
        TicketStatus.QUEUING, TicketStatus.ALLOCATING, TicketStatus.ASSIGNED, TicketStatus.PROCESSING);

    @Scheduled(fixedDelay = 30000)
    public void scanResolutionSla() {
        List<Ticket> activeTickets = ticketRepository.findByStatusIn(MONITORING_STATUSES);
        log.info("[SLA监控-处理时长] 本轮扫描{}个活跃工单", activeTickets.size());

        for (Ticket ticket : activeTickets) {
            try {
                SlaRule rule = slaRuleService.matchRule(ticket);
                if (rule == null) {
                    continue;
                }

                long elapsedSeconds = (System.currentTimeMillis() - ticket.getCreateTime()) / 1000;
                if (elapsedSeconds < rule.getResolutionTimeoutSeconds()) {
                    continue;
                }

                boolean isNewViolation = slaViolationRepository.recordIfAbsent(SlaViolation.of(
                    ticket.getTicketId(), "RESOLUTION", elapsedSeconds, System.currentTimeMillis()));

                if (isNewViolation) {
                    log.warn("[SLA违约-处理时长] 工单整体处理超时, ticketId={}, elapsed={}s, threshold={}s",
                        ticket.getTicketId(), elapsedSeconds, rule.getResolutionTimeoutSeconds());
                }

                // 无论是否新违约都持续推进升级策略，因为超时时间越长应升级到更高级别
                escalationService.escalate(ticket, rule, elapsedSeconds - rule.getResolutionTimeoutSeconds());

            } catch (Exception e) {
                log.error("[SLA监控-处理时长] 检测异常, ticketId={}", ticket.getTicketId(), e);
            }
        }
    }
```

#### 10.3.5 分级升级策略与多渠道告警

```java
/**
 * SLA升级服务
 * 根据超时时长匹配升级策略链中最高符合条件的级别，逐级通知不同角色
 *
 * 幂等设计：
 * 使用Redis记录"工单当前已达到的最高升级级别"，只有当新计算的级别高于已记录级别时才触发通知，
 * 避免定时任务重复扫描导致同一级别反复告警
 */
@Service
@Slf4j
public class EscalationService {

    @Resource
    private RedisTemplate<String, String> redisTemplate;

    @Resource
    private NotifyChannelRouter notifyChannelRouter;

    @Resource
    private AgentGroupService agentGroupService;

    private static final String ESCALATION_LEVEL_KEY_PREFIX = "sla:escalation:level:";

    public void escalate(Ticket ticket, SlaRule rule, long overtimeSeconds) {
        if (overtimeSeconds < 0 || CollectionUtils.isEmpty(rule.getEscalationLevels())) {
            return;
        }

        // 找到超时时长范围内最高符合条件的升级级别
        EscalationLevel targetLevel = rule.getEscalationLevels().stream()
            .filter(level -> overtimeSeconds >= level.getTriggerAfterSeconds())
            .max(Comparator.comparingInt(EscalationLevel::getLevel))
            .orElse(null);

        if (targetLevel == null) {
            return;
        }

        String levelKey = ESCALATION_LEVEL_KEY_PREFIX + ticket.getTicketId();
        String currentLevelStr = redisTemplate.opsForValue().get(levelKey);
        int currentLevel = currentLevelStr == null ? 0 : Integer.parseInt(currentLevelStr);

        if (targetLevel.getLevel() <= currentLevel) {
            // 已经处于该级别或更高级别，不重复通知
            return;
        }

        try {
            doEscalate(ticket, targetLevel);
            // 通知成功后更新级别记录，TTL设置为7天，超过工单生命周期后自动过期
            redisTemplate.opsForValue().set(levelKey, String.valueOf(targetLevel.getLevel()), 7, TimeUnit.DAYS);
            log.info("[SLA升级] 升级通知发送成功, ticketId={}, level={}, notifyRole={}",
                ticket.getTicketId(), targetLevel.getLevel(), targetLevel.getNotifyRole());
        } catch (Exception e) {
            // 升级通知失败不应影响SLA监控主流程继续扫描其他工单，记录日志并触发兜底告警
            log.error("[SLA升级] 升级通知发送失败, ticketId={}, level={}",
                ticket.getTicketId(), targetLevel.getLevel(), e);
            fallbackAlert(ticket, targetLevel, e);
        }
    }

    private void doEscalate(Ticket ticket, EscalationLevel level) {
        List<String> recipients = resolveRecipients(ticket, level.getNotifyRole());
        if (recipients.isEmpty()) {
            log.warn("[SLA升级] 未找到升级通知对象, ticketId={}, notifyRole={}",
                ticket.getTicketId(), level.getNotifyRole());
            return;
        }

        String content = String.format("工单%s已触发SLA升级（级别%d），业务线：%s，请及时处理",
            ticket.getTicketId(), level.getLevel(), ticket.getBizLine());

        for (String channel : level.getNotifyChannels()) {
            try {
                notifyChannelRouter.send(channel, recipients, content);
            } catch (Exception e) {
                // 单一渠道失败不影响其他渠道继续发送，尽量提高触达率
                log.error("[SLA升级] 渠道{}发送失败, ticketId={}, recipients={}",
                    channel, ticket.getTicketId(), recipients, e);
            }
        }
    }

    private List<String> resolveRecipients(Ticket ticket, String notifyRole) {
        switch (notifyRole) {
            case "AGENT":
                return ticket.getAssignedAgentId() == null
                    ? Collections.emptyList() : List.of(ticket.getAssignedAgentId());
            case "TEAM_LEADER":
                return agentGroupService.findTeamLeaders(ticket.getAssignedAgentId());
            case "MANAGER":
                return agentGroupService.findBizLineManagers(ticket.getBizLine());
            default:
                return Collections.emptyList();
        }
    }

    /**
     * 兜底告警：升级通知渠道全部失败时，写入系统级告警，由监控大盘人工介入
     */
    private void fallbackAlert(Ticket ticket, EscalationLevel level, Exception cause) {
        try {
            alertService.sendAlert("SLA_ESCALATION_NOTIFY_FAILED",
                String.format("工单%s的SLA升级通知（级别%d）发送失败：%s",
                    ticket.getTicketId(), level.getLevel(), cause.getMessage()));
        } catch (Exception e) {
            // 兜底告警也失败时只能记录严重错误日志，等待人工巡检发现
            log.error("[SLA升级] 兜底告警发送也失败，需人工巡检, ticketId={}", ticket.getTicketId(), e);
        }
    }

    @Resource
    private AlertService alertService;
}
```

#### 10.3.6 小结

三个案例分别覆盖了工单系统"写入侧"（用户提交）、"调度侧"（自动派单）、"保障侧"（SLA监控）三条最核心的链路。三者共享同一套幂等设计范式：入口使用Redis幂等键或分布式锁快速拦截，关键写操作使用数据库唯一索引或乐观锁兜底并发，跨进程的状态推进通过状态机严格校验合法性；同时统一采用"try-catch分层处理 + 详细日志埋点 + 独立告警兜底"的异常处理风格，保证任意环节出现故障时都能被快速发现并有明确的降级或补偿路径，而不会让工单静默丢失或状态错乱。
