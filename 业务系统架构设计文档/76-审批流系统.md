# 审批流系统架构设计

## 一、系统概述

审批流系统是企业级业务自动化的核心基础设施，用于实现业务流程的自动化流转。工作流是对工作流程及其各操作步骤之间业务规则的抽象、概括描述，工作流建模即将工作流程中的工作如何前后组织在一起的逻辑和规则在计算机中以恰当的模型表达并对其实施计算。工作流要解决的核心问题是：为实现某个业务目标，利用计算机在多个参与者之间按某种预定规则自动传递文档、信息或者任务。本质上，工作流引擎是专用于实现业务自动化的工具。

### 1.1 适用场景

工作流引擎适用于需要人工参与的或每一个步骤执行时间超过秒级的自动化业务场景。典型场景包括：关键业务流程如订单处理、报价处理、采购处理、合同审核、客户电话处理、供应链管理；行政管理类如出差申请、加班申请、请假申请、用车申请、各种办公用品申请；财务相关类如付款请求、应收款处理、日常报销处理、出差报销、预算和计划申请；客户服务类如客户信息管理、客户投诉、请求处理、售后服务管理。

工作流引擎也可充当多个系统之间交互的胶水角色，例如采购系统下单后需要转到财务系统进入付款流程，然后转入物流系统进入物流环节，接着需要转入仓储系统进行库存管理，整个流程横跨若干个系统。

不适用场景包括：业务流程简单明确且变化很少的场景，以及高并发场景。工作流引擎属于重量级系统，对于简单流程使用工作流引擎会增加不必要的复杂性和性能开销。

### 1.2 核心挑战

审批流系统面临以下核心技术挑战。第一，灵活性：业务流程频繁变化，系统需要支持流程图的动态调整而无需修改代码。第二，状态管理：流程实例的状态流转复杂，包括顺序、并行、分支、汇聚、回退等多种模式。第三，流程回退：审批驳回后需要回退到指定节点，且保证数据一致性。第四，性能：流程查询和任务分配需要高效，不能成为业务瓶颈。第五，可靠性：流程状态必须持久化，系统故障恢复后流程不丢失。

### 1.3 设计理念

工作流引擎可以看成一个状态机组件。通过定义流程图告诉引擎应该有哪些状态、状态之间是如何转化的，引擎能够将任务节点的开始事件、结束事件推送至业务系统，方便业务系统感知状态机当前的状态。业务程序原来新建状态机的操作等效于在引擎创建一个流程，业务程序原来触发状态机进入下一个状态的操作等效于完成一个引擎的任务节点。

## 二、整体架构

系统采用五层架构设计：流程定义层、流程引擎层、任务管理层、事件通知层和持久化层。

```java
┌─────────────────────────────────────────────────────┐
│                    流程定义层                          │
│    流程图设计器 │ BPMN模型 │ 流程部署 │ 版本管理       │
├─────────────────────────────────────────────────────┤
│                    流程引擎层                          │
│    流程实例创建 │ 状态流转 │ 网关执行 │ 流程变量       │
├─────────────────────────────────────────────────────┤
│                    任务管理层                          │
│    用户任务 │ 服务任务 │ 任务分配 │ 任务查询           │
├─────────────────────────────────────────────────────┤
│                    事件通知层                          │
│    事件回调 │ MQ异步通知 │ 事件监听 │ 定时事件         │
├─────────────────────────────────────────────────────┤
│                    持久化层                            │
│    流程实例存储 │ 任务存储 │ 变量存储 │ 历史数据       │
└─────────────────────────────────────────────────────┘
```

流程定义层提供流程图设计能力，遵循BPMN 2.0规范，支持可视化设计流程图并部署到引擎。流程引擎层是核心，负责流程实例的创建和状态流转，包括网关条件求值、并行执行汇聚等。任务管理层管理审批任务的创建、分配、查询和完成。事件通知层通过回调接口和消息队列将流程事件通知业务系统。持久化层负责流程实例、任务、变量和历史数据的持久化存储。

## 三、流程定义模型

### 3.1 BPMN模型要素

流程定义遵循BPMN 2.0规范，核心模型要素包括节点、连线和事件。

```java
/**
 * 流程节点基类
 * 所有流程节点的抽象基类
 */
@Data
public abstract class FlowNode {
    private String nodeId;          // 节点ID
    private String nodeName;        // 节点名称
    private NodeType nodeType;      // 节点类型
    private List<FlowSequence> outgoingFlows;  // 出边
    private List<FlowSequence> incomingFlows;  // 入边
    
    public enum NodeType {
        START_EVENT,           // 开始事件
        END_EVENT,             // 结束事件
        USER_TASK,             // 用户任务（人工审批）
        SERVICE_TASK,          // 服务任务（自动执行）
        EXCLUSIVE_GATEWAY,     // 排他网关（条件分支）
        PARALLEL_GATEWAY,      // 并行网关
        INCLUSIVE_GATEWAY,     // 包含网关
        TIMER_EVENT,           // 定时事件
        MESSAGE_EVENT          // 消息事件
    }
}

/**
 * 用户任务节点
 * 人工审批节点，需要指定审批人
 */
@Data
@EqualsAndHashCode(callSuper = true)
public class UserTask extends FlowNode {
    private String assignee;              // 指定审批人
    private List<String> candidateUsers;  // 候选审批人列表
    private List<String> candidateGroups; // 候选审批组
    private TaskAssignmentType assignmentType;  // 分配方式
    
    public enum TaskAssignmentType {
        SINGLE,        // 单人审批
        COUNTERSIGN,   // 会签（所有人都需同意）
        OR_SIGN,       // 或签（任一人同意即可）
        ADD_SIGN       // 加签（中途增加审批人）
    }
}

/**
 * 服务任务节点
 * 自动执行程序，无需人工参与
 */
@Data
@EqualsAndHashCode(callSuper = true)
public class ServiceTask extends FlowNode {
    private String serviceInterface;  // 服务接口
    private String serviceMethod;     // 服务方法
    private Map<String, String> inputParams;  // 输入参数
}

/**
 * 排他网关
 * 条件分支，根据条件表达式选择一条路径
 */
@Data
@EqualsAndHashCode(callSuper = true)
public class ExclusiveGateway extends FlowNode {
    private List<GatewayCondition> conditions;  // 条件列表
}

/**
 * 并行网关
 * 并行执行所有出边，汇聚时等待所有入边到达
 */
@Data
@EqualsAndHashCode(callSuper = true)
public class ParallelGateway extends FlowNode {
    // 并行网关不需要条件，所有出边同时执行
}

/**
 * 流程连线
 * 连接两个节点，可携带条件表达式
 */
@Data
public class FlowSequence {
    private String flowId;
    private String sourceRef;     // 源节点ID
    private String targetRef;     // 目标节点ID
    private String conditionExpression;  // 条件表达式（排他网关用）
}

/**
 * 网关条件
 */
@Data
public class GatewayCondition {
    private String flowId;           // 对应的连线ID
    private String expression;       // 条件表达式
    private boolean defaultFlow;     // 是否默认分支
}
```

### 3.2 流程定义

```java
/**
 * 流程定义
 * 一个完整的流程图，包含所有节点和连线
 */
@Data
public class ProcessDefinition {
    private String processId;        // 流程定义ID
    private String processName;      // 流程名称
    private String version;          // 版本号
    private String tenantId;         // 租户ID
    private ProcessStatus status;    // 部署状态
    
    private Map<String, FlowNode> nodes;  // 所有节点
    private List<FlowSequence> flows;     // 所有连线
    
    public enum ProcessStatus {
        DRAFT,        // 草稿
        DEPLOYED,     // 已部署
        SUSPENDED,    // 已挂起
        DEPRECATED    // 已废弃
    }
    
    /**
     * 获取开始节点
     */
    public FlowNode getStartNode() {
        return nodes.values().stream()
            .filter(n -> n.getNodeType() == FlowNode.NodeType.START_EVENT)
            .findFirst()
            .orElse(null);
    }
    
    /**
     * 获取节点的所有后续节点
     */
    public List<FlowNode> getOutgoingNodes(String nodeId) {
        FlowNode node = nodes.get(nodeId);
        if (node == null || node.getOutgoingFlows() == null) {
            return Collections.emptyList();
        }
        
        return node.getOutgoingFlows().stream()
            .map(flow -> nodes.get(flow.getTargetRef()))
            .filter(Objects::nonNull)
            .collect(Collectors.toList());
    }
}
```

### 3.3 流程图JSON序列化

流程定义使用JSON格式存储，便于设计器与引擎之间的数据交换。

```java
/**
 * 流程定义序列化服务
 * 将流程图序列化为JSON存储，反序列化为ProcessDefinition
 */
@Service
public class ProcessDefinitionSerializer {
    
    /**
     * 序列化流程定义为JSON
     */
    public String serialize(ProcessDefinition definition) {
        JSONObject json = new JSONObject();
        json.put("processId", definition.getProcessId());
        json.put("processName", definition.getProcessName());
        json.put("version", definition.getVersion());
        
        // 序列化节点
        JSONArray nodesArray = new JSONArray();
        for (FlowNode node : definition.getNodes().values()) {
            JSONObject nodeJson = new JSONObject();
            nodeJson.put("nodeId", node.getNodeId());
            nodeJson.put("nodeName", node.getNodeName());
            nodeJson.put("nodeType", node.getNodeType().name());
            
            if (node instanceof UserTask) {
                UserTask task = (UserTask) node;
                nodeJson.put("assignee", task.getAssignee());
                nodeJson.put("candidateUsers", task.getCandidateUsers());
                nodeJson.put("assignmentType", task.getAssignmentType().name());
            } else if (node instanceof ExclusiveGateway) {
                ExclusiveGateway gw = (ExclusiveGateway) node;
                nodeJson.put("conditions", gw.getConditions());
            }
            
            nodesArray.add(nodeJson);
        }
        json.put("nodes", nodesArray);
        
        // 序列化连线
        JSONArray flowsArray = new JSONArray();
        for (FlowSequence flow : definition.getFlows()) {
            JSONObject flowJson = new JSONObject();
            flowJson.put("flowId", flow.getFlowId());
            flowJson.put("sourceRef", flow.getSourceRef());
            flowJson.put("targetRef", flow.getTargetRef());
            flowJson.put("conditionExpression", flow.getConditionExpression());
            flowsArray.add(flowJson);
        }
        json.put("flows", flowsArray);
        
        return json.toJSONString();
    }
    
    /**
     * 反序列化JSON为流程定义
     */
    public ProcessDefinition deserialize(String json) {
        JSONObject obj = JSON.parseObject(json);
        ProcessDefinition definition = new ProcessDefinition();
        definition.setProcessId(obj.getString("processId"));
        definition.setProcessName(obj.getString("processName"));
        definition.setVersion(obj.getString("version"));
        
        // 反序列化节点和连线
        Map<String, FlowNode> nodes = new HashMap<>();
        JSONArray nodesArray = obj.getJSONArray("nodes");
        for (int i = 0; i < nodesArray.size(); i++) {
            JSONObject nodeJson = nodesArray.getJSONObject(i);
            FlowNode node = createNode(nodeJson);
            nodes.put(node.getNodeId(), node);
        }
        definition.setNodes(nodes);
        
        List<FlowSequence> flows = JSON.parseArray(
            obj.getString("flows"), FlowSequence.class);
        definition.setFlows(flows);
        
        // 建立节点的出入边引用
        buildNodeReferences(definition);
        
        return definition;
    }
    
    private FlowNode createNode(JSONObject json) {
        FlowNode.NodeType type = FlowNode.NodeType.valueOf(
            json.getString("nodeType"));
        
        switch (type) {
            case USER_TASK:
                UserTask task = new UserTask();
                task.setNodeId(json.getString("nodeId"));
                task.setNodeName(json.getString("nodeName"));
                task.setNodeType(type);
                task.setAssignee(json.getString("assignee"));
                task.setCandidateUsers(json.getJSONArray("candidateUsers")
                    .toJavaList(String.class));
                task.setAssignmentType(UserTask.TaskAssignmentType.valueOf(
                    json.getString("assignmentType")));
                return task;
            case EXCLUSIVE_GATEWAY:
                ExclusiveGateway gw = new ExclusiveGateway();
                gw.setNodeId(json.getString("nodeId"));
                gw.setNodeName(json.getString("nodeName"));
                gw.setNodeType(type);
                gw.setConditions(json.getJSONArray("conditions")
                    .toJavaList(GatewayCondition.class));
                return gw;
            default:
                FlowNode node = new FlowNode() {};
                node.setNodeId(json.getString("nodeId"));
                node.setNodeName(json.getString("nodeName"));
                node.setNodeType(type);
                return node;
        }
    }
    
    private void buildNodeReferences(ProcessDefinition definition) {
        for (FlowSequence flow : definition.getFlows()) {
            FlowNode source = definition.getNodes().get(flow.getSourceRef());
            FlowNode target = definition.getNodes().get(flow.getTargetRef());
            
            if (source != null) {
                if (source.getOutgoingFlows() == null) {
                    source.setOutgoingFlows(new ArrayList<>());
                }
                source.getOutgoingFlows().add(flow);
            }
            if (target != null) {
                if (target.getIncomingFlows() == null) {
                    target.setIncomingFlows(new ArrayList<>());
                }
                target.getIncomingFlows().add(flow);
            }
        }
    }
}
```

## 四、流程引擎核心

### 4.1 流程实例管理

流程引擎的核心是状态机模式。创建流程实例等同于初始化一个状态机，完成一个任务节点等同于触发状态机进入下一个状态。

```java
/**
 * 流程实例
 * 一次具体的审批流程
 */
@Data
public class ProcessInstance {
    private String instanceId;          // 实例ID
    private String processId;           // 流程定义ID
    private String version;             // 流程版本
    private String tenantId;            // 租户ID
    private String businessKey;         // 业务键（与业务数据的关联）
    private String businessId;          // 业务数据ID
    private InstanceStatus status;      // 实例状态
    private String currentNodeId;       // 当前节点ID
    private Map<String, Object> variables;  // 流程变量
    private Long startTime;             // 开始时间
    private Long endTime;               // 结束时间
    private String initiator;           // 发起人
    
    public enum InstanceStatus {
        RUNNING,      // 运行中
        COMPLETED,    // 已完成
        TERMINATED,   // 已终止
        SUSPENDED     // 已挂起
    }
}
```

```java
/**
 * 流程引擎核心
 * 负责流程实例的创建、状态流转和节点执行
 * 
 * 设计模式：状态机模式
 * 每个流程实例是一个状态机，节点是状态，连线是状态转换
 */
@Service
public class ProcessEngine {
    
    @Resource
    private ProcessDefinitionService definitionService;
    
    @Resource
    private ProcessInstanceRepository instanceRepository;
    
    @Resource
    private TaskService taskService;
    
    @Resource
    private EventNotificationService eventService;
    
    @Resource
    private GatewayEvaluator gatewayEvaluator;
    
    /**
     * 创建流程实例
     * 
     * 算法说明：
     * 1. 查询流程定义
     * 2. 创建流程实例，初始化流程变量
     * 3. 找到开始节点，执行状态流转
     * 4. 持久化实例
     */
    public ProcessInstance startProcess(String processId, String businessKey,
            Map<String, Object> variables, String initiator) {
        // 1. 查询流程定义
        ProcessDefinition definition = definitionService.getDeployedDefinition(processId);
        if (definition == null) {
            throw new ProcessException("Process definition not found: " + processId);
        }
        
        // 2. 创建流程实例
        ProcessInstance instance = new ProcessInstance();
        instance.setInstanceId(IdGenerator.nextId());
        instance.setProcessId(processId);
        instance.setVersion(definition.getVersion());
        instance.setBusinessKey(businessKey);
        instance.setVariables(variables != null ? variables : new HashMap<>());
        instance.setStatus(InstanceStatus.RUNNING);
        instance.setStartTime(System.currentTimeMillis());
        instance.setInitiator(initiator);
        
        // 3. 找到开始节点，执行流转
        FlowNode startNode = definition.getStartNode();
        if (startNode == null) {
            throw new ProcessException("No start event found in process: " + processId);
        }
        
        instance.setCurrentNodeId(startNode.getNodeId());
        instanceRepository.save(instance);
        
        // 4. 从开始节点开始执行
        executeNode(instance, definition, startNode);
        
        return instance;
    }
    
    /**
     * 执行节点
     * 
     * 算法说明：
     * 1. 根据节点类型执行不同逻辑
     * 2. 用户任务：创建审批任务，等待人工完成
     * 3. 服务任务：自动执行服务，完成后流转
     * 4. 网关：求值条件，选择路径
     * 5. 事件：触发事件通知
     */
    public void executeNode(ProcessInstance instance, ProcessDefinition definition, 
            FlowNode node) {
        // 触发节点开始事件
        eventService.fireEvent(instance.getInstanceId(), node.getNodeId(), 
            EventType.NODE_START);
        
        switch (node.getNodeType()) {
            case START_EVENT:
                // 开始事件：直接流转到下一节点
                moveToNextNodes(instance, definition, node);
                break;
                
            case USER_TASK:
                // 用户任务：创建审批任务
                taskService.createTask(instance, (UserTask) node);
                break;
                
            case SERVICE_TASK:
                // 服务任务：自动执行
                executeServiceTask(instance, (ServiceTask) node);
                moveToNextNodes(instance, definition, node);
                break;
                
            case EXCLUSIVE_GATEWAY:
                // 排他网关：条件求值选择路径
                FlowNode nextNode = gatewayEvaluator.evaluateExclusive(
                    (ExclusiveGateway) node, instance.getVariables());
                if (nextNode != null) {
                    instance.setCurrentNodeId(nextNode.getNodeId());
                    instanceRepository.save(instance);
                    executeNode(instance, definition, nextNode);
                }
                break;
                
            case PARALLEL_GATEWAY:
                // 并行网关：同时执行所有出边
                executeParallelGateway(instance, definition, (ParallelGateway) node);
                break;
                
            case END_EVENT:
                // 结束事件：完成流程
                completeInstance(instance);
                break;
                
            default:
                break;
        }
        
        // 触发节点结束事件
        eventService.fireEvent(instance.getInstanceId(), node.getNodeId(),
            EventType.NODE_END);
    }
    
    /**
     * 流转到下一节点
     */
    private void moveToNextNodes(ProcessInstance instance, ProcessDefinition definition, 
            FlowNode currentNode) {
        List<FlowNode> nextNodes = definition.getOutgoingNodes(currentNode.getNodeId());
        
        if (nextNodes.isEmpty()) {
            // 没有后续节点，结束流程
            completeInstance(instance);
            return;
        }
        
        // 默认只取第一个（排他网关已经在上层处理了路径选择）
        FlowNode nextNode = nextNodes.get(0);
        instance.setCurrentNodeId(nextNode.getNodeId());
        instanceRepository.save(instance);
        
        executeNode(instance, definition, nextNode);
    }
    
    /**
     * 完成流程实例
     */
    private void completeInstance(ProcessInstance instance) {
        instance.setStatus(InstanceStatus.COMPLETED);
        instance.setEndTime(System.currentTimeMillis());
        instanceRepository.save(instance);
        
        eventService.fireEvent(instance.getInstanceId(), null, EventType.PROCESS_END);
    }
    
    /**
     * 执行服务任务
     */
    private void executeServiceTask(ProcessInstance instance, ServiceTask task) {
        // 通过反射调用服务方法
        try {
            Class<?> serviceClass = Class.forName(task.getServiceInterface());
            Object service = SpringContext.getBean(serviceClass);
            Method method = serviceClass.getMethod(task.getServiceMethod(), Map.class);
            Object result = method.invoke(service, instance.getVariables());
            
            // 将结果存入流程变量
            if (result != null) {
                instance.getVariables().put(task.getNodeId() + "_result", result);
            }
        } catch (Exception e) {
            log.error("Service task execution failed: {}", task.getNodeId(), e);
            throw new ProcessException("Service task failed: " + e.getMessage());
        }
    }
    
    /**
     * 执行并行网关
     */
    private void executeParallelGateway(ProcessInstance instance, 
            ProcessDefinition definition, ParallelGateway gateway) {
        List<FlowNode> parallelNodes = definition.getOutgoingNodes(gateway.getNodeId());
        
        // 并行执行所有出边
        for (FlowNode node : parallelNodes) {
            // 创建并行执行上下文
            ProcessInstance branchInstance = copyInstance(instance);
            branchInstance.setCurrentNodeId(node.getNodeId());
            instanceRepository.save(branchInstance);
            
            executeNode(branchInstance, definition, node);
        }
    }
}
```

## 五、网关与条件分支

### 5.1 排他网关求值

排他网关根据条件表达式选择一条执行路径。条件表达式使用EL表达式语法，支持流程变量引用和逻辑运算。

```java
/**
 * 网关求值器
 * 
 * 设计模式：解释器模式
 * 条件表达式被解析为AST，然后对AST求值
 */
@Service
public class GatewayEvaluator {
    
    /**
     * 排他网关求值
     * 
     * 算法说明：
     * 1. 遍历所有条件
     * 2. 对每个条件表达式求值
     * 3. 第一个满足条件的连线即为选中路径
     * 4. 如果没有条件满足，走默认分支
     */
    public FlowNode evaluateExclusive(ExclusiveGateway gateway, 
            Map<String, Object> variables) {
        for (GatewayCondition condition : gateway.getConditions()) {
            if (condition.isDefaultFlow()) {
                continue;  // 默认分支最后判断
            }
            
            if (evaluateExpression(condition.getExpression(), variables)) {
                // 找到流程定义中对应的连线目标节点
                return findTargetNode(gateway, condition.getFlowId());
            }
        }
        
        // 没有条件满足，走默认分支
        for (GatewayCondition condition : gateway.getConditions()) {
            if (condition.isDefaultFlow()) {
                return findTargetNode(gateway, condition.getFlowId());
            }
        }
        
        throw new ProcessException("No matching condition and no default flow in gateway: " 
            + gateway.getNodeId());
    }
    
    /**
     * 表达式求值
     * 支持EL表达式，如：${amount > 10000 && type == 'urgent'}
     * 
     * 算法说明：
     * 1. 解析表达式中的变量引用 ${var}
     * 2. 替换为实际值
     * 3. 执行逻辑运算
     */
    public boolean evaluateExpression(String expression, Map<String, Object> variables) {
        if (expression == null || expression.isEmpty()) {
            return true;
        }
        
        // 去除${}包裹
        String expr = expression.trim();
        if (expr.startsWith("${") && expr.endsWith("}")) {
            expr = expr.substring(2, expr.length() - 1).trim();
        }
        
        // 替换变量引用
        for (Map.Entry<String, Object> entry : variables.entrySet()) {
            String varRef = entry.getKey();
            String varValue = entry.getValue() != null 
                ? entry.getValue().toString() : "null";
            
            // 字符串类型加引号
            if (entry.getValue() instanceof String) {
                varValue = "'" + varValue + "'";
            }
            
            expr = expr.replace(varRef, varValue);
        }
        
        // 使用ScriptEngine求值
        try {
            ScriptEngine engine = new ScriptEngineManager().getEngineByName("js");
            Object result = engine.eval(expr);
            return Boolean.TRUE.equals(result);
        } catch (Exception e) {
            log.error("Expression evaluation failed: {}", expression, e);
            return false;
        }
    }
    
    private FlowNode findTargetNode(FlowNode gateway, String flowId) {
        return gateway.getOutgoingFlows().stream()
            .filter(f -> f.getFlowId().equals(flowId))
            .map(f -> {
                // 需要从流程定义中查找目标节点
                return (FlowNode) null;  // 实际实现需要传入流程定义
            })
            .findFirst()
            .orElse(null);
    }
}
```

## 六、审批操作

### 6.1 任务服务

审批操作包括审批通过、驳回、加签、会签、或签、转办、委派等。每种操作对应不同的任务处理逻辑。

```java
/**
 * 任务服务
 * 管理审批任务的创建、查询和完成
 */
@Service
public class TaskService {
    
    @Resource
    private TaskRepository taskRepository;
    
    @Resource
    private ProcessEngine processEngine;
    
    @Resource
    private ProcessDefinitionService definitionService;
    
    /**
     * 创建审批任务
     */
    public void createTask(ProcessInstance instance, UserTask userTask) {
        Task task = new Task();
        task.setTaskId(IdGenerator.nextId());
        task.setInstanceId(instance.getInstanceId());
        task.setNodeId(userTask.getNodeId());
        task.setNodeName(userTask.getNodeName());
        task.setAssignee(userTask.getAssignee());
        task.setCandidateUsers(userTask.getCandidateUsers());
        task.setAssignmentType(userTask.getAssignmentType());
        task.setStatus(TaskStatus.PENDING);
        task.setCreateTime(System.currentTimeMillis());
        
        // 会签/或签：为每个候选人都创建任务
        if (userTask.getAssignmentType() == UserTask.TaskAssignmentType.COUNTERSIGN
            || userTask.getAssignmentType() == UserTask.TaskAssignmentType.OR_SIGN) {
            for (String candidate : userTask.getCandidateUsers()) {
                Task candidateTask = copyTask(task);
                candidateTask.setAssignee(candidate);
                taskRepository.save(candidateTask);
            }
        } else {
            taskRepository.save(task);
        }
    }
    
    /**
     * 完成任务（审批通过）
     * 
     * 算法说明：
     * 1. 校验任务状态
     * 2. 根据审批类型处理：
     *    - 单人审批：直接完成，流转到下一节点
     *    - 会签：所有候选人都完成后才流转
     *    - 或签：任一人完成即流转，其他任务自动取消
     * 3. 触发流程继续执行
     */
    public void completeTask(String taskId, String userId, String comment, 
            Map<String, Object> variables) {
        Task task = taskRepository.findById(taskId);
        if (task == null) {
            throw new ProcessException("Task not found: " + taskId);
        }
        if (task.getStatus() != TaskStatus.PENDING) {
            throw new ProcessException("Task is not pending: " + task.getStatus());
        }
        
        // 更新任务状态
        task.setStatus(TaskStatus.COMPLETED);
        task.setCompleteTime(System.currentTimeMillis());
        task.setComment(comment);
        taskRepository.save(task);
        
        // 合并流程变量
        ProcessInstance instance = instanceRepository.findById(task.getInstanceId());
        if (variables != null) {
            instance.getVariables().putAll(variables);
        }
        
        // 根据审批类型判断是否流转
        if (task.getAssignmentType() == UserTask.TaskAssignmentType.COUNTERSIGN) {
            // 会签：检查所有候选人是否都已完成
            List<Task> siblingTasks = taskRepository.findByInstanceIdAndNodeId(
                task.getInstanceId(), task.getNodeId());
            boolean allCompleted = siblingTasks.stream()
                .allMatch(t -> t.getStatus() == TaskStatus.COMPLETED);
            
            if (!allCompleted) {
                return;  // 等待其他人完成
            }
        } else if (task.getAssignmentType() == UserTask.TaskAssignmentType.OR_SIGN) {
            // 或签：取消其他任务
            List<Task> siblingTasks = taskRepository.findByInstanceIdAndNodeId(
                task.getInstanceId(), task.getNodeId());
            for (Task sibling : siblingTasks) {
                if (sibling.getStatus() == TaskStatus.PENDING) {
                    sibling.setStatus(TaskStatus.CANCELLED);
                    sibling.setCompleteTime(System.currentTimeMillis());
                    taskRepository.save(sibling);
                }
            }
        }
        
        // 流转到下一节点
        ProcessDefinition definition = definitionService.getDefinition(
            instance.getProcessId(), instance.getVersion());
        FlowNode currentNode = definition.getNodes().get(task.getNodeId());
        processEngine.executeNode(instance, definition, currentNode);
    }
    
    /**
     * 驳回
     * 驳回到指定节点，支持驳回到发起人、驳回到上一节点、驳回到指定节点
     */
    public void rejectTask(String taskId, String userId, String comment, 
            String rejectToNodeId) {
        Task task = taskRepository.findById(taskId);
        ProcessInstance instance = instanceRepository.findById(task.getInstanceId());
        
        // 更新任务状态为驳回
        task.setStatus(TaskStatus.REJECTED);
        task.setComment(comment);
        task.setCompleteTime(System.currentTimeMillis());
        taskRepository.save(task);
        
        // 驳回到指定节点
        if (rejectToNodeId != null) {
            ProcessDefinition definition = definitionService.getDefinition(
                instance.getProcessId(), instance.getVersion());
            FlowNode targetNode = definition.getNodes().get(rejectToNodeId);
            
            instance.setCurrentNodeId(rejectToNodeId);
            instanceRepository.save(instance);
            
            // 在目标节点重新创建任务
            if (targetNode instanceof UserTask) {
                createTask(instance, (UserTask) targetNode);
            }
        } else {
            // 没有指定节点，终止流程
            instance.setStatus(ProcessInstance.InstanceStatus.TERMINATED);
            instance.setEndTime(System.currentTimeMillis());
            instanceRepository.save(instance);
        }
    }
    
    /**
     * 加签
     * 在当前审批节点增加审批人
     */
    public void addSign(String taskId, String userId, List<String> newAssignees) {
        Task task = taskRepository.findById(taskId);
        
        for (String newAssignee : newAssignees) {
            Task newTask = copyTask(task);
            newTask.setTaskId(IdGenerator.nextId());
            newTask.setAssignee(newAssignee);
            newTask.setStatus(TaskStatus.PENDING);
            newTask.setCreateTime(System.currentTimeMillis());
            taskRepository.save(newTask);
        }
    }
    
    /**
     * 转办
     * 将任务转给其他人处理
     */
    public void transferTask(String taskId, String userId, String toUserId) {
        Task task = taskRepository.findById(taskId);
        task.setAssignee(toUserId);
        task.setTransferFrom(userId);
        task.setTransferTime(System.currentTimeMillis());
        taskRepository.save(task);
    }
}
```

## 七、事件驱动机制

### 7.1 事件通知

引擎通过事件回调机制将流程节点的开始和结束事件推送至业务系统。触发时机可以设置为节点开始、节点结束、任务负责人更换等情况。触发的动作可以是回调业务的Thrift服务、HTTP接口或发送MQ消息。

```java
/**
 * 事件通知服务
 * 将流程事件推送到业务系统
 * 
 * 设计模式：观察者模式
 * 业务系统注册为观察者，流程事件发生时通知观察者
 */
@Service
public class EventNotificationService {
    
    @Resource
    private List<EventListener> listeners;
    
    @Resource
    private RocketMQTemplate mqTemplate;
    
    /**
     * 触发事件
     */
    public void fireEvent(String instanceId, String nodeId, EventType eventType) {
        ProcessEvent event = new ProcessEvent();
        event.setEventId(IdGenerator.nextId());
        event.setInstanceId(instanceId);
        event.setNodeId(nodeId);
        event.setEventType(eventType);
        event.setTimestamp(System.currentTimeMillis());
        
        // 1. 同步通知注册的监听器
        for (EventListener listener : listeners) {
            try {
                listener.onEvent(event);
            } catch (Exception e) {
                log.error("Event listener failed", e);
            }
        }
        
        // 2. 异步发送MQ消息
        mqTemplate.asyncSend("process-event-topic", event, new SendCallback() {
            @Override
            public void onSuccess(SendResult result) {}
            @Override
            public void onException(Throwable e) {
                log.error("Event MQ send failed", e);
            }
        });
    }
}

 * 事件类型
 */
public enum EventType {
    PROCESS_START,    // 流程启动
    PROCESS_END,      // 流程结束
    NODE_START,       // 节点开始
    NODE_END,         // 节点结束
    TASK_CREATED,     // 任务创建
    TASK_COMPLETED,   // 任务完成
    TASK_REJECTED     // 任务驳回
}
```

### 8.2 容错处理

```java
/**
 * 引擎容错处理器
 * 对引擎接口调用进行容错包装
 * 
 * 最佳实践：增强对引擎接口的容错处理，保障业务系统稳定性
 */
@Component
public class EngineFaultToleranceHandler {
    
    @Resource
    private ProcessEngine processEngine;
    
    private static final int MAX_RETRY = 3;
    private static final long RETRY_INTERVAL = 1000;
    
    /**
     * 带容错的流程启动
     */
    public ProcessInstance startProcessWithRetry(String processId, 
            String businessKey, Map<String, Object> variables, String initiator) {
        Exception lastException = null;
        
        for (int i = 0; i < MAX_RETRY; i++) {
            try {
                return processEngine.startProcess(processId, businessKey, 
                    variables, initiator);
            } catch (Exception e) {
                lastException = e;
                log.warn("Process start failed, attempt {}/{}", i + 1, MAX_RETRY, e);
                try {
                    Thread.sleep(RETRY_INTERVAL);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }
        }
        
        // 重试失败，走降级逻辑
        log.error("Process start failed after {} retries", MAX_RETRY, lastException);
        throw new ProcessException("Process engine unavailable", lastException);
    }
}
```

### 8.3 防止无限循环

不要设计可以无限循环下去的流程，防止流程任务实例无限膨胀。如果一个流程的任务实例超过2000个，将造成大量数据的删除操作而产生大事务，可能造成数据库表不可用。

```java
/**
 * 流程循环检测器
 * 防止流程实例任务数无限增长
 */
@Service
public class ProcessLoopDetector {
    
    private static final int MAX_TASK_COUNT = 2000;
    
    /**
     * 检查流程实例的任务数是否超限
     */
    public void checkTaskCount(String instanceId) {
        long taskCount = taskRepository.countByInstanceId(instanceId);
        if (taskCount > MAX_TASK_COUNT) {
            throw new ProcessException(
                "Process instance task count exceeds limit: " + taskCount 
                + "/" + MAX_TASK_COUNT + ", possible infinite loop detected");
        }
    }
}
```

## 九、系统总结

审批流系统的核心设计包括以下方面。流程模型方面，遵循BPMN 2.0规范，支持用户任务、服务任务、排他网关、并行网关、定时事件等多种节点类型，流程定义使用JSON序列化存储，支持版本管理。流程引擎方面，采用状态机模式，创建流程实例等同于初始化状态机，完成任务节点等同于触发状态转换，节点执行根据类型走不同逻辑分支。网关方面，排他网关使用解释器模式对条件表达式求值选择路径，并行网关同时执行所有出边并在汇聚点等待所有分支到达。审批操作方面，支持审批通过、驳回、加签、会签、或签、转办等操作，会签需要所有候选人完成后才流转，或签任一人完成即流转并取消其他任务。事件驱动方面，使用观察者模式通过事件回调和MQ消息将流程事件推送到业务系统，支持节点开始、结束、任务创建、完成等事件。最佳实践方面，关联关系保存在业务系统本地以减少引擎查询，接口调用进行容错处理和重试机制，防止无限循环导致任务实例膨胀。

## 十、全链路实战案例

前面章节从模型、引擎、网关、审批操作、事件机制等维度自顶向下地拆解了审批流系统。本章从相反的方向出发，选取三个典型的端到端场景，把前面分散的组件串联起来，展示一次完整审批请求在系统内部是如何流转的。每个案例都给出可运行的Java代码，并重点补齐生产环境不可或缺的四类横切关注点：异常处理、日志记录、幂等控制和可观测性。

### 10.1 案例一：请假审批全链路

请假审批是最经典的审批场景，链路为：员工提交申请 -> 逐级审批（直属主管 -> 部门总监，金额/天数触发不同层级）-> 审批通过或驳回 -> 通知相关人 -> 回调业务系统更新考勤。本案例贯穿"发起、流转、决策、通知、回调"五个阶段，并演示如何用幂等键防止重复提交、用状态机保证驳回一致性、用回调补偿保证最终一致。

#### 10.1.1 业务实体与流程定义

请假单是业务侧的核心数据，流程实例通过`businessKey`与请假单关联。流程图为：开始 -> 直属主管审批 -> 排他网关（请假天数是否大于3天）-> 若大于3天则部门总监审批 -> 结束；网关默认分支直接到结束。

```java
/**
```

#### 10.1.2 阶段一：提交申请（幂等控制）

提交是整条链路的入口，也是重复请求最集中的地方（用户连点、前端重试、网关重发）。这里采用"业务幂等键 + 唯一索引 + 分布式锁"三重保障：幂等键由前端生成或由`申请人+起止日期+提交时间窗`派生，落库时依赖唯一索引兜底，分布式锁避免并发穿透。

```java
/**
 * 请假申请服务
 * 负责请假单的提交、与流程引擎的对接、以及全链路的幂等控制
 */
@Service
@Slf4j
public class LeaveApplicationService {

    @Resource
    private LeaveApplicationRepository leaveRepository;

    @Resource
    private EngineFaultToleranceHandler engineHandler;

    @Resource
    private BusinessProcessLinkService linkService;

    @Resource
    private RedissonClient redissonClient;

    private static final String LEAVE_PROCESS_ID = "leave_approval_process";
    private static final String IDEMPOTENT_KEY_PREFIX = "leave:submit:idem:";
    private static final String SUBMIT_LOCK_PREFIX = "leave:submit:lock:";

    /**
     * 提交请假申请（全链路入口）
     *
     * 幂等控制：
     * 1. 分布式锁串行化同一幂等键的并发请求
     * 2. 幂等表记录已处理的 idempotentKey，命中则直接返回历史结果
     * 3. 请假单表 (applicantId, idempotentKey) 建唯一索引兜底
     *
     * @param application    请假单
     * @param idempotentKey  幂等键，客户端生成，保证同一次提交唯一
     */
    public LeaveApplication submit(LeaveApplication application, String idempotentKey) {
        String lockKey = SUBMIT_LOCK_PREFIX + idempotentKey;
        RLock lock = redissonClient.getLock(lockKey);
        boolean locked = false;
        try {
            // 1. 抢占分布式锁，最多等待 2s，持锁 10s 自动释放
            locked = lock.tryLock(2, 10, TimeUnit.SECONDS);
            if (!locked) {
                log.warn("[请假提交] 获取幂等锁失败, idempotentKey={}, applicant={}",
                    idempotentKey, application.getApplicantId());
                throw new ProcessException("提交过于频繁，请稍后重试");
            }

            // 2. 幂等校验：命中历史记录直接返回，避免重复发起流程
            LeaveApplication existing = leaveRepository.findByIdempotentKey(idempotentKey);
            if (existing != null) {
                log.info("[请假提交] 幂等命中, 返回已有单据, leaveId={}, idempotentKey={}",
                    existing.getLeaveId(), idempotentKey);
                return existing;
            }

            // 3. 参数校验
            validate(application);

            // 4. 落库请假单（状态=SUBMITTED），依赖唯一索引兜底幂等
            application.setLeaveId(IdGenerator.nextId());
            application.setStatus(LeaveApplication.LeaveStatus.SUBMITTED);
            application.setSubmitTime(System.currentTimeMillis());
            try {
                leaveRepository.saveWithIdempotentKey(application, idempotentKey);
            } catch (DuplicateKeyException e) {
                // 并发穿透兜底：唯一索引冲突，说明已有请求成功落库
                log.warn("[请假提交] 唯一索引冲突, 走幂等返回, idempotentKey={}", idempotentKey, e);
                return leaveRepository.findByIdempotentKey(idempotentKey);
            }

            // 5. 组装流程变量并启动流程实例（带重试容错）
            Map<String, Object> variables = new HashMap<>();
            variables.put("leaveDays", application.getLeaveDays());
            variables.put("leaveType", application.getLeaveType().name());
            variables.put("applicantId", application.getApplicantId());
            variables.put("department", application.getDepartment());

            ProcessInstance instance = engineHandler.startProcessWithRetry(
                LEAVE_PROCESS_ID, application.getLeaveId(), variables,
                application.getApplicantId());

            // 6. 保存业务与流程的关联关系（最佳实践 8.1）
            application.setInstanceId(instance.getInstanceId());
            leaveRepository.updateInstanceId(application.getLeaveId(), instance.getInstanceId());
            linkService.saveLink(application.getLeaveId(), instance.getInstanceId());

            log.info("[请假提交] 成功, leaveId={}, instanceId={}, applicant={}, days={}",
                application.getLeaveId(), instance.getInstanceId(),
                application.getApplicantId(), application.getLeaveDays());

            return application;

        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            log.error("[请假提交] 线程中断, idempotentKey={}", idempotentKey, e);
            throw new ProcessException("提交被中断", e);
        } catch (ProcessException e) {
            throw e;
        } catch (Exception e) {
            log.error("[请假提交] 未知异常, idempotentKey={}, applicant={}",
                idempotentKey, application.getApplicantId(), e);
            throw new ProcessException("提交失败，请稍后重试", e);
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    private void validate(LeaveApplication application) {
        if (application.getApplicantId() == null) {
            throw new ProcessException("申请人不能为空");
        }
        if (application.getLeaveDays() <= 0) {
            throw new ProcessException("请假天数必须大于0");
        }
        if (application.getStartDate() == null || application.getEndDate() == null
            || application.getStartDate().after(application.getEndDate())) {
            throw new ProcessException("请假起止日期不合法");
        }
    }
}
```

#### 10.1.3 阶段二至四：逐级审批、决策、通知（回调驱动）

流程启动后，引擎在"直属主管审批"节点创建用户任务。审批人调用`approve`/`reject`，任务完成触发引擎流转；排他网关根据`leaveDays`决定是否进入"部门总监审批"。业务系统通过实现`EventListener`（观察者模式，见7.1）监听任务事件，同步更新请假单冗余状态并发出通知。

```java
/**
 * 请假审批业务监听器
 * 监听引擎事件，回写业务状态、发送通知
 * 注册进 EventNotificationService.listeners
 */
@Component
@Slf4j
public class LeaveApprovalEventListener implements EventListener {

    @Resource
    private LeaveApplicationRepository leaveRepository;

    @Resource
    private TaskService taskService;

    @Resource
    private NotificationService notificationService;

    @Resource
    private ProcessInstanceRepository instanceRepository;

    @Override
    public void onEvent(ProcessEvent event) {
        // 只关心请假流程的事件，其它流程忽略
        ProcessInstance instance = instanceRepository.findById(event.getInstanceId());
        if (instance == null || !"leave_approval_process".equals(instance.getProcessId())) {
            return;
        }
        String leaveId = instance.getBusinessKey();

        try {
            switch (event.getEventType()) {
                case TASK_CREATED:
                    handleTaskCreated(leaveId, instance, event);
                    break;
                case TASK_COMPLETED:
                    handleTaskCompleted(leaveId, event);
                    break;
                case TASK_REJECTED:
                    handleTaskRejected(leaveId, event);
                    break;
                case PROCESS_END:
                    handleProcessEnd(leaveId, instance);
                    break;
                default:
                    break;
            }
        } catch (Exception e) {
            // 监听器异常必须吞掉，不能影响引擎主流程（见 EventNotificationService 的 try-catch）
            // 但要记录并投递到补偿队列，保证通知/回写最终一致
            log.error("[请假事件] 处理失败, leaveId={}, eventType={}, eventId={}",
                leaveId, event.getEventType(), event.getEventId(), e);
            notificationService.enqueueRetry(event);
        }
    }

    /** 新任务创建：更新当前审批人并通知待办 */
    private void handleTaskCreated(String leaveId, ProcessInstance instance, ProcessEvent event) {
        Task task = taskService.findCurrentTaskByInstanceId(instance.getInstanceId());
        if (task == null) {
            log.warn("[请假事件] 任务创建事件但未找到任务, leaveId={}", leaveId);
            return;
        }
        leaveRepository.updateCurrentApprover(leaveId, task.getAssignee());
        notificationService.sendTodo(task.getAssignee(),
            String.format("您有一条请假审批待处理，单号：%s", leaveId));
        log.info("[请假事件] 待办已通知, leaveId={}, approver={}, node={}",
            leaveId, task.getAssignee(), task.getNodeName());
    }

    private void handleTaskCompleted(String leaveId, ProcessEvent event) {
        log.info("[请假事件] 一级审批通过, leaveId={}, node={}", leaveId, event.getNodeId());
    }

    private void handleTaskRejected(String leaveId, ProcessEvent event) {
        LeaveApplication app = leaveRepository.findById(leaveId);
        app.setStatus(LeaveApplication.LeaveStatus.REJECTED);
        app.setFinishTime(System.currentTimeMillis());
        leaveRepository.save(app);
        notificationService.sendMessage(app.getApplicantId(),
            String.format("很抱歉，您的请假申请(单号:%s)已被驳回", leaveId));
        log.info("[请假事件] 已驳回并通知申请人, leaveId={}", leaveId);
    }

    /** 流程结束：终态通过，触发回调业务系统 */
    private void handleProcessEnd(String leaveId, ProcessInstance instance) {
        LeaveApplication app = leaveRepository.findById(leaveId);
        if (app.getStatus() == LeaveApplication.LeaveStatus.SUBMITTED) {
            app.setStatus(LeaveApplication.LeaveStatus.APPROVED);
            app.setFinishTime(System.currentTimeMillis());
            leaveRepository.save(app);
            notificationService.sendMessage(app.getApplicantId(),
                String.format("您的请假申请(单号:%s)已审批通过", leaveId));
            log.info("[请假事件] 审批通过, leaveId={}", leaveId);
        }
    }
}
```

审批动作本身也需要幂等，防止审批人重复点击"同意"导致流程被推进两次。这里用任务状态机 + 版本乐观锁保证一个任务只能被完成一次。

```java
/**
 * 请假审批动作服务
 * 封装审批人的通过/驳回操作，保证审批动作幂等
 */
@Service
@Slf4j
public class LeaveApproveService {

    @Resource
    private TaskRepository taskRepository;

    @Resource
    private TaskService taskService;

    /**
     * 审批通过
     * 幂等：基于任务状态 + 乐观锁，重复调用第二次即命中已完成态直接返回
     */
    @Transactional(rollbackFor = Exception.class)
    public void approve(String taskId, String approverId, String comment) {
        Task task = taskRepository.findById(taskId);
        if (task == null) {
            throw new ProcessException("任务不存在: " + taskId);
        }
        // 幂等：任务已完成，重复审批直接返回，不再推进流程
        if (task.getStatus() == TaskStatus.COMPLETED) {
            log.info("[请假审批] 幂等命中，任务已完成, taskId={}, approver={}", taskId, approverId);
            return;
        }
        if (task.getStatus() != TaskStatus.PENDING) {
            throw new ProcessException("任务状态不可审批: " + task.getStatus());
        }
        // 权限校验
        if (!isAuthorized(task, approverId)) {
            log.warn("[请假审批] 无审批权限, taskId={}, approver={}, assignee={}",
                taskId, approverId, task.getAssignee());
            throw new ProcessException("您无权审批该任务");
        }

        Map<String, Object> vars = new HashMap<>();
        vars.put("lastApprover", approverId);
        vars.put("lastApproveTime", System.currentTimeMillis());

        try {
            // 交由 TaskService 完成任务，内部会推进引擎流转（触发排他网关判断天数）
            taskService.completeTask(taskId, approverId, comment, vars);
            log.info("[请假审批] 审批通过, taskId={}, approver={}", taskId, approverId);
        } catch (OptimisticLockException e) {
            // 并发审批：另一线程已完成，视作幂等成功
            log.warn("[请假审批] 乐观锁冲突, 视为幂等成功, taskId={}", taskId, e);
        }
    }

    /**
     * 审批驳回，驳回到发起人（rejectToNodeId=null 时终止流程）
     */
    @Transactional(rollbackFor = Exception.class)
    public void reject(String taskId, String approverId, String comment, String rejectToNodeId) {
        Task task = taskRepository.findById(taskId);
        if (task == null) {
            throw new ProcessException("任务不存在: " + taskId);
        }
        if (task.getStatus() == TaskStatus.REJECTED) {
            log.info("[请假审批] 幂等命中，任务已驳回, taskId={}", taskId);
            return;
        }
        if (task.getStatus() != TaskStatus.PENDING) {
            throw new ProcessException("任务状态不可驳回: " + task.getStatus());
        }
        taskService.rejectTask(taskId, approverId, comment, rejectToNodeId);
        log.info("[请假审批] 已驳回, taskId={}, approver={}, rejectTo={}",
            taskId, approverId, rejectToNodeId);
    }

    private boolean isAuthorized(Task task, String approverId) {
        if (approverId.equals(task.getAssignee())) {
            return true;
        }
        return task.getCandidateUsers() != null
            && task.getCandidateUsers().contains(approverId);
    }
}
```

#### 10.1.4 阶段五：回调业务系统（可靠回调 + 补偿）

流程走到终态后，除了同步监听器回写状态外，通常还需要回调下游业务系统（如考勤系统扣减假期额度）。跨系统回调必须保证可靠：本地事务消息 + 回调幂等键 + 定时补偿。

```java
/**
 * 请假回调服务
 * 流程终态后回调考勤等下游系统，保证可靠投递与幂等消费
 */
@Service
@Slf4j
public class LeaveCallbackService {

    @Resource
    private AttendanceClient attendanceClient;   // 下游考勤系统 RPC

    @Resource
    private CallbackLogRepository callbackLogRepository;

    /**
     * 回调考勤系统扣减假期额度
     * 幂等：以 leaveId 为回调幂等键，callback_log 唯一索引防重
     * 可靠：失败写入 FAILED，由定时任务扫描重投
     */
    public void callbackAttendance(LeaveApplication app) {
        String callbackKey = "attendance_deduct:" + app.getLeaveId();

        // 幂等：已成功回调过则跳过
        CallbackLog existing = callbackLogRepository.findByCallbackKey(callbackKey);
        if (existing != null && existing.getStatus() == CallbackStatus.SUCCESS) {
            log.info("[请假回调] 幂等命中，已回调成功, leaveId={}", app.getLeaveId());
            return;
        }

        CallbackLog callbackLog = existing != null ? existing : new CallbackLog();
        callbackLog.setCallbackKey(callbackKey);
        callbackLog.setBusinessId(app.getLeaveId());
        callbackLog.setStatus(CallbackStatus.PROCESSING);
        callbackLog.setUpdateTime(System.currentTimeMillis());
        callbackLogRepository.upsert(callbackLog);

        try {
            AttendanceDeductRequest req = new AttendanceDeductRequest();
            req.setRequestId(callbackKey);           // 下游据此幂等
            req.setUserId(app.getApplicantId());
            req.setLeaveType(app.getLeaveType().name());
            req.setDays(app.getLeaveDays());
            req.setStartDate(app.getStartDate());

            AttendanceDeductResponse resp = attendanceClient.deduct(req);
            if (resp.isSuccess()) {
                callbackLog.setStatus(CallbackStatus.SUCCESS);
                callbackLogRepository.upsert(callbackLog);
                log.info("[请假回调] 考勤扣减成功, leaveId={}, days={}",
                    app.getLeaveId(), app.getLeaveDays());
            } else {
                markFailed(callbackLog, resp.getMessage());
            }
        } catch (Exception e) {
            markFailed(callbackLog, e.getMessage());
            log.error("[请假回调] 考勤扣减异常, leaveId={}", app.getLeaveId(), e);
        }
    }

    private void markFailed(CallbackLog callbackLog, String reason) {
        callbackLog.setStatus(CallbackStatus.FAILED);
        callbackLog.setFailReason(reason);
        callbackLog.setRetryCount(callbackLog.getRetryCount() + 1);
        callbackLog.setUpdateTime(System.currentTimeMillis());
        callbackLogRepository.upsert(callbackLog);
    }

    /**
     * 定时补偿：扫描 FAILED 且未超最大重试次数的回调，重新投递
     * 由 XXL-Job 每分钟触发
     */
    public void compensate() {
        List<CallbackLog> failedLogs = callbackLogRepository.findFailedForRetry(3, 100);
        for (CallbackLog log2 : failedLogs) {
            LeaveApplication app = leaveRepository.findById(log2.getBusinessId());
            if (app != null) {
                log.info("[请假回调补偿] 重投, leaveId={}, retryCount={}",
                    log2.getBusinessId(), log2.getRetryCount());
                callbackAttendance(app);
            }
        }
    }

    @Resource
    private LeaveApplicationRepository leaveRepository;

    public enum CallbackStatus {
        PROCESSING, SUCCESS, FAILED
    }
}
```

#### 10.1.5 全链路时序小结

请假审批全链路的关键控制点如下：提交阶段用分布式锁 + 幂等表 + 唯一索引三重防重；发起阶段用容错重试保证流程可靠创建，并本地保存关联关系；审批阶段用任务状态机 + 乐观锁保证审批动作幂等；决策阶段由排他网关按天数动态选择审批层级；通知阶段由观察者监听器异步回写并投递补偿队列；回调阶段用本地回调日志 + 幂等键 + 定时补偿保证跨系统最终一致。任何一个阶段失败都不会污染其它阶段的状态，异常均被就地捕获并转化为可补偿的记录。

### 10.2 案例二：会签/或签全链路

会签（所有人都需同意）与或签（任一人同意即可）是多人审批的两种核心投票规则。本案例演示：并行会签的任务分裂与汇聚、串行会签的顺序流转、或签的抢占与其余任务取消、以及超时自动通过的定时兜底。难点在于多任务并发完成时的计票一致性——必须用锁或原子计数避免"最后一票"的竞态。

#### 10.2.1 投票规则模型

```java
/**
 * 多人审批投票配置
 * 挂在 UserTask 上，描述会签/或签的具体规则
 */
@Data
public class MultiInstanceConfig {

    private CollectType collectType;        // 计票方式
    private ExecutionMode executionMode;    // 并行 or 串行
    private int passRatio;                   // 会签通过比例（百分比），如 100=全票，50=半数
    private long timeoutMillis;              // 超时时长，0 表示不超时
    private TimeoutStrategy timeoutStrategy; // 超时策略
    private List<String> approvers;          // 审批人有序列表（串行按此顺序）

    public enum CollectType {
        COUNTERSIGN,   // 会签：按 passRatio 计票
        OR_SIGN        // 或签：任一通过即通过
    }

    public enum ExecutionMode {
        PARALLEL,      // 并行：一次性给所有人创建任务
        SEQUENTIAL     // 串行：一个接一个
    }

    public enum TimeoutStrategy {
        AUTO_PASS,     // 超时自动通过
        AUTO_REJECT,   // 超时自动驳回
        REMIND         // 仅催办
    }
}
```

#### 10.2.2 会签/或签计票核心（并发安全）

多人并行审批时，多个审批人可能几乎同时提交，导致对"是否达到通过阈值"的判断出现竞态。这里以实例节点为粒度加分布式锁，保证计票与流转的原子性；同时用幂等键防止同一审批人重复投票。

```java
/**
 * 多人审批投票服务
 * 处理会签/或签的投票、计票、汇聚与超时
 */
@Service
@Slf4j
public class MultiInstanceVoteService {

    @Resource
    private TaskRepository taskRepository;

    @Resource
    private ProcessInstanceRepository instanceRepository;

    @Resource
    private ProcessDefinitionService definitionService;

    @Resource
    private ProcessEngine processEngine;

    @Resource
    private RedissonClient redissonClient;

    private static final String VOTE_LOCK_PREFIX = "vote:lock:";

    /**
     * 投票（通过/反对）
     *
     * 并发安全：以 instanceId+nodeId 为锁粒度，计票与流转在锁内完成
     * 幂等：任务终态直接返回
     *
     * @param agree true=同意, false=反对
     */
    public void vote(String taskId, String userId, boolean agree, String comment) {
        Task task = taskRepository.findById(taskId);
        if (task == null) {
            throw new ProcessException("任务不存在: " + taskId);
        }
        // 幂等：任务已终态，重复投票直接返回
        if (task.getStatus() != TaskStatus.PENDING) {
            log.info("[多人审批] 幂等命中，任务非待办, taskId={}, status={}", taskId, task.getStatus());
            return;
        }

        String lockKey = VOTE_LOCK_PREFIX + task.getInstanceId() + ":" + task.getNodeId();
        RLock lock = redissonClient.getLock(lockKey);
        boolean locked = false;
        try {
            locked = lock.tryLock(3, 10, TimeUnit.SECONDS);
            if (!locked) {
                throw new ProcessException("投票繁忙，请重试");
            }

            // 锁内重读，避免脏读
            task = taskRepository.findById(taskId);
            if (task.getStatus() != TaskStatus.PENDING) {
                log.info("[多人审批] 锁内幂等命中, taskId={}", taskId);
                return;
            }

            // 记录本人投票
            task.setStatus(agree ? TaskStatus.COMPLETED : TaskStatus.REJECTED);
            task.setComment(comment);
            task.setCompleteTime(System.currentTimeMillis());
            taskRepository.save(task);

            ProcessInstance instance = instanceRepository.findById(task.getInstanceId());
            MultiInstanceConfig config = getConfig(instance, task.getNodeId());

            List<Task> siblings = taskRepository.findByInstanceIdAndNodeId(
                task.getInstanceId(), task.getNodeId());

            log.info("[多人审批] 收到投票, taskId={}, user={}, agree={}, node={}, type={}",
                taskId, userId, agree, task.getNodeId(), config.getCollectType());

            if (config.getCollectType() == MultiInstanceConfig.CollectType.OR_SIGN) {
                handleOrSign(instance, task, siblings, agree);
            } else {
                handleCountersign(instance, task, siblings, config);
            }

            // 串行会签：本人通过后，激活下一个审批人的任务
            if (config.getExecutionMode() == MultiInstanceConfig.ExecutionMode.SEQUENTIAL
                && agree && !isNodeFinished(instance, task.getNodeId())) {
                activateNextSequential(instance, task.getNodeId(), config, siblings);
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new ProcessException("投票被中断", e);
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    /** 或签：任一同意即整体通过，取消其余待办；全部反对则驳回 */
    private void handleOrSign(ProcessInstance instance, Task current,
            List<Task> siblings, boolean agree) {
        if (agree) {
            for (Task s : siblings) {
                if (s.getStatus() == TaskStatus.PENDING) {
                    s.setStatus(TaskStatus.CANCELLED);
                    s.setCompleteTime(System.currentTimeMillis());
                    taskRepository.save(s);
                }
            }
            log.info("[多人审批] 或签通过, instanceId={}, node={}, 通过人={}",
                instance.getInstanceId(), current.getNodeId(), current.getAssignee());
            advance(instance, current.getNodeId());
        } else {
            boolean allReject = siblings.stream()
                .noneMatch(s -> s.getStatus() == TaskStatus.PENDING
                    || s.getStatus() == TaskStatus.COMPLETED);
            if (allReject) {
                log.info("[多人审批] 或签全部反对，驳回, instanceId={}", instance.getInstanceId());
                reject(instance, current.getNodeId());
            }
        }
    }

    /** 会签：按通过比例计票，达标则通过，不可能达标则提前驳回 */
    private void handleCountersign(ProcessInstance instance, Task current,
            List<Task> siblings, MultiInstanceConfig config) {
        long total = siblings.size();
        long agreeCount = siblings.stream()
            .filter(s -> s.getStatus() == TaskStatus.COMPLETED).count();
        long rejectCount = siblings.stream()
            .filter(s -> s.getStatus() == TaskStatus.REJECTED).count();

        long needAgree = (long) Math.ceil(total * config.getPassRatio() / 100.0);

        log.info("[多人审批] 会签计票, node={}, agree={}/{}, need={}, reject={}",
            current.getNodeId(), agreeCount, total, needAgree, rejectCount);

        if (agreeCount >= needAgree) {
            // 达到通过阈值，取消剩余待办并流转
            cancelPending(siblings);
            log.info("[多人审批] 会签通过, instanceId={}, node={}",
                instance.getInstanceId(), current.getNodeId());
            advance(instance, current.getNodeId());
        } else if (total - rejectCount < needAgree) {
            // 即使剩余全部同意也无法达标，提前驳回
            cancelPending(siblings);
            log.info("[多人审批] 会签不可能达标，提前驳回, instanceId={}", instance.getInstanceId());
            reject(instance, current.getNodeId());
        }
        // 否则继续等待其余人投票
    }

    private void cancelPending(List<Task> siblings) {
        for (Task s : siblings) {
            if (s.getStatus() == TaskStatus.PENDING) {
                s.setStatus(TaskStatus.CANCELLED);
                s.setCompleteTime(System.currentTimeMillis());
                taskRepository.save(s);
            }
        }
    }

    private boolean isNodeFinished(ProcessInstance instance, String nodeId) {
        ProcessInstance latest = instanceRepository.findById(instance.getInstanceId());
        return !nodeId.equals(latest.getCurrentNodeId());
    }

    /** 串行会签：激活列表中下一个尚未创建任务的审批人 */
    private void activateNextSequential(ProcessInstance instance, String nodeId,
            MultiInstanceConfig config, List<Task> siblings) {
        Set<String> created = siblings.stream()
            .map(Task::getAssignee).collect(Collectors.toSet());
        for (String approver : config.getApprovers()) {
            if (!created.contains(approver)) {
                Task next = new Task();
                next.setTaskId(IdGenerator.nextId());
                next.setInstanceId(instance.getInstanceId());
                next.setNodeId(nodeId);
                next.setAssignee(approver);
                next.setStatus(TaskStatus.PENDING);
                next.setCreateTime(System.currentTimeMillis());
                taskRepository.save(next);
                log.info("[多人审批] 串行会签激活下一审批人, node={}, next={}", nodeId, approver);
                return;
            }
        }
    }

    private void advance(ProcessInstance instance, String nodeId) {
        ProcessDefinition def = definitionService.getDefinition(
            instance.getProcessId(), instance.getVersion());
        FlowNode node = def.getNodes().get(nodeId);
        processEngine.executeNode(instance, def, node);
    }

    private void reject(ProcessInstance instance, String nodeId) {
        instance.setStatus(ProcessInstance.InstanceStatus.TERMINATED);
        instance.setEndTime(System.currentTimeMillis());
        instanceRepository.save(instance);
    }

    private MultiInstanceConfig getConfig(ProcessInstance instance, String nodeId) {
        ProcessDefinition def = definitionService.getDefinition(
            instance.getProcessId(), instance.getVersion());
        UserTask task = (UserTask) def.getNodes().get(nodeId);
        return (MultiInstanceConfig) task.getClass().getClassLoader() != null
            ? buildConfigFromTask(task) : null;
    }

    private MultiInstanceConfig buildConfigFromTask(UserTask task) {
        MultiInstanceConfig cfg = new MultiInstanceConfig();
        cfg.setApprovers(task.getCandidateUsers());
        cfg.setCollectType(task.getAssignmentType() == UserTask.TaskAssignmentType.OR_SIGN
            ? MultiInstanceConfig.CollectType.OR_SIGN
            : MultiInstanceConfig.CollectType.COUNTERSIGN);
        cfg.setExecutionMode(MultiInstanceConfig.ExecutionMode.PARALLEL);
        cfg.setPassRatio(100);
        return cfg;
    }
}
```

#### 10.2.3 超时自动通过（定时兜底）

多人审批常配置超时策略，防止某个审批人长期不处理阻塞流程。通过扫描待办任务的创建时间，对超时任务按策略自动通过/驳回/催办。定时任务同样要幂等，避免重复处理。

```java
/**
 * 审批超时处理器
 * 扫描超时的多人审批任务，按策略自动通过/驳回/催办
 * 由 XXL-Job 每 30s 触发
 */
@Service
@Slf4j
public class ApprovalTimeoutHandler {

    @Resource
    private TaskRepository taskRepository;

    @Resource
    private MultiInstanceVoteService voteService;

    @Resource
    private ProcessInstanceRepository instanceRepository;

    @Resource
    private ProcessDefinitionService definitionService;

    @Resource
    private NotificationService notificationService;

    /**
     * 扫描并处理超时任务
     */
    public void handleTimeoutTasks() {
        long now = System.currentTimeMillis();
        List<Task> pendingTasks = taskRepository.findAllPending(500);

        for (Task task : pendingTasks) {
            try {
                MultiInstanceConfig config = resolveConfig(task);
                if (config == null || config.getTimeoutMillis() <= 0) {
                    continue;
                }
                long deadline = task.getCreateTime() + config.getTimeoutMillis();
                if (now < deadline) {
                    continue;
                }

                switch (config.getTimeoutStrategy()) {
                    case AUTO_PASS:
                        log.info("[审批超时] 自动通过, taskId={}, assignee={}",
                            task.getTaskId(), task.getAssignee());
                        voteService.vote(task.getTaskId(), "SYSTEM_AUTO", true,
                            "超时系统自动通过");
                        break;
                    case AUTO_REJECT:
                        log.info("[审批超时] 自动驳回, taskId={}", task.getTaskId());
                        voteService.vote(task.getTaskId(), "SYSTEM_AUTO", false,
                            "超时系统自动驳回");
                        break;
                    case REMIND:
                        notificationService.sendTodo(task.getAssignee(),
                            "您有一条审批已超时，请尽快处理，任务号：" + task.getTaskId());
                        log.info("[审批超时] 已催办, taskId={}", task.getTaskId());
                        break;
                    default:
                        break;
                }
            } catch (Exception e) {
                // 单个任务失败不影响其余任务，记录后继续
                log.error("[审批超时] 处理失败, taskId={}", task.getTaskId(), e);
            }
        }
    }

    private MultiInstanceConfig resolveConfig(Task task) {
        ProcessInstance instance = instanceRepository.findById(task.getInstanceId());
        if (instance == null
            || instance.getStatus() != ProcessInstance.InstanceStatus.RUNNING) {
            return null;
        }
        ProcessDefinition def = definitionService.getDefinition(
            instance.getProcessId(), instance.getVersion());
        FlowNode node = def.getNodes().get(task.getNodeId());
        if (!(node instanceof UserTask)) {
            return null;
        }
        UserTask ut = (UserTask) node;
        if (ut.getAssignmentType() != UserTask.TaskAssignmentType.COUNTERSIGN
            && ut.getAssignmentType() != UserTask.TaskAssignmentType.OR_SIGN) {
            return null;
        }
        MultiInstanceConfig cfg = new MultiInstanceConfig();
        cfg.setCollectType(ut.getAssignmentType() == UserTask.TaskAssignmentType.OR_SIGN
            ? MultiInstanceConfig.CollectType.OR_SIGN
            : MultiInstanceConfig.CollectType.COUNTERSIGN);
        cfg.setTimeoutMillis(24 * 3600 * 1000L);   // 示例：24 小时超时
        cfg.setTimeoutStrategy(MultiInstanceConfig.TimeoutStrategy.AUTO_PASS);
        return cfg;
    }
}
```

#### 10.2.4 会签/或签要点小结

多人审批的核心在于"计票一致性"与"超时兜底"。并行模式下一次性为所有审批人创建任务，靠节点级分布式锁串行化计票；串行模式下每完成一票再激活下一人。或签遵循"一票通过、全票反对才驳回"，会签按 passRatio 计票并支持"提前驳回"优化（剩余票数不可能达标时立即结束）。超时策略由定时任务兜底，复用投票入口从而天然幂等——即便定时任务与人工审批并发触发，节点锁 + 任务终态判断也能保证只生效一次。

### 10.3 案例三：审批流程动态配置全链路

审批流系统的核心价值在于"流程可配置、可热更新而无需改代码"。本案例演示完整的流程生命周期：BPMN 流程定义 -> 校验 -> 部署 -> 版本管理 -> 灰度/热更新 -> 运行中实例的兼容。难点在于热更新时"存量实例走旧版、新发起走新版"的版本隔离，以及部署的幂等与回滚。

#### 10.3.1 部署与版本模型

#### 10.3.2 部署全链路：校验 -> 版本递增 -> 原子切换

```java
/**
 * 流程定义部署服务
 * 负责 BPMN 解析校验、版本管理、部署与热更新
 */
@Service
@Slf4j
public class ProcessDeployService {

    @Resource
    private ProcessDeploymentRepository deploymentRepository;

    @Resource
    private ProcessDefinitionRepository definitionRepository;

    @Resource
    private BpmnParser bpmnParser;

    @Resource
    private ProcessDefinitionCache definitionCache;

    @Resource
    private RedissonClient redissonClient;

    private static final String DEPLOY_LOCK_PREFIX = "process:deploy:lock:";

    /**
     * 部署流程（全链路入口）
     *
     * 步骤：
     * 1. 分布式锁串行化同一 processKey 的部署
     * 2. 解析并校验 BPMN（结构合法性、连通性、无死循环）
     * 3. 幂等：BPMN 内容哈希未变则直接返回当前版本
     * 4. 版本号递增，落库新版本流程定义
     * 5. 原子切换 latest 标记，刷新缓存（热更新生效）
     *
     * @param idempotentKey 部署幂等键，可由内容哈希派生
     */
    public ProcessDeployment deploy(String processKey, String bpmnXml,
            String deployBy, String changeLog, String idempotentKey) {
        String lockKey = DEPLOY_LOCK_PREFIX + processKey;
        RLock lock = redissonClient.getLock(lockKey);
        boolean locked = false;
        try {
            locked = lock.tryLock(5, 30, TimeUnit.SECONDS);
            if (!locked) {
                throw new ProcessException("部署繁忙，请稍后重试: " + processKey);
            }

            // 1. 解析并校验 BPMN
            ProcessDefinition definition;
            try {
                definition = bpmnParser.parse(bpmnXml);
            } catch (Exception e) {
                log.error("[流程部署] BPMN 解析失败, processKey={}", processKey, e);
                throw new ProcessException("BPMN 格式错误: " + e.getMessage(), e);
            }
            validateDefinition(definition);

            // 2. 幂等：内容哈希与当前生效版本一致则跳过
            String contentHash = DigestUtils.md5Hex(bpmnXml);
            ProcessDeployment latest = deploymentRepository.findLatest(processKey);
            if (latest != null && contentHash.equals(DigestUtils.md5Hex(latest.getBpmnXml()))) {
                log.info("[流程部署] 内容未变化，幂等返回当前版本, processKey={}, version={}",
                    processKey, latest.getVersion());
                return latest;
            }

            // 3. 版本号递增
            int newVersion = latest == null ? 1 : latest.getVersion() + 1;
            String processId = processKey + ":" + newVersion;
            definition.setProcessId(processId);
            definition.setVersion(String.valueOf(newVersion));
            definition.setStatus(ProcessDefinition.ProcessStatus.DEPLOYED);

            // 4. 落库（新版本流程定义 + 部署记录），事务内完成
            ProcessDeployment deployment = new ProcessDeployment();
            deployment.setDeploymentId(IdGenerator.nextId());
            deployment.setProcessKey(processKey);
            deployment.setProcessId(processId);
            deployment.setVersion(newVersion);
            deployment.setBpmnXml(bpmnXml);
            deployment.setDeployStatus("DEPLOYED");
            deployment.setDeployBy(deployBy);
            deployment.setDeployTime(System.currentTimeMillis());
            deployment.setChangeLog(changeLog);

            atomicSwitch(definition, deployment, latest);

            // 5. 刷新缓存，热更新对新发起实例立即生效
            definitionCache.evict(processKey);
            definitionCache.put(processId, definition);

            log.info("[流程部署] 部署成功, processKey={}, version={}, deployBy={}, changeLog={}",
                processKey, newVersion, deployBy, changeLog);
            return deployment;

        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new ProcessException("部署被中断", e);
        } catch (ProcessException e) {
            throw e;
        } catch (Exception e) {
            log.error("[流程部署] 未知异常, processKey={}", processKey, e);
            throw new ProcessException("部署失败: " + e.getMessage(), e);
        } finally {
            if (locked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    /**
     * 原子切换生效版本：老版本 latest 置 false，新版本置 true
     * 关键：存量运行实例仍按自身记录的 version 加载定义，不受影响
     */
    @Transactional(rollbackFor = Exception.class)
    public void atomicSwitch(ProcessDefinition definition,
            ProcessDeployment newDeployment, ProcessDeployment oldLatest) {
        definitionRepository.save(definition);
        if (oldLatest != null) {
            oldLatest.setLatest(false);
            deploymentRepository.save(oldLatest);
        }
        newDeployment.setLatest(true);
        deploymentRepository.save(newDeployment);
    }

    /**
     * 校验流程定义合法性
     * 1. 有且仅有一个开始节点
     * 2. 至少一个结束节点
     * 3. 所有节点连通（无孤岛）
     * 4. 无自环死循环风险
     */
    private void validateDefinition(ProcessDefinition definition) {
        List<FlowNode> startNodes = definition.getNodes().values().stream()
            .filter(n -> n.getNodeType() == FlowNode.NodeType.START_EVENT)
            .collect(Collectors.toList());
        if (startNodes.size() != 1) {
            throw new ProcessException("流程必须有且仅有一个开始节点，当前: " + startNodes.size());
        }
        boolean hasEnd = definition.getNodes().values().stream()
            .anyMatch(n -> n.getNodeType() == FlowNode.NodeType.END_EVENT);
        if (!hasEnd) {
            throw new ProcessException("流程必须至少有一个结束节点");
        }
        checkConnectivity(definition, startNodes.get(0));
        log.info("[流程部署] 定义校验通过, nodes={}, flows={}",
            definition.getNodes().size(), definition.getFlows().size());
    }

    /** 从开始节点 BFS，校验可达性并检测环 */
    private void checkConnectivity(ProcessDefinition definition, FlowNode start) {
        Set<String> visited = new HashSet<>();
        Queue<FlowNode> queue = new LinkedList<>();
        queue.add(start);
        while (!queue.isEmpty()) {
            FlowNode cur = queue.poll();
            if (!visited.add(cur.getNodeId())) {
                continue;
            }
            for (FlowNode next : definition.getOutgoingNodes(cur.getNodeId())) {
                queue.add(next);
            }
        }
        if (visited.size() < definition.getNodes().size()) {
            throw new ProcessException("存在不可达节点（孤岛），无法部署");
        }
    }
}
```

#### 10.3.3 版本兼容：存量实例与新实例隔离加载

热更新的正确性依赖"运行中实例锁定其发起时的版本"。流程定义服务据实例记录的 version 加载对应版本定义，而非总是最新版；只有新发起的实例才使用 latest 版本。

```java
/**
 * 流程定义服务（版本感知加载）
 * 保证存量实例走旧版、新实例走新版，实现平滑热更新
 */
@Service
@Slf4j
public class ProcessDefinitionService {

    @Resource
    private ProcessDefinitionRepository definitionRepository;

    @Resource
    private ProcessDeploymentRepository deploymentRepository;

    @Resource
    private ProcessDefinitionCache definitionCache;

    @Resource
    private ProcessDefinitionSerializer serializer;

    /**
     * 新发起流程时使用：加载当前生效（latest）版本
     */
    public ProcessDefinition getDeployedDefinition(String processKey) {
        ProcessDeployment latest = deploymentRepository.findLatest(processKey);
        if (latest == null || !"DEPLOYED".equals(latest.getDeployStatus())) {
            log.warn("[流程定义] 无可用生效版本, processKey={}", processKey);
            throw new ProcessException("流程未部署或已挂起: " + processKey);
        }
        return getDefinition(latest.getProcessId(), String.valueOf(latest.getVersion()));
    }

    /**
     * 运行中实例使用：按 processId+version 精确加载，保证版本隔离
     */
    public ProcessDefinition getDefinition(String processId, String version) {
        String cacheKey = processId;
        ProcessDefinition cached = definitionCache.get(cacheKey);
        if (cached != null) {
            return cached;
        }
        ProcessDefinition def = definitionRepository.findByProcessId(processId);
        if (def == null) {
            // 缓存穿透兜底：从部署记录的 BPMN 重新反序列化
            ProcessDeployment dep = deploymentRepository.findByProcessId(processId);
            if (dep == null) {
                throw new ProcessException("流程定义不存在: " + processId);
            }
            def = serializer.deserialize(dep.getBpmnXml());
        }
        definitionCache.put(cacheKey, def);
        return def;
    }

    /**
     * 挂起指定版本（不再受理新发起，存量实例继续跑完）
     */
    public void suspend(String processKey, int version) {
        ProcessDeployment dep = deploymentRepository.findByKeyAndVersion(processKey, version);
        if (dep == null) {
            throw new ProcessException("部署记录不存在");
        }
        dep.setDeployStatus("SUSPENDED");
        deploymentRepository.save(dep);
        definitionCache.evict(dep.getProcessId());
        log.info("[流程定义] 已挂起, processKey={}, version={}", processKey, version);
    }

    /**
     * 回滚：将 latest 指回指定历史版本
     */
    public void rollback(String processKey, int targetVersion) {
        ProcessDeployment current = deploymentRepository.findLatest(processKey);
        ProcessDeployment target = deploymentRepository.findKeyAndVersionForUpdate(
            processKey, targetVersion);
        if (target == null) {
            throw new ProcessException("回滚目标版本不存在: " + targetVersion);
        }
        if (current != null) {
            current.setLatest(false);
            deploymentRepository.save(current);
        }
        target.setLatest(true);
        target.setDeployStatus("DEPLOYED");
        deploymentRepository.save(target);
        definitionCache.evict(processKey);
        log.info("[流程定义] 回滚成功, processKey={}, from={} to={}",
            processKey, current != null ? current.getVersion() : "none", targetVersion);
    }
}
```

#### 10.3.4 动态配置要点小结

流程动态配置的关键在于"版本隔离"与"原子切换"。部署入口用分布式锁串行化、用内容哈希做幂等，避免同一份 BPMN 被重复部署出多个版本；部署前的连通性/唯一开始节点/无孤岛校验把非法流程挡在运行之前；版本切换在单事务内完成 latest 标记翻转，配合缓存 evict 实现热更新对新实例即时生效。最重要的是运行中实例始终按自身记录的 version 加载定义，与最新版彻底隔离，从而做到"改流程不影响在途审批"，并支持随时挂起、回滚。三个案例合起来覆盖了审批流从单人到多人、从静态到动态的完整能力面，异常处理、日志埋点、幂等控制、可靠回调贯穿始终，可直接作为生产落地的骨架参考。
