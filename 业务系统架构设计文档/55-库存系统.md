# 库存系统架构设计

## 一、问题背景

### 1.1 业务场景

库存系统是电商交易链路的核心，负责管理商品从供给到售卖的全过程。一个完整的库存生命周期：商家设置库存 → 用户浏览看到库存 → 下单扣减库存 → 取消订单恢复库存 → 售后退款恢复库存。

看似简单，但在高并发场景下，库存系统面临极其严峻的挑战：1000件商品同时有10万人抢，如何保证不超卖？一个商品在多个渠道售卖，库存怎么分配？大促秒杀场景下数据库热点行怎么扛？

### 1.2 核心挑战

| 挑战维度 | 具体问题 | 影响 |
|---------|---------|------|
| 超卖 | 并发扣减导致库存变负数 | 资金损失、用户投诉 |
| 少卖 | 扣减异常后未恢复库存 | 商品卖不掉、库存虚耗 |
| 多渠道库存 | 同一商品在不同渠道有不同的库存策略 | 配置复杂、互相挤占 |
| 热点行 | 秒杀商品单行并发更新，数据库行锁瓶颈 | TPS上不去、请求超时 |
| 数据一致性 | Redis缓存与MySQL数据不一致 | 展示有货实际无货 |
| 版本控制 | 并发更新库存时写覆盖 | 数据丢失 |

### 1.3 减库存时机选择

这是一个架构层面必须先确定的核心决策，有三种方案，各有取舍：

**方案一：下单减库存**——用户下单时立即扣减库存。优点是控制最精确，基本不会超卖。缺点是用户下单后可能不付款，导致库存被占用。适用于秒杀场景（抢到就是赚到，不付款概率极低）。

**方案二：付款减库存**——用户付款时才扣减库存。优点是不会占库存。缺点是并发高时可能下单成功但付款时库存不足，体验差。

**方案三：预扣库存**——下单后冻结库存一定时间（如10分钟），超时自动释放。付款前校验库存是否还有保留。这是最常见的方案，兼顾了体验和库存安全。

```java
/**
 * 库存策略选择：根据业务场景动态选择
 */
public enum InventoryStrategy {
    /**
     * 下单减库存：适用于秒杀场景
     * 优点：控制精确，性能最优（无需保留/释放）
     * 缺点：恶意占库存
     */
    DEDUCT_ON_ORDER,

    /**
     * 付款减库存：适用于常规电商
     * 优点：不占库存
     * 缺点：下单成功但付款失败
     */
    DEDUCT_ON_PAY,

    /**
     * 预扣库存：最通用方案
     * 优点：兼顾体验和安全
     * 缺点：逻辑复杂（冻结/释放/校验）
     */
    PRE_DEDUCT
}
```

## 二、整体架构设计

### 2.1 多级库存模型

借鉴领域驱动设计（DDD），将库存划分为多个聚合，每层有独立的库存值和扣减逻辑：

```
爆品库存（商家供给总量）
  └── 券包库存（运营投放给特定商品的总量）
       └── 渠道库存（分配到不同销售渠道的库存）
            └── 时段库存（分配到不同时间段的库存，用于准点秒杀）
```

三种库存分配类型：

| 类型 | 说明 | 扣减来源 |
|------|------|---------|
| 独占库存 | 从上级库存划拨出固定数量，其他渠道/时段无法使用 | 从本级库存表扣减 |
| 共享库存 | 不设固定值，与同级共享上级剩余库存 | 从上级库存表扣减 |
| 不限库存 | 无限库存，仅作用于日库存字段 | 不扣减，仅校验总库存 |

## 三、核心链路设计

### 3.1 库存扣减：Redis Lua原子操作

**问题**：高并发下多个请求同时扣减库存，如何保证不超卖？

**思路**：
1. 先用Redis扛并发——Redis单线程+Lua脚本保证原子性
2. MySQL做最终持久化——异步落库
3. 库存流水表做防重和对账

```java
/**
 * 库存扣减服务
 *
 * 完整链路：
 * 1. 参数校验（SKU存在性、数量合法性）
 * 2. Redis Lua脚本原子扣减：
 *    a. 检查可用库存是否充足
 *    b. 检查日库存是否充足
 *    c. 扣减可用库存 + 日可用库存
 *    d. 增加冻结库存
 * 3. 发送MQ消息异步落库（MySQL扣减+流水记录）
 * 4. 如果Redis扣减成功但MQ发送失败，通过定时对账补偿
 */
@Service
public class InventoryDeductService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private RocketMQTemplate mqTemplate;

    /**
     * Lua脚本：原子性预扣库存
     * KEYS[1] = 库存Hash: inv:{skuId}:{channelId}
     * ARGV[1] = quantity (扣减数量)
     * ARGV[2] = orderId (用于流水防重)
     *
     * 返回值：
     *   1  = 成功
     *  -1  = 可用库存不足
     *  -2  = 日库存不足
     *  -3  = 库存不存在
     */
    private static final String DEDUCT_LUA =
        // 1. 检查库存是否存在
        "if redis.call('EXISTS', KEYS[1]) == 0 then\n" +
        "    return -3\n" +
        "end\n" +
        // 2. 读取可用库存和日可用库存
        "local available = tonumber(redis.call('HGET', KEYS[1], 'availableStock'))\n" +
        "local dailyAvailable = tonumber(redis.call('HGET', KEYS[1], 'dailyAvailableStock'))\n" +
        "local qty = tonumber(ARGV[1])\n" +
        // 3. 检查可用库存
        "if available < qty then\n" +
        "    return -1\n" +
        "end\n" +
        // 4. 检查日库存（-1表示不限）
        "if dailyAvailable >= 0 and dailyAvailable < qty then\n" +
        "    return -2\n" +
        "end\n" +
        // 5. 原子扣减
        "redis.call('HINCRBY', KEYS[1], 'availableStock', -qty)\n" +
        "redis.call('HINCRBY', KEYS[1], 'frozenStock', qty)\n" +
        "if dailyAvailable >= 0 then\n" +
        "    redis.call('HINCRBY', KEYS[1], 'dailyAvailableStock', -qty)\n" +
        "end\n" +
        "return 1\n";

    /**
     * 预扣库存
     */
    public DeductResult preDeduct(Long skuId, Integer channelId,
                                   int quantity, Long orderId) {
        String stockKey = "inv:" + skuId + ":" + channelId;

        DefaultRedisScript<Long> script = new DefaultRedisScript<>();
        script.setScriptText(DEDUCT_LUA);
        script.setResultType(Long.class);

        Long result = redisTemplate.execute(script,
            Collections.singletonList(stockKey),
            String.valueOf(quantity),
            String.valueOf(orderId));

        if (result == null || result == -3L) {
            return DeductResult.fail("商品不存在");
        }
        if (result == -1L) {
            return DeductResult.fail("库存不足");
        }
        if (result == -2L) {
            return DeductResult.fail("今日库存已抢完");
        }

        // 异步落库
        InventoryDeductMessage msg = new InventoryDeductMessage();
        msg.setSkuId(skuId);
        msg.setChannelId(channelId);
        msg.setQuantity(quantity);
        msg.setOrderId(orderId);
        msg.setBizType("PRE_DEDUCT");
        msg.setTimestamp(System.currentTimeMillis());

        mqTemplate.asyncSend("inventory-deduct-topic", msg, new SendCallback() {
            @Override
            public void onSuccess(SendResult r) {
                log.info("库存扣减MQ发送成功, skuId={}, orderId={}", skuId, orderId);
            }
            @Override
            public void onException(Throwable e) {
                log.error("库存扣减MQ失败, skuId={}, orderId={}", skuId, orderId, e);
                // MQ失败不影响用户体验，有定时对账兜底
            }
        });

        return DeductResult.success();
    }
}
```

### 3.2 库存扣减消费者：MySQL落库 + 流水防重

```java
/**
 * 库存扣减消费者
 *
 * 消费流程：
 * 1. 幂等检查（流水表中是否已有该订单的扣减记录）
 * 2. MySQL扣减库存（乐观锁防写覆盖）
 * 3. 插入库存流水（防重 + 可追溯）
 * 4. 如果扣减失败（库存不足），需要回滚Redis
 */
@Component
@RocketMQMessageListener(topic = "inventory-deduct-topic",
    consumerGroup = "inventory-deduct-consumer-group")
public class InventoryDeductConsumer implements RocketMQListener<InventoryDeductMessage> {

    @Autowired
    private InventoryMapper inventoryMapper;

    @Autowired
    private InventoryLogMapper logMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void onMessage(InventoryDeductMessage msg) {
        // 1. 幂等检查：流水表中是否已处理
        InventoryLog existLog = logMapper.selectByOrderAndBiz(
            msg.getOrderId(), msg.getBizType());
        if (existLog != null) {
            return; // 已处理
        }

        // 2. 查询当前库存（带乐观锁）
        InventoryDO inventory = inventoryMapper.selectBySkuAndChannel(
            msg.getSkuId(), msg.getChannelId());
        if (inventory == null) {
            // Redis有但MySQL没有，说明数据不一致，告警
            log.error("MySQL库存记录不存在! skuId={}, channelId={}",
                msg.getSkuId(), msg.getChannelId());
            alertService.sendInventoryInconsistencyAlert(msg);
            return;
        }

        // 3. 检查库存是否充足（MySQL层面二次校验）
        if (inventory.getAvailableStock() < msg.getQuantity()) {
            // MySQL库存不足，但Redis扣减成功了，需要回滚Redis
            rollbackRedis(msg);
            log.error("MySQL库存不足，已回滚Redis. skuId={}, orderId={}",
                msg.getSkuId(), msg.getOrderId());
            return;
        }

        // 4. 乐观锁扣减库存
        int beforeStock = inventory.getAvailableStock();
        int afterStock = beforeStock - msg.getQuantity();
        int updated = inventoryMapper.deductWithVersion(
            msg.getSkuId(), msg.getChannelId(),
            msg.getQuantity(), inventory.getVersion());

        if (updated == 0) {
            // 乐观锁失败，重试
            throw new RuntimeException("乐观锁冲突，需要重试");
        }

        // 5. 插入库存流水
        InventoryLog log = new InventoryLog();
        log.setSkuId(msg.getSkuId());
        log.setChannelId(msg.getChannelId());
        log.setOrderId(msg.getOrderId());
        log.setBizType(msg.getBizType());
        log.setQuantity(msg.getQuantity());
        log.setBeforeStock(beforeStock);
        log.setAfterStock(afterStock);
        log.setCreateTime(new Date());
        logMapper.insert(log);
    }

    /**
     * 回滚Redis扣减
     */
    private void rollbackRedis(InventoryDeductMessage msg) {
        String stockKey = "inv:" + msg.getSkuId() + ":" + msg.getChannelId();
        redisTemplate.opsForHash().increment(stockKey, "availableStock", msg.getQuantity());
        redisTemplate.opsForHash().increment(stockKey, "frozenStock", -msg.getQuantity());
    }
}
```

### 3.3 库存恢复：取消订单/退款

**问题**：用户取消订单或退款时，需要将冻结的库存恢复。如何保证恢复操作幂等？

```java
/**
 * 库存恢复服务
 *
 * 恢复链路：
 * 1. 检查是否已恢复过（流水防重）
 * 2. Redis原子恢复（冻结库存→可用库存）
 * 3. 异步落库MySQL
 */
@Service
public class InventoryRestoreService {

    /**
     * Lua脚本：原子性恢复库存
     * KEYS[1] = 库存Hash: inv:{skuId}:{channelId}
     * ARGV[1] = quantity
     * ARGV[2] = orderId
     */
    private static final String RESTORE_LUA =
        // 检查冻结库存是否足够恢复
        "local frozen = tonumber(redis.call('HGET', KEYS[1], 'frozenStock'))\n" +
        "local qty = tonumber(ARGV[1])\n" +
        "if frozen < qty then\n" +
        "    return -1\n" +  // 冻结库存不足，可能数据异常
        "end\n" +
        // 恢复：冻结减少，可用增加
        "redis.call('HINCRBY', KEYS[1], 'frozenStock', -qty)\n" +
        "redis.call('HINCRBY', KEYS[1], 'availableStock', qty)\n" +
        "return 1\n";

    public RestoreResult restore(Long skuId, Integer channelId,
                                  int quantity, Long orderId) {
        // 1. 流水防重检查（MySQL层面）
        InventoryLog existLog = logMapper.selectByOrderAndBiz(orderId, "RESTORE");
        if (existLog != null) {
            return RestoreResult.success(); // 已恢复
        }

        // 2. Redis原子恢复
        String stockKey = "inv:" + skuId + ":" + channelId;
        DefaultRedisScript<Long> script = new DefaultRedisScript<>();
        script.setScriptText(RESTORE_LUA);
        script.setResultType(Long.class);

        Long result = redisTemplate.execute(script,
            Collections.singletonList(stockKey),
            String.valueOf(quantity),
            String.valueOf(orderId));

        if (result == null || result == -1L) {
            log.error("恢复库存失败，冻结库存不足. skuId={}, orderId={}",
                skuId, orderId);
            return RestoreResult.fail("冻结库存不足");
        }

        // 3. 异步落库
        InventoryRestoreMessage msg = new InventoryRestoreMessage();
        msg.setSkuId(skuId);
        msg.setChannelId(channelId);
        msg.setQuantity(quantity);
        msg.setOrderId(orderId);
        msg.setBizType("RESTORE");
        mqTemplate.asyncSend("inventory-restore-topic", msg, null);

        return RestoreResult.success();
    }
}
```

### 3.4 预扣超时释放：延时任务

**问题**：用户下单预扣了库存，但10分钟内未付款，需要自动释放库存。

**方案**：延时任务 + 幂等释放。

```java
/**
 * 预扣超时释放服务
 *
 * 方案：Redis ZSet延时队列 + 定时扫描
 * 1. 预扣成功后，将(orderId, expireTime)写入ZSet
 * 2. 定时任务扫描已过期的订单
 * 3. 检查订单状态，如果未付款则释放库存
 */
@Service
public class InventoryTimeoutService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private OrderFeignClient orderClient;

    private static final String TIMEOUT_ZSET_KEY = "inv:timeout";
    private static final long TIMEOUT_MS = 10 * 60 * 1000; // 10分钟

    /**
     * 预扣成功后注册超时任务
     */
    public void registerTimeout(Long orderId, Long skuId, Integer channelId,
                                 int quantity) {
        long expireTime = System.currentTimeMillis() + TIMEOUT_MS;
        String value = orderId + ":" + skuId + ":" + channelId + ":" + quantity;
        redisTemplate.opsForZSet().add(TIMEOUT_ZSET_KEY, value, expireTime);
    }

    /**
     * 定时扫描超时任务（每30秒执行）
     */
    @Scheduled(fixedRate = 30000)
    public void scanTimeout() {
        long now = System.currentTimeMillis();

        // 1. 获取所有已过期的任务
        Set<ZSetOperations.TypedTuple<String>> expired = redisTemplate.opsForZSet()
            .rangeByScoreWithScores(TIMEOUT_ZSET_KEY, 0, now);

        if (expired == null || expired.isEmpty()) {
            return;
        }

        for (ZSetOperations.TypedTuple<String> tuple : expired) {
            String value = tuple.getValue();
            String[] parts = value.split(":");
            Long orderId = Long.parseLong(parts[0]);
            Long skuId = Long.parseLong(parts[1]);
            Integer channelId = Integer.parseInt(parts[2]);
            int quantity = Integer.parseInt(parts[3]);

            try {
                // 2. 查询订单状态
                OrderStatus status = orderClient.getOrderStatus(orderId);

                if (status == OrderStatus.UNPAID || status == OrderStatus.CANCELLED) {
                    // 3. 未付款，释放库存
                    inventoryRestoreService.restore(skuId, channelId, quantity, orderId);
                    log.info("预扣超时释放库存, orderId={}, skuId={}", orderId, skuId);
                }

                // 4. 从ZSet中移除
                redisTemplate.opsForZSet().remove(TIMEOUT_ZSET_KEY, value);

            } catch (Exception e) {
                log.error("超时释放库存异常, orderId={}", orderId, e);
            }
        }
    }
}
```

## 四、秒杀场景优化

### 4.1 MySQL热点行优化

秒杀场景下，所有请求争抢同一行库存记录的行锁，TPS瓶颈在数据库。借鉴线上实践，可以做以下优化：

```java
/**
 * MySQL秒杀优化配置
 *
 * 核心思路：
 * 1. 关闭双1：sync_binlog=0, innodb_flush_log_at_trx_commit=2
 *    → 牺牲极端崩溃安全性，换取写入性能（TPS从500提升到1000）
 * 2. 关闭组提交：binlog_group_commit_sync_delay=0
 *    → 减少事务等待，加速提交（TPS进一步提升）
 * 3. 关闭死锁检测：innodb_deadlock_detect=0
 *    → 消除死锁检测开销（TPS从1000提升到1500+）
 *    → 风险：死锁时靠innodb_lock_wait_timeout回滚（默认50秒），需要缩短
 */
```

### 4.2 库存分片：分散热点

将一个商品的库存拆分到多行，分散行锁竞争：

```java
/**
 * 库存分片：将一个SKU的库存拆分到N个分片
 * 扣减时随机选一个分片扣减，分散行锁竞争
 */
public class InventoryShardService {

    private static final int SHARD_COUNT = 10;

    /**
     * 扣减库存：随机选分片
     */
    public boolean deductSharded(Long skuId, int quantity) {
        // 随机选一个分片尝试扣减
        List<Integer> shardIndexes = getRandomShardOrder();

        for (int shardIndex : shardIndexes) {
            String shardKey = "inv:" + skuId + ":shard:" + shardIndex;
            Long result = tryDeductShard(shardKey, quantity);
            if (result == 1L) {
                return true; // 扣减成功
            }
            // 该分片库存不足，尝试下一个分片
        }

        // 所有分片都失败，尝试从主库存扣减
        return false;
    }

    /**
     * 库存分片初始化
     * 将1000件库存拆分到10个分片，每个分片100件
     */
    public void initShards(Long skuId, int totalStock) {
        int perShard = totalStock / SHARD_COUNT;
        int remainder = totalStock % SHARD_COUNT;

        for (int i = 0; i < SHARD_COUNT; i++) {
            int shardStock = perShard + (i < remainder ? 1 : 0);
            String shardKey = "inv:" + skuId + ":shard:" + i;
            Map<String, String> fields = new HashMap<>();
            fields.put("availableStock", String.valueOf(shardStock));
            fields.put("frozenStock", "0");
            redisTemplate.opsForHash().putAll(shardKey, fields);
        }
    }

    private List<Integer> getRandomShardOrder() {
        List<Integer> indexes = new ArrayList<>();
        for (int i = 0; i < SHARD_COUNT; i++) {
            indexes.add(i);
        }
        Collections.shuffle(indexes);
        return indexes;
    }
}
```

### 4.3 多级缓存

```
请求 → Caffeine本地缓存(1秒TTL) → Redis集群 → MySQL
```

```java
/**
 * 多级缓存库存查询
 */
@Service
public class InventoryQueryService {

    // 本地缓存：极短TTL，防止缓存穿透
    private final Cache<String, Integer> localCache = Caffeine.newBuilder()
        .maximumSize(50000)
        .expireAfterWrite(1, TimeUnit.SECONDS)
        .build();

    /**
     * 查询可用库存
     */
    public int getAvailableStock(Long skuId, Integer channelId) {
        String key = "inv:" + skuId + ":" + channelId;

        // 1. 先查本地缓存
        Integer cached = localCache.getIfPresent(key);
        if (cached != null) {
            return cached;
        }

        // 2. 查Redis
        Object value = redisTemplate.opsForHash().get(key, "availableStock");
        if (value != null) {
            int stock = Integer.parseInt(value.toString());
            localCache.put(key, stock);
            return stock;
        }

        // 3. 查MySQL并回填Redis
        InventoryDO inventory = inventoryMapper.selectBySkuAndChannel(skuId, channelId);
        if (inventory == null) {
            return 0;
        }

        // 回填Redis
        Map<String, String> fields = new HashMap<>();
        fields.put("availableStock", String.valueOf(inventory.getAvailableStock()));
        fields.put("frozenStock", String.valueOf(inventory.getFrozenStock()));
        redisTemplate.opsForHash().putAll(key, fields);

        return inventory.getAvailableStock();
    }
}
```

## 五、数据一致性与对账

### 5.1 Redis与MySQL一致性保障

```
正常流程：Redis先扣减 → MQ → MySQL扣减 → 流水记录
异常场景：
  1. Redis扣减成功，MQ丢失 → 定时对账补偿
  2. MySQL扣减失败（乐观锁冲突）→ 回滚Redis
  3. Redis宕机 → 降级到MySQL直接扣减
```

### 5.2 定时对账

```java
/**
 * 库存对账定时任务
 *
 * 对账逻辑：
 * 1. 对比Redis和MySQL的库存值
 * 2. 对比库存流水合计 = 库存变更值
 * 3. 不一致时告警，以MySQL为准修正Redis
 */
@Scheduled(cron = "0 */5 * * * ?")  // 每5分钟
public void reconcile() {
    List<InventoryDO> allInventory = inventoryMapper.selectAllActive();

    for (InventoryDO mysqlInv : allInventory) {
        String redisKey = "inv:" + mysqlInv.getSkuId() + ":" + mysqlInv.getChannelId();

        // 1. 读取Redis库存
        Object redisAvailable = redisTemplate.opsForHash().get(redisKey, "availableStock");
        if (redisAvailable == null) {
            // Redis没有，回填
            redisTemplate.opsForHash().put(redisKey, "availableStock",
                String.valueOf(mysqlInv.getAvailableStock()));
            continue;
        }

        int redisStock = Integer.parseInt(redisAvailable.toString());

        // 2. 对比
        if (redisStock != mysqlInv.getAvailableStock()) {
            log.warn("库存不一致! skuId={}, Redis={}, MySQL={}",
                mysqlInv.getSkuId(), redisStock, mysqlInv.getAvailableStock());

            // 以MySQL为准修正Redis
            redisTemplate.opsForHash().put(redisKey, "availableStock",
                String.valueOf(mysqlInv.getAvailableStock()));

            // 告警
            alertService.sendStockInconsistencyAlert(
                mysqlInv.getSkuId(), redisStock, mysqlInv.getAvailableStock());
        }
    }

    // 3. 流水对账：sum(quantity) by biz_type = 库存变更值
    List<StockCheckResult> checkResults = logMapper.checkStockConsistency();
    for (StockCheckResult r : checkResults) {
        if (!r.isConsistent()) {
            log.error("库存流水不一致! skuId={}", r.getSkuId());
            alertService.sendStockLogAlert(r);
        }
    }
}
```

### 5.3 库存流水校验

```java
/**
 * 库存流水校验
 *
 * 每次扣减/恢复操作都记录流水，通过流水可以：
 * 1. 防重：相同orderId+bizType不重复处理
 * 2. 可追溯：记录变更前后的库存值
 * 3. 对账：流水合计应该等于库存变更值
 */
public class InventoryFlowChecker {

    /**
     * 校验库存流水一致性
     * 公式：初始库存 - SUM(扣减流水) + SUM(恢复流水) = 当前库存
     */
    public boolean check(Long skuId, Integer channelId) {
        InventoryDO inventory = inventoryMapper.selectBySkuAndChannel(skuId, channelId);
        List<InventoryLog> logs = logMapper.selectBySkuAndChannel(skuId, channelId);

        int initialStock = inventory.getTotalStock();
        int deductSum = logs.stream()
            .filter(l -> l.getBizType().equals("DEDUCT") || l.getBizType().equals("PRE_DEDUCT"))
            .mapToInt(InventoryLog::getQuantity)
            .sum();
        int restoreSum = logs.stream()
            .filter(l -> l.getBizType().equals("RESTORE") || l.getBizType().equals("UNFREEZE"))
            .mapToInt(InventoryLog::getQuantity)
            .sum();

        int expectedStock = initialStock - deductSum + restoreSum;
        int actualStock = inventory.getAvailableStock() + inventory.getFrozenStock() + inventory.getSoldStock();

        return expectedStock == actualStock;
    }
}
```

## 六、日库存刷新

借鉴线上实践，为了防止商品在某一天被抢完后后续几天没有曝光，引入日库存机制：每天零点自动从总库存划拨一定数量到日库存。

```java
/**

 * 每天零点执行：

 * 2. 从总库存划拨日库存到日可用库存
 * 3. 更新Redis和MySQL

@Scheduled(cron = "0 0 0 * * ?")

    List<InventoryDO> configs = inventoryMapper.selectAllWithDailyConfig();

    for (InventoryDO inv : configs) {
        try {
            // 日库存 = min(配置日库存, 剩余总库存)
```

## 七、异常处理与容错

### 7.1 异常场景处理

| 异常场景 | 处理方案 |
|---------|---------|
| Redis宕机 | 降级到MySQL直接扣减（性能下降但保证正确） |
| MQ消息丢失 | 定时对账发现Redis已扣MySQL未扣，补偿扣减 |
| MQ重复消费 | 流水表防重（order_id + biz_type唯一索引） |
| 乐观锁冲突 | 自动重试3次，仍失败则回滚Redis |
| MySQL扣减失败 | 回滚Redis，返回失败 |

### 7.2 降级方案

```java
/**
 * 库存扣减降级：Redis不可用时直接走MySQL
 */
public DeductResult deductWithFallback(Long skuId, Integer channelId,
                                        int quantity, Long orderId) {
    try {
        // 正常走Redis
        return deductViaRedis(skuId, channelId, quantity, orderId);
    } catch (Exception e) {
        log.warn("Redis扣减失败，降级到MySQL. skuId={}", skuId, e);
        return deductViaMySQL(skuId, channelId, quantity, orderId);
    }
}

/**
 * MySQL直接扣减（降级方案）
 * 使用乐观锁 + 流水防重
 */
@Transactional(rollbackFor = Exception.class)
public DeductResult deductViaMySQL(Long skuId, Integer channelId,
                                    int quantity, Long orderId) {
    // 1. 流水防重
    if (logMapper.selectByOrderAndBiz(orderId, "DEDUCT") != null) {
        return DeductResult.success();
    }

    // 2. 乐观锁扣减
    for (int retry = 0; retry < 3; retry++) {
        InventoryDO inv = inventoryMapper.selectBySkuAndChannel(skuId, channelId);
        if (inv.getAvailableStock() < quantity) {
            return DeductResult.fail("库存不足");
        }

        int updated = inventoryMapper.deductWithVersion(
            skuId, channelId, quantity, inv.getVersion());
        if (updated > 0) {
            // 3. 插入流水
            InventoryLog log = new InventoryLog();
            log.setSkuId(skuId);
            log.setChannelId(channelId);
            log.setOrderId(orderId);
            log.setBizType("DEDUCT");
            log.setQuantity(quantity);
            log.setBeforeStock(inv.getAvailableStock());
            log.setAfterStock(inv.getAvailableStock() - quantity);
            logMapper.insert(log);
            return DeductResult.success();
        }
    }
    return DeductResult.fail("系统繁忙");
}
```

## 八、最佳实践与总结

### 8.1 核心设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 减库存时机 | 预扣库存（通用）/下单减（秒杀） | 兼顾体验和安全 |
| 并发扣减 | Redis Lua原子操作 | 高性能 + 防超卖 |
| 持久化 | MQ异步落库 | 不阻塞主流程 |
| 防重 | 流水表唯一索引 | 幂等保证 |
| 版本控制 | 乐观锁 | 防写覆盖 |
| 对账 | 定时全量对账 | 兜底保障 |
| 热点优化 | 分片 + MySQL参数调优 | 分散行锁 |
| 多渠道 | 独占/共享/不限三种模式 | 灵活供给 |

### 8.2 容易踩的坑

1. **没有库存流水**：扣减失败时无法恢复正确值，出问题无法追溯
2. **Redis扣减成功但MySQL失败未回滚**：导致Redis和MySQL不一致
3. **恢复库存没做幂等**：取消订单重试导致库存多恢复
4. **乐观锁没加版本号**：并发更新写覆盖，库存数据丢失
5. **秒杀没做分片**：单行热点导致数据库TPS上不去
6. **日库存没自动刷新**：大促第一天卖完后后续几天无曝光

## 九、全链路实战案例

前面的章节从架构层面拆解了库存系统的核心设计，但真实业务中一次库存扣减从HTTP请求进入到最终落库，中间要经过参数校验、幂等控制、Redis预扣减、MQ异步落库、失败回滚等多个环节。本章通过三个完整全链路案例，把前面散落的知识点串联起来，展示在真实生产环境中各组件如何协作。

### 案例一：下单扣减库存全链路

**业务场景**：用户在APP上提交订单，交易系统调用库存系统扣减商品库存。要求：不超卖、不重复扣减、高性能、可追溯。

**全链路时序**：

```
用户下单 → 库存Controller → 参数校验 → 幂等校验(Redis) → Redis Lua预扣减
    → 预扣成功 → 发MQ异步落库 → 返回"下单成功"
                                    ↓
                        MQ Consumer → MySQL乐观锁扣减 → 写流水表
                                    ↓ (失败)
                        回滚Redis库存 → 告警
```

#### 9.1.2 幂等校验

```java
/**
 * 库存扣减Facade
 *
 * 职责：编排幂等校验 → Redis预扣减 → MQ异步落库的完整流程
 * 对Controller屏蔽内部逻辑，对外提供统一接口
 */
@Service
@Slf4j
public class InventoryDeductFacade {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private InventoryDeductService deductService;

    @Autowired
    private InventoryTimeoutService timeoutService;

    /**
     * 幂等校验Lua脚本
     * KEYS[1] = 幂等key: inv:deduct:idempotent:{orderId}
     * ARGV[1] = 过期时间（秒），24小时
     * ARGV[2] = traceId
     *
     * 返回值：
     *   1 = 首次请求，放行
     *   0 = 重复请求，拦截
     */
    private static final String IDEMPOTENT_LUA =
        "if redis.call('SET', KEYS[1], ARGV[2], 'NX', 'EX', ARGV[1]) then\n" +
        "    return 1\n" +
        "else\n" +
        "    return 0\n" +
        "end\n";

    /**
     * 扣减库存全流程
     */
    public DeductResult deduct(DeductRequest request) {
        // ========== 第1步：幂等校验 ==========
        // 同一订单不能重复扣减，用Redis SET NX实现
        // 过期时间24小时，足够覆盖MQ消费延迟
        String idempotentKey = "inv:deduct:idempotent:" + request.getOrderId();
        DefaultRedisScript<Long> script = new DefaultRedisScript<>();
        script.setScriptText(IDEMPOTENT_LUA);
        script.setResultType(Long.class);

        Long idempotentResult = redisTemplate.execute(script,
            Collections.singletonList(idempotentKey),
            String.valueOf(24 * 3600),
            request.getTraceId());

        if (idempotentResult == null || idempotentResult == 0L) {
            log.warn("重复扣减请求被拦截, orderId={}, traceId={}",
                request.getOrderId(), request.getTraceId());
            // 幂等拦截不报错，返回成功（调用方重试时拿到成功即可）
            return DeductResult.success();
        }

        // ========== 第2步：Redis预扣减 ==========
        DeductResult deductResult = deductService.preDeduct(
            request.getSkuId(), request.getChannelId(),
            request.getQuantity(), request.getOrderId());

        if (!deductResult.isSuccess()) {
            // 预扣减失败（库存不足等），删除幂等标记，允许调用方修正后重试
            redisTemplate.delete(idempotentKey);
            log.warn("预扣减失败, orderId={}, reason={}",
                request.getOrderId(), deductResult.getMessage());
            return deductResult;
        }

        // ========== 第3步：注册超时释放任务 ==========
        // 预扣成功后，10分钟未付款自动释放库存
        timeoutService.registerTimeout(
            request.getOrderId(),
            request.getSkuId(),
            request.getChannelId(),
            request.getQuantity());

        // ========== 第4步：MQ异步落库已在deductService中发送 ==========
        // 到这里返回成功，用户感知到"下单成功"
        log.info("扣减全流程完成, orderId={}, skuId={}, quantity={}",
            request.getOrderId(), request.getSkuId(), request.getQuantity());

        return DeductResult.success();
    }
}
```

#### 9.1.3 Redis预扣减（Lua脚本原子操作）

```java
/**
 * 库存扣减服务（核心）
 *
 * Redis预扣减：Lua脚本保证"检查库存 + 扣减"的原子性
 * 扣减成功后发MQ异步落库，不阻塞主流程
 */
@Service
@Slf4j
public class InventoryDeductService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private RocketMQTemplate mqTemplate;

    @Autowired
    private InventoryDegradeService degradeService;

    /**
     * Lua脚本：原子性预扣库存
     * KEYS[1] = 库存Hash: inv:{skuId}:{channelId}
     * ARGV[1] = quantity (扣减数量)
     * ARGV[2] = orderId (用于流水防重)
     *
     * 返回值：
     *   1  = 成功
     *  -1  = 可用库存不足
     *  -2  = 日库存不足
     *  -3  = 库存不存在
     */
    private static final String DEDUCT_LUA =
        // 1. 检查库存是否存在
        "if redis.call('EXISTS', KEYS[1]) == 0 then\n" +
        "    return -3\n" +
        "end\n" +
        // 2. 读取可用库存和日可用库存
        "local available = tonumber(redis.call('HGET', KEYS[1], 'availableStock'))\n" +
        "local dailyAvailable = tonumber(redis.call('HGET', KEYS[1], 'dailyAvailableStock'))\n" +
        "local qty = tonumber(ARGV[1])\n" +
        // 3. 检查可用库存
        "if available < qty then\n" +
        "    return -1\n" +
        "end\n" +
        // 4. 检查日库存（-1表示不限）
        "if dailyAvailable >= 0 and dailyAvailable < qty then\n" +
        "    return -2\n" +
        "end\n" +
        // 5. 原子扣减：可用库存减少、冻结库存增加
        "redis.call('HINCRBY', KEYS[1], 'availableStock', -qty)\n" +
        "redis.call('HINCRBY', KEYS[1], 'frozenStock', qty)\n" +
        "if dailyAvailable >= 0 then\n" +
        "    redis.call('HINCRBY', KEYS[1], 'dailyAvailableStock', -qty)\n" +
        "end\n" +
        "return 1\n";

    /**
     * 预扣库存
     */
    public DeductResult preDeduct(Long skuId, Integer channelId,
                                   int quantity, Long orderId) {
        String stockKey = "inv:" + skuId + ":" + channelId;

        try {
            DefaultRedisScript<Long> script = new DefaultRedisScript<>();
            script.setScriptText(DEDUCT_LUA);
            script.setResultType(Long.class);

            Long result = redisTemplate.execute(script,
                Collections.singletonList(stockKey),
                String.valueOf(quantity),
                String.valueOf(orderId));

            if (result == null || result == -3L) {
                return DeductResult.fail("STOCK_NOT_FOUND", "商品不存在");
            }
            if (result == -1L) {
                // 库存不足，快速失败返回
                return DeductResult.fail("STOCK_INSUFFICIENT", "库存不足");
            }
            if (result == -2L) {
                return DeductResult.fail("DAILY_STOCK_INSUFFICIENT", "今日库存已抢完");
            }

            // 预扣成功，发MQ异步落库
            sendDeductMessage(skuId, channelId, quantity, orderId, "PRE_DEDUCT");

            return DeductResult.success();

        } catch (Exception e) {
            // Redis异常，降级到MySQL直接扣减
            log.error("Redis预扣减异常，降级MySQL. skuId={}, orderId={}", skuId, orderId, e);
            return degradeService.deductViaMySQL(skuId, channelId, quantity, orderId);
        }
    }

    /**
     * 发送扣减MQ消息
     */
    private void sendDeductMessage(Long skuId, Integer channelId,
                                    int quantity, Long orderId, String bizType) {
        InventoryDeductMessage msg = new InventoryDeductMessage();
        msg.setSkuId(skuId);
        msg.setChannelId(channelId);
        msg.setQuantity(quantity);
        msg.setOrderId(orderId);
        msg.setBizType(bizType);
        msg.setTimestamp(System.currentTimeMillis());

        try {
            mqTemplate.asyncSend("inventory-deduct-topic", msg, new SendCallback() {
                @Override
                public void onSuccess(SendResult r) {
                    log.info("库存扣减MQ发送成功, skuId={}, orderId={}", skuId, orderId);
                }
                @Override
                public void onException(Throwable e) {
                    // MQ失败不影响用户体验，定时对账兜底
                    log.error("库存扣减MQ发送失败, skuId={}, orderId={}", skuId, orderId, e);
                }
            });
        } catch (Exception e) {
            log.error("库存扣减MQ发送异常, skuId={}, orderId={}", skuId, orderId, e);
            // 不抛异常，对账任务会补偿
        }
    }
```

#### 9.1.4 MQ消费者：MySQL乐观锁扣减 + 失败回滚

```java
/**
 * 库存扣减消费者
 *
 * 消费流程：
 * 1. 幂等检查（流水表中是否已有该订单的扣减记录）
 * 2. MySQL扣减库存（乐观锁防写覆盖，WHERE stock >= deductNum）
 * 3. 插入库存流水（防重 + 可追溯）
 * 4. 如果扣减失败（库存不足），回滚Redis预扣减
 *
 * 异常处理：
 * - 消费失败 → MQ自动重试（最多3次）
 * - 重试3次仍失败 → 进入死信队列 → 人工介入
 */
@Component
@RocketMQMessageListener(topic = "inventory-deduct-topic",
    consumerGroup = "inventory-deduct-consumer-group",
    maxReconsumeTimes = 3)
@Slf4j
public class InventoryDeductConsumer implements RocketMQListener<InventoryDeductMessage> {

    @Autowired
    private InventoryMapper inventoryMapper;

    @Autowired
    private InventoryLogMapper logMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private AlertService alertService;

    @Override
    public void onMessage(InventoryDeductMessage msg) {
        log.info("收到扣减MQ消息, orderId={}, skuId={}, quantity={}",
            msg.getOrderId(), msg.getSkuId(), msg.getQuantity());

        try {
            processDeduct(msg);
        } catch (Exception e) {
            log.error("扣减消费异常, orderId={}", msg.getOrderId(), e);
            throw e; // 抛出异常触发MQ重试
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void processDeduct(InventoryDeductMessage msg) {
        // ========== 第1步：幂等检查 ==========
        InventoryLog existLog = logMapper.selectByOrderAndBiz(
            msg.getOrderId(), msg.getBizType());
        if (existLog != null) {
            log.info("扣减已处理，跳过. orderId={}", msg.getOrderId());
            return;
        }

        // ========== 第2步：查询MySQL库存 ==========
        InventoryDO inventory = inventoryMapper.selectBySkuAndChannel(
            msg.getSkuId(), msg.getChannelId());
        if (inventory == null) {
            log.error("MySQL库存记录不存在! skuId={}, channelId={}",
                msg.getSkuId(), msg.getChannelId());
            alertService.sendInventoryInconsistencyAlert(msg);
            rollbackRedis(msg);
            return;
        }

        // ========== 第3步：MySQL库存二次校验 ==========
        if (inventory.getAvailableStock() < msg.getQuantity()) {
            // MySQL库存不足但Redis扣减成功了，说明数据不一致
            log.error("MySQL库存不足，回滚Redis. skuId={}, orderId={}, mysqlStock={}, deductQty={}",
                msg.getSkuId(), msg.getOrderId(),
                inventory.getAvailableStock(), msg.getQuantity());
            rollbackRedis(msg);
            alertService.sendStockInconsistencyAlert(
                msg.getSkuId(), "MySQL库存不足，已回滚Redis");
            return;
        }

        // ========== 第4步：乐观锁扣减（WHERE stock >= deductNum） ==========
        int beforeStock = inventory.getAvailableStock();
        int afterStock = beforeStock - msg.getQuantity();

        int updated = inventoryMapper.deductWithVersion(
            msg.getSkuId(), msg.getChannelId(),
            msg.getQuantity(), inventory.getVersion());

        if (updated == 0) {
            // 乐观锁冲突，说明并发更新，重试
            throw new RuntimeException("乐观锁冲突，需要重试. orderId=" + msg.getOrderId());
        }

        // ========== 第5步：插入库存流水 ==========
        InventoryLog log = new InventoryLog();
        log.setSkuId(msg.getSkuId());
        log.setChannelId(msg.getChannelId());
        log.setOrderId(msg.getOrderId());
        log.setBizType(msg.getBizType());
        log.setQuantity(msg.getQuantity());
        log.setBeforeStock(beforeStock);
        log.setAfterStock(afterStock);
        log.setCreateTime(new Date());
        logMapper.insert(log);

        log.info("MySQL扣减成功, orderId={}, skuId={}, before={}, after={}",
            msg.getOrderId(), msg.getSkuId(), beforeStock, afterStock);
    }

    /**
     * 回滚Redis预扣减
     * 将冻结库存转回可用库存
     */
    private void rollbackRedis(InventoryDeductMessage msg) {
        String stockKey = "inv:" + msg.getSkuId() + ":" + msg.getChannelId();
        try {
            redisTemplate.opsForHash().increment(stockKey, "availableStock", msg.getQuantity());
            redisTemplate.opsForHash().increment(stockKey, "frozenStock", -msg.getQuantity());
            log.info("Redis回滚成功, skuId={}, orderId={}, quantity={}",
                msg.getSkuId(), msg.getOrderId(), msg.getQuantity());
        } catch (Exception e) {
            log.error("Redis回滚失败! 需人工处理. skuId={}, orderId={}",
                msg.getSkuId(), msg.getOrderId(), e);
            alertService.sendRollbackFailureAlert(msg);
        }
    }
}
```

### 案例二：库存归还全链路（订单取消/超时未支付）

**业务场景**：用户下单后取消订单，或10分钟未支付自动超时，或退款成功后，需要将冻结的库存归还到可用库存。核心要求：归还幂等、Redis与MySQL双归还、可追溯。

**全链路时序**：

```
订单取消/超时/退款 → 库存归还Controller → 归还幂等校验(Redis + MySQL流水)
    → Redis原子归还（冻结→可用）→ 发MQ异步落库 → 返回成功
                                        ↓
                            MQ Consumer → MySQL库存增加(UPDATE stock + returnNum)
                                        → 写归还流水表
                                        → 清除售罄标记
                                        → 对账校验（归还 vs 扣减）
```

#### 9.2.2 归还幂等校验

```java
/**
 * 库存归还Facade
 *
 * 编排：幂等校验 → Redis归还 → MQ异步落库
 * 核心保证：同一订单只能归还一次
 */
@Service
@Slf4j
public class InventoryRestoreFacade {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private InventoryRestoreService restoreService;

    @Autowired
    private InventoryLogMapper logMapper;

    @Autowired
    private StockInsufficientHandler soldOutHandler;

    /**
     * 归还库存全流程
     */
    public RestoreResult restore(RestoreRequest request) {
        // ========== 第1步：双层幂等校验 ==========
        // 第一层：Redis幂等标记（快速拦截重复请求）
        String idempotentKey = "inv:restore:idempotent:" + request.getOrderId();
        Boolean setSuccess = redisTemplate.opsForValue()
            .setIfAbsent(idempotentKey, request.getTraceId(), 48, TimeUnit.HOURS);

        if (Boolean.FALSE.equals(setSuccess)) {
            // Redis标记已存在，再查MySQL流水确认是否真的已归还
            InventoryLog existLog = logMapper.selectByOrderAndBiz(
                request.getOrderId(), "RESTORE");
            if (existLog != null) {
                log.info("归还已处理(MySQL确认)，跳过. orderId={}", request.getOrderId());
                return RestoreResult.success();
            }
            // Redis标记存在但MySQL没有流水，可能是之前处理到一半失败了
            // 删除标记，允许重新处理
            redisTemplate.delete(idempotentKey);
            log.warn("归还幂等标记残留，已清除. orderId={}", request.getOrderId());
        }

        // 第二层：MySQL流水表防重（兜底保证）
        InventoryLog existLog = logMapper.selectByOrderAndBiz(
            request.getOrderId(), "RESTORE");
        if (existLog != null) {
            log.info("归还已处理(MySQL流水确认)，跳过. orderId={}", request.getOrderId());
            return RestoreResult.success();
        }

        // ========== 第2步：Redis原子归还 ==========
        RestoreResult restoreResult = restoreService.restore(
            request.getSkuId(), request.getChannelId(),
            request.getQuantity(), request.getOrderId());

        if (!restoreResult.isSuccess()) {
            // 归还失败，删除幂等标记，允许重试
            redisTemplate.delete(idempotentKey);
            log.warn("Redis归还失败, orderId={}, reason={}",
                request.getOrderId(), restoreResult.getMessage());
            return restoreResult;
        }

        // ========== 第3步：清除售罄标记 ==========
        // 库存回补后，清除售罄标记，恢复购买
        soldOutHandler.clearSoldOut(request.getSkuId(), request.getChannelId());

        log.info("归还全流程完成, orderId={}, skuId={}, quantity={}",
            request.getOrderId(), request.getSkuId(), request.getQuantity());

        return RestoreResult.success();
    }
}
```

#### 9.2.3 Redis原子归还与MQ异步落库

```java
/**
 * 库存恢复服务
 *
 * Redis原子归还：冻结库存 → 可用库存
 * 归还成功后发MQ异步落库MySQL
 */
@Service
@Slf4j
public class InventoryRestoreService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private RocketMQTemplate mqTemplate;

    @Autowired
    private InventoryDegradeService degradeService;

    /**
     * Lua脚本：原子性恢复库存
     * KEYS[1] = 库存Hash: inv:{skuId}:{channelId}
     * ARGV[1] = quantity
     * ARGV[2] = orderId
     *
     * 返回值：
     *   1  = 成功
     *  -1  = 冻结库存不足（数据异常）
     *  -2  = 库存不存在
     */
    private static final String RESTORE_LUA =
        "if redis.call('EXISTS', KEYS[1]) == 0 then\n" +
        "    return -2\n" +
        "end\n" +
        "local frozen = tonumber(redis.call('HGET', KEYS[1], 'frozenStock'))\n" +
        "local qty = tonumber(ARGV[1])\n" +
        "if frozen < qty then\n" +
        "    return -1\n" +
        "end\n" +
        // 恢复：冻结减少，可用增加
        "redis.call('HINCRBY', KEYS[1], 'frozenStock', -qty)\n" +
        "redis.call('HINCRBY', KEYS[1], 'availableStock', qty)\n" +
        "return 1\n";

    /**
     * 归还库存
     */
    public RestoreResult restore(Long skuId, Integer channelId,
                                  int quantity, Long orderId) {
        String stockKey = "inv:" + skuId + ":" + channelId;

        try {
            DefaultRedisScript<Long> script = new DefaultRedisScript<>();
            script.setScriptText(RESTORE_LUA);
            script.setResultType(Long.class);

            Long result = redisTemplate.execute(script,
                Collections.singletonList(stockKey),
                String.valueOf(quantity),
                String.valueOf(orderId));

            if (result == null || result == -2L) {
                log.error("库存不存在，无法归还. skuId={}, orderId={}", skuId, orderId);
                return RestoreResult.fail("STOCK_NOT_FOUND", "库存记录不存在");
            }
            if (result == -1L) {
                // 冻结库存不足，可能是重复归还或数据异常
                log.error("冻结库存不足，无法归还. skuId={}, orderId={}, frozen={}, returnQty={}",
                    skuId, orderId, getFrozenStock(stockKey), quantity);
                // 触发数据修复流程
                triggerStockRepair(skuId, channelId, orderId);
                return RestoreResult.fail("FROZEN_INSUFFICIENT", "冻结库存不足，已触发修复");
            }

            // Redis归还成功，发MQ异步落库
            InventoryRestoreMessage msg = new InventoryRestoreMessage();
            msg.setSkuId(skuId);
            msg.setChannelId(channelId);
            msg.setQuantity(quantity);
            msg.setOrderId(orderId);
            msg.setBizType("RESTORE");
            msg.setTimestamp(System.currentTimeMillis());

            try {
                mqTemplate.syncSend("inventory-restore-topic", msg);
            } catch (Exception e) {
                log.error("归还MQ发送失败，对账任务会补偿. orderId={}", orderId, e);
                // 不影响Redis归还结果，对账兜底
            }

            return RestoreResult.success();

        } catch (Exception e) {
            // Redis异常，降级到MySQL直接归还
            log.error("Redis归还异常，降级MySQL. skuId={}, orderId={}", skuId, orderId, e);
            return degradeService.restoreViaMySQL(skuId, channelId, quantity, orderId);
        }
    }

    private int getFrozenStock(String key) {
        Object val = redisTemplate.opsForHash().get(key, "frozenStock");
        return val == null ? 0 : Integer.parseInt(val.toString());
    }

    private void triggerStockRepair(Long skuId, Integer channelId, Long orderId) {
        // 发送库存修复消息，由对账服务处理
        log.error("触发库存修复, skuId={}, channelId={}, orderId={}", skuId, channelId, orderId);
    }
}
```

#### 9.2.4 MQ消费者：MySQL库存增加 + 流水写入 + 对账

```java
/**
 * 库存归还消费者
 *
 * 消费流程：
 * 1. 幂等检查（流水表防重）
 * 2. MySQL库存增加（UPDATE stock + returnNum）
 * 3. 写归还流水表
 * 4. 对账校验：归还记录 vs 扣减记录
 */
@Component
@RocketMQMessageListener(topic = "inventory-restore-topic",
    consumerGroup = "inventory-restore-consumer-group",
    maxReconsumeTimes = 3)
@Slf4j
public class InventoryRestoreConsumer implements RocketMQListener<InventoryRestoreMessage> {

    @Autowired
    private InventoryMapper inventoryMapper;

    @Autowired
    private InventoryLogMapper logMapper;

    @Autowired
    private InventoryReconcileService reconcileService;

    @Override
    public void onMessage(InventoryRestoreMessage msg) {
        log.info("收到归还MQ消息, orderId={}, skuId={}, quantity={}",
            msg.getOrderId(), msg.getSkuId(), msg.getQuantity());
        try {
            processRestore(msg);
        } catch (Exception e) {
            log.error("归还消费异常, orderId={}", msg.getOrderId(), e);
            throw e;
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void processRestore(InventoryRestoreMessage msg) {
        // ========== 第1步：幂等检查 ==========
        InventoryLog existLog = logMapper.selectByOrderAndBiz(
            msg.getOrderId(), msg.getBizType());
        if (existLog != null) {
            log.info("归还已处理，跳过. orderId={}", msg.getOrderId());
            return;
        }

        // ========== 第2步：校验扣减流水存在 ==========
        // 归还前确认该订单确实有扣减记录，防止无扣减的归还
        InventoryLog deductLog = logMapper.selectByOrderAndBiz(
            msg.getOrderId(), "PRE_DEDUCT");
        if (deductLog == null) {
            deductLog = logMapper.selectByOrderAndBiz(
                msg.getOrderId(), "DEDUCT");
        }
        if (deductLog == null) {
            log.error("未找到扣减流水，拒绝归还. orderId={}", msg.getOrderId());
            return;
        }

        // ========== 第3步：MySQL库存增加 ==========
        InventoryDO inventory = inventoryMapper.selectBySkuAndChannel(
            msg.getSkuId(), msg.getChannelId());
        if (inventory == null) {
            log.error("MySQL库存记录不存在! skuId={}", msg.getSkuId());
            return;
        }

        int beforeStock = inventory.getAvailableStock();
        int afterStock = beforeStock + msg.getQuantity();

        // 乐观锁更新：增加可用库存，减少冻结库存
        int updated = inventoryMapper.restoreWithVersion(
            msg.getSkuId(), msg.getChannelId(),
            msg.getQuantity(), inventory.getVersion());

        if (updated == 0) {
            throw new RuntimeException("乐观锁冲突，需要重试. orderId=" + msg.getOrderId());
        }

        // ========== 第4步：写归还流水 ==========
        InventoryLog restoreLog = new InventoryLog();
        restoreLog.setSkuId(msg.getSkuId());
        restoreLog.setChannelId(msg.getChannelId());
        restoreLog.setOrderId(msg.getOrderId());
        restoreLog.setBizType("RESTORE");
        restoreLog.setQuantity(msg.getQuantity());
        restoreLog.setBeforeStock(beforeStock);
        restoreLog.setAfterStock(afterStock);
        restoreLog.setCreateTime(new Date());
        logMapper.insert(restoreLog);

        log.info("MySQL归还成功, orderId={}, skuId={}, before={}, after={}",
            msg.getOrderId(), msg.getSkuId(), beforeStock, afterStock);

        // ========== 第5步：对账校验 ==========
        // 归还后立即做一次轻量对账：该订单的扣减数量 = 归还数量
        reconcileService.checkOrderBalance(msg.getOrderId());
    }
}
```

#### 9.2.5 归还与扣减的对账

```java
/**
 * 库存对账服务
 *
 * 对账维度：
 * 1. 单订单对账：每个订单的扣减数量 = 归还数量（已取消的订单）
 * 2. 全量对账：Redis库存 vs MySQL库存 vs 流水合计
 */
@Service
@Slf4j
public class InventoryReconcileService {

    @Autowired
    private InventoryLogMapper logMapper;

    @Autowired
    private InventoryMapper inventoryMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private AlertService alertService;

    /**
     * 单订单对账：扣减数量是否等于归还数量
     * 在归还完成后立即执行，快速发现异常
     */
    public void checkOrderBalance(Long orderId) {
        List<InventoryLog> logs = logMapper.selectByOrderId(orderId);

        int deductQty = logs.stream()
            .filter(l -> "DEDUCT".equals(l.getBizType()) || "PRE_DEDUCT".equals(l.getBizType()))
            .mapToInt(InventoryLog::getQuantity)
            .sum();

        int restoreQty = logs.stream()
            .filter(l -> "RESTORE".equals(l.getBizType()) || "UNFREEZE".equals(l.getBizType()))
            .mapToInt(InventoryLog::getQuantity)
            .sum();

        // 已归还的订单：扣减量应该等于归还量
        // 未归还的订单：扣减量 > 归还量（还有冻结库存）
        // 异常情况：归还量 > 扣减量 → 多还了，告警
        if (restoreQty > deductQty) {
            log.error("对账异常：归还量大于扣减量! orderId={}, deduct={}, restore={}",
                orderId, deductQty, restoreQty);
            alertService.sendReconcileAlert(orderId, "归还量超过扣减量");
        }

        log.info("单订单对账完成, orderId={}, deduct={}, restore={}",
            orderId, deductQty, restoreQty);
    }

    /**
     * 全量对账：Redis vs MySQL vs 流水合计
     * 定时任务每5分钟执行一次
     */
    @Scheduled(cron = "0 */5 * * * ?")
    public void fullReconcile() {
        log.info("开始全量库存对账...");
        int inconsistencyCount = 0;

        List<InventoryDO> allInventory = inventoryMapper.selectAllActive();

        for (InventoryDO mysqlInv : allInventory) {
            String redisKey = "inv:" + mysqlInv.getSkuId() + ":" + mysqlInv.getChannelId();

            // 1. Redis vs MySQL
            Object redisAvailable = redisTemplate.opsForHash().get(redisKey, "availableStock");
            if (redisAvailable == null) {
                // Redis没有，回填
                Map<String, String> fields = new HashMap<>();
                fields.put("availableStock", String.valueOf(mysqlInv.getAvailableStock()));
                fields.put("frozenStock", String.valueOf(mysqlInv.getFrozenStock()));
                redisTemplate.opsForHash().putAll(redisKey, fields);
                continue;
            }

            int redisStock = Integer.parseInt(redisAvailable.toString());
            int mysqlStock = mysqlInv.getAvailableStock();

            if (redisStock != mysqlStock) {
                inconsistencyCount++;
                log.warn("库存不一致! skuId={}, Redis={}, MySQL={}",
                    mysqlInv.getSkuId(), redisStock, mysqlStock);

                // 以MySQL为准修正Redis
                redisTemplate.opsForHash().put(redisKey, "availableStock",
                    String.valueOf(mysqlStock));

                alertService.sendStockInconsistencyAlert(
                    mysqlInv.getSkuId(), redisStock, mysqlStock);
            }

            // 2. 流水对账：初始库存 - 扣减合计 + 归还合计 = 当前库存
            List<InventoryLog> logs = logMapper.selectBySkuAndChannel(
                mysqlInv.getSkuId(), mysqlInv.getChannelId());

            int deductSum = logs.stream()
                .filter(l -> "DEDUCT".equals(l.getBizType()) || "PRE_DEDUCT".equals(l.getBizType()))
                .mapToInt(InventoryLog::getQuantity)
                .sum();
            int restoreSum = logs.stream()
                .filter(l -> "RESTORE".equals(l.getBizType()) || "UNFREEZE".equals(l.getBizType()))
                .mapToInt(InventoryLog::getQuantity)
                .sum();

            int expectedStock = mysqlInv.getTotalStock() - deductSum + restoreSum;
            int actualStock = mysqlInv.getAvailableStock()
                + mysqlInv.getFrozenStock() + mysqlInv.getSoldStock();

            if (expectedStock != actualStock) {
                inconsistencyCount++;
                log.error("流水对账不一致! skuId={}, expected={}, actual={}",
                    mysqlInv.getSkuId(), expectedStock, actualStock);
                alertService.sendStockLogAlert(mysqlInv.getSkuId());
            }
        }

        log.info("全量对账完成, 总计{}条库存, 不一致{}条",
            allInventory.size(), inconsistencyCount);
    }
}
```

### 案例三：库存分桶与热点商品库存扣减全链路

**业务场景**：某秒杀活动商品1000件，预估瞬时QPS 5万+。如果所有请求都打到同一行库存记录，MySQL行锁会成为瓶颈。通过库存分桶将热点分散，同时保证不超卖。

**全链路时序**：

```
活动开始前：
  热点检测(QPS超阈值) → 自动触发分桶 → 1000件拆10桶(每桶100件) → 写入Redis + MySQL

活动进行中：
  用户下单 → 随机选桶 → Lua原子扣减(桶内)
    → 桶内扣减成功 → MQ异步落库(记录桶号)
    → 桶内库存不足 → 尝试下一个桶 → 全部不足 → 尝试主库存

活动结束后：
  定时检查分桶 → 桶间库存再平衡 → 低库存桶合并 → 最终合并回主库存
```

#### 9.3.1 热点商品检测

```java
/**
 * 热点商品检测服务
 *
 * 通过滑动窗口统计QPS，超过阈值自动触发分桶
 */
@Service
@Slf4j
public class HotItemDetectService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private InventoryBucketService bucketService;

    /** QPS阈值，超过则触发分桶 */
    private static final int HOT_QPS_THRESHOLD = 1000;

    /** 检测窗口大小（秒） */
    private static final int WINDOW_SECONDS = 10;

    /**
     * 每10秒检测一次热点商品
     */
    @Scheduled(fixedRate = 10000)
    public void detectHotItems() {
        // 1. 扫描最近窗口内的库存访问计数
        String counterKey = "inv:access:counter";
        Map<Object, Object> counters = redisTemplate.opsForHash().entries(counterKey);

        for (Map.Entry<Object, Object> entry : counters.entrySet()) {
            String skuChannel = (String) entry.getKey();
            int accessCount = Integer.parseInt(entry.getValue().toString());
            int qps = accessCount / WINDOW_SECONDS;

            String[] parts = skuChannel.split(":");
            Long skuId = Long.parseLong(parts[0]);
            Integer channelId = Integer.parseInt(parts[1]);

            if (qps >= HOT_QPS_THRESHOLD) {
                // 检查是否已分桶
                if (!bucketService.isBucketed(skuId, channelId)) {
                    log.warn("检测到热点商品! skuId={}, channelId={}, QPS={}, 触发分桶",
                        skuId, channelId, qps);
                    bucketService.initBuckets(skuId, channelId);
                }
            }

            // 清零计数器
            redisTemplate.opsForHash().delete(counterKey, skuChannel);
        }
    }

    /**
     * 库存访问计数（在每次扣减/查询时调用）
     */
    public void recordAccess(Long skuId, Integer channelId) {
        String counterKey = "inv:access:counter";
        String field = skuId + ":" + channelId;
        redisTemplate.opsForHash().increment(counterKey, field, 1);
    }

    /**
     * 获取当前QPS（用于分桶合并判断）
     */
    public int getCurrentQps(Long skuId, Integer channelId) {
        String counterKey = "inv:access:counter";
        Object count = redisTemplate.opsForHash().get(counterKey, skuId + ":" + channelId);
        if (count == null) return 0;
        return Integer.parseInt(count.toString()) / WINDOW_SECONDS;
    }
}
```

#### 9.3.2 库存分桶策略

```java
/**
 * 库存分桶服务
 *
 * 将一个SKU的库存拆分到N个桶，分散热点
 * 每个桶独立存储在Redis中，扣减时随机选桶
 */
@Service
@Slf4j
public class InventoryBucketService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private InventoryMapper inventoryMapper;

    /** 默认桶数量 */
    private static final int DEFAULT_BUCKET_COUNT = 10;

    /** 分桶元数据key前缀 */
    private static final String BUCKET_META_KEY = "inv:bucket:meta:";

    /** 桶库存key前缀 */
    private static final String BUCKET_KEY = "inv:bucket:";

    /**
     * 初始化分桶
     * 将totalStock件库存拆分成bucketCount个桶
     *
     * 例如：1000件库存，10个桶，每桶100件
     */
    public void initBuckets(Long skuId, Integer channelId) {
        initBuckets(skuId, channelId, DEFAULT_BUCKET_COUNT);
    }

    @Transactional(rollbackFor = Exception.class)
    public void initBuckets(Long skuId, Integer channelId, int bucketCount) {
        // 1. 查询当前库存
        InventoryDO inventory = inventoryMapper.selectBySkuAndChannel(skuId, channelId);
        if (inventory == null) {
            log.error("分桶失败：库存记录不存在. skuId={}", skuId);
            return;
        }

        int totalStock = inventory.getAvailableStock();
        if (totalStock <= 0) {
            log.warn("分桶跳过：库存为0. skuId={}", skuId);
            return;
        }

        // 2. 计算每桶库存（尽量均匀分配）
        int perBucket = totalStock / bucketCount;
        int remainder = totalStock % bucketCount;

        // 3. 初始化Redis桶
        for (int i = 0; i < bucketCount; i++) {
            int bucketStock = perBucket + (i < remainder ? 1 : 0);
            String bucketKey = BUCKET_KEY + skuId + ":" + channelId + ":" + i;

            Map<String, String> fields = new HashMap<>();
            fields.put("availableStock", String.valueOf(bucketStock));
            fields.put("frozenStock", "0");
            fields.put("bucketIndex", String.valueOf(i));
            redisTemplate.opsForHash().putAll(bucketKey, fields);
        }

        // 4. 写入分桶元数据
        String metaKey = BUCKET_META_KEY + skuId + ":" + channelId;
        Map<String, String> meta = new HashMap<>();
        meta.put("bucketCount", String.valueOf(bucketCount));
        meta.put("totalStock", String.valueOf(totalStock));
        meta.put("status", "ACTIVE");
        meta.put("createTime", String.valueOf(System.currentTimeMillis()));
        redisTemplate.opsForHash().putAll(metaKey, meta);

        // 5. MySQL主库存标记为"已分桶"，可用库存清零（库存已分配到桶中）
        inventoryMapper.markBucketed(skuId, channelId, bucketCount);

        log.info("分桶完成, skuId={}, channelId={}, bucketCount={}, totalStock={}",
            skuId, channelId, bucketCount, totalStock);
    }

    /**
     * 检查是否已分桶
     */
    public boolean isBucketed(Long skuId, Integer channelId) {
        String metaKey = BUCKET_META_KEY + skuId + ":" + channelId;
        Object status = redisTemplate.opsForHash().get(metaKey, "status");
        return "ACTIVE".equals(status);
    }

    /**
     * 获取桶数量
     */
    public int getBucketCount(Long skuId, Integer channelId) {
        String metaKey = BUCKET_META_KEY + skuId + ":" + channelId;
        Object count = redisTemplate.opsForHash().get(metaKey, "bucketCount");
        return count == null ? 0 : Integer.parseInt(count.toString());
    }
}
```

#### 9.3.3 分桶下的Lua脚本扣减

```java
/**
 * 分桶库存扣减服务
 *
 * 扣减策略：
 * 1. 随机选一个桶尝试扣减
 * 2. 桶内库存不足，尝试下一个桶（最多遍历所有桶）
 * 3. 所有桶都不足，尝试从主库存扣减（兜底）
 */
@Service
@Slf4j
public class BucketDeductService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private InventoryBucketService bucketService;

    @Autowired
    private RocketMQTemplate mqTemplate;

    @Autowired
    private InventoryDegradeService degradeService;

    /**
     * 分桶扣减Lua脚本
     * KEYS[1] = 桶库存Hash: inv:bucket:{skuId}:{channelId}:{bucketIndex}
     * ARGV[1] = quantity
     * ARGV[2] = orderId
     *
     * 返回值：
     *   1  = 扣减成功
     *  -1  = 桶内库存不足
     *  -2  = 桶不存在
     */
    private static final String BUCKET_DEDUCT_LUA =
        "if redis.call('EXISTS', KEYS[1]) == 0 then\n" +
        "    return -2\n" +
        "end\n" +
        "local available = tonumber(redis.call('HGET', KEYS[1], 'availableStock'))\n" +
        "local qty = tonumber(ARGV[1])\n" +
        "if available < qty then\n" +
        "    return -1\n" +
        "end\n" +
        "redis.call('HINCRBY', KEYS[1], 'availableStock', -qty)\n" +
        "redis.call('HINCRBY', KEYS[1], 'frozenStock', qty)\n" +
        "return 1\n";

    /**
     * 分桶扣减库存
     */
    public DeductResult deduct(Long skuId, Integer channelId,
                                int quantity, Long orderId) {
        // 检查是否已分桶
        if (!bucketService.isBucketed(skuId, channelId)) {
            // 未分桶，走普通扣减流程
            return degradeService.deductViaRedis(skuId, channelId, quantity, orderId);
        }

        int bucketCount = bucketService.getBucketCount(skuId, channelId);
        List<Integer> bucketOrder = getRandomBucketOrder(bucketCount);

        DefaultRedisScript<Long> script = new DefaultRedisScript<>();
        script.setScriptText(BUCKET_DEDUCT_LUA);
        script.setResultType(Long.class);

        // 遍历桶，逐个尝试扣减
        for (int bucketIndex : bucketOrder) {
            String bucketKey = "inv:bucket:" + skuId + ":" + channelId + ":" + bucketIndex;

            try {
                Long result = redisTemplate.execute(script,
                    Collections.singletonList(bucketKey),
                    String.valueOf(quantity),
                    String.valueOf(orderId));

                if (result != null && result == 1L) {
                    // 扣减成功，记录桶号，发MQ异步落库
                    log.info("分桶扣减成功, skuId={}, bucketIndex={}, orderId={}",
                        skuId, bucketIndex, orderId);

                    sendBucketDeductMessage(skuId, channelId, quantity,
                        orderId, bucketIndex);
                    return DeductResult.success();
                }
                // 该桶库存不足，尝试下一个桶
            } catch (Exception e) {
                log.warn("桶扣减异常, bucketIndex={}, skuId={}", bucketIndex, skuId, e);
            }
        }

        // 所有桶都扣减失败
        log.warn("所有桶库存不足, skuId={}, orderId={}, quantity={}",
            skuId, orderId, quantity);
        return DeductResult.fail("STOCK_INSUFFICIENT", "库存不足");
    }

    /**
     * 发送分桶扣减MQ消息（携带桶号）
     */
    private void sendBucketDeductMessage(Long skuId, Integer channelId,
            int quantity, Long orderId, int bucketIndex) {
        BucketDeductMessage msg = new BucketDeductMessage();
        msg.setSkuId(skuId);
        msg.setChannelId(channelId);
        msg.setQuantity(quantity);
        msg.setOrderId(orderId);
        msg.setBucketIndex(bucketIndex);
        msg.setBizType("BUCKET_DEDUCT");
        msg.setTimestamp(System.currentTimeMillis());

        try {
            mqTemplate.asyncSend("inventory-bucket-deduct-topic", msg, new SendCallback() {
                @Override
                public void onSuccess(SendResult r) {
                    log.info("分桶扣减MQ发送成功, orderId={}, bucketIndex={}",
                        orderId, bucketIndex);
                }
                @Override
                public void onException(Throwable e) {
                    log.error("分桶扣减MQ发送失败, orderId={}, bucketIndex={}",
                        orderId, bucketIndex, e);
                }
            });
        } catch (Exception e) {
            log.error("分桶扣减MQ发送异常, orderId={}", orderId, e);
        }
    }

    private List<Integer> getRandomBucketOrder(int bucketCount) {
        List<Integer> indexes = new ArrayList<>();
        for (int i = 0; i < bucketCount; i++) {
            indexes.add(i);
        }
        Collections.shuffle(indexes);
        return indexes;
    }
}
```

#### 9.3.4 桶间库存再平衡

```java
/**
 * 桶间库存再平衡服务
 *
 * 问题：分桶后某些桶先卖完，其他桶还有库存，导致扣减失败率上升
 * 方案：定期检查各桶库存，将库存从余量多的桶调拨到余量少的桶
 *
 * 触发条件：
 * 1. 某个桶库存为0，其他桶还有库存
 * 2. 各桶库存差异超过阈值（如最大桶 > 最小桶 * 3）
 */
@Service
@Slf4j
public class BucketRebalanceService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private InventoryBucketService bucketService;

    /** 库存差异阈值倍数 */
    private static final int DIFF_THRESHOLD = 3;

    /**
     * 每30秒检查一次桶间平衡
     */
    @Scheduled(fixedRate = 30000)
    public void rebalance() {
        // 1. 获取所有活跃的分桶商品
        Set<String> metaKeys = redisTemplate.keys("inv:bucket:meta:*");
        if (metaKeys == null || metaKeys.isEmpty()) {
            return;
        }

        for (String metaKey : metaKeys) {
            try {
                Object status = redisTemplate.opsForHash().get(metaKey, "status");
                if (!"ACTIVE".equals(status)) {
                    continue;
                }

                // 解析skuId和channelId
                String[] parts = metaKey.replace("inv:bucket:meta:", "").split(":");
                Long skuId = Long.parseLong(parts[0]);
                Integer channelId = Integer.parseInt(parts[1]);

                rebalanceBuckets(skuId, channelId);
            } catch (Exception e) {
                log.error("桶间再平衡异常, metaKey={}", metaKey, e);
            }
        }
    }

    /**
     * 对指定SKU的桶进行再平衡
     */
    private void rebalanceBuckets(Long skuId, Integer channelId) {
        int bucketCount = bucketService.getBucketCount(skuId, channelId);
        if (bucketCount == 0) return;

        // 1. 收集各桶库存
        List<Integer> bucketStocks = new ArrayList<>();
        int totalAvailable = 0;
        for (int i = 0; i < bucketCount; i++) {
            String bucketKey = "inv:bucket:" + skuId + ":" + channelId + ":" + i;
            Object stock = redisTemplate.opsForHash().get(bucketKey, "availableStock");
            int s = stock == null ? 0 : Integer.parseInt(stock.toString());
            bucketStocks.add(s);
            totalAvailable += s;
        }

        if (totalAvailable == 0) {
            return; // 所有桶都空了
        }

        // 2. 检查是否需要再平衡
        int maxStock = Collections.max(bucketStocks);
        int minStock = Collections.min(bucketStocks);

        // 最大桶是最小桶的3倍以上，或者有桶为0但总量不为0
        boolean needRebalance = (minStock == 0 && maxStock > 0)
            || (minStock > 0 && maxStock > minStock * DIFF_THRESHOLD);

        if (!needRebalance) {
            return;
        }

        // 3. 重新均匀分配
        int avgStock = totalAvailable / bucketCount;
        int remainder = totalAvailable % bucketCount;

        log.info("触发桶间再平衡, skuId={}, totalAvailable={}, before={}, after avg={}",
            skuId, totalAvailable, bucketStocks, avgStock);

        for (int i = 0; i < bucketCount; i++) {
            String bucketKey = "inv:bucket:" + skuId + ":" + channelId + ":" + i;
            int targetStock = avgStock + (i < remainder ? 1 : 0);
            int currentStock = bucketStocks.get(i);
            int delta = targetStock - currentStock;

            if (delta != 0) {
                redisTemplate.opsForHash().increment(bucketKey, "availableStock", delta);
                log.info("桶再平衡, skuId={}, bucket={}, {}→{}",
                    skuId, i, currentStock, targetStock);
            }
        }
    }
}
```

#### 9.3.5 分桶合并回主库存

```java
/**
 * 分桶合并服务
 *
 * 活动结束后（分桶商品的QPS低于阈值或活动结束），将各桶剩余库存合并回主库存
 *
 * 合并流程：
 * 1. 冻结所有桶（不再接受新的分桶扣减）
 * 2. 将各桶剩余库存汇总
 * 3. 写回主库存（Redis + MySQL）
 * 4. 删除桶数据
 * 5. 更新分桶元数据状态为MERGED
 */
@Service
@Slf4j
public class BucketMergeService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private InventoryBucketService bucketService;

    @Autowired
    private InventoryMapper inventoryMapper;

    @Autowired
    private HotItemDetectService hotItemDetectService;

    /**
     * 每5分钟检查一次：QPS低于阈值时触发合并
     */
    @Scheduled(fixedRate = 300000)
    public void checkAndMerge() {
        Set<String> metaKeys = redisTemplate.keys("inv:bucket:meta:*");
        if (metaKeys == null || metaKeys.isEmpty()) {
            return;
        }

        for (String metaKey : metaKeys) {
            try {
                Object status = redisTemplate.opsForHash().get(metaKey, "status");
                if (!"ACTIVE".equals(status)) {
                    continue;
                }

                String[] parts = metaKey.replace("inv:bucket:meta:", "").split(":");
                Long skuId = Long.parseLong(parts[0]);
                Integer channelId = Integer.parseInt(parts[1]);

                // 检查QPS是否已降低（非热点了）
                int currentQps = hotItemDetectService.getCurrentQps(skuId, channelId);
                if (currentQps < 200) {
                    // QPS已降低，触发合并
                    mergeBuckets(skuId, channelId);
                }
            } catch (Exception e) {
                log.error("分桶合并检查异常, metaKey={}", metaKey, e);
            }
        }
    }

    /**
     * 合并分桶回主库存
     */
    @Transactional(rollbackFor = Exception.class)
    public void mergeBuckets(Long skuId, Integer channelId) {
        int bucketCount = bucketService.getBucketCount(skuId, channelId);
        if (bucketCount == 0) return;

        log.info("开始合并分桶, skuId={}, channelId={}, bucketCount={}",
            skuId, channelId, bucketCount);

        // 1. 标记为MERGING状态，拒绝新的分桶扣减
        String metaKey = "inv:bucket:meta:" + skuId + ":" + channelId;
        redisTemplate.opsForHash().put(metaKey, "status", "MERGING");

        // 2. 汇总各桶剩余库存
        int totalAvailable = 0;
        int totalFrozen = 0;
        for (int i = 0; i < bucketCount; i++) {
            String bucketKey = "inv:bucket:" + skuId + ":" + channelId + ":" + i;
            Object available = redisTemplate.opsForHash().get(bucketKey, "availableStock");
            Object frozen = redisTemplate.opsForHash().get(bucketKey, "frozenStock");

            totalAvailable += available == null ? 0 : Integer.parseInt(available.toString());
            totalFrozen += frozen == null ? 0 : Integer.parseInt(frozen.toString());
        }

        // 3. 写回Redis主库存
        String mainKey = "inv:" + skuId + ":" + channelId;
        Map<String, String> mainFields = new HashMap<>();
        mainFields.put("availableStock", String.valueOf(totalAvailable));
        mainFields.put("frozenStock", String.valueOf(totalFrozen));
        redisTemplate.opsForHash().putAll(mainKey, mainFields);

        // 4. 更新MySQL主库存（取消分桶标记，恢复可用库存）
        inventoryMapper.unmarkBucketed(skuId, channelId, totalAvailable);

        // 5. 删除桶数据
        for (int i = 0; i < bucketCount; i++) {
            String bucketKey = "inv:bucket:" + skuId + ":" + channelId + ":" + i;
            redisTemplate.delete(bucketKey);
        }

        // 6. 更新分桶元数据
        redisTemplate.opsForHash().put(metaKey, "status", "MERGED");
        redisTemplate.opsForHash().put(metaKey, "mergeTime",
            String.valueOf(System.currentTimeMillis()));

        log.info("分桶合并完成, skuId={}, channelId={}, mergedAvailable={}, mergedFrozen={}",
            skuId, channelId, totalAvailable, totalFrozen);
    }
}
```

#### 9.3.6 分桶扣减MQ消费者

```java
/**
 * 分桶扣减消费者
 *
 * 与普通扣减消费者类似，但需要记录桶号
 * MySQL层面不分桶，所有桶的扣减最终汇总到主库存行
 */
@Component
@RocketMQMessageListener(topic = "inventory-bucket-deduct-topic",
    consumerGroup = "inventory-bucket-deduct-consumer-group",
    maxReconsumeTimes = 3)
@Slf4j
public class BucketDeductConsumer implements RocketMQListener<BucketDeductMessage> {

    @Autowired
    private InventoryMapper inventoryMapper;

    @Autowired
    private InventoryLogMapper logMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Override
    public void onMessage(BucketDeductMessage msg) {
        log.info("收到分桶扣减MQ, orderId={}, skuId={}, bucketIndex={}",
            msg.getOrderId(), msg.getSkuId(), msg.getBucketIndex());
        try {
            processBucketDeduct(msg);
        } catch (Exception e) {
            log.error("分桶扣减消费异常, orderId={}", msg.getOrderId(), e);
            throw e;
        }
    }

    @Transactional(rollbackFor = Exception.class)
    public void processBucketDeduct(BucketDeductMessage msg) {
        // 1. 幂等检查
        InventoryLog existLog = logMapper.selectByOrderAndBiz(
            msg.getOrderId(), msg.getBizType());
        if (existLog != null) {
            log.info("分桶扣减已处理，跳过. orderId={}", msg.getOrderId());
            return;
        }

        // 2. 查询MySQL主库存
        InventoryDO inventory = inventoryMapper.selectBySkuAndChannel(
            msg.getSkuId(), msg.getChannelId());
        if (inventory == null) {
            log.error("MySQL库存记录不存在! skuId={}", msg.getSkuId());
            rollbackBucketRedis(msg);
            return;
        }

        // 3. MySQL库存二次校验
        // 注意：分桶模式下MySQL主库存的availableStock可能为0（库存已分配到桶）
        // 实际可用 = MySQL主库存availableStock + 各桶剩余
        // 因此MySQL层面做"总库存"校验：soldStock + quantity <= totalStock
        if (inventory.getTotalStock() - inventory.getSoldStock() < msg.getQuantity()) {
            log.error("MySQL总库存不足，回滚桶Redis. skuId={}, orderId={}",
                msg.getSkuId(), msg.getOrderId());
            rollbackBucketRedis(msg);
            return;
        }

        // 4. 乐观锁扣减（增加soldStock，减少frozenStock由归还时处理）
        int beforeSold = inventory.getSoldStock();
        int afterSold = beforeSold + msg.getQuantity();

        int updated = inventoryMapper.increaseSoldWithVersion(
            msg.getSkuId(), msg.getChannelId(),
            msg.getQuantity(), inventory.getVersion());

        if (updated == 0) {
            throw new RuntimeException("乐观锁冲突，需要重试. orderId=" + msg.getOrderId());
        }

        // 5. 插入流水（记录桶号）
        InventoryLog log = new InventoryLog();
        log.setSkuId(msg.getSkuId());
        log.setChannelId(msg.getChannelId());
        log.setOrderId(msg.getOrderId());
        log.setBizType(msg.getBizType());
        log.setQuantity(msg.getQuantity());
        log.setBeforeStock(beforeSold);
        log.setAfterStock(afterSold);
        log.setCreateTime(new Date());
        // 扩展字段记录桶号（需在inventory_log表增加bucket_index字段）
        // log.setBucketIndex(msg.getBucketIndex());
        logMapper.insert(log);

        log.info("分桶扣减MySQL落库成功, orderId={}, bucketIndex={}, soldStock: {}→{}",
            msg.getOrderId(), msg.getBucketIndex(), beforeSold, afterSold);
    }

    /**
     * 回滚桶Redis预扣减
     */
    private void rollbackBucketRedis(BucketDeductMessage msg) {
        String bucketKey = "inv:bucket:" + msg.getSkuId() + ":" + msg.getChannelId()
            + ":" + msg.getBucketIndex();
        try {
            redisTemplate.opsForHash().increment(bucketKey, "availableStock", msg.getQuantity());
            redisTemplate.opsForHash().increment(bucketKey, "frozenStock", -msg.getQuantity());
            log.info("桶Redis回滚成功, bucketIndex={}, orderId={}",
                msg.getBucketIndex(), msg.getOrderId());
        } catch (Exception e) {
            log.error("桶Redis回滚失败! bucketIndex={}, orderId={}",
                msg.getBucketIndex(), msg.getOrderId(), e);
        }
    }
}
```

### 案例小结

| 案例 | 核心链路 | 关键保障 |
|------|---------|---------|
| 下单扣减 | Controller校验 → Redis幂等 → Lua预扣减 → MQ异步落库 → 乐观锁扣减 | 幂等标记 + Lua原子性 + 乐观锁 + 流水防重 + 失败回滚 |
| 库存归还 | 归还幂等(双层) → Redis原子归还 → MQ异步落库 → MySQL增加 → 对账校验 | 双层幂等(Redis+MySQL) + 归还前校验扣减流水 + 单订单对账 |
| 分桶扣减 | 热点检测 → 自动分桶 → 随机选桶Lua扣减 → 桶间再平衡 → 活动后合并 | 随机分散热点 + 桶间再平衡 + 合并回主库存 + 桶号记录可追溯 |
