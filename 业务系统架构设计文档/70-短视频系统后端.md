# 短视频系统后端架构设计

## 一、问题背景

### 1.1 行业现状与技术挑战

短视频已成为互联网内容消费的主流形态。截至近年统计，短视频用户规模已超过9亿，占网民整体的93.4%。短视频平台的核心技术挑战体现在以下几个方面：

1. **海量数据处理**：每天数百万条视频上传，单条1080p未压缩视频每分钟约11GB，90分钟电影约1000GB，数据压缩与高效存储是首要问题。
2. **实时性要求**：用户期望视频上传后秒级可见、播放秒开（首帧<1s），对系统的端到端延迟提出了极高要求。
3. **高并发访问**：热门视频可能在短时间内达到百万级并发播放，CDN分发和负载均衡是必须解决的核心问题。
4. **内容质量保障**：UGC内容质量参差不齐，需要自动化的视频质量评价、封面生成、内容去重等能力。
5. **推荐精准度**：信息流推荐直接影响用户留存和内容消费效率，召回-排序-重排的级联架构需要持续优化。
6. **成本控制**：带宽和存储是短视频平台最大的成本项，转码压缩、CDN调度、存储分层策略至关重要。

### 1.2 系统设计目标

| 指标维度 | 设计目标 |
|---------|---------|
| 视频上传 | 支持最大5GB单文件，分片并行上传，断点续传，上传成功率>99.9% |
| 视频转码 | 支持H.264/H.265多分辨率转码，窄带高清压缩比提升30%+ |
| 推荐延迟 | 端到端推荐响应<200ms（P99） |
| 播放体验 | 首帧加载<1s，卡顿率<5%，播放成功率>99.5% |
| 系统可用性 | 整体可用性>99.99%，核心链路具备降级和容灾能力 |
| 数据一致性 | 播放量、互动数据最终一致，延迟<5s |

### 1.3 核心业务场景

短视频系统后端需要覆盖以下核心业务场景：

- **视频生产链路**：上传 → 转码 → 审核 → 入库 → 分发
- **视频消费链路**：推荐 → 播放 → 互动 → 数据采集
- **内容运营链路**：封面生成 → 去重检测 → 质量评价 → 标签提取
- **数据分析链路**：播放统计 → 完播率分析 → 用户画像更新

### 2.2 核心数据流

视频从生产到消费的完整数据流如下：

```

    → 分片上传(S3对象存储)
    → 转码服务(多分辨率/多码率)
    → 内容审核(机器审核+人工审核)
    → 封面生成(抽帧+AI选帧)
    → 去重检测(MD5+pHash)
    → 元信息入库(MySQL+ES)
    → CDN预热分发
    → 推荐引擎(召回→粗排→精排→重排)
    → 播放服务(CDN边缘节点就近分发)
    → 数据采集(播放量/完播率/互动)
```

## 三、核心链路设计

### 3.1 视频上传：分片上传与断点续传

#### 3.1.1 问题分析

视频文件通常体积较大（几十MB到几GB），在移动网络环境下面临三大挑战：

1. **网络不稳定**：移动网络丢包率高，大文件上传容易中途失败
2. **上传耗时长**：大文件单次上传耗时可达数分钟，用户体验差
3. **失败代价高**：普通上传失败需要从头重传，浪费已上传的数据

#### 3.1.2 分片上传协议设计

分片上传将大文件切分为多个小块（Part），分别上传后在服务端合并。核心流程分为四步：

**第一步：初始化上传任务（InitiateMultipartUpload）**

客户端请求服务端创建一个分片上传任务，服务端返回全局唯一的`uploadId`。

```java
/**
 * 分片上传管理器
 * 负责协调分片上传的全生命周期：初始化、分片传输、合并、断点续传
 */
public class MultipartUploadManager {

    private final ObjectStorageClient storageClient;
    private final RedisTemplate<String, String> redisTemplate;
    private final int defaultPartSize = 5 * 1024 * 1024; // 5MB 每片

    /**
     * 初始化分片上传任务
     * 服务端生成 uploadId 并记录任务元信息到 Redis
     */
    public InitUploadResult initiateUpload(String userId, String fileName,
                                           long fileSize, String fileMd5) {
        // 1. 检查是否存在未完成的上传任务（秒传 + 断点续传）
        String existingUploadId = redisTemplate.opsForValue()
                .get("upload:resume:" + userId + ":" + fileMd5);
        if (existingUploadId != null) {
            // 存在历史任务，返回已上传分片信息，支持断点续传
            List<PartInfo> uploadedParts = listUploadedParts(existingUploadId);
            return new InitUploadResult(existingUploadId, uploadedParts,
                    calculatePartCount(fileSize), true);
        }

        // 2. 检查文件MD5是否已存在（秒传）
        String existingVideoId = redisTemplate.opsForValue()
                .get("file:md5:" + fileMd5);
        if (existingVideoId != null) {
            return new InitUploadResult(existingVideoId, true); // 秒传成功
        }

        // 3. 初始化新的分片上传任务
        String uploadId = storageClient.initiateMultipartUpload(
                buildObjectKey(userId, fileName));

        // 4. 记录任务元信息到 Redis，设置3天过期
        UploadTaskMeta meta = new UploadTaskMeta(uploadId, userId,
                fileName, fileSize, fileMd5,
                calculatePartCount(fileSize));
        redisTemplate.opsForValue().set(
                "upload:task:" + uploadId,
                JSON.toJSONString(meta),
                3, TimeUnit.DAYS);

        // 5. 记录用户+文件MD5与uploadId的映射，用于断点续传
        redisTemplate.opsForValue().set(
                "upload:resume:" + userId + ":" + fileMd5,
                uploadId,
                3, TimeUnit.DAYS);

        return new InitUploadResult(uploadId, Collections.emptyList(),
                meta.getTotalParts(), false);
    }

    private int calculatePartCount(long fileSize) {
        return (int) Math.ceil((double) fileSize / defaultPartSize);
    }
}
```

**第二步：并行上传分片（UploadPart）**

每个分片独立上传，可以多线程并行执行，失败的分片独立重试不影响其他分片。

```java
/**
 * 分片上传执行器
 * 支持并行上传、单片重试、进度回调
 */
public class PartUploadExecutor {

    private final ObjectStorageClient storageClient;
    private final ExecutorService uploadPool;
    private final RedisTemplate<String, String> redisTemplate;
    private static final int MAX_RETRY = 3;
    private static final int CONCURRENT_PARTS = 4; // 并行上传数

    public PartUploadExecutor(ObjectStorageClient storageClient,
                              RedisTemplate<String, String> redisTemplate) {
        this.storageClient = storageClient;
        this.redisTemplate = redisTemplate;
        // 使用有界线程池控制并发度，避免移动端资源耗尽
        this.uploadPool = new ThreadPoolExecutor(
                CONCURRENT_PARTS, CONCURRENT_PARTS,
                60L, TimeUnit.SECONDS,
                new LinkedBlockingQueue<>(100),
                new ThreadPoolExecutor.CallerRunsPolicy());
    }

    /**
     * 并行上传所有未完成的分片
     * @param uploadId 上传任务ID
     * @param file 待上传文件
     * @param uploadedParts 已上传的分片列表（断点续传场景）
     * @param progressCallback 进度回调
     */
    public CompletableFuture<List<PartETag>> uploadAllParts(
            String uploadId, File file,
            List<PartInfo> uploadedParts,
            UploadProgressCallback progressCallback) {

        long fileSize = file.length();
        int partSize = 5 * 1024 * 1024; // 5MB
        int totalParts = (int) Math.ceil((double) fileSize / partSize);

        // 构建已上传分片号集合，跳过已完成的分片
        Set<Integer> completedPartNumbers = uploadedParts.stream()
                .map(PartInfo::getPartNumber)
                .collect(Collectors.toSet());

        AtomicInteger completedCount = new AtomicInteger(completedPartNumbers.size());
        List<CompletableFuture<PartETag>> futures = new ArrayList<>();

        for (int partNumber = 1; partNumber <= totalParts; partNumber++) {
            if (completedPartNumbers.contains(partNumber)) {
                continue; // 跳过已上传的分片
            }

            final int currentPart = partNumber;
            long offset = (long) (currentPart - 1) * partSize;
            long length = Math.min(partSize, fileSize - offset);

            CompletableFuture<PartETag> future = CompletableFuture.supplyAsync(() ->
                    uploadSinglePartWithRetry(uploadId, file, currentPart,
                            offset, length, MAX_RETRY),
                    uploadPool
            ).thenApply(etag -> {
                // 更新上传进度
                int done = completedCount.incrementAndGet();
                progressCallback.onProgress(done, totalParts);

                // 记录已完成分片到 Redis（支持断点续传）
                redisTemplate.opsForHash().put(
                        "upload:parts:" + uploadId,
                        String.valueOf(currentPart),
                        etag.getETag());
                return etag;
            });

            futures.add(future);
        }

        return CompletableFuture.allOf(futures.toArray(new CompletableFuture[0]))
                .thenApply(v -> futures.stream()
                        .map(CompletableFuture::join)
                        .collect(Collectors.toList()));
    }

    /**
     * 单片上传，带重试机制
     * 采用指数退避策略：第1次重试等待1s，第2次等待2s，第3次等待4s
     */
    private PartETag uploadSinglePartWithRetry(String uploadId, File file,
                                               int partNumber, long offset,
                                               long length, int maxRetry) {
        int attempt = 0;
        while (true) {
            try {
                byte[] data = readFileChunk(file, offset, length);
                String etag = storageClient.uploadPart(uploadId, partNumber, data);
                return new PartETag(partNumber, etag);
            } catch (Exception e) {
                attempt++;
                if (attempt >= maxRetry) {
                    throw new UploadPartException(
                            "Part " + partNumber + " upload failed after "
                            + maxRetry + " retries", e);
                }
                // 指数退避
                try {
                    Thread.sleep((long) Math.pow(2, attempt - 1) * 1000);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw new UploadPartException("Upload interrupted", ie);
                }
            }
        }
    }

    private byte[] readFileChunk(File file, long offset, long length)
            throws IOException {
        try (RandomAccessFile raf = new RandomAccessFile(file, "r")) {
            raf.seek(offset);
            byte[] buffer = new byte[(int) length];
            raf.readFully(buffer);
            return buffer;
        }
    }
}
```

**第三步：完成上传（CompleteMultipartUpload）**

所有分片上传完成后，调用合并接口，服务端按照`partNumber`顺序将分片合并为完整文件。

```java
/**
 * 完成分片上传，触发后续处理流水线
 */
public CompleteUploadResult completeUpload(String uploadId,
                                          List<PartETag> partETags) {
    // 1. 校验所有分片是否齐全
    UploadTaskMeta meta = getTaskMeta(uploadId);
    if (partETags.size() != meta.getTotalParts()) {
        throw new IncompleteUploadException(
                "Expected " + meta.getTotalParts()
                + " parts, got " + partETags.size());
    }

    // 2. 按 partNumber 排序后调用存储服务合并
    partETags.sort(Comparator.comparingInt(PartETag::getPartNumber));
    String objectKey = storageClient.completeMultipartUpload(
            uploadId, partETags);

    // 3. 生成视频ID，写入视频元信息表
    String videoId = IdGenerator.nextId();
    VideoMeta videoMeta = VideoMeta.builder()
            .videoId(videoId)
            .userId(meta.getUserId())
            .objectKey(objectKey)
            .fileSize(meta.getFileSize())
            .fileMd5(meta.getFileMd5())
            .status(VideoStatus.UPLOADED)
            .createTime(System.currentTimeMillis())
            .build();
    videoMetaDao.insert(videoMeta);

    // 4. 记录文件MD5映射，支持后续秒传
    redisTemplate.opsForValue().set(
            "file:md5:" + meta.getFileMd5(), videoId);

    // 5. 发送MQ消息，触发转码流水线
    TranscodeMessage msg = new TranscodeMessage(videoId, objectKey);
    mqProducer.send("topic_video_transcode", msg);

    // 6. 清理上传任务的临时数据
    cleanupUploadTask(uploadId, meta);

    return new CompleteUploadResult(videoId, VideoStatus.UPLOADED);
}
```

**第四步：断点续传机制**

断点续传的核心思想是：上传任务的元信息和已完成分片列表持久化到 Redis，客户端重新打开时通过`ListParts`接口查询已完成分片，从断点继续上传。

```java
/**
 * 断点续传：查询已上传的分片列表
 * 客户端重启后调用此接口，获取已完成分片号，跳过已上传部分
 */
public ResumeUploadInfo getResumeInfo(String userId, String fileMd5) {
    // 1. 查找未完成的上传任务
    String uploadId = redisTemplate.opsForValue()
            .get("upload:resume:" + userId + ":" + fileMd5);
    if (uploadId == null) {
        return ResumeUploadInfo.notFound();
    }

    // 2. 获取任务元信息
    UploadTaskMeta meta = getTaskMeta(uploadId);
    if (meta == null || meta.isExpired()) {
        return ResumeUploadInfo.expired();
    }

    // 3. 查询已上传的分片列表
    List<PartInfo> uploadedParts = listUploadedParts(uploadId);

    // 4. 计算上传进度
    double progress = (double) uploadedParts.size() / meta.getTotalParts();

    return ResumeUploadInfo.builder()
            .uploadId(uploadId)
            .uploadedParts(uploadedParts)
            .totalParts(meta.getTotalParts())
            .progress(progress)
            .build();
}

/**
 * 从 Redis 和对象存储中获取已上传的分片信息
 */
private List<PartInfo> listUploadedParts(String uploadId) {
    // 优先从 Redis 缓存读取
    Map<Object, Object> cachedParts = redisTemplate.opsForHash()
            .entries("upload:parts:" + uploadId);
    if (!cachedParts.isEmpty()) {
        return cachedParts.entrySet().stream()
                .map(e -> new PartInfo(
                        Integer.parseInt(e.getKey().toString()),
                        e.getValue().toString()))
                .sorted(Comparator.comparingInt(PartInfo::getPartNumber))
                .collect(Collectors.toList());
    }

    // 回退到对象存储查询
    return storageClient.listParts(uploadId).stream()
            .map(p -> new PartInfo(p.getPartNumber(), p.getETag()))
            .collect(Collectors.toList());
}
```

#### 3.1.3 分片上传的设计要点

| 设计要点 | 说明 |
|---------|------|
| 分片大小 | 每片5MB（最后一片可小于5MB），最大支持10000片，即最大50GB |
| 并发控制 | 移动端建议4并发，弱网环境降为2并发 |

| 过期机制 | 未完成的上传任务默认3天后自动清理，避免存储空间浪费 |
| 秒传判断 | 通过文件整体MD5判断，已存在的文件直接返回videoId |

### 3.2 视频转码：多分辨率与多码率自适应（ABR）

#### 3.2.1 问题分析

用户上传的原始视频格式、编码标准、分辨率各不相同，直接播放会面临：
- 不同终端设备兼容性问题（部分设备不支持某些编码格式）
- 不同网络环境下的播放体验问题（高码率视频在弱网下卡顿严重）
- 带宽成本问题（未优化的视频码率远高于必要水平）

转码的核心目标是：将原始视频转换为多种分辨率、多种码率的标准格式，适应不同终端和网络环境。

#### 3.2.2 转码流水线设计

转码流水线采用异步消息驱动模式，上传完成后通过MQ触发转码任务。

```java
/**
 * 转码任务调度器
 * 接收上传完成的MQ消息，生成转码任务并分发到转码集群
 */
@Component
public class TranscodeDispatcher {

    @Autowired
    private TranscodeProfileManager profileManager;
    @Autowired
    private TranscodeTaskDao taskDao;
    @Autowired
    private TranscodeWorkerRouter workerRouter;

    /**
     * 监听上传完成消息，创建转码任务
     */
    @RocketMQListener(topic = "topic_video_transcode",
                      consumerGroup = "cg_transcode_dispatcher")
    public void onVideoUploaded(TranscodeMessage msg) {
        String videoId = msg.getVideoId();
        String sourceKey = msg.getObjectKey();

        // 1. 探测原始视频的元信息
        VideoProbeResult probeResult = probeVideo(sourceKey);

        // 2. 根据原始视频参数，确定转码配置（转码模板）
        List<TranscodeProfile> profiles = profileManager
                .selectProfiles(probeResult);

        // 3. 为每个转码配置创建子任务
        String taskGroupId = IdGenerator.nextId();
        List<TranscodeTask> tasks = new ArrayList<>();

        for (TranscodeProfile profile : profiles) {
            TranscodeTask task = TranscodeTask.builder()
                    .taskId(IdGenerator.nextId())
                    .taskGroupId(taskGroupId)
                    .videoId(videoId)
                    .sourceKey(sourceKey)
                    .profile(profile)
                    .status(TaskStatus.PENDING)
                    .createTime(System.currentTimeMillis())
                    .build();
            tasks.add(task);
        }

        // 4. 批量入库
        taskDao.batchInsert(tasks);

        // 5. 分发到转码Worker（根据负载选择节点）
        for (TranscodeTask task : tasks) {
            TranscodeWorkerNode worker = workerRouter
                    .selectWorker(task.getProfile());
            workerRouter.dispatch(worker, task);
        }
    }

    /**
     * 探测视频元信息：编码格式、分辨率、码率、帧率、时长等
     * 底层调用 FFprobe 命令
     */
    private VideoProbeResult probeVideo(String sourceKey) {
        // 从对象存储下载视频头部数据（前1MB足够探测元信息）
        byte[] header = storageClient.getObjectRange(sourceKey, 0, 1024 * 1024);
        Path tempFile = writeTempFile(header);

        try {
            // 调用 FFprobe 分析视频元信息
            ProcessBuilder pb = new ProcessBuilder(
                    "ffprobe", "-v", "quiet",
                    "-print_format", "json",
                    "-show_format", "-show_streams",
                    tempFile.toString());
            Process process = pb.start();
            String output = readProcessOutput(process);
            return VideoProbeResult.parse(output);
        } finally {
            Files.deleteIfExists(tempFile);
        }
    }
}
```

#### 3.2.3 转码配置选择策略

根据原始视频的分辨率和码率，自动选择合适的转码配置列表。遵循"不超过原始分辨率"原则——不对低分辨率视频做升采样转码。

```java
/**
 * 转码配置管理器
 * 根据原始视频参数自动选择转码模板
 */
@Component
public class TranscodeProfileManager {

    /**
     * 预定义的转码配置表
     * 每种分辨率对应一组码率梯度，支持ABR自适应切换
     */
    private static final List<TranscodeProfile> ALL_PROFILES = Arrays.asList(
        // 分辨率        视频编码    视频码率   音频码率  帧率  GOP
        profile("1080p", "h264",    4000,      128,     30,   60),
        profile("1080p", "h265",    2500,      128,     30,   60), // H.265窄带高清
        profile("720p",  "h264",    2000,      96,      30,   60),
        profile("720p",  "h265",    1200,      96,      30,   60),
        profile("480p",  "h264",    1000,      64,      30,   60),
        profile("480p",  "h265",    600,       64,      30,   60),
        profile("360p",  "h264",    500,       48,      25,   50)
    );

    /**
     * 根据原始视频参数选择转码配置
     * 核心规则：
     *   1. 不对低分辨率视频做升采样（即不转出超过原始分辨率的版本）
     *   2. 至少保留一个 H.264 版本确保兼容性
     *   3. H.265 版本用于支持高压缩比的终端
     */
    public List<TranscodeProfile> selectProfiles(VideoProbeResult source) {
        int sourceHeight = source.getHeight();
        long sourceBitrate = source.getBitrate();

        List<TranscodeProfile> selected = new ArrayList<>();

        for (TranscodeProfile profile : ALL_PROFILES) {
            int profileHeight = parseHeight(profile.getResolution());

            // 规则1：不超过原始分辨率
            if (profileHeight > sourceHeight) {
                continue;
            }

            // 规则2：目标码率不超过原始码率的1.5倍
            // （避免对低码率视频转出更高码率的无意义版本）
            if (profile.getVideoBitrate() > sourceBitrate * 1.5) {
                continue;
            }

            selected.add(profile);
        }

        // 规则3：至少保留一个最低分辨率版本
        if (selected.isEmpty()) {
            selected.add(ALL_PROFILES.get(ALL_PROFILES.size() - 1));
        }

        return selected;
    }

    private int parseHeight(String resolution) {
        return Integer.parseInt(resolution.replace("p", ""));
    }
}
```

#### 3.2.4 转码Worker执行引擎

转码Worker负责实际的FFmpeg调用，支持H.264/H.265编码、窄带高清、硬件加速等特性。

```java
/**
 * 转码Worker：接收转码任务，调用FFmpeg执行转码
 * 支持软编/硬编自动选择，优先使用GPU硬件加速
 */
@Component
public class TranscodeWorker {

    @Autowired
    private ObjectStorageClient storageClient;
    @Autowired
    private TranscodeTaskDao taskDao;
    @Autowired
    private MQProducer mqProducer;

    /**
     * 执行单个转码任务
     */
    public void executeTask(TranscodeTask task) {
        Path inputFile = null;
        Path outputFile = null;

        try {
            // 1. 更新任务状态为处理中
            taskDao.updateStatus(task.getTaskId(), TaskStatus.PROCESSING);

            // 2. 下载原始视频到本地临时目录
            inputFile = downloadToLocal(task.getSourceKey());

            // 3. 构建 FFmpeg 命令
            outputFile = Files.createTempFile("transcode_", ".mp4");
            List<String> command = buildFFmpegCommand(
                    inputFile, outputFile, task.getProfile());

            // 4. 执行 FFmpeg 转码
            ProcessBuilder pb = new ProcessBuilder(command);
            pb.redirectErrorStream(true);
            Process process = pb.start();

            // 5. 监控转码进度（解析FFmpeg输出中的时间进度）
            monitorProgress(process, task);

            int exitCode = process.waitFor();
            if (exitCode != 0) {
                throw new TranscodeException("FFmpeg exit code: " + exitCode);
            }

            // 6. 上传转码后的文件到对象存储
            String outputKey = buildOutputKey(task);
            storageClient.putObject(outputKey, outputFile.toFile());

            // 7. 更新任务状态
            taskDao.updateStatusAndOutput(task.getTaskId(),
                    TaskStatus.COMPLETED, outputKey);

            // 8. 检查同组任务是否全部完成
            checkAndNotifyGroupComplete(task.getTaskGroupId());

        } catch (Exception e) {
            taskDao.updateStatus(task.getTaskId(), TaskStatus.FAILED);
            // 发送失败告警
            alertService.sendTranscodeFailAlert(task, e);
        } finally {
            // 清理临时文件
            deleteQuietly(inputFile);
            deleteQuietly(outputFile);
        }
    }

    /**
     * 构建FFmpeg转码命令
     * 核心参数：编码器选择、码率控制、GOP设置、音频参数
     */
    private List<String> buildFFmpegCommand(Path input, Path output,
                                            TranscodeProfile profile) {
        List<String> cmd = new ArrayList<>();
        cmd.add("ffmpeg");
        cmd.add("-y"); // 覆盖输出文件

        // 输入参数
        cmd.addAll(Arrays.asList("-i", input.toString()));

        // 视频编码器选择（优先硬编码）
        String videoCodec = selectVideoEncoder(profile);
        cmd.addAll(Arrays.asList("-c:v", videoCodec));

        // 视频分辨率
        String scale = buildScaleFilter(profile.getResolution());
        cmd.addAll(Arrays.asList("-vf", scale));

        // 码率控制：使用ABR（Average Bit Rate）+ VBV缓冲
        // CRF模式保证质量一致性，maxrate+bufsize限制峰值码率
        cmd.addAll(Arrays.asList(
                "-b:v", profile.getVideoBitrate() + "k",
                "-maxrate", (int)(profile.getVideoBitrate() * 1.5) + "k",
                "-bufsize", (profile.getVideoBitrate() * 2) + "k"
        ));

        // 帧率
        cmd.addAll(Arrays.asList("-r", String.valueOf(profile.getFps())));

        // GOP（关键帧间隔）：帧率 * 2秒
        cmd.addAll(Arrays.asList("-g", String.valueOf(profile.getGop())));

        // H.265 特殊参数
        if ("h265".equals(profile.getCodec())) {
            cmd.addAll(Arrays.asList("-tag:v", "hvc1")); // Apple兼容
            // 窄带高清：预设medium平衡速度和质量
            cmd.addAll(Arrays.asList("-preset", "medium"));
        } else {
            // H.264 profile 和 level 设置
            cmd.addAll(Arrays.asList(
                    "-profile:v", "high",
                    "-level", "4.1",
                    "-preset", "medium"
            ));
        }

        // 音频参数
        cmd.addAll(Arrays.asList(
                "-c:a", "aac",
                "-b:a", profile.getAudioBitrate() + "k",
                "-ar", "44100",   // 采样率
                "-ac", "2"        // 双声道
        ));

        // 输出格式
        cmd.addAll(Arrays.asList(
                "-f", "mp4",
                "-movflags", "+faststart" // moov atom前置，支持边下边播
        ));

        cmd.add(output.toString());
        return cmd;
    }

    /**
     * 选择视频编码器
     * 优先使用硬件编码器（NVIDIA NVENC），不可用时回退到软编码
     */
    private String selectVideoEncoder(TranscodeProfile profile) {
        if ("h265".equals(profile.getCodec())) {
            // 检测是否有NVIDIA GPU
            if (isNvencAvailable()) {
                return "hevc_nvenc";  // NVIDIA 硬件编码 H.265
            }
            return "libx265";         // 软件编码 H.265
        } else {
            if (isNvencAvailable()) {
                return "h264_nvenc";  // NVIDIA 硬件编码 H.264
            }
            return "libx264";         // 软件编码 H.264
        }
    }

    /**
     * 构建缩放滤镜
     * 保持原始宽高比，高度对齐到目标分辨率，宽度自适应（取2的倍数）
     */
    private String buildScaleFilter(String resolution) {
        int targetHeight = Integer.parseInt(resolution.replace("p", ""));
        // -2 表示宽度自动计算并取2的倍数（编码器要求）
        return "scale=-2:" + targetHeight;
    }
}
```

#### 3.2.5 HLS多码率自适应（ABR）打包

转码完成后，生成HLS多码率自适应播放列表（Master Playlist），播放器可以根据网络状况实时切换清晰度。

```java
/**
 * HLS ABR 打包器
 * 将多分辨率转码结果打包为 HLS 自适应码率流
 */
@Component
public class HlsAbrPackager {

    /**
     * 生成 HLS Master Playlist
     * Master Playlist 描述了所有可用的码率版本及其带宽信息
     * 播放器根据当前网络带宽自动选择最合适的版本
     */
    public String generateMasterPlaylist(String videoId,
                                         List<TranscodeOutput> outputs) {
        StringBuilder m3u8 = new StringBuilder();
        m3u8.append("#EXTM3U\n");
        m3u8.append("#EXT-X-VERSION:3\n\n");

        // 按带宽从高到低排序
        outputs.sort((a, b) -> Long.compare(
                b.getProfile().getVideoBitrate(),
                a.getProfile().getVideoBitrate()));

        for (TranscodeOutput output : outputs) {
            TranscodeProfile profile = output.getProfile();
            int bandwidth = (profile.getVideoBitrate()
                    + profile.getAudioBitrate()) * 1000; // 转换为 bps
            String resolution = buildResolutionString(profile);
            String codecs = buildCodecsString(profile);

            // EXT-X-STREAM-INF 标签描述了该码率流的参数
            m3u8.append(String.format(
                    "#EXT-X-STREAM-INF:BANDWIDTH=%d,RESOLUTION=%s,CODECS=\"%s\"\n",
                    bandwidth, resolution, codecs));
            m3u8.append(output.getPlaylistUrl()).append("\n\n");
        }

        return m3u8.toString();
    }

    /**
     * 为单个转码结果生成 Media Playlist（TS切片列表）
     * 每个切片时长约为 GOP的倍数（通常2-6秒）
     */
    public String generateMediaPlaylist(TranscodeOutput output,
                                        List<TsSegment> segments) {
        StringBuilder m3u8 = new StringBuilder();
        m3u8.append("#EXTM3U\n");
        m3u8.append("#EXT-X-VERSION:3\n");
        m3u8.append("#EXT-X-TARGETDURATION:").append(
                getMaxSegmentDuration(segments)).append("\n");
        m3u8.append("#EXT-X-MEDIA-SEQUENCE:0\n\n");

        for (TsSegment segment : segments) {
            m3u8.append("#EXTINF:").append(
                    String.format("%.3f", segment.getDuration()))
                 .append(",\n");
            m3u8.append(segment.getUrl()).append("\n");
        }

        m3u8.append("#EXT-X-ENDLIST\n");
        return m3u8.toString();
    }

    private String buildCodecsString(TranscodeProfile profile) {
        if ("h265".equals(profile.getCodec())) {
            return "hvc1.1.6.L120.90,mp4a.40.2"; // HEVC Main Profile
        }
        return "avc1.640029,mp4a.40.2"; // H.264 High Profile Level 4.1
    }

    private String buildResolutionString(TranscodeProfile profile) {
        int height = Integer.parseInt(
                profile.getResolution().replace("p", ""));
        int width = (int)(height * 16.0 / 9); // 假设16:9宽高比
        return width + "x" + height;
    }
```

#### 3.2.6 窄带高清技术

窄带高清是指在清晰度损失可控（SSIM>0.95）的前提下，通过更智能的编码参数调优实现更高压缩比。核心思路是对视频内容进行分析，根据场景复杂度动态调整CRF/QP参数。

```java
/**
 * 窄带高清参数优化器
 * 根据视频内容特征（场景复杂度、运动剧烈程度）动态调整编码参数
 */
@Component
public class NarrowBandHDOptimizer {

    /**
     * 分析视频内容并返回优化后的编码参数
     * 
     * 算法思路：
     * 1. 对视频均匀抽取N帧，计算每帧的空间复杂度（SI）和时间复杂度（TI）
     * 2. SI高表示帧内细节多（如风景），需要更高码率保持细节
     * 3. TI高表示帧间运动剧烈（如体育），需要更高帧率和码率
     * 4. 根据SI和TI综合评分，动态调整CRF值
     */
    public EncodingParams optimize(VideoProbeResult source,
                                   TranscodeProfile baseProfile) {
        // 抽取采样帧
        List<FrameMetrics> frameMetrics = sampleFrames(
                source.getSourceKey(), 20); // 均匀抽20帧

        // 计算空间复杂度（SI）：对每帧应用Sobel滤波后求标准差
        double avgSI = frameMetrics.stream()
                .mapToDouble(FrameMetrics::getSpatialComplexity)
                .average().orElse(50.0);

        // 计算时间复杂度（TI）：相邻帧差分的标准差
        double avgTI = frameMetrics.stream()
                .mapToDouble(FrameMetrics::getTemporalComplexity)
                .average().orElse(30.0);

        // 根据 SI/TI 计算码率调整因子
        // SI 和 TI 归一化到 [0, 1]，加权求和得到复杂度评分
        double normalizedSI = Math.min(avgSI / 100.0, 1.0);
        double normalizedTI = Math.min(avgTI / 80.0, 1.0);
        double complexityScore = 0.6 * normalizedSI + 0.4 * normalizedTI;

        // 动态调整码率
        // 简单场景（如静态画面）可以大幅降低码率，复杂场景保持基础码率
        double bitrateMultiplier = 0.5 + 0.5 * complexityScore;
        int optimizedBitrate = (int)(baseProfile.getVideoBitrate()
                * bitrateMultiplier);

        // 动态调整CRF值
        // CRF范围：18-28，值越小质量越高
        int crf = calculateOptimalCRF(complexityScore);

        return EncodingParams.builder()
                .videoBitrate(optimizedBitrate)
                .crf(crf)
                .preset(complexityScore > 0.7 ? "slow" : "medium")
                .build();
    }

    /**
     * 根据内容复杂度计算最优CRF值
     * 简单场景使用较高CRF（更高压缩比），复杂场景使用较低CRF
     */
    private int calculateOptimalCRF(double complexityScore) {
        // 线性映射：complexityScore 0.0 -> CRF 28, 1.0 -> CRF 18
        return (int)(28 - 10 * complexityScore);
    }
}
```

### 3.3 推荐流：召回 → 粗排 → 精排 → 重排

#### 3.3.1 推荐系统整体架构

短视频推荐系统采用工业界流行的级联架构，形成"漏斗型"筛选流程。每一层在效率和精度之间取不同的平衡点：

```
全量视频库（百万级）
    ↓ 召回层：从百万级候选中快速筛出数千条
候选集（数千条）
    ↓ 粗排层：用轻量模型从数千条精简到数百条
粗排集（数百条）
    ↓ 精排层：用复杂模型对数百条做精确排序
精排集（数十条）
    ↓ 重排层：业务策略调整，去重/打散/多样性
最终推荐结果（数十条，展示给用户）
```

#### 3.3.2 召回层设计

召回层的目标是从百万级视频库中快速（<50ms）筛出用户可能感兴趣的数千条候选。通常采用多路召回策略并行执行，最后合并结果。

```java
/**
 * 多路召回管理器
 * 并行执行多种召回策略，合并去重后返回候选集
 */
@Component
public class RecallManager {

    @Autowired
    private List<RecallStrategy> recallStrategies;
    @Autowired
    private ExecutorService recallExecutor;

    /**
     * 执行多路召回
     * 各路召回策略并行执行，超时50ms强制返回已完成的结果
     */
    public RecallResult multiChannelRecall(UserProfile user,
                                           RecallContext context) {
        // 1. 并行执行所有召回策略
        List<CompletableFuture<List<RecallItem>>> futures = recallStrategies
                .stream()
                .map(strategy -> CompletableFuture.supplyAsync(
                        () -> executeWithTimeout(strategy, user, context),
                        recallExecutor))
                .collect(Collectors.toList());

        // 2. 等待所有策略完成（最长50ms超时）
        CompletableFuture.allOf(futures.toArray(new CompletableFuture[0]))
                .orTimeout(50, TimeUnit.MILLISECONDS)
                .exceptionally(e -> null); // 超时不抛异常

        // 3. 收集已完成的召回结果
        List<RecallItem> allItems = new ArrayList<>();
        for (CompletableFuture<List<RecallItem>> future : futures) {
            if (future.isDone() && !future.isCompletedExceptionally()) {
                allItems.addAll(future.join());
            }
        }

        // 4. 去重（同一视频可能被多路召回命中）
        Map<String, RecallItem> deduped = new LinkedHashMap<>();
        for (RecallItem item : allItems) {
            deduped.merge(item.getVideoId(), item, (existing, newItem) -> {
                // 被多路命中的视频，提高其召回分数
                existing.setScore(existing.getScore() + newItem.getScore());
                existing.addSource(newItem.getSource());
                return existing;
            });
        }

        // 5. 过滤已曝光/已不喜欢的视频
        List<RecallItem> filtered = filterExposedAndBlocked(
                new ArrayList<>(deduped.values()), user);

        return new RecallResult(filtered, allItems.size(),
                filtered.size());
    }

    private List<RecallItem> executeWithTimeout(RecallStrategy strategy,
                                                UserProfile user,
                                                RecallContext context) {
        try {
            return strategy.recall(user, context);
        } catch (Exception e) {
            log.warn("Recall strategy {} failed: {}",
                    strategy.getName(), e.getMessage());
            return Collections.emptyList();
        }
    }
}

/**
 * 协同过滤召回策略（ItemCF）
 * 基于用户历史行为的物品协同过滤
 */
@Component
public class ItemCFRecallStrategy implements RecallStrategy {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Override
    public String getName() {
        return "ItemCF";
    }

    @Override
    public List<RecallItem> recall(UserProfile user, RecallContext context) {
        // 1. 获取用户最近N个正向行为的视频（播放完成/点赞/收藏）
        List<String> seedVideos = user.getRecentPositiveVideos(20);

        // 2. 从 Redis 中查找每个种子视频的相似视频列表
        //    相似度数据由离线 ItemCF 模型每天更新到 Redis
        Set<RecallItem> candidates = new LinkedHashSet<>();
        for (String seedVideoId : seedVideos) {
            String key = "itemcf:sim:" + seedVideoId;
            // ZREVRANGE 获取相似度最高的 TopK
            Set<ZSetOperations.TypedTuple<String>> simVideos =
                    redisTemplate.opsForZSet()
                            .reverseRangeWithScores(key, 0, 50);
            if (simVideos != null) {
                for (ZSetOperations.TypedTuple<String> tuple : simVideos) {
                    candidates.add(new RecallItem(
                            tuple.getValue(),
                            tuple.getScore(),
                            "ItemCF"));
                }
            }
        }

        return new ArrayList<>(candidates);
    }
}

/**

/**
 * 热门召回策略
 * 分城市/分类别的热门视频，解决冷启动和多样性问题
 */
@Component
public class HotRecallStrategy implements RecallStrategy {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Override
    public String getName() {
        return "Hot";
    }

    @Override
    public List<RecallItem> recall(UserProfile user, RecallContext context) {
        List<RecallItem> items = new ArrayList<>();

        // 1. 全局热门
        addHotItems(items, "hot:global", 50);

        // 2. 城市热门

        return items;
    }

    private void addHotItems(List<RecallItem> items, String key, int count) {
        Set<ZSetOperations.TypedTuple<String>> hotVideos =
                redisTemplate.opsForZSet().reverseRangeWithScores(key, 0, count);
        if (hotVideos != null) {
            for (ZSetOperations.TypedTuple<String> tuple : hotVideos) {
                items.add(new RecallItem(
                        tuple.getValue(), tuple.getScore(), "Hot"));
            }
        }
    }
}
```

#### 3.3.3 粗排层设计

粗排层位于召回和精排之间，需要从数千条候选中筛选出数百条。粗排需要同时兼顾精度和效率，通常使用双塔模型或轻量级交叉网络。

```java
/**
 * 粗排服务
 * 使用轻量级双塔模型对召回结果进行初步排序
 * 要求：延迟<20ms处理数千条候选
 */
@Component
public class PreRankService {

    @Autowired
    private FeatureService featureService;
    @Autowired
    private ModelInferenceClient modelClient;
    private static final int PRE_RANK_OUTPUT_SIZE = 300;

    /**
     * 粗排入口
     * 输入：召回候选集（数千条）
     * 输出：粗排结果（数百条）
     */
    public List<RankItem> preRank(UserProfile user,
                                  List<RecallItem> candidates) {
        // 1. 批量获取视频特征（从特征缓存中批量拉取，减少IO次数）
        Map<String, VideoFeature> videoFeatures = featureService
                .batchGetVideoFeatures(
                        candidates.stream()
                                .map(RecallItem::getVideoId)
                                .collect(Collectors.toList()));

        // 2. 获取用户特征
        UserFeature userFeature = featureService
                .getUserFeature(user.getUserId());

        // 3. 构建粗排模型输入（双塔模型：用户特征和物品特征独立编码）
        //    双塔模型的优势：用户侧和物品侧的打分可以并行计算
        //    用户Embedding可以缓存复用，只需要计算物品侧的打分
        PreRankModelInput input = PreRankModelInput.builder()
                .userFeature(userFeature)
                .videoFeatures(new ArrayList<>(videoFeatures.values()))
                .build();

        // 4. 模型推理（批量推理，GPU加速）
        List<Float> scores = modelClient.batchPredict(
                "pre_rank_model_v3", input);

        // 5. 组装排序结果
        List<RankItem> rankItems = new ArrayList<>();
        List<RecallItem> candidateList = new ArrayList<>(candidates);
        for (int i = 0; i < candidateList.size(); i++) {
            RecallItem recall = candidateList.get(i);
            VideoFeature feature = videoFeatures.get(recall.getVideoId());
            if (feature != null) {
                rankItems.add(new RankItem(
                        recall.getVideoId(),
                        scores.get(i),
                        recall.getSources(),
                        feature));
            }
        }

        // 6. 按分数降序排序，截取Top N
        rankItems.sort(Comparator.comparingDouble(
                RankItem::getScore).reversed());
        return rankItems.subList(0,
                Math.min(PRE_RANK_OUTPUT_SIZE, rankItems.size()));
    }
}
```

#### 3.3.4 精排层设计

精排层使用更复杂的深度学习模型，融入更多交叉特征，对数百条候选进行精确排序。这是决定推荐质量的关键环节。

```java
/**
 * 精排服务
 * 使用深度交叉网络（DCN）进行精确排序
 * 多目标优化：预估点击率(CTR)、完播率、点赞率、评论率
 */
@Component
public class FineRankService {

    @Autowired
    private FeatureService featureService;
    @Autowired
    private ModelInferenceClient modelClient;
    private static final int FINE_RANK_OUTPUT_SIZE = 50;

    /**
     * 精排入口
     * 与粗排的区别：
     *   1. 使用更复杂的模型（DCN / DeepFM / DIN）
     *   2. 引入更多交叉特征（用户-视频交叉、上下文特征）
     *   3. 多目标预估，综合评分
     */
    public List<RankItem> fineRank(UserProfile user,
                                   List<RankItem> preRankResult,
                                   RequestContext reqContext) {
        // 1. 构建精排特征
        //    精排特征比粗排多出：
        //    - 用户-视频交叉特征（如用户对该作者的历史互动）
        //    - 实时上下文特征（时间段、网络类型、设备型号）
        //    - 实时统计特征（视频近1小时播放量增速）
        List<FineRankFeature> features = new ArrayList<>();
        for (RankItem item : preRankResult) {
            FineRankFeature feature = FineRankFeature.builder()
                    .userFeature(featureService.getUserFeature(
                            user.getUserId()))
                    .videoFeature(item.getVideoFeature())
                    .crossFeature(featureService.getCrossFeature(
                            user.getUserId(), item.getVideoId()))
                    .contextFeature(buildContextFeature(reqContext))
                    .realtimeStats(featureService.getRealtimeStats(
                            item.getVideoId()))
                    .build();
            features.add(feature);
        }

        // 2. 多目标模型推理
        //    同时预估多个目标的概率
        MultiObjectiveResult moResult = modelClient.multiObjectivePredict(
                "fine_rank_dcn_v5", features);

        // 3. 融合多目标得分
        //    融合公式：score = w1*pCTR + w2*pFinish + w3*pLike + w4*pComment
        //    各权重通过线上AB实验调优确定
        for (int i = 0; i < preRankResult.size(); i++) {
            RankItem item = preRankResult.get(i);
            MultiObjectiveScore moScore = moResult.getScores().get(i);

            double finalScore = computeFusionScore(moScore);
            item.setScore(finalScore);
            item.setPredictedCTR(moScore.getPCtr());
            item.setPredictedFinishRate(moScore.getPFinish());
        }

        // 4. 按融合分数排序
        preRankResult.sort(Comparator.comparingDouble(
                RankItem::getScore).reversed());

        return preRankResult.subList(0,
                Math.min(FINE_RANK_OUTPUT_SIZE, preRankResult.size()));
    }

    /**
     * 多目标融合评分
     * 采用加权求和方式，权重通过线上实验调优
     * pCTR：预估点击率
     * pFinish：预估完播率（短视频核心指标）
     * pLike：预估点赞率
     * pComment：预估评论率
     */
    private double computeFusionScore(MultiObjectiveScore moScore) {
        // 权重配置（实际由配置中心管理，可动态调整）
        double wCtr = 0.3;
        double wFinish = 0.35;  // 完播率权重最高
        double wLike = 0.2;
        double wComment = 0.15;

        return wCtr * moScore.getPCtr()
                + wFinish * moScore.getPFinish()
                + wLike * moScore.getPLike()
                + wComment * moScore.getPComment();
    }

    private ContextFeature buildContextFeature(RequestContext ctx) {
        return ContextFeature.builder()
                .hourOfDay(ctx.getHourOfDay())
                .dayOfWeek(ctx.getDayOfWeek())
                .networkType(ctx.getNetworkType()) // WiFi/4G/5G
                .deviceType(ctx.getDeviceType())
                .osType(ctx.getOsType())
                .build();
    }
}
```

#### 3.3.5 重排层设计

重排层是推荐流的最后一道环节，负责在精排结果基础上应用业务策略，保证推荐结果的多样性和合规性。

```java
/**
 * 重排服务
 * 在精排结果基础上应用业务策略
 * 核心策略：类别打散、作者去重、多样性保障、流量调控
 */
@Component
public class ReRankService {

    @Autowired
    private List<ReRankStrategy> strategies;

    /**
     * 重排入口
     * 按策略优先级依次执行
     */
    public List<RankItem> reRank(UserProfile user,
                                 List<RankItem> fineRankResult) {
        List<RankItem> result = new ArrayList<>(fineRankResult);

        for (ReRankStrategy strategy : strategies) {
            result = strategy.apply(user, result);
        }

        return result;
    }
}

/**
 * 类别打散策略
 * 避免相邻位置出现相同类别的视频（如连续3个美食视频）
 * 算法：滑动窗口检测 + 位置交换
 */
@Component
@Order(1)
public class CategoryDiversityStrategy implements ReRankStrategy {

    // 滑动窗口大小：连续N个位置内不允许出现同一类别超过阈值次
    private static final int WINDOW_SIZE = 5;
    private static final int MAX_SAME_CATEGORY_IN_WINDOW = 2;

    @Override
    public List<RankItem> apply(UserProfile user, List<RankItem> items) {
        List<RankItem> result = new ArrayList<>(items);

        for (int i = 0; i < result.size(); i++) {
            // 检查当前位置的视频类别在窗口内是否已经超标
            String currentCategory = result.get(i).getVideoFeature()
                    .getCategory();
            int windowStart = Math.max(0, i - WINDOW_SIZE + 1);

            long sameCount = result.subList(windowStart, i).stream()
                    .filter(item -> currentCategory.equals(
                            item.getVideoFeature().getCategory()))
                    .count();

            if (sameCount >= MAX_SAME_CATEGORY_IN_WINDOW) {
                // 从后面找一个不同类别的视频交换到当前位置
                for (int j = i + 1; j < result.size(); j++) {
                    String otherCategory = result.get(j).getVideoFeature()
                            .getCategory();
                    if (!otherCategory.equals(currentCategory)) {
                        Collections.swap(result, i, j);
                        break;
                    }
                }
            }
        }

        return result;
    }
}

/**
 * 作者去重策略
 * 同一作者的视频在一次推荐中最多出现N条
 */
@Component
@Order(2)
public class AuthorDeduplicationStrategy implements ReRankStrategy {

    private static final int MAX_VIDEOS_PER_AUTHOR = 2;

    @Override
    public List<RankItem> apply(UserProfile user, List<RankItem> items) {
        Map<String, Integer> authorCount = new HashMap<>();
        List<RankItem> result = new ArrayList<>();
        List<RankItem> overflow = new ArrayList<>();

        for (RankItem item : items) {
            String authorId = item.getVideoFeature().getAuthorId();
            int count = authorCount.getOrDefault(authorId, 0);

            if (count < MAX_VIDEOS_PER_AUTHOR) {
                result.add(item);
                authorCount.put(authorId, count + 1);
            } else {
                overflow.add(item);
            }
        }

        // 超出限制的视频追加到末尾（不完全丢弃）
        result.addAll(overflow);
        return result;
    }
}
```

### 3.4 播放统计：播放量/完播率/互动数据异步采集

#### 3.4.1 问题分析

播放统计是短视频业务的核心数据基础，包括播放量（VV）、完播率、点赞数、评论数、分享数等指标。这些数据具有以下特点：
- **写入量极大**：每次播放、每个互动动作都会产生一条事件数据
- **允许短时间延迟**：统计数据不需要强实时性，秒级~分钟级延迟可接受
- **需要防刷**：播放量直接影响推荐排序，必须防止恶意刷量

```java
@Component

    private RedisTemplate<String, String> redisTemplate;
    @Autowired

     * 消费播放事件，更新实时计数器

            redisTemplate.opsForValue().increment(

        }

        // 4. 累计播放时长
        redisTemplate.opsForValue().increment(
                "stats:play_duration:" + videoId,
                event.getPlayDuration());

        // 5. 定期将Redis中的实时数据同步到数据库（由定时任务执行）
        //    这里只做实时增量更新
    }

    /**
     * 定时任务：每5分钟将Redis中的统计数据持久化到数据库
     */
    @Scheduled(fixedRate = 300000)
    public void syncStatsToDB() {
        // 扫描所有有更新的视频ID
        Set<String> updatedVideos = getUpdatedVideoIds();

        for (String videoId : updatedVideos) {
            Long vv = getLongValue("stats:vv:" + videoId);
            Long finishCount = getLongValue("stats:finish:" + videoId);
            Long uv = redisTemplate.opsForHyperLogLog()
                    .size("stats:uv:" + videoId);
            Long totalPlayDuration = getLongValue(
                    "stats:play_duration:" + videoId);

            // 计算完播率
            double finishRate = (vv != null && vv > 0 && finishCount != null)
                    ? (double) finishCount / vv : 0.0;

            VideoStats stats = VideoStats.builder()
                    .videoId(videoId)
                    .playCount(vv != null ? vv : 0)
                    .uniqueViewers(uv != null ? uv : 0)
                    .finishCount(finishCount != null ? finishCount : 0)
                    .finishRate(finishRate)
                    .totalPlayDuration(
                            totalPlayDuration != null ? totalPlayDuration : 0)
                    .updateTime(System.currentTimeMillis())
                    .build();

            videoStatsDao.upsert(stats);
        }
    }

        String val = redisTemplate.opsForValue().get(key);
        return val != null ? Long.parseLong(val) : null;
```

### 3.5 CDN分发与调度

#### 3.5.1 CDN架构设计

CDN（Content Delivery Network，内容分发网络）的核心目标是让用户从距离最近的边缘节点获取视频内容，减少传输延迟和源站压力。短视频CDN架构通常采用三级结构。

```
                    ┌──────────────┐
                    │   源站集群     │ ← 对象存储（原始文件 + 转码文件）
                    │  (Origin)    │
                    └──────┬───────┘
                           │ 回源拉取
                    ┌──────┴───────┐
                    │  中心节点(DC)  │ ← 二级缓存，跨区域回源中继
                    │ 北京/上海/广州 │
                    └──────┬───────┘
                           │ 内部分发
         ┌─────────────────┼─────────────────┐
   ┌─────┴──────┐    ┌─────┴──────┐    ┌─────┴──────┐
   │ 边缘节点(OC)│    │ 边缘节点(OC)│    │ 边缘节点(OC)│
   │  省级机房    │    │  省级机房    │    │  省级机房    │
   └─────┬──────┘    └─────┬──────┘    └─────┬──────┘
         │                 │                 │
     用户请求            用户请求            用户请求
```

#### 3.5.2 CDN调度策略

```java
/**
 * CDN调度服务
 * 根据用户位置和网络状况，返回最优的CDN边缘节点地址
 */
@Component
public class CdnSchedulerService {

    @Autowired
    private CdnNodeManager nodeManager;
    @Autowired
    private IpLocationService ipLocationService;

    /**
     * 获取视频播放URL（带CDN调度）
     * 调度策略：
     *   1. 根据用户IP确定地理位置和运营商
     *   2. 优先选择同运营商、同省份的边缘节点
     *   3. 多CDN厂商之间按质量权重分流
     *   4. 节点故障时自动摘除并切换
     */
    public PlayUrlResult getPlayUrl(String videoId, String clientIp,
                                    String networkType) {
        // 1. 获取视频的转码输出信息
        List<TranscodeOutput> outputs = getTranscodeOutputs(videoId);
        if (outputs.isEmpty()) {
            throw new VideoNotReadyException(videoId);
        }

        // 2. 解析用户IP的地理位置和运营商
        IpLocation location = ipLocationService.lookup(clientIp);

        // 3. 选择最优CDN节点
        CdnNode bestNode = nodeManager.selectBestNode(
                location.getProvince(),
                location.getIsp(),
                networkType);

        // 4. 生成带防盗链签名的播放URL
        List<PlayUrl> playUrls = new ArrayList<>();
        for (TranscodeOutput output : outputs) {
            String signedUrl = generateSignedUrl(
                    bestNode.getDomain(),
                    output.getObjectKey(),
                    3600); // URL有效期1小时

            playUrls.add(new PlayUrl(
                    output.getProfile().getResolution(),
                    output.getProfile().getVideoBitrate(),
                    signedUrl));
        }

        // 5. 生成HLS Master Playlist URL（ABR自适应）
        String masterUrl = generateSignedUrl(
                bestNode.getDomain(),
                "hls/" + videoId + "/master.m3u8",
                3600);

        return new PlayUrlResult(videoId, masterUrl, playUrls);
    }

    /**
     * 生成URL防盗链签名
     * 签名算法：MD5(secret + path + expireTime)
     * 播放URL格式：https://cdn.example.com/path?sign=xxx&t=expireTime
     */
    private String generateSignedUrl(String domain, String path,
                                      int ttlSeconds) {
        long expireTime = System.currentTimeMillis() / 1000 + ttlSeconds;
        String signPayload = CDN_SECRET + "/" + path + expireTime;
        String sign = DigestUtils.md5Hex(signPayload);

        return String.format("https://%s/%s?sign=%s&t=%d",
                domain, path, sign, expireTime);
    }
}

/**
 * CDN节点管理器
 * 维护多CDN厂商的节点列表，根据质量监控数据动态调度
 */
@Component
public class CdnNodeManager {

    /**
     * 选择最优CDN节点
     * 算法：加权打分，综合考虑距离、负载、历史质量
     */
    public CdnNode selectBestNode(String province, String isp,
                                   String networkType) {
        List<CdnNode> candidates = getAvailableNodes();

        // 过滤掉故障节点
        candidates = candidates.stream()
                .filter(CdnNode::isHealthy)
                .collect(Collectors.toList());

        // 加权打分
        CdnNode best = null;
        double bestScore = -1;

        for (CdnNode node : candidates) {
            double score = 0;

            // 同省加分（权重40%）
            if (province.equals(node.getProvince())) {
                score += 40;
            } else if (isSameRegion(province, node.getProvince())) {
                score += 20; // 同区域（如华东）
            }

            // 同运营商加分（权重30%）
            if (isp.equals(node.getIsp())) {
                score += 30;
            }

            // 历史质量评分（权重20%）：基于过去1小时的成功率和延迟
            score += node.getQualityScore() * 0.2;

            // 负载评分（权重10%）：负载越低分数越高
            score += (1 - node.getLoadRatio()) * 10;

            if (score > bestScore) {
                bestScore = score;
                best = node;
            }
        }

        return best;
    }
}
```

#### 3.5.3 多CDN容灾切换

```java
/**
 * CDN质量监控与自动切换
 * 基于客户端上报的播放质量数据，实时监控各CDN节点的健康状态
 * 故障时自动摘除节点，恢复后自动恢复流量

@Component
public class CdnHealthMonitor {

    @Autowired
    private CdnNodeManager nodeManager;
    @Autowired
    private AlertService alertService;

    /**
     * 定时检查CDN节点健康状态（每10秒执行）
     * 判断标准：
     *   - 成功率 < 95%
     *   - 平均首帧时间 > 2000ms
     *   - 卡顿率 > 10%

    public void checkHealth() {

                    && metrics.getAvgFirstFrameTime() <= 2000
                    && metrics.getBufferRate() <= 0.10;

            if (!healthy && node.isHealthy()) {
                // 节点变为不健康，摘除流量
                node.setHealthy(false);
                alertService.sendCdnAlert(node, metrics);
            } else if (healthy && !node.isHealthy()) {
                // 节点恢复健康，灰度恢复流量
                node.setHealthy(true);
            }
        }
    }
```

### 3.6 视频封面生成：抽帧与AI选帧

#### 3.6.1 问题分析

视频封面是用户决定是否点击观看的第一印象，直接影响视频的点击率（CTR）。默认的封面策略（如取第一帧或中间帧）经常出现黑屏、模糊、转场帧等低质量封面。智能封面生成通过AI技术，自动从视频中选出质量最佳、内容最吸引人的帧作为封面。

#### 3.6.2 智能封面生成流水线

```java
/**
 * 视频智能封面生成服务
 * 流程：关键帧抽取 → 低质帧过滤 → 美学评分 → 内容相关性评分 → 最优帧选取
 */
@Component
public class SmartCoverService {

    @Autowired
    private FrameExtractor frameExtractor;
    @Autowired
    private QualityScorer qualityScorer;
    @Autowired
    private AestheticScorer aestheticScorer;
    @Autowired
    private ObjectStorageClient storageClient;

    /**
     * 为视频生成智能封面
     * 
     * 整体算法流程：
     * 1. 均匀抽取N帧关键帧（每秒1帧 或 基于场景切换抽帧）
     * 2. 过滤低质帧（黑屏、模糊、转场帧）
     * 3. 对剩余帧进行美学评分（构图、色彩、清晰度）
     * 4. 对剩余帧进行内容评分（是否有人脸、文字、品牌元素）
     * 5. 综合评分取Top1作为静态封面
     * 6. 取Top1附近的片段作为动态封面（WebP动图）
     */
    public CoverResult generateSmartCover(String videoId, String sourceKey) {
        // 1. 抽取候选帧
        List<ExtractedFrame> frames = frameExtractor.extractKeyFrames(
                sourceKey,
                FrameExtractionConfig.builder()
                        .strategy(ExtractionStrategy.SCENE_DETECT) // 场景切换检测
                        .maxFrames(30)        // 最多抽30帧
                        .minInterval(0.5)     // 最小间隔0.5秒
                        .build());

        // 2. 低质帧过滤
        List<ExtractedFrame> qualityFiltered = frames.stream()
                .filter(frame -> {
                    FrameQuality quality = qualityScorer.score(frame);
                    // 过滤：黑屏（亮度<15）、模糊（拉普拉斯方差<50）、
                    //       过曝（亮度>240）
                    return quality.getBrightness() >= 15
                            && quality.getBrightness() <= 240
                            && quality.getSharpness() >= 50
                            && !quality.isTransitionFrame();
                })
                .collect(Collectors.toList());

        // 3. 美学评分
        for (ExtractedFrame frame : qualityFiltered) {
            double aestheticScore = aestheticScorer.score(frame.getImageData());
            frame.setAestheticScore(aestheticScore);
        }

        // 4. 综合评分并排序
        qualityFiltered.sort(Comparator.comparingDouble(
                ExtractedFrame::getAestheticScore).reversed());

        if (qualityFiltered.isEmpty()) {
            // 兜底：如果所有帧都被过滤，使用视频25%位置的帧
            return generateFallbackCover(videoId, sourceKey);
        }

        // 5. 生成静态封面（Top1帧）
        ExtractedFrame bestFrame = qualityFiltered.get(0);
        String staticCoverKey = uploadCover(
                videoId, bestFrame.getImageData(), "static");

        // 6. 生成动态封面（以Top1帧为中心，截取前后共3秒的片段）
        String dynamicCoverKey = generateDynamicCover(
                videoId, sourceKey, bestFrame.getTimestamp(), 3.0);

        return CoverResult.builder()
                .videoId(videoId)
                .staticCoverUrl(storageClient.getUrl(staticCoverKey))
                .dynamicCoverUrl(storageClient.getUrl(dynamicCoverKey))
                .selectedTimestamp(bestFrame.getTimestamp())
                .aestheticScore(bestFrame.getAestheticScore())
                .build();
    }

    /**
     * 生成动态封面（WebP动图）
     * 从视频中截取指定时间段，转成WebP动图
     */
    private String generateDynamicCover(String videoId, String sourceKey,
                                        double centerTime, double duration) {
        double startTime = Math.max(0, centerTime - duration / 2);

        // 使用FFmpeg截取片段并转成WebP动图
        // -vf fps=10 控制动图帧率（10fps足够流畅且文件小）
        // -loop 0 表示无限循环
        String outputKey = "covers/" + videoId + "/dynamic.webp";

        List<String> cmd = Arrays.asList(
                "ffmpeg", "-y",
                "-ss", String.valueOf(startTime),
                "-t", String.valueOf(duration),
                "-i", getLocalPath(sourceKey),
                "-vf", "fps=10,scale=480:-1",
                "-vcodec", "libwebp",
                "-lossless", "0",
                "-compression_level", "6",
                "-q:v", "75",
                "-loop", "0",
                getTempOutputPath(videoId, "dynamic.webp")
        );

        executeFFmpeg(cmd);
        storageClient.putObject(outputKey,
                new File(getTempOutputPath(videoId, "dynamic.webp")));

        return outputKey;
    }
}

/**
 * 帧质量评分器
 * 检测黑屏、模糊、过曝、转场帧等低质量问题
 */
@Component
public class QualityScorer {

    /**
     * 评估单帧的质量
     * 使用图像处理算法：
     *   - 亮度检测：计算像素均值
     *   - 模糊检测：拉普拉斯算子方差（值越小越模糊）
     *   - 转场检测：与前后帧的直方图差异
     */
    public FrameQuality score(ExtractedFrame frame) {
        byte[] imageData = frame.getImageData();

        // 计算亮度均值（灰度图的像素均值）
        double brightness = computeBrightness(imageData);

        // 计算清晰度（拉普拉斯方差）
        // 拉普拉斯算子检测图像的二阶导数，方差越大表示边缘越清晰
        double sharpness = computeLaplacianVariance(imageData);

        // 转场帧检测
        // 与前一帧的直方图相似度 < 阈值则判定为转场帧
        boolean isTransition = false;
        if (frame.getPreviousFrame() != null) {
            double similarity = computeHistogramSimilarity(
                    imageData, frame.getPreviousFrame().getImageData());
            isTransition = similarity < 0.3;
        }

        return new FrameQuality(brightness, sharpness, isTransition);
    }
}
```

### 3.7 视频去重：MD5 + 感知哈希（pHash）

#### 3.7.1 问题分析

视频去重需要解决两类问题：
- **完全相同的视频**：文件内容一模一样（字节级相同）
- **内容相似的视频**：经过裁剪、加滤镜、改分辨率等轻度编辑后内容本质相同

前者使用MD5即可解决，后者需要感知哈希（Perceptual Hash）技术。

#### 3.7.2 去重流水线实现

```java
/**
 * 视频去重服务
 * 两级去重策略：
 *   第一级：MD5精确去重（O(1) 查找，处理完全相同的文件）
 *   第二级：感知哈希（pHash）近似去重（处理轻度编辑的视频）
 */
@Component
public class VideoDeduplicationService {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    @Autowired
    private VideoFingerprintDao fingerprintDao;
    @Autowired
    private FrameExtractor frameExtractor;

    private static final int PHASH_HAMMING_THRESHOLD = 10; // 汉明距离阈值

    /**
     * 检查视频是否重复
     * 返回值：如果是重复视频，返回原始视频ID；否则返回null
     */
    public DeduplicationResult checkDuplicate(String videoId,
                                              String sourceKey,
                                              String fileMd5) {
        // ===== 第一级：MD5精确去重 =====
        String existingVideoId = redisTemplate.opsForValue()
                .get("dedup:md5:" + fileMd5);
        if (existingVideoId != null) {
            return DeduplicationResult.duplicate(
                    existingVideoId, DedupType.MD5_EXACT);
        }

        // ===== 第二级：感知哈希近似去重 =====
        // 1. 对视频均匀抽取关键帧
        List<ExtractedFrame> frames = frameExtractor.extractKeyFrames(
                sourceKey,
                FrameExtractionConfig.builder()
                        .strategy(ExtractionStrategy.UNIFORM)
                        .maxFrames(16)   // 抽16帧
                        .build());

        // 2. 对每帧计算感知哈希
        List<Long> frameHashes = frames.stream()
                .map(frame -> computePerceptualHash(frame.getImageData()))
                .collect(Collectors.toList());

        // 3. 生成视频级别的指纹（16帧pHash拼接）
        String videoFingerprint = frameHashes.stream()
                .map(String::valueOf)
                .collect(Collectors.joining(","));

        // 4. 与数据库中的指纹进行比对
        //    使用分桶策略减少比较次数（LSH局部敏感哈希）
        List<VideoFingerprint> candidates = fingerprintDao
                .findCandidatesByBucket(
                        computeLshBuckets(frameHashes));

        for (VideoFingerprint candidate : candidates) {
            double similarity = computeFingerprintSimilarity(
                    frameHashes, candidate.getFrameHashes());
            if (similarity >= 0.85) { // 相似度阈值85%
                return DeduplicationResult.duplicate(
                        candidate.getVideoId(),
                        DedupType.PHASH_SIMILAR);
            }
        }

        // 5. 非重复视频，保存指纹
        VideoFingerprint fingerprint = VideoFingerprint.builder()
                .videoId(videoId)
                .fileMd5(fileMd5)
                .frameHashes(frameHashes)
                .lshBuckets(computeLshBuckets(frameHashes))
                .build();
        fingerprintDao.insert(fingerprint);

        // 记录MD5映射
        redisTemplate.opsForValue().set("dedup:md5:" + fileMd5, videoId);

        return DeduplicationResult.unique();
    }

    /**
     * 计算单帧的感知哈希（pHash）
     * 
     * 算法步骤：
     * 1. 缩放图像到 32x32
     * 2. 转灰度图
     * 3. 对灰度图执行DCT（离散余弦变换）
     * 4. 取DCT左上角 8x8 的低频系数
     * 5. 计算低频系数的均值
     * 6. 大于均值的位置置1，否则置0，得到64位哈希值
     */
    private long computePerceptualHash(byte[] imageData) {
        // 1. 缩放到 32x32
        int[][] grayPixels = resizeAndGrayscale(imageData, 32, 32);

        // 2. DCT变换
        double[][] dctMatrix = applyDCT(grayPixels);

        // 3. 取左上角 8x8 低频区域
        double[] lowFreq = new double[64];
        int index = 0;
        for (int i = 0; i < 8; i++) {
            for (int j = 0; j < 8; j++) {
                lowFreq[index++] = dctMatrix[i][j];
            }
        }

        // 4. 计算均值
        double mean = Arrays.stream(lowFreq).average().orElse(0);

        // 5. 生成64位哈希
        long hash = 0;
        for (int i = 0; i < 64; i++) {
            if (lowFreq[i] > mean) {
                hash |= (1L << i);
            }
        }

        return hash;
    }

    /**
     * 计算两个视频指纹的相似度
     * 方法：计算对应帧pHash的汉明距离，取平均相似度
     * 汉明距离 = 两个哈希值异或后1的个数（不同的位数）
     */
    private double computeFingerprintSimilarity(List<Long> hashes1,
                                                List<Long> hashes2) {
        int compareCount = Math.min(hashes1.size(), hashes2.size());
        double totalSimilarity = 0;

        for (int i = 0; i < compareCount; i++) {
            int hammingDistance = Long.bitCount(
                    hashes1.get(i) ^ hashes2.get(i));
            // 64位哈希，汉明距离越小越相似
            double frameSimilarity = 1.0 - (double) hammingDistance / 64;
            totalSimilarity += frameSimilarity;
        }

        return totalSimilarity / compareCount;
    }
}
```

### 3.8 存储架构：对象存储 + CDN

#### 3.8.1 存储分层设计

短视频系统的存储架构采用分层设计，不同类型的数据使用不同的存储介质和策略。

```java
/**
 * 存储分层管理器
 * 根据数据的访问频率和生命周期，自动迁移存储层级
 *
 * 存储层级：
 *   热存储（SSD对象存储）：最近7天上传的视频 + 高播放量视频
 *   温存储（HDD对象存储）：7-90天的视频
 *   冷存储（归档存储）：90天以上且播放量极低的视频
 */
@Component
public class StorageTieringManager {

    @Autowired
    private ObjectStorageClient hotStorage;   // SSD存储
    @Autowired
    private ObjectStorageClient warmStorage;  // HDD存储
    @Autowired
    private ObjectStorageClient coldStorage;  // 归档存储
    @Autowired
    private VideoStatsDao videoStatsDao;

    /**
     * 定时任务：每天凌晨执行存储降级
     */
    @Scheduled(cron = "0 0 3 * * ?")
    public void tieringMigration() {
        long now = System.currentTimeMillis();
        long sevenDaysAgo = now - 7 * 24 * 3600 * 1000L;
        long ninetyDaysAgo = now - 90 * 24 * 3600 * 1000L;

        // 热 → 温：上传超过7天 且 近7天播放量 < 100
        List<VideoMeta> hotToWarm = videoMetaDao
                .findByStorageTierAndCreateTimeBefore(
                        StorageTier.HOT, sevenDaysAgo);
        for (VideoMeta meta : hotToWarm) {
            VideoStats stats = videoStatsDao.getRecentStats(
                    meta.getVideoId(), 7);
            if (stats.getPlayCount() < 100) {
                migrateStorage(meta, StorageTier.HOT, StorageTier.WARM);
            }
        }

        // 温 → 冷：上传超过90天 且 近30天播放量 < 10
        List<VideoMeta> warmToCold = videoMetaDao
                .findByStorageTierAndCreateTimeBefore(
                        StorageTier.WARM, ninetyDaysAgo);
        for (VideoMeta meta : warmToCold) {
            VideoStats stats = videoStatsDao.getRecentStats(
                    meta.getVideoId(), 30);
            if (stats.getPlayCount() < 10) {
                migrateStorage(meta, StorageTier.WARM, StorageTier.COLD);
            }
        }
    }

    /**
     * 存储迁移：跨层级迁移视频文件
     * 迁移过程中保持原存储可读，迁移完成后删除原存储
     */
    private void migrateStorage(VideoMeta meta,
                                StorageTier from, StorageTier to) {
        String objectKey = meta.getObjectKey();

        ObjectStorageClient srcStorage = getStorage(from);
        ObjectStorageClient dstStorage = getStorage(to);

        try {
            // 复制到目标存储
            byte[] data = srcStorage.getObject(objectKey);
            dstStorage.putObject(objectKey, data);

            // 更新元数据
            videoMetaDao.updateStorageTier(meta.getVideoId(), to);

            // 删除源存储（延迟删除，确保CDN缓存过期）
            scheduleDelete(srcStorage, objectKey,
                    Duration.ofHours(24));
        } catch (Exception e) {
            log.error("Storage migration failed: videoId={}, from={}, to={}",
                    meta.getVideoId(), from, to, e);
        }
    }
}
```

#### 3.8.2 对象存储与CDN的协同

对象存储作为源站，CDN作为加速层，二者之间通过回源协议协同工作。

| 组件 | 职责 | 存储内容 |

| 对象存储 | 持久化存储所有视频文件 | 原始视频 + 所有转码版本 + 封面图 |

| MySQL | 持久化存储视频元数据 | 视频信息 + 用户信息 + 互动数据 |

## 四、异常处理与容错机制

### 4.1 上传链路容错

| 异常场景 | 处理策略 |
|---------|----------|
| 分片上传超时 | 单片重试3次，指数退避（1s/2s/4s），超出后标记失败 |
| 网络中断 | 客户端保存uploadId和已完成分片列表，恢复后断点续传 |
| 上传任务过期 | 未完成任务3天后自动清理，释放存储空间 |
| 文件校验失败 | MD5不一致时拒绝合并，通知客户端重新上传问题分片 |

### 4.2 转码链路容错

```java
/**
 * 转码任务失败处理
 * 策略：
 *   1. 单任务失败自动重试3次
 *   2. 重试仍失败则标记为FAILED，发送告警
 *   3. 同组部分任务失败不影响已完成任务的可用性
 *   4. 关键分辨率（如480p H.264）失败时触发人工介入
 */
@Component
public class TranscodeFailureHandler {

    @Autowired
    private TranscodeTaskDao taskDao;
    @Autowired
    private TranscodeWorkerRouter workerRouter;
    @Autowired
    private AlertService alertService;

    private static final int MAX_RETRY = 3;

    public void handleFailure(TranscodeTask task, Exception error) {
        int retryCount = task.getRetryCount();

        if (retryCount < MAX_RETRY) {
            // 重试：更换Worker节点（避免同一节点重复失败）
            task.setRetryCount(retryCount + 1);
            task.setStatus(TaskStatus.PENDING);
            taskDao.update(task);

            TranscodeWorkerNode anotherWorker = workerRouter
                    .selectWorkerExcluding(task.getProfile(),
                            task.getLastWorkerId());
            workerRouter.dispatch(anotherWorker, task);
        } else {
            // 重试耗尽
            task.setStatus(TaskStatus.FAILED);
            task.setErrorMessage(error.getMessage());
            taskDao.update(task);

            // 判断是否为关键分辨率
            if (isCriticalProfile(task.getProfile())) {
                alertService.sendCriticalTranscodeAlert(task);
            }
        }
    }

    private boolean isCriticalProfile(TranscodeProfile profile) {
        // 480p H.264 是最基本的播放版本，必须保证成功
        return "480p".equals(profile.getResolution())
                && "h264".equals(profile.getCodec());
    }
}
```

### 4.3 推荐链路降级

| 故障环节 | 降级策略 |
|---------|----------|
| 召回层超时 | 部分召回策略超时不影响整体，返回已完成的召回结果 |
| 粗排模型不可用 | 降级为基于召回分数的简单排序 |
| 精排模型不可用 | 降级为粗排结果直接输出 |
| 特征服务不可用 | 使用缓存的历史特征，标记为降级 |
| 全链路故障 | 返回预先缓存的兜底推荐列表（按城市+时段预计算） |

### 4.4 CDN容灾

当某家CDN厂商出现区域故障时，调度系统通过客户端上报的质量数据在10秒内感知，并自动将流量切换到备用CDN。切换过程对用户透明，播放器在感知到当前URL失败后自动请求新的播放地址。

## 六、最佳实践与总结

### 6.1 架构设计原则

1. **异步解耦**：上传、转码、封面生成、去重等流程通过消息队列异步串联，任一环节的延迟不影响用户的上传体验。

2. **分层漏斗**：推荐系统采用"召回→粗排→精排→重排"的分层架构，每层在效率和精度之间取不同的平衡，整体延迟控制在200ms以内。

3. **多级缓存**：从客户端本地缓存、CDN边缘缓存、CDN中心缓存到源站，构建完整的缓存体系，热点视频命中率>99%。

4. **弹性伸缩**：转码集群根据任务队列深度自动扩缩容，高峰期快速扩容处理突发转码需求。

5. **优雅降级**：每个关键链路都设计了降级方案，部分组件故障时系统仍可提供核心服务。

```java
/**
 * 视频发布Controller
 * 用户发布短视频的统一入口，负责参数校验、幂等控制、异步流水线触发
 */
@RestController
@RequestMapping("/api/v1/video")
public class VideoPublishController {

    @Autowired
    private VideoPublishService videoPublishService;
    @Autowired
    private IdempotentService idempotentService;

    private static final Logger log = LoggerFactory.getLogger(
            VideoPublishController.class);

    /**
     * 发布视频
     * 幂等控制：基于 userId + uploadId 的幂等键，防止重复提交
     */
    @PostMapping("/publish")
    public Result<PublishResponse> publish(
            @RequestBody @Valid PublishRequest request,
            @RequestHeader("X-User-Id") String userId,
            @RequestHeader("X-Request-Id") String requestId) {

        log.info("[Publish] userId={}, requestId={}, title={}, uploadId={}",
                userId, requestId, request.getTitle(),
                request.getUploadId());

        // 1. 幂等检查：同一 requestId 只处理一次
        String idempotentKey = "publish:idem:" + requestId;
        PublishResponse cached = idempotentService.getAndLock(
                idempotentKey, PublishResponse.class);
        if (cached != null) {
            log.info("[Publish] Idempotent hit, requestId={}, videoId={}",
                    requestId, cached.getVideoId());
            return Result.success(cached);
        }

        try {
            // 2. 执行发布流程
            PublishResponse response = videoPublishService.publish(
                    userId, request);

            // 3. 缓存幂等结果（30分钟有效）
            idempotentService.put(idempotentKey, response,
                    Duration.ofMinutes(30));

            log.info("[Publish] Success, userId={}, videoId={}, status={}",
                    userId, response.getVideoId(), response.getStatus());
            return Result.success(response);

        } catch (IllegalArgumentException e) {
            log.warn("[Publish] Param error, userId={}, msg={}",
                    userId, e.getMessage());
            return Result.fail(400, e.getMessage());
        } catch (VideoNotFoundException e) {
            log.warn("[Publish] Video not found, userId={}, uploadId={}",
                    userId, request.getUploadId());
            return Result.fail(404, "视频文件不存在，请重新上传");
        } catch (Exception e) {
            log.error("[Publish] Unexpected error, userId={}, requestId={}",
                    userId, requestId, e);
            return Result.fail(500, "发布失败，请稍后重试");
        }
    }

    /**
     * 查询发布状态
     * 客户端轮询发布进度：转码中 → 审核中 → 已发布
     */
    @GetMapping("/publish/status")
    public Result<PublishStatusResponse> getPublishStatus(
            @RequestParam String videoId,
            @RequestHeader("X-User-Id") String userId) {

        log.info("[PublishStatus] userId={}, videoId={}", userId, videoId);
        PublishStatusResponse status = videoPublishService
                .getPublishStatus(videoId, userId);
        return Result.success(status);
    }
}
```

```java
/**

public class PublishRequest {

/**
 * 视频发布核心服务
 * 编排上传确认 → 异步流水线触发 → 状态机管理
 */
@Service
public class VideoPublishService {

    @Autowired
    private MultipartUploadManager uploadManager;
    @Autowired
    private VideoMetaDao videoMetaDao;
    @Autowired
    private MQProducer mqProducer;
    @Autowired
    private ElasticsearchClient esClient;
    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    private static final Logger log = LoggerFactory.getLogger(
            VideoPublishService.class);

    /**
     * 执行视频发布
     *
     * 核心流程：
     *   1. 确认文件上传完成，获取objectKey
     *   2. 创建视频元信息记录（状态=PROCESSING）
     *   3. 发送异步流水线消息（转码 + 封面 + 审核 + 去重并行）
     *   4. 返回videoId，客户端轮询发布状态
     */
    @Transactional(rollbackFor = Exception.class)
    public PublishResponse publish(String userId,
                                    PublishRequest request) {
        // 1. 确认上传完成，获取视频文件信息
        UploadTaskMeta uploadMeta = uploadManager
                .getTaskMeta(request.getUploadId());
        if (uploadMeta == null) {
            throw new VideoNotFoundException(
                    "Upload not found: " + request.getUploadId());
        }

        // 2. 校验文件大小限制（最大5GB）
        if (uploadMeta.getFileSize() > 5L * 1024 * 1024 * 1024) {
            throw new IllegalArgumentException("视频文件超过5GB限制");
        }

        // 3. 生成视频ID，创建元信息记录
        String videoId = IdGenerator.nextId();
        VideoMeta videoMeta = VideoMeta.builder()
                .videoId(videoId)
                .userId(userId)
                .title(request.getTitle())
                .description(request.getDescription())
                .objectKey(uploadMeta.getObjectKey())
                .fileSize(uploadMeta.getFileSize())
                .fileMd5(uploadMeta.getFileMd5())
                .tags(request.getTags())
                .category(request.getCategory())
                .latitude(request.getLatitude())
                .longitude(request.getLongitude())
                .locationName(request.getLocationName())
                .privacyLevel(request.getPrivacyLevel())
                .allowDownload(request.getAllowDownload())
                .allowComment(request.getAllowComment())
                .status(VideoStatus.PROCESSING)  // 初始状态：处理中
                .createTime(System.currentTimeMillis())
                .updateTime(System.currentTimeMillis())
                .build();

        videoMetaDao.insert(videoMeta);

        log.info("[Publish] Video meta created, videoId={}, userId={}, "
                + "fileSize={}, fileMd5={}",
                videoId, userId, uploadMeta.getFileSize(),
                uploadMeta.getFileMd5());

        // 4. 发送异步流水线消息
        //    使用同一个pipelineId串联所有子任务，便于状态追踪
        String pipelineId = IdGenerator.nextId();

        // 4.1 转码任务（最耗时，先触发）
        TranscodeMessage transcodeMsg = new TranscodeMessage(
                videoId, uploadMeta.getObjectKey(), pipelineId);
        mqProducer.send("topic_video_transcode", transcodeMsg);

        // 4.2 封面生成任务
        CoverGenerateMessage coverMsg = new CoverGenerateMessage(
                videoId, uploadMeta.getObjectKey(),
                request.getCoverUploadId(), pipelineId);
        mqProducer.send("topic_cover_generate", coverMsg);

        // 4.3 内容审核任务
        AuditMessage auditMsg = new AuditMessage(
                videoId, uploadMeta.getObjectKey(),
                uploadMeta.getFileMd5(), pipelineId);
        mqProducer.send("topic_video_audit", auditMsg);

        // 4.4 视频去重任务
        DedupMessage dedupMsg = new DedupMessage(
                videoId, uploadMeta.getObjectKey(),
                uploadMeta.getFileMd5(), pipelineId);
        mqProducer.send("topic_video_dedup", dedupMsg);

        // 5. 记录流水线状态到Redis，用于客户端轮询
        PipelineStatus pipelineStatus = new PipelineStatus(
                pipelineId, videoId, userId);
        pipelineStatus.markTranscodePending();
        pipelineStatus.markCoverPending();
        pipelineStatus.markAuditPending();
        pipelineStatus.markDedupPending();

        redisTemplate.opsForValue().set(
                "pipeline:status:" + videoId,
                JSON.toJSONString(pipelineStatus),
                24, TimeUnit.HOURS);

        return PublishResponse.builder()
                .videoId(videoId)
                .status(VideoStatus.PROCESSING)
                .pipelineId(pipelineId)
                .build();
    }

    /**
     * 查询发布状态
     * 客户端轮询此接口，展示转码/审核进度
     */
    public PublishStatusResponse getPublishStatus(String videoId,
                                                   String userId) {
        // 1. 查询视频元信息
        VideoMeta meta = videoMetaDao.findByVideoId(videoId);
        if (meta == null || !userId.equals(meta.getUserId())) {
            throw new VideoNotFoundException(videoId);
        }

        // 2. 查询流水线状态
        String statusJson = redisTemplate.opsForValue()
                .get("pipeline:status:" + videoId);
        PipelineStatus pipelineStatus = statusJson != null
                ? JSON.parseObject(statusJson, PipelineStatus.class)
                : null;

        // 3. 构建响应
        PublishStatusResponse response = new PublishStatusResponse();
        response.setVideoId(videoId);
        response.setVideoStatus(meta.getStatus().name());

        if (pipelineStatus != null) {
            response.setTranscodeStatus(
                    pipelineStatus.getTranscodeStatus());
            response.setCoverStatus(pipelineStatus.getCoverStatus());
            response.setAuditStatus(pipelineStatus.getAuditStatus());
            response.setDedupStatus(pipelineStatus.getDedupStatus());
            response.setOverallProgress(
                    pipelineStatus.calculateOverallProgress());
        }

        // 4. 如果审核被拒，返回拒绝原因
        if (meta.getStatus() == VideoStatus.AUDIT_REJECTED) {
            response.setRejectReason(meta.getAuditRejectReason());
        }

        return response;
    }
}
```

#### 7.1.4 内容审核服务（视频抽帧鉴黄 + 音频ASR敏感词）

```java
/**
 * 内容审核服务
 * 双通道审核：
 *   1. 视频画面审核：均匀抽帧 → 图像分类模型鉴黄/暴恐/政治敏感
 *   2. 音频内容审核：提取音轨 → ASR语音转文字 → 敏感词匹配
 * 审核结果分为：PASS / REVIEW（人工复审）/ REJECT（直接拒绝）
 */
@Component
public class ContentAuditService {

    @Autowired
    private FrameExtractor frameExtractor;
    @Autowired
    private ImageAuditClient imageAuditClient;   // 图像审核模型客户端
    @Autowired
    private AudioExtractService audioExtractService;
    @Autowired
    private AsrService asrService;                // 语音转文字服务
    @Autowired
    private SensitiveWordMatcher sensitiveWordMatcher;
    @Autowired
    private VideoMetaDao videoMetaDao;
    @Autowired
    private MQProducer mqProducer;
    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    private static final Logger log = LoggerFactory.getLogger(
            ContentAuditService.class);

    // 审核阈值配置
    private static final double PORN_THRESHOLD = 0.85;      // 鉴黄置信度阈值
    private static final double VIOLENCE_THRESHOLD = 0.80;  // 暴恐置信度阈值
    private static final double POLITICS_THRESHOLD = 0.75;  // 政治敏感阈值
    private static final int MAX_AUDIT_FRAMES = 20;         // 最多审核帧数
    private static final int REVIEW_THRESHOLD_FRAMES = 2;   // 命中帧数超过此值才拒绝

    /**
     * 执行内容审核
     * 监听审核MQ消息，异步执行
     */
    @RocketMQListener(topic = "topic_video_audit",
                      consumerGroup = "cg_video_audit")
    public void onAuditMessage(AuditMessage msg) {
        String videoId = msg.getVideoId();
        String pipelineId = msg.getPipelineId();

        log.info("[Audit] Start, videoId={}, pipelineId={}",
                videoId, pipelineId);

        try {
            // 更新流水线状态
            updatePipelineStatus(videoId, "audit", "PROCESSING");

            // 1. 视频画面审核
            VisualAuditResult visualResult = auditVisualContent(
                    videoId, msg.getObjectKey());

            // 2. 音频内容审核
            AudioAuditResult audioResult = auditAudioContent(
                    videoId, msg.getObjectKey());

            // 3. 综合审核结果
            AuditResult finalResult = combineAuditResults(
                    visualResult, audioResult);

            log.info("[Audit] Done, videoId={}, result={}, "
                    + "visualScore={}, audioHit={}",
                    videoId, finalResult.getDecision(),
                    visualResult.getMaxPornScore(),
                    audioResult.getHitWords().size());

            // 4. 根据审核结果执行后续操作
            handleAuditResult(videoId, finalResult, pipelineId);

        } catch (Exception e) {
            log.error("[Audit] Failed, videoId={}", videoId, e);
            // 审核失败时标记为人工复审，避免误放过
            handleAuditResult(videoId,
                    AuditResult.review("审核服务异常，转人工复审"),
                    pipelineId);
        }
    }

    /**
     * 视频画面审核
     * 均匀抽帧 → 逐帧调用图像审核模型
     */
    private VisualAuditResult auditVisualContent(String videoId,
                                                  String objectKey) {
        // 1. 均匀抽帧（每2秒抽1帧，最多20帧）
        List<ExtractedFrame> frames = frameExtractor.extractKeyFrames(
                objectKey,
                FrameExtractionConfig.builder()
                        .strategy(ExtractionStrategy.UNIFORM)
                        .interval(2.0)  // 每2秒抽1帧
                        .maxFrames(MAX_AUDIT_FRAMES)
                        .build());

        log.info("[Audit] Visual frames extracted, videoId={}, count={}",
                videoId, frames.size());

        // 2. 逐帧审核
        double maxPornScore = 0;
        double maxViolenceScore = 0;
        double maxPoliticsScore = 0;
        int pornHitFrames = 0;
        int violenceHitFrames = 0;

        for (ExtractedFrame frame : frames) {
            // 调用图像审核模型，返回多标签分类分数
            ImageAuditResponse resp = imageAuditClient.audit(
                    frame.getImageData());

            double pornScore = resp.getPornScore();
            double violenceScore = resp.getViolenceScore();
            double politicsScore = resp.getPoliticsScore();

            maxPornScore = Math.max(maxPornScore, pornScore);
            maxViolenceScore = Math.max(maxViolenceScore, violenceScore);
            maxPoliticsScore = Math.max(maxPoliticsScore, politicsScore);

            if (pornScore >= PORN_THRESHOLD) pornHitFrames++;
            if (violenceScore >= VIOLENCE_THRESHOLD) violenceHitFrames++;
        }

        // 3. 判定：命中帧数超过阈值才拒绝，避免单帧误判
        VisualAuditResult result = new VisualAuditResult();
        result.setMaxPornScore(maxPornScore);
        result.setMaxViolenceScore(maxViolenceScore);
        result.setMaxPoliticsScore(maxPoliticsScore);
        result.setPornHitFrames(pornHitFrames);
        result.setViolenceHitFrames(violenceHitFrames);

        return result;
    }

    /**
     * 音频内容审核
     * 提取音轨 → ASR转文字 → 敏感词匹配
     */
    private AudioAuditResult auditAudioContent(String videoId,
                                                String objectKey) {
        // 1. 提取音轨（AAC格式）
        String audioKey = audioExtractService.extractAudio(
                objectKey, "aac");

        // 2. ASR语音转文字
        AsrResult asrResult = asrService.recognize(audioKey);
        String transcript = asrResult.getTranscript();

        log.info("[Audit] ASR done, videoId={}, textLength={}",
                videoId, transcript.length());

        // 3. 敏感词匹配
        List<SensitiveWordHit> hits = sensitiveWordMatcher
                .match(transcript);

        AudioAuditResult result = new AudioAuditResult();
        result.setTranscript(transcript);
        result.setHitWords(hits);
        return result;
    }

    /**
     * 综合视频和音频审核结果，做出最终决策
     */
    private AuditResult combineAuditResults(VisualAuditResult visual,
                                            AudioAuditResult audio) {
        // 视频画面：命中帧数超过阈值 → 拒绝
        if (visual.getPornHitFrames() >= REVIEW_THRESHOLD_FRAMES) {
            return AuditResult.reject("视频画面涉嫌色情内容");
        }
        if (visual.getViolenceHitFrames() >= REVIEW_THRESHOLD_FRAMES) {
            return AuditResult.reject("视频画面涉嫌暴恐内容");
        }
        if (visual.getMaxPoliticsScore() >= POLITICS_THRESHOLD) {
            return AuditResult.reject("视频画面涉嫌政治敏感内容");
        }

        // 音频：命中严重级别敏感词 → 拒绝
        boolean hasSevereHit = audio.getHitWords().stream()
                .anyMatch(h -> h.getLevel() == SensitiveLevel.SEVERE);
        if (hasSevereHit) {
            return AuditResult.reject("音频内容包含严重违规词汇");
        }

        // 命中中等级别敏感词 → 人工复审
        boolean hasModerateHit = audio.getHitWords().stream()
                .anyMatch(h -> h.getLevel() == SensitiveLevel.MODERATE);
        if (hasModerateHit) {
            return AuditResult.review("音频内容包含敏感词汇，需人工复审");
        }

        // 单帧命中但未超阈值 → 人工复审
        if (visual.getPornHitFrames() > 0
                || visual.getViolenceHitFrames() > 0) {
            return AuditResult.review("视频画面存在风险，需人工复审");
        }

        return AuditResult.pass();
    }

    /**
     * 根据审核结果处理后续流程
     */
    private void handleAuditResult(String videoId, AuditResult result,
                                    String pipelineId) {
        switch (result.getDecision()) {
            case PASS:
                // 审核通过，更新状态
                videoMetaDao.updateAuditStatus(videoId,
                        VideoStatus.AUDIT_PASSED, null);
                updatePipelineStatus(videoId, "audit", "PASSED");

                // 检查所有流水线任务是否完成，触发最终发布
                checkAndFinalPublish(videoId, pipelineId);
                break;

            case REVIEW:
                // 转人工复审
                videoMetaDao.updateAuditStatus(videoId,
                        VideoStatus.AUDIT_REVIEW, result.getReason());
                updatePipelineStatus(videoId, "audit", "REVIEW");

                // 发送人工复审任务
                ManualReviewTask task = new ManualReviewTask(
                        videoId, result.getReason(), pipelineId);
                mqProducer.send("topic_manual_review", task);
                break;

            case REJECT:
                // 直接拒绝
                videoMetaDao.updateAuditStatus(videoId,
                        VideoStatus.AUDIT_REJECTED, result.getReason());
                updatePipelineStatus(videoId, "audit", "REJECTED");

                log.warn("[Audit] Video rejected, videoId={}, reason={}",
                        videoId, result.getReason());
                break;
        }
    }

    private void updatePipelineStatus(String videoId, String stage,
                                       String status) {
        String key = "pipeline:status:" + videoId;
        String json = redisTemplate.opsForValue().get(key);
        if (json != null) {
            PipelineStatus ps = JSON.parseObject(json, PipelineStatus.class);
            ps.updateStage(stage, status);
            redisTemplate.opsForValue().set(key, JSON.toJSONString(ps),
                    24, TimeUnit.HOURS);
        }
    }

    /**
     * 检查所有流水线任务是否完成
     * 转码 + 封面 + 审核 + 去重 全部完成后，执行最终发布
     */
    private void checkAndFinalPublish(String videoId, String pipelineId) {
        String json = redisTemplate.opsForValue()
                .get("pipeline:status:" + videoId);
        if (json == null) return;

        PipelineStatus ps = JSON.parseObject(json, PipelineStatus.class);
        if (ps.isAllCompleted()) {
            // 所有任务完成，触发最终发布
            FinalPublishMessage msg = new FinalPublishMessage(
                    videoId, pipelineId);
            mqProducer.send("topic_final_publish", msg);
            log.info("[Audit] All pipeline tasks done, "
                    + "triggering final publish, videoId={}", videoId);
        }
    }
}
```

```java
/**
 * 最终发布服务
 * 所有流水线任务完成后，将视频正式发布：
 *   1. 更新视频状态为PUBLISHED
     2. 写入Elasticsearch搜索索引

@Component
public class FinalPublishService {

    @Autowired
    private VideoMetaDao videoMetaDao;
    @Autowired
    private VideoStatsDao videoStatsDao;
    @Autowired
    private ElasticsearchClient esClient;
    @Autowired

    @Autowired
    private FanoutNotificationService fanoutService;
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    @Autowired
    private MQProducer mqProducer;

    private static final Logger log = LoggerFactory.getLogger(
            FinalPublishService.class);

    @RocketMQListener(topic = "topic_final_publish",
                      consumerGroup = "cg_final_publish")
    public void onFinalPublish(FinalPublishMessage msg) {
        String videoId = msg.getVideoId();

        log.info("[FinalPublish] Start, videoId={}", videoId);

        try {
            // 1. 查询视频完整元信息
            VideoMeta meta = videoMetaDao.findByVideoId(videoId);
            if (meta == null) {
                log.error("[FinalPublish] Video not found, videoId={}",
                        videoId);
                return;
            }

            // 2. 幂等检查：避免重复发布
            if (meta.getStatus() == VideoStatus.PUBLISHED) {
                log.info("[FinalPublish] Already published, skip, videoId={}",
                        videoId);
                return;
            }

            // 3. 更新视频状态为已发布
            videoMetaDao.updateStatus(videoId, VideoStatus.PUBLISHED);
            meta.setStatus(VideoStatus.PUBLISHED);

            // 4. 初始化统计数据记录
            VideoStats stats = VideoStats.builder()
                    .videoId(videoId)
                    .playCount(0)
                    .uniqueViewers(0)
                    .likeCount(0)
                    .commentCount(0)
                    .shareCount(0)
                    .finishCount(0)
                    .finishRate(0.0)
                    .createTime(System.currentTimeMillis())
                    .build();
            videoStatsDao.insert(stats);

            // 5. 写入Elasticsearch搜索索引
            indexToElasticsearch(meta);

            // 6. 推送到推荐池
            pushToRecommendPool(meta);

            // 7. CDN预热：将视频的默认播放版本推送到CDN边缘节点
            cdnPreheatService.preheat(videoId,
                    meta.getDefaultPlayKey());

            // 8. 推送粉丝通知
            fanoutService.notifyFollowers(
                    meta.getUserId(), videoId, meta.getTitle());

            // 9. 清理流水线状态缓存
            redisTemplate.delete("pipeline:status:" + videoId);

            log.info("[FinalPublish] Success, videoId={}, userId={}",
                    videoId, meta.getUserId());

        } catch (Exception e) {
            log.error("[FinalPublish] Failed, videoId={}", videoId, e);
            // 发送到死信队列，等待人工处理
            mqProducer.send("topic_final_publish_dlq", msg);
        }
    }

    /**
     * 写入Elasticsearch搜索索引
     * 支持按标题、描述、标签全文检索
     */
    private void indexToElasticsearch(VideoMeta meta) {
        Map<String, Object> doc = new HashMap<>();
        doc.put("videoId", meta.getVideoId());
        doc.put("userId", meta.getUserId());
        doc.put("title", meta.getTitle());
        doc.put("description", meta.getDescription());
        doc.put("tags", meta.getTags());
        doc.put("category", meta.getCategory());
        doc.put("createTime", meta.getCreateTime());
        doc.put("status", meta.getStatus().name());

        try {
            esClient.index(i -> i
                    .index("video_search")
                    .id(meta.getVideoId())
                    .document(doc)
            );
            log.info("[FinalPublish] ES indexed, videoId={}",
                    meta.getVideoId());
        } catch (Exception e) {
            log.error("[FinalPublish] ES index failed, videoId={}",
                    meta.getVideoId(), e);
            // ES写入失败不影响主流程，后续补偿任务会重试
        }
    }

    /**
     * 推送到推荐池
     * 将视频ID写入Redis推荐候选集合，召回服务从此集合获取新视频
     */
    private void pushToRecommendPool(VideoMeta meta) {
        // 1. 加入全局新视频池
        redisTemplate.opsForList().leftPush(
                "recommend:pool:new_videos",
                meta.getVideoId());

        // 2. 按分类加入分类新视频池
        if (meta.getCategory() != null) {
            redisTemplate.opsForList().leftPush(
                    "recommend:pool:category:" + meta.getCategory(),
                    meta.getVideoId());
        }

        // 3. 记录视频特征到Redis，供召回策略使用
        Map<String, String> features = new HashMap<>();
        features.put("category", meta.getCategory());
        features.put("authorId", meta.getUserId());
        features.put("createTime", String.valueOf(meta.getCreateTime()));
        features.put("tags", String.join(",", meta.getTags()));
        redisTemplate.opsForHash().putAll(
                "video:features:" + meta.getVideoId(), features);

        log.info("[FinalPublish] Pushed to recommend pool, videoId={}",
                meta.getVideoId());
    }
}
```

#### 7.1.6 全链路时序与异常处理总结

```
用户发布 → 上传确认(50ms) → 创建元信息(20ms) → 异步触发4个流水线任务
                                                    ↓
    ┌───────────────────────────────────────────────────┐
    │  转码(30-120s)  封面生成(5-10s)  审核(10-30s)  去重(2-5s) │
    └───────────────────────────────────────────────────┘
                                                    ↓
                              全部完成 → 最终发布(100ms)
                                    ├─ MySQL入库
                                    ├─ ES索引写入
                                    ├─ 推荐池推送
                                    ├─ CDN预热
                                    └─ 粉丝通知
```

| 异常场景 | 处理策略 | 幂等机制 |
|---------|----------|----------|
| 重复点击发布 | requestId幂等，返回已缓存的videoId | Redis幂等缓存30分钟 |
| 转码失败 | 自动重试3次，更换Worker节点 | 任务状态PENDING可重入 |
| 审核服务超时 | 超时转人工复审，不误放过 | 审核结果以最后一次为准 |
| 最终发布失败 | 发送死信队列，人工介入处理 | 检查status==PUBLISHED跳过 |
| CDN预热失败 | 不阻塞发布流程，首次播放自动回源 | 预热任务幂等 |

#### 7.2.3 推荐流核心服务（多级缓存 + CDN签名 + 预加载）

```java
/**
 * 推荐流核心服务
 * 编排推荐系统调用 → 视频详情查询 → 播放URL生成 → 预加载策略
 */
@Service
public class FeedService {

    @Autowired
    private RecommendService recommendService;
    @Autowired
    private VideoDetailService videoDetailService;
    @Autowired
    private CdnSchedulerService cdnSchedulerService;
    @Autowired
    private ExposureLogService exposureLogService;
    @Autowired
    private UserProfileService userProfileService;
    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    private static final Logger log = LoggerFactory.getLogger(
            FeedService.class);

    private static final int PRELOAD_COUNT = 3;  // 预加载后续3个视频

    /**
     * 获取推荐流
     */
    public FeedResponse getRecommendFeed(FeedRequest request) {
        String userId = request.getUserId();

        // 1. 获取用户画像
        UserProfile userProfile = userProfileService
                .getUserProfile(userId, request.getDeviceId(),
                        request.getCityId());

        // 2. 调用推荐系统，获取视频ID列表
        //    推荐系统内部执行：召回 → 粗排 → 精排 → 重排
        RecommendResult recommendResult = recommendService.recommend(
                userProfile, request.getPage(), request.getPageSize());

        List<String> videoIds = recommendResult.getVideoIds();
        if (videoIds.isEmpty()) {
            log.warn("[Feed] Empty recommendation, userId={}, page={}",
                    userId, request.getPage());
            return FeedResponse.empty();
        }

        // 3. 批量查询视频详情（多级缓存）
        List<VideoDetail> details = videoDetailService
                .batchGetVideoDetails(videoIds);

        // 4. 生成播放URL（CDN调度 + 防盗链签名）
        String clientIp = request.getClientIp();
        String networkType = request.getNetworkType();

        List<FeedVideo> feedVideos = new ArrayList<>();
        for (VideoDetail detail : details) {
            if (detail == null) continue;

            // 4.1 生成播放URL
            PlayUrlResult playUrl = cdnSchedulerService.getPlayUrl(
                    detail.getVideoId(), clientIp, networkType);

            // 4.2 组装Feed视频信息
            FeedVideo feedVideo = FeedVideo.builder()
                    .videoId(detail.getVideoId())
                    .title(detail.getTitle())
                    .coverUrl(detail.getStaticCoverUrl())
                    .dynamicCoverUrl(detail.getDynamicCoverUrl())
                    .duration(detail.getDuration())
                    .author(detail.getAuthor())
                    .playUrl(playUrl.getMasterUrl())
                    .playUrls(playUrl.getPlayUrls())
                    .likeCount(detail.getLikeCount())
                    .commentCount(detail.getCommentCount())
                    .shareCount(detail.getShareCount())
                    .hasLiked(detail.isHasLiked())
                    .build();

            feedVideos.add(feedVideo);
        }

        // 5. 预加载策略：为后续N个视频生成播放URL
        //    推荐系统一次返回 pageSize + PRELOAD_COUNT 个视频ID
        //    前 pageSize 个返回给客户端播放，后 PRELOAD_COUNT 个
        //    的URL随响应一起下发，客户端提前加载
        if (recommendResult.hasPreloadItems()) {
            List<PreloadVideo> preloads = generatePreloadUrls(
                    recommendResult.getPreloadVideoIds(),
                    clientIp, networkType);
            return FeedResponse.builder()
                    .videos(feedVideos)
                    .preloadVideos(preloads)
                    .hasMore(recommendResult.hasMore())
                    .requestId(IdGenerator.nextId())
                    .build();
        }

        return FeedResponse.builder()
                .videos(feedVideos)
                .hasMore(recommendResult.hasMore())
                .requestId(IdGenerator.nextId())
                .build();
    }

    /**
     * 生成预加载视频URL列表
     */
    private List<PreloadVideo> generatePreloadUrls(
            List<String> preloadVideoIds,
            String clientIp, String networkType) {
        List<PreloadVideo> preloads = new ArrayList<>();

        for (String videoId : preloadVideoIds) {
            try {
                PlayUrlResult playUrl = cdnSchedulerService.getPlayUrl(
                        videoId, clientIp, networkType);
                preloads.add(PreloadVideo.builder()
                        .videoId(videoId)
                        .playUrl(playUrl.getMasterUrl())
                        .build());
            } catch (Exception e) {
                log.warn("[Feed] Preload URL failed, videoId={}, "
                        + "error={}", videoId, e.getMessage());
            }
        }
        return preloads;
    }

    /**
     * 兜底推荐列表
     * 推荐系统故障时使用，按城市+时段预计算的热门视频
     */
    public FeedResponse getFallbackFeed(String userId, int cityId,
                                        int pageSize) {
        log.warn("[Feed] Using fallback feed, userId={}, cityId={}",
                userId, cityId);

        // 从Redis读取预计算的兜底列表
        String key = "fallback:feed:city:" + cityId;
        List<String> fallbackVideoIds = redisTemplate.opsForList()
                .range(key, 0, pageSize - 1);

        if (fallbackVideoIds == null || fallbackVideoIds.isEmpty()) {
            // 全局兜底
            fallbackVideoIds = redisTemplate.opsForList()
                    .range("fallback:feed:global", 0, pageSize - 1);
        }

        if (fallbackVideoIds == null || fallbackVideoIds.isEmpty()) {
            return FeedResponse.empty();
        }

        List<VideoDetail> details = videoDetailService
                .batchGetVideoDetails(fallbackVideoIds);

        List<FeedVideo> videos = details.stream()
                .filter(Objects::nonNull)
                .map(detail -> FeedVideo.builder()
                        .videoId(detail.getVideoId())
                        .title(detail.getTitle())
                        .coverUrl(detail.getStaticCoverUrl())
                        .duration(detail.getDuration())
                        .author(detail.getAuthor())
                        .build())
                .collect(Collectors.toList());

        return FeedResponse.builder()
                .videos(videos)
                .hasMore(false)
                .fallback(true)
                .build();
    }
}
```

#### 7.2.4 视频详情多级缓存查询

```java
/**
 * 视频详情服务
 * 多级缓存策略：本地缓存(Caffeine) → Redis → MySQL
 * 
 * 缓存层级设计：
 *   L1: 本地缓存（Caffeine），容量10000条，TTL 60秒
 *       缓解热点视频对Redis的读取压力
 *   L2: Redis集群缓存，TTL 10分钟
 *       缓存完整的视频详情JSON
 *   L3: MySQL数据库
 *       持久化存储，命中率极低（<1%）
 */
@Service
public class VideoDetailService {

    @Autowired
    private VideoMetaDao videoMetaDao;
    @Autowired
    private VideoStatsDao videoStatsDao;
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    @Autowired
    private UserInteractionDao userInteractionDao;

    // L1: 本地缓存（Caffeine）
    private final Cache<String, VideoDetail> localCache = Caffeine.newBuilder()
            .maximumSize(10000)
            .expireAfterWrite(60, TimeUnit.SECONDS)
            .recordStats()
            .build();

    private static final Logger log = LoggerFactory.getLogger(
            VideoDetailService.class);

    /**
     * 批量查询视频详情（多级缓存）
     * 使用Pipeline批量查Redis，减少网络往返
     */
    public List<VideoDetail> batchGetVideoDetails(List<String> videoIds) {
        if (videoIds.isEmpty()) {
            return Collections.emptyList();
        }

        List<VideoDetail> result = new ArrayList<>(videoIds.size());
        List<String> missIds = new ArrayList<>();  // 未命中缓存的ID

        // 1. L1: 本地缓存查询
        for (String videoId : videoIds) {
            VideoDetail cached = localCache.getIfPresent(videoId);
            if (cached != null) {
                result.add(cached);
            } else {
                missIds.add(videoId);
                // 占位，保持顺序
                result.add(null);
            }
        }

        if (missIds.isEmpty()) {
            return result;
        }

        // 2. L2: Redis批量查询（使用Pipeline减少RTT）
        List<String> redisKeys = missIds.stream()
                .map(id -> "video:detail:" + id)
                .collect(Collectors.toList());

        List<Object> redisResults = redisTemplate.executePipelined(
                (RedisCallback<Object>) connection -> {
                    for (String key : redisKeys) {
                        connection.get(key.getBytes());
                    }
                    return null;
                });

        List<String> dbMissIds = new ArrayList<>();
        for (int i = 0; i < missIds.size(); i++) {
            String videoId = missIds.get(i);
            String json = (String) redisResults.get(i);

            if (json != null) {
                // Redis命中
                VideoDetail detail = JSON.parseObject(json,
                        VideoDetail.class);
                localCache.put(videoId, detail);

                // 填充到结果列表对应位置
                int idx = videoIds.indexOf(videoId);
                result.set(idx, detail);
            } else {
                dbMissIds.add(videoId);
            }
        }

        if (dbMissIds.isEmpty()) {
            return result;
        }

        // 3. L3: MySQL查询
        List<VideoMeta> metas = videoMetaDao.batchFindByVideoIds(
                dbMissIds);
        List<VideoStats> stats = videoStatsDao.batchFindByVideoIds(
                dbMissIds);

        Map<String, VideoMeta> metaMap = metas.stream()
                .collect(Collectors.toMap(VideoMeta::getVideoId,
                        Function.identity()));
        Map<String, VideoStats> statsMap = stats.stream()
                .collect(Collectors.toMap(VideoStats::getVideoId,
                        Function.identity()));

        for (String videoId : dbMissIds) {
            VideoMeta meta = metaMap.get(videoId);
            VideoStats stat = statsMap.get(videoId);

            if (meta == null || meta.getStatus() != VideoStatus.PUBLISHED) {
                // 视频不存在或未发布，跳过
                continue;
            }

            VideoDetail detail = buildVideoDetail(meta, stat);

            // 回填缓存
            String json = JSON.toJSONString(detail);
            redisTemplate.opsForValue().set(
                    "video:detail:" + videoId, json,
                    10, TimeUnit.MINUTES);
            localCache.put(videoId, detail);

            // 填充结果
            int idx = videoIds.indexOf(videoId);
            result.set(idx, detail);
        }

        log.info("[VideoDetail] Batch query, total={}, l1Hit={}, "
                + "l2Hit={}, dbHit={}",
                videoIds.size(),
                videoIds.size() - missIds.size(),
                missIds.size() - dbMissIds.size(),
                dbMissIds.size());

        return result;
    }

    /**
     * 构建视频详情对象
     */
    private VideoDetail buildVideoDetail(VideoMeta meta,
                                          VideoStats stats) {
        return VideoDetail.builder()
                .videoId(meta.getVideoId())
                .title(meta.getTitle())
                .description(meta.getDescription())
                .duration(meta.getDuration())
                .staticCoverUrl(meta.getStaticCoverUrl())
                .dynamicCoverUrl(meta.getDynamicCoverUrl())
                .author(AuthorInfo.builder()
                        .userId(meta.getUserId())
                        .nickname(meta.getAuthorNickname())
                        .avatarUrl(meta.getAuthorAvatar())
                        .build())
                .likeCount(stats != null ? stats.getLikeCount() : 0)
                .commentCount(stats != null ? stats.getCommentCount() : 0)
                .shareCount(stats != null ? stats.getShareCount() : 0)
                .playCount(stats != null ? stats.getPlayCount() : 0)
                .createTime(meta.getCreateTime())
                .build();
    }
}
```

#### 7.3.3 点赞服务（Redis实时计数 + Kafka行为日志 + 幂等控制）

```java
/**
 * 点赞服务
 * 
 * 设计要点：
 *   1. 实时性：点赞/取消后，前端展示的点赞数秒级更新
 *      → 使用Redis原子计数器 + Redis Set记录用户点赞关系
 *   2. 幂等性：同一用户重复点赞不会重复计数
 *      → 使用Redis Set的SISMEMBER判断是否已点赞
 *   3. 持久化：异步将点赞数据写入MySQL，保证数据不丢
 *      → 通过Kafka + 定时批量写入实现
 *   4. 推荐反馈：点赞行为是推荐模型的重要正样本
 *      → 写入Kafka供Flink实时消费，更新用户特征
 */
@Service
public class LikeService {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    @Autowired
    private MQProducer mqProducer;
    @Autowired
    private VideoMetaDao videoMetaDao;

    private static final Logger log = LoggerFactory.getLogger(
            LikeService.class);

    // Redis Key 设计：
    // like:set:{videoId}      → Set，存储已点赞的用户ID（用于幂等判断）
    // like:count:{videoId}   → String，点赞总数（用于快速读取）
    // like:user:{userId}     → Set，用户点赞过的视频ID（用于个人主页）

    /**
     * 点赞/取消点赞（原子操作）
     * 使用Redis Lua脚本保证「判断+计数」的原子性
     */
    public LikeResponse toggleLike(String userId, String videoId,
                                    LikeAction action) {
        // 1. 校验视频是否存在且已发布
        VideoMeta meta = videoMetaDao.findByVideoId(videoId);
        if (meta == null || meta.getStatus() != VideoStatus.PUBLISHED) {
            throw new VideoNotFoundException(videoId);
        }

        // 2. 检查视频是否允许互动
        if (Boolean.FALSE.equals(meta.getAllowComment())) {
            throw new IllegalArgumentException("该视频已关闭互动");
        }

        // 3. 执行原子点赞/取消操作
        //    使用Lua脚本保证「Set操作 + 计数操作」的原子性
        String likeSetKey = "like:set:" + videoId;
        String likeCountKey = "like:count:" + videoId;
        String userLikeKey = "like:user:" + userId;

        Long newCount;
        if (action == LikeAction.LIKE) {
            newCount = doLike(userId, videoId, likeSetKey,
                    likeCountKey, userLikeKey);
        } else {
            newCount = doUnlike(userId, videoId, likeSetKey,
                    likeCountKey, userLikeKey);
        }

        // 4. 写入Kafka行为日志（供推荐模型 + 异步持久化）
        InteractionEvent event = new InteractionEvent();
        event.setVideoId(videoId);
        event.setUserId(userId);
        event.setEventType(action == LikeAction.LIKE
                ? "LIKE" : "UNLIKE");
        event.setTimestamp(System.currentTimeMillis());
        mqProducer.send("topic_interaction_event", event);

        log.info("[Like] userId={}, videoId={}, action={}, newCount={}",
                userId, videoId, action, newCount);

        return LikeResponse.builder()
                .videoId(videoId)
                .likeCount(newCount)
                .hasLiked(action == LikeAction.LIKE)
                .build();
    }

    /**
     * 执行点赞（Lua脚本保证原子性）
     * 逻辑：
     *   1. SISMEMBER 检查是否已点赞
     *   2. 如果未点赞：SADD 加入集合，INCR 计数+1
     *   3. 如果已点赞：返回当前计数（幂等）
     */
    private Long doLike(String userId, String videoId,
                        String likeSetKey, String likeCountKey,
                        String userLikeKey) {
        // Lua脚本：原子化执行判断+添加+计数
        String luaScript =
            "if redis.call('SISMEMBER', KEYS[1], ARGV[1]) == 1 then "
            + "  return tonumber(redis.call('GET', KEYS[2]) or '0') "
            + "else "
            + "  redis.call('SADD', KEYS[1], ARGV[1]) "
            + "  redis.call('SADD', KEYS[3], ARGV[2]) "
            + "  return redis.call('INCR', KEYS[2]) "
            + "end";

        Long count = redisTemplate.execute(
                new DefaultRedisScript<>(luaScript, Long.class),
                Arrays.asList(likeSetKey, likeCountKey, userLikeKey),
                userId, videoId);

        return count;
    }

    /**
     * 执行取消点赞（Lua脚本保证原子性）
     * 逻辑：
     *   1. SISMEMBER 检查是否已点赞
     *   2. 如果已点赞：SREM 移出集合，DECR 计数-1
     *   3. 如果未点赞：返回当前计数（幂等）
     */
    private Long doUnlike(String userId, String videoId,
                          String likeSetKey, String likeCountKey,
                          String userLikeKey) {
        String luaScript =
            "if redis.call('SISMEMBER', KEYS[1], ARGV[1]) == 0 then "
            + "  return tonumber(redis.call('GET', KEYS[2]) or '0') "
            + "else "
            + "  redis.call('SREM', KEYS[1], ARGV[1]) "
            + "  redis.call('SREM', KEYS[3], ARGV[2]) "
            + "  return redis.call('DECR', KEYS[2]) "
            + "end";

        Long count = redisTemplate.execute(
                new DefaultRedisScript<>(luaScript, Long.class),
                Arrays.asList(likeSetKey, likeCountKey, userLikeKey),
                userId, videoId);

        return count;
    }

    /**
     * 查询用户是否已点赞（用于视频详情展示）
     */
    public boolean hasLiked(String userId, String videoId) {
        Boolean isMember = redisTemplate.opsForSet()
                .isMember("like:set:" + videoId, userId);
        return Boolean.TRUE.equals(isMember);
    }

    /**
     * 获取点赞数（优先读Redis，兜底读DB）
     */
    public long getLikeCount(String videoId) {
        String count = redisTemplate.opsForValue()
                .get("like:count:" + videoId);
        if (count != null) {
            return Long.parseLong(count);
        }
        // Redis未命中，从DB加载并回填缓存
        // 实际场景中点赞数在Redis中几乎不会miss（除非Redis故障）
        return 0;
    }
}
```

#### 7.3.4 互动行为流式处理（推荐模型实时反馈）

```java
/**
 * 互动行为流式处理器
 * 消费Kafka中的互动事件，执行：
 *   1. 实时更新用户特征（用于推荐模型）
 *   2. 异步持久化到MySQL（批量写入，降低DB压力）
 *   3. 更新视频统计计数（每5分钟同步到DB）
 */
@Component
public class InteractionEventProcessor {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    @Autowired
    private UserInteractionDao userInteractionDao;
    @Autowired
    private VideoStatsDao videoStatsDao;

    private static final Logger log = LoggerFactory.getLogger(
            InteractionEventProcessor.class);

    /**
     * 消费互动事件
     * 使用批量消费模式，每100条或每2秒提交一次
     */
    @KafkaListener(topics = "topic_interaction_event",
                   groupId = "cg_interaction_processor",
                   batch = true)
    public void onInteractionEvent(List<InteractionEvent> events) {

        log.info("[InteractionProcessor] Batch size={}", events.size());

        // 1. 按事件类型分组
        Map<String, List<InteractionEvent>> grouped = events.stream()
                .collect(Collectors.groupingBy(
                        InteractionEvent::getEventType));

        // 2. 更新视频统计计数（Redis实时计数）
        for (Map.Entry<String, List<InteractionEvent>> entry
                : grouped.entrySet()) {
            String eventType = entry.getKey();
            List<InteractionEvent> eventList = entry.getValue();

            // 按videoId聚合
            Map<String, Long> countByVideo = eventList.stream()
                    .collect(Collectors.groupingBy(
                            InteractionEvent::getVideoId,
                            Collectors.counting()));

            for (Map.Entry<String, Long> e : countByVideo.entrySet()) {
                String videoId = e.getKey();
                long delta = e.getValue();

                switch (eventType) {
                    case "LIKE":
                        redisTemplate.opsForValue().increment(
                                "stats:like:" + videoId, delta);
                        break;
                    case "COMMENT":
                        redisTemplate.opsForValue().increment(
                                "stats:comment:" + videoId, delta);
                        break;
                    case "SHARE":
                        redisTemplate.opsForValue().increment(
                                "stats:share:" + videoId, delta);
                        break;
                    case "FOLLOW":
                        // 关注事件单独处理
                        break;
                }
            }
        }

        // 3. 更新用户实时特征（供推荐模型使用）
        //    将用户最近的正向行为写入Redis，作为实时特征
        for (InteractionEvent event : events) {
            if (isPositiveAction(event.getEventType())) {
                // 记录用户最近正向行为的视频ID（最近20条）
                redisTemplate.opsForList().leftPush(
                        "user:recent_positive:" + event.getUserId(),
                        event.getVideoId());
                redisTemplate.opsForList().trim(
                        "user:recent_positive:" + event.getUserId(),
                        0, 19);
                redisTemplate.expire(
                        "user:recent_positive:" + event.getUserId(),
                        7, TimeUnit.DAYS);

                // 更新用户兴趣标签权重
                updateUserInterestTags(event);
            }
        }

        // 4. 异步持久化到数据库（批量写入）
        batchPersistToDB(events);
    }

    /**
     * 更新用户兴趣标签权重
     * 点赞/完播的视频 → 提取视频标签 → 增加用户对应标签的兴趣权重
     */
    private void updateUserInterestTags(InteractionEvent event) {
        // 获取视频的标签
        String tagsJson = (String) redisTemplate.opsForHash()
                .get("video:features:" + event.getVideoId(), "tags");
        if (tagsJson == null) return;

        String[] tags = tagsJson.split(",");
        double weight = getActionWeight(event.getEventType());

        for (String tag : tags) {
            // 增加用户对该标签的兴趣分数
            redisTemplate.opsForZSet().incrementScore(
                    "user:interest:" + event.getUserId(),
                    tag, weight);
        }
    }

    private double getActionWeight(String eventType) {
        switch (eventType) {
            case "LIKE": return 3.0;
            case "COMMENT": return 5.0;
            case "SHARE": return 4.0;
            case "COLLECT": return 4.0;
            case "FOLLOW": return 6.0;
            default: return 1.0;
        }
    }

    private boolean isPositiveAction(String eventType) {
        return "LIKE".equals(eventType)
                || "COMMENT".equals(eventType)
                || "SHARE".equals(eventType)
                || "COLLECT".equals(eventType)
                || "FOLLOW".equals(eventType);
    }

    /**
     * 批量持久化到数据库
     */
    private void batchPersistToDB(List<InteractionEvent> events) {
        try {
            List<UserInteractionRecord> records = events.stream()
                    .map(e -> UserInteractionRecord.builder()
                            .id(IdGenerator.nextId())
                            .userId(e.getUserId())
                            .videoId(e.getVideoId())
                            .eventType(e.getEventType())
                            .createTime(e.getTimestamp())
                            .build())
                    .collect(Collectors.toList());

            userInteractionDao.batchInsert(records);
        } catch (Exception e) {
            log.error("[InteractionProcessor] DB persist failed, "
                    + "batchSize={}", events.size(), e);
            // 持久化失败不丢失数据：重新写入Kafka死信队列
            // 实际实现中通过Kafka的ack机制 + 重试策略保证
        }
    }
}
```

```java
@Service

                .build();

        // 4. 记录分享行为
        InteractionEvent event = new InteractionEvent();
        event.setVideoId(videoId);
        event.setUserId(userId);
        event.setEventType("SHARE");

/**
 * 短链生成服务
 * 使用自增ID + Base62编码生成短链，6位短码支持568亿种组合
 */
@Service
public class ShortUrlService {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    private static final String SHORT_URL_COUNTER = "shorturl:counter";
    private static final String SHORT_URL_MAPPING = "shorturl:mapping:";
    private static final char[] BASE62 =
            "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"
                    .toCharArray();

    /**
     * 生成短链
     * 
     * 算法：
     *   1. Redis INCR 获取全局自增ID
     *   2. 将ID转为Base62编码（6位短码）
     *   3. 存储短码 → 原始URL的映射到Redis
     *   4. 持久化到MySQL（异步）
     */
    public String generateShortUrl(String originalUrl,
                                    String userId, String videoId) {
        // 1. 检查是否已有短链（幂等）
        String existingCode = redisTemplate.opsForValue()
                .get("shorturl:origin:" + hashUrl(originalUrl));
        if (existingCode != null) {
            return existingCode;
        }

        // 2. 获取自增ID
        Long id = redisTemplate.opsForValue()
                .increment(SHORT_URL_COUNTER);

        // 3. Base62编码
        String shortCode = encodeBase62(id);

        // 4. 存储映射关系
        redisTemplate.opsForValue().set(
                SHORT_URL_MAPPING + shortCode,
                originalUrl,
                90, TimeUnit.DAYS);

        // 5. 存储反向映射（用于幂等检查）
        redisTemplate.opsForValue().set(
                "shorturl:origin:" + hashUrl(originalUrl),
                shortCode,
                90, TimeUnit.DAYS);

        log.info("[ShortUrl] Generated, id={}, shortCode={}, videoId={}",
                id, shortCode, videoId);

        return shortCode;
    }

    /**
     * Base62编码
     * 10 → 'a', 61 → 'Z'
     */
    private String encodeBase62(long id) {
        StringBuilder sb = new StringBuilder();
        while (id > 0) {
            sb.insert(0, BASE62[(int) (id % 62)]);
            id /= 62;
        }
        // 补齐到6位
        while (sb.length() < 6) {
            sb.insert(0, '0');
        }
        return sb.toString();
    }

    /**
     * 短链解析：短码 → 原始URL
     */
    public String resolveShortUrl(String shortCode) {
        String url = redisTemplate.opsForValue()
                .get(SHORT_URL_MAPPING + shortCode);
        if (url == null) {
            // Redis未命中，查询MySQL
            // 实际实现中会回源数据库
            return null;
        }
        return url;
    }

    private String hashUrl(String url) {
        return DigestUtils.md5Hex(url).substring(0, 16);
    }
}
```

#### 7.3.6 全链路时序与异常处理总结

```
用户点赞
  → Controller(参数校验 + 幂等检查) → 2ms
  → Lua脚本原子操作(Redis Set + INCR) → 3ms
  → 写Kafka行为日志 → 1ms（异步发送）
  → 返回最新点赞数 → 总耗时 < 10ms

  异步链路：
    Kafka消费 → 更新Redis统计计数 → 更新用户兴趣标签 → 批量写入MySQL

用户分享
  → 生成短链(Base62编码) → 3ms
  → 组装分享卡片 → 1ms
  → 写Kafka + Redis计数 → 1ms
  → 返回短链 + 卡片 → 总耗时 < 10ms
```

| 异常场景 | 处理策略 | 幂等机制 |
|---------|----------|----------|
| 重复点赞 | Lua脚本SISMEMBER判断，已点赞则跳过 | Redis Set天然幂等 |
| 重复评论 | requestId幂等缓存10分钟 | Redis幂等键 |
| Redis计数异常 | 降级为MySQL直接查询计数 | DB层面唯一索引兜底 |
| Kafka写入失败 | 本地缓冲 + 异步重试 | 消息携带事件ID去重 |
| MySQL批量写入失败 | 重试3次，失败后写死信队列 | 事件ID唯一索引 |
| 短链生成重复 | MD5哈希检查已有短链 | 反向映射缓存 |

### 7.4 三个案例的串联关系

三个案例覆盖了短视频系统的核心生命周期，相互串联形成闭环：

```
案例一（发布）           案例二（消费）           案例三（互动）
用户发布视频     →     推荐流展示视频     →     用户点赞/评论/分享
  ↓                       ↓                       ↓
视频入库 + 推荐池   →   召回层获取候选      →   实时特征更新
  ↓                       ↓                       ↓
CDN预热            →    CDN播放URL签名     →   Kafka行为日志
  ↓                       ↓                       ↓
审核通过可发布     →    曝光上报(负样本)   →   推荐模型反馈(正样本)
                                                    ↓
                                              优化下一轮推荐 → 回到案例二
```

| 维度 | 案例一：发布 | 案例二：推荐流 | 案例三：互动 |
|------|------------|--------------|------------|
| 响应延迟 | 同步<500ms，异步流水线2-5分钟 | P99<200ms | <10ms |
| 一致性要求 | 最终一致 | 允许弱一致（缓存延迟） | 最终一致 |
| 核心存储 | MySQL + Redis + ES | Redis + Caffeine + MySQL | Redis + MySQL |
| 消息队列 | RocketMQ（流水线编排） | Kafka（行为日志） | Kafka（行为日志 + 特征更新） |
| 幂等机制 | requestId + 状态检查 | 无（读操作天然幂等） | Lua脚本 + requestId |
| 降级策略 | 审核失败转人工复审 | 返回兜底推荐列表 | Redis故障降级DB查询 |
