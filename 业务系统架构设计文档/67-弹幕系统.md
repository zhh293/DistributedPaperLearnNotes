# 弹幕系统架构设计

> 本文部分内容参考学城文档整理（《直播IM系统架构设计》《直播通道》相关内容），并结合公开的弹幕/推送系统工程实践进行系统性梳理和扩展。文中不涉及任何企业内部产品名称，示例代码为通用Java实现，可直接迁移到任意后端技术栈。

## 一、问题背景

### 1.1 弹幕的本质：一种推送系统

学城文档在描述直播弹幕能力时给出了一个非常精炼的定义：

> "直播弹幕服务本质上是一种推送系统，所谓推送系统，就是当你发送一条消息时，它可以将消息推送给所有的人。对于直播弹幕来说，用户不断发送消息，不断进行广播，当一个直播间有10万人时，一条消息就要发送10万次，同时直播场景下的互动对消息的延时要求也较为苛刻。"

这句话点出了弹幕系统与普通IM系统最大的不同：**IM是点对点或点对小群体的消息投递，弹幕是点对海量人群的广播**。一条弹幕消息产生后，理论上需要被直播间内所有在线用户看到，人数从几十到几十万甚至上百万不等，消息的"写放大"效应极其显著。

同时，弹幕系统通常是更大的"直播互动系统"的一个子集。互动系统的定位在于承载直播间内的聊天、弹幕、礼物、点赞等实时消息："直播间里常见的聊天、弹幕、礼物、点赞等互动消息基本都是基于统一的实时通信通道实现的"——这意味着弹幕系统在架构设计上不应该是一套孤立系统，而应该是可复用的实时消息通道之上的一种业务消息类型。

### 1.2 业务场景

- 直播间实时弹幕：观众发送文字弹幕，实时展示在直播画面上，所有在线观众几乎同时可见。
- 点播回放弹幕：用户观看录播视频时，弹幕按视频播放进度回放，还原当时的直播互动氛围。
- 超大直播间广播：热门直播、大促直播、晚会直播等场景，单场直播间同时在线人数可达数十万甚至上百万，弹幕系统需要支持这种量级的扇出。
- 多端接入：H5、Android、iOS、PC、小程序等多种客户端形态需要统一接入。

### 1.3 核心挑战

结合学城文档对推送系统的设计目标描述，弹幕系统需要同时满足以下几个维度的要求：

| 挑战维度 | 具体问题 | 对应设计目标 |
|---------|---------|-------------|
| 高并发写入 | 百万观众同时发弹幕，写入QPS峰值极高 | 支持高并发，系统可水平扩容 |
| 海量扇出 | 一条弹幕要广播给直播间内所有在线用户，消息体量被放大数万甚至数十万倍 | 单机高吞吐推送能力，支持横向扩展 |
| 实时性 | 弹幕延迟必须控制在1秒以内，否则互动体验割裂 | 弹幕消息延时控制在1s以内 |
| 消息分级 | 高峰期弹幕量远超客户端渲染/带宽承载能力，需要区分消息优先级 | 支持消息优先级设置，内置丢弃策略保证用户端体验 |
| 多协议多端 | 客户端形态多样，网络环境复杂 | 支持多协议（WebSocket、TCP、HTTP），支持多端（H5、Android、iOS、PC） |
| 鉴权与安全 | 弹幕作为公开可见内容，容易被恶意刷屏、注入 | 支持鉴权，确保消息安全 |
| 消息回看 | 点播场景需要将历史弹幕按时间轴重放 | 支持消息回看 |
| 内容审核 | 弹幕需要实时过滤敏感词、违规内容 | 结合审核链路做前置过滤 |

以上目标共同决定了弹幕系统在架构上必须是一个"高并发、高实时、可分级降级"的推送系统，而不是一个简单的聊天室实现。

## 二、整体架构设计

### 2.1 分层架构

参考学城文档对直播互动系统的架构分层描述，系统整体可以划分为四层：**客户端层、网络接入层、业务逻辑层、数据存储层**。

学城文档指出架构分层的三个主要考量点：

1. 由于长连接承载了大部分实时推送职责，短连接更适合处理账号、关系链等偏静态的业务，长连接聚焦于上线维护和消息推送。
2. 后台架构需要具备灵活性和可扩展性，支持分布式部署：把**网络接入层**、**业务逻辑层**、**数据存储层**分离，接入层和逻辑层支持负载均衡策略，存储层支持分布式存储。
3. 客户端SDK的易用性同样依赖于这种分层：上层业务不需要关心底层协议细节。


### 2.2 各角色职责

学城文档给出了长连接推送架构的经典四角色划分，这套分工模型在弹幕/直播互动系统中被广泛复用：

- **Connect Server（网络接入层/网关层）**：负责维护海量用户的长连接，支持多协议接入（HTTP长轮询、TCP、WebSocket），通过水平扩容支撑海量用户，具备连接超时和心跳保活机制。这一层是弹幕系统面向公网的门面，不承载业务逻辑。
- **Logic Server（业务逻辑层）**：负责业务逻辑处理，并将处理后的消息投递给Job服务器。它是消息推送的入口，通过用户ID在Router服务中查找该用户当前连接在哪个Connect节点上，再将目标节点ID和消息内容一起写入消息队列。Logic是无状态服务，可以随意扩缩容。
- **Job Server（消息转发层）**：从消息队列中获取消息，按照消息中标注的目标Connect节点ID，将消息发送给对应的Connect服务器完成最终投递。Job同样是无状态服务。
- **Router Server（路由存储层）**：存储"用户-连接"的映射关系。当Connect服务器接收到用户连接后，会通过Logic服务器把这个连接的注册信息（Session）保存到Router中，从而知道某个用户当前连接在哪台Connect机器上。

这种"Connect负责连接、Logic负责路由决策、Job负责转发、Router负责存储映射"的四层拆分，本质上是把"连接管理"和"消息处理"两个关注点彻底解耦——Connect层可以独立按连接数扩容，Logic/Job层可以独立按消息吞吐扩容，两者互不干扰。

### 2.3 网络部署考量

学城文档特别强调了单机房部署的问题：**单机房部署会有掉线率高、不稳定的问题，需要在网络结构上做调整**。具体做法：

1. Connect接入层服务需要部署到全国多个区域的BGP机房中，通过DNS智能解析，让用户就近接入，降低网络延迟和抖动。
2. 除Connect服务外的其他服务（Logic、Job、Router）部署到一个或多个中心机房，中心机房和各Connect机房之间需要有高质量的专线网络通道，保证消息转发的稳定性。

这种"边缘接入 + 中心处理"的部署模式，兼顾了连接就近性和逻辑处理的集中性，是大规模长连接系统的通用部署范式。

### 2.4 技术选型对比

学城文档中对直播互动系统常见的网络传输协议做了系统性对比，弹幕系统在选型时应参考类似的权衡：

| 协议 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| WebSocket | Web浏览器和服务器之间的全双工通信协议，一旦建立连接后续通信都基于该连接进行 | 实现简单，方便开发上手，同时保证性能和消息及时性 | 部分老旧网络环境和代理对WebSocket支持不佳 |
| HTTP长轮询 | 客户端发起请求，服务端hold住连接直到有数据或超时 | 实现简单，消息规模不大时可满足要求 | 消息规模增大后会出现连接挂起导致资源浪费的情况 |
| TCP长连接 | 客户端与服务端建立持久TCP连接 | 能更好地支持大批量用户，实时性好 | 客户端和服务端实现复杂，需要解决单机高并发和扩展架构问题 |
| UDP | 无连接传输协议 | 实时性更好 | 处理安全可靠传输和不同客户端间消息交互较为复杂，工程实现门槛高 |

综合权衡，业界通用做法是**原生App使用TCP长连接，H5/小程序场景使用WebSocket**，两者通过统一的接入网关抽象成相同的内部消息格式，上层业务逻辑不感知具体传输协议差异。

## 三、核心链路设计

### 3.1 弹幕发送链路总览

弹幕发送的核心链路遵循学城文档描述的推送系统模型：

```
客户端 → WebSocket网关接收 → 频率限制（防刷屏）
      → 敏感词过滤（DFA算法）→ 分配弹幕轨道
      → 写入消息管道（Kafka）→ 消费者按直播间分发推送
      → 异步持久化（供历史回放）
```

以下用完整的Java代码实现这条链路。

#### 3.1.1 弹幕消息模型

```java
/**
 * 弹幕消息实体
 */
public class DanmakuMessage implements Serializable {

    private Long danmakuId;        // 弹幕唯一ID
    private Long roomId;           // 直播间/视频ID
    private Long userId;           // 发送者ID
    private String content;        // 弹幕文本内容
    private String color;          // 弹幕颜色
    private Integer fontSize;      // 字号
    private Integer priority;      // 消息优先级：0-高（礼物/系统）1-中（付费弹幕）2-低（普通弹幕）
    private Long timestamp;        // 服务端接收时间戳
    private Integer videoTimestamp; // 点播场景下对应的视频内时间点（秒）

    // getter/setter省略
}

/**
 * 弹幕发送请求
 */
public class DanmakuRequest {
    private Long roomId;
    private String content;
    private String color;
    private Integer fontSize;
    private Integer videoTimestamp;
    // getter/setter省略
}
```

#### 3.1.2 弹幕发送服务

```java
/**
 * 弹幕发送服务
 *
 * 完整链路：
 * 1. WebSocket网关接收弹幕请求
 * 2. 频率限制（防刷屏）
 * 3. 敏感词过滤（DFA算法）
 * 4. 分配弹幕轨道（避免客户端渲染重叠，服务端可选择做统一规划）
 * 5. 写入消息管道（按直播间分区，保证同一直播间消息有序）
 * 6. 消费者按优先级/丢弃策略分发推送
 * 7. 异步持久化，供点播回放使用
 */
@Service
public class DanmakuSendService {

    @Autowired
    private SensitiveWordFilter sensitiveFilter;

    @Autowired
    private DanmakuRateLimiter rateLimiter;

    @Autowired
    private MessageChannelProducer messageProducer;

    @Autowired
    private DanmakuIdGenerator idGenerator;

    /**
     * 发送弹幕
     */
    public SendResult send(DanmakuRequest request, Long userId) {

        // 1. 用户级频率限制：防止单用户刷屏
        if (!rateLimiter.checkUserRate(userId)) {
            return SendResult.fail("发送太频繁，请稍后再试");
        }

        // 2. 直播间级限流：单个直播间弹幕总量控制
        if (!rateLimiter.checkRoomRate(request.getRoomId())) {
            return SendResult.fail("当前弹幕过多，请稍后再试");
        }

        // 3. 敏感词过滤（不通过则拒绝发送，而不是仅仅打码）
        if (sensitiveFilter.contains(request.getContent())) {
            return SendResult.fail("弹幕包含敏感内容");
        }
        String filteredContent = sensitiveFilter.filter(request.getContent());

        // 4. 构建弹幕消息
        DanmakuMessage msg = new DanmakuMessage();
        msg.setDanmakuId(idGenerator.nextId());
        msg.setRoomId(request.getRoomId());
        msg.setUserId(userId);
        msg.setContent(filteredContent);
        msg.setColor(request.getColor());
        msg.setFontSize(request.getFontSize());
        msg.setPriority(DanmakuPriority.NORMAL.getCode());
        msg.setTimestamp(System.currentTimeMillis());
        msg.setVideoTimestamp(request.getVideoTimestamp());

        // 5. 写入消息管道：按直播间ID做分区键，保证同一直播间消息顺序性
        messageProducer.sendDanmaku(msg);

        return SendResult.success(msg.getDanmakuId());
    }
}
```

#### 3.1.3 消息管道生产者

```java
/**
 * 消息管道生产者
 *
 * 弹幕消息按 roomId 分区写入消息管道，
 * 保证同一直播间的消息在同一分区内保持发送顺序
 */
@Component
public class MessageChannelProducer {

    @Autowired
    private KafkaTemplate<String, DanmakuMessage> kafkaTemplate;

    private static final int PARTITION_COUNT = 32;

    public void sendDanmaku(DanmakuMessage msg) {
        String topic = "danmaku-topic";
        // 使用roomId作为分区键，保证同一直播间弹幕顺序投递到同一分区
        String partitionKey = String.valueOf(msg.getRoomId());
        kafkaTemplate.send(topic, partitionKey, msg);
    }

    /**
     * 高优先级消息（礼物特效、系统公告等）走独立Topic，
     * 避免被普通弹幕的流量洪峰淹没
     */
    public void sendHighPriority(DanmakuMessage msg) {
        kafkaTemplate.send("danmaku-priority-topic",
            String.valueOf(msg.getRoomId()), msg);
    }
}
```

### 3.2 消息分发：Kafka消费者推送

```java
/**
 * 弹幕分发消费者
 *
 * 消费消息管道中的弹幕消息，推送给该直播间内所有在线连接
 * 分发前经过优先级判断和丢弃策略（详见第四章）
 */
@Component
public class DanmakuDispatchConsumer {

    @Autowired
    private ConnectionRegistry connectionRegistry;

    @Autowired
    private DanmakuPriorityDropStrategy dropStrategy;

    @KafkaListener(topics = "danmaku-topic", groupId = "danmaku-dispatch-group",
                   concurrency = "16")
    public void dispatch(DanmakuMessage msg) {

        // 1. 获取该直播间所有在线连接
        Set<String> connectionIds = connectionRegistry.getConnectionsByRoom(msg.getRoomId());
        if (connectionIds.isEmpty()) {
            return;
        }

        // 2. 应用优先级丢弃策略，决定本条消息是否需要下发、下发比例
        if (!dropStrategy.shouldDeliver(msg, connectionIds.size())) {
            return;
        }

        // 3. 序列化消息（一次序列化，多次复用，避免重复编码开销）
        String payload = JSON.toJSONString(msg);

        // 4. 批量异步推送
        for (String connectionId : connectionIds) {
            connectionRegistry.pushAsync(connectionId, payload);
        }
    }

    @KafkaListener(topics = "danmaku-priority-topic", groupId = "danmaku-priority-group")
    public void dispatchHighPriority(DanmakuMessage msg) {
        // 高优先级消息不参与丢弃策略，全量下发
        Set<String> connectionIds = connectionRegistry.getConnectionsByRoom(msg.getRoomId());
        String payload = JSON.toJSONString(msg);
        for (String connectionId : connectionIds) {
            connectionRegistry.pushAsync(connectionId, payload);
        }
    }
}
```

## 四、消息优先级与丢弃策略

### 4.1 为什么必须做丢弃

学城文档在描述弹幕通道能力时明确指出：

> "支持消息优先级设置，内置了丢弃策略，保证用户端体验（业界通常控制每秒下发到客户端的消息量，基于高低优先级执行丢弃策略）"

这是弹幕系统区别于普通消息系统的核心设计理念之一：**弹幕系统不追求100%消息必达，而是追求用户体验的稳定性**。原因很直观——当一个直播间同时在线人数达到十万甚至百万级别时，如果所有人发的弹幕都要求全量、无损地投递给每一个客户端，会带来两个致命问题：

1. **服务端扇出压力爆炸**：假设每秒有1000条弹幕，直播间有50万在线用户，理论下发次数是5亿次/秒，远超任何单机或集群能承受的范围。
2. **客户端渲染和带宽瓶颈**：客户端每秒能渲染的弹幕数量是有限的（受屏幕大小、渲染性能、可读性约束），即使服务端把所有消息都推给客户端，用户也看不过来，反而造成体验灾难（弹幕完全糊在一起）和不必要的流量消耗。

因此业界通用做法是"控制每秒下发到客户端的消息总量，超出部分按优先级丢弃"，用有损但可控的方式换取系统的稳定性和用户体验的一致性。

### 4.2 优先级分级模型

```java
/**
 * 弹幕消息优先级枚举
 *
 * 优先级从高到低：系统消息 > 礼物特效 > 付费弹幕/管理员消息 > 普通弹幕
 */
public enum DanmakuPriority {

    SYSTEM(0, "系统公告", Integer.MAX_VALUE),      // 永不丢弃
    GIFT(1, "礼物特效", 1000),                      // 极少丢弃
    VIP(2, "付费弹幕/管理员消息", 500),              // 优先保证
    NORMAL(3, "普通弹幕", 100);                     // 按容量丢弃

    private final int code;
    private final String desc;
    private final int weight; // 权重越高，被保留概率越大

    DanmakuPriority(int code, String desc, int weight) {
        this.code = code;
        this.desc = desc;
        this.weight = weight;
    }

    public int getCode() { return code; }
    public String getDesc() { return desc; }
    public int getWeight() { return weight; }
}
```

### 4.3 高低优先级丢弃策略实现

丢弃策略的核心思路：**每个直播间维护一个"每秒下发预算"，消息进来后先按优先级排队，预算耗尽后，低优先级消息被直接丢弃，不进入客户端下发队列**。

```java
/**
 * 弹幕优先级丢弃策略
 *
 * 核心思想：
 * 1. 每个直播间每秒设定一个下发消息数上限（如：每用户每秒最多接收若干条）
 * 2. 高优先级消息（系统/礼物）尽量全量下发，几乎不丢
 * 3. 低优先级消息（普通弹幕）在预算不足时按概率/权重丢弃
 * 4. 观众规模越大，单条消息的丢弃概率相应提高（避免带宽和渲染过载）
 */
@Component
public class DanmakuPriorityDropStrategy {

    // 每个直播间的令牌桶：key为roomId，value为剩余下发预算
    private final Map<Long, AtomicInteger> roomBudget = new ConcurrentHashMap<>();

    // 每秒基础预算（可根据机器规格及网络带宽调整）
    private static final int BASE_BUDGET_PER_SECOND = 2000;

    private final ScheduledExecutorService scheduler =
        Executors.newSingleThreadScheduledExecutor();

    @PostConstruct
    public void init() {
        // 每秒重置一次预算
        scheduler.scheduleAtFixedRate(this::resetBudget, 1, 1, TimeUnit.SECONDS);
    }

    private void resetBudget() {
        roomBudget.forEach((roomId, counter) -> counter.set(BASE_BUDGET_PER_SECOND));
    }

    /**
     * 判断该消息是否应该下发
     *
     * @param msg 弹幕消息
     * @param onlineCount 当前直播间在线人数
     */
    public boolean shouldDeliver(DanmakuMessage msg, int onlineCount) {

        DanmakuPriority priority = DanmakuPriority.values()[msg.getPriority()];

        // 系统消息永不丢弃
        if (priority == DanmakuPriority.SYSTEM) {
            return true;
        }

        AtomicInteger budget = roomBudget.computeIfAbsent(msg.getRoomId(),
            k -> new AtomicInteger(BASE_BUDGET_PER_SECOND));

        // 在线人数越多，单条消息消耗的"预算权重"越高，
        // 因为下发一条消息意味着扇出到更多连接，成本更高
        int cost = calculateCost(onlineCount, priority);

        int remaining = budget.addAndGet(-cost);
        if (remaining >= 0) {
            return true; // 预算充足，正常下发
        }

        // 预算不足，按优先级概率决定是否仍然放行（软丢弃，避免完全饥饿）
        double surviveProbability = priority.getWeight() / (double) DanmakuPriority.NORMAL.getWeight() * 0.3;
        return ThreadLocalRandom.current().nextDouble() < surviveProbability;
    }

    /**
     * 计算单条消息消耗的预算：在线人数越大，扇出成本越高，
     * 用对数平滑，避免超大直播间预算瞬间清零
     */
    private int calculateCost(int onlineCount, DanmakuPriority priority) {
        int baseCost = (int) Math.max(1, Math.log10(onlineCount + 10));
        // 优先级越低，相对成本系数越高（更容易触发丢弃）
        double priorityFactor = (DanmakuPriority.NORMAL.getWeight() + 1.0) / (priority.getWeight() + 1.0);
        return (int) Math.ceil(baseCost * priorityFactor);
    }
}
```

### 4.4 客户端侧下发抽样

除了服务端预算控制，针对超大直播间（如50万以上在线），还需要在广播扇出前做"抽样式广播"，进一步降低单条消息的服务端下发成本：

```java
/**
 * 超大直播间抽样广播策略
 *
 * 当在线人数超过阈值时，不再对所有连接逐一推送，
 * 而是按抽样比例随机选取一部分连接进行推送，
 * 抽样比例随人数规模动态调整
 */
@Component
public class LargeRoomSamplingStrategy {

    private static final int SAMPLING_THRESHOLD = 50_000;

    /**
     * 根据在线人数计算抽样比例
     */
    public double calculateSampleRate(int onlineCount) {
        if (onlineCount <= SAMPLING_THRESHOLD) {
            return 1.0; // 不抽样，全量下发
        }
        // 人数越多，抽样比例越低，但保证一个下限（如20%），避免观众完全看不到弹幕
        double rate = (double) SAMPLING_THRESHOLD / onlineCount;
        return Math.max(rate, 0.2);
    }

    /**
     * 对连接集合做抽样，返回本次实际推送的连接子集
     */
    public List<String> sample(Set<String> connectionIds, double sampleRate) {
        if (sampleRate >= 1.0) {
            return new ArrayList<>(connectionIds);
        }
        List<String> all = new ArrayList<>(connectionIds);
        Collections.shuffle(all);
        int sampleSize = (int) (all.size() * sampleRate);
        return all.subList(0, sampleSize);
    }
}
```

### 5.2 连接注册中心

```java
/**
 * 连接注册中心
 *
 * 维护 roomId -> Set<connectionId> 以及 connectionId -> Connection 的映射
 * 用户进入直播间时注册连接，退出/断开时注销
 *
 * 单机维度的注册中心之外，还需要一个分布式Router（如Redis）
 * 记录 userId -> 所在Connect节点 的映射，供跨节点消息路由使用
 */
@Component
public class ConnectionRegistry {

    // roomId -> 该直播间所有连接ID
    private final ConcurrentHashMap<Long, Set<String>> roomConnections =
        new ConcurrentHashMap<>();

    // connectionId -> Connection 实例
    private final ConcurrentHashMap<String, Connection> connections =
        new ConcurrentHashMap<>();

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Value("${server.node.id}")
    private String nodeId;

    private final ExecutorService pushExecutor =
        new ThreadPoolExecutor(32, 64, 60, TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(100_000),
            new ThreadFactoryBuilder().setNameFormat("danmaku-push-%d").build(),
            new ThreadPoolExecutor.CallerRunsPolicy());

    /**
     * 用户连接建立时注册
     */
    public void register(Connection connection) {
        connections.put(connection.getConnectionId(), connection);
        roomConnections.computeIfAbsent(connection.getRoomId(),
            k -> ConcurrentHashMap.newKeySet()).add(connection.getConnectionId());

        // 写入分布式Router，记录用户当前连接所在的节点，供跨节点路由
        String routerKey = "danmaku:router:" + connection.getUserId();
        redisTemplate.opsForValue().set(routerKey, nodeId, 1, TimeUnit.HOURS);
    }

    /**
     * 连接断开时注销
     */
    public void unregister(Connection connection) {
        connections.remove(connection.getConnectionId());
        Set<String> set = roomConnections.get(connection.getRoomId());
        if (set != null) {
            set.remove(connection.getConnectionId());
            if (set.isEmpty()) {
                roomConnections.remove(connection.getRoomId());
            }
        }

        String routerKey = "danmaku:router:" + connection.getUserId();
        redisTemplate.delete(routerKey);
    }

    /**
     * 获取某直播间所有在线连接ID
     */
    public Set<String> getConnectionsByRoom(Long roomId) {
        return roomConnections.getOrDefault(roomId, Collections.emptySet());
    }

    /**
     * 异步推送单条消息
     */
    public void pushAsync(String connectionId, String message) {
        Connection connection = connections.get(connectionId);
        if (connection == null || !connection.isOpen()) {
            return;
        }
        pushExecutor.submit(() -> {
            try {
                connection.send(message);
            } catch (Exception e) {
                unregister(connection);
            }
        });
    }

    /**
     * 获取某直播间在线人数（用于丢弃策略、抽样策略计算）
     */
    public int getOnlineCount(Long roomId) {
        return getConnectionsByRoom(roomId).size();
    }
}
```

### 5.3 心跳保活与超时清理

长连接系统必须处理"僵尸连接"问题——客户端异常断开（如网络切换、App被杀）但服务端未及时感知的情况。学城文档在Connect服务的职责描述中提到"有超时机制"，具体实现如下：

```java
/**
 * 心跳保活管理
 *
 * 客户端定期发送心跳包，服务端记录最后心跳时间
 * 超过一定时长未收到心跳则判定连接失效，主动清理
 */
@Component
public class HeartbeatManager {

    private final Map<String, Long> lastHeartbeatTime = new ConcurrentHashMap<>();

    private static final long HEARTBEAT_TIMEOUT_MS = 60_000; // 60秒无心跳视为超时

    @Autowired
    private ConnectionRegistry connectionRegistry;

    public void onHeartbeat(String connectionId) {
        lastHeartbeatTime.put(connectionId, System.currentTimeMillis());
    }

    /**
     * 定时扫描超时连接并清理
     */
    @Scheduled(fixedRate = 15_000)
    public void scanTimeoutConnections() {
        long now = System.currentTimeMillis();
        Iterator<Map.Entry<String, Long>> it = lastHeartbeatTime.entrySet().iterator();
        while (it.hasNext()) {
            Map.Entry<String, Long> entry = it.next();
            if (now - entry.getValue() > HEARTBEAT_TIMEOUT_MS) {
                // 通知连接注册中心清理该连接
                connectionRegistry.closeAndUnregister(entry.getKey());
                it.remove();
            }
        }
    }
}
```

### 5.4 鉴权设计

学城文档设计目标中提出"支持鉴权，确保消息安全"，实现上通常在建立连接时通过Token校验：

```java
 * 未授权用户不允许建立连接，避免未鉴权流量消耗接入层资源

@Component
public class DanmakuAuthInterceptor implements HandshakeInterceptor {

    private TokenService tokenService;

    @Override
    public boolean beforeHandshake(ServerHttpRequest request, ServerHttpResponse response,

        String token = extractToken(request);
        if (token == null) {

            return false;

        return true;
    }

        List<String> params = UriComponentsBuilder.fromUri(request.getURI())
            .build().getQueryParams().get("token");
        return CollectionUtils.isEmpty(params) ? null : params.get(0);
    }

    @Override
    public void afterHandshake(ServerHttpRequest request, ServerHttpResponse response,
                                WebSocketHandler wsHandler, Exception exception) {
        // 无需处理
    }
}
```

## 六、敏感词过滤：DFA算法

### 6.1 为什么选择DFA

弹幕作为公开可见的实时内容，必须在写入消息管道之前完成敏感词过滤，否则一旦扩散到全直播间将无法撤回。敏感词匹配对性能要求极高——弹幕系统的QPS可能是每秒数千甚至数万条，如果用简单的字符串包含（`String.contains`）逐词匹配，词库稍大时匹配性能会急剧下降。

DFA（Deterministic Finite Automaton，确定有限自动机）通过构建一棵字符树（Trie树的变种），实现**一次遍历文本即可完成所有敏感词的匹配**，时间复杂度为O(n)，n为文本长度，与敏感词库大小无关，非常适合弹幕这种高频短文本的场景。

### 6.2 DFA树构建与匹配实现

```java
/**
 * 敏感词过滤器（DFA算法实现）
 *
 * 核心数据结构：以字符为节点的多叉树（Map嵌套Map模拟）
 * 每个节点标记是否为某个敏感词的结束位置
 *
 * 时间复杂度：
 * - 构建：O(所有敏感词总字符数)
 * - 匹配：O(待检测文本长度)，与词库大小无关
 */
@Component
public class SensitiveWordFilter {

    private final Map<Character, Object> sensitiveTree = new HashMap<>();
    private static final String END_FLAG = "isEnd";

    @Autowired
    private SensitiveWordRepository wordRepository;

    @PostConstruct
    public void init() {
        List<String> words = wordRepository.loadAll();
        for (String word : words) {
            addWord(word);
        }
    }

    /**
     * 向DFA树中添加一个敏感词
     */
    @SuppressWarnings("unchecked")
    private void addWord(String word) {
        Map<Character, Object> current = sensitiveTree;
        for (int i = 0; i < word.length(); i++) {
            char c = word.charAt(i);
            Map<Character, Object> next = (Map<Character, Object>) current.get(c);
            if (next == null) {
                next = new HashMap<>();
                current.put(c, next);
            }
            current = next;
            if (i == word.length() - 1) {
                current.put(END_FLAG, Boolean.TRUE);
            }
        }
    }

    /**
     * 运行时动态添加敏感词（无需重启服务）
     */
    public synchronized void addWordAtRuntime(String word) {
        addWord(word);
    }

    /**
     * 过滤敏感词：将命中的敏感词替换为等长的 * 号
     *
     * 采用"最大长度匹配"策略：在同一起点上，优先匹配最长的敏感词，
     * 避免短词命中后漏掉更长的完整敏感词
     */
    @SuppressWarnings("unchecked")
    public String filter(String text) {
        if (text == null || text.isEmpty()) {
            return text;
        }

        StringBuilder result = new StringBuilder(text.length());
        int i = 0;

        while (i < text.length()) {
            int matchLength = matchLongestFrom(text, i);
            if (matchLength > 0) {
                for (int k = 0; k < matchLength; k++) {
                    result.append('*');
                }
                i += matchLength;
            } else {
                result.append(text.charAt(i));
                i++;
            }
        }

        return result.toString();
    }

    /**
     * 从指定起点开始，尝试匹配最长的敏感词，返回匹配长度（0表示未命中）
     */
    @SuppressWarnings("unchecked")
    private int matchLongestFrom(String text, int start) {
        Map<Character, Object> current = sensitiveTree;
        int matchEnd = -1;

        int j = start;
        while (j < text.length()) {
            char c = text.charAt(j);
            Object node = current.get(c);
            if (node == null) {
                break;
            }
            current = (Map<Character, Object>) node;
            if (Boolean.TRUE.equals(current.get(END_FLAG))) {
                matchEnd = j; // 记录当前最长命中位置，继续尝试往后延伸匹配更长的词
            }
            j++;
        }

        return matchEnd >= 0 ? (matchEnd - start + 1) : 0;
    }

    /**
     * 判断文本是否包含敏感词（不做替换，仅做检测）
     */
    public boolean contains(String text) {
        if (text == null || text.isEmpty()) {
            return false;
        }
        for (int i = 0; i < text.length(); i++) {
            if (matchLongestFrom(text, i) > 0) {
                return true;
            }
        }
        return false;
    }
}
```

## 七、弹幕轨道算法（防重叠）

### 7.1 问题描述

弹幕在客户端展示时如果不做轨道规划，多条弹幕会在同一高度重叠显示，严重影响可读性。业界通用做法是将屏幕划分为若干条水平"轨道"，每条弹幕从右侧滑入、匀速向左滑出，同一轨道上的相邻弹幕之间需要保持足够的时间/空间间隔，避免追尾重叠。

轨道分配既可以完全交给客户端本地计算（客户端有精确的渲染帧率和实际画布尺寸），也可以在服务端做一次粗粒度的轨道预分配（用于弹幕特效优先级展示、防止刷屏攻击提前拦截等场景）。下面给出服务端侧的轨道分配算法实现，客户端可采用类似逻辑做本地渲染优化。

### 7.2 轨道分配算法实现

```java
/**
 * 弹幕轨道管理器
 *
 * 轨道算法核心逻辑：
 * 1. 屏幕（或渲染区域）划分为N条轨道
 * 2. 每条轨道记录"上一条弹幕完全滑出屏幕的时间点"
 * 3. 新弹幕到来时，优先选择最早空闲的轨道
 * 4. 若所有轨道都被占用，则该弹幕排队等待或直接丢弃（取决于优先级）
 */
public class DanmakuTrackManager {

    private final int trackCount;
    // 每条轨道：记录当前轨道上最后一条弹幕的完全滑出时间
    private final double[] trackFreeTime;

    public DanmakuTrackManager(int trackCount) {
        this.trackCount = trackCount;
        this.trackFreeTime = new double[trackCount];
    }

    /**
     * 尝试为一条新弹幕分配轨道
     *
     * @param currentTime   当前时间（秒，可用视频播放进度或系统时间）
     * @param danmakuWidth  弹幕文本渲染后的像素宽度
     * @param screenWidth   屏幕/渲染区域宽度
     * @param speed         弹幕滑动速度（像素/秒）
     * @return 轨道编号，-1表示当前无可用轨道
     */
    public synchronized int allocateTrack(double currentTime, int danmakuWidth,
                                           int screenWidth, double speed) {
        // 弹幕完全滑出屏幕所需时间
        double passTime = (screenWidth + danmakuWidth) / speed;
        double occupyUntil = currentTime + passTime;

        // 安全间距：保证前一条弹幕的尾部已经与新弹幕头部拉开一定距离，避免视觉追尾
        double safeGap = (danmakuWidth / speed) * 0.5;

        int bestTrack = -1;
        double earliestFreeTime = Double.MAX_VALUE;

        for (int i = 0; i < trackCount; i++) {
            if (trackFreeTime[i] <= currentTime) {
                // 该轨道已完全空闲，直接使用
                trackFreeTime[i] = occupyUntil;
                return i;
            }
            // 记录最早会释放的轨道，作为兜底选择
            if (trackFreeTime[i] < earliestFreeTime) {
                earliestFreeTime = trackFreeTime[i];
                bestTrack = i;
            }
        }

        // 没有完全空闲的轨道，判断最早释放的轨道是否已经满足安全间距
        if (bestTrack >= 0 && (currentTime - (earliestFreeTime - safeGap)) >= 0) {
            trackFreeTime[bestTrack] = occupyUntil;
            return bestTrack;
        }

        return -1; // 所有轨道都被占用且不满足安全间距，本条弹幕丢弃或降级为浮层展示
    }

    /**
     * 重置轨道状态（如切换直播间、视频重新播放时调用）
     */
    public synchronized void reset() {
        Arrays.fill(trackFreeTime, 0);
    }
}
```

### 8.4 回放查询服务

```java

 * 历史弹幕回放服务
 *
 * 点播场景下，客户端根据当前播放进度分段预拉取弹幕，
 * 通常以30秒~60秒为一个窗口，提前拉取即将播放到的弹幕数据

@Service
public class DanmakuReplayService {

    @Autowired
    private DanmakuHistoryMapper historyMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final int CACHE_WINDOW_SECONDS = 60;

    /**
     * 查询某视频指定时间窗口内的历史弹幕，优先走缓存
     */
    public List<DanmakuVO> getHistoryDanmaku(Long roomId, int startSeconds, int endSeconds) {
        String cacheKey = buildCacheKey(roomId, startSeconds);
        String cached = redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return JSON.parseArray(cached, DanmakuVO.class);
        }

        List<DanmakuHistory> list = historyMapper.selectByTimeRange(roomId, startSeconds, endSeconds);
        List<DanmakuVO> result = list.stream().map(this::toVO).collect(Collectors.toList());

        redisTemplate.opsForValue().set(cacheKey, JSON.toJSONString(result),
            10, TimeUnit.MINUTES);

        return result;
    }

    private String buildCacheKey(Long roomId, int startSeconds) {
        int window = startSeconds / CACHE_WINDOW_SECONDS;
        return "danmaku:replay:" + roomId + ":" + window;
    }

    private DanmakuVO toVO(DanmakuHistory h) {
        DanmakuVO vo = new DanmakuVO();
        vo.setContent(h.getContent());
        vo.setColor(h.getColor());
        vo.setFontSize(h.getFontSize());
        vo.setVideoTimestamp(h.getVideoTimestamp());
        return vo;
    }

    /**
     * 弹幕密度统计：用于生成"弹幕热力图"，
     * 提示用户视频中哪些时间段互动最活跃
     */
    public List<DanmakuDensityPoint> getDensityMap(Long roomId, int videoDurationSeconds, int bucketSeconds) {
        List<DanmakuDensityPoint> result = new ArrayList<>();
        for (int start = 0; start < videoDurationSeconds; start += bucketSeconds) {
            int end = Math.min(start + bucketSeconds, videoDurationSeconds);
            int count = historyMapper.countByTimeRange(roomId, start, end);
            result.add(new DanmakuDensityPoint(start, count));
        }
        return result;
    }
}
```

## 九、性能优化：向单机600W消息/秒看齐

### 9.1 学城文档的性能基准

学城文档给出了业界推送系统的一组具体性能指标，可以作为弹幕系统性能优化的参照基准：

> "单机支持600W消息/s的发送能力，可横向扩展（如单机同时在线人数为5万，每个用户每秒可收120条消息）"
> "弹幕消息延时控制在1s以内"

这组数字揭示了一个关键设计理念：**单机吞吐能力 = 在线连接数 × 每连接每秒可承受的消息数**。以5万在线连接、每连接每秒120条为例，单机总吞吐约为600万消息/秒。要达到这个量级，必须在多个层面做系统性优化。

### 9.2 连接层优化：I/O模型与线程模型

```java
/**
 * 基于Netty的高性能长连接接入层配置示例
 *
 * 核心优化点：
 * 1. 使用epoll事件驱动模型（Linux下EpollEventLoopGroup），避免阻塞式I/O
 * 2. Boss线程组与Worker线程组分离，Boss只负责accept连接
 * 3. 合理设置Worker线程数（通常为CPU核数的1~2倍）
 * 4. 开启TCP_NODELAY，降低小数据包的传输延迟
 */
@Configuration
public class NettyServerConfig {

    @Bean
    public ServerBootstrap serverBootstrap() {
        EventLoopGroup bossGroup = new EpollEventLoopGroup(1);
        EventLoopGroup workerGroup = new EpollEventLoopGroup(
            Runtime.getRuntime().availableProcessors() * 2);

        ServerBootstrap bootstrap = new ServerBootstrap();
        bootstrap.group(bossGroup, workerGroup)
            .channel(EpollServerSocketChannel.class)
            .option(ChannelOption.SO_BACKLOG, 65536)
            .option(ChannelOption.SO_REUSEADDR, true)
            .childOption(ChannelOption.TCP_NODELAY, true)
            .childOption(ChannelOption.SO_KEEPALIVE, true)
            .childHandler(new ChannelInitializer<SocketChannel>() {
                @Override
                protected void initChannel(SocketChannel ch) {
                    ch.pipeline()
                        .addLast(new HttpServerCodec())
                        .addLast(new HttpObjectAggregator(65536))
                        .addLast(new WebSocketServerProtocolHandler("/danmaku"))
                        .addLast(new DanmakuFrameHandler());
                }
            });

        return bootstrap;
    }
}
```

### 9.3 批量推送：降低系统调用开销

单条消息单次系统调用（write）的开销在超大规模推送场景下会成为瓶颈。将同一直播间在短时间窗口内产生的多条弹幕合并成一批推送，能显著降低网络I/O调用次数。

```java
/**
 * 弹幕批量聚合推送服务
 *
 * 高峰期逐条推送WebSocket帧效率低下（大量小包），
 * 将100ms窗口内同一直播间产生的多条弹幕合并为一批，一次性推送
 */
@Service
public class DanmakuBatchPushService {

    private final Map<Long, Queue<DanmakuMessage>> buffer = new ConcurrentHashMap<>();

    @Autowired
    private ConnectionRegistry connectionRegistry;

    private final ScheduledExecutorService scheduler =
        Executors.newScheduledThreadPool(4, new ThreadFactoryBuilder()
            .setNameFormat("danmaku-batch-flush-%d").build());

    @PostConstruct
    public void init() {
        scheduler.scheduleAtFixedRate(this::flush, 100, 100, TimeUnit.MILLISECONDS);
    }

    public void offer(DanmakuMessage msg) {
        buffer.computeIfAbsent(msg.getRoomId(), k -> new ConcurrentLinkedQueue<>()).add(msg);
    }

    private void flush() {
        for (Map.Entry<Long, Queue<DanmakuMessage>> entry : buffer.entrySet()) {
            Long roomId = entry.getKey();
            Queue<DanmakuMessage> queue = entry.getValue();
            if (queue.isEmpty()) {
                continue;
            }

            List<DanmakuMessage> batch = new ArrayList<>();
            DanmakuMessage msg;
            while ((msg = queue.poll()) != null) {
                batch.add(msg);
            }
            if (batch.isEmpty()) {
                continue;
            }

            String payload = JSON.toJSONString(batch);
            Set<String> connectionIds = connectionRegistry.getConnectionsByRoom(roomId);
            for (String connectionId : connectionIds) {
                connectionRegistry.pushAsync(connectionId, payload);
            }
        }
    }
}
```

### 9.4 分层限流：用户级、直播间级、全局级

```java
/**
 * 弹幕三层限流体系
 *
 * 1. 用户级：单用户防刷屏
 * 2. 直播间级：单直播间弹幕总量控制，避免热门直播间打垮下游
 * 3. 全局级（单机）：保护单机不被瞬时流量击穿
 */
@Service
public class DanmakuRateLimiter {

    @Autowired
    private StringRedisTemplate redisTemplate;

    // 用户级：每用户3秒最多发送1条
    public boolean checkUserRate(Long userId) {
        String key = "danmaku:freq:user:" + userId;
        Boolean success = redisTemplate.opsForValue().setIfAbsent(key, "1", 3, TimeUnit.SECONDS);
        return Boolean.TRUE.equals(success);
    }

    // 直播间级：每直播间每秒最多1000条进入处理链路
    public boolean checkRoomRate(Long roomId) {
        String key = "danmaku:freq:room:" + roomId;
        Long count = redisTemplate.opsForValue().increment(key);
        if (count != null && count == 1L) {
            redisTemplate.expire(key, 1, TimeUnit.SECONDS);
        }
        return count != null && count <= 1000;
    }

    // 全局级（单机）：基于令牌桶算法的进程内限流，保护单机不被打垮
    private final RateLimiter globalLimiter = RateLimiter.create(600_0000 / 10.0);
    // 说明：单机目标吞吐600W/s是"下发能力"，
    // 写入侧的全局令牌桶按实际压测结果单独设定，此处仅作示例参照

    public boolean checkGlobalRate() {
        return globalLimiter.tryAcquire();
    }
}
```

## 十、最佳实践与总结

### 10.1 核心设计决策

| 决策点 | 选择 | 理由（关联学城文档描述） |
|--------|------|------------------------|
| 系统定位 | 推送系统而非聊天室 | "本质上是一种推送系统，当你发送一条消息时，它可以将消息推送给所有的人" |
| 架构分层 | 客户端/接入层/逻辑层/存储层四层分离 | 支持分布式部署、接入层与逻辑层独立水平扩容 |
| 传输协议 | 原生App用TCP长连接，H5/小程序用WebSocket | 兼顾实时性与开发便捷性 |
| 消息不追求100%必达 | 高低优先级丢弃策略 | "内置了丢弃策略，保证用户端体验" |
| 延迟目标 | 端到端控制在1秒以内 | "弹幕消息延时控制在1s以内" |
| 敏感词过滤 | DFA算法 | O(n)时间复杂度，满足高频短文本实时过滤需求 |
| 弹幕轨道 | 按轨道分配，安全间距控制 | 防止客户端弹幕重叠，提升可读性 |
| 历史回放 | 异步持久化 + 分窗口缓存 | "支持消息回看"，且不阻塞实时推送主链路 |
| 网络部署 | 多机房就近接入 + 中心机房处理 | 避免单机房掉线率高、不稳定的问题 |

### 10.2 容易踩的坑

1. **把弹幕系统当成普通聊天系统设计**：普通IM追求消息必达和强一致，弹幕系统追求的是海量扇出下的体验稳定，二者设计目标根本不同，照搬IM的可靠投递机制会导致系统在流量洪峰下直接被压垮。
2. **没有优先级丢弃机制，试图让所有弹幕都到达所有人**：这是最常见的架构错误。当直播间人数达到十万级别时，不做丢弃控制的系统一定会在某个流量峰值点雪崩。
3. **连接管理与业务逻辑耦合在一起**：如果Connect层直接处理敏感词过滤、频率限制等业务逻辑，会导致接入层无法独立扩容，业务逻辑变更也会影响连接稳定性。应严格遵循"接入层只管连接、逻辑层处理业务"的分层原则。
4. **敏感词匹配使用简单字符串查找**：词库达到几千甚至上万级别后，`String.contains`逐词匹配的性能会严重拖慢发送链路，必须使用DFA或AC自动机等O(n)复杂度算法。
5. **弹幕轨道完全依赖客户端，服务端不做任何粗粒度控制**：在恶意刷屏或异常流量场景下，客户端轨道算法可能被绕过（如自定义客户端），服务端仍需要有基础的频率限制和丢弃兜底能力。
6. **历史弹幕持久化写在发送主链路上**：应通过消息管道异步落库，避免数据库写入抖动影响实时推送延迟。
7. **忽视多机房网络部署**：单机房部署在用户分布广泛、跨运营商访问的场景下会出现明显的掉线率和延迟问题，需要采用"边缘接入 + 中心处理"的部署模式。
8. **WebSocket连接泄漏**：用户异常断开后，如果服务端没有及时清理Session，会导致推送任务持续堆积、内存缓慢泄漏，必须配合心跳保活机制做主动超时清理。

### 10.3 总结

弹幕系统的架构设计本质上是在解决一个"海量扇出场景下如何权衡实时性、可靠性与系统稳定性"的问题。它与传统IM系统的核心区别在于：IM追求消息的可靠必达，而弹幕系统更强调在海量并发场景下通过合理的优先级分级、丢弃策略、抽样广播等手段，用有限的系统资源换取整体用户体验的稳定与可控。理解这一设计哲学的差异，是构建高可用弹幕/直播互动系统的关键前提。

## 十一、全链路实战案例

> 前面章节从架构分层、核心链路、优先级丢弃、连接管理、敏感词过滤、轨道算法、历史回放、性能优化等维度分别拆解了弹幕系统的关键组件。本章将把这些组件串联起来，以三个完整的端到端实战案例，展示从用户操作到最终效果呈现的全链路处理过程，包含异常处理、日志记录、幂等控制等工程实践细节。

### 案例一：用户发送弹幕全链路

#### 11.1.1 链路概览

```
客户端发起WebSocket连接
  → 握手鉴权（Token校验）
  → 连接注册（ConnectionRegistry + Router）
  → 心跳保活建立
  → 用户发送弹幕（文本/颜色/位置/时间点）
  → 频率限制（用户级 + 直播间级 + 全局级）
  → 内容审核（DFA敏感词实时过滤）
  → 幂等检查（防重复提交）
  → 弹幕消息构建（ID生成 + 轨道预分配）
  → 写入消息管道（Kafka，按roomId分区）
  → 异步持久化（批量落库）
  → 消费者分发推送（优先级丢弃 + 抽样 + 批量合并）
  → WebSocket推送到同房间所有在线用户
```

#### 11.1.2 WebSocket连接建立与认证

```java
/**
 * 弹幕WebSocket连接处理器
 *
 * 完整的连接生命周期管理：
 * 1. 握手阶段鉴权（由DanmakuAuthInterceptor完成）
 * 2. 连接建立后注册到ConnectionRegistry和Router
 * 3. 进入直播间，加入房间连接集合
 * 4. 连接断开时清理资源，防止连接泄漏
 */
@Component
@Slf4j
public class DanmakuWebSocketHandler extends AbstractWebSocketHandler {

    @Autowired
    private ConnectionRegistry connectionRegistry;

    @Autowired
    private HeartbeatManager heartbeatManager;

    @Autowired
    private RoomOnlineCounter onlineCounter;

    @Override
    public void afterConnectionEstablished(WebSocketSession session) {
        Long userId = (Long) session.getAttributes().get("userId");
        Long roomId = parseRoomId(session.getUri());

        String connectionId = generateConnectionId(session);

        try {
            // 构建连接对象并注册
            Connection connection = new WebSocketConnection(
                connectionId, userId, roomId, session);
            connectionRegistry.register(connection);

            // 初始化心跳时间
            heartbeatManager.onHeartbeat(connectionId);

            // 在线人数计数+1
            onlineCounter.increment(roomId);

            log.info("弹幕连接建立成功, userId={}, roomId={}, connectionId={}, protocol={}",
                userId, roomId, connectionId, session.getUri());

            // 推送欢迎消息与当前在线人数
            String welcome = JSON.toJSONString(Map.of(
                "type", "system",
                "content", "欢迎来到直播间",
                "onlineCount", onlineCounter.getCount(roomId)
            ));
            connection.send(welcome);

        } catch (Exception e) {
            log.error("连接注册失败, userId={}, roomId={}, connectionId={}",
                userId, roomId, connectionId, e);
            closeQuietly(session);
        }
    }

    @Override
    protected void handleTextMessage(WebSocketSession session, TextMessage message) {
        Long userId = (Long) session.getAttributes().get("userId");
        String connectionId = (String) session.getAttributes().get("connectionId");

        try {
            JsonNode node = JSON.parseObject(message.getPayload(), JsonNode.class);
            String type = node.get("type").asText();

            if ("heartbeat".equals(type)) {
                heartbeatManager.onHeartbeat(connectionId);
                return;
            }

            if ("danmaku".equals(type)) {
                DanmakuRequest request = JSON.parseObject(
                    message.getPayload(), DanmakuRequest.class);
                handleDanmakuSend(request, userId, connectionId);
                return;
            }

            log.warn("未知消息类型, userId={}, type={}", userId, type);

        } catch (Exception e) {
            log.error("消息处理异常, userId={}, connectionId={}, payload={}",
                userId, connectionId, message.getPayload(), e);
        }
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus status) {
        Long userId = (Long) session.getAttributes().get("userId");
        Long roomId = parseRoomId(session.getUri());
        String connectionId = (String) session.getAttributes().get("connectionId");

        try {
            Connection connection = connectionRegistry.getConnection(connectionId);
            if (connection != null) {
                connectionRegistry.unregister(connection);
                onlineCounter.decrement(roomId);
            }
            heartbeatManager.remove(connectionId);
            log.info("弹幕连接关闭, userId={}, roomId={}, connectionId={}, status={}",
                userId, roomId, connectionId, status);
        } catch (Exception e) {
            log.error("连接清理异常, userId={}, connectionId={}", userId, connectionId, e);
        }
    }

    @Override
    public void handleTransportError(WebSocketSession session, Throwable exception) {
        Long userId = (Long) session.getAttributes().get("userId");
        log.error("WebSocket传输异常, userId={}", userId, exception);
        closeQuietly(session);
    }

    @Autowired
    private DanmakuSendFacade danmakuSendFacade;

    private void handleDanmakuSend(DanmakuRequest request, Long userId, String connectionId) {
        SendResult result = danmakuSendFacade.send(request, userId);
        if (!result.isSuccess()) {
            // 发送失败时通过WebSocket回传错误信息，让客户端感知
            String errorResp = JSON.toJSONString(Map.of(
                "type", "error",
                "message", result.getMessage()
            ));
            connectionRegistry.pushAsync(connectionId, errorResp);
        }
    }

    private Long parseRoomId(URI uri) {
        String query = uri.getQuery();
        for (String param : query.split("&")) {
            String[] kv = param.split("=");
            if ("roomId".equals(kv[0])) {
                return Long.parseLong(kv[1]);
            }
        }
        throw new IllegalArgumentException("缺少roomId参数");
    }

    private String generateConnectionId(WebSocketSession session) {
        String connectionId = UUID.randomUUID().toString().replace("-", "");
        session.getAttributes().put("connectionId", connectionId);
        return connectionId;
    }

    private void closeQuietly(WebSocketSession session) {
        try {
            if (session.isOpen()) {
                session.close(CloseStatus.SERVER_ERROR);
            }
        } catch (IOException ignored) {
        }
    }
}
```

#### 11.1.3 弹幕发送门面（含幂等控制、限流、审核、异步入库）

```java
/**
 * 弹幕发送门面服务
 *
 * 整合限流、审核、幂等、消息管道写入等完整链路
 * 对外提供统一入口，内部按顺序执行各环节
 */
@Service
@Slf4j
public class DanmakuSendFacade {

    @Autowired
    private DanmakuRateLimiter rateLimiter;

    @Autowired
    private SensitiveWordFilter sensitiveFilter;

    @Autowired
    private MessageChannelProducer messageProducer;

    @Autowired
    private DanmakuIdGenerator idGenerator;

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private RoomTrackManagerRegistry trackRegistry;

    /**
     * 发送弹幕（全链路）
     *
     * 链路顺序：
     * 1. 参数校验
     * 2. 幂等检查（客户端可能因网络重试导致重复提交）
     * 3. 三级限流（用户级 → 直播间级 → 全局级）
     * 4. 敏感词过滤
     * 5. 构建弹幕消息（分配ID、轨道）
     * 6. 写入消息管道（实时分发 + 异步入库）
     */
    public SendResult send(DanmakuRequest request, Long userId) {

        // ---------- 1. 参数校验 ----------
        if (request.getRoomId() == null || request.getRoomId() <= 0) {
            log.warn("参数校验失败: roomId为空, userId={}", userId);
            return SendResult.fail("直播间ID无效");
        }
        if (request.getContent() == null || request.getContent().trim().isEmpty()) {
            log.warn("参数校验失败: content为空, userId={}", userId);
            return SendResult.fail("弹幕内容不能为空");
        }
        if (request.getContent().length() > 256) {
            log.warn("参数校验失败: content超长, userId={}, length={}", userId, request.getContent().length());
            return SendResult.fail("弹幕内容超过256字符限制");
        }

        // ---------- 2. 幂等检查 ----------
        // 客户端为每条弹幕生成唯一clientMsgId，服务端用Redis SET NX做去重
        // 防止网络重试导致的重复发送
        String clientMsgId = request.getClientMsgId();
        if (clientMsgId != null && !clientMsgId.isEmpty()) {
            String idempotentKey = "danmaku:idempotent:" + userId + ":" + clientMsgId;
            Boolean isFirst = redisTemplate.opsForValue()
                .setIfAbsent(idempotentKey, "1", 10, TimeUnit.SECONDS);
            if (!Boolean.TRUE.equals(isFirst)) {
                log.info("幂等拦截: 重复提交, userId={}, clientMsgId={}", userId, clientMsgId);
                return SendResult.fail("请勿重复发送");
            }
        }

        // ---------- 3. 三级限流 ----------
        if (!rateLimiter.checkUserRate(userId)) {
            log.info("用户级限流: userId={}", userId);
            return SendResult.fail("发送太频繁，请稍后再试");
        }
        if (!rateLimiter.checkRoomRate(request.getRoomId())) {
            log.info("直播间级限流: roomId={}", request.getRoomId());
            return SendResult.fail("当前弹幕过多，请稍后再试");
        }
        if (!rateLimiter.checkGlobalRate()) {
            log.warn("全局级限流触发, userId={}, roomId={}", userId, request.getRoomId());
            return SendResult.fail("系统繁忙，请稍后再试");
        }

        // ---------- 4. 敏感词过滤 ----------
        // 先检测：如果包含高严重级别敏感词，直接拒绝
        if (sensitiveFilter.contains(request.getContent())) {
            log.info("敏感词拦截: userId={}, roomId={}, content={}",
                userId, request.getRoomId(), maskContent(request.getContent()));
            return SendResult.fail("弹幕包含敏感内容");
        }
        // 再过滤：低级别敏感词做打码处理
        String filteredContent = sensitiveFilter.filter(request.getContent());

        // ---------- 5. 构建弹幕消息 ----------
        DanmakuMessage msg = new DanmakuMessage();
        msg.setDanmakuId(idGenerator.nextId());
        msg.setRoomId(request.getRoomId());
        msg.setUserId(userId);
        msg.setContent(filteredContent);
        msg.setColor(request.getColor() != null ? request.getColor() : "#FFFFFF");
        msg.setFontSize(request.getFontSize() != null ? request.getFontSize() : 24);
        msg.setPriority(DanmakuPriority.NORMAL.getCode());
        msg.setTimestamp(System.currentTimeMillis());
        msg.setVideoTimestamp(request.getVideoTimestamp() != null ? request.getVideoTimestamp() : 0);

        // 服务端粗粒度轨道预分配（防刷屏场景的提前拦截）
        DanmakuTrackManager trackManager = trackRegistry.getOrCreate(request.getRoomId());
        int track = trackManager.allocateTrack(
            System.currentTimeMillis() / 1000.0,
            estimateWidth(filteredContent, msg.getFontSize()),
            1920, 150.0
        );
        msg.setTrack(track); // -1表示客户端自行分配

        // ---------- 6. 写入消息管道 ----------
        try {
            messageProducer.sendDanmaku(msg);
            log.info("弹幕发送成功: danmakuId={}, userId={}, roomId={}, content={}",
                msg.getDanmakuId(), userId, request.getRoomId(), maskContent(filteredContent));
            return SendResult.success(msg.getDanmakuId());
        } catch (Exception e) {
            log.error("消息管道写入失败: danmakuId={}, userId={}, roomId={}",
                msg.getDanmakuId(), userId, request.getRoomId(), e);
            // 写入失败时清除幂等标记，允许客户端重试
            if (clientMsgId != null) {
                redisTemplate.delete("danmaku:idempotent:" + userId + ":" + clientMsgId);
            }
            return SendResult.fail("发送失败，请重试");
        }
    }

    private String maskContent(String content) {
        if (content.length() <= 2) return "**";
        return content.substring(0, 1) + "***" + content.substring(content.length() - 1);
    }

    private int estimateWidth(String content, int fontSize) {
        return content.length() * fontSize;
    }
}
```

#### 11.1.4 高并发下的消息合并推送策略

```java
/**
 * 弹幕合并推送服务
 *
 * 在超高并发场景下（如百万直播间），逐条推送会导致：
 * 1. 大量小WebSocket帧，网络I/O开销巨大
 * 2. 客户端频繁触发渲染，导致卡顿
 *
 * 策略：将100ms时间窗口内同一直播间的弹幕合并为批量消息，
 * 一次性推送给每个连接。同时配合优先级丢弃策略，
 * 在合并前对低优先级消息做采样，控制单批次消息量。
 */
@Service
@Slf4j
public class DanmakuMergePushService {

    /** 每个直播间的弹幕缓冲区 */
    private final Map<Long, MergeBuffer> buffers = new ConcurrentHashMap<>();

    /** 单批次最大消息数，防止极端情况下单帧过大 */
    private static final int MAX_BATCH_SIZE = 50;

    /** 合并窗口（毫秒） */
    private static final long MERGE_WINDOW_MS = 100;

    @Autowired
    private ConnectionRegistry connectionRegistry;

    @Autowired
    private DanmakuPriorityDropStrategy dropStrategy;

    @Autowired
    private LargeRoomSamplingStrategy samplingStrategy;

    private final ScheduledExecutorService scheduler =
        Executors.newScheduledThreadPool(4, new ThreadFactoryBuilder()
            .setNameFormat("danmaku-merge-flush-%d").build());

    @PostConstruct
    public void init() {
        scheduler.scheduleAtFixedRate(this::flushAll, MERGE_WINDOW_MS, MERGE_WINDOW_MS,
            TimeUnit.MILLISECONDS);
    }

    /**
     * 接收一条弹幕，放入合并缓冲区
     */
    public void offer(DanmakuMessage msg) {
        MergeBuffer buffer = buffers.computeIfAbsent(msg.getRoomId(), k -> new MergeBuffer());
        buffer.add(msg);
    }

    /**
     * 定时刷新所有缓冲区，将积攒的弹幕合并推送
     */
    private void flushAll() {
        for (Map.Entry<Long, MergeBuffer> entry : buffers.entrySet()) {
            try {
                flushRoom(entry.getKey(), entry.getValue());
            } catch (Exception e) {
                log.error("合并推送异常, roomId={}", entry.getKey(), e);
            }
        }
    }

    private void flushRoom(Long roomId, MergeBuffer buffer) {
        List<DanmakuMessage> batch = buffer.drain();
        if (batch.isEmpty()) {
            return;
        }

        Set<String> connectionIds = connectionRegistry.getConnectionsByRoom(roomId);
        if (connectionIds.isEmpty()) {
            return;
        }

        int onlineCount = connectionIds.size();

        // 应用优先级丢弃：在合并前对低优先级消息做筛选
        List<DanmakuMessage> filtered = batch.stream()
            .filter(msg -> dropStrategy.shouldDeliver(msg, onlineCount))
            .collect(Collectors.toList());

        if (filtered.isEmpty()) {
            log.debug("合并推送: 全部被丢弃, roomId={}, originalSize={}", roomId, batch.size());
            return;
        }

        // 超大批次截断，防止单帧过大
        if (filtered.size() > MAX_BATCH_SIZE) {
            filtered = filtered.subList(0, MAX_BATCH_SIZE);
        }

        // 一次序列化，多连接复用
        String payload = JSON.toJSONString(Map.of(
            "type", "danmaku_batch",
            "data", filtered
        ));

        // 超大直播间抽样推送
        double sampleRate = samplingStrategy.calculateSampleRate(onlineCount);
        List<String> targets = samplingStrategy.sample(connectionIds, sampleRate);

        for (String connectionId : targets) {
            connectionRegistry.pushAsync(connectionId, payload);
        }

        log.debug("合并推送完成: roomId={}, batchSize={}, onlineCount={}, pushed={}, sampled={}",
            roomId, filtered.size(), onlineCount, targets.size(), sampleRate);
    }

    /**
     * 合并缓冲区
     *
     * 使用ConcurrentLinkedQueue保证线程安全，
     * drain()方法原子性地取出并清空缓冲区
     */
    private static class MergeBuffer {
        private final Queue<DanmakuMessage> queue = new ConcurrentLinkedQueue<>();

        void add(DanmakuMessage msg) {
            queue.offer(msg);
        }

        List<DanmakuMessage> drain() {
            List<DanmakuMessage> result = new ArrayList<>();
            DanmakuMessage msg;
            while ((msg = queue.poll()) != null) {
                result.add(msg);
            }
            return result;
        }
    }

    @PreDestroy
    public void shutdown() {
        // 服务关闭前做最后一次flush，尽量不丢消息
        flushAll();
        scheduler.shutdown();
        try {
            if (!scheduler.awaitTermination(5, TimeUnit.SECONDS)) {
                scheduler.shutdownNow();
            }
        } catch (InterruptedException e) {
            scheduler.shutdownNow();
            Thread.currentThread().interrupt();
        }
        log.info("弹幕合并推送服务已关闭");
    }
}
```

#### 11.1.5 异步入库消费者

```java
/**
 * 弹幕异步入库消费者
 *
 * 与实时推送链路完全解耦，独立消费组，
 * 攒批写入数据库，降低写入压力
 *
 * 异常处理策略：
 * - 单条解析失败：跳过该条，记录日志，不中断批次
 * - 批量写入失败：重试3次，仍失败则写入死信队列人工排查
 */
@Service
@Slf4j
public class DanmakuPersistConsumer {

    @Autowired
    private DanmakuHistoryMapper historyMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final int MAX_RETRY = 3;

    @KafkaListener(topics = "danmaku-topic", groupId = "danmaku-persist-group",
                   containerFactory = "batchKafkaListenerContainerFactory")
    public void persistBatch(List<ConsumerRecord<String, DanmakuMessage>> records,
                              Acknowledgment ack) {
        if (records.isEmpty()) {
            ack.acknowledge();
            return;
        }

        List<DanmakuHistory> entities = new ArrayList<>(records.size());
        List<String> failedKeys = new ArrayList<>();

        for (ConsumerRecord<String, DanmakuMessage> record : records) {
            try {
                DanmakuMessage msg = record.value();
                DanmakuHistory history = convert(msg);

                // 幂等检查：基于danmaku_id唯一键，避免重复入库
                String idempotentKey = "danmaku:persist:" + msg.getDanmakuId();
                Boolean exists = redisTemplate.hasKey(idempotentKey);
                if (Boolean.TRUE.equals(exists)) {
                    log.debug("弹幕已入库，跳过: danmakuId={}", msg.getDanmakuId());
                    continue;
                }

                entities.add(history);
            } catch (Exception e) {
                failedKeys.add(record.key());
                log.error("弹幕解析失败: key={}", record.key(), e);
            }
        }

        if (!entities.isEmpty()) {
            try {
                batchInsertWithRetry(entities);
                // 标记已入库，防止重复消费时重复写入
                for (DanmakuHistory h : entities) {
                    redisTemplate.opsForValue().set(
                        "danmaku:persist:" + h.getDanmakuId(), "1",
                        24, TimeUnit.HOURS);
                }
                log.info("弹幕批量入库成功: count={}", entities.size());
            } catch (Exception e) {
                log.error("弹幕批量入库失败，写入死信队列: count={}", entities.size(), e);
                sendToDeadLetter(entities);
            }
        }

        if (!failedKeys.isEmpty()) {
            log.warn("本批次部分消息解析失败: failedKeys={}", failedKeys);
        }

        ack.acknowledge();
    }

    private void batchInsertWithRetry(List<DanmakuHistory> entities) {
        int retry = 0;
        while (retry < MAX_RETRY) {
            try {
                historyMapper.batchInsert(entities);
                return;
            } catch (Exception e) {
                retry++;
                if (retry >= MAX_RETRY) {
                    throw e;
                }
                log.warn("批量入库重试 {}/{}", retry, MAX_RETRY);
                try {
                    Thread.sleep(100L * retry);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw new RuntimeException("入库重试被中断", ie);
                }
            }
        }
    }

    private void sendToDeadLetter(List<DanmakuHistory> entities) {
        // 写入死信Topic或数据库异常表，供人工排查
        try {
            for (DanmakuHistory h : entities) {
                log.error("DEAD_LETTER: danmakuId={}, roomId={}, content={}",
                    h.getDanmakuId(), h.getRoomId(), h.getContent());
            }
        } catch (Exception e) {
            log.error("死信写入也失败了", e);
        }
    }

    private DanmakuHistory convert(DanmakuMessage msg) {
        DanmakuHistory h = new DanmakuHistory();
        h.setDanmakuId(msg.getDanmakuId());
        h.setRoomId(msg.getRoomId());
        h.setUserId(msg.getUserId());
        h.setContent(msg.getContent());
        h.setColor(msg.getColor());
        h.setFontSize(msg.getFontSize());
        h.setVideoTimestamp(msg.getVideoTimestamp() != null ? msg.getVideoTimestamp() : 0);
        h.setCreateTime(new Date(msg.getTimestamp()));
        return h;
    }
}
```

### 案例二：历史弹幕加载全链路

#### 11.2.1 链路概览

```
用户打开视频/直播
  → 客户端请求初始弹幕段
  → 多级缓存查询（本地缓存 → Redis → 数据库）
  → 缓存未命中时回源数据库
  → 弹幕密度控制（采样策略）
  → 分页返回客户端
  → 客户端按视频进度预加载下一段弹幕
```

#### 11.2.2 多级缓存查询服务

```java
/**
 * 历史弹幕多级缓存查询服务
 *
 * 缓存层级：
 * 1. L1 本地缓存（Caffeine）：热点视频的弹幕段，进程内命中，延迟极低
 * 2. L2 Redis缓存：跨实例共享，热门视频弹幕段缓存
 * 3. L3 数据库：兜底数据源
 *
 * 缓存策略：
 * - 热门视频弹幕段全量缓存在Redis（命中率>95%）
 * - L1只缓存极热视频（如首页推荐视频），容量受限
 * - 缓存按"视频ID + 时间窗口"为键，窗口大小60秒
 * - 防缓存穿透：对不存在的弹幕段缓存空值（短TTL）
 * - 防缓存击穿：使用分布式锁保证同一时间只有一个请求回源
 */
@Service
@Slf4j
public class DanmakuMultiLevelCacheService {

    @Autowired
    private DanmakuHistoryMapper historyMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    /** L1 本地缓存：Caffeine */
    private final Cache<String, List<DanmakuVO>> localCache = Caffeine.newBuilder()
        .maximumSize(10_000)
        .expireAfterWrite(30, TimeUnit.SECONDS)
        .recordStats()
        .build();

    /** 缓存窗口大小（秒） */
    private static final int CACHE_WINDOW_SECONDS = 60;

    /** 空值标记，防止缓存穿透 */
    private static final String EMPTY_MARKER = "[]";

    /** 分布式锁前缀 */
    private static final String LOCK_PREFIX = "danmaku:lock:";

    /**
     * 查询指定视频在 [startSeconds, endSeconds) 时间段内的历史弹幕
     *
     * @param roomId       视频/直播间ID
     * @param startSeconds 起始时间（秒）
     * @param endSeconds   结束时间（秒）
     * @return 弹幕列表（已按时间排序）
     */
    public List<DanmakuVO> query(Long roomId, int startSeconds, int endSeconds) {
        List<DanmakuVO> result = new ArrayList<>();

        // 按60秒窗口逐段查询，每段独立走多级缓存
        for (int start = startSeconds; start < endSeconds; start += CACHE_WINDOW_SECONDS) {
            int end = Math.min(start + CACHE_WINDOW_SECONDS, endSeconds);
            result.addAll(querySingleWindow(roomId, start, end));
        }

        // 弹幕密度控制：如果某段弹幕过多，做采样降密
        result = applyDensityControl(result, startSeconds, endSeconds);

        return result;
    }

    /**
     * 查询单个缓存窗口内的弹幕
     */
    private List<DanmakuVO> querySingleWindow(Long roomId, int startSeconds, int endSeconds) {
        String cacheKey = buildCacheKey(roomId, startSeconds);

        // ---------- L1 本地缓存 ----------
        List<DanmakuVO> l1Result = localCache.getIfPresent(cacheKey);
        if (l1Result != null) {
            log.debug("L1命中: key={}", cacheKey);
            return l1Result;
        }

        // ---------- L2 Redis缓存 ----------
        String l2Raw = redisTemplate.opsForValue().get(cacheKey);
        if (l2Raw != null) {
            if (EMPTY_MARKER.equals(l2Raw)) {
                log.debug("L2命中空值: key={}", cacheKey);
                return Collections.emptyList();
            }
            List<DanmakuVO> l2Result = JSON.parseArray(l2Raw, DanmakuVO.class);
            // 回填L1
            localCache.put(cacheKey, l2Result);
            log.debug("L2命中: key={}, size={}", cacheKey, l2Result.size());
            return l2Result;
        }

        // ---------- L3 数据库回源 ----------
        // 使用分布式锁防止缓存击穿：同一时间只有一个请求回源
        String lockKey = LOCK_PREFIX + cacheKey;
        String lockValue = UUID.randomUUID().toString();
        try {
            Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, lockValue, 3, TimeUnit.SECONDS);
            if (!Boolean.TRUE.equals(locked)) {
                // 未获取锁，短暂等待后重试缓存
                Thread.sleep(50);
                String retryRaw = redisTemplate.opsForValue().get(cacheKey);
                if (retryRaw != null && !EMPTY_MARKER.equals(retryRaw)) {
                    return JSON.parseArray(retryRaw, DanmakuVO.class);
                }
                // 等待后仍未命中，直接查库（降级策略，保证可用性）
                return queryFromDbAndCache(roomId, startSeconds, endSeconds, cacheKey);
            }

            return queryFromDbAndCache(roomId, startSeconds, endSeconds, cacheKey);

        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            log.warn("查询被中断, roomId={}, start={}", roomId, startSeconds);
            return Collections.emptyList();
        } finally {
            // 释放分布式锁（Lua脚本保证原子性）
            releaseLock(lockKey, lockValue);
        }
    }

    /**
     * 从数据库查询并回填缓存
     */
    private List<DanmakuVO> queryFromDbAndCache(Long roomId, int start, int end, String cacheKey) {
        List<DanmakuHistory> dbResult;
        try {
            dbResult = historyMapper.selectByTimeRange(roomId, start, end);
        } catch (Exception e) {
            log.error("数据库查询异常: roomId={}, start={}, end={}", roomId, start, end, e);
            return Collections.emptyList();
        }

        List<DanmakuVO> voList = dbResult.stream()
            .map(this::toVO)
            .collect(Collectors.toList());

        // 回填缓存：空结果也缓存（短TTL防穿透）
        String cacheValue = voList.isEmpty() ? EMPTY_MARKER : JSON.toJSONString(voList);
        int ttl = voList.isEmpty() ? 30 : 600; // 空值30秒，有值10分钟
        redisTemplate.opsForValue().set(cacheKey, cacheValue, ttl, TimeUnit.SECONDS);

        // 回填L1
        if (!voList.isEmpty()) {
            localCache.put(cacheKey, voList);
        }

        log.debug("DB回源完成: key={}, size={}", cacheKey, voList.size());
        return voList;
    }

    /**
     * 弹幕密度控制
     *
     * 当某时间段弹幕过多时（如直播高潮片段），
     * 客户端渲染压力和带宽消耗会过大，需要做采样降密
     *
     * 策略：
     * - 每秒弹幕数 <= MAX_PER_SECOND：全量返回
     * - 每秒弹幕数 > MAX_PER_SECOND：按等间隔采样，保留MAX_PER_SECOND条
     */
    private static final int MAX_PER_SECOND = 30;

    private List<DanmakuVO> applyDensityControl(List<DanmakuVO> danmakus,
                                                  int startSeconds, int endSeconds) {
        if (danmakus.isEmpty()) {
            return danmakus;
        }

        int duration = endSeconds - startSeconds;
        int threshold = duration * MAX_PER_SECOND;

        if (danmakus.size() <= threshold) {
            return danmakus; // 密度在合理范围内，全量返回
        }

        // 等间隔采样：保留threshold条，保证时间分布均匀
        List<DanmakuVO> sampled = new ArrayList<>(threshold);
        double step = (double) danmakus.size() / threshold;
        for (int i = 0; i < threshold; i++) {
            int index = (int) (i * step);
            sampled.add(danmakus.get(index));
        }

        log.info("弹幕密度控制: 原始={}, 采样后={}, roomId={}",
            danmakus.size(), sampled.size(), danmakus.get(0).getRoomId());
        return sampled;
    }

    private String buildCacheKey(Long roomId, int startSeconds) {
        int window = startSeconds / CACHE_WINDOW_SECONDS;
        return "danmaku:replay:" + roomId + ":" + window;
    }

    private DanmakuVO toVO(DanmakuHistory h) {
        DanmakuVO vo = new DanmakuVO();
        vo.setDanmakuId(h.getDanmakuId());
        vo.setRoomId(h.getRoomId());
        vo.setContent(h.getContent());
        vo.setColor(h.getColor());
        vo.setFontSize(h.getFontSize());
        vo.setVideoTimestamp(h.getVideoTimestamp());
        return vo;
    }
}
```

#### 11.2.3 分页加载与预加载服务

```java
/**
 * 弹幕分页加载与预加载服务
 *
 * 设计思路：
 * - 点播场景：按视频时间轴分段加载，每段60秒，支持向前/向后翻页
 * - 直播场景：加载最近N条弹幕，滚动加载
 * - 客户端在播放到当前段末尾前10秒，自动预加载下一段
 *
 * 分页设计：
 * - 不使用传统offset分页（大数据量下性能差）
 * - 使用游标分页：以videoTimestamp为游标，每次查询 > lastCursor 的数据
 */
@Service
@Slf4j
public class DanmakuPaginationService {

    @Autowired
    private DanmakuMultiLevelCacheService cacheService;

    @Autowired
    private DanmakuHistoryMapper historyMapper;

    /** 每页大小 */
    private static final int PAGE_SIZE = 200;

    /** 直播场景加载最近弹幕条数 */
    private static final int LIVE_RECENT_COUNT = 500;

    /**
     * 点播场景：分页加载历史弹幕
     *
     * @param roomId     视频ID
     * @param cursor     上一次返回的最后一条弹幕的videoTimestamp（首次为0）
     * @param direction  加载方向：FORWARD（向后翻页）、BACKWARD（向前翻页）
     * @return 分页结果
     */
    public DanmakuPageResult loadByPage(Long roomId, int cursor, LoadDirection direction) {
        try {
            int startSeconds, endSeconds;

            if (direction == LoadDirection.FORWARD) {
                startSeconds = cursor;
                endSeconds = cursor + CACHE_WINDOW_SECONDS;
            } else {
                startSeconds = Math.max(0, cursor - CACHE_WINDOW_SECONDS);
                endSeconds = cursor;
            }

            List<DanmakuVO> danmakus = cacheService.query(roomId, startSeconds, endSeconds);

            // 游标分页：如果结果超过PAGE_SIZE，截断并返回下一页游标
            boolean hasMore = danmakus.size() > PAGE_SIZE;
            if (hasMore) {
                danmakus = danmakus.subList(0, PAGE_SIZE);
            }

            int nextCursor = danmakus.isEmpty() ? endSeconds
                : danmakus.get(danmakus.size() - 1).getVideoTimestamp() + 1;

            log.info("弹幕分页加载: roomId={}, cursor={}, direction={}, size={}, hasMore={}",
                roomId, cursor, direction, danmakus.size(), hasMore);

            return DanmakuPageResult.builder()
                .danmakus(danmakus)
                .nextCursor(nextCursor)
                .hasMore(hasMore)
                .build();

        } catch (Exception e) {
            log.error("弹幕分页加载异常: roomId={}, cursor={}", roomId, cursor, e);
            return DanmakuPageResult.builder()
                .danmakus(Collections.emptyList())
                .nextCursor(cursor)
                .hasMore(false)
                .build();
        }
    }

    /**
     * 直播场景：加载最近N条弹幕
     *
     * 直播没有"时间轴"概念，取最近产生的弹幕即可
     */
    public List<DanmakuVO> loadRecentForLive(Long roomId) {
        try {
            List<DanmakuHistory> recent = historyMapper.selectRecent(roomId, LIVE_RECENT_COUNT);
            List<DanmakuVO> result = recent.stream()
                .map(this::toVO)
                .collect(Collectors.toList());

            log.info("直播弹幕加载: roomId={}, count={}", roomId, result.size());
            return result;
        } catch (Exception e) {
            log.error("直播弹幕加载异常: roomId={}", roomId, e);
            return Collections.emptyList();
        }
    }

    /**
     * 预加载下一段弹幕
     *
     * 客户端在播放到当前段末尾前10秒时调用，
     * 服务端提前将下一段弹幕加载到缓存，避免播放到时出现卡顿
     */
    @Async("danmakuPreloadExecutor")
    public CompletableFuture<Void> preloadNextSegment(Long roomId, int currentEndSeconds) {
        try {
            int nextStart = currentEndSeconds;
            int nextEnd = currentEndSeconds + CACHE_WINDOW_SECONDS;
            cacheService.query(roomId, nextStart, nextEnd);
            log.debug("弹幕预加载完成: roomId={}, segment=[{}-{}]", roomId, nextStart, nextEnd);
        } catch (Exception e) {
            log.warn("弹幕预加载失败: roomId={}, segment={}", roomId, currentEndSeconds, e);
        }
        return CompletableFuture.completedFuture(null);
    }

    private DanmakuVO toVO(DanmakuHistory h) {
        DanmakuVO vo = new DanmakuVO();
        vo.setDanmakuId(h.getDanmakuId());
        vo.setRoomId(h.getRoomId());
        vo.setContent(h.getContent());
        vo.setColor(h.getColor());
        vo.setFontSize(h.getFontSize());
        vo.setVideoTimestamp(h.getVideoTimestamp());
        return vo;
    }

    private static final int CACHE_WINDOW_SECONDS = 60;

    public enum LoadDirection {
        FORWARD, BACKWARD
    }
}
```

#### 11.3.1 链路概览

#### 11.3.2 用户屏蔽规则管理

```java
/**
 * 弹幕屏蔽规则服务
 *
 * 支持两种屏蔽维度：
 * 1. 关键词屏蔽：包含指定关键词的弹幕不展示给该用户
 * 2. 用户屏蔽：指定用户发送的弹幕不展示给该用户
 *
 * 规则存储：
 * - 持久化：MySQL（用户维度的屏蔽规则表）
 * - 缓存：Redis（用户维度的屏蔽规则集合，实时读取）
 *
 * 实时生效：
 * - 用户修改屏蔽规则后，立即更新Redis缓存
 * - 通过WebSocket推送规则变更通知，客户端同步更新本地过滤规则
 * - 推送链路在服务端做服务端侧过滤（减少无效推送），
 *   同时客户端也做本地过滤（兜底，防止规则同步延迟）
 */
@Service
@Slf4j
public class DanmakuBlockRuleService {

    @Autowired
    private DanmakuBlockRuleMapper blockRuleMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private ConnectionRegistry connectionRegistry;

    /** Redis Key前缀 */
    private static final String KEYWORD_KEY_PREFIX = "danmaku:block:keywords:";
    private static final String USER_KEY_PREFIX = "danmaku:block:users:";

    /**
     * 添加关键词屏蔽规则
     */
    public void addKeywordBlock(Long userId, String keyword) {
        if (keyword == null || keyword.trim().isEmpty()) {
            return;
        }
        keyword = keyword.trim();

        try {
            // 1. 持久化到数据库
            DanmakuBlockRule rule = new DanmakuBlockRule();
            rule.setUserId(userId);
            rule.setBlockType("KEYWORD");
            rule.setBlockValue(keyword);
            rule.setCreateTime(new Date());
            blockRuleMapper.insert(rule);

            // 2. 更新Redis缓存（Set结构，去重）
            String key = KEYWORD_KEY_PREFIX + userId;
            redisTemplate.opsForSet().add(key, keyword);

            // 3. 通知客户端规则变更
            notifyRuleChange(userId, "keyword_add", keyword);

            log.info("添加关键词屏蔽: userId={}, keyword={}", userId, keyword);
        } catch (Exception e) {
            log.error("添加关键词屏蔽失败: userId={}, keyword={}", userId, keyword, e);
            throw new RuntimeException("添加屏蔽规则失败", e);
        }
    }

    /**
     * 添加用户屏蔽规则
     */
    public void addUserBlock(Long userId, Long blockedUserId) {
        try {
            DanmakuBlockRule rule = new DanmakuBlockRule();
            rule.setUserId(userId);
            rule.setBlockType("USER");
            rule.setBlockValue(String.valueOf(blockedUserId));
            rule.setCreateTime(new Date());
            blockRuleMapper.insert(rule);

            String key = USER_KEY_PREFIX + userId;
            redisTemplate.opsForSet().add(key, String.valueOf(blockedUserId));

            notifyRuleChange(userId, "user_block", String.valueOf(blockedUserId));

            log.info("添加用户屏蔽: userId={}, blockedUserId={}", userId, blockedUserId);
        } catch (Exception e) {
            log.error("添加用户屏蔽失败: userId={}, blockedUserId={}", userId, blockedUserId, e);
            throw new RuntimeException("添加屏蔽规则失败", e);
        }
    }

    /**
     * 移除屏蔽规则
     */
    public void removeBlock(Long userId, String blockType, String blockValue) {
        try {
            blockRuleMapper.delete(userId, blockType, blockValue);

            if ("KEYWORD".equals(blockType)) {
                redisTemplate.opsForSet().remove(KEYWORD_KEY_PREFIX + userId, blockValue);
            } else if ("USER".equals(blockType)) {
                redisTemplate.opsForSet().remove(USER_KEY_PREFIX + userId, blockValue);
            }

            notifyRuleChange(userId, "block_remove", blockValue);

            log.info("移除屏蔽规则: userId={}, type={}, value={}", userId, blockType, blockValue);
        } catch (Exception e) {
            log.error("移除屏蔽规则失败: userId={}, type={}, value={}",
                userId, blockType, blockValue, e);
            throw new RuntimeException("移除屏蔽规则失败", e);
        }
    }

    /**
     * 判断弹幕是否被该用户的屏蔽规则命中
     *
     * 在推送链路中调用：服务端在推送前对每个用户做个性化过滤
     * 命中的弹幕不推送给该用户
     */
    public boolean isBlocked(Long userId, DanmakuMessage msg) {
        // 检查用户屏蔽
        String userKey = USER_KEY_PREFIX + userId;
        Boolean isUserBlocked = redisTemplate.opsForSet()
            .isMember(userKey, String.valueOf(msg.getUserId()));
        if (Boolean.TRUE.equals(isUserBlocked)) {
            return true;
        }

        // 检查关键词屏蔽
        String keywordKey = KEYWORD_KEY_PREFIX + userId;
        Set<String> keywords = redisTemplate.opsForSet().members(keywordKey);
        if (keywords != null) {
            for (String keyword : keywords) {
                if (msg.getContent().contains(keyword)) {
                    return true;
                }
            }
        }

        return false;
    }

    /**
     * 批量加载用户屏蔽规则到Redis缓存
     *
     * 用户首次连接时调用，确保屏蔽规则在Redis中可用
     */
    public void loadUserBlockRules(Long userId) {
        try {
            List<DanmakuBlockRule> rules = blockRuleMapper.selectByUserId(userId);
            String keywordKey = KEYWORD_KEY_PREFIX + userId;
            String userKey = USER_KEY_PREFIX + userId;

            // 清除旧缓存
            redisTemplate.delete(keywordKey);
            redisTemplate.delete(userKey);

            for (DanmakuBlockRule rule : rules) {
                if ("KEYWORD".equals(rule.getBlockType())) {
                    redisTemplate.opsForSet().add(keywordKey, rule.getBlockValue());
                } else if ("USER".equals(rule.getBlockType())) {
                    redisTemplate.opsForSet().add(userKey, rule.getBlockValue());
                }
            }

            log.info("用户屏蔽规则加载完成: userId={}, keywordCount={}, userBlockCount={}",
                userId,
                redisTemplate.opsForSet().size(keywordKey),
                redisTemplate.opsForSet().size(userKey));
        } catch (Exception e) {
            log.error("加载用户屏蔽规则失败: userId={}", userId, e);
        }
    }

    /**
     * 通过WebSocket通知客户端屏蔽规则变更
     */
    private void notifyRuleChange(Long userId, String action, String value) {
        String payload = JSON.toJSONString(Map.of(
            "type", "block_rule_change",
            "action", action,
            "value", value
        ));
        // 推送给该用户的所有连接（可能多端在线）
        Set<String> connectionIds = connectionRegistry.getConnectionsByUser(userId);
        for (String connId : connectionIds) {
            connectionRegistry.pushAsync(connId, payload);
        }
    }
}
```

#### 11.3.3 带屏蔽过滤的个性化推送

```java
/**
 * 个性化弹幕分发消费者
 *
 * 在标准分发链路基础上，增加用户级屏蔽过滤：
 * - 对每条弹幕，在推送给具体连接前检查该用户的屏蔽规则
 * - 命中屏蔽规则的弹幕跳过该用户，不推送
 *
 * 性能考量：
 * - 屏蔽规则缓存在Redis，读取延迟低（~1ms）
 * - 对超大直播间（10W+在线），逐用户检查开销较大，
 *   可降级为仅在客户端做过滤，服务端跳过检查
 */
@Component
@Slf4j
public class PersonalizedDanmakuDispatcher {

    @Autowired
    private ConnectionRegistry connectionRegistry;

    @Autowired
    private DanmakuBlockRuleService blockRuleService;

    @Autowired
    private DanmakuPriorityDropStrategy dropStrategy;

    /** 超过此在线人数时，跳过服务端屏蔽检查，降级为纯客户端过滤 */
    private static final int SERVER_SIDE_FILTER_THRESHOLD = 10_000;

    @KafkaListener(topics = "danmaku-topic", groupId = "danmaku-personalized-group",
                   concurrency = "16")
    public void dispatch(DanmakuMessage msg) {
        Set<String> connectionIds = connectionRegistry.getConnectionsByRoom(msg.getRoomId());
        if (connectionIds.isEmpty()) {
            return;
        }

        if (!dropStrategy.shouldDeliver(msg, connectionIds.size())) {
            return;
        }

        String payload = JSON.toJSONString(msg);
        int onlineCount = connectionIds.size();
        boolean serverSideFilter = onlineCount <= SERVER_SIDE_FILTER_THRESHOLD;

        for (String connectionId : connectionIds) {
            try {
                Connection conn = connectionRegistry.getConnection(connectionId);
                if (conn == null || !conn.isOpen()) {
                    continue;
                }

                // 服务端屏蔽过滤（小直播间才做）
                if (serverSideFilter && blockRuleService.isBlocked(conn.getUserId(), msg)) {
                    continue;
                }

                connectionRegistry.pushAsync(connectionId, payload);
            } catch (Exception e) {
                log.error("个性化推送异常: connectionId={}, danmakuId={}",
                    connectionId, msg.getDanmakuId(), e);
            }
        }
    }
}
```

#### 11.3.4 管理员删除违规弹幕

```java
/**
 * 弹幕管理服务
 *
 * 管理员操作：
 * - 删除单条违规弹幕（软删除，保留记录用于审计）
 * - 批量删除违规弹幕
 * - 删除后清除缓存并广播通知
 *
 * 幂等控制：
 * - 删除操作基于danmakuId，重复删除不会产生副作用
 * - 使用乐观锁（status字段）避免并发操作冲突
 */
@Service
@Slf4j
public class DanmakuManageService {

    @Autowired
    private DanmakuHistoryMapper historyMapper;

    @Autowired
    private StringRedisTemplate redisTemplate;

    @Autowired
    private ConnectionRegistry connectionRegistry;

    @Autowired
    private DanmakuBlockRuleService blockRuleService;

    /**
     * 删除单条弹幕（管理员操作）
     *
     * @param danmakuId  弹幕ID
     * @param operatorId 操作人ID
     * @param reason     删除原因
     */
    @Transactional
    public boolean deleteDanmaku(Long danmakuId, Long operatorId, String reason) {
        try {
            // 1. 查询弹幕信息
            DanmakuHistory history = historyMapper.selectByDanmakuId(danmakuId);
            if (history == null) {
                log.warn("弹幕不存在: danmakuId={}, operatorId={}", danmakuId, operatorId);
                return false;
            }

            // 幂等检查：已删除的弹幕不重复操作
            if (history.getStatus() == DanmakuStatus.DELETED.getCode()) {
                log.info("弹幕已删除，跳过: danmakuId={}", danmakuId);
                return true;
            }

            // 2. 软删除：更新状态为已删除
            int affected = historyMapper.updateStatus(
                danmakuId, DanmakuStatus.DELETED.getCode(), operatorId, reason);
            if (affected == 0) {
                log.warn("弹幕删除失败（乐观锁冲突）: danmakuId={}", danmakuId);
                return false;
            }

            // 3. 清除该弹幕所在时间窗口的缓存
            clearCacheForSegment(history.getRoomId(), history.getVideoTimestamp());

            // 4. 广播删除通知到直播间所有在线用户
            broadcastDeletion(history.getRoomId(), danmakuId);

            log.info("弹幕删除成功: danmakuId={}, roomId={}, operatorId={}, reason={}",
                danmakuId, history.getRoomId(), operatorId, reason);

            // 5. 可选：自动将违规内容加入敏感词库
            if (reason != null && reason.contains("sensitive")) {
                log.info("违规弹幕内容将提交至敏感词审核: danmakuId={}", danmakuId);
                // sensitiveFilter.addWordAtRuntime(history.getContent()); // 需审核后执行
            }

            return true;

        } catch (Exception e) {
            log.error("弹幕删除异常: danmakuId={}, operatorId={}", danmakuId, operatorId, e);
            throw new RuntimeException("弹幕删除失败", e);
        }
    }

    /**
     * 批量删除弹幕
     */
    @Transactional
    public int batchDelete(List<Long> danmakuIds, Long operatorId, String reason) {
        int successCount = 0;
        for (Long danmakuId : danmakuIds) {
            try {
                if (deleteDanmaku(danmakuId, operatorId, reason)) {
                    successCount++;
                }
            } catch (Exception e) {
                log.error("批量删除中单条失败: danmakuId={}", danmakuId, e);
                // 继续处理下一条，不中断批量操作
            }
        }
        log.info("批量删除弹幕完成: total={}, success={}, operatorId={}",
            danmakuIds.size(), successCount, operatorId);
        return successCount;
    }

    /**
     * 清除弹幕所在时间窗口的缓存
     */
    private void clearCacheForSegment(Long roomId, int videoTimestamp) {
        int window = videoTimestamp / 60;
        String cacheKey = "danmaku:replay:" + roomId + ":" + window;
        redisTemplate.delete(cacheKey);
        log.debug("清除弹幕缓存: key={}", cacheKey);
    }

    /**
     * 广播弹幕删除通知
     *
     * 客户端收到通知后，从本地弹幕列表中移除该条弹幕
     */
    private void broadcastDeletion(Long roomId, Long danmakuId) {
        String payload = JSON.toJSONString(Map.of(
            "type", "danmaku_delete",
            "danmakuId", danmakuId
        ));
        Set<String> connectionIds = connectionRegistry.getConnectionsByRoom(roomId);
        for (String connId : connectionIds) {
            connectionRegistry.pushAsync(connId, payload);
        }
        log.debug("广播删除通知: roomId={}, danmakuId={}, connectionCount={}",
            roomId, danmakuId, connectionIds.size());
    }
}
```

#### 11.3.5 弹幕举报处理

```java
/**
 * 弹幕举报服务
 *
 * 举报流程：
 * 1. 用户举报弹幕 → 举报记录入库
 * 2. 自动初审：敏感词库匹配 + 举报次数阈值
 *    - 命中高危敏感词或举报次数超阈值 → 自动隐藏弹幕
 *    - 其他情况 → 进入人工审核队列
 * 3. 人工审核：审核员判定违规 → 删除弹幕 + 封禁用户
 * 4. 审核结果通知举报人
 *
 * 幂等控制：
 * - 同一用户对同一弹幕的举报做去重（唯一索引）
 * - 防止恶意刷举报
 */
@Service
@Slf4j
public class DanmakuReportService {

    @Autowired
    private DanmakuReportMapper reportMapper;

    @Autowired
    private DanmakuHistoryMapper historyMapper;

    @Autowired
    private DanmakuManageService manageService;

    @Autowired
    private SensitiveWordFilter sensitiveFilter;

    @Autowired
    private StringRedisTemplate redisTemplate;

    /** 自动隐藏的举报次数阈值 */
    private static final int AUTO_HIDE_THRESHOLD = 5;

    /**
     * 用户举报弹幕
     *
     * @param danmakuId  被举报的弹幕ID
     * @param reporterId 举报人ID
     * @param reason     举报原因
     */
    public void report(Long danmakuId, Long reporterId, String reason) {
        try {
            // 1. 查询弹幕是否存在
            DanmakuHistory history = historyMapper.selectByDanmakuId(danmakuId);
            if (history == null) {
                log.warn("举报的弹幕不存在: danmakuId={}, reporterId={}", danmakuId, reporterId);
                throw new IllegalArgumentException("弹幕不存在");
            }

            // 2. 幂等检查：同一用户对同一弹幕只能举报一次
            String idempotentKey = "danmaku:report:" + reporterId + ":" + danmakuId;
            Boolean isFirst = redisTemplate.opsForValue()
                .setIfAbsent(idempotentKey, "1", 7, TimeUnit.DAYS);
            if (!Boolean.TRUE.equals(isFirst)) {
                log.info("重复举报拦截: reporterId={}, danmakuId={}", reporterId, danmakuId);
                throw new IllegalStateException("您已举报过该弹幕");
            }

            // 3. 举报记录入库
            DanmakuReport report = new DanmakuReport();
            report.setDanmakuId(danmakuId);
            report.setRoomId(history.getRoomId());
            report.setReporterId(reporterId);
            report.setReason(reason);
            report.setStatus(ReportStatus.PENDING.getCode());
            report.setCreateTime(new Date());
            reportMapper.insert(report);

            log.info("弹幕举报记录: danmakuId={}, reporterId={}, reason={}",
                danmakuId, reporterId, reason);

            // 4. 自动初审
            autoReview(history, danmakuId);

        } catch (IllegalArgumentException | IllegalStateException e) {
            throw e; // 业务异常直接抛出
        } catch (Exception e) {
            log.error("弹幕举报异常: danmakuId={}, reporterId={}", danmakuId, reporterId, e);
            throw new RuntimeException("举报处理失败", e);
        }
    }

    /**
     * 自动初审
     *
     * 规则：
     * - 弹幕内容命中敏感词 → 立即自动删除
     * - 被举报次数达到阈值 → 自动隐藏（待人工确认）
     */
    private void autoReview(DanmakuHistory history, Long danmakuId) {
        // 规则1：敏感词检测
        if (sensitiveFilter.contains(history.getContent())) {
            log.info("自动审核-敏感词命中，自动删除: danmakuId={}", danmakuId);
            manageService.deleteDanmaku(danmakuId, 0L, "auto_sensitive");
            reportMapper.batchUpdateStatus(danmakuId, ReportStatus.AUTO_RESOLVED.getCode());
            return;
        }

        // 规则2：举报次数阈值检测
        int reportCount = reportMapper.countByDanmakuId(danmakuId);
        if (reportCount >= AUTO_HIDE_THRESHOLD) {
            log.info("自动审核-举报次数超阈值，自动隐藏: danmakuId={}, count={}",
                danmakuId, reportCount);
            manageService.deleteDanmaku(danmakuId, 0L, "auto_report_threshold");
            reportMapper.batchUpdateStatus(danmakuId, ReportStatus.AUTO_RESOLVED.getCode());
            return;
        }

        // 其他情况：等待人工审核
        log.debug("弹幕举报进入人工审核队列: danmakuId={}, reportCount={}",
            danmakuId, reportCount);
    }

    /**
     * 人工审核处理
     *
     * @param reportId   举报记录ID
     * @param reviewerId 审核员ID
     * @param decision   审核决定：CONFIRM_VIOLATION / REJECT
     * @param remark     审核备注
     */
    @Transactional
    public void manualReview(Long reportId, Long reviewerId,
                              ReviewDecision decision, String remark) {
        try {
            DanmakuReport report = reportMapper.selectById(reportId);
            if (report == null) {
                log.warn("举报记录不存在: reportId={}", reportId);
                throw new IllegalArgumentException("举报记录不存在");
            }

            if (report.getStatus() != ReportStatus.PENDING.getCode()) {
                log.info("举报已处理，跳过: reportId={}, currentStatus={}",
                    reportId, report.getStatus());
                return;
            }

            // 更新举报状态
            reportMapper.updateStatus(reportId,
                decision == ReviewDecision.CONFIRM_VIOLATION
                    ? ReportStatus.CONFIRMED.getCode()
                    : ReportStatus.REJECTED.getCode(),
                reviewerId, remark, new Date());

            if (decision == ReviewDecision.CONFIRM_VIOLATION) {
                // 确认违规：删除弹幕
                manageService.deleteDanmaku(report.getDanmakuId(), reviewerId,
                    "manual_confirm: " + remark);
                log.info("人工审核确认违规，弹幕已删除: reportId={}, danmakuId={}, reviewerId={}",
                    reportId, report.getDanmakuId(), reviewerId);
            } else {
                log.info("人工审核驳回举报: reportId={}, danmakuId={}, reviewerId={}",
                    reportId, report.getDanmakuId(), reviewerId);
            }

        } catch (IllegalArgumentException e) {
            throw e;
        } catch (Exception e) {
            log.error("人工审核异常: reportId={}, reviewerId={}", reportId, reviewerId, e);
            throw new RuntimeException("审核处理失败", e);
        }
    }

    public enum ReviewDecision {
        CONFIRM_VIOLATION, REJECT
    }

    public enum ReportStatus {
        PENDING(0, "待审核"),
        AUTO_RESOLVED(1, "自动处理"),
        CONFIRMED(2, "确认违规"),
        REJECTED(3, "驳回");

        private final int code;
        private final String desc;

        ReportStatus(int code, String desc) {
            this.code = code;
            this.desc = desc;
        }

        public int getCode() { return code; }
    }

    public enum DanmakuStatus {
        NORMAL(0, "正常"),
        DELETED(1, "已删除"),
        HIDDEN(2, "已隐藏");

        private final int code;
        private final String desc;

        DanmakuStatus(int code, String desc) {
            this.code = code;
            this.desc = desc;
        }

        public int getCode() { return code; }
    }
}
```
