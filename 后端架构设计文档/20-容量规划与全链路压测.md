## 1. 问题背景

### 1.1 核心问题

在大规模分布式系统中，最令人恐惧的场景莫过于：大促活动开始的瞬间，系统因为流量激增而全面崩溃。用户看到的是白屏、超时、下单失败，业务看到的是真金白银的损失。这个问题的根源在于——**我们不知道系统的真实容量边界在哪里**。

容量规划的核心命题可以归结为三个问题：

1. **系统现在能扛多少？**（容量评估）——当前系统在各项资源约束下的最大服务能力是多少？
2. **系统将来需要扛多少？**（容量预测）——基于业务增长趋势和运营活动规划，未来某个时间点需要系统承载多大的流量？
3. **差距怎么补？**（容量规划与优化）——如果当前容量不足，是通过扩容还是优化来弥补差距？成本如何最优？

全链路压测则是回答第一个问题的最可靠手段：在生产环境中，使用真实的系统拓扑、真实的数据分布、真实的依赖关系，对完整的业务调用链路施加模拟流量，从而精准评估系统的真实容量上限。

### 1.2 传统性能测试的局限性

传统的性能测试方式存在三个致命缺陷：

**缺陷一：单接口压测无法反映全链路瓶颈**

微服务架构下，一个业务请求往往要经过 10+ 个服务节点。单独压测某一个接口根本无法暴露链路级别的瓶颈。例如订单服务单独压测能扛住 5000 QPS，但一旦与库存服务、支付服务组合调用，实际只能扛住 2000 QPS，因为库存服务的数据库连接池成了瓶颈。

```
单接口压测视角（乐观估计）：
  订单服务: 5000 QPS ✓
  库存服务: 8000 QPS ✓
  支付服务: 6000 QPS ✓
  → 预期系统容量: 5000 QPS（取最小值）

全链路压测视角（真实情况）：
  订单服务 → 库存服务 → 支付服务
       ↓         ↓         ↓
     DB连接池   DB锁竞争   第三方限流
  → 实际系统容量: 2000 QPS（存在链路级瓶颈）
```

**缺陷二：离线测试环境与生产环境差异巨大**

传统做法是在独立的测试环境进行压测，然后通过一个"环境差异系数"来估算生产环境的容量。这个系数通常由经验给出（例如 0.6~0.8），但实际上非常不准确：

- 测试环境的机器规格可能只有生产环境的一半
- 测试环境的数据量可能只有生产环境的 1%，数据库查询性能差异巨大
- 测试环境的网络拓扑、负载均衡策略与生产环境完全不同
- 测试环境缺少真实的缓存预热、连接池状态等运行时条件

```
测试环境压测结果 × 环境差异系数 = 预估生产容量
   5000 QPS     ×    0.7      =   3500 QPS

实际生产容量: 可能只有 2000 QPS（因为数据量差异导致 DB 查询慢了 3 倍）
也可能有 6000 QPS（因为生产环境缓存命中率更高）

→ 预估偏差可达 3~5 倍，完全不可靠
```

**缺陷三：无法模拟真实的混合流量模式**

真实用户行为是混合的——有人在浏览商品、有人在加购物车、有人在下单、有人在查物流。这些请求之间存在资源竞争关系（共享数据库连接池、缓存、CPU 等）。单场景压测无法模拟这种混合流量下的资源竞争态势。

另一种方式是完全搭建一套与生产一模一样的镜像环境进行压测，虽然精度高，但成本极其高昂——需要双倍的机器资源，且环境的同步维护本身就是巨大的运维负担。

**生产全链路压测的价值**

生产全链路压测结合了两种方式的优点：使用生产环境的真实数据和拓扑（精度高），同时通过数据隔离技术避免对线上业务的影响（成本低）。这一技术路线最早被应用于电商大促场景的容量验证，已经成为大规模分布式系统容量评估的事实标准。

### 1.3 不解决的后果

- **大促崩盘**：流量超过系统承受能力，引发级联故障，上下游服务雪崩，分钟级损失可达数百万
- **资源浪费**：为了"保险"而过度扩容，导致大量机器常年空闲，年化成本增加 30% 以上
- **被动救火**：每次出问题都是事后补救，团队疲于奔命，无法形成系统性的容量管理能力
- **信心不足**：研发团队无法回答"系统到底能扛多少流量"，业务团队无法放心做增长规划
- **发布风险不可控**：新版本上线后容量变化未知，系统退化无法及时发现

### 1.4 解决目标

建设一套完整的全链路压测平台，需要满足三个核心要求：

1. **充足的压力容量**：能够产生足够大的压力流量，覆盖预期峰值的 1.5~2 倍
2. **丰富的流量构造手段**：支持多种流量录制、参数化、场景编排能力，能够模拟真实的业务流量分布
3. **对目标服务的高度安全性**：确保压测流量不会污染线上真实数据，且能在异常时自动熔断

### 2.2 核心模块划分

| 模块 | 职责 | 关键能力 |
|------|------|---------|
| 管理控制台 | 压测任务全生命周期管理 | 任务创建/编辑/执行、场景编排、元数据配置、实时监控大屏、压测报告生成 |
| 压测引擎 | 发送压测请求 | 接收控制指令（启动/停止/动态调整 QPS）、按指定协议发送请求、上报客户端指标 |
| 压测探针 | 嵌入目标服务的中间件 | 数据隔离（影子库/表/缓存/消息队列）、压力标识透传、服务端指标采集上报 |
| 监控数据计算 | 原始指标聚合与告警 | 从原始数据计算有意义的业务指标（P99 延迟、错误率等），生成告警事件 |

### 2.3 技术选型与依赖

```
压测引擎通信协议: HTTP/1.1, HTTP/2, gRPC, Dubbo, Thrift
消息队列: Kafka（指标上报、指令下发）
数据存储: MySQL（任务元数据）、ClickHouse（监控指标）、Redis（实时状态）
配置管理: ZooKeeper / Etcd（引擎集群协调）
监控集成: Prometheus + Grafana（指标可视化）
调用链集成: 基于 OpenTracing 的链路追踪系统
```

### 3.2 压测引擎架构

压测引擎是整个平台的心脏，负责产生压测流量。采用 **Master-Slave** 架构实现分布式压力生成。

#### 3.2.1 机器资源估算模型

在启动压测任务前，需要计算所需的引擎机器数量。核心公式如下：

```
所需机器数 = 总目标压力 / 单机压力

单机压力 = 单线程吞吐量 × 并发线程数

单线程吞吐量 = 吞吐量单位（通常为 1000ms） / 预估响应时间（ms）
```

**示例计算**：

```
目标 QPS: 50,000
预估平均 RT: 50ms
单线程吞吐量 = 1000 / 50 = 20 QPS
默认并发线程数: 50
单机压力 = 20 × 50 = 1,000 QPS
所需机器数 = 50,000 / 1,000 = 50 台
```

```java
/**
 * 压测机器资源估算器
 */
public class EngineResourceEstimator {

    /**
     * 计算所需引擎机器数量
     *
     * @param targetQps       目标总 QPS
     * @param estimatedRtMs   预估平均响应时间（毫秒）
     * @param concurrentThreads 单机并发线程数（默认 1，用户可自行设置）
     * @return 所需机器数量
     */
    public int estimateMachineCount(int targetQps, double estimatedRtMs,
                                     int concurrentThreads) {
        // 单线程吞吐量 = 1000ms / 预估RT
        double singleThreadThroughput = 1000.0 / estimatedRtMs;

        // 单机压力 = 单线程吞吐量 × 并发线程数
        double singleMachinePressure = singleThreadThroughput * concurrentThreads;

        // 所需机器数 = 总目标压力 / 单机压力（向上取整，并预留 20% 缓冲）
        int machineCount = (int) Math.ceil(targetQps / singleMachinePressure);
        int bufferedCount = (int) Math.ceil(machineCount * 1.2);

        return bufferedCount;
    }

    /**
     * 验证资源估算的合理性
     */
    public EstimationResult validateEstimation(int targetQps, double estimatedRtMs,
                                                int concurrentThreads,
                                                int availableMachines) {
        int required = estimateMachineCount(targetQps, estimatedRtMs, concurrentThreads);
        EstimationResult result = new EstimationResult();
        result.setRequiredMachines(required);
        result.setAvailableMachines(availableMachines);
        result.setFeasible(availableMachines >= required);

        if (!result.isFeasible()) {
            // 计算在现有机器数量下能达到的最大 QPS
            double singleThreadThroughput = 1000.0 / estimatedRtMs;
            double singleMachinePressure = singleThreadThroughput * concurrentThreads;
            int maxAchievableQps = (int) (availableMachines * singleMachinePressure);
            result.setMaxAchievableQps(maxAchievableQps);
            result.setSuggestion(String.format(
                "可用机器不足，当前最大可达 %d QPS，建议增加 %d 台机器或降低目标QPS",
                maxAchievableQps, required - availableMachines));
        }

        return result;
    }
}
```

#### 3.2.2 引擎集群管理

引擎集群支持两种管理模式：

**静态集群模式**：预先部署固定数量的引擎机器，通过心跳检测维护机器状态。适合压测频率高、团队有专属机器池的场景。

**动态集群模式**：按需从公司统一的机器资源池中申请和释放机器。优势是资源利用率更高，且引擎代码可以随申请自动部署最新版本，不需要手动升级。

```java
/**
 * 引擎集群管理器
 */
public class EngineClusterManager {

    private final MachinePoolClient machinePoolClient;
    private final HeartbeatDetector heartbeatDetector;
    private final ConcurrentMap<String, EngineNode> activeNodes = new ConcurrentHashMap<>();

    /**
     * 静态集群：注册预部署的引擎节点
     */
    public void registerStaticNode(String nodeId, String host, int port) {
        EngineNode node = new EngineNode(nodeId, host, port, ClusterMode.STATIC);
        node.setStatus(NodeStatus.IDLE);
        activeNodes.put(nodeId, node);

        // 启动心跳检测
        heartbeatDetector.startMonitoring(node, heartbeat -> {
            if (!heartbeat.isAlive()) {
                node.setStatus(NodeStatus.OFFLINE);
                activeNodes.remove(nodeId);
                log.warn("引擎节点 {} 心跳丢失，已标记为离线", nodeId);
            }
        });
    }

    /**
     * 动态集群：按需申请引擎机器
     */
    public List<EngineNode> allocateDynamicNodes(int count, MachineSpec spec) {
        // 向公司机器资源池申请指定规格的机器
        List<MachineInfo> machines = machinePoolClient.allocate(count, spec);

        List<EngineNode> nodes = new ArrayList<>();
        for (MachineInfo machine : machines) {
            // 远程部署压测引擎 Agent
            deployEngineAgent(machine);

            EngineNode node = new EngineNode(
                machine.getMachineId(), machine.getHost(),
                machine.getPort(), ClusterMode.DYNAMIC);
            node.setStatus(NodeStatus.IDLE);
            activeNodes.put(node.getNodeId(), node);
            nodes.add(node);
        }

        return nodes;
    }

    /**
     * 动态集群：释放引擎机器
     */
    public void releaseDynamicNodes(List<String> nodeIds) {
        for (String nodeId : nodeIds) {
            EngineNode node = activeNodes.remove(nodeId);
            if (node != null && node.getClusterMode() == ClusterMode.DYNAMIC) {
                machinePoolClient.release(node.getHost());
            }
        }
    }

    /**
     * 获取当前可用的空闲引擎节点
     */
    public List<EngineNode> getAvailableNodes(int count) {
        return activeNodes.values().stream()
            .filter(n -> n.getStatus() == NodeStatus.IDLE)
            .limit(count)
            .collect(Collectors.toList());
    }
}
```

#### 3.2.3 Master 节点设计

Master 节点负责任务分发、QPS 动态调控和 Slave 节点的生命周期管理。

```java
/**
 * 压测引擎 Master 节点
 */
public class EngineMaster {

    private final EngineClusterManager clusterManager;
    private final TaskAssigner taskAssigner;
    private final QpsController qpsController;

    /**
     * 启动压测任务
     */
    public TaskExecutionResult startTask(StressTestTask task) {
        // 1. 估算所需机器数量
        int requiredMachines = estimateRequiredMachines(task);

        // 2. 获取可用引擎节点
        List<EngineNode> nodes = clusterManager.getAvailableNodes(requiredMachines);
        if (nodes.size() < requiredMachines) {
            // 尝试动态申请补充
            int deficit = requiredMachines - nodes.size();
            List<EngineNode> dynamicNodes = clusterManager.allocateDynamicNodes(
                deficit, getDefaultMachineSpec());
            nodes.addAll(dynamicNodes);
        }

        // 3. 将任务均匀分配到各 Slave 节点
        Map<EngineNode, TaskSlice> assignments = taskAssigner.assign(task, nodes);

        // 4. 下发任务到各 Slave
        for (Map.Entry<EngineNode, TaskSlice> entry : assignments.entrySet()) {
            EngineNode node = entry.getKey();
            TaskSlice slice = entry.getValue();
            node.setStatus(NodeStatus.RUNNING);
            sendTaskToSlave(node, slice);
        }

        // 5. 启动 QPS 控制器（处理动态调压请求）
        qpsController.start(task.getTaskId(), nodes);

        return new TaskExecutionResult(task.getTaskId(), nodes.size(), "STARTED");
    }

    /**
     * 动态调整 QPS
     */
    public void adjustQps(Long taskId, int newTargetQps) {
        List<EngineNode> taskNodes = getNodesForTask(taskId);
        // 将新的目标 QPS 均匀分配到各节点
        int perNodeQps = newTargetQps / taskNodes.size();
        int remainder = newTargetQps % taskNodes.size();

        for (int i = 0; i < taskNodes.size(); i++) {
            int nodeQps = perNodeQps + (i < remainder ? 1 : 0);
            sendQpsAdjustCommand(taskNodes.get(i), nodeQps);
        }

        log.info("任务 {} QPS 已调整为 {}，分配到 {} 个节点",
            taskId, newTargetQps, taskNodes.size());
    }

    /**
     * 停止压测任务
     */
    public void stopTask(Long taskId) {
        List<EngineNode> taskNodes = getNodesForTask(taskId);
        for (EngineNode node : taskNodes) {
            sendStopCommand(node);
            node.setStatus(NodeStatus.IDLE);
        }
        qpsController.stop(taskId);
        log.info("任务 {} 已停止，释放 {} 个引擎节点", taskId, taskNodes.size());
    }
}
```

#### 3.2.4 Slave 节点——压测 Agent 设计

每个 Slave 节点运行一个压测 Agent，包含三个核心组件：控制器（接收 Master 指令）、流量生成器（发送请求）、指标上报器（采集并上报客户端指标）。

流量生成器采用**生产者-消费者模式**，使用有界阻塞队列控制内存：

```java
/**
 * 压测 Agent——Slave 节点核心实现
 */
public class StressAgent {

    /** 有界阻塞队列，控制待发送请求的内存占用 */
    private final BlockingQueue<StressRequest> requestQueue;

    /** 请求生产者线程 */
    private final RequestProducer producer;

    /** 请求消费者（发送）线程池 */
    private final List<RequestConsumer> consumers;

    /** 指标采集器 */
    private final ClientMetricsCollector metricsCollector;

    /** 当前 QPS 限流器 */
    private final RateLimiter rateLimiter;

    /** Agent 状态 */
    private volatile AgentStatus status = AgentStatus.IDLE;

    public StressAgent(int queueCapacity, int concurrentThreads) {
        // 有界阻塞队列，防止内存溢出
        this.requestQueue = new ArrayBlockingQueue<>(queueCapacity);
        this.producer = new RequestProducer(requestQueue);
        this.consumers = new ArrayList<>();
        this.metricsCollector = new ClientMetricsCollector();

        for (int i = 0; i < concurrentThreads; i++) {
            consumers.add(new RequestConsumer(requestQueue, metricsCollector));
        }

        this.rateLimiter = RateLimiter.create(1); // 初始 QPS 为 1
    }

    /**
     * 接收 Master 指令
     */
    public void handleCommand(EngineCommand command) {
        switch (command.getType()) {
            case START:
                start(command.getTaskSlice());
                break;
            case STOP:
                stop();
                break;
            case ADJUST_QPS:
                adjustQps(command.getTargetQps());
                break;
            default:
                log.warn("未知指令类型: {}", command.getType());
        }
    }

    /**
     * 启动压测
     */
    public void start(TaskSlice taskSlice) {
        this.status = AgentStatus.RUNNING;

        // 设置目标 QPS
        rateLimiter.setRate(taskSlice.getTargetQps());

        // 启动请求生产者：根据场景配置生成请求并放入队列
        producer.start(taskSlice);

        // 启动请求消费者：从队列取出请求并发送
        for (RequestConsumer consumer : consumers) {
            consumer.start(rateLimiter);
        }

        // 启动指标上报定时任务（每秒上报一次）
        metricsCollector.startReporting(taskSlice.getTaskId(), 1000);

        log.info("Agent 启动，目标 QPS: {}, 并发线程: {}",
            taskSlice.getTargetQps(), consumers.size());
    }

    /**
     * 动态调整 QPS
     */
    public void adjustQps(int newQps) {
        rateLimiter.setRate(newQps);
        log.info("Agent QPS 已调整为: {}", newQps);
    }

    /**
     * 停止压测
     */
    public void stop() {
        this.status = AgentStatus.IDLE;
        producer.stop();
        consumers.forEach(RequestConsumer::stop);
        metricsCollector.stopReporting();
        requestQueue.clear();
    }
}

/**
 * 请求消费者——从队列取出请求并异步发送
 */
public class RequestConsumer implements Runnable {

    private final BlockingQueue<StressRequest> queue;
    private final ClientMetricsCollector metricsCollector;
    private final AsyncHttpClient httpClient;
    private volatile boolean running = false;

    @Override
    public void run() {
        while (running) {
            try {
                StressRequest request = queue.poll(100, TimeUnit.MILLISECONDS);
                if (request == null) continue;

                // 使用限流器控制发送速率
                rateLimiter.acquire();

                long startTime = System.nanoTime();

                // 异步发送请求，提高吞吐量
                httpClient.executeAsync(request.toHttpRequest())
                    .whenComplete((response, throwable) -> {
                        long costMs = TimeUnit.NANOSECONDS.toMillis(
                            System.nanoTime() - startTime);

                        if (throwable != null) {
                            metricsCollector.recordFailure(request, costMs, throwable);
                        } else {
                            metricsCollector.recordSuccess(request, costMs,
                                response.getStatusCode());
                            // 执行响应提取（供后续接口参数化使用）
                            executeExtractors(request, response);
                        }
                    });
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
    }
}
```

```java
/**
 * 客户端指标采集器
 * 在引擎端采集请求发送的性能数据
 */
public class ClientMetricsCollector {

    /** 滑动窗口指标：每秒一个桶 */
    private final SlidingWindowCounter successCounter = new SlidingWindowCounter(60);
    private final SlidingWindowCounter failureCounter = new SlidingWindowCounter(60);

    /** RT 分布直方图 */
    private final HdrHistogram rtHistogram = new HdrHistogram(1, 60000, 3);

    /** 指标上报 Kafka Producer */
    private final KafkaProducer<String, MetricsMessage> kafkaProducer;

    /**
     * 记录成功请求
     */
    public void recordSuccess(StressRequest request, long costMs, int statusCode) {
        successCounter.increment();
        rtHistogram.recordValue(costMs);

        // 判断业务成功（HTTP 200 不一定是业务成功，需要检查业务码）
        if (statusCode >= 400) {
            failureCounter.increment();
        }
    }

    /**
     * 记录失败请求
     */
    public void recordFailure(StressRequest request, long costMs, Throwable error) {
        failureCounter.increment();
        if (costMs > 0) {
            rtHistogram.recordValue(costMs);
        }
    }

    /**
     * 定时上报聚合指标
     */
    public void reportMetrics(Long taskId) {
        MetricsMessage metrics = new MetricsMessage();
        metrics.setTaskId(taskId);
        metrics.setTimestamp(System.currentTimeMillis());
        metrics.setNodeId(getNodeId());

        // 吞吐量指标
        metrics.setTotalQps(successCounter.getCount() + failureCounter.getCount());
        metrics.setSuccessQps(successCounter.getCount());
        metrics.setFailureQps(failureCounter.getCount());
        metrics.setErrorRate(failureCounter.getCount() * 1.0 /
            Math.max(1, metrics.getTotalQps()));

        // RT 分位值指标
        metrics.setAvgRt(rtHistogram.getMean());
        metrics.setP50Rt(rtHistogram.getValueAtPercentile(50));
        metrics.setP90Rt(rtHistogram.getValueAtPercentile(90));
        metrics.setP95Rt(rtHistogram.getValueAtPercentile(95));
        metrics.setP99Rt(rtHistogram.getValueAtPercentile(99));
        metrics.setMaxRt(rtHistogram.getMaxValue());

        // 发送到 Kafka
        kafkaProducer.send(new ProducerRecord<>("stress_metrics", 
            String.valueOf(taskId), metrics));

        // 重置直方图（每个上报周期清零）
        rtHistogram.reset();
    }
}
```

### 3.3 流量构造与录制回放

流量构造是全链路压测的基础能力，决定了压测流量能否真实反映线上实际请求分布。

#### 3.3.1 流量录制方式

支持三种流量录制方式，适用于不同场景：

| 方式 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| TCP 抓包 | 在网络层捕获数据包，解析协议内容 | 无侵入，不需要修改代码 | 解析复杂协议困难，HTTPS 需要证书 | HTTP 协议的简单接口 |
| 中间件集成 | 在 Web 框架或 RPC 框架中植入录制逻辑 | 精度高，能获取完整请求上下文 | 需要中间件支持 | 统一框架的微服务集群 |
| Java 字节码注入 | 通过 JavaAgent 在运行时注入录制逻辑 | 无需修改源码，灵活性强 | 实现复杂，有一定性能开销 | 无法修改中间件的场景 |

#### 3.3.2 录制探针设计

录制探针必须是**低开销**的，否则会影响线上服务性能。关键约束包括：

- 内存使用量限制在 50MB 以内
- 对请求 RT 的影响不超过 1ms
- 使用 UDP 传输录制数据（可接受少量丢失，换取最小的性能影响）

```java
/**
 * 流量录制探针
 * 通过字节码注入嵌入目标服务的请求处理链路
 */
public class TrafficRecordingProbe {

    /** 录制数据缓冲区（有界队列，防止内存溢出） */
    private final BlockingQueue<RecordedRequest> buffer;

    /** UDP 发送器（低延迟，不阻塞业务线程） */
    private final UdpSender udpSender;

    /** 采样率（不是所有请求都需要录制） */
    private final double samplingRate;

    /** 内存使用量监控 */
    private final MemoryMonitor memoryMonitor;

    private static final long MAX_MEMORY_BYTES = 50 * 1024 * 1024; // 50MB

    public TrafficRecordingProbe(String receiverHost, int receiverPort,
                                  double samplingRate, int bufferSize) {
        this.buffer = new ArrayBlockingQueue<>(bufferSize);
        this.udpSender = new UdpSender(receiverHost, receiverPort);
        this.samplingRate = samplingRate;
        this.memoryMonitor = new MemoryMonitor(MAX_MEMORY_BYTES);

        // 启动异步发送线程
        startAsyncSender();
    }

    /**
     * 录制一次请求（被字节码注入到请求处理链路中）
     * 必须是非阻塞的，不能影响业务请求处理
     */
    public void recordRequest(HttpServletRequest request, 
                               HttpServletResponse response,
                               long processingTimeMs) {
        // 采样判断
        if (ThreadLocalRandom.current().nextDouble() > samplingRate) {
            return;
        }

        // 内存保护：如果内存使用量超限，直接丢弃
        if (memoryMonitor.isOverLimit()) {
            return;
        }

        RecordedRequest recorded = new RecordedRequest();
        recorded.setMethod(request.getMethod());
        recorded.setUri(request.getRequestURI());
        recorded.setQueryString(request.getQueryString());
        recorded.setHeaders(extractHeaders(request));
        recorded.setBody(readBody(request));
        recorded.setStatusCode(response.getStatus());
        recorded.setProcessingTimeMs(processingTimeMs);
        recorded.setRecordTime(System.currentTimeMillis());

        // 非阻塞地放入缓冲区，如果队列满则直接丢弃
        if (!buffer.offer(recorded)) {
            log.debug("录制缓冲区已满，丢弃请求: {}", recorded.getUri());
        }
    }

    /**
     * 异步发送线程：从缓冲区取出录制数据，通过 UDP 发送到流量接收器
     */
    private void startAsyncSender() {
        Thread senderThread = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                try {
                    RecordedRequest recorded = buffer.poll(100, TimeUnit.MILLISECONDS);
                    if (recorded != null) {
                        byte[] data = serialize(recorded);
                        udpSender.send(data);
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }
        }, "traffic-recording-sender");
        senderThread.setDaemon(true);
        senderThread.start();
    }
}

/**
 * 流量接收器——接收录制探针发送的数据
 */
public class TrafficReceiver {

    /** 令牌桶限流器，防止录制数据洪峰压垮接收器 */
    private final RateLimiter rateLimiter;

    /** 录制数据存储 */
    private final TrafficStorage storage;

    public TrafficReceiver(int maxReceiveRate) {
        this.rateLimiter = RateLimiter.create(maxReceiveRate);
        this.storage = new TrafficStorage();
    }

    /**
     * 接收录制数据
     */
    public void receive(byte[] data) {
        // 限流保护：防止录制数据太多压垮接收器
        if (!rateLimiter.tryAcquire()) {
            return; // 超过限流阈值，直接丢弃
        }

        RecordedRequest recorded = deserialize(data);
        storage.save(recorded);
    }
}
```

#### 3.3.3 参数化与响应提取

录制的流量不能原样重放——例如用户 ID、订单号等参数需要替换为压测专用的数据，以确保数据隔离。同时，多步骤场景中，后一个接口的入参可能依赖前一个接口的返回值。

```java
/**
 * 请求参数化处理器
 */
public class RequestParameterizer {

    /** 参数数据源：CSV 文件、数据库、Redis 等 */
    private final Map<String, DataIterator> dataSources = new HashMap<>();

    /**
     * 注册参数化数据源
     * @param paramName 参数名，对应请求模板中的 ${paramName}
     * @param iterator  数据迭代器
     */
    public void registerDataSource(String paramName, DataIterator iterator) {
        dataSources.put(paramName, iterator);
    }

    /**
     * 对请求模板进行参数化替换
     */
    public StressRequest parameterize(StressApi api,
                                       Map<String, String> extractedVars) {
        String body = api.getBodyTemplate();
        String url = api.getUrl();
        Map<String, String> headers = new HashMap<>(api.getHeaders());

        // 1. 替换数据源参数 ${paramName}
        for (Map.Entry<String, DataIterator> entry : dataSources.entrySet()) {
            String placeholder = "${" + entry.getKey() + "}";
            String value = entry.getValue().next();

            body = body.replace(placeholder, value);
            url = url.replace(placeholder, value);
        }

        // 2. 替换从前置接口响应中提取的变量
        for (Map.Entry<String, String> entry : extractedVars.entrySet()) {
            String placeholder = "${" + entry.getKey() + "}";
            body = body.replace(placeholder, entry.getValue());
            url = url.replace(placeholder, entry.getValue());
        }

        // 3. 注入压力标识
        headers.put("X-Stress-Tag", "STRESS_TAG=" + getCurrentTaskId());

        StressRequest request = new StressRequest();
        request.setMethod(api.getMethod());
        request.setUrl(url);
        request.setHeaders(headers);
        request.setBody(body);
        return request;
    }
}

/**
 * 响应提取器——从接口响应中提取变量供后续接口使用
 */
public class ResponseExtractor {

    /** 变量名 */
    private String variableName;

    /** 提取方式: JSON_PATH, REGEX, HEADER */
    private ExtractType extractType;

    /** 提取表达式 */
    private String expression;

    /**
     * 从响应中提取变量值
     */
    public String extract(HttpResponse response) {
        switch (extractType) {
            case JSON_PATH:
                // 使用 JsonPath 从响应体中提取
                return JsonPath.read(response.getBody(), expression).toString();
            case REGEX:
                // 使用正则表达式从响应体中提取
                Matcher matcher = Pattern.compile(expression)
                    .matcher(response.getBody());
                return matcher.find() ? matcher.group(1) : null;
            case HEADER:
                // 从响应头中提取
                return response.getHeader(expression);
            default:
                return null;
        }
    }
}
```

### 3.4 数据隔离体系

数据隔离是生产全链路压测的安全基石。核心原则：**压测流量产生的所有数据写入操作，必须路由到隔离的存储空间，绝对不能污染线上真实数据**。

#### 3.4.1 压力标识结构

所有压测请求都携带一个标准化的压力标识，格式为：

```
STRESS_TAG=${taskId}
```

该标识贯穿整条调用链路，是数据隔离路由决策的依据。

#### 3.4.2 数据库隔离

数据库隔离有两种方案：**影子库**和**影子表**。

```
方案对比：
┌──────────┬──────────────────────┬──────────────────────┐
│          │      影子库           │       影子表          │
├──────────┼──────────────────────┼──────────────────────┤
│ 隔离级别  │ 高（独立数据库实例）   │ 中（同库不同表）       │
│ 运维成本  │ 高（需维护独立实例）   │ 低（自动创建影子表）   │
│ 数据安全  │ 更安全               │ 有同库资源竞争风险     │
│ 实现方式  │ 数据源路由            │ 表名改写              │
│ 适用场景  │ 核心交易链路          │ 非核心业务链路         │
└──────────┴──────────────────────┴──────────────────────┘
```

**影子表命名规则**：影子表与真实表结构完全一致，表名添加 `_shadow_` 前缀。例如：

```
真实表: t_order         →  影子表: _shadow_t_order
真实表: t_order_item    →  影子表: _shadow_t_order_item
真实表: t_inventory     →  影子表: _shadow_t_inventory
```

```java
/**
 * 数据库路由中间件——根据压力标识决定访问真实库/表还是影子库/表
 */
public class ShadowDatabaseRouter {

    /** 影子数据源（影子库方案使用） */
    private final DataSource shadowDataSource;

    /** 真实数据源 */
    private final DataSource realDataSource;

    /** 隔离策略 */
    private final IsolationStrategy strategy;

    /**
     * 获取当前应该使用的数据源
     * 在 MyBatis Interceptor 或 Spring AbstractRoutingDataSource 中调用
     */
    public DataSource determineDataSource() {
        if (StressContext.isStressRequest()) {
            if (strategy == IsolationStrategy.SHADOW_DATABASE) {
                return shadowDataSource;
            }
            // 影子表方案使用同一数据源，在 SQL 层面改写表名
            return realDataSource;
        }
        return realDataSource;
    }

    /**
     * SQL 表名改写（影子表方案）
     * 拦截 SQL 语句，将表名替换为影子表名
     */
    public String rewriteSql(String originalSql) {
        if (!StressContext.isStressRequest()) {
            return originalSql;
        }

        if (strategy != IsolationStrategy.SHADOW_TABLE) {
            return originalSql;
        }

        // 解析 SQL 中涉及的表名，添加 _shadow_ 前缀
        SqlParser parser = new SqlParser(originalSql);
        List<String> tableNames = parser.extractTableNames();

        String rewrittenSql = originalSql;
        for (String tableName : tableNames) {
            String shadowTableName = "_shadow_" + tableName;
            rewrittenSql = rewrittenSql.replace(tableName, shadowTableName);
        }

        return rewrittenSql;
    }
}

/**
 * MyBatis 拦截器——实现 SQL 级别的影子表路由
 */
@Intercepts({
    @Signature(type = StatementHandler.class,
               method = "prepare",
               args = {Connection.class, Integer.class})
})
public class ShadowTableInterceptor implements Interceptor {

                "delegate.boundSql.sql");

            }
        }

    }
```

### 3.5 压力标识传递机制

压力标识的准确传递是数据隔离生效的前提。标识必须贯穿整个调用链路中的每一个环节——进程内、跨线程、跨服务。

#### 3.5.1 进程内传递——ThreadLocal

```java
/**
 * 压测上下文——基于 ThreadLocal 的压力标识传递
 */
public class StressContext {

    /** 当前线程的压力标识 */
    private static final ThreadLocal<String> STRESS_TAG = new ThreadLocal<>();

    /** InheritableThreadLocal 用于子线程继承压力标识 */
    private static final InheritableThreadLocal<String> INHERITABLE_STRESS_TAG =
        new InheritableThreadLocal<>();

    /**
     * 设置压力标识（在请求入口处调用）
     */
    public static void setStressTag(String tag) {
        STRESS_TAG.set(tag);
        INHERITABLE_STRESS_TAG.set(tag);
    }

    /**
     * 获取压力标识
     */
    public static String getStressTag() {
        String tag = STRESS_TAG.get();
        if (tag == null) {
            tag = INHERITABLE_STRESS_TAG.get();
        }
        return tag;
    }

    /**
     * 判断当前请求是否为压测请求
     */
    public static boolean isStressRequest() {
        return getStressTag() != null;
    }

    /**
     * 清理压力标识（在请求处理完毕后调用，防止 ThreadLocal 泄露）
     */
    public static void clear() {
        STRESS_TAG.remove();
        INHERITABLE_STRESS_TAG.remove();
    }

    /**
     * 获取当前压测任务 ID
     */
    public static String getTaskId() {
        String tag = getStressTag();
        if (tag != null && tag.startsWith("STRESS_TAG=")) {
            return tag.substring("STRESS_TAG=".length());
        }
        return null;
    }
}
```

#### 3.5.2 线程池场景的标识传递

当业务代码使用线程池异步处理时，ThreadLocal 中的压力标识不会自动传递到线程池的工作线程。需要对 Runnable/Callable 进行包装：

```java
/**
 * 压测上下文感知的 Runnable 包装器
 * 确保提交到线程池的任务能够继承压力标识
 */
public class StressContextRunnable implements Runnable {

    private final Runnable delegate;
    private final String stressTag;

    public StressContextRunnable(Runnable delegate) {
        this.delegate = delegate;
        // 在创建时（提交线程）捕获压力标识
        this.stressTag = StressContext.getStressTag();
    }

    @Override
    public void run() {
        // 在执行时（工作线程）恢复压力标识
        String previousTag = StressContext.getStressTag();
        try {
            if (stressTag != null) {
                StressContext.setStressTag(stressTag);
            }
            delegate.run();
        } finally {
            // 恢复工作线程之前的上下文
            if (previousTag != null) {
                StressContext.setStressTag(previousTag);
            } else {
                StressContext.clear();
            }
        }
    }

    /**
     * 便捷工厂方法
     */
    public static Runnable wrap(Runnable runnable) {
        if (runnable instanceof StressContextRunnable) {
            return runnable;
        }
        return new StressContextRunnable(runnable);
    }
}

/**
 * 压测上下文感知的线程池装饰器
 */
public class StressContextExecutorService implements ExecutorService {

    private final ExecutorService delegate;

    public StressContextExecutorService(ExecutorService delegate) {
        this.delegate = delegate;
    }

    @Override
    public void execute(Runnable command) {
        delegate.execute(StressContextRunnable.wrap(command));
    }

    @Override
    public <T> Future<T> submit(Callable<T> task) {
        return delegate.submit(StressContextCallable.wrap(task));
    }

    @Override
    public Future<?> submit(Runnable task) {
        return delegate.submit(StressContextRunnable.wrap(task));
    }

    // ... 其他方法类似包装
}
```

#### 3.5.4 入口处标识初始化

在请求入口（通常是 Web 服务器的 Filter 或 Interceptor）需要识别压测请求并初始化上下文：

```java
/**
 * Web 请求入口——识别压测请求并初始化上下文
 */
public class StressTagFilter implements Filter {

    @Override
    public void doFilter(ServletRequest request, ServletResponse response,
                          FilterChain chain) throws IOException, ServletException {
        HttpServletRequest httpRequest = (HttpServletRequest) request;

        try {
            // 从多个位置尝试提取压力标识
            String stressTag = extractStressTag(httpRequest);
            if (stressTag != null) {
                StressContext.setStressTag(stressTag);
            }

            chain.doFilter(request, response);
        } finally {
            // 请求处理完毕，清理上下文，防止 ThreadLocal 泄露
            StressContext.clear();
        }
    }

    private String extractStressTag(HttpServletRequest request) {
        // 优先级 1：自定义请求头
        String tag = request.getHeader("X-Stress-Tag");
        if (tag != null) return tag;

        // 优先级 2：URL 参数
        tag = request.getParameter("_stress_tag");
        if (tag != null) return tag;

        // 优先级 3：Cookie
        Cookie[] cookies = request.getCookies();
        if (cookies != null) {
            for (Cookie cookie : cookies) {
                if ("_stress_tag".equals(cookie.getName())) {
                    return cookie.getValue();
                }
            }
        }

        return null;
    }
}
```

### 3.6 压测探针设计

压测探针嵌入目标服务，负责两个核心职责：数据隔离路由（前文已详述）和服务端指标采集上报。

#### 3.6.1 服务端指标采集

```java
/**
 * 服务端指标采集器——嵌入目标服务的探针
 * 采集目标服务在处理压测请求时的性能表现
 */
public class ServerSideMetricsProbe {

    /** 服务标识 */
    private final String serviceId;

    /** 指标上报通道 */
    private final MetricsReporter reporter;

    /** 方法级别的指标收集器 */
    private final ConcurrentMap<String, MethodMetrics> methodMetricsMap =
        new ConcurrentHashMap<>();

    /**
     * 请求处理前调用
     */
    public void beforeProcess(String methodName) {
        if (!StressContext.isStressRequest()) return;

        MethodMetrics metrics = methodMetricsMap.computeIfAbsent(
            methodName, k -> new MethodMetrics(k));
        metrics.incrementActiveCount();
    }

    /**
     * 请求处理后调用
     */
    public void afterProcess(String methodName, long processingTimeMs,
                              boolean success) {
        if (!StressContext.isStressRequest()) return;

        MethodMetrics metrics = methodMetricsMap.get(methodName);
        if (metrics != null) {
            metrics.decrementActiveCount();
            metrics.recordLatency(processingTimeMs);
            if (success) {
                metrics.incrementSuccess();
            } else {
                metrics.incrementFailure();
            }
        }
    }

    /**
     * 系统级别指标采集（JVM、OS）
     */
    public SystemMetrics collectSystemMetrics() {
        SystemMetrics metrics = new SystemMetrics();

        // CPU 使用率
        OperatingSystemMXBean osBean = ManagementFactory.getOperatingSystemMXBean();
        if (osBean instanceof com.sun.management.OperatingSystemMXBean) {
            metrics.setCpuUsage(
                ((com.sun.management.OperatingSystemMXBean) osBean)
                    .getProcessCpuLoad() * 100);
        }

        // JVM 内存
        MemoryMXBean memoryBean = ManagementFactory.getMemoryMXBean();
        MemoryUsage heapUsage = memoryBean.getHeapMemoryUsage();
        metrics.setHeapUsedMb(heapUsage.getUsed() / (1024 * 1024));
        metrics.setHeapMaxMb(heapUsage.getMax() / (1024 * 1024));
        metrics.setHeapUsagePercent(
            heapUsage.getUsed() * 100.0 / heapUsage.getMax());

        // GC 信息
        List<GarbageCollectorMXBean> gcBeans =
            ManagementFactory.getGarbageCollectorMXBeans();
        long totalGcCount = 0;
        long totalGcTimeMs = 0;
        for (GarbageCollectorMXBean gcBean : gcBeans) {
            totalGcCount += gcBean.getCollectionCount();
            totalGcTimeMs += gcBean.getCollectionTime();
        }
        metrics.setGcCount(totalGcCount);
        metrics.setGcTimeMs(totalGcTimeMs);

        // 线程信息
        ThreadMXBean threadBean = ManagementFactory.getThreadMXBean();
        metrics.setActiveThreadCount(threadBean.getThreadCount());
        metrics.setDeadlockedThreadCount(
            threadBean.findDeadlockedThreads() != null ?
                threadBean.findDeadlockedThreads().length : 0);

        return metrics;
    }

    /**
     * 定时上报聚合后的服务端指标
     */
    public void reportMetrics() {
        ServerMetricsMessage message = new ServerMetricsMessage();
        message.setServiceId(serviceId);
        message.setTimestamp(System.currentTimeMillis());
        message.setSystemMetrics(collectSystemMetrics());
        message.setMethodMetrics(new ArrayList<>(methodMetricsMap.values()));

        reporter.report(message);

        // 重置方法级别指标
        methodMetricsMap.values().forEach(MethodMetrics::reset);
    }
}
```

### 3.7 监控数据计算与告警

监控数据计算模块从 Kafka 消费原始指标数据，进行聚合计算后生成有意义的业务指标，并基于阈值规则生成告警事件。

#### 3.7.1 指标聚合计算

```java
/**
 * 监控指标聚合计算引擎
 */
public class MetricsAggregationEngine {

    /** 指标存储 */
    private final MetricsStorage storage;

    /** 告警事件生成器 */
    private final AlertEventGenerator alertGenerator;

    /**
     * 消费 Kafka 中的原始指标数据，进行聚合计算
     */
    @KafkaListener(topics = "stress_metrics")
    public void consumeClientMetrics(MetricsMessage rawMetrics) {
        Long taskId = rawMetrics.getTaskId();
        long timestamp = rawMetrics.getTimestamp();

        // 按时间窗口聚合（1 秒一个窗口）
        long windowKey = timestamp / 1000 * 1000;

        AggregatedMetrics aggregated = storage.getOrCreate(taskId, windowKey);

        // 累加各节点上报的指标
        synchronized (aggregated) {
            aggregated.addTotalQps(rawMetrics.getTotalQps());
            aggregated.addSuccessQps(rawMetrics.getSuccessQps());
            aggregated.addFailureQps(rawMetrics.getFailureQps());
            aggregated.mergeRtDistribution(rawMetrics);

            // 重新计算聚合指标
            aggregated.recalculateErrorRate();
            aggregated.recalculateP99();
        }

        // 存储到 ClickHouse 供历史查询
        storage.persist(aggregated);

        // 实时推送到监控大屏（WebSocket）
        pushToMonitorDashboard(aggregated);

        // 检查是否触发告警
        alertGenerator.check(aggregated);
    }

    /**
     * 消费服务端指标数据
     */
    @KafkaListener(topics = "stress_server_metrics")

        Long taskId = extractTaskId(serverMetrics);
```

#### 3.7.2 告警事件生成

```java
/**
 * 告警事件生成器——基于规则判断是否触发告警
 */
public class AlertEventGenerator {

    private final AlertRuleRepository ruleRepository;
    private final CircuitBreaker circuitBreaker;

    /**
     * 检查客户端指标是否触发告警
     */
    public void check(AggregatedMetrics metrics) {
        Long taskId = metrics.getTaskId();
        List<AlertRule> rules = ruleRepository.getRules(taskId);

        for (AlertRule rule : rules) {
            AlertEvent event = evaluate(metrics, rule);
            if (event != null) {
                // 发送告警通知
                notifyAlert(event);
                // 触发熔断动作
                circuitBreaker.onAlert(event);
            }
        }
    }

    /**
     * 评估单条告警规则
     */
    private AlertEvent evaluate(AggregatedMetrics metrics, AlertRule rule) {
        double currentValue;

        switch (rule.getMetricType()) {
            case ERROR_RATE:
                currentValue = metrics.getErrorRate();
                break;
            case P99_LATENCY:
                currentValue = metrics.getP99Rt();
                break;
            case QPS_DROP:
                // QPS 突降检测（与前一分钟对比）
                currentValue = metrics.getQpsDropRate();
                break;
            default:
                return null;
        }

        if (rule.getOperator() == Operator.GREATER_THAN
                && currentValue > rule.getThreshold()) {
            return createAlertEvent(metrics.getTaskId(), rule, currentValue);
        }

        if (rule.getOperator() == Operator.LESS_THAN
                && currentValue < rule.getThreshold()) {
            return createAlertEvent(metrics.getTaskId(), rule, currentValue);
        }

        return null;
    }

    /**
     * 检查服务端指标告警
     */
    public void checkServerMetrics(Long taskId, ServiceNodeHealth health) {
        ServiceProtectionConfig config = getProtectionConfig(taskId);

        // CPU 超限告警
        if (health.getCpuUsage() > config.getCpuThreshold()) {
            AlertEvent event = new AlertEvent();
            event.setTaskId(taskId);
            event.setAlertType(AlertType.CPU_OVERLOAD);
            event.setServiceId(health.getServiceId());
            event.setMessage(String.format("服务 %s CPU 使用率 %.1f%% 超过阈值 %d%%",
                health.getServiceId(), health.getCpuUsage(), config.getCpuThreshold()));
            event.setSeverity(AlertSeverity.CRITICAL);

            notifyAlert(event);
            circuitBreaker.onAlert(event);
        }

        // 内存超限告警
        if (health.getMemoryUsage() > config.getMemoryThreshold()) {
            AlertEvent event = new AlertEvent();
            event.setTaskId(taskId);
            event.setAlertType(AlertType.MEMORY_OVERLOAD);
            event.setServiceId(health.getServiceId());
            event.setMessage(String.format("服务 %s 内存使用率 %.1f%% 超过阈值 %d%%",
                health.getServiceId(), health.getMemoryUsage(),
                config.getMemoryThreshold()));
            event.setSeverity(AlertSeverity.CRITICAL);

            notifyAlert(event);
            circuitBreaker.onAlert(event);
        }
    }
}
```

### 3.8 服务保护与熔断机制

在生产环境进行压测，服务安全是第一优先级。服务保护机制通过**链路拓扑分析**和**实时监控告警**实现自动熔断。

#### 3.8.1 链路拓扑分析

在压测开始前，需要从分布式链路追踪系统获取目标链路涉及的所有服务节点，建立完整的服务拓扑图。这样才能对所有相关节点进行监控。

```java
/**
 * 链路拓扑分析器——从追踪系统获取服务拓扑
 */
public class ChainTopologyAnalyzer {

    private final TracingSystemClient tracingClient;

    /**
     * 分析压测目标链路涉及的所有服务节点
     *
     * @param entryServiceId 链路入口服务 ID
     * @param entryMethodName 链路入口方法名
     * @return 完整的服务拓扑图
     */
    public ServiceTopology analyzeTopology(String entryServiceId,
                                            String entryMethodName) {
        // 从追踪系统查询该入口服务最近 N 条 Trace
        List<TraceData> recentTraces = tracingClient.queryTraces(
            entryServiceId, entryMethodName, 100);

        // 从 Trace 中提取调用关系
        ServiceTopology topology = new ServiceTopology();
        for (TraceData trace : recentTraces) {
            for (SpanData span : trace.getSpans()) {
                ServiceNode from = new ServiceNode(
                    span.getServiceId(), span.getHost());
                ServiceNode to = new ServiceNode(
                    span.getRemoteServiceId(), span.getRemoteHost());

                topology.addEdge(from, to, span.getOperationName());
            }
        }

        // 去重并生成拓扑
        topology.build();
        log.info("链路拓扑分析完成，共涉及 {} 个服务节点，{} 条调用边",
            topology.getNodeCount(), topology.getEdgeCount());

        return topology;
```

```java
/**
 * 压测熔断器——基于告警事件自动保护目标服务
 */
public class StressCircuitBreaker {

    private final EngineMaster engineMaster;
    private final AlertNotifier notifier;

    /** 告警计数器：用于判断是否为持续性告警 */
    private final ConcurrentMap<String, AtomicInteger> alertCounters =
        new ConcurrentHashMap<>();

    /** 连续告警次数阈值 */
    private static final int CONSECUTIVE_ALERT_THRESHOLD = 3;

    /**
     * 响应告警事件
     */
    public void onAlert(AlertEvent event) {
        String alertKey = event.getTaskId() + ":" + event.getAlertType();
        int count = alertCounters
            .computeIfAbsent(alertKey, k -> new AtomicInteger(0))
            .incrementAndGet();

        // 单次告警不立即熔断，避免误判（瞬时毛刺）
        if (count < CONSECUTIVE_ALERT_THRESHOLD) {
            log.warn("任务 {} 收到告警 [{}] 第 {} 次，暂不触发熔断",
                event.getTaskId(), event.getAlertType(), count);
            return;
        }

        // 连续 N 次告警，触发熔断动作
        ServiceProtectionConfig config = getProtectionConfig(event.getTaskId());
        executeCircuitBreakAction(event, config);

        // 重置计数器
        alertCounters.remove(alertKey);
    }

    /**
     * 执行熔断动作
     */
    private void executeCircuitBreakAction(AlertEvent event,
                                            ServiceProtectionConfig config) {
        switch (config.getAction()) {
            case STOP_TASK:
                // 最严格：直接停止压测任务
                engineMaster.stopTask(event.getTaskId());
                notifier.notify(event.getTaskId(),
                    "压测任务已自动停止，原因: " + event.getMessage());
                log.error("任务 {} 触发自动停止: {}", event.getTaskId(),
                    event.getMessage());
                break;

            case REDUCE_QPS:
                // 柔性降级：降低压测 QPS
                int currentQps = engineMaster.getCurrentQps(event.getTaskId());
                int reducedQps = (int) (currentQps * (1 - config.getQpsReduceRatio()));
                reducedQps = Math.max(reducedQps, 1); // 至少保留 1 QPS
                engineMaster.adjustQps(event.getTaskId(), reducedQps);
                notifier.notify(event.getTaskId(),
                    String.format("压测 QPS 已自动降低: %d → %d，原因: %s",
                        currentQps, reducedQps, event.getMessage()));
                log.warn("任务 {} QPS 降级 {} → {}: {}",
                    event.getTaskId(), currentQps, reducedQps,
                    event.getMessage());
                break;

            case ALERT_ONLY:
                // 仅告警，不自动干预
                notifier.notify(event.getTaskId(),
                    "压测告警（需人工关注）: " + event.getMessage());
                log.warn("任务 {} 告警: {}", event.getTaskId(),
                    event.getMessage());
                break;
        }
    }

    /**
     * 告警恢复：当指标恢复正常时清除告警计数
     */
    public void onAlertRecovered(Long taskId, AlertType alertType) {
        String alertKey = taskId + ":" + alertType;
        alertCounters.remove(alertKey);
        log.info("任务 {} 告警 [{}] 已恢复", taskId, alertType);
    }
}
```

```java
/**
 * 容量评估报告生成器
 */
public class CapacityAssessmentReporter {

    /**
     * 根据压测结果生成容量评估报告
     */
    public CapacityReport generateReport(Long taskId,
                                          List<AggregatedMetrics> metricsHistory) {
        CapacityReport report = new CapacityReport();
        report.setTaskId(taskId);
        report.setGenerateTime(new Date());

        // 1. 找到系统的容量拐点
        CapacityInflectionPoint inflection = findInflectionPoint(metricsHistory);
        report.setInflectionPoint(inflection);

        // 2. 计算最大安全容量（拐点 QPS 的 80% 作为安全水位线）
        int maxSafeQps = (int) (inflection.getQpsAtInflection() * 0.8);
        report.setMaxSafeQps(maxSafeQps);

        // 3. 识别瓶颈节点
        List<BottleneckNode> bottlenecks = identifyBottlenecks(metricsHistory);
        report.setBottlenecks(bottlenecks);

        // 4. 生成容量规划建议
        List<String> recommendations = generateRecommendations(
            inflection, bottlenecks);
        report.setRecommendations(recommendations);

        return report;
    }

    /**
     * 找到系统容量拐点
     * 拐点定义：RT 开始急剧上升或错误率开始明显增加的 QPS 值
     */
    private CapacityInflectionPoint findInflectionPoint(
            List<AggregatedMetrics> history) {
        // 按 QPS 从低到高排序
        history.sort(Comparator.comparing(AggregatedMetrics::getTotalQps));

        double previousRt = 0;
        double previousErrorRate = 0;

        for (AggregatedMetrics metrics : history) {
            double currentRt = metrics.getP99Rt();
            double currentErrorRate = metrics.getErrorRate();

            // RT 增长率超过 50% 或错误率超过 1%，认为到达拐点
            if (previousRt > 0) {
                double rtGrowthRate = (currentRt - previousRt) / previousRt;

                if (rtGrowthRate > 0.5 || currentErrorRate > 0.01) {
                    CapacityInflectionPoint point = new CapacityInflectionPoint();
                    point.setQpsAtInflection(metrics.getTotalQps());
                    point.setRtAtInflection(currentRt);
                    point.setErrorRateAtInflection(currentErrorRate);
                    point.setReason(rtGrowthRate > 0.5 ?
                        "RT 急剧上升" : "错误率超过阈值");
                    return point;
                }
            }

            previousRt = currentRt;
            previousErrorRate = currentErrorRate;
        }

        // 未找到拐点，说明当前压力还不够大
        AggregatedMetrics last = history.get(history.size() - 1);
        CapacityInflectionPoint point = new CapacityInflectionPoint();
        point.setQpsAtInflection(last.getTotalQps());
        point.setRtAtInflection(last.getP99Rt());
        point.setReason("未达到容量上限，建议继续加压");
        return point;
    }

    /**
     * 识别瓶颈节点
     */
    private List<BottleneckNode> identifyBottlenecks(
            List<AggregatedMetrics> history) {
        List<BottleneckNode> bottlenecks = new ArrayList<>();

        // 获取压测峰值时刻的服务节点健康数据
        AggregatedMetrics peakMetrics = history.stream()
            .max(Comparator.comparing(AggregatedMetrics::getTotalQps))
            .orElse(null);

        if (peakMetrics == null) return bottlenecks;

        for (ServiceNodeHealth nodeHealth : peakMetrics.getNodeHealthList()) {
            if (nodeHealth.getCpuUsage() > 80
                    || nodeHealth.getMemoryUsage() > 85
                    || nodeHealth.getActiveThreads() > 500) {
                BottleneckNode node = new BottleneckNode();
                node.setServiceId(nodeHealth.getServiceId());
                node.setCpuUsage(nodeHealth.getCpuUsage());
                node.setMemoryUsage(nodeHealth.getMemoryUsage());
                node.setActiveThreads(nodeHealth.getActiveThreads());

                if (nodeHealth.getCpuUsage() > 80) {
                    node.setBottleneckType("CPU 密集");
                    node.setSuggestion("优化计算逻辑或增加机器");
                } else if (nodeHealth.getMemoryUsage() > 85) {
                    node.setBottleneckType("内存不足");
                    node.setSuggestion("检查内存泄漏或增大堆内存");
                } else {
                    node.setBottleneckType("线程池耗尽");
                    node.setSuggestion("优化下游调用或增大线程池");
                }

                bottlenecks.add(node);
            }
        }

        return bottlenecks;
    }
}
```

```java
/**
 * 压力递增策略——控制 QPS 的变化曲线
 */
public class RampUpStrategy {

    /** 递增模式 */
    private RampUpMode mode;

    /** 目标 QPS */
    private int targetQps;

    /** 递增时长（秒） */
    private int rampUpDurationSeconds;

    /** 阶梯数（阶梯递增模式使用） */
    private int stepCount;

    /**
     * 计算指定时间点的 QPS
     */
    public int calculateQpsAtTime(int elapsedSeconds) {
        switch (mode) {
            case LINEAR:
                // 线性递增：QPS 随时间线性增长
                if (elapsedSeconds >= rampUpDurationSeconds) {
                    return targetQps;
                }
                return (int) (targetQps * 1.0 * elapsedSeconds
                    / rampUpDurationSeconds);

            case STEP:
                // 阶梯递增：每个阶梯保持固定 QPS
                int stepDuration = rampUpDurationSeconds / stepCount;
                int currentStep = Math.min(
                    elapsedSeconds / stepDuration, stepCount);
                return (int) (targetQps * 1.0 * currentStep / stepCount);

            case EXPONENTIAL:
                // 指数递增：QPS 指数增长（模拟流量突增场景）
                if (elapsedSeconds >= rampUpDurationSeconds) {
                    return targetQps;
                }
                double ratio = 1.0 * elapsedSeconds / rampUpDurationSeconds;
                return (int) (targetQps * Math.pow(ratio, 2));

            case INSTANT:
                // 直接打满：瞬间到达目标 QPS（压力测试场景）
                return targetQps;

            default:
                return targetQps;
        }
    }
}
```

```java
/**
 * 引擎节点故障处理器
 */
public class EngineNodeFailureHandler {

    private final EngineClusterManager clusterManager;
    private final EngineMaster engineMaster;

    /**
     * 处理引擎节点故障
     * 场景：某个 Slave 节点在压测过程中宕机
     */
    public void handleNodeFailure(String failedNodeId, Long taskId) {
        log.error("引擎节点 {} 在任务 {} 执行中故障", failedNodeId, taskId);

        // 1. 从活跃节点列表中移除
        clusterManager.removeNode(failedNodeId);

        // 2. 将故障节点的任务分片重新分配给其他节点
        TaskSlice failedSlice = engineMaster.getNodeSlice(failedNodeId, taskId);
        if (failedSlice == null) return;

        // 3. 尝试获取备用节点
        List<EngineNode> spareNodes = clusterManager.getAvailableNodes(1);
        if (spareNodes.isEmpty()) {
            // 无备用节点，将压力分摊到其余节点
            redistributeLoad(taskId, failedSlice);
        } else {
            // 有备用节点，分配任务
            EngineNode spareNode = spareNodes.get(0);
            engineMaster.assignSliceToNode(spareNode, failedSlice);
            log.info("故障节点 {} 的任务已迁移到 {}", failedNodeId,
                spareNode.getNodeId());
        }
    }

    /**
     * 将故障节点的负载分摊给其余存活节点
     */
    private void redistributeLoad(Long taskId, TaskSlice failedSlice) {
        List<EngineNode> aliveNodes = engineMaster.getNodesForTask(taskId);
        if (aliveNodes.isEmpty()) {
            log.error("任务 {} 所有引擎节点均已故障，任务终止", taskId);
            engineMaster.markTaskFailed(taskId, "所有引擎节点故障");
            return;
        }

        int extraQpsPerNode = failedSlice.getTargetQps() / aliveNodes.size();
        for (EngineNode node : aliveNodes) {
            int currentQps = engineMaster.getNodeQps(node.getNodeId(), taskId);
            engineMaster.adjustNodeQps(node.getNodeId(), taskId,
                currentQps + extraQpsPerNode);
        }

        log.warn("故障节点的 {} QPS 已分摊到 {} 个存活节点",
            failedSlice.getTargetQps(), aliveNodes.size());
    }
}
```

```java
/**

public class DataIsolationSafetyChecker {

    /**
     * 数据库写入前的安全检查
     * 如果检测到压测请求试图写入真实表，立即拦截
     */
    public void checkBeforeWrite(String sql, boolean isStressRequest) {
        if (!isStressRequest) {
            // 非压测请求写入影子表也需要拦截
            if (isShadowTable(sql)) {
                throw new DataIsolationException(
                    "非压测请求不允许写入影子表: " + sql);
            }
            return;
        }

        // 压测请求必须写入影子表/库
        if (isWriteOperation(sql) && !isShadowTable(sql)) {
            throw new DataIsolationException(
                "压测请求写入了真实表，已拦截！SQL: " + sql);
        }
    }

    /**
     * 定期检查影子表数据量，防止影子数据无限增长
     */
    public void scheduleShadowDataCleanup() {
        // 每天凌晨清理超过 7 天的影子表数据
        ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1);
        scheduler.scheduleAtFixedRate(() -> {
            List<String> shadowTables = getAllShadowTables();
            for (String table : shadowTables) {
                long rowCount = getTableRowCount(table);
                if (rowCount > 1000000) {
                    log.warn("影子表 {} 数据量 {} 行，执行清理", table, rowCount);
                    truncateTable(table);
                }
            }
        }, 0, 24, TimeUnit.HOURS);
    }

    private boolean isShadowTable(String sql) {
        return sql.toLowerCase().contains("_shadow_");
    }

    private boolean isWriteOperation(String sql) {
        String upperSql = sql.trim().toUpperCase();
        return upperSql.startsWith("INSERT") || upperSql.startsWith("UPDATE")
            || upperSql.startsWith("DELETE");
    }
```

### 5.1 引擎端优化

#### 5.1.1 异步非阻塞请求发送

传统的同步 HTTP 请求方式下，每个线程在等待响应期间被阻塞，无法处理其他请求。使用异步非阻塞的方式可以大幅提升单机吞吐量。

```java
/**
 * 高性能异步请求发送器
 * 基于 Netty 的异步非阻塞实现，单线程可处理数千并发请求
 */
public class AsyncRequestSender {

    private final EventLoopGroup eventLoopGroup;
    private final Bootstrap bootstrap;

    public AsyncRequestSender(int ioThreads) {
        this.eventLoopGroup = new NioEventLoopGroup(ioThreads);
        this.bootstrap = new Bootstrap()
            .group(eventLoopGroup)
            .channel(NioSocketChannel.class)
            .option(ChannelOption.TCP_NODELAY, true)
            .option(ChannelOption.SO_KEEPALIVE, true)
            .option(ChannelOption.CONNECT_TIMEOUT_MILLIS, 3000);
    }

    /**
     * 异步发送请求
     * 返回 CompletableFuture，不阻塞调用线程
     */
    public CompletableFuture<HttpResponse> sendAsync(StressRequest request) {
        CompletableFuture<HttpResponse> future = new CompletableFuture<>();

        long startTime = System.nanoTime();

        bootstrap.clone()
            .handler(new ChannelInitializer<SocketChannel>() {
                @Override
                protected void initChannel(SocketChannel ch) {
                    ch.pipeline()
                        .addLast(new HttpClientCodec())
                        .addLast(new HttpObjectAggregator(1024 * 1024))
                        .addLast(new SimpleChannelInboundHandler<FullHttpResponse>() {
                            @Override
                            protected void channelRead0(ChannelHandlerContext ctx,
                                                         FullHttpResponse msg) {
                                long costNanos = System.nanoTime() - startTime;
                                HttpResponse response = convertResponse(msg, costNanos);
                                future.complete(response);
                                ctx.close();
                            }

                            @Override
                            public void exceptionCaught(ChannelHandlerContext ctx,
                                                         Throwable cause) {
                                future.completeExceptionally(cause);
                                ctx.close();
                            }
                        });
                }
            })
            .connect(request.getHost(), request.getPort())
            .addListener((ChannelFutureListener) connectFuture -> {
                if (connectFuture.isSuccess()) {
                    FullHttpRequest nettyRequest = buildNettyRequest(request);
                    connectFuture.channel().writeAndFlush(nettyRequest);
                } else {
                    future.completeExceptionally(connectFuture.cause());
                }
            });

        return future;
    }
}
```

```java
    /** 全局最大连接数 */
    private static final int MAX_TOTAL_CONNECTIONS = 2000;

    /** 连接空闲超时（毫秒） */
    private static final long IDLE_TIMEOUT_MS = 60000;

    /**
     * 创建优化后的连接池
     */
    public PoolingHttpClientConnectionManager createConnectionPool() {
        PoolingHttpClientConnectionManager cm =
            new PoolingHttpClientConnectionManager();
        cm.setMaxTotal(MAX_TOTAL_CONNECTIONS);
        cm.setDefaultMaxPerRoute(MAX_CONNECTIONS_PER_HOST);

        // 设置 TCP 参数优化
        SocketConfig socketConfig = SocketConfig.custom()
            .setTcpNoDelay(true)    // 关闭 Nagle 算法，减少延迟
            .setSoTimeout(10000)
            .setSoKeepAlive(true)
            .build();
        cm.setDefaultSocketConfig(socketConfig);

        // 启动空闲连接清理线程
        startIdleConnectionEvictor(cm);

        return cm;
    }

    /**
     * 定期清理空闲连接
     */
    private void startIdleConnectionEvictor(
            PoolingHttpClientConnectionManager cm) {
        Thread evictor = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                try {
                    Thread.sleep(30000); // 每 30 秒检查一次
                    cm.closeExpiredConnections();
                    cm.closeIdleConnections(IDLE_TIMEOUT_MS,
                        TimeUnit.MILLISECONDS);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        }, "idle-connection-evictor");
        evictor.setDaemon(true);
        evictor.start();
    }
}
```

```java
    /** 批量大小 */
    private static final int BATCH_SIZE = 100;

    /** 批量缓冲区 */
    private final BlockingQueue<MetricsMessage> buffer =
        new LinkedBlockingQueue<>(10000);

    /** 上报间隔（毫秒） */
    private static final long REPORT_INTERVAL_MS = 1000;

    private final KafkaProducer<String, byte[]> kafkaProducer;

    /**
     * 添加指标到批量缓冲区
     */
    public void addMetrics(MetricsMessage metrics) {
        if (!buffer.offer(metrics)) {
            log.warn("指标缓冲区已满，丢弃指标数据");
        }
    }

    /**
     * 批量上报线程
     */
    public void startBatchReporting() {
        Thread reporter = new Thread(() -> {
            List<MetricsMessage> batch = new ArrayList<>(BATCH_SIZE);

            while (!Thread.currentThread().isInterrupted()) {
                try {
                    // 等待第一条数据
                    MetricsMessage first = buffer.poll(
                        REPORT_INTERVAL_MS, TimeUnit.MILLISECONDS);
                    if (first == null) continue;
                    batch.add(first);

                    // 尽可能多地获取更多数据（但不阻塞）
                    buffer.drainTo(batch, BATCH_SIZE - 1);

                    // 序列化并压缩
                    byte[] compressed = compressAndSerialize(batch);

                    // 发送到 Kafka
                    kafkaProducer.send(new ProducerRecord<>(
                        "stress_metrics_batch",
                        compressed));

                    batch.clear();
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        }, "batch-metrics-reporter");
        reporter.setDaemon(true);
        reporter.start();
    }

    /**
     * 使用 Snappy 压缩序列化后的数据
     */
    private byte[] compressAndSerialize(List<MetricsMessage> batch) {
        byte[] serialized = JsonSerializer.serialize(batch);
        return Snappy.compress(serialized);
    }
}
```

```java
        }

        return rewritten;
    }

    /**

    public void invalidate() {
        cache.clear();
    }
```

## 6. 最佳实践与总结

### 6.1 压测执行规范

#### 6.1.1 压测前检查清单

```
□ 数据隔离验证
  ├── 影子库/表已创建且结构一致
  ├── 影子缓存配置已生效
  ├── 影子消息队列已配置
  └── 执行小流量验证，确认数据写入影子存储

□ 链路覆盖验证
  ├── 链路拓扑已分析，所有服务节点已纳入监控
  ├── 所有服务已部署压测探针
  └── 压力标识透传链路已验证

□ 监控告警阈值已配置
  ├── 熔断策略已设定
  └── 告警通知人已确认

□ 引擎资源准备
  ├── 压测引擎集群已就绪
  ├── 引擎节点资源充足（CPU/内存/网络）
  └── 引擎节点与目标服务网络连通性已验证

□ 业务方确认
  ├── 压测时间窗口已与相关团队沟通
  ├── 压测目标 QPS 与预期已对齐
  └── 应急预案已制定（含回滚方案）
```

#### 6.1.2 压测执行流程

```
1. 【准备阶段】
   ├── 创建压测任务，配置场景与参数
   ├── 执行小流量预热（目标 QPS 的 1%）
   ├── 验证数据隔离、指标采集、告警功能正常
   └── 确认各环节就绪

2. 【执行阶段】
   ├── 按计划的递增策略逐步加压
   ├── 每个阶梯保持至少 3 分钟，观察系统表现
   ├── 实时监控关键指标：QPS、RT、错误率、CPU、内存
   ├── 发现异常立即分析，必要时暂停或降压
   └── 达到目标 QPS 后保持 10-15 分钟，验证稳定性

3. 【收尾阶段】
   ├── 逐步降压（不要瞬间停止，避免连接池异常）
   ├── 清理影子数据
   ├── 生成压测报告
   └── 组织复盘会议，记录发现的问题与优化建议
```

### 6.2 容量规划方法论

#### 6.2.1 容量预测公式

```
目标容量 = 日常峰值 QPS × 业务增长系数 × 大促放大系数 × 安全冗余系数

示例：
  日常峰值 QPS：5000
  业务增长系数：1.5（预计半年增长 50%）
  大促放大系数：3.0（大促流量是日常的 3 倍）
  安全冗余系数：1.3（预留 30% 冗余）

  目标容量 = 5000 × 1.5 × 3.0 × 1.3 = 29250 QPS
```

#### 6.2.2 容量规划周期

```
┌─────────────────────────────────────────────┐
│             容量规划年度周期                    │
├────────────┬────────────────────────────────┤
│  Q1（1-3月） │ 年度容量基线评估，春节大促压测     │
│  Q2（4-6月） │ 618 大促容量规划与验证            │
│  Q3（7-9月） │ 中期容量评估，性能优化专项         │
│  Q4（10-12月）│ 双11 容量规划、压测、扩容、验证    │
└────────────┴────────────────────────────────┘

每次大促前至少进行 3 轮压测：
  第 1 轮：基线压测，摸清当前容量
  第 2 轮：优化后验证，确认优化效果
  第 3 轮：终极验证，确认达到目标容量
```

### 6.3 常见问题与解决方案

| 问题 | 现象 | 根因 | 解决方案 |
|------|------|------|----------|
| 压力打不上去 | 实际 QPS 远低于目标 | 引擎机器不足或单机瓶颈 | 增加引擎节点，优化并发参数 |
| RT 异常偏低 | 压测 RT 远低于线上真实值 | 缓存命中率过高，数据不够分散 | 增加数据多样性，降低缓存命中率 |
| 错误率突增 | 加压到一定程度错误率飙升 | 目标服务到达容量上限 | 记录当前 QPS 作为容量拐点 |
| 压力标识丢失 | 部分请求未被标记为压测流量 | 某些中间件未正确透传标识 | 排查透传链路，补充缺失的埋点 |
| 影子数据污染 | 压测数据写入了真实库 | 数据隔离配置遗漏 | 立即停止压测，清理脏数据，修复配置 |
| 监控数据缺失 | 部分服务节点无监控数据 | 探针未部署或网络不通 | 检查探针部署状态，验证网络连通性 |
| 引擎 OOM | 引擎进程频繁崩溃 | 请求队列积压，内存不足 | 限制队列大小，增大堆内存，减少并发 |
| 连接池耗尽 | 大量请求超时失败 | 目标服务连接数不足 | 增大目标服务连接池，优化慢查询 |

### 6.4 核心设计原则总结

#### 6.4.1 安全第一

生产环境全链路压测的第一原则是**绝对不能影响真实用户**。这意味着：

- 数据隔离必须是多层防护（存储层 + 应用层 + 监控层），任何一层失效都不会导致数据污染
- 熔断机制必须是自动化的，不能依赖人工判断和操作
- 压测任务必须有明确的超时机制，防止失控
- 所有压测操作必须有审计日志，可追溯可回滚

#### 6.4.2 精准度优先

压测的核心价值在于数据的准确性：

- 使用线上真实流量录制作为压测数据源，而非人工构造的假数据
- 混合流量模型要尽可能贴近真实的用户行为分布
- 监控指标要同时采集客户端和服务端数据，交叉验证
- 容量评估要考虑系统的非线性特征（随着负载增加，性能衰减是非线性的）

#### 6.4.3 自动化与可重复

- 压测场景应该可以一键执行，避免每次都需要大量人工配置
- 压测报告自动生成，与历史数据自动对比
- 容量基线自动更新，持续跟踪系统容量变化
- 将压测纳入 CI/CD 流程，在重大变更上线前自动执行回归压测

#### 6.4.4 架构要点回顾

```
全链路压测平台的关键架构决策：

1. 引擎架构：Master-Slave 模式
   - Master 负责调度与流量控制
   - Slave 负责实际的流量生成
   - 动态集群支持按需扩缩容

2. 流量构造：录制回放 + 参数化
   - TCP 抓包 / 字节码注入录制真实流量
   - 参数化模板支持链式场景
   - 响应提取实现步骤间数据传递

3. 数据隔离：三层防护
   - 压力标识贯穿全链路（ThreadLocal + RPC Header）
   - 存储层自动路由（影子库/表/缓存/队列）
   - 安全检查兜底拦截

4. 服务保护：自动熔断
   - 链路拓扑分析覆盖所有关联服务
   - 实时监控 + 规则引擎生成告警
   - 连续告警自动触发降压或停止

5. 监控体系：全维度覆盖
   - 客户端指标（引擎侧 QPS、RT、错误率）
   - 服务端指标（CPU、内存、线程、连接池）
   - 业务指标（成功率、业务异常码）
```

### 7.1 案例一：全链路压测执行全链路

本案例覆盖一次生产全链路压测从发起到收尾的完整流程：**压测准备 → 影子库/影子表配置 → 压测标识透传 → 流量录制回放 → 实时监控 → 压测报告**。整个流程由一个编排器 `FullLinkStressExecutor` 驱动，每个阶段都是一个可独立重试、可幂等的步骤。

#### 7.1.1 执行流程总览

```
│  ① 压测准备      ② 影子存储配置    ③ 标识透传验证                  │

│       ▼                ▼                 ▼                        │
│  ④ 流量录制回放  ⑤ 实时监控       ⑥ 压测报告                       │
│  replayTraffic   monitorRealtime  generateReport                 │
│                                                                    │
│  贯穿全程：幂等控制（executionId）+ 审计日志 + 异常熔断            │
```

#### 7.1.2 压测执行编排器

编排器以 `executionId` 作为全局幂等键。每个阶段执行前先查询阶段状态表，已完成的阶段直接跳过，保证整个流程可以在任意阶段失败后安全重入。

```java
/**
 * 全链路压测执行编排器
 *
 * 负责串联压测准备 -> 影子存储配置 -> 标识透传 -> 录制回放 -> 实时监控 -> 报告的完整链路。
 * 以 executionId 作为幂等键，任意阶段失败后可从断点安全重入。
 */
@Slf4j
public class FullLinkStressExecutor {

    private final ReadinessChecker readinessChecker;
    private final ShadowStorageProvisioner shadowProvisioner;
    private final TagPropagationVerifier tagVerifier;
    private final TrafficReplayer trafficReplayer;
    private final RealtimeMonitor realtimeMonitor;
    private final CapacityAssessmentReporter reporter;

    /** 阶段状态存储，用于幂等控制 */
    private final ExecutionStageRepository stageRepository;

    /** 已完成执行的结果缓存，防止重复提交同一 executionId 触发重复压测 */
    private final ConcurrentMap<String, StressExecutionResult> resultCache =
        new ConcurrentHashMap<>();

    /**
     * 执行一次完整的全链路压测。
     *
     * @param request 压测请求，request.getExecutionId() 由调用方生成并保证唯一，作为幂等键
     * @return 压测执行结果
     */
    public StressExecutionResult execute(StressExecutionRequest request) {
        String executionId = request.getExecutionId();
        if (executionId == null || executionId.isEmpty()) {
            throw new IllegalArgumentException("executionId 不能为空，需由调用方保证幂等");
        }

        // 幂等控制：同一 executionId 已经完成过，直接返回历史结果，不重复压测
        StressExecutionResult cached = resultCache.get(executionId);
        if (cached != null && cached.isTerminal()) {
            log.warn("[{}] 该执行已处于终态 {}，命中幂等缓存直接返回",
                executionId, cached.getStatus());
            return cached;
        }

        StressExecutionResult result = new StressExecutionResult(executionId);
        MDC.put("executionId", executionId);
        try {
            log.info("[{}] 全链路压测开始，任务={}, 目标QPS={}",
                executionId, request.getTaskId(), request.getTargetQps());

            // ① 压测准备
            runStage(executionId, StressStage.READINESS, result,
                () -> readinessChecker.check(request));

            // ② 影子库/影子表配置
            runStage(executionId, StressStage.SHADOW_PROVISION, result,
                () -> shadowProvisioner.provision(request));

            // ③ 压测标识透传验证
            runStage(executionId, StressStage.TAG_PROPAGATION, result,
                () -> tagVerifier.verify(request));

            // ④ 流量录制回放（正式加压）
            runStage(executionId, StressStage.TRAFFIC_REPLAY, result,
                () -> trafficReplayer.replay(request));

            // ⑤ 实时监控（与④并行启动，此处等待监控收尾并返回聚合数据）
            runStage(executionId, StressStage.MONITOR, result,
                () -> realtimeMonitor.collect(request.getTaskId()));

            // ⑥ 压测报告
            runStage(executionId, StressStage.REPORT, result, () -> {
                List<AggregatedMetrics> history =
                    realtimeMonitor.getMetricsHistory(request.getTaskId());
                CapacityReport report =
                    reporter.generateReport(request.getTaskId(), history);
                result.setCapacityReport(report);
                return report;
            });

            result.markSuccess();
            log.info("[{}] 全链路压测成功完成，最大安全容量={} QPS",
                executionId,
                result.getCapacityReport() != null
                    ? result.getCapacityReport().getMaxSafeQps() : -1);
        } catch (StressAbortException e) {
            // 主动熔断/中止：属于预期内的保护性中断，记录后进入 ABORTED 终态
            result.markAborted(e.getMessage());
            log.error("[{}] 压测被中止，原因: {}", executionId, e.getMessage(), e);
        } catch (Exception e) {
            result.markFailed(e.getMessage());
            log.error("[{}] 压测执行异常", executionId, e);
        } finally {
            // 无论成功失败，都执行收尾清理（降压、清数据由对应步骤内部保证幂等）
            safeCleanup(executionId, request);
            resultCache.put(executionId, result);
            MDC.remove("executionId");
        }
        return result;
    }

    /**
     * 执行单个阶段，内置幂等跳过与阶段级异常包装。
     */
    private <T> void runStage(String executionId, StressStage stage,
                              StressExecutionResult result,
                              StageAction<T> action) {
        // 幂等控制：阶段已完成则跳过，实现断点重入
        if (stageRepository.isCompleted(executionId, stage)) {
            log.info("[{}] 阶段 {} 已完成，跳过", executionId, stage);
            result.recordStage(stage, StageStatus.SKIPPED);
            return;
        }

        long start = System.currentTimeMillis();
        try {
            log.info("[{}] 阶段 {} 开始执行", executionId, stage);
            T stageResult = action.run();
            stageRepository.markCompleted(executionId, stage);
            result.recordStage(stage, StageStatus.SUCCESS);
            log.info("[{}] 阶段 {} 执行成功，耗时 {} ms",
                executionId, stage, System.currentTimeMillis() - start);
        } catch (StressAbortException e) {
            // 保护性中止直接向上抛出，交由 execute 统一处理
            result.recordStage(stage, StageStatus.ABORTED);
            throw e;
        } catch (Exception e) {
            result.recordStage(stage, StageStatus.FAILED);
            log.error("[{}] 阶段 {} 执行失败，耗时 {} ms",
                executionId, stage, System.currentTimeMillis() - start, e);
            throw new StressStageException(stage, "阶段执行失败: " + stage, e);
        }
    }

    /**
     * 收尾清理，任何异常都不再向上抛出，避免掩盖主流程结果。
     */
    private void safeCleanup(String executionId, StressExecutionRequest request) {
        try {
            trafficReplayer.rampDown(request.getTaskId());
            log.info("[{}] 已完成流量降压收尾", executionId);
        } catch (Exception e) {
            log.error("[{}] 收尾降压失败，需人工确认引擎状态", executionId, e);
        }
    }

    @FunctionalInterface
    private interface StageAction<T> {
        T run() throws Exception;
    }
}
```

#### 7.1.3 压测准备与就绪检查

压测准备阶段对照第 6.1.1 节的检查清单做程序化校验。任何一项硬性检查未通过都会以 `StressAbortException` 主动中止，防止在未就绪的状态下加压污染线上数据。

```java
/**
 * 压测就绪检查器——对照检查清单做程序化校验。
 */
@Slf4j
public class ReadinessChecker {

    private final ShadowStorageValidator shadowValidator;
    private final ProbeRegistry probeRegistry;
    private final EngineClusterManager engineClusterManager;

    /**
     * 执行就绪检查，返回检查明细；存在硬性阻断项时抛出 StressAbortException。
     */
    public ReadinessResult check(StressExecutionRequest request) {
        ReadinessResult result = new ReadinessResult();
        List<String> blockers = new ArrayList<>();

        // 1. 数据隔离验证：小流量试探，确认写入影子存储
        try {
            boolean isolated = shadowValidator.verifySmallTraffic(request.getTaskId());
            result.addCheck("数据隔离", isolated);
            if (!isolated) {
                blockers.add("数据隔离验证未通过：小流量写入落到了真实存储");
            }
        } catch (Exception e) {
            log.error("数据隔离验证异常，任务={}", request.getTaskId(), e);
            blockers.add("数据隔离验证异常: " + e.getMessage());
        }

        // 2. 链路探针覆盖：所有链路节点都必须部署探针
        List<String> topologyNodes = request.getTopologyNodes();
        List<String> missingProbes = topologyNodes.stream()
            .filter(node -> !probeRegistry.isProbeActive(node))
            .collect(Collectors.toList());
        result.addCheck("探针覆盖", missingProbes.isEmpty());
        if (!missingProbes.isEmpty()) {
            blockers.add("以下节点未部署或探针离线: " + missingProbes);
        }

        // 3. 引擎资源：可用 Slave 节点数需满足目标 QPS 的发压需求
        int availableSlaves = engineClusterManager.countAvailableSlaves();
        int requiredSlaves = estimateRequiredSlaves(request.getTargetQps());
        result.addCheck("引擎资源", availableSlaves >= requiredSlaves);
        if (availableSlaves < requiredSlaves) {
            blockers.add(String.format("引擎节点不足，需要 %d 台，当前可用 %d 台",
                requiredSlaves, availableSlaves));
        }

        if (!blockers.isEmpty()) {
            // 硬性阻断项存在，主动中止后续所有阶段
            String reason = "就绪检查未通过: " + String.join("; ", blockers);
            log.error("任务 {} {}", request.getTaskId(), reason);
            throw new StressAbortException(reason);
        }

        log.info("任务 {} 就绪检查全部通过", request.getTaskId());
        return result;
    }

    /**
     * 按单机发压能力（经验值 2000 QPS/台）估算所需 Slave 数量，向上取整并预留 1 台冗余。
     */
    private int estimateRequiredSlaves(int targetQps) {
        int perSlaveQps = 2000;
        return (int) Math.ceil((double) targetQps / perSlaveQps) + 1;
    }
}
```

#### 7.1.4 影子存储配置

影子存储配置负责在正式加压前把影子库/影子表准备就绪。该步骤天然要求幂等——重复执行不能重复建表，因此每张影子表创建前先探测其是否已存在。

```java
/**
 * 影子存储准备器——创建并校验影子库/影子表。
 */
@Slf4j
public class ShadowStorageProvisioner {

    private final ShadowSchemaManager schemaManager;

    /**
     * 准备影子存储。对每张业务表创建对应影子表，创建操作幂等。
     */
    public ShadowProvisionResult provision(StressExecutionRequest request) {
        ShadowProvisionResult result = new ShadowProvisionResult();
        for (String table : request.getBusinessTables()) {
            String shadowTable = "_shadow_" + table;
            try {
                // 幂等控制：已存在则只做结构一致性校验，不重复建表
                if (schemaManager.exists(shadowTable)) {
                    boolean consistent =
                        schemaManager.isSchemaConsistent(table, shadowTable);
                    if (!consistent) {
                        // 结构漂移：删除重建，保证影子表与真实表结构一致
                        log.warn("影子表 {} 结构与 {} 不一致，将重建", shadowTable, table);
                        schemaManager.drop(shadowTable);
                        schemaManager.createLike(table, shadowTable);
                    }
                    result.markReused(shadowTable);
                    log.info("影子表 {} 已存在且结构一致，复用", shadowTable);
                } else {
                    schemaManager.createLike(table, shadowTable);
                    result.markCreated(shadowTable);
                    log.info("影子表 {} 创建成功", shadowTable);
                }
            } catch (Exception e) {
                log.error("影子表 {} 准备失败", shadowTable, e);
                throw new StressStageException(StressStage.SHADOW_PROVISION,
                    "影子表准备失败: " + shadowTable, e);
            }
        }
        log.info("影子存储准备完成，新建 {} 张，复用 {} 张",
            result.getCreatedCount(), result.getReusedCount());
        return result;
    }
}
```

#### 7.1.5 标识透传验证

透传验证发送一个带压测标识的探测请求，走完整链路后从每个节点的探针回捞标识命中记录，确认没有任何节点丢失标识。这一步是防止影子数据污染的最后一道预防线。

```java
/**
 * 压测标识透传验证器——发送探测请求，校验全链路节点均识别到压力标识。
 */
@Slf4j
public class TagPropagationVerifier {

    private final ProbeTraceQuery probeTraceQuery;
    private final ProbeRequestSender probeRequestSender;

    /**
     * 发送一条带压测标识的探测请求，校验全链路透传情况。
     */
    public TagPropagationResult verify(StressExecutionRequest request) {
        // 生成唯一 traceId，便于从各节点探针回捞该请求的透传记录
        String traceId = "stress-verify-" + UUID.randomUUID();
        StressContext.markStress(traceId);
        try {
            log.info("发送标识透传探测请求，traceId={}", traceId);
            probeRequestSender.sendProbe(request.getEntryApi(), traceId);

            // 从链路追踪回捞每个节点是否识别到压力标识
            List<NodeTagRecord> records =
                probeTraceQuery.queryByTraceId(traceId, request.getTopologyNodes());

            List<String> lostNodes = records.stream()
                .filter(r -> !r.isStressTagRecognized())
                .map(NodeTagRecord::getNodeName)
                .collect(Collectors.toList());

            if (!lostNodes.isEmpty()) {
                // 存在丢标节点，若继续压测将导致影子数据污染，主动中止
                String reason = "压力标识在以下节点丢失: " + lostNodes;
                log.error("traceId={} {}", traceId, reason);
                throw new StressAbortException(reason);
            }

            log.info("traceId={} 标识透传验证通过，覆盖 {} 个节点",
                traceId, records.size());
            return new TagPropagationResult(records);
        } finally {
            // 清理线程上下文，避免污染后续请求
            StressContext.clear();
        }
    }
}
```

#### 7.1.6 流量录制回放与实时监控

正式加压阶段复用第 3.3 节的录制回放能力，同时并行启动第 3.7 节的实时监控。回放器按阶梯递增策略加压，每个阶梯采样一次监控指标，一旦监控判定触发熔断即抛出 `StressAbortException` 中止加压。

```java
/**
 * 流量回放器——按阶梯策略加压，并在每个阶梯联动实时监控做熔断判定。
 */
@Slf4j
public class TrafficReplayer {

    private final EngineMaster engineMaster;
    private final RealtimeMonitor realtimeMonitor;

    /** 每个阶梯保持时长 */
    private static final long STEP_HOLD_MILLIS = 3 * 60 * 1000L;

    /**
     * 执行阶梯递增回放。
     */
    public ReplayResult replay(StressExecutionRequest request) {
        Long taskId = request.getTaskId();
        int targetQps = request.getTargetQps();
        int stepQps = Math.max(targetQps / 5, 1); // 5 个阶梯递增
        ReplayResult result = new ReplayResult();

        try {
            realtimeMonitor.start(taskId);
            for (int currentQps = stepQps; currentQps <= targetQps;
                 currentQps += stepQps) {
                engineMaster.adjustQps(taskId, currentQps);
                log.info("任务 {} 加压至 {} QPS，保持 {} 秒观察",
                    taskId, currentQps, STEP_HOLD_MILLIS / 1000);

                boolean stable = holdAndObserve(taskId, currentQps);
                if (!stable) {
                    // 监控判定系统已到达容量拐点，主动中止加压并记录拐点
                    result.setInflectionQps(currentQps);
                    throw new StressAbortException(
                        "任务 " + taskId + " 在 " + currentQps + " QPS 触发熔断");
                }
                result.recordStep(currentQps);
            }
            log.info("任务 {} 已加压至目标 {} QPS 且保持稳定", taskId, targetQps);
            return result;
        } catch (StressAbortException e) {
            throw e;
        } catch (Exception e) {
            log.error("任务 {} 流量回放异常", taskId, e);
            throw new StressStageException(StressStage.TRAFFIC_REPLAY,
                "流量回放失败", e);
        }
    }

    /**
     * 保持当前阶梯并周期性采样监控指标，返回系统是否稳定。
     */
    private boolean holdAndObserve(Long taskId, int currentQps)
            throws InterruptedException {
        long deadline = System.currentTimeMillis() + STEP_HOLD_MILLIS;
        while (System.currentTimeMillis() < deadline) {
            AggregatedMetrics metrics = realtimeMonitor.snapshot(taskId);
            // 错误率超 1% 或 P99 超 SLA（此处示例 1s）视为不稳定
            if (metrics.getErrorRate() > 0.01 || metrics.getP99Rt() > 1000) {
                log.warn("任务 {} @ {} QPS 指标异常: 错误率={}, P99={}ms",
                    taskId, currentQps, metrics.getErrorRate(), metrics.getP99Rt());
                return false;
            }
            Thread.sleep(5000); // 每 5 秒采样一次
        }
        return true;
    }

    /**
     * 逐步降压收尾，避免瞬时停止导致连接池异常。
     */
    public void rampDown(Long taskId) {
        try {
            int current = engineMaster.getCurrentQps(taskId);
            while (current > 0) {
                current = Math.max(current / 2, 0);
                engineMaster.adjustQps(taskId, current);
                log.info("任务 {} 降压至 {} QPS", taskId, current);
                Thread.sleep(2000);
            }
            engineMaster.stopTask(taskId);
            realtimeMonitor.stop(taskId);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            log.warn("任务 {} 降压被中断", taskId);
        } catch (Exception e) {
            log.error("任务 {} 降压收尾失败", taskId, e);
        }
    }
}
```

至此，案例一形成了闭环：编排器保证幂等与断点重入，各阶段各司其职，异常统一分类为"保护性中止（StressAbortException）"和"阶段失败（StressStageException）"，收尾降压与报告生成在 `finally` 中确保执行。

### 7.2 案例二：容量评估与水位计算全链路

本案例聚焦"用数据说话"的容量规划：**历史数据分析 → 峰值模型 → 资源需求计算 → 弹性扩容决策 → 容量验证**。它承接案例一产出的压测容量基线，结合线上历史流量，推导出面向未来大促的扩容方案。

#### 7.2.1 计算流程总览

```
历史流量样本 ──► PeakModelBuilder ──► 峰值模型(均值/P99/尖峰系数)
                                          │
                                          ▼
                              ResourceDemandCalculator
                              (目标QPS ÷ 单实例容量)
                                          │
                                          ▼
                              ElasticScalingDecider
                              (对比当前实例数 → 扩容/缩容建议)
                                          │
                                          ▼

```

#### 7.2.2 历史数据分析与峰值模型

```java
/**
 * 峰值模型构建器——从历史流量样本推导峰值特征。
 */
@Slf4j
public class PeakModelBuilder {

    private final TrafficHistoryRepository historyRepository;

    /**
     * 基于最近 N 天的分钟级流量样本构建峰值模型。
     *
     * @param serviceName 服务名
     * @param days        回溯天数
     */
    public PeakModel build(String serviceName, int days) {
        if (days <= 0) {
            throw new IllegalArgumentException("回溯天数必须为正数");
        }
        List<TrafficSample> samples =
            historyRepository.loadRecentSamples(serviceName, days);
        if (samples == null || samples.isEmpty()) {
            throw new CapacityDataException("服务 " + serviceName + " 无历史流量样本");
        }

        // 剔除异常样本（如故障期间的塌陷或异常尖刺）
        List<TrafficSample> cleaned = removeOutliers(samples);
        log.info("服务 {} 加载样本 {} 条，清洗后剩余 {} 条",
            serviceName, samples.size(), cleaned.size());

        double[] qpsArray = cleaned.stream()
            .mapToDouble(TrafficSample::getQps).sorted().toArray();

        double mean = Arrays.stream(qpsArray).average().orElse(0);
        double p99 = percentile(qpsArray, 0.99);
        double dailyPeak = qpsArray[qpsArray.length - 1];
        // 尖峰系数：日峰值相对均值的放大倍数，反映流量突发程度
        double spikeFactor = mean > 0 ? dailyPeak / mean : 1.0;

        PeakModel model = new PeakModel();
        model.setServiceName(serviceName);
        model.setMeanQps(mean);
        model.setP99Qps(p99);
        model.setDailyPeakQps(dailyPeak);
        model.setSpikeFactor(spikeFactor);
        log.info("服务 {} 峰值模型: 均值={}, P99={}, 日峰值={}, 尖峰系数={}",
            serviceName, mean, p99, dailyPeak, spikeFactor);
        return model;
    }

    /**
     * 基于 3 倍标准差剔除离群点。
     */
    private List<TrafficSample> removeOutliers(List<TrafficSample> samples) {
        double mean = samples.stream()
            .mapToDouble(TrafficSample::getQps).average().orElse(0);
        double std = Math.sqrt(samples.stream()
            .mapToDouble(s -> Math.pow(s.getQps() - mean, 2))
            .average().orElse(0));
        double upper = mean + 3 * std;
        double lower = Math.max(mean - 3 * std, 0);
        return samples.stream()
            .filter(s -> s.getQps() >= lower && s.getQps() <= upper)
            .collect(Collectors.toList());
    }

    private double percentile(double[] sorted, double p) {
        if (sorted.length == 0) return 0;
        int idx = (int) Math.ceil(p * sorted.length) - 1;
        return sorted[Math.max(0, Math.min(idx, sorted.length - 1))];
    }
}
```

#### 7.2.3 资源需求计算与弹性扩容决策

资源需求计算把"目标容量"折算为"需要多少实例"。目标容量沿用第 6.2.1 节的预测公式，单实例容量取自案例一的压测基线（最大安全 QPS）。扩容决策器对比当前实例数给出增减建议，并对结果做幂等落库。

```java
/**
 * 资源需求计算与弹性扩容决策器。
 */
@Slf4j
public class ElasticScalingDecider {

    private final CapacityBaselineRepository baselineRepository;
    private final InstanceInventory instanceInventory;
    private final ScalingPlanRepository planRepository;

    /**
     * 根据峰值模型和容量基线，计算资源需求并给出扩容决策。
     *
     * @param model     峰值模型
     * @param growth    业务增长系数
     * @param promoAmp  大促放大系数
     * @param safetyRedundancy 安全冗余系数
     * @param planId    计划幂等键，同一 planId 重复计算返回既有计划
     */
    public ScalingPlan decide(PeakModel model, double growth, double promoAmp,
                              double safetyRedundancy, String planId) {
        // 幂等控制：同一 planId 已生成过计划则直接复用，避免重复触发扩容工单
        ScalingPlan existing = planRepository.findByPlanId(planId);
        if (existing != null) {
            log.warn("计划 {} 已存在，命中幂等直接返回", planId);
            return existing;
        }

        // 目标容量 = 日常峰值 × 增长 × 大促放大 × 安全冗余
        double targetQps = model.getDailyPeakQps()
            * growth * promoAmp * safetyRedundancy;

        CapacityBaseline baseline =
            baselineRepository.findLatest(model.getServiceName());
        if (baseline == null || baseline.getMaxSafeQpsPerInstance() <= 0) {
            throw new CapacityDataException(
                "服务 " + model.getServiceName() + " 缺少有效的单实例容量基线");
        }

        double perInstance = baseline.getMaxSafeQpsPerInstance();
        int requiredInstances = (int) Math.ceil(targetQps / perInstance);
        int currentInstances =
            instanceInventory.countRunning(model.getServiceName());
        int delta = requiredInstances - currentInstances;

        ScalingPlan plan = new ScalingPlan();
        plan.setPlanId(planId);
        plan.setServiceName(model.getServiceName());
        plan.setTargetQps(targetQps);
        plan.setRequiredInstances(requiredInstances);
        plan.setCurrentInstances(currentInstances);
        plan.setDelta(delta);
        if (delta > 0) {
            plan.setAction(ScalingAction.SCALE_OUT);
            log.info("服务 {} 需扩容 {} 实例（{} -> {}），目标 {} QPS",
                model.getServiceName(), delta, currentInstances,
                requiredInstances, targetQps);
        } else if (delta < 0) {
            plan.setAction(ScalingAction.SCALE_IN);
            log.info("服务 {} 可缩容 {} 实例（{} -> {}）",
                model.getServiceName(), -delta, currentInstances, requiredInstances);
        } else {
            plan.setAction(ScalingAction.NO_CHANGE);
            log.info("服务 {} 当前 {} 实例已满足目标，无需调整",
                model.getServiceName(), currentInstances);
        }

        // 幂等落库：唯一约束在 planId 上，捕获并发重复写入
        try {
            planRepository.save(plan);
        } catch (DuplicateKeyException e) {
            log.warn("计划 {} 并发写入冲突，回读既有计划", planId);
            return planRepository.findByPlanId(planId);
        }
        return plan;
    }
}
```

#### 7.2.4 容量验证

扩容执行后必须复压验证，确认新的实例规模确实能承载目标容量，形成"评估 → 扩容 → 验证"的闭环。验证不通过则回滚扩容或告警人工介入。

```java
/**
 * 容量验证器——扩容后复压，验证是否达到目标容量。
 */
@Slf4j
public class CapacityValidator {

    private final FullLinkStressExecutor stressExecutor;
    private final InstanceInventory instanceInventory;

    /**
     * 对扩容后的服务发起验证性压测。
     */
    public ValidationResult validate(ScalingPlan plan) {
        String executionId = "capacity-validate-" + plan.getPlanId();
        // 校验扩容是否已生效
        int running = instanceInventory.countRunning(plan.getServiceName());
        if (running < plan.getRequiredInstances()) {
            String msg = String.format("扩容未完成，期望 %d 实例，当前 %d，暂缓验证",
                plan.getRequiredInstances(), running);
            log.warn("计划 {} {}", plan.getPlanId(), msg);
            return ValidationResult.pending(msg);
        }

        StressExecutionRequest req = StressExecutionRequest.builder()
            .executionId(executionId)
            .targetQps((int) Math.ceil(plan.getTargetQps()))
            .build();
        StressExecutionResult result = stressExecutor.execute(req);

        if (result.isSuccess() && result.getCapacityReport() != null
            && result.getCapacityReport().getMaxSafeQps() >= plan.getTargetQps()) {
            log.info("计划 {} 容量验证通过，实测安全容量 {} QPS >= 目标 {} QPS",
                plan.getPlanId(), result.getCapacityReport().getMaxSafeQps(),
                plan.getTargetQps());
            return ValidationResult.pass();
        }

        log.error("计划 {} 容量验证未达标，需复查瓶颈或追加扩容", plan.getPlanId());
        return ValidationResult.fail("实测容量未达到目标");
    }
}
```

案例二说明：容量规划不是一次性的静态计算，而是"历史数据 → 模型 → 决策 → 验证"的持续闭环。压测基线是折算实例数的关键输入，验证环节则保证决策真正落地生效。

### 7.3 案例三：压测数据隔离全链路

数据隔离是生产全链路压测的生命线。本案例把散落在第 3.4、3.5 节的隔离能力串成一条端到端链路：**压测标识注入 → 中间件识别 → 影子数据路由 → 压测数据清理**，并给出每一环的幂等与异常兜底。

#### 7.3.1 隔离链路总览

```
入口注入标识 ──► ThreadLocal/RPC Header ──► 中间件识别 isStressRequest()
                                                    │
                             ┌──────────────────────┼──────────────────────┐
                             ▼                       ▼                      ▼
                        影子库/表路由           影子缓存路由           影子队列路由
                             │                       │                      │
                             └──────────────────────┬──────────────────────┘
                                                    ▼
                                         压测结束后影子数据清理
```

#### 7.3.2 压测标识注入

入口过滤器识别压测请求并注入标识。为防止外部伪造压测流量绕过隔离，标识需携带签名校验；只有校验通过才建立压测上下文。

```java
/**
 * 压测标识注入过滤器——在请求入口识别并建立压测上下文。
 */
@Slf4j
public class StressTagInjectFilter implements Filter {

    private static final String STRESS_HEADER = "X-Stress-Tag";
    private static final String STRESS_SIGN_HEADER = "X-Stress-Sign";

    private final StressTagSigner signer;

    @Override
    public void doFilter(ServletRequest request, ServletResponse response,
                         FilterChain chain) throws IOException, ServletException {
        HttpServletRequest httpReq = (HttpServletRequest) request;
        String tag = httpReq.getHeader(STRESS_HEADER);
        boolean marked = false;
        try {
            if (tag != null && !tag.isEmpty()) {
                String sign = httpReq.getHeader(STRESS_SIGN_HEADER);
                // 校验签名，防止伪造压测流量污染影子链路
                if (!signer.verify(tag, sign)) {
                    log.error("压测标识签名校验失败，拒绝请求，tag={}", tag);
                    ((HttpServletResponse) response)
                        .sendError(HttpServletResponse.SC_FORBIDDEN,
                            "invalid stress signature");
                    return;
                }
                StressContext.markStress(tag);
                marked = true;
                MDC.put("stressTag", tag);
                log.info("识别到压测请求，tag={}, uri={}", tag, httpReq.getRequestURI());
            }
            chain.doFilter(request, response);
        } finally {
            // 无论如何都清理上下文，避免线程复用导致标识泄漏到正常请求
            if (marked) {
                StressContext.clear();
                MDC.remove("stressTag");
            }
        }
    }
}
```

#### 7.3.3 中间件识别与影子数据路由

统一的路由分发器封装库、缓存、消息三类存储的路由决策。业务代码只需调用该分发器，无需感知隔离细节。路由失败时按"宁可拒绝、不可污染"原则处理——若压测请求无法确定影子目标，直接抛异常而非降级到真实存储。

```java
/**
 * 影子数据路由分发器——统一封装库/缓存/队列的隔离路由。
 */
@Slf4j
public class ShadowRouteDispatcher {

    private final ShadowDatabaseRouter dbRouter;
    private final ShadowCacheRouter cacheRouter;
    private final ShadowMessageQueueRouter mqRouter;

    /**
     * 路由数据库访问。压测请求下若无法解析影子目标，抛异常而非落真实库。
     */
    public DataSource routeDataSource() {
        if (!StressContext.isStressRequest()) {
            return dbRouter.determineDataSource();
        }
        try {
            DataSource ds = dbRouter.determineDataSource();
            if (ds == null) {
                throw new ShadowRouteException("压测请求未能解析到影子数据源");
            }
            return ds;
        } catch (ShadowRouteException e) {
            // 安全兜底：宁可让压测请求失败，也不能落到真实库
            log.error("影子库路由失败，拦截该压测请求以保护真实数据", e);
            throw e;
        }
    }

    /**
     * 路由缓存读取。
     */
    public String cacheGet(String key) {
        try {
            return cacheRouter.get(key);
        } catch (Exception e) {
            log.error("影子缓存读取异常，key={}, isStress={}",
                key, StressContext.isStressRequest(), e);
            throw new ShadowRouteException("缓存路由失败: " + key, e);
        }
    }

    /**
     * 路由消息发送。
     */
    public void mqSend(String topic, String message) {
        try {
            mqRouter.send(topic, message);
        } catch (Exception e) {
            log.error("影子队列发送异常，topic={}, isStress={}",
                topic, StressContext.isStressRequest(), e);
            throw new ShadowRouteException("消息路由失败: " + topic, e);
        }
    }
}
```

#### 7.3.4 压测数据清理

压测结束后清理影子存储中的数据，回收资源并避免影子数据长期堆积。清理以 `cleanupId` 幂等，分批删除避免大事务，任一存储清理失败不影响其它存储继续清理，并记录残留供人工核查。

```java
/**
 * 压测数据清理器——清理影子库/表、影子缓存、影子队列中的压测数据。
 */
@Slf4j
public class ShadowDataCleaner {

    private final ShadowSchemaManager schemaManager;
    private final RedisClient shadowCacheClient;
    private final ShadowMessageQueueRouter mqRouter;
    private final CleanupRecordRepository cleanupRepository;

    /** 单批删除行数，避免大事务锁表 */
    private static final int BATCH_SIZE = 1000;

    /**
     * 清理指定压测任务的影子数据。
     *
     * @param cleanupId 幂等键，重复调用不会重复清理
     */
    public CleanupResult clean(String cleanupId, StressCleanupRequest request) {
        // 幂等控制：已清理完成则直接返回历史结果
        CleanupRecord done = cleanupRepository.findCompleted(cleanupId);
        if (done != null) {
            log.warn("清理 {} 已完成，命中幂等直接返回", cleanupId);
            return done.toResult();
        }

        CleanupResult result = new CleanupResult(cleanupId);
        MDC.put("cleanupId", cleanupId);
        try {
            // 1. 清理影子表数据（分批删除）
            for (String table : request.getBusinessTables()) {
                String shadowTable = "_shadow_" + table;
                try {
                    long deleted = deleteInBatches(shadowTable);
                    result.addTableDeleted(shadowTable, deleted);
                    log.info("影子表 {} 清理完成，删除 {} 行", shadowTable, deleted);
                } catch (Exception e) {
                    // 单表失败不阻断其它表清理，记录残留供人工核查
                    result.addResidual(shadowTable);
                    log.error("影子表 {} 清理失败，标记残留", shadowTable, e);
                }
            }

            // 2. 清理影子缓存（按前缀扫描删除）
            try {
                long cacheDeleted =
                    shadowCacheClient.deleteByPrefix("_shadow_:");
                result.setCacheDeleted(cacheDeleted);
                log.info("影子缓存清理完成，删除 {} 个 key", cacheDeleted);
            } catch (Exception e) {
                result.addResidual("shadow-cache");
                log.error("影子缓存清理失败，标记残留", e);
            }

            // 3. 清理影子队列积压消息
            try {
                for (String topic : request.getShadowTopics()) {
                    mqRouter.purgeShadowTopic(topic);
                    log.info("影子队列 {} 已清空", topic);
                }
            } catch (Exception e) {
                result.addResidual("shadow-mq");
                log.error("影子队列清理失败，标记残留", e);
            }

            // 仅当全部清理无残留时才标记为完成，保证幂等语义正确
            if (result.getResiduals().isEmpty()) {
                cleanupRepository.markCompleted(cleanupId, result);
                log.info("清理 {} 全部完成", cleanupId);
            } else {
                log.warn("清理 {} 存在残留 {}，未标记完成，等待重试",
                    cleanupId, result.getResiduals());
            }
            return result;
        } finally {
            MDC.remove("cleanupId");
        }
    }

    /**
     * 分批删除影子表数据，避免单次大事务。
     */
    private long deleteInBatches(String shadowTable) {
        long total = 0;
        int affected;
        do {
            affected = schemaManager.deleteLimit(shadowTable, BATCH_SIZE);
            total += affected;
            if (affected > 0) {
                log.debug("影子表 {} 本批删除 {} 行，累计 {} 行",
                    shadowTable, affected, total);
            }
        } while (affected == BATCH_SIZE);
        return total;
    }
}
```

案例三的核心原则是"隔离失效即中断"：从入口的签名校验，到中间件的"路由不到影子目标即抛异常"，再到清理阶段"有残留就不标记完成"，每一环都遵循"宁可让压测失败，也绝不污染真实数据"的安全底线。

### 7.4 三个案例的关系

三个实战案例并非孤立，而是一次完整容量保障工作的三个侧面：

```
案例三（数据隔离）── 是案例一压测能安全执行的前提
        │
        ▼
案例一（压测执行）── 产出单实例/系统容量基线
        │
        ▼
案例二（容量评估）── 消费基线，推导扩容方案并复压验证
```

- **案例三是地基**：没有可靠的数据隔离，生产全链路压测无从谈起。
- **案例一是引擎**：把隔离能力、录制回放、实时监控串成可执行、可重入的压测流程，产出容量基线。
- **案例二是目标**：将压测基线转化为面向未来的资源规划，并通过复压验证形成闭环。

三者共同遵循本文档反复强调的三大原则——安全第一、精准度优先、自动化与可重复。所有代码都以显式的幂等键（executionId / planId / cleanupId）、分层的异常处理（保护性中止 vs 阶段失败 vs 路由拒绝）和贯穿全程的结构化日志（MDC 上下文）为骨架，确保在生产环境中可观测、可追溯、可回滚。
