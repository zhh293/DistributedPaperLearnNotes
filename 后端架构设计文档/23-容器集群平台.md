# 容器集群平台技术架构设计

## 1. 问题背景

### 1.1 基础设施演进历程

大规模互联网企业的基础设施部署形态经历了三个标志性阶段的演进，每一次跃迁都是对前一阶段核心瓶颈的系统性解决：

**第一阶段：传统虚拟化时代（~2013）**

服务直接运行在物理服务器或通过 Hypervisor（KVM/Xen）切分的虚拟机上。每台虚拟机包含完整的 Guest OS，资源利用率仅 10%~15%，采购上架周期长达数周。运维团队通过手工脚本或 Puppet/Ansible 管理配置，但随着服务规模增长到数千台虚拟机，配置漂移、环境不一致、交付周期长成为核心瓶颈。

典型问题：
- 资源利用率极低，大量 CPU 和内存空闲
- 虚拟机启动慢（分钟级），扩缩容响应不及时
- 环境不一致导致"在我机器上能跑"成为常态
- 资源申请流程冗长，通常需要 3~5 个工作日

**第二阶段：容器化初期（~2015）**

引入 Docker 容器技术，基于 Linux Namespace 和 Cgroup 实现进程级隔离。通过 Dockerfile 标准化构建镜像，实现"Build once, run anywhere"。第一代容器编排平台通常基于自研调度系统或 Docker Swarm 构建，解决了环境一致性和快速交付的问题。

但第一代平台也暴露出显著局限：
- 自研调度器缺乏社区生态支持，功能迭代完全依赖内部团队
- 与开源工具链（Prometheus、Istio、Helm 等）兼容性差
- 调度算法简单，缺乏拓扑感知、亲和性、抢占等高级能力
- 滚动更新、灰度发布等部署策略需要自行实现
- 存储编排能力薄弱，有状态应用支撑困难

**第三阶段：Kubernetes 原生化（~2018）**

全面转向 Kubernetes 作为底层编排引擎，但不是简单替换，而是在 K8s 之上构建企业级容器管理平台。通过三层 API 抽象（业务 API → 平台 API → Kubernetes API），在享受 K8s 社区红利的同时，对外屏蔽底层复杂性。

这次架构升级带来了质的飞跃：
- 社区标准 API，与 CNCF 生态无缝集成
- 声明式管理，自愈能力内建
- 丰富的调度策略，支持大规模异构资源调度
- 完善的扩展机制（CRD/Operator/Webhook），可按需定制

### 1.2 大规模容器管理的挑战

当容器数量从几十增长到十万级以上时，核心挑战呈指数级增长：

| 挑战维度 | 具体问题 | 规模量级 |
|---------|---------|---------|
| 调度效率 | 数十万容器如何在数万节点上高效分配，满足多维资源约束和拓扑亲和性 | 10万+实例/万级节点 |
| 网络管理 | 跨主机容器通信、网络策略执行、Service负载均衡 | 百万级Pod IP |
| 存储编排 | 有状态应用数据持久化，容器迁移后数据不丢失 | PB级存储 |
| 弹性伸缩 | 根据负载自动扩缩容，缩容时保证服务不中断 | 秒级响应 |
| 容错自愈 | 节点宕机自动感知和容器迁移，灰度发布和回滚 | 99.99%可用性 |
| 资源效率 | 在保证SLA的前提下最大化利用率，降低基础设施成本 | 数亿元/年成本 |
| 多集群管理 | 多地域、多机房的集群统一管控 | 数十集群 |
| 安全隔离 | 多租户资源隔离、网络隔离、运行时安全 | 数百业务线 |

### 1.3 容器编排平台的价值定位

容器集群平台不仅仅是 Kubernetes 的简单封装，而是一个面向业务的基础设施管理平台。其核心价值体现在四个层面：

**对业务研发**：提供标准化的应用发布、扩缩容、灰度发布能力，屏蔽底层基础设施差异。

**对 SRE 运维**：提供统一的集群管理、监控告警、日常巡检、故障自愈能力，降低运维复杂度。

**对资源管理**：通过智能调度、资源画像、混部等手段，在保证 SLA 的前提下最大化资源利用率。

**对平台架构**：提供标准化的扩展机制，让各基础设施组件（Service Mesh、Serverless、CI/CD）以插件方式接入。

### 1.4 不解决的后果

- **交付效率低下**：环境不一致导致部署失败率高，线上问题难以在测试环境复现
- **资源严重浪费**：静态资源分配模式下，平均利用率不足 20%，年浪费数亿基础设施成本
- **运维负担沉重**：数万节点依赖人工巡检，故障发现和恢复时间长
- **扩展能力受限**：无法快速响应业务峰值流量，导致核心大促场景容量不足
- **技术债务累积**：自研组件与社区脱节，维护成本持续增长

## 2. 整体架构设计

### 2.1 三层 API 架构

容器集群平台采用三层 API 分层设计，这是平台架构的核心理念：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        外部用户 / CI-CD / 运维系统                        │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────────────┐
│  第一层: 业务 API (对外统一入口)                                           │
│  ┌──────────────────────────────────────────────────────────────────┐   │
│  │  - 面向业务语义: 创建应用/扩缩容/发布/回滚                           │   │
│  │  - 对外唯一入口，所有外部系统通过此API交互                            │   │
│  │  - 屏蔽底层K8s复杂性，用户无需了解Pod/Deployment等概念                │   │
│  │  - 内置鉴权、审计、配额管理                                         │   │
│  └──────────────────────────────────────────────────────────────────┘   │
│                                │                                        │
│  ┌─────────────────────────────▼────────────────────────────────────┐   │
│  │  第二层: 平台 API (内部能力编排)                                     │   │
│  │  - 多集群路由: 根据业务属性选择目标集群                               │   │
│  │  - 资源编排: 将业务意图翻译为K8s原生对象组合                          │   │
│  │  - 策略引擎: 注入调度约束、网络策略、安全策略                          │   │
│  │  - 跨集群调度: 容量规划、故障切换                                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                │                                        │
│  ┌─────────────────────────────▼────────────────────────────────────┐   │
│  │  第三层: Kubernetes API (标准编排引擎)                                │   │

│  │  - 通过CRD/Operator扩展能力                                         │   │
│  │  - 保证可随社区版本平滑升级                                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
```

三层 API 的设计动机：

| 层次 | 面向对象 | 核心职责 | 设计约束 |
|------|---------|---------|---------|
| 业务API | 业务研发、CI/CD系统 | 统一入口，业务语义抽象 | 稳定性最高，不可随意变更 |
| 平台API | 平台内部组件 | 多集群编排，策略注入 | 可扩展，支持插件化 |
| K8s API | K8s集群 | 标准编排执行 | 严格遵循社区标准 |

```java
/**
 * 业务API层 - 面向业务语义的统一入口
 * 将业务操作翻译为平台层可理解的编排指令
 */
@RestController
@RequestMapping("/api/v1/apps")
public class ApplicationController {

    private final PlatformOrchestrator orchestrator;
    private final AuthService authService;
    private final AuditLogger auditLogger;

    /**
     * 创建应用 - 业务语义：用户只需要关心应用名、镜像、规格、副本数
     * 平台自动完成：集群选择、调度策略注入、监控配置、网络策略等
     */
    @PostMapping
    public Response<AppInfo> createApp(@RequestBody CreateAppRequest request,
                                       @RequestHeader("X-User-Token") String token) {
        // 1. 鉴权
        UserInfo user = authService.authenticate(token);
        authService.checkPermission(user, request.getNamespace(), "app:create");

        // 2. 配额检查
        ResourceQuota quota = quotaService.getQuota(request.getNamespace());
        ResourceRequirement needed = calculateResource(request);
        if (!quota.canAllocate(needed)) {
            throw new QuotaExceededException("Namespace quota exceeded");
        }

        // 3. 选择目标集群（多集群路由）
        ClusterInfo targetCluster = clusterRouter.selectCluster(
            request.getRegion(), request.getResourceProfile(), request.getAffinity());

        // 4. 委托平台API编排
        AppInfo appInfo = orchestrator.createApplication(
            targetCluster, request, buildSchedulingPolicy(request));

        // 5. 审计日志
        auditLogger.log(user, "CREATE_APP", request.getAppName(), targetCluster.getName());
        return Response.success(appInfo);
    }

    /**
     * 扩缩容 - 业务语义：只需要指定目标副本数
     * 平台自动完成：容量检查、安全校验、灰度扩容
     */
    @PutMapping("/{appName}/scale")
    public Response<ScaleResult> scaleApp(@PathVariable String appName,
                                          @RequestBody ScaleRequest request) {
        // 安全校验：缩容超过50%需要二次确认
        int currentReplicas = orchestrator.getCurrentReplicas(appName);
        if (request.getReplicas() < currentReplicas / 2 && !request.isForceConfirmed()) {
            throw new SafetyCheckException("Scale down >50% requires force confirmation");
        }
        return Response.success(orchestrator.scale(appName, request.getReplicas()));
    }
}
```

```java
/**
 * 平台API层 - 将业务意图翻译为K8s原生对象
 */
public class PlatformOrchestrator {

    private final Map<String, KubernetesClient> clusterClients;
    private final SchedulingPolicyEngine policyEngine;
    private final MonitoringIntegration monitoringIntegration;

    public AppInfo createApplication(ClusterInfo cluster, CreateAppRequest request,
                                      SchedulingPolicy policy) {
        KubernetesClient client = clusterClients.get(cluster.getName());

        // 1. 构建Deployment（业务语义 → K8s原生对象）
        Deployment deployment = buildDeployment(request, policy);

        // 2. 注入平台增强
        //    - 自动注入监控sidecar
        //    - 注入日志采集配置
        //    - 注入安全策略annotation
        deployment = policyEngine.applyPlatformEnhancements(deployment, request);

        // 3. 构建Service
        Service service = buildService(request);

        // 4. 构建HPA（如果配置了自动扩缩容）
        HorizontalPodAutoscaler hpa = null;
        if (request.getAutoScaling() != null) {
            hpa = buildHPA(request);
        }

        // 5. 提交到目标K8s集群（第三层API）
        client.apps().deployments().inNamespace(request.getNamespace()).create(deployment);
        client.services().inNamespace(request.getNamespace()).create(service);
        if (hpa != null) {
            client.autoscaling().v2().horizontalPodAutoscalers()
                .inNamespace(request.getNamespace()).create(hpa);
        }

        // 6. 注册监控
        monitoringIntegration.registerApp(request.getAppName(), cluster.getName());

        return buildAppInfo(deployment, service, cluster);
    }

    /**
     * 调度策略构建：将业务级参数转化为K8s调度约束
     */
    private Deployment buildDeployment(CreateAppRequest request, SchedulingPolicy policy) {
        DeploymentBuilder builder = new DeploymentBuilder()
            .withNewMetadata()
                .withName(request.getAppName())
                .withNamespace(request.getNamespace())
                .addToLabels("app", request.getAppName())
                .addToLabels("platform/managed", "true")
                .addToAnnotations("platform/owner", request.getOwner())
            .endMetadata()
            .withNewSpec()
                .withReplicas(request.getReplicas())
                .withNewSelector().addToMatchLabels("app", request.getAppName()).endSelector()
                .withNewTemplate()
                    .withNewMetadata().addToLabels("app", request.getAppName()).endMetadata()
                    .withNewSpec()
                        .addNewContainer()
                            .withName("app")
                            .withImage(request.getImage())
                            .withNewResources()
                                .addToRequests("cpu", new Quantity(request.getCpuRequest()))
                                .addToRequests("memory", new Quantity(request.getMemRequest()))
                                .addToLimits("cpu", new Quantity(request.getCpuLimit()))
                                .addToLimits("memory", new Quantity(request.getMemLimit()))
                            .endResources()
                        .endContainer()
                    .endSpec()
                .endTemplate()
            .endSpec();

        // 注入调度约束
        if (policy.getScatterLevel() != null) {
            injectTopologySpread(builder, policy);
        }
        if (policy.getNodeAffinity() != null) {
            injectNodeAffinity(builder, policy);
        }
        return builder.build();
    }
}
```

### 2.2 多集群管理架构

```
┌─────────────── 全局控制面板 ──────────────────────────────┐
│  集群注册 │ 全局调度 │ 跨集群服务发现 │ 全局DNS │ 容量规划  │
└────┬────────────┬───────────────┬──────────────────────┘
     │            │               │
     ▼            ▼               ▼
┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐
│Region-A │  │Region-B │  │Region-C │  │Region-D │
│K8s集群  │  │K8s集群  │  │K8s集群  │  │K8s集群  │
│万级节点  │  │万级节点  │  │千级节点  │  │千级节点  │
└────────┘  └────────┘  └────────┘  └────────┘
```

生产环境通常管理十万级以上实例，分布在多个地域的多个 Kubernetes 集群中。全局控制面板负责：

- **集群生命周期管理**：集群创建、扩容、升级、下线
- **全局容量规划**：跨集群资源使用率监控和容量预警
- **跨集群调度**：大促前的容量预分配，故障时的跨集群迁移
- **统一配置分发**：全局策略（网络策略、安全策略）下发到所有集群

```java
/**
 * 多集群路由器：根据业务属性选择最优集群
 */
public class ClusterRouter {

    private final List<ClusterInfo> clusters;
    private final ClusterCapacityMonitor capacityMonitor;

    /**
     * 集群选择策略：
     * 1. 按地域筛选（就近部署）
     * 2. 按资源类型筛选（GPU/大内存/普通）
     * 3. 按可用容量排序
     * 4. 考虑集群健康度
     */
    public ClusterInfo selectCluster(String region, String resourceProfile,
                                      AffinitySpec affinity) {
        return clusters.stream()
            // 地域匹配
            .filter(c -> c.getRegion().equals(region))
            // 资源类型匹配
            .filter(c -> c.supportsProfile(resourceProfile))
            // 集群健康
            .filter(c -> c.getHealthScore() > 0.8)
            // 按可用容量排序
            .sorted(Comparator.comparingDouble(c ->
                -capacityMonitor.getAvailableCapacityRatio(c.getName())))
            .findFirst()
            .orElseThrow(() -> new NoAvailableClusterException(
                "No cluster available for region=" + region));
    }

    /**
     * 跨集群迁移：源集群故障时，将应用迁移到备用集群
     */
    public MigrationResult migrateApplication(String appName, String sourceCluster,
                                                String targetCluster) {
        // 1. 获取源集群应用配置
        AppConfig config = getAppConfig(sourceCluster, appName);
        // 2. 在目标集群创建应用
        createAppInCluster(targetCluster, config);
        // 3. 等待就绪
        waitForReady(targetCluster, appName, Duration.ofMinutes(5));
        // 4. 切换流量（更新全局DNS/服务发现）
        switchTraffic(appName, sourceCluster, targetCluster);
        // 5. 清理源集群残留
        cleanupSource(sourceCluster, appName);
        return MigrationResult.success(sourceCluster, targetCluster);
    }
}
```

### 2.4 核心设计原则

**声明式 API**：用户通过 YAML 描述期望状态，控制器持续将实际状态向期望状态收敛。具有天然的幂等性和自愈能力。

**控制循环**（Control Loop）：观察当前状态 → 与期望状态比较 → 执行操作 → 更新状态。采用 Level-triggered 而非 Edge-triggered，保证最终一致性。

**松耦合**：各组件通过 API Server 间接通信，基于 etcd Watch 实现事件分发，可独立部署和升级。

**标准化与兼容性**：严格遵循 Kubernetes 社区 API 标准，确保与社区版本的兼容性，可随社区版本平滑升级。

## 3. 核心链路设计

### 3.1 容器编排架构

#### 3.1.1 API Server 请求处理管线

写请求处理流程：认证(AuthN) → 授权(AuthZ/RBAC) → Mutating Admission → Schema Validation → Validating Admission → etcd持久化 → Watch事件通知。

```java
/**
 * 准入控制管线 - 责任链模式
 * 平台通过自定义Admission Webhook注入企业级策略
 */
public class AdmissionPipeline {
    private final List<MutatingAdmissionPlugin> mutatingPlugins;
    private final List<ValidatingAdmissionPlugin> validatingPlugins;

    public AdmissionResponse admit(AdmissionRequest request) {
        KubernetesObject object = request.getObject();

        // Phase 1: Mutating - 可修改对象
        // 典型场景: 注入sidecar、添加标签、注入环境变量
        for (MutatingAdmissionPlugin plugin : mutatingPlugins) {
            MutationResult result = plugin.mutate(object);
            if (!result.isAllowed()) {
                return AdmissionResponse.denied(result.getReason());
            }
            if (result.hasPatch()) {
                object = applyJsonPatch(object, result.getPatch());
            }
        }

        // Phase 2: Schema Validation - 结构校验
        ValidationResult schemaResult = validateSchema(object);
        if (!schemaResult.isValid()) {
            return AdmissionResponse.denied(schemaResult.getErrors());
        }

        // Phase 3: Validating - 只读校验
        // 典型场景: 镜像安全扫描、资源配额检查、命名规范
        for (ValidatingAdmissionPlugin plugin : validatingPlugins) {
            ValidationResult result = plugin.validate(object);
            if (!result.isAllowed()) {
                return AdmissionResponse.denied(result.getReason());
            }
        }
```

#### 3.1.2 etcd 数据模型与 Watch 机制

etcd 基于 Raft 共识算法，所有 K8s 对象存储为键值对：

```
/registry/{resource_type}/{namespace}/{name}

示例：
/registry/pods/default/nginx-7d8f9c5b9-x2k4m
/registry/deployments/production/web-server
/registry/services/kube-system/kube-dns
/registry/nodes/worker-node-001
```

三节点 etcd 集群的 Raft 写入流程：

```
1. Client → Leader:   提交写请求
2. Leader → 本地WAL:  追加日志条目
3. Leader → Followers: 复制日志 (AppendEntries RPC)
4. Followers → Leader: 确认收到 (ACK)
5. Leader:             收到多数派(2/3)确认后提交
6. Leader → Client:    返回成功
```

Kubernetes Informer 框架基于 etcd Watch 构建：先 List 全量数据填充本地缓存，再 Watch 增量变更。ResourceVersion 过期时自动 re-list。这种 List-Watch 机制将 O(n) 轮询降为 O(1) 事件推送，是支撑大规模集群的关键。

```java
/**
 * Informer: List-Watch + 本地缓存，减少API Server压力
 */
public class ResourceInformer<T extends KubernetesObject> {
    private final ConcurrentMap<String, T> localCache = new ConcurrentHashMap<>();
    private final List<ResourceEventHandler<T>> eventHandlers = new CopyOnWriteArrayList<>();
    private volatile long lastResourceVersion = 0;

    public void start() {
        // Phase 1: List全量
        ResourceList<T> list = apiClient.list(resourceType);
        lastResourceVersion = list.getMetadata().getResourceVersion();
        list.getItems().forEach(item -> localCache.put(keyOf(item), item));
        // Phase 2: Watch增量
        CompletableFuture.runAsync(this::watchLoop);
    }

    private void watchLoop() {
        while (!Thread.currentThread().isInterrupted()) {
            try {
                WatchStream<T> stream = apiClient.watch(resourceType, lastResourceVersion);
                for (WatchEvent<T> event : stream) {
                    lastResourceVersion = event.getObject().getMetadata().getResourceVersion();
                    String key = keyOf(event.getObject());
                    switch (event.getType()) {
                        case ADDED -> { localCache.put(key, event.getObject()); 
                            eventHandlers.forEach(h -> h.onAdd(event.getObject())); }
                        case MODIFIED -> { T old = localCache.put(key, event.getObject());
                            eventHandlers.forEach(h -> h.onUpdate(old, event.getObject())); }
                        case DELETED -> { localCache.remove(key);
                            eventHandlers.forEach(h -> h.onDelete(event.getObject())); }
                    }
                }
            } catch (GoneException e) { relist(); } // ResourceVersion过期
              catch (Exception e) { sleepWithBackoff(); }
        }
    }

    public T get(String namespace, String name) {
        return localCache.get(namespace + "/" + name);
    }
}
```

### 3.2 调度器深度优化

调度器是容器集群平台最核心的组件之一。在大规模集群（万级节点、十万+实例）场景下，原生 K8s 调度器面临严重的性能瓶颈。通过以下优化手段，实现了 400%+ 的调度性能提升。

#### 3.2.1 基础调度算法：预选 + 优选

```
待调度Pod → [Filter: 过滤不满足硬性约束的节点] → [Score: 对候选节点评分] → 最优节点
```

```java
/**
 * 调度器核心算法（优化前基线版本）
 */
public class PodScheduler {
    private final List<FilterPlugin> filterPlugins;
    private final List<ScorePlugin> scorePlugins;

    public ScheduleResult schedule(Pod pod) {
        List<NodeInfo> allNodes = nodeLister.snapshot();

        // Phase 1: Filter（预选 - 硬性约束过滤）
        List<NodeInfo> feasible = new ArrayList<>();
        for (NodeInfo node : allNodes) {
            boolean pass = true;
            for (FilterPlugin plugin : filterPlugins) {
                if (!plugin.filter(pod, node).isPass()) {
                    pass = false;
                    break;
                }
            }
            if (pass) feasible.add(node);
        }
        if (feasible.isEmpty()) return ScheduleResult.unschedulable("no feasible nodes");
        if (feasible.size() == 1) return ScheduleResult.success(feasible.get(0).getNode());

        // Phase 2: Score（优选 - 候选节点评分）
        long[] scores = new long[feasible.size()];
        for (ScorePlugin plugin : scorePlugins) {
            for (int i = 0; i < feasible.size(); i++) {
                scores[i] += (long) plugin.score(pod, feasible.get(i)) * plugin.getWeight();
            }
        }

        // 选最高分，同分随机打破（避免热点）
        int best = IntStream.range(0, scores.length)
            .reduce((a, b) -> scores[a] >= scores[b] ? a : b).orElse(0);
        return ScheduleResult.success(feasible.get(best).getNode());
    }
}
```

#### 3.2.2 优化一：预选失败短路（Predicate Failure Short-circuit）

**问题**：原生调度器在预选阶段，即使某个 Filter 已经失败，仍会继续执行该节点剩余的所有 Filter。对于有 20+ 个 Filter 的场景，大量无效计算浪费 CPU。

**方案**：一旦任意 predicate 失败，立即跳过该节点剩余的所有 predicate 检查。这个优化看似简单，但在大规模集群中效果显著——因为大部分节点会在前几个 predicate 就被过滤掉。

**效果**：调度延迟降低 40%+。此优化已贡献给 Kubernetes 社区（PR#56926），在 K8s 1.10 版本正式发布。

```java
/**
 * 优化后的预选流程：短路机制
 * 核心思想：任意Filter失败即跳过该节点剩余Filter
 * 
 * 已贡献社区: kubernetes/kubernetes PR#56926, released in K8s 1.10
 */
public class OptimizedFilterPhase {

    private final List<FilterPlugin> filterPlugins;
    // 按过滤率从高到低排序的Filter索引（动态统计）
    private volatile int[] filterOrder;
    // 各Filter的历史过滤率统计
    private final AtomicLongArray filterHitCount;
    private final AtomicLongArray filterTotalCount;

    /**
     * 短路过滤 + 动态排序
     * 
     * 两层优化：
     * 1. 短路：第一个Filter失败即停止（减少无效计算）
     * 2. 动态排序：过滤率高的Filter优先执行（让短路更早触发）
     */
    public FilterResult filterNode(Pod pod, NodeInfo node) {
        int[] order = this.filterOrder; // 读取快照（volatile）

        for (int idx : order) {
            FilterPlugin plugin = filterPlugins.get(idx);
            filterTotalCount.incrementAndGet(idx);

            FilterResult result = plugin.filter(pod, node);
            if (!result.isPass()) {
                filterHitCount.incrementAndGet(idx);
                // 短路：不再检查剩余Filter
                return result;
            }
        }
        return FilterResult.pass();
    }

    /**
     * 每1000次调度后重新排序Filter
     * 过滤率高的排在前面，使短路更早触发
     */
    @Scheduled(fixedDelay = 5000)
    public void reorderFilters() {
        int n = filterPlugins.size();
        Integer[] indices = IntStream.range(0, n).boxed().toArray(Integer[]::new);
        Arrays.sort(indices, (a, b) -> {
            double rateA = filterTotalCount.get(a) == 0 ? 0 :
                (double) filterHitCount.get(a) / filterTotalCount.get(a);
            double rateB = filterTotalCount.get(b) == 0 ? 0 :
                (double) filterHitCount.get(b) / filterTotalCount.get(b);
            return Double.compare(rateB, rateA); // 降序：过滤率高的优先
        });
        this.filterOrder = Arrays.stream(indices).mapToInt(Integer::intValue).toArray();
    }
}
```

#### 3.2.3 优化二：局部最优解（Local Optimal Solution）

**问题**：原生调度器对所有节点进行全量遍历（BestFit），在万级节点集群中，一次调度需要遍历上万个节点。即使每个节点只花 0.1ms，一次调度也需要数秒。

**方案**：不再扫描所有节点，而是找到 N 个可接受的候选节点后即停止搜索，在这 N 个候选中选择最优。N 的计算公式根据集群规模动态调整。

**效果**：大规模集群调度延迟大幅降低。此优化以多个 PR 贡献给社区（PR#66733, PR#67555），在 K8s 1.12 版本发布。

```java
/**
 * 局部最优解调度：不扫描全部节点，找到足够候选即停止
 * 
 * 已贡献社区: kubernetes/kubernetes PR#66733, PR#67555, released in K8s 1.12
 */
public class LocalOptimalScheduler {

    private final List<FilterPlugin> filterPlugins;
    private final List<ScorePlugin> scorePlugins;
    private final OptimizedFilterPhase filterPhase;

    /**
     * 计算需要搜索的候选节点数量
     * 
     * 策略：
     * - 集群 <= 100 节点: 全量搜索（小集群全搜代价不大）
     * - 集群 > 100 节点: max(100, clusterSize * percentage / 100)
     * - percentage 默认 50%，可配置
     * 
     * 例如：5000节点集群 → 搜索2500个候选
     *       10000节点集群 → 搜索5000个候选
     */
    private int calculateNumCandidates(int totalNodes, int percentageOfNodes) {
        if (totalNodes <= 100) {
            return totalNodes; // 小集群全量搜索
        }
        return Math.max(100, totalNodes * percentageOfNodes / 100);
    }

    public ScheduleResult schedule(Pod pod) {
        List<NodeInfo> allNodes = nodeLister.snapshot();
        int numCandidates = calculateNumCandidates(allNodes.size(), 50);

        // Phase 1: Filter - 找到numCandidates个候选即停止
        List<NodeInfo> feasible = new ArrayList<>(numCandidates);
        // 从随机位置开始遍历，避免总是从同一节点开始导致热点
        int startIndex = ThreadLocalRandom.current().nextInt(allNodes.size());

        for (int i = 0; i < allNodes.size() && feasible.size() < numCandidates; i++) {
            int idx = (startIndex + i) % allNodes.size();
            NodeInfo node = allNodes.get(idx);

            FilterResult result = filterPhase.filterNode(pod, node);
            if (result.isPass()) {
                feasible.add(node);
            }
        }

        if (feasible.isEmpty()) {
            return ScheduleResult.unschedulable("no feasible nodes in sampled set");
        }

        // Phase 2: Score - 只对候选节点评分
        long bestScore = Long.MIN_VALUE;
        NodeInfo bestNode = null;
        List<NodeInfo> tiedNodes = new ArrayList<>();

        for (NodeInfo node : feasible) {
            long totalScore = 0;
            for (ScorePlugin plugin : scorePlugins) {
                totalScore += (long) plugin.score(pod, node) * plugin.getWeight();
            }
            if (totalScore > bestScore) {
                bestScore = totalScore;
                bestNode = node;
                tiedNodes.clear();
                tiedNodes.add(node);
            } else if (totalScore == bestScore) {
                tiedNodes.add(node);
            }
        }

        // 同分随机选择，打破热点
        if (tiedNodes.size() > 1) {
            bestNode = tiedNodes.get(ThreadLocalRandom.current().nextInt(tiedNodes.size()));
        }

        return ScheduleResult.success(bestNode.getNode());
    }
}
```

```java
/** PodFitsResources: CPU/内存/GPU等资源是否充足 */
public class PodFitsResourcesFilter implements FilterPlugin {
    @Override
    public FilterResult filter(Pod pod, NodeInfo nodeInfo) {

        Resource allocated = nodeInfo.getAllocatedResources();

/** LeastRequestedPriority: 资源空闲率越高分越高（Spread策略） */
public class LeastRequestedScorePlugin implements ScorePlugin {
    @Override
    public int score(Pod pod, NodeInfo node) {
        Resource req = calculatePodRequest(pod);
        long cpuFree = node.getAllocatable().getCpu() - node.getAllocated().getCpu() - req.getCpu();
        int cpuScore = (int)(cpuFree * 100 / node.getAllocatable().getCpu());
        long memFree = node.getAllocatable().getMem() - node.getAllocated().getMem() - req.getMem();
        int memScore = (int)(memFree * 100 / node.getAllocatable().getMem());
        return (cpuScore + memScore) / 2;
    }
}

/** BalancedResourceAllocation: CPU和内存使用率越均衡分越高 */
public class BalancedResourceScorePlugin implements ScorePlugin {
    @Override
    public int score(Pod pod, NodeInfo node) {
        Resource req = calculatePodRequest(pod);
        double cpuRatio = (double)(node.getAllocated().getCpu() + req.getCpu())
            / node.getAllocatable().getCpu();
        double memRatio = (double)(node.getAllocated().getMem() + req.getMem())
            / node.getAllocatable().getMem();
        // 差值越小越均衡，分越高
        double diff = Math.abs(cpuRatio - memRatio);
        return (int)((1.0 - diff) * 100);
    }
}
```

#### 3.2.7 Taints 和 Tolerations

Taints 设置在节点上，Tolerations 设置在 Pod 上。只有声明了对应容忍的 Pod 才能调度到有污点的节点。

```
Taint效果(Effect):
- NoSchedule:      不调度新Pod（已运行不受影响）
- PreferNoSchedule: 尽量不调度（软性）
- NoExecute:       不调度 + 驱逐已运行的Pod

常见场景：
  GPU专用节点:      gpu=true:NoSchedule
  Master节点隔离:   node-role/master:NoSchedule
  节点维护:         maintenance=true:NoExecute
  专用计算节点:      dedicated=compute:NoSchedule
```

```java
/** Taint/Toleration Filter */
public class TaintTolerationFilter implements FilterPlugin {
    @Override
    public FilterResult filter(Pod pod, NodeInfo nodeInfo) {
        List<Taint> taints = nodeInfo.getNode().getSpec().getTaints();
        if (taints == null) return FilterResult.pass();
        List<Toleration> tolerations = pod.getSpec().getTolerations();
        for (Taint taint : taints) {
            if ("PreferNoSchedule".equals(taint.getEffect())) continue;
            boolean tolerated = tolerations != null && tolerations.stream()
                .anyMatch(t -> matchesTaint(t, taint));
            if (!tolerated) return FilterResult.fail("Untolerated taint: " + taint);
        }
        return FilterResult.pass();
    }

    private boolean matchesTaint(Toleration toleration, Taint taint) {
        if ("Exists".equals(toleration.getOperator()) && toleration.getKey() == null) return true;
        if ("Exists".equals(toleration.getOperator())) return toleration.getKey().equals(taint.getKey());
        return toleration.getKey().equals(taint.getKey()) 
            && Objects.equals(toleration.getValue(), taint.getValue())
            && (toleration.getEffect() == null || toleration.getEffect().equals(taint.getEffect()));
    }
}
```

#### 3.2.8 拓扑分布约束与打散部署

TopologySpreadConstraints 控制 Pod 在拓扑域间的分布均匀度，核心是保证各域的 Pod 数偏差不超过 maxSkew。在生产环境中，打散部署是容灾的核心手段，需要在多个维度进行打散：

```
打散层级（从细到粗）：
  ① 主机级别(hostname):    同一应用副本分散到不同物理机
  ② 机架级别(ToR Switch):  分散到不同机架，容忍单机架故障
  ③ 机房级别(datacenter):  分散到不同机房，容忍单机房故障
  ④ 可用区级别(zone):      分散到不同可用区，容忍区域故障
```

```java
/**
 * 多层级打散部署 Filter
 * 在主机、机架、机房、可用区四个维度同时保证打散
 */
public class MultiLevelScatterFilter implements FilterPlugin {

    /** 拓扑层级及其最大偏差配置 */
    private static final List<ScatterLevel> SCATTER_LEVELS = List.of(
        new ScatterLevel("kubernetes.io/hostname",           1),  // 主机级别: 最多差1
        new ScatterLevel("topology.kubernetes.io/rack",      2),  // 机架级别: 最多差2
        new ScatterLevel("topology.kubernetes.io/datacenter", 3), // 机房级别: 最多差3
        new ScatterLevel("topology.kubernetes.io/zone",       2)  // 可用区级别: 最多差2
    );

    @Override
    public FilterResult filter(Pod pod, NodeInfo nodeInfo) {
        String appLabel = pod.getMetadata().getLabels().get("app");
        if (appLabel == null) return FilterResult.pass();

        for (ScatterLevel level : SCATTER_LEVELS) {
            Map<String, Integer> counts = countPodsPerTopology(appLabel, level.topologyKey);
            String nodeTopology = nodeInfo.getNode().getLabels().get(level.topologyKey);
            if (nodeTopology == null) continue;

            int afterSchedule = counts.getOrDefault(nodeTopology, 0) + 1;
            int minCount = counts.values().stream()
                .mapToInt(Integer::intValue).min().orElse(0);

            if (afterSchedule - minCount > level.maxSkew) {
                return FilterResult.fail(String.format(
                    "Scatter violation at %s level: skew=%d > maxSkew=%d",
                    level.topologyKey, afterSchedule - minCount, level.maxSkew));
            }
        }
        return FilterResult.pass();
    }

    private record ScatterLevel(String topologyKey, int maxSkew) {}
}
```

#### 3.2.9 优先级调度与抢占

在资源紧张时，高优先级应用可以抢占低优先级应用的资源。优先级分为两层实现：调度层（决定调度顺序和抢占策略）和主机层（决定资源争抢时的分配比例）。

```java
/**
 * 优先级调度器：高优先级Pod可以抢占低优先级Pod
 * 
 * 优先级层次：
 *   P0 (Critical):    核心服务（支付、订单），不可被抢占
 *   P1 (High):        重要服务（搜索、推荐），可被P0抢占
 *   P2 (Normal):      普通服务（后台任务），可被P0/P1抢占
 *   P3 (Low):         低优先级（离线计算），可被所有在线服务抢占
 */
public class PriorityPreemptionScheduler {

    /**
     * 当Pod无法调度时，尝试抢占低优先级Pod
     */
    public PreemptionResult tryPreempt(Pod preemptor) {
        int preemptorPriority = preemptor.getSpec().getPriorityValue();

        // 遍历所有节点，找到抢占代价最小的节点
        PreemptionCandidate bestCandidate = null;

        for (NodeInfo node : nodeLister.snapshot()) {
            // 找到该节点上可被抢占的Pod（优先级低于preemptor）
            List<Pod> victims = node.getPods().stream()
                .filter(p -> p.getSpec().getPriorityValue() < preemptorPriority)
                .sorted(Comparator.comparingInt(p -> p.getSpec().getPriorityValue()))
                .collect(Collectors.toList());

            if (victims.isEmpty()) continue;

            // 模拟驱逐：逐个移除victim直到资源满足
            List<Pod> toEvict = new ArrayList<>();
            Resource available = node.getAvailableResources();

            for (Pod victim : victims) {
                if (canFit(preemptor, available)) break; // 资源已足够
                toEvict.add(victim);
                available = available.add(getResourceRequest(victim));
            }

            if (!canFit(preemptor, available)) continue; // 即使全部驱逐也不够

            // 检查PDB（Pod Disruption Budget）约束
            if (!checkPDBCompliance(toEvict)) continue;

            // 计算抢占代价（被驱逐Pod的总优先级和数量）
            int cost = toEvict.stream().mapToInt(p -> p.getSpec().getPriorityValue()).sum();
            if (bestCandidate == null || cost < bestCandidate.cost) {
                bestCandidate = new PreemptionCandidate(node, toEvict, cost);
            }
        }

        if (bestCandidate != null) {
            // 执行抢占：驱逐victim，调度preemptor
            for (Pod victim : bestCandidate.victims) {
                evictPod(victim, "Preempted by higher priority pod: " + preemptor.getName());
            }
            return PreemptionResult.success(bestCandidate.node, bestCandidate.victims);
        }

        return PreemptionResult.failed("No node found for preemption");
    }
}
```

### 3.3 Kubelet 深度定制

标准 Kubelet 在大规模生产环境中存在多项不足，需要针对性定制。以下是五个关键的 Kubelet 增强方向。

#### 3.3.1 容器重启策略（Reuse模式）

**问题**：标准 K8s 中，Pod 重建意味着容器被销毁后重新创建。但在某些场景下（如宿主机重启维护），我们希望保留容器的系统盘和数据盘信息，重启后直接复用原有容器。

**方案**：自定义容器重启策略 Reuse，在宿主机重启时保留容器元数据（磁盘挂载信息、网络配置），重启后恢复容器而非重建。

```java
/**
 * 容器Reuse策略：宿主机重启后复用原有容器
 * 保留系统盘和数据盘信息，避免数据丢失和IP变更
 */
public class ContainerReuseManager {

    private static final String REUSE_STATE_DIR = "/var/lib/kubelet/container-reuse/";

    /**
     * 在宿主机关机/重启前，持久化容器元数据
     */
    public void persistContainerState(String podUid, ContainerInfo container) {
        ContainerReuseState state = ContainerReuseState.builder()
            .podUid(podUid)
            .containerId(container.getId())
            .containerName(container.getName())
            // 保留系统盘信息
            .systemDiskPath(container.getSystemDiskPath())
            .systemDiskSize(container.getSystemDiskSize())
            // 保留数据盘信息
            .dataDiskMounts(container.getDataDiskMounts().stream()
                .map(m -> new DiskMountInfo(m.getSource(), m.getTarget(), m.getFsType()))
                .collect(Collectors.toList()))
            // 保留网络信息
            .ipAddress(container.getIpAddress())
            .macAddress(container.getMacAddress())
            .networkNamespace(container.getNetworkNamespace())
            // 保留Cgroup配置
            .cgroupPath(container.getCgroupPath())
            .cpuRequest(container.getCpuRequest())
            .memoryLimit(container.getMemoryLimit())
            .build();

        // 持久化到本地磁盘（宿主机重启不丢失）
        String filePath = REUSE_STATE_DIR + podUid + "/" + container.getName() + ".json";
        Files.write(Path.of(filePath), JsonSerializer.serialize(state).getBytes(),
            StandardOpenOption.CREATE, StandardOpenOption.TRUNCATE_EXISTING);
    }

    /**
     * 宿主机重启后，恢复容器
     */
    public ContainerRestoreResult restoreContainer(String podUid, String containerName) {
        String filePath = REUSE_STATE_DIR + podUid + "/" + containerName + ".json";
        if (!Files.exists(Path.of(filePath))) {
            return ContainerRestoreResult.notFound();
        }

        ContainerReuseState state = JsonSerializer.deserialize(
            Files.readString(Path.of(filePath)), ContainerReuseState.class);

        // 1. 恢复网络命名空间
        networkManager.restoreNetworkNamespace(
            state.getNetworkNamespace(), state.getIpAddress(), state.getMacAddress());

        // 2. 恢复磁盘挂载
        for (DiskMountInfo mount : state.getDataDiskMounts()) {
            mountManager.mount(mount.getSource(), mount.getTarget(), mount.getFsType());
        }

        // 3. 恢复Cgroup配置
        cgroupManager.restoreCgroup(state.getCgroupPath(),
            state.getCpuRequest(), state.getMemoryLimit());

        // 4. 启动容器（复用原有rootfs，不重新拉取镜像）
        containerRuntime.startContainer(state.getContainerId());

        return ContainerRestoreResult.success(state.getContainerId());
    }
}
```

#### 3.3.2 IP 状态保持

**问题**：标准 K8s 中 Pod 重建后 IP 会变化，对于依赖固定 IP 的有状态服务（如数据库、缓存集群）造成严重影响。

**方案**：自定义 CNI 插件，基于 Pod 唯一标识符（而非 Pod UID）进行 IP 分配。Pod 重建时，CNI 插件根据唯一标识符复用之前的 IP。

```java
/**
 * IP状态保持：基于Pod唯一标识符的IP复用
 * 自定义CNI插件，确保Pod重建后IP不变
 */
public class StatefulIpamPlugin implements CniPlugin {

    // IP分配记录：podUniqueId -> IP
    private final ConcurrentMap<String, IpAllocation> ipAllocations = new ConcurrentHashMap<>();
    // 持久化存储（etcd或本地文件）
    private final IpAllocationStore persistStore;

    /**
     * 分配IP：优先复用历史IP
     * 
     * Pod唯一标识符 = StatefulSet名称 + 序号（如 mysql-0, redis-1）
     * 或自定义标签: platform/pod-identity
     */
    @Override
    public CniResult cmdAdd(CniArgs args) {
        String podUniqueId = extractPodUniqueId(args);

        // 1. 尝试复用历史IP
        IpAllocation existing = persistStore.get(podUniqueId);
        if (existing != null && isIpAvailable(existing.getIp())) {
            // IP仍在可用池中，直接复用
            ipAllocations.put(podUniqueId, existing);
            configureNetworkInterface(args.getNetns(), existing);
            return CniResult.success(existing.getIp(), existing.getGateway(), existing.getSubnet());
        }

        // 2. 分配新IP
        IpAllocation newAlloc = allocateNewIp(args.getSubnet());
        ipAllocations.put(podUniqueId, newAlloc);
        persistStore.save(podUniqueId, newAlloc); // 持久化
        configureNetworkInterface(args.getNetns(), newAlloc);
        return CniResult.success(newAlloc.getIp(), newAlloc.getGateway(), newAlloc.getSubnet());
    }

    @Override
    public CniResult cmdDel(CniArgs args) {
        String podUniqueId = extractPodUniqueId(args);
        // 删除时不释放IP，保留分配记录供下次复用
        // 只清理网络命名空间中的配置
        cleanupNetworkInterface(args.getNetns());
        // IP保留策略：超过TTL（如7天）后自动释放
        persistStore.setExpiry(podUniqueId, Duration.ofDays(7));
        return CniResult.success();
    }

    private String extractPodUniqueId(CniArgs args) {
        // 优先使用自定义标签
        String customId = args.getPodAnnotations().get("platform/pod-identity");
        if (customId != null) return customId;
        // 其次使用StatefulSet身份
        String podName = args.getPodName();
        String ownerKind = args.getPodLabels().get("app.kubernetes.io/managed-by");
        if ("StatefulSet".equals(ownerKind)) return podName; // StatefulSet Pod名称稳定
        // 默认使用Pod UID（无法复用）
        return args.getPodUid();
    }
}
```

#### 3.3.3 驱逐策略限制

**问题**：标准 Kubelet 在节点资源压力（DiskPressure、MemoryPressure、PIDPressure）时会自主驱逐 Pod。在大规模集群中，这种自主驱逐可能引发雪崩效应——某些节点因驱逐导致其他节点负载升高，进而引发连锁驱逐。

**方案**：限制 Kubelet 的自主驱逐决策权，将驱逐判断上移到集群级别的控制器，由全局视角决策是否驱逐。

```java
/**
 * 驱逐策略限制：防止Kubelet自主驱逐引发雪崩
 * 
 * 核心改动：
 * 1. 提高驱逐阈值，减少误触发
 * 2. 添加驱逐速率限制
 * 3. 驱逐前请求集群控制器确认
 */
public class EvictionPolicyGuard {

    private final RateLimiter evictionRateLimiter;
    private final ClusterEvictionController clusterController;
    private final AlertManager alertManager;

    // 自定义驱逐阈值（比默认值更保守）
    private static final Map<String, String> CUSTOM_THRESHOLDS = Map.of(
        "memory.available",   "200Mi",   // 默认100Mi
        "nodefs.available",   "15%",     // 默认10%
        "nodefs.inodesFree",  "10%",     // 默认5%
        "imagefs.available",  "15%"      // 默认15%
    );

    /**
     * 驱逐决策拦截
     * 
     * 在Kubelet执行驱逐前插入拦截逻辑：
     * 1. 速率限制：每分钟最多驱逐N个Pod
     * 2. 集群确认：请求集群控制器确认
     * 3. 优先驱逐无状态Pod
     */
    public EvictionDecision shouldEvict(Pod pod, EvictionReason reason) {
        // 1. 速率限制
        if (!evictionRateLimiter.tryAcquire()) {
            alertManager.warn("Eviction rate limit reached on node " + getNodeName());
            return EvictionDecision.deny("Rate limit exceeded");
        }

        // 2. 保护关键Pod
        if (isCriticalPod(pod)) {
            alertManager.critical("Attempted to evict critical pod: " + pod.getName());
            return EvictionDecision.deny("Critical pod protected");
        }

        // 3. 请求集群控制器确认（全局视角判断）
        ClusterEvictionAdvice advice = clusterController.requestAdvice(
            getNodeName(), pod.getName(), reason);
        if (advice.isDenied()) {
            return EvictionDecision.deny(advice.getReason());
        }

        // 4. 软驱逐：先通知Pod优雅关闭
        return EvictionDecision.allow(Duration.ofSeconds(30)); // 30s优雅关闭期
    }

    private boolean isCriticalPod(Pod pod) {
        // 系统关键Pod、P0优先级Pod、带有protection标签的Pod
        return "kube-system".equals(pod.getNamespace())
            || pod.getSpec().getPriorityValue() >= 1000000
            || "true".equals(pod.getLabels().getOrDefault("platform/eviction-protected", "false"));
    }
}
```

#### 3.3.4 应用原地升级

**问题**：标准 K8s 升级应用需要销毁旧 Pod、创建新 Pod（Rolling Update），涉及 IP 变更、重新调度、镜像拉取，过程慢且有中断风险。

**方案**：修改应用信息而不重建 Pod，直接在原有容器上更新应用配置、版本信息，实现秒级升级。

```java
/**
 * 应用原地升级：不重建Pod，直接更新容器内应用
 * 
 * 适用场景：
 * - 应用配置变更（不涉及镜像变更）
 * - 应用版本小版本升级（同基础镜像，不同应用包）
 * - 环境变量变更
 */
public class InPlaceUpdateManager {

    private final ContainerRuntime containerRuntime;
    private final KubernetesClient client;

    /**
     * 原地升级流程：
     * 1. 从服务发现中摘除Pod（停止接收新流量）
     * 2. 等待存量请求处理完成
     * 3. 更新容器内应用文件或配置
     * 4. 重启应用进程（非重建容器）
     * 5. 健康检查通过后重新注册服务发现
     */
    public InPlaceUpdateResult update(String podName, String namespace,
                                        InPlaceUpdateSpec spec) {
        Pod pod = client.pods().inNamespace(namespace).withName(podName).get();
        if (pod == null) return InPlaceUpdateResult.podNotFound();

        String containerId = getMainContainerId(pod);

        try {
            // Step 1: 摘流量
            setReadinessGate(pod, false);
            Thread.sleep(Duration.ofSeconds(5)); // 等待负载均衡感知

            // Step 2: 等待存量请求
            waitForDraining(containerId, Duration.ofSeconds(30));

            // Step 3: 更新应用
            if (spec.getNewImage() != null) {
                // 镜像层更新：拉取新镜像层，overlay mount
                containerRuntime.updateImageLayers(containerId, spec.getNewImage());
            }
            if (spec.getConfigUpdates() != null) {
                // 配置文件更新：直接写入容器内
                for (Map.Entry<String, String> entry : spec.getConfigUpdates().entrySet()) {
                    containerRuntime.execInContainer(containerId,
                        "sh", "-c", "echo '" + entry.getValue() + "' > " + entry.getKey());
                }
            }
            if (spec.getEnvUpdates() != null) {
                // 环境变量更新
                containerRuntime.updateEnv(containerId, spec.getEnvUpdates());
            }

            // Step 4: 重启应用进程
            containerRuntime.execInContainer(containerId,
                "sh", "-c", "kill -SIGTERM 1 && sleep 2");
            // 容器的PID 1进程由supervisord管理，会自动重启应用

            // Step 5: 健康检查
            boolean healthy = waitForHealthy(podName, namespace, Duration.ofSeconds(60));
            if (!healthy) {
                rollbackInPlace(containerId, spec);
                return InPlaceUpdateResult.healthCheckFailed();
            }

            // Step 6: 恢复流量
            setReadinessGate(pod, true);

            // 更新Pod annotation记录升级信息
            patchPodAnnotation(pod, Map.of(
                "platform/last-inplace-update", Instant.now().toString(),
                "platform/app-version", spec.getNewVersion()
            ));

            return InPlaceUpdateResult.success();

        } catch (Exception e) {
            setReadinessGate(pod, true); // 恢复流量
            return InPlaceUpdateResult.failed(e.getMessage());
        }
    }
}
```

#### 3.3.5 镜像分发优化

大规模集群中，数千节点同时拉取镜像会对中心 Registry 造成巨大压力。需要多层次的镜像分发优化策略。

```java
/**
 * 镜像分发优化：多层次策略
 * 
 * 1. 跨站同步：主Registry推送到各机房本地Registry
 * 2. 基础镜像预分发：周期性将基础镜像预推到所有节点
 * 3. P2P分发：节点间P2P传输，降低Registry压力
 */
public class ImageDistributionManager {

    private final RegistryClient registryClient;
    private final P2PDistributor p2pDistributor;
    private final NodeImageCache nodeImageCache;

    /**
     * 跨站镜像同步：主站推送到各地域本地Registry
     */
    public void crossSiteSync(String imageRef, List<String> targetRegions) {
        // 解析镜像manifest
        ImageManifest manifest = registryClient.getManifest(imageRef);

        for (String region : targetRegions) {
            RegistryEndpoint localRegistry = getRegionalRegistry(region);

            // 检查目标Registry是否已有该镜像
            if (localRegistry.hasManifest(manifest.getDigest())) {
                continue; // 已存在，跳过
            }

            // 逐层同步（利用内容可寻址去重）
            for (LayerDescriptor layer : manifest.getLayers()) {
                if (!localRegistry.hasBlob(layer.getDigest())) {
                    try (InputStream stream = registryClient.pullBlob(layer.getDigest())) {
                        localRegistry.pushBlob(layer.getDigest(), stream, layer.getSize());
                    }
                }
            }
            // 同步manifest
            localRegistry.pushManifest(imageRef, manifest);
        }
    }

    /**
     * 基础镜像预分发：每日将基础镜像推送到所有节点
     * 基础镜像更新频率低，预分发可大幅减少业务镜像拉取时间
     */
    @Scheduled(cron = "0 2 * * *") // 每天凌晨2点
    public void preDistributeBaseImages() {
        List<String> baseImages = getBaseImageList(); // 如 jdk:8, python:3.9, node:18

        for (String image : baseImages) {
            // 使用P2P协议分发到所有节点
            p2pDistributor.distribute(image, DistributionPolicy.builder()
                .concurrency(50)          // 最多50个节点同时拉取
                .p2pEnabled(true)          // 启用P2P
                .seedNodes(5)              // 先分发到5个种子节点
                .bandwidthLimit("100Mbps") // 带宽限制
                .build());
        }
    }

    /**
     * P2P镜像分发：节点间直接传输镜像层
     * 
     * 流程：
     * 1. 客户端向Tracker请求镜像层位置
     * 2. Tracker返回拥有该层的Peer列表
     * 3. 客户端从最近的Peer下载
     * 4. 下载完成后向Tracker注册自己为新的Peer
     */
    public void pullImageWithP2P(String nodeId, String imageRef) {
        ImageManifest manifest = registryClient.getManifest(imageRef);

        for (LayerDescriptor layer : manifest.getLayers()) {
            if (nodeImageCache.hasLayer(nodeId, layer.getDigest())) continue;

            // 查询拥有该层的Peer
            List<PeerInfo> peers = p2pDistributor.findPeers(layer.getDigest());

            if (!peers.isEmpty()) {
                // 从最近的Peer下载（按网络距离排序）
                PeerInfo nearestPeer = selectNearestPeer(nodeId, peers);
                downloadFromPeer(nearestPeer, layer);
            } else {
                // 无Peer，从Registry下载
                downloadFromRegistry(layer);
            }

            // 注册自己为Peer
            p2pDistributor.registerPeer(nodeId, layer.getDigest());
        }
    }
}
```

### 3.4 资源管理与画像

#### 3.4.1 服务画像（Service Profiling）

服务画像是精细化资源管理的基础。通过持续采集服务的 CPU、内存、网络、磁盘 I/O 等维度的运行数据，构建每个服务的资源使用模型。

```java
/**
 * 服务资源画像系统
 * 
 * 采集维度：
 * - CPU: 使用率、核数、峰值、周期性模式
 * - 内存: 使用量、峰值、GC特征
 * - 网络: 带宽、连接数、QPS
 * - 磁盘I/O: 读写IOPS、吞吐量
 * 
 * 画像用途：
 * - 精准资源推荐（替代人工配置requests/limits）
 * - 混合部署决策（哪些服务可以混部）
 * - 调度优化输入（资源互补型服务优先同节点调度）
 */
public class ServiceProfiler {

    private final MetricsCollector metricsCollector;
    private final TimeSeriesStore timeSeriesStore;

    /**
     * 构建服务资源画像
     * 基于7天历史数据，计算各维度的统计特征
     */
    public ServiceProfile buildProfile(String appName, Duration window) {
        Instant start = Instant.now().minus(window);
        Instant end = Instant.now();

        // 采集CPU指标
        TimeSeries cpuSeries = metricsCollector.query(
            "container_cpu_usage_seconds_total", appName, start, end);
        CpuProfile cpuProfile = CpuProfile.builder()
            .avgCores(cpuSeries.average())
            .p50Cores(cpuSeries.percentile(50))
            .p95Cores(cpuSeries.percentile(95))
            .p99Cores(cpuSeries.percentile(99))
            .peakCores(cpuSeries.max())
            .dailyPattern(extractDailyPattern(cpuSeries))  // 日内周期性
            .weeklyPattern(extractWeeklyPattern(cpuSeries)) // 周期性
            .cpuThrottleRate(getCpuThrottleRate(appName))   // CPU限流率
            .build();

        // 采集内存指标
        TimeSeries memSeries = metricsCollector.query(
            "container_memory_working_set_bytes", appName, start, end);
        MemoryProfile memProfile = MemoryProfile.builder()
            .avgBytes(memSeries.average())
            .p95Bytes(memSeries.percentile(95))
            .peakBytes(memSeries.max())
            .oomCount(getOomCount(appName, window))
            .gcOverheadRatio(getGcOverhead(appName))
            .build();

        // 采集网络指标
        NetworkProfile netProfile = NetworkProfile.builder()
            .avgBandwidthMbps(getAvgBandwidth(appName))
            .peakBandwidthMbps(getPeakBandwidth(appName))
            .avgConnectionCount(getAvgConnections(appName))
            .avgQps(getAvgQps(appName))
            .build();

        // 采集磁盘I/O指标
        DiskIoProfile diskProfile = DiskIoProfile.builder()
            .readIops(getAvgReadIops(appName))
            .writeIops(getAvgWriteIops(appName))
            .readThroughputMBps(getAvgReadThroughput(appName))
            .writeThroughputMBps(getAvgWriteThroughput(appName))
            .build();

        return ServiceProfile.builder()
            .appName(appName)
            .profileTime(Instant.now())
            .window(window)
            .cpu(cpuProfile)
            .memory(memProfile)
            .network(netProfile)
            .diskIo(diskProfile)
            // 资源推荐值
            .recommendedCpuRequest(cpuProfile.getP50Cores() + "")
            .recommendedCpuLimit(cpuProfile.getP99Cores() * 1.2 + "")
            .recommendedMemRequest(memProfile.getP95Bytes() * 1.1 + "")
            .recommendedMemLimit(memProfile.getPeakBytes() * 1.25 + "")
            .build();
    }

    /**
     * 判断两个服务是否资源互补（适合混合部署）
     * 互补条件：CPU峰值时段不重叠，资源使用具有互补性
     */
    public boolean isComplementary(ServiceProfile a, ServiceProfile b) {
        // CPU峰值时段互补性
        double cpuCorrelation = calculateCorrelation(
            a.getCpu().getDailyPattern(), b.getCpu().getDailyPattern());
        // 负相关说明峰值错开
        boolean cpuComplementary = cpuCorrelation < -0.3;

        // 资源类型互补性（一个CPU密集一个内存密集）
        boolean typeComplementary =
            (a.getCpu().getP95Cores() > 2 && b.getMemory().getP95Bytes() > 2_000_000_000L) ||
            (b.getCpu().getP95Cores() > 2 && a.getMemory().getP95Bytes() > 2_000_000_000L);

        return cpuComplementary || typeComplementary;
    }
}
```

#### 3.4.2 NUMA 绑定与 CPU Set

对于延迟敏感型应用，需要将容器绑定到特定的 NUMA 节点和 CPU 核心，避免跨 NUMA 内存访问带来的性能损失。

```java
/**
 * NUMA感知资源管理
 * 
 * NUMA(Non-Uniform Memory Access)架构中，CPU访问本地内存比远程内存快3-5倍。
 * 对于延迟敏感型应用，需要确保：
 * 1. 容器的CPU核心和内存在同一NUMA节点
 * 2. 容器独占CPU核心（CPU Set），避免上下文切换
 */
public class NumaAwareResourceManager {

    /**
     * 获取节点NUMA拓扑信息
     */
    public NumaTopology discoverTopology() {
        // 解析 /sys/devices/system/node/ 获取NUMA信息
        List<NumaNode> nodes = new ArrayList<>();
        for (int i = 0; i < getNumaNodeCount(); i++) {
            Set<Integer> cpus = parseCpuList("/sys/devices/system/node/node" + i + "/cpulist");
            long memoryBytes = parseMemInfo("/sys/devices/system/node/node" + i + "/meminfo");
            nodes.add(new NumaNode(i, cpus, memoryBytes));
        }
        return new NumaTopology(nodes);
    }

    /**
     * 为延迟敏感Pod分配NUMA绑定的CPU Set
     */
    public CpuSetAllocation allocateCpuSet(Pod pod, NumaTopology topology) {
        int requestedCpus = (int) Math.ceil(
            parseQuantity(pod.getSpec().getContainers().get(0)
                .getResources().getRequests().get("cpu")));

        boolean numaBinding = "true".equals(
            pod.getAnnotations().getOrDefault("platform/numa-binding", "false"));

        if (numaBinding) {
            // NUMA绑定模式：在同一NUMA节点上分配连续的CPU核心
            for (NumaNode node : topology.getNodes()) {
                Set<Integer> availableCpus = getAvailableCpus(node);
                if (availableCpus.size() >= requestedCpus) {
                    // 选择连续的CPU核心（利于缓存局部性）
                    Set<Integer> allocated = selectContiguousCpus(availableCpus, requestedCpus);
                    return CpuSetAllocation.builder()
                        .cpuSet(allocated)
                        .numaNode(node.getId())
                        .memoryNodeBinding(node.getId())
                        .build();
                }
            }
            throw new InsufficientResourceException(
                "No NUMA node has " + requestedCpus + " contiguous CPUs available");
        } else {
            // 非绑定模式：分配CPU share（Cgroup cpu.weight）
            return CpuSetAllocation.shared(requestedCpus);
        }
    }

    /**
     * 应用CPU Set配置到Cgroup
     */
    public void applyCpuSet(String cgroupPath, CpuSetAllocation allocation) {
        if (allocation.isExclusive()) {
            // 独占模式：设置cpuset.cpus和cpuset.mems
            String cpuSetStr = allocation.getCpuSet().stream()
                .sorted().map(String::valueOf).collect(Collectors.joining(","));
            writeCgroup(cgroupPath + "/cpuset.cpus", cpuSetStr);
            writeCgroup(cgroupPath + "/cpuset.mems", String.valueOf(allocation.getNumaNode()));
            // 禁用CPU迁移
            writeCgroup(cgroupPath + "/cpuset.cpu_exclusive", "1");
        }
    }
}
```

#### 3.4.3 应用错峰与重调度

```java
/**
 * 应用错峰调度：根据服务画像，将峰值时段互补的应用调度到同一节点
 * 重调度：运行中发现资源使用不均衡时，迁移Pod到更合适的节点
 */
public class ReschedulingController implements Reconciler {

    private final ServiceProfiler profiler;
    private final PodScheduler scheduler;

    /**
     * 定期检查节点资源均衡性，发现不均衡时触发重调度
     */
    @Override
    public ReconcileResult reconcile(String nodeKey) {
        NodeInfo node = nodeLister.get(nodeKey);
        NodeMetrics metrics = metricsCollector.getNodeMetrics(nodeKey);

        // 检查是否需要重调度
        if (!needsRescheduling(node, metrics)) {
            return ReconcileResult.requeueAfter(Duration.ofMinutes(10));
        }

        // 选择迁移候选Pod（低优先级、可迁移、对延迟不敏感的Pod）
        List<Pod> candidates = selectMigrationCandidates(node, metrics);

        for (Pod candidate : candidates) {
            // 找到更合适的目标节点
            ScheduleResult target = scheduler.schedule(candidate);
            if (target.isSuccess()) {
                // 在目标节点创建新Pod
                createPodOnNode(candidate, target.getNode());
                // 等待新Pod就绪
                waitForReady(candidate.getName(), Duration.ofMinutes(2));
                // 删除旧Pod
                deletePod(candidate);
            }
        }

        return ReconcileResult.requeueAfter(Duration.ofMinutes(10));
    }

    private boolean needsRescheduling(NodeInfo node, NodeMetrics metrics) {
        // CPU或内存使用率超过阈值
        return metrics.getCpuUtilization() > 0.85
            || metrics.getMemoryUtilization() > 0.90
            // 或者资源使用严重不均衡（CPU高但内存低，或反之）
            || Math.abs(metrics.getCpuUtilization() - metrics.getMemoryUtilization()) > 0.4;
    }
}
```

#### 3.4.4 干扰分析

```java
/**
 * 应用干扰分析：检测同节点应用间的资源干扰
 * 
 * 干扰类型：
 * - CPU干扰：共享LLC(Last Level Cache)导致缓存命中率下降
 * - 内存带宽干扰：带宽密集型应用抢占内存总线
 * - 网络干扰：共享网卡带宽竞争
 * - 磁盘I/O干扰：共享磁盘的I/O竞争
 */
public class InterferenceAnalyzer {

    /**
     * 分析节点上应用间的干扰程度
     */
    public InterferenceReport analyzeNode(String nodeName) {
        List<Pod> pods = getPodsByNode(nodeName);
        List<InterferenceRecord> records = new ArrayList<>();

        for (int i = 0; i < pods.size(); i++) {
            for (int j = i + 1; j < pods.size(); j++) {
                Pod podA = pods.get(i);
                Pod podB = pods.get(j);

                // LLC缓存干扰
                double llcMissRateA = getLlcMissRate(podA);
                double llcMissRateBaseline = getBaselineLlcMissRate(podA.getAppName());
                double llcInterference = llcMissRateA / llcMissRateBaseline;

                // 内存带宽干扰
                double memBandwidthA = getMemBandwidth(podA);
                double memBandwidthBaseline = getBaselineMemBandwidth(podA.getAppName());
                double memInterference = memBandwidthBaseline / memBandwidthA;

                if (llcInterference > 1.5 || memInterference > 1.3) {
                    records.add(InterferenceRecord.builder()
                        .podA(podA.getName())
                        .podB(podB.getName())
                        .llcInterferenceRatio(llcInterference)
                        .memBandwidthInterferenceRatio(memInterference)
                        .recommendation(llcInterference > 2.0 ?
                            "SEPARATE" : "MONITOR")
                        .build());
                }
            }
        }

        return new InterferenceReport(nodeName, records);
    }
}
```

#### 3.6.1 Linux Cgroup 资源限制

```java
/** Cgroup资源配置 */
public class CgroupResourceManager {
    /**
     * CPU限制:
     * - cpu.weight: 相对权重，CPU争抢时按权重分配（requests映射）
     * - cpu.max: "quota period"格式，如"50000 100000"=每100ms用50ms=0.5CPU（limits映射）
     */
    public void setCpuLimit(String path, long requestMilliCores, long limitMilliCores) {
        int weight = (int) Math.max(1, Math.min(10000, requestMilliCores * 1024 / 1000));
        writeCgroup(path + "/cpu.weight", String.valueOf(weight));
        if (limitMilliCores > 0) {
            long period = 100000, quota = limitMilliCores * period / 1000;
            writeCgroup(path + "/cpu.max", quota + " " + period);
        }
    }

    /**
     * 内存限制（不可压缩资源，超limit触发OOM Kill）:
     * - memory.max: 硬限制
     * - memory.high: 软限制(90%处，提前触发回收)
     * - memory.min: 最低保障（Guaranteed QoS Pod）
     */
    public void setMemoryLimit(String path, long requestBytes, long limitBytes) {
        if (limitBytes > 0) writeCgroup(path + "/memory.max", String.valueOf(limitBytes));
        if (limitBytes > 0) writeCgroup(path + "/memory.high",
            String.valueOf((long)(limitBytes * 0.9)));
        if (requestBytes > 0) writeCgroup(path + "/memory.min", String.valueOf(requestBytes));
    }
}
```

#### 3.6.2 QoS 等级与 OOM 行为

```java
/** QoS判定 */
public class QosClassifier {
    public QosClass classify(Pod pod) {
        boolean allGuaranteed = true, anySet = false;
        for (Container c : pod.getSpec().getContainers()) {
            ResourceRequirements r = c.getResources();
            if (r == null || r.getRequests() == null || r.getLimits() == null) {
                allGuaranteed = false; continue;
            }
            anySet = true;
            if (!r.getRequests().equals(r.getLimits())) allGuaranteed = false;
        }
        if (allGuaranteed && anySet) return GUARANTEED;
        if (anySet) return BURSTABLE;
        return BEST_EFFORT;
    }
}
```

### 3.9 自动扩缩容

#### 3.9.1 HPA (Horizontal Pod Autoscaler)

核心算法：`期望副本数 = ceil(当前副本数 * 当前指标值 / 目标指标值)`

```java
/** HPA控制器（每15s执行一次） */
public class HorizontalPodAutoscaler implements Reconciler {
    private static final double TOLERANCE = 0.1;

    @Override
    public ReconcileResult reconcile(String key) {
        HpaSpec hpa = hpaLister.get(key);
        int current = deployment.getSpec().getReplicas();
        int desired = current;

        for (MetricSpec metric : hpa.getMetrics()) {
            double ratio;
            switch (metric.getType()) {
                case "Resource" -> {
                    double avgUtil = getAvgUtilization(metric.getResource().getName());
                    ratio = avgUtil / metric.getResource().getTarget().getAverageUtilization();
                }
                case "Pods" -> {
                    ratio = getCurrentValue() / metric.getPods().getTarget().getAverageValue();
                }
                case "External" -> {
                    ratio = getExternalValue() / metric.getExternal().getTarget().getValue();
                }
                default -> { ratio = 1.0; }
            }
            if (Math.abs(ratio - 1.0) > TOLERANCE)
                desired = Math.max(desired, (int) Math.ceil(current * ratio));
        }
        desired = clamp(desired, hpa.getMinReplicas(), hpa.getMaxReplicas());

        // 防抖: 扩容冷却3min，缩容冷却5min
        if (desired > current && !cooldownExpired(SCALE_UP_COOLDOWN))
            return requeueAfter(SCALE_UP_COOLDOWN);
        if (desired < current && !cooldownExpired(SCALE_DOWN_COOLDOWN))
            return requeueAfter(SCALE_DOWN_COOLDOWN);
        if (desired < current) desired = Math.max(desired, current - current / 2);
        if (desired != current) scaleDeployment(deployment, desired);
        return ReconcileResult.requeueAfter(Duration.ofSeconds(15));
    }
}
```

#### 3.9.2 Cluster Autoscaler

```java
/** 集群自动扩缩容 */
public class ClusterAutoscaler {
    /** 扩容: Pending Pod因资源不足无法调度时，模拟添加新节点 */
    public ScaleUpResult checkScaleUp() {
        List<Pod> pending = podLister.list().stream()
            .filter(p -> "Pending".equals(p.getStatus().getPhase()))
            .filter(this::isUnschedulableDueToResources)
            .collect(Collectors.toList());
        if (pending.isEmpty()) return ScaleUpResult.notNeeded();

        for (NodeGroup group : nodeGroupManager.list()) {
            if (group.getCurrentSize() >= group.getMaxSize()) continue;
            NodeInfo simulated = group.getTemplateNode();
            long schedulable = pending.stream()
                .filter(p -> scheduler.canSchedule(p, simulated)).count();
            if (schedulable > 0) {
                int needed = estimateNodesNeeded(pending, simulated);
                nodeGroupManager.setSize(group,
                    Math.min(group.getCurrentSize() + needed, group.getMaxSize()));
                return ScaleUpResult.scaled(group, needed);
            }
        }
        return ScaleUpResult.noSuitableGroup();
    }

    /** 缩容: CPU和内存利用率都低于50%且持续10min */
    public ScaleDownResult checkScaleDown() {
        for (Node node : nodeLister.list()) {
            if (getCpuUtil(node) < 0.5 && getMemUtil(node) < 0.5
                && unneededFor(node, Duration.ofMinutes(10))) {
                List<Pod> pods = getPodsOnNode(node);
                boolean allMovable = pods.stream().allMatch(p ->
                    !isOwnedByDaemonSet(p) && !usesLocalStorage(p)
                    && canEvictWithPdb(p) && hasController(p));
                if (allMovable) {
                    cordonNode(node); drainNode(node); deleteNode(node);
                    return ScaleDownResult.scaled(node);
                }
            }
        }
        return ScaleDownResult.notNeeded();
    }
}
```

## 4. 异常处理与容错

### 4.1 Pod 驱逐与抢占

节点资源压力（DiskPressure/MemoryPressure）时，kubelet 按 QoS 等级驱逐 Pod：BestEffort 最先 -> Burstable（按使用超出 requests 比例）-> Guaranteed 最后。高优先级 Pod 可抢占低优先级 Pod 的资源。

### 4.2 节点故障处理

```
时间线：
│ kubelet心跳停止  │ 40s: NotReady    │ 5min: 开始驱逐    │ Pod重新调度
│                │                  │ Pod              │ 到健康节点

关键参数：
  --node-monitor-period=5s        Node Controller检查间隔
  --node-monitor-grace-period=40s 心跳超时阈值
  --pod-eviction-timeout=5m0s     驱逐等待时间
```

kubelet 每 10s 发送心跳（更新 Lease 对象），Node Controller 每 5s 检查。40s 无心跳标记 NotReady，等待 5min 后开始驱逐，Deployment Controller 在其他节点创建新 Pod。

### 4.4 雪崩防护

```java
/**
 * 集群级雪崩防护
 * 防止批量节点故障或批量驱逐引发连锁反应
 */
public class CascadeFailureProtector {

    private static final double UNHEALTHY_THRESHOLD = 0.3; // 30%节点异常时触发保护
    private final AtomicInteger recentEvictions = new AtomicInteger(0);

    /**
     * 检查是否触发雪崩保护
     */
    public boolean shouldActivateProtection() {
        long totalNodes = nodeLister.list().size();
        long unhealthyNodes = nodeLister.list().stream()
            .filter(n -> !isNodeReady(n)).count();

        // 超过30%节点异常，可能是网络分区而非真实故障
        if ((double) unhealthyNodes / totalNodes > UNHEALTHY_THRESHOLD) {
            alertManager.critical(String.format(
                "Cascade protection activated: %d/%d nodes unhealthy",
                unhealthyNodes, totalNodes));
            return true;
        }

        // 短时间内大量驱逐
        if (recentEvictions.get() > totalNodes * 0.1) {
            alertManager.critical("Too many evictions in short period");
            return true;
        }

        return false;
    }

    /**
     * 保护模式下的行为：
     * 1. 暂停所有自动驱逐
     * 2. 暂停Cluster Autoscaler缩容
     * 3. 通知运维人工介入
     */
    public void activateProtection() {
        pauseEviction();
        pauseClusterScaleDown();
        alertManager.page("Cascade failure protection activated. Manual intervention needed.");
    }
}
```

```java
        return ResourceRecommendation.builder()
            .cpuRequest(cpuRequest).cpuLimit(cpuLimit)
            .memRequest(memRequest).memLimit(memLimit)
            .confidence(calculateConfidence(profile))
            .estimatedSaving(calculateSaving(appName, cpuRequest, memRequest))

    }

    /**
     * 混合部署优化：将互补服务调度到同一节点
     */
    public List<CoLocationPair> findCoLocationPairs() {
        List<ServiceProfile> profiles = getAllServiceProfiles();
        List<CoLocationPair> pairs = new ArrayList<>();

        for (int i = 0; i < profiles.size(); i++) {
            for (int j = i + 1; j < profiles.size(); j++) {
                if (profiler.isComplementary(profiles.get(i), profiles.get(j))) {
                    pairs.add(new CoLocationPair(
                        profiles.get(i).getAppName(),
                        profiles.get(j).getAppName(),
                        calculateUtilizationGain(profiles.get(i), profiles.get(j))));
                }
            }
        }

        return pairs.stream()
            .sorted(Comparator.comparingDouble(CoLocationPair::getGain).reversed())
            .collect(Collectors.toList());
    }
```

#### 7.1.2 镜像构建与推送（Java 实现）

```java
/**
 * 镜像构建与推送服务
 * 
 * 全链路流程：
 * 1. Dockerfile 上下文打包
 * 2. docker build 构建镜像（多阶段）
 * 3. docker tag 打标签（含 Git commit SHA，保证可追溯）
 * 4. docker push 推送到企业镜像仓库
 * 5. 镜像安全扫描
 * 6. 更新部署清单（Deployment YAML 中镜像引用）
 */
public class ImageBuildPushService {

    private static final Logger log = LoggerFactory.getLogger(ImageBuildPushService.class);
    private final RegistryClient registryClient;
    private final ImageSecurityScanner securityScanner;
    private final IdempotentExecutor idempotentExecutor;

    /**
     * 构建并推送镜像
     * 
     * 幂等控制：基于 gitCommitSha + dockerfileHash 生成唯一构建ID，
     * 同一 commit 重复触发不会重复构建。
     */
    public BuildPushResult buildAndPush(BuildPushRequest request) {
        // ---- 幂等检查 ----
        String buildId = generateBuildId(request);
        IdempotentResult idempotentResult = idempotentExecutor.checkAndMark(buildId);
        if (idempotentResult.isAlreadyProcessed()) {
            log.info("[BUILD_IDEMPOTENT] buildId={}, skip duplicate build, image={}",
                buildId, idempotentResult.getCachedResult().getImageRef());
            return BuildPushResult.cached(idempotentResult.getCachedResult());
        }

        String imageRef = String.format("%s/%s:%s",
            registryClient.getRegistryHost(),
            request.getAppName(),
            request.getGitCommitSha().substring(0, 8));

        try {
            // ---- Step 1: 构建镜像 ----
            log.info("[BUILD_START] buildId={}, appName={}, context={}",
                buildId, request.getAppName(), request.getContextPath());

            BuildResult buildResult = dockerBuild(request, imageRef);
            if (buildResult.getExitCode() != 0) {
                throw new ImageBuildException(
                    "Docker build failed: " + buildResult.getStderr());
            }
            log.info("[BUILD_SUCCESS] buildId={}, imageRef={}, size={}MB, duration={}ms",
                buildId, imageRef, buildResult.getImageSizeMB(),
                buildResult.getDurationMs());

            // ---- Step 2: 推送镜像 ----
            log.info("[PUSH_START] buildId={}, imageRef={}", buildId, imageRef);
            PushResult pushResult = dockerPush(imageRef, request.getRegistryCreds());
            if (pushResult.getExitCode() != 0) {
                throw new ImagePushException(
                    "Docker push failed: " + pushResult.getStderr());
            }
            log.info("[PUSH_SUCCESS] buildId={}, imageRef={}, digest={}, duration={}ms",
                buildId, imageRef, pushResult.getDigest(), pushResult.getDurationMs());

            // ---- Step 3: 镜像安全扫描 ----
            SecurityScanResult scanResult = securityScanner.scan(imageRef);
            if (scanResult.hasCriticalVulnerabilities()) {
                log.error("[SECURITY_SCAN_FAILED] buildId={}, imageRef={}, criticalVulns={}",
                    buildId, imageRef, scanResult.getCriticalCount());
                throw new SecurityScanException(
                    "Image has " + scanResult.getCriticalCount() + " critical vulnerabilities");
            }
            log.info("[SECURITY_SCAN_PASSED] buildId={}, imageRef={}, vulns={}",
                buildId, imageRef, scanResult.getTotalVulnerabilities());

            // ---- Step 4: 缓存构建结果（幂等） ----
            BuildPushResult result = BuildPushResult.success(imageRef, pushResult.getDigest());
            idempotentExecutor.cacheResult(buildId, result);

            return result;

        } catch (ImageBuildException e) {
            log.error("[BUILD_FAILED] buildId={}, error={}", buildId, e.getMessage(), e);
            idempotentExecutor.markFailed(buildId, e.getMessage());
            throw e;
        } catch (ImagePushException e) {
            log.error("[PUSH_FAILED] buildId={}, imageRef={}, error={}",
                buildId, imageRef, e.getMessage(), e);
            idempotentExecutor.markFailed(buildId, e.getMessage());
            throw e;
        } catch (SecurityScanException e) {
            log.error("[SECURITY_BLOCKED] buildId={}, imageRef={}, error={}",
                buildId, imageRef, e.getMessage(), e);
            idempotentExecutor.markFailed(buildId, e.getMessage());
            throw e;
        } catch (Exception e) {
            log.error("[BUILD_UNEXPECTED_ERROR] buildId={}, error={}",
                buildId, e.getMessage(), e);
            idempotentExecutor.markFailed(buildId, e.getMessage());
            throw new RuntimeException("Unexpected build error", e);
        }
    }

    private BuildResult dockerBuild(BuildPushRequest request, String imageRef) {
        List<String> cmd = List.of("docker", "build",
            "-t", imageRef,
            "-f", request.getDockerfilePath(),
            "--label", "git.commit=" + request.getGitCommitSha(),
            "--label", "build.timestamp=" + Instant.now().toString(),
            "--label", "build.id=" + generateBuildId(request),
            request.getContextPath());

        ProcessResult pr = ProcessExecutor.execute(cmd, Duration.ofMinutes(15));
        return BuildResult.builder()
            .exitCode(pr.getExitCode())
            .stdout(pr.getStdout())
            .stderr(pr.getStderr())
            .durationMs(pr.getDurationMs())
            .imageSizeMB(queryImageSize(imageRef))
            .build();
    }

    private PushResult dockerPush(String imageRef, RegistryCredentials creds) {
        // 先登录
        ProcessExecutor.execute(List.of("docker", "login",
            registryClient.getRegistryHost(),
            "-u", creds.getUsername(), "-p", creds.getPassword()),
            Duration.ofSeconds(30));

        ProcessResult pr = ProcessExecutor.execute(
            List.of("docker", "push", imageRef), Duration.ofMinutes(10));

        String digest = registryClient.getImageDigest(imageRef);
        return PushResult.builder()
            .exitCode(pr.getExitCode())
            .stderr(pr.getStderr())
            .digest(digest)
            .durationMs(pr.getDurationMs())
            .build();
    }

    /**
     * 幂等构建ID = sha256(appName + gitCommitSha + dockerfileHash)
     * 同一代码版本 + 同一Dockerfile 只构建一次
     */
    private String generateBuildId(BuildPushRequest request) {
        String raw = request.getAppName() + "|"
            + request.getGitCommitSha() + "|"
            + sha256(Files.readString(Path.of(request.getDockerfilePath())));
        return "build-" + sha256(raw).substring(0, 16);
    }
}
```

```java
/**
 * 滚动更新控制器
 * 
 * 职责：
 * 1. 触发 Deployment 滚动更新（更新镜像引用）
 * 2. 监控滚动更新进度（可用副本数、就绪副本数）
 * 3. 异常时自动回滚
 * 4. 全程结构化日志 + 幂等控制
 */
public class RollingUpdateController {

    private static final Logger log = LoggerFactory.getLogger(RollingUpdateController.class);
    private final KubernetesClient client;
    private final AlertManager alertManager;
    private final IdempotentExecutor idempotentExecutor;

    /**
     * 触发滚动更新
     * 
     * 幂等控制：deployKey = deploymentName + newImageDigest
     * 同一镜像 digest 的重复部署请求不会重复触发滚动更新。
     */
    public RolloutResult rollout(RolloutRequest request) {
        String deployKey = request.getDeploymentName() + "|" + request.getImageDigest();
        IdempotentResult idempotent = idempotentExecutor.checkAndMark(deployKey);
        if (idempotent.isAlreadyProcessed()) {
            log.info("[ROLLOUT_IDEMPOTENT] deployKey={}, skip. Previous rollout already done.",
                deployKey);
            return RolloutResult.cached(idempotent.getCachedResult());
        }

        String namespace = request.getNamespace();
        String deployName = request.getDeploymentName();
        String newImage = request.getNewImageRef();

        log.info("[ROLLOUT_START] namespace={}, deployment={}, newImage={}, deployKey={}",
            namespace, deployName, newImage, deployKey);

        try {
            // ---- Step 1: 更新 Deployment 镜像引用 ----
            Deployment deployment = client.apps().deployments()
                .inNamespace(namespace).withName(deployName).get();

            if (deployment == null) {
                throw new DeploymentNotFoundException(
                    "Deployment not found: " + namespace + "/" + deployName);
            }

            String oldImage = deployment.getSpec().getTemplate().getSpec()
                .getContainers().get(0).getImage();
            log.info("[ROLLOUT_IMAGE_CHANGE] deployment={}, oldImage={}, newImage={}",
                deployName, oldImage, newImage);

            // 记录旧版本用于回滚
            String rollbackKey = saveRollbackSnapshot(deployment);

            // 更新镜像引用（触发滚动更新）
            client.apps().deployments().inNamespace(namespace)
                .withName(deployName)
                .edit(d -> {
                    d.getSpec().getTemplate().getSpec()
                        .getContainers().get(0).setImage(newImage);
                    // 更新版本标签
                    d.getSpec().getTemplate().getMetadata().getLabels()
                        .put("version", request.getVersionLabel());
                    // 注入部署追踪ID
                    d.getMetadata().getAnnotations()
                        .put("platform/last-rollout", Instant.now().toString());
                    return d;
                });

            log.info("[ROLLOUT_TRIGGERED] deployment={}, waiting for rollout to complete...",
                deployName);

            // ---- Step 2: 等待滚动更新完成 ----
            RolloutStatus status = waitForRollout(namespace, deployName,
                Duration.ofMinutes(10));

            if (status.isSuccess()) {
                log.info("[ROLLOUT_SUCCESS] deployment={}, updatedReplicas={}, readyReplicas={}, duration={}ms",
                    deployName, status.getUpdatedReplicas(), status.getReadyReplicas(),
                    status.getDurationMs());

                RolloutResult result = RolloutResult.success(
                    deployName, oldImage, newImage, status);
                idempotentExecutor.cacheResult(deployKey, result);
                return result;

            } else {
                // ---- Step 3: 滚动更新失败，自动回滚 ----
                log.error("[ROLLOUT_FAILED] deployment={}, reason={}, updated={}, desired={}",
                    deployName, status.getFailureReason(),
                    status.getUpdatedReplicas(), status.getDesiredReplicas());

                RollbackResult rollbackResult = rollback(namespace, deployName, rollbackKey);
                log.warn("[ROLLOUT_ROLLBACK_DONE] deployment={}, rolledBackTo={}",
                    deployName, oldImage);

                alertManager.critical(String.format(
                    "Rollout failed and rolled back: %s/%s, reason: %s",
                    namespace, deployName, status.getFailureReason()));

                idempotentExecutor.markFailed(deployKey, status.getFailureReason());
                return RolloutResult.failed(status, rollbackResult);
            }

        } catch (DeploymentNotFoundException e) {
            log.error("[ROLLOUT_DEPLOYMENT_NOT_FOUND] namespace={}, deployment={}",
                namespace, deployName, e);
            idempotentExecutor.markFailed(deployKey, e.getMessage());
            throw e;
        } catch (KubernetesClientException e) {
            log.error("[ROLLOUT_K8S_ERROR] namespace={}, deployment={}, code={}, message={}",
                namespace, deployName, e.getCode(), e.getMessage(), e);
            idempotentExecutor.markFailed(deployKey, e.getMessage());
            throw e;
        } catch (Exception e) {
            log.error("[ROLLOUT_UNEXPECTED_ERROR] namespace={}, deployment={}, error={}",
                namespace, deployName, e.getMessage(), e);
            idempotentExecutor.markFailed(deployKey, e.getMessage());
            throw new RuntimeException("Unexpected rollout error", e);
        }
    }

    /**
     * 等待滚动更新完成
     * 
     * 判定逻辑：
     * - updatedReplicas == desiredReplicas (所有Pod已更新)
     * - readyReplicas == desiredReplicas (所有Pod已就绪)
     * - availableReplicas == desiredReplicas (所有Pod可用)
     * 超时则判定失败
     */
    private RolloutStatus waitForRollout(String namespace, String deployName,
                                          Duration timeout) {
        long deadline = System.currentTimeMillis() + timeout.toMillis();
        long startTime = System.currentTimeMillis();

        while (System.currentTimeMillis() < deadline) {
            Deployment dep = client.apps().deployments()
                .inNamespace(namespace).withName(deployName).get();

            DeploymentStatus status = dep.getStatus();
            int desired = dep.getSpec().getReplicas();
            int updated = status.getUpdatedReplicas() != null ? status.getUpdatedReplicas() : 0;
            int ready = status.getReadyReplicas() != null ? status.getReadyReplicas() : 0;
            int available = status.getAvailableReplicas() != null
                ? status.getAvailableReplicas() : 0;

            log.debug("[ROLLOUT_PROGRESS] deployment={}, desired={}, updated={}, ready={}, available={}",
                deployName, desired, updated, ready, available);

            // 检查是否有Pod处于异常状态
            if (status.getConditions() != null) {
                for (DeploymentCondition cond : status.getConditions()) {
                    if ("ReplicaFailure".equals(cond.getType())
                        && "True".equals(cond.getStatus())) {
                        return RolloutStatus.failed(
                            "ReplicaFailure: " + cond.getMessage(), startTime);
                    }
                }
            }

            // 成功判定
            if (updated == desired && ready == desired && available == desired) {
                return RolloutStatus.success(updated, ready, available, startTime);
            }

            try { Thread.sleep(2000); } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return RolloutStatus.failed("Interrupted", startTime);
            }
        }

        return RolloutStatus.failed("Rollout timed out after " + timeout, startTime);
    }

    /**
     * 回滚到上一个版本
     */
    private RollbackResult rollback(String namespace, String deployName, String rollbackKey) {
        Deployment snapshot = loadRollbackSnapshot(rollbackKey);
        client.apps().deployments().inNamespace(namespace)
            .withName(deployName)
            .patch(snapshot);
        return RollbackResult.success(snapshot.getSpec().getTemplate().getSpec()
            .getContainers().get(0).getImage());
    }

    private String saveRollbackSnapshot(Deployment deployment) {
        String key = "rollback-" + deployment.getMetadata().getName() + "-"
            + System.currentTimeMillis();
        rollbackStore.save(key, deployment);
        return key;
    }
}
```

#### 7.1.4 健康检查端点实现

```java
/**
 * 应用健康检查端点
 * 
 * 三级健康检查：
 * - liveness: 进程是否存活（失败 → 重启容器）
 * - readiness: 是否准备好接收流量（失败 → 摘除流量）
 * - startup: 启动阶段保护（JVM预热期不触发liveness失败）
 */
@RestController
@RequestMapping("/actuator/health")
public class HealthCheckController {

    private static final Logger log = LoggerFactory.getLogger(HealthCheckController.class);
    private final ApplicationContext applicationContext;
    private final DataSource dataSource;
    private final RedisTemplate<String, String> redisTemplate;
    private final AtomicBoolean startupCompleted = new AtomicBoolean(false);

    /**
     * 启动健康检查
     * 在应用完全启动前，liveness 检查依赖此探针保护
     */
    @GetMapping("/liveness")
    public ResponseEntity<HealthResponse> liveness() {
        if (!startupCompleted.get()) {
            // 启动阶段：返回200但不表示就绪
            return ResponseEntity.ok(HealthResponse.up("STARTING"));
        }
        // 运行阶段：检查JVM关键指标
        Runtime runtime = Runtime.getRuntime();
        long usedMem = runtime.totalMemory() - runtime.freeMemory();
        long maxMem = runtime.maxMemory();
        double memRatio = (double) usedMem / maxMem;

        if (memRatio > 0.95) {
            log.error("[LIVENESS_FAIL] memoryUsageRatio={}, used={}MB, max={}MB",
                String.format("%.2f", memRatio), usedMem / 1048576, maxMem / 1048576);
            return ResponseEntity.status(503)
                .body(HealthResponse.down("MEMORY_CRITICAL"));
        }

        return ResponseEntity.ok(HealthResponse.up("RUNNING"));
    }

    /**
     * 就绪健康检查
     * 检查所有外部依赖连通性，任一失败则摘除流量
     */
    @GetMapping("/readiness")
    public ResponseEntity<HealthResponse> readiness() {
        if (!startupCompleted.get()) {
            return ResponseEntity.status(503)
                .body(HealthResponse.down("NOT_STARTED"));
        }

        List<HealthCheck> checks = List.of(
            checkDatabase(),
            checkRedis(),
            checkDownstreamServices()
        );

        List<HealthCheck> failed = checks.stream()
            .filter(c -> !c.isHealthy())
            .collect(Collectors.toList());

        if (!failed.isEmpty()) {
            log.warn("[READINESS_FAIL] failedChecks={}",
                failed.stream().map(HealthCheck::getName).collect(Collectors.joining(",")));
            return ResponseEntity.status(503)
                .body(HealthResponse.down(failed));
        }

        return ResponseEntity.ok(HealthResponse.up("READY"));
    }

    /**
     * 应用启动完成后调用（ApplicationReadyEvent监听）
     */
    @EventListener(ApplicationReadyEvent.class)
    public void onApplicationReady() {
        startupCompleted.set(true);
        log.info("[STARTUP_COMPLETE] liveness gate opened, app ready to serve traffic");
    }

    /**
     * 优雅下线注册
     * preStop hook 调用此接口，从服务发现注销
     */
    @PostMapping("/deregister")
    public ResponseEntity<String> deregister() {
        log.info("[DEREGISTER_START] removing from service discovery");
        try {
            serviceRegistry.deregister(applicationContext.getId());
            log.info("[DEREGISTER_SUCCESS] removed from service discovery");
            return ResponseEntity.ok("deregistered");
        } catch (Exception e) {
            log.error("[DEREGISTER_FAILED] error={}", e.getMessage(), e);
            return ResponseEntity.status(500).body("deregister failed: " + e.getMessage());
        }
    }

    private HealthCheck checkDatabase() {
        try (Connection conn = dataSource.getConnection()) {
            boolean valid = conn.isValid(2);
            return new HealthCheck("database", valid,
                valid ? null : "Connection invalid");
        } catch (SQLException e) {
            return new HealthCheck("database", false, e.getMessage());
        }
    }

    private HealthCheck checkRedis() {
        try {
            String result = redisTemplate.opsForValue().get("health-check-key");
            return new HealthCheck("redis", true, null);
        } catch (Exception e) {
            return new HealthCheck("redis", false, e.getMessage());
        }
    }

    private HealthCheck checkDownstreamServices() {
        // 检查下游服务连通性（简化实现）
        return new HealthCheck("downstream", true, null);
    }

    private record HealthCheck(String name, boolean healthy, String message) {
        public boolean isHealthy() { return healthy; }
        public String getName() { return name; }
    }

    private record HealthResponse(String status, String state, List<HealthCheck> checks) {
        static HealthResponse up(String state) {
            return new HealthResponse("UP", state, List.of());
        }
        static HealthResponse down(String reason) {
            return new HealthResponse("DOWN", reason, List.of());
        }
        static HealthResponse down(List<HealthCheck> failed) {
            return new HealthResponse("DOWN", "DEPENDENCIES_UNHEALTHY", failed);
        }
    }
}
```

```java
/**
 * 容器指标采集服务
 * 
 * 采集链路：
 * Pod内cAdvisor → kubelet /metrics/cadvisor → Metrics Server → HPA查询
 * 
 * 自定义指标链路：
 * Pod应用暴露 /metrics → Prometheus抓取 → Prometheus Adapter → HPA查询
 */
public class MetricsCollectionService {

    private static final Logger log = LoggerFactory.getLogger(MetricsCollectionService.class);
    private final PrometheusClient prometheusClient;
    private final MetricsServerClient metricsServerClient;
    private final TimeSeriesStore timeSeriesStore;

    /**
     * 采集Pod级CPU/内存指标
     * 通过kubelet的cAdvisor端点获取容器级资源使用数据
     */
    @Scheduled(fixedRate = 15000) // 每15s采集一次（与HPA控制循环对齐）
    public void collectPodMetrics() {
        try {
            List<PodMetrics> podMetricsList = metricsServerClient.getAllPodMetrics();

            for (PodMetrics pm : podMetricsList) {
                try {
                    ContainerMetrics cm = pm.getContainers().get(0);
                    long cpuNano = cm.getUsage().get("cpu").getAmount();
                    long memBytes = cm.getUsage().get("memory").getAmount();

                    // 转换为标准单位
                    double cpuCores = cpuNano / 1_000_000_000.0;
                    double cpuUtilization = cpuCores / parseCpuRequest(cm) * 100;

                    // 写入时序数据库
                    timeSeriesStore.write("pod_cpu_utilization",
                        pm.getName(), Instant.now(), cpuUtilization);
                    timeSeriesStore.write("pod_memory_bytes",
                        pm.getName(), Instant.now(), (double) memBytes);

                    log.debug("[METRICS_COLLECT] pod={}, cpuUtilization={}%, mem={}MB",
                        pm.getName(),
                        String.format("%.1f", cpuUtilization),
                        memBytes / 1048576);

                } catch (Exception e) {
                    log.warn("[METRICS_COLLECT_FAILED] pod={}, error={}",
                        pm.getName(), e.getMessage());
                }
            }

            log.info("[METRICS_BATCH_DONE] collected {} pods, duration={}ms",
                podMetricsList.size(),
                System.currentTimeMillis() - startTime);

        } catch (MetricsServerUnavailableException e) {
            log.error("[METRICS_SERVER_UNAVAILABLE] retrying next cycle. error={}",
                e.getMessage());
        } catch (Exception e) {
            log.error("[METRICS_COLLECT_ERROR] unexpected error", e);
        }
    }

    /**
     * 采集自定义QPS指标
     * 从Prometheus查询应用暴露的http_requests_per_second
     */
    public double queryQps(String appName, String namespace) {
        String query = String.format(
            "sum(rate(http_requests_total{app=\"%s\",namespace=\"%s\"}[2m]))",
            appName, namespace);

        try {
            PrometheusQueryResult result = prometheusClient.query(query);
            if (result.getValues().isEmpty()) {
                log.warn("[QPS_QUERY_EMPTY] app={}, namespace={}", appName, namespace);
                return 0.0;
            }
            double qps = result.getValues().get(0).getValue();
            log.debug("[QPS_QUERY] app={}, qps={}", appName, String.format("%.2f", qps));
            return qps;
        } catch (PrometheusQueryException e) {
            log.error("[QPS_QUERY_FAILED] app={}, query={}, error={}",
                appName, query, e.getMessage());
            return -1; // 返回-1表示查询失败，HPA决策时忽略此指标
        }
    }
}
```

#### 7.2.3 扩缩容决策与执行（Java 实现）

```java
/**
 * 弹性伸缩决策与执行服务
 * 
 * 完整链路：
 * 1. 采集多维度指标（CPU、QPS、自定义指标）
 * 2. 计算期望副本数
 * 3. 防抖检查（冷却期判断）
 * 4. 执行扩容/缩容
 * 5. 等待Pod就绪并更新负载均衡
 * 6. 缩容时优雅摘除Pod
 */
public class AutoScalingService {

    private static final Logger log = LoggerFactory.getLogger(AutoScalingService.class);
    private final KubernetesClient client;
    private final MetricsCollectionService metricsService;
    private final AlertManager alertManager;
    private final IdempotentExecutor idempotentExecutor;

    // 扩容冷却期：60s
    private static final Duration SCALE_UP_COOLDOWN = Duration.ofSeconds(60);
    // 缩容冷却期：300s
    private static final Duration SCALE_DOWN_COOLDOWN = Duration.ofSeconds(300);
    // 指标容忍度：10%以内不触发伸缩
    private static final double TOLERANCE = 0.1;

    // 记录每个应用的上次扩容/缩容时间
    private final ConcurrentMap<String, Instant> lastScaleUpTime = new ConcurrentHashMap<>();
    private final ConcurrentMap<String, Instant> lastScaleDownTime = new ConcurrentHashMap<>();

    /**
     * 伸缩决策与执行（每15s调用一次）
     * 
     * 幂等控制：scaleKey = appName + desiredReplicas
     * 如果期望副本数与当前一致，不执行任何操作。
     */
    @Scheduled(fixedRate = 15000)
    public void scalingLoop() {
        List<HpaConfig> hpaConfigs = getAllHpaConfigs();

        for (HpaConfig hpa : hpaConfigs) {
            try {
                evaluateAndScale(hpa);
            } catch (Exception e) {
                log.error("[SCALING_ERROR] app={}, error={}",
                    hpa.getAppName(), e.getMessage(), e);
                alertManager.warn(String.format("Scaling error for %s: %s",
                    hpa.getAppName(), e.getMessage()));
            }
        }
    }

    private void evaluateAndScale(HpaConfig hpa) {
        String appName = hpa.getAppName();
        String namespace = hpa.getNamespace();

        // ---- Step 1: 获取当前状态 ----
        Deployment dep = client.apps().deployments()
            .inNamespace(namespace).withName(appName).get();
        if (dep == null) {
            log.warn("[SCALING_SKIP] deployment not found: {}/{}", namespace, appName);
            return;
        }

        int currentReplicas = dep.getSpec().getReplicas();
        int readyReplicas = dep.getStatus().getReadyReplicas() != null
            ? dep.getStatus().getReadyReplicas() : 0;

        // ---- Step 2: 采集指标 ----
        double cpuUtilization = metricsService.getAvgCpuUtilization(appName, namespace);
        double qps = metricsService.queryQps(appName, namespace);

        log.debug("[SCALING_EVALUATE] app={}, current={}, ready={}, cpuUtil={}%, qps={}",
            appName, currentReplicas, readyReplicas,
            String.format("%.1f", cpuUtilization), String.format("%.1f", qps));

        // ---- Step 3: 计算期望副本数 ----
        int desiredReplicas = currentReplicas;

        // CPU指标决策
        if (cpuUtilization >= 0) {
            double cpuRatio = cpuUtilization / hpa.getCpuTargetUtilization();
            if (Math.abs(cpuRatio - 1.0) > TOLERANCE) {
                desiredReplicas = Math.max(desiredReplicas,
                    (int) Math.ceil(currentReplicas * cpuRatio));
            }
        }

        // QPS指标决策（取两者中较大的）
        if (qps >= 0 && hpa.getQpsTarget() > 0) {
            double totalQps = qps * currentReplicas;
            double qpsRatio = totalQps / (hpa.getQpsTarget() * currentReplicas);
            if (Math.abs(qpsRatio - 1.0) > TOLERANCE) {
                desiredReplicas = Math.max(desiredReplicas,
                    (int) Math.ceil(currentReplicas * qpsRatio));
            }
        }

        // 限制在[min, max]范围内
        desiredReplicas = Math.max(hpa.getMinReplicas(),
            Math.min(hpa.getMaxReplicas(), desiredReplicas));

        // ---- Step 4: 幂等检查 ----
        if (desiredReplicas == currentReplicas) {
            log.debug("[SCALING_NO_CHANGE] app={}, current={} (no scaling needed)",
                appName, currentReplicas);
            return;
        }

        // ---- Step 5: 防抖检查 ----
        if (desiredReplicas > currentReplicas) {
            // 扩容方向
            Instant lastScaleUp = lastScaleUpTime.get(appName);
            if (lastScaleUp != null && lastScaleUp.plus(SCALE_UP_COOLDOWN).isAfter(Instant.now())) {
                log.info("[SCALING_COOLDOWN] app={}, scaleUp in cooldown, skip. lastScaleUp={}",
                    appName, lastScaleUp);
                return;
            }
            // 扩容执行
            executeScaleUp(namespace, appName, currentReplicas, desiredReplicas,
                cpuUtilization, qps, hpa);

        } else {
            // 缩容方向
            Instant lastScaleDown = lastScaleDownTime.get(appName);
            if (lastScaleDown != null && lastScaleDown.plus(SCALE_DOWN_COOLDOWN).isAfter(Instant.now())) {
                log.info("[SCALING_COOLDOWN] app={}, scaleDown in cooldown, skip. lastScaleDown={}",
                    appName, lastScaleDown);
                return;
            }
            // 缩容时逐步进行：最多缩容50%
            int maxScaleDown = currentReplicas / 2;
            int actualDesired = Math.max(desiredReplicas, currentReplicas - maxScaleDown);
            executeScaleDown(namespace, appName, currentReplicas, actualDesired,
                cpuUtilization, qps, hpa);
        }
    }

    /**
     * 执行扩容
     */
    private void executeScaleUp(String namespace, String appName,
                                 int current, int desired,
                                 double cpuUtil, double qps, HpaConfig hpa) {
        String scaleKey = appName + "|scaleUp|" + desired + "|" + Instant.now().getEpochSecond();
        log.info("[SCALE_UP_START] app={}, current={}, desired={}, cpuUtil={}%, qps={}, reason={}",
            appName, current, desired, String.format("%.1f", cpuUtil),
            String.format("%.1f", qps),
            cpuUtil > hpa.getCpuTargetUtilization() ? "CPU_HIGH" : "QPS_HIGH");

        try {
            // 更新Deployment副本数
            client.apps().deployments().inNamespace(namespace)
                .withName(appName)
                .scale(desired);

            log.info("[SCALE_UP_APPLIED] app={}, replicas={}->{}", appName, current, desired);

            // 等待新Pod就绪
            boolean allReady = waitForReplicasReady(namespace, appName, desired,
                Duration.ofMinutes(5));

            if (allReady) {
                log.info("[SCALE_UP_SUCCESS] app={}, all {} replicas ready,Endpoints updated",
                    appName, desired);
                lastScaleUpTime.put(appName, Instant.now());
                alertManager.info(String.format("Scaled up %s: %d -> %d (CPU=%.1f%%, QPS=%.1f)",
                    appName, current, desired, cpuUtil, qps));
            } else {
                log.error("[SCALE_UP_TIMEOUT] app={}, not all replicas ready within timeout",
                    appName);
                alertManager.warn(String.format(
                    "Scale up %s: %d -> %d, but not all replicas ready",
                    appName, current, desired));
                // 不回滚扩容，等待下一轮检查
            }

        } catch (KubernetesClientException e) {
            log.error("[SCALE_UP_K8S_ERROR] app={}, code={}, message={}",
                appName, e.getCode(), e.getMessage(), e);
            throw e;
        }
    }

    /**
     * 执行缩容
     * 
     * 缩容比扩容更危险：需要确保被缩容的Pod优雅退出
     */
    private void executeScaleDown(String namespace, String appName,
                                   int current, int desired,
                                   double cpuUtil, double qps, HpaConfig hpa) {
        log.info("[SCALE_DOWN_START] app={}, current={}, desired={}, cpuUtil={}%, qps={}",
            appName, current, desired, String.format("%.1f", cpuUtil),
            String.format("%.1f", qps));

        try {
            // 缩容前检查：确保剩余Pod能承载当前流量
            double perPodQps = qps / current;
            double projectedPerPodQps = qps / desired;
            if (projectedPerPodQps > hpa.getQpsTarget() * 1.5) {
                log.warn("[SCALE_DOWN_ABORT] app={}, projected perPodQps={} exceeds safety threshold {}",
                    appName, String.format("%.1f", projectedPerPodQps),
                    hpa.getQpsTarget() * 1.5);
                return;
            }

            // 更新Deployment副本数
            client.apps().deployments().inNamespace(namespace)
                .withName(appName)
                .scale(desired);

            log.info("[SCALE_DOWN_APPLIED] app={}, replicas={}->{}, waiting for graceful termination",
                appName, current, desired);

            // 等待Pod优雅终止（preStop + terminationGracePeriodSeconds）
            boolean allTerminated = waitForReplicasReady(namespace, appName, desired,
                Duration.ofMinutes(3));

            if (allTerminated) {
                log.info("[SCALE_DOWN_SUCCESS] app={}, scaled to {}, Endpoints updated",
                    appName, desired);
                lastScaleDownTime.put(appName, Instant.now());
                alertManager.info(String.format("Scaled down %s: %d -> %d",
                    appName, current, desired));
            } else {
                log.warn("[SCALE_DOWN_TIMEOUT] app={}, some pods still terminating",
                    appName);
            }

        } catch (KubernetesClientException e) {
            log.error("[SCALE_DOWN_K8S_ERROR] app={}, code={}, message={}",
                appName, e.getCode(), e.getMessage(), e);
            throw e;
        }
    }

    /**
     * 等待副本数达到期望且全部就绪
     */
    private boolean waitForReplicasReady(String namespace, String appName,
                                           int expectedReplicas, Duration timeout) {
        long deadline = System.currentTimeMillis() + timeout.toMillis();

        while (System.currentTimeMillis() < deadline) {
            Deployment dep = client.apps().deployments()
                .inNamespace(namespace).withName(appName).get();
            int ready = dep.getStatus().getReadyReplicas() != null
                ? dep.getStatus().getReadyReplicas() : 0;

            log.debug("[WAIT_READY] app={}, expected={}, ready={}",
                appName, expectedReplicas, ready);

            if (ready >= expectedReplicas) {
                return true;
            }

            try { Thread.sleep(3000); } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return false;
            }
        }
        return false;
    }
}
```

```java
/**

public class LoadBalancerSyncService {

    private final EndpointsInformer endpointsInformer;

            namespace, serviceName, readyAddresses.size(), notReadyAddresses.size());

        // 验证：就绪地址数 >= minReplicas
        int minReplicas = getDeploymentMinReplicas(namespace, serviceName);
        if (readyAddresses.size() < minReplicas) {
            log.error("[ENDPOINTS_INSUFFICIENT] service={}, ready={} < minReplicas={}",
                serviceName, readyAddresses.size(), minReplicas);
            alertManager.critical(String.format(
                "Service %s has only %d ready endpoints (min=%d)",
                serviceName, readyAddresses.size(), minReplicas));
        }
    }

    /**
     * 监听Pod终止事件，确保优雅摘除
     */
    public void onPodTerminating(Pod pod) {
        String podName = pod.getMetadata().getName();
        String namespace = pod.getMetadata().getNamespace();
        String appName = pod.getMetadata().getLabels().get("app");

        log.info("[POD_TERMINATING] pod={}/{}, app={}", namespace, podName, appName);

        // 1. 等待Pod从Endpoints中移除（kube-controller-manager自动处理）
        boolean removed = waitForEndpointRemoval(namespace, appName, podName,
            Duration.ofSeconds(30));

        if (!removed) {
            log.warn("[ENDPOINT_STALE] pod={} still in Endpoints after 30s, force removing",
                podName);
            forceRemoveFromEndpoints(namespace, appName, podName);
        }

        // 2. 等待存量请求处理完成（检查Pod活跃连接数）
        boolean drained = waitForConnectionDrain(podName, Duration.ofSeconds(30));

        log.info("[POD_DRAIN_COMPLETE] pod={}, endpointRemoved={}, connectionDrained={}",
            podName, removed, drained);
    }

    private boolean waitForEndpointRemoval(String namespace, String serviceName,
                                             String podName, Duration timeout) {
        long deadline = System.currentTimeMillis() + timeout.toMillis();
        while (System.currentTimeMillis() < deadline) {
            Endpoints ep = client.endpoints()
                .inNamespace(namespace).withName(serviceName).get();
            boolean stillPresent = ep != null && ep.getSubsets().stream()
                .anyMatch(s -> s.getAddresses().stream()
                    .anyMatch(a -> a.getTargetRef() != null
                        && a.getTargetRef().getName().equals(podName)));
            if (!stillPresent) return true;
            try { Thread.sleep(2000); } catch (InterruptedException e) {
                Thread.currentThread().interrupt(); return false;
            }
        }
        return false;
    }
}
```

#### 7.3.1 Pod 异常检测与重启策略（Java 实现）

```java
/**
 * Pod故障自愈控制器
 * 
 * 职责：
 * 1. 监听Pod健康状态变更事件
 * 2. 容器级故障：liveness失败 → 重启容器（restartPolicy: Always）
 * 3. Pod级故障：CrashLoopBackOff → 诊断 → 修复或告警
 * 4. 节点级故障：Node NotReady → 触发Pod迁移
 * 5. 全程结构化日志 + 告警通知
 */
public class PodSelfHealingController {

    private static final Logger log = LoggerFactory.getLogger(PodSelfHealingController.class);
    private final KubernetesClient client;
    private final AlertManager alertManager;
    private final CrashLoopDiagnostician diagnostician;
    private final IdempotentExecutor idempotentExecutor;

    // CrashLoopBackOff 诊断阈值
    private static final int CRASH_LOOP_THRESHOLD = 5;
    // 记录每个Pod的重启历史
    private final ConcurrentMap<String, RestartHistory> restartHistoryMap = new ConcurrentHashMap<>();

    /**
     * 监听Pod状态变更事件
     * 
     * 通过Informer Watch机制实时感知Pod状态变化
     */
    public void onPodStatusChanged(Pod oldPod, Pod newPod) {
        String podName = newPod.getMetadata().getName();
        String namespace = newPod.getMetadata().getNamespace();
        String nodeName = newPod.getSpec().getNodeName();

        PodStatus status = newPod.getStatus();
        String phase = status.getPhase();

        // ---- 检测1: 容器重启事件 ----
        for (ContainerStatus cs : status.getContainerStatuses()) {
            if (cs.getRestartCount() > 0) {
                RestartHistory prev = restartHistoryMap.get(podName);
                long prevCount = prev != null ? prev.getCount() : 0;
                if (cs.getRestartCount() > prevCount) {
                    handleContainerRestart(namespace, podName, nodeName, cs, newPod);
                }
            }

            // ---- 检测2: CrashLoopBackOff ----
            if ("CrashLoopBackOff".equals(cs.getState().getWaiting() != null
                ? cs.getState().getWaiting().getReason() : null)) {
                handleCrashLoopBackOff(namespace, podName, cs);
            }

            // ---- 检测3: OOM Killed ----
            if (cs.getLastState() != null && cs.getLastState().getTerminated() != null) {
                String reason = cs.getLastState().getTerminated().getReason();
                if ("OOMKilled".equals(reason)) {
                    handleOomKilled(namespace, podName, nodeName, cs, newPod);
                }
            }
        }

        // ---- 检测4: Pod Pending（调度失败）----
        if ("Pending".equals(phase)) {
            handlePendingPod(namespace, podName, status);
        }

        // ---- 检测5: 节点故障导致Pod丢失 ----
        if (oldPod != null && oldPod.getSpec().getNodeName() != null
            && newPod.getSpec().getNodeName() == null) {
            log.warn("[POD_NODE_LOST] pod={}/{}, previousNode={}",
                namespace, podName, oldPod.getSpec().getNodeName());
        }
    }

    /**
     * 处理容器重启事件
     */
    private void handleContainerRestart(String namespace, String podName,
                                          String nodeName, ContainerStatus cs, Pod pod) {
        long restartCount = cs.getRestartCount();
        String containerName = cs.getName();

        // 记录重启历史
        RestartHistory history = restartHistoryMap.compute(podName,
            (k, v) -> v == null
                ? new RestartHistory(restartCount, Instant.now())
                : v.increment(restartCount));

        String terminationReason = "";
        if (cs.getLastState() != null && cs.getLastState().getTerminated() != null) {
            terminationReason = cs.getLastState().getTerminated().getReason();
        }

        log.warn("[CONTAINER_RESTART] pod={}/{}, container={}, restartCount={}, reason={}, node={}",
            namespace, podName, containerName, restartCount, terminationReason, nodeName);

        // 重启次数超过阈值，升级告警
        if (restartCount >= CRASH_LOOP_THRESHOLD) {
            log.error("[CRASH_LOOP_DETECTED] pod={}/{}, restartCount={} >= {}",
                namespace, podName, restartCount, CRASH_LOOP_THRESHOLD);
            alertManager.critical(String.format(
                "Pod %s/%s crash loop detected: %d restarts, last reason: %s",
                namespace, podName, restartCount, terminationReason));
        } else if (restartCount >= 3) {
            alertManager.warn(String.format(
                "Pod %s/%s restarted %d times, reason: %s",
                namespace, podName, restartCount, terminationReason));
        }
    }

    /**
     * 处理CrashLoopBackOff
     * 
     * 自动诊断流程：
     * 1. 获取容器日志
     * 2. 获取容器退出码和原因
     * 3. 匹配已知问题模式
     * 4. 尝试自动修复或告警人工介入
     */
    private void handleCrashLoopBackOff(String namespace, String podName,
                                          ContainerStatus cs) {
        String healKey = podName + "|crashloop|" + cs.getRestartCount();
        IdempotentResult idempotent = idempotentExecutor.checkAndMark(healKey);
        if (idempotent.isAlreadyProcessed()) {
            log.debug("[CRASHLOOP_IDEMPOTENT] already processed: {}", healKey);
            return;
        }

        log.error("[CRASHLOOP_BACKOFF] pod={}/{}, container={}, state=CrashLoopBackOff",
            namespace, podName, cs.getName());

        try {
            // 诊断
            CrashLoopDiagnosis diagnosis = diagnostician.diagnose(namespace, podName, cs.getName());

            log.info("[CRASHLOOP_DIAGNOSIS] pod={}, exitCode={}, reason={}, pattern={}, suggestion={}",
                podName, diagnosis.getExitCode(), diagnosis.getReason(),
                diagnosis.getPattern(), diagnosis.getSuggestion());

            switch (diagnosis.getPattern()) {
                case OOM_KILLED -> {
                    // OOM: 尝试自动调大内存limit
                    log.info("[CRASHLOOP_FIX_OOM] pod={}, attempting memory limit increase",
                        podName);
                    attemptResourceAdjustment(namespace, podName, "memory", 1.5);
                    alertManager.warn(String.format(
                        "Pod %s OOM, auto-increased memory limit. Diagnosis: %s",
                        podName, diagnosis.getSuggestion()));
                }
                case CONFIG_ERROR -> {
                    // 配置错误: 无法自动修复，告警
                    alertManager.critical(String.format(
                        "Pod %s crash loop due to config error: %s. Manual fix needed.",
                        podName, diagnosis.getSuggestion()));
                }
                case IMAGE_PULL_ERROR -> {
                    // 镜像拉取失败: 检查镜像引用和仓库权限
                    alertManager.critical(String.format(
                        "Pod %s image pull failed: %s. Check image ref and registry credentials.",
                        podName, diagnosis.getSuggestion()));
                }
                case APP_STARTUP_ERROR -> {
                    // 应用启动失败: 获取应用日志
                    String appLogs = client.pods().inNamespace(namespace)
                        .withName(podName).getLog();
                    alertManager.critical(String.format(
                        "Pod %s app startup failed. Logs:\n%s",
                        podName, truncateLogs(appLogs, 2000)));
                }
                default -> {
                    alertManager.warn(String.format(
                        "Pod %s crash loop, unknown pattern. Exit code: %d",
                        podName, diagnosis.getExitCode()));
                }
            }

        } catch (Exception e) {
            log.error("[CRASHLOOP_DIAGNOSIS_FAILED] pod={}, error={}",
                podName, e.getMessage(), e);
        }
    }

    /**
     * 处理OOM Killed
     */
    private void handleOomKilled(String namespace, String podName, String nodeName,
                                   ContainerStatus cs, Pod pod) {
        int exitCode = cs.getLastState().getTerminated().getExitCode();
        log.error("[OOM_KILLED] pod={}/{}, container={}, exitCode={}, node={}",
            namespace, podName, cs.getName(), exitCode, nodeName);

        // 记录OOM事件到时序数据库（供服务画像使用）
        oomEventRecorder.record(namespace, podName, nodeName, Instant.now());

        // 如果频繁OOM，自动调整资源限制
        RestartHistory history = restartHistoryMap.get(podName);
        if (history != null && history.getOomCount() >= 2) {
            log.info("[OOM_AUTO_FIX] pod={}, oomCount={}, increasing memory limit",
                podName, history.getOomCount());
            attemptResourceAdjustment(namespace, podName, "memory", 1.5);
        }

        alertManager.critical(String.format(
            "Pod %s/%s OOMKilled (exitCode=%d, node=%s). Memory limit: %s",
            namespace, podName, exitCode, nodeName,
            getContainerMemoryLimit(pod, cs.getName())));
    }

    /**
     * 尝试调整Pod资源配置
     * 
     * 通过更新Deployment的资源limit实现
     * 幂等控制：同一Pod同一资源只调整一次
     */
    private void attemptResourceAdjustment(String namespace, String podName,
                                             String resource, double multiplier) {
        String adjustKey = podName + "|adjust|" + resource;
        IdempotentResult idempotent = idempotentExecutor.checkAndMark(adjustKey);
        if (idempotent.isAlreadyProcessed()) {
            log.info("[RESOURCE_ADJUST_IDEMPOTENT] already adjusted: {}", adjustKey);
            return;
        }

        try {
            // 找到Pod所属的Deployment
            String deploymentName = getOwningDeploymentName(namespace, podName);
            if (deploymentName == null) {
                log.warn("[RESOURCE_ADJUST_SKIP] pod={} has no Deployment owner", podName);
                return;
            }

            Deployment dep = client.apps().deployments()
                .inNamespace(namespace).withName(deploymentName).get();

            Container container = dep.getSpec().getTemplate().getSpec()
                .getContainers().get(0);
            Quantity currentLimit = container.getResources().getLimits().get(resource);
            long currentVal = parseQuantityToBytes(currentLimit, resource);
            long newLimit = (long) (currentVal * multiplier);

            log.info("[RESOURCE_ADJUST] deployment={}/{}, resource={}, {} -> {} (x{})",
                namespace, deploymentName, resource,
                formatBytes(currentVal), formatBytes(newLimit), multiplier);

            // 更新Deployment
            client.apps().deployments().inNamespace(namespace)
                .withName(deploymentName)
                .edit(d -> {
                    d.getSpec().getTemplate().getSpec().getContainers().get(0)
                        .getResources().getLimits()
                        .put(resource, new Quantity(formatBytes(newLimit)));
                    return d;
                });

            log.info("[RESOURCE_ADJUST_SUCCESS] deployment={}/{} memory limit increased",
                namespace, deploymentName);

        } catch (Exception e) {
            log.error("[RESOURCE_ADJUST_FAILED] pod={}, error={}",
                podName, e.getMessage(), e);
            idempotentExecutor.markFailed(adjustKey, e.getMessage());
        }
    }

    /**
     * 处理Pending Pod（调度失败）
     */
    private void handlePendingPod(String namespace, String podName, PodStatus status) {
        String reason = "";
        if (status.getConditions() != null) {
            for (PodCondition cond : status.getConditions()) {
                if ("PodScheduled".equals(cond.getType()) && "False".equals(cond.getStatus())) {
                    reason = cond.getMessage();
                    break;
                }
            }
        }

        log.error("[POD_PENDING] pod={}/{}, reason={}", namespace, podName, reason);

        if (reason.contains("Insufficient") || reason.contains("exceeded quota")) {
            // 资源不足
            alertManager.critical(String.format(
                "Pod %s/%s unschedulable due to insufficient resources: %s",
                namespace, podName, reason));
        } else if (reason.contains("node(s) didn't match")) {
            // 亲和性/污点不匹配
            alertManager.warn(String.format(
                "Pod %s/%s unschedulable due to affinity/taint mismatch: %s",
                namespace, podName, reason));
        }
    }

    private static class RestartHistory {
        private final long count;
        private final Instant lastRestart;
        private final int oomCount;

        RestartHistory(long count, Instant lastRestart) {
            this(count, lastRestart, 0);
        }

        RestartHistory(long count, Instant lastRestart, int oomCount) {
            this.count = count;
            this.lastRestart = lastRestart;
            this.oomCount = oomCount;
        }

        RestartHistory increment(long newCount) {
            return new RestartHistory(newCount, Instant.now(), this.oomCount);
        }

        RestartHistory incrementOom() {
            return new RestartHistory(this.count, this.lastRestart, this.oomCount + 1);
        }

        long getCount() { return count; }
        int getOomCount() { return oomCount; }
    }
}
```

#### 7.3.2 节点故障检测与Pod迁移（Java 实现）

```java
/**
 * 节点故障检测与Pod迁移控制器
 * 
 * 全链路：
 * 1. 监听Node状态变更（Ready → NotReady）
 * 2. 等待宽限期（pod-eviction-timeout=5min）
 * 3. 驱逐故障节点上的所有Pod
 * 4. Deployment Controller在其他节点重建Pod
 * 5. 等待Pod在新节点就绪
 * 6. 发送告警通知
 */
public class NodeFailureHandler {

    private static final Logger log = LoggerFactory.getLogger(NodeFailureHandler.class);
    private final KubernetesClient client;
    private final AlertManager alertManager;
    private final IdempotentExecutor idempotentExecutor;

    // Node NotReady后的宽限期（与 --pod-eviction-timeout 对齐）
    private static final Duration POD_EVICTION_TIMEOUT = Duration.ofMinutes(5);
    // 节点故障迁移幂等key前缀
    private static final String MIGRATION_KEY_PREFIX = "node-migration|";

    // 记录Node变为NotReady的时间
    private final ConcurrentMap<String, Instant> notReadySince = new ConcurrentHashMap<>();

    /**
     * 监听Node状态变更
     */
    public void onNodeStatusChanged(Node oldNode, Node newNode) {
        String nodeName = newNode.getMetadata().getName();
        boolean wasReady = isNodeReady(oldNode);
        boolean isReady = isNodeReady(newNode);

        // Ready → NotReady: 节点故障
        if (wasReady && !isReady) {
            handleNodeNotReady(nodeName, newNode);
        }

        // NotReady → Ready: 节点恢复
        if (!wasReady && isReady) {
            handleNodeRecovered(nodeName);
        }
    }

    /**
     * 节点变为NotReady
     */
    private void handleNodeNotReady(String nodeName, Node node) {
        notReadySince.put(nodeName, Instant.now());

        // 获取故障原因
        String reason = "";
        for (NodeCondition cond : node.getStatus().getConditions()) {
            if ("Ready".equals(cond.getType()) && "False".equals(cond.getStatus())) {
                reason = cond.getMessage();
                break;
            }
        }

        log.error("[NODE_NOT_READY] node={}, reason={}, starting eviction timer ({}min grace period)",
            nodeName, reason, POD_EVICTION_TIMEOUT.toMinutes());

        alertManager.critical(String.format(
            "Node %s is NotReady: %s. Pods will be evicted in %d minutes.",
            nodeName, reason, POD_EVICTION_TIMEOUT.toMinutes()));

        // 启动异步驱逐定时器
        scheduleEviction(nodeName, reason);
    }

    /**
     * 延迟驱逐：等待宽限期后检查节点是否恢复
     * 
     * 幂等控制：每个节点同一故障周期内只触发一次迁移
     */
    private void scheduleEviction(String nodeName, String failureReason) {
        String migrationKey = MIGRATION_KEY_PREFIX + nodeName + "|" + notReadySince.get(nodeName);
        IdempotentResult idempotent = idempotentExecutor.checkAndMark(migrationKey);
        if (idempotent.isAlreadyProcessed()) {
            log.info("[NODE_MIGRATION_IDEMPOTENT] already processed: {}", migrationKey);
            return;
        }

        CompletableFuture.runAsync(() -> {
            try {
                // 等待宽限期
                log.info("[NODE_EVICTION_WAIT] node={}, waiting {} before eviction",
                    nodeName, POD_EVICTION_TIMEOUT);
                Thread.sleep(POD_EVICTION_TIMEOUT.toMillis());

                // 检查节点是否恢复
                Node node = client.nodes().withName(nodeName).get();
                if (isNodeReady(node)) {
                    log.info("[NODE_RECOVERED_BEFORE_EVICTION] node={}, no eviction needed",
                        nodeName);
                    notReadySince.remove(nodeName);
                    return;
                }

                // 节点仍未恢复，执行驱逐
                evictPodsFromNode(nodeName, failureReason);

            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                log.warn("[NODE_EVICTION_INTERRUPTED] node={}", nodeName);
            } catch (Exception e) {
                log.error("[NODE_EVICTION_ERROR] node={}, error={}",
                    nodeName, e.getMessage(), e);
                alertManager.critical(String.format(
                    "Node %s eviction failed: %s", nodeName, e.getMessage()));
            }
        });
    }

    /**
     * 驱逐节点上所有Pod
     */
    private void evictPodsFromNode(String nodeName, String failureReason) {
        List<Pod> podsOnNode = client.pods().inAnyNamespace()
            .withField("spec.nodeName", nodeName).list().getItems();

        log.warn("[NODE_EVICT_START] node={}, podCount={}, reason={}",
            nodeName, podsOnNode.size(), failureReason);

        int evicted = 0;
        int failed = 0;

        for (Pod pod : podsOnNode) {
            String podName = pod.getMetadata().getName();
            String namespace = pod.getMetadata().getNamespace();

            try {
                // 跳过DaemonSet Pod（随节点生命周期，不需要迁移）
                if (isOwnedByDaemonSet(pod)) {
                    log.debug("[EVICT_SKIP_DAEMONSET] pod={}/{}", namespace, podName);
                    continue;
                }

                // 跳过已终止的Pod
                if ("Succeeded".equals(pod.getStatus().getPhase())
                    || "Failed".equals(pod.getStatus().getPhase())) {
                    continue;
                }

                log.info("[EVICT_POD] pod={}/{}, owner={}",
                    namespace, podName, getOwnerKind(pod));

                // 发起驱逐请求（graceful eviction）
                Eviction eviction = new EvictionBuilder()
                    .withNewMetadata()
                        .withName(podName)
                        .withNamespace(namespace)
                    .endMetadata()
                    .withDeleteOptions(new DeleteOptionsBuilder()
                        .withGracePeriodSeconds(30L)
                        .build())
                    .build();

                client.pods().inNamespace(namespace).withName(podName).evict(eviction);
                evicted++;

            } catch (KubernetesClientException e) {
                if (e.getCode() == 429) {
                    // Too Many Requests: 驱逐速率受限，等待后重试
                    log.warn("[EVICT_RATE_LIMITED] pod={}/{}, retrying after delay",
                        namespace, podName);
                    try { Thread.sleep(5000); } catch (InterruptedException ie) {
                        Thread.currentThread().interrupt(); break;
                    }
                } else {
                    log.error("[EVICT_FAILED] pod={}/{}, code={}, message={}",
                        namespace, podName, e.getCode(), e.getMessage());
                    failed++;
                }
            } catch (Exception e) {
                log.error("[EVICT_ERROR] pod={}/{}, error={}",
                    namespace, podName, e.getMessage(), e);
                failed++;
            }
        }

        log.info("[NODE_EVICT_DONE] node={}, evicted={}, failed={}, total={}",
            nodeName, evicted, failed, podsOnNode.size());

        // 等待Pod在新节点重建
        waitForPodsRescheduled(nodeName, podsOnNode, Duration.ofMinutes(5));

        // 发送告警
        alertManager.critical(String.format(
            "Node %s failure handled: %d pods evicted, %d failed. Failure reason: %s",
            nodeName, evicted, failed, failureReason));
    }

    /**
     * 等待Pod在新节点重建就绪
     */
    private void waitForPodsRescheduled(String failedNode, List<Pod> originalPods,
                                          Duration timeout) {
        long deadline = System.currentTimeMillis() + timeout.toMillis();
        int totalPods = (int) originalPods.stream()
            .filter(p -> !isOwnedByDaemonSet(p)
                && !"Succeeded".equals(p.getStatus().getPhase())
                && !"Failed".equals(p.getStatus().getPhase()))
            .count();

        if (totalPods == 0) return;

        log.info("[RESCHEDULE_WAIT] failedNode={}, waiting for {} pods to reschedule",
            failedNode, totalPods);

        while (System.currentTimeMillis() < deadline) {
            int rescheduled = 0;
            for (Pod originalPod : originalPods) {
                if (isOwnedByDaemonSet(originalPod)) continue;

                String appName = originalPod.getMetadata().getLabels().get("app");
                String namespace = originalPod.getMetadata().getNamespace();
                if (appName == null) continue;

                // 检查该应用是否有Pod在运行（可能在其他节点）
                PodList pods = client.pods().inNamespace(namespace)
                    .withLabel("app", appName).list();
                boolean hasRunning = pods.getItems().stream()
                    .anyMatch(p -> "Running".equals(p.getStatus().getPhase())
                        && !failedNode.equals(p.getSpec().getNodeName()));

                if (hasRunning) rescheduled++;
            }

            log.debug("[RESCHEDULE_PROGRESS] failedNode={}, rescheduled={}/{}",
                failedNode, rescheduled, totalPods);

            if (rescheduled >= totalPods) {
                log.info("[RESCHEDULE_COMPLETE] failedNode={}, all {} pods rescheduled",
                    failedNode, totalPods);
                return;
            }

            try { Thread.sleep(5000); } catch (InterruptedException e) {
                Thread.currentThread().interrupt(); return;
            }
        }

        log.error("[RESCHEDULE_TIMEOUT] failedNode={}, not all pods rescheduled within {}",
            failedNode, timeout);
        alertManager.critical(String.format(
            "Node %s: some pods not rescheduled within %d minutes. Manual check needed.",
            failedNode, timeout.toMinutes()));
    }

    /**
     * 节点恢复
     */
    private void handleNodeRecovered(String nodeName) {
        Instant notReadyTime = notReadySince.remove(nodeName);
        Duration downtime = notReadyTime != null
            ? Duration.between(notReadyTime, Instant.now()) : Duration.ZERO;

        log.info("[NODE_RECOVERED] node={}, downtime={}s", nodeName, downtime.getSeconds());
        alertManager.info(String.format(
            "Node %s recovered after %d seconds downtime", nodeName, downtime.getSeconds()));
    }

    private boolean isNodeReady(Node node) {
        if (node == null || node.getStatus() == null
            || node.getStatus().getConditions() == null) return false;
        return node.getStatus().getConditions().stream()
            .filter(c -> "Ready".equals(c.getType()))
            .anyMatch(c -> "True".equals(c.getStatus()));
    }

    private boolean isOwnedByDaemonSet(Pod pod) {
        return pod.getMetadata().getOwnerReferences() != null
            && pod.getMetadata().getOwnerReferences().stream()
            .anyMatch(ref -> "DaemonSet".equals(ref.getKind()));
    }

    private String getOwnerKind(Pod pod) {
        if (pod.getMetadata().getOwnerReferences() == null
            || pod.getMetadata().getOwnerReferences().isEmpty()) return "None";
        return pod.getMetadata().getOwnerReferences().get(0).getKind();
    }
}
```

#### 7.3.3 告警通知服务（Java 实现）

```java
/**
 * 容器故障告警通知服务
 * 
 * 告警分级：
 * - CRITICAL: 立即电话+大象通知（P0服务故障、节点宕机、OOM频发）
 * - WARNING: 大象消息通知（重启次数异常、CrashLoopBackOff）
 * - INFO: 记录日志（扩缩容、节点恢复）
 * 
 * 告警抑制：同一告警5分钟内不重复发送（防告警风暴）
 */
public class ContainerAlertNotifier {

    private static final Logger log = LoggerFactory.getLogger(ContainerAlertNotifier.class);
    private final AlertChannel emailChannel;
    private final AlertChannel imChannel;     // 大象消息
    private final AlertChannel phoneChannel;  // 电话告警

    // 告警抑制：key = alertFingerprint, value = 上次发送时间
    private final ConcurrentMap<String, Instant> alertSuppressMap = new ConcurrentHashMap<>();
    private static final Duration SUPPRESS_WINDOW = Duration.ofMinutes(5);

    /**
     * 发送告警（带抑制）
     * 
     * 幂等控制：同一告警指纹在抑制窗口内不重复发送
     */
    public void notify(AlertLevel level, String message) {
        String fingerprint = sha256(level.name() + "|" + message);

        // 告警抑制检查
        Instant lastSent = alertSuppressMap.get(fingerprint);
        if (lastSent != null && lastSent.plus(SUPPRESS_WINDOW).isAfter(Instant.now())) {
            log.debug("[ALERT_SUPPRESSED] fingerprint={}, message={}", fingerprint, message);
            return;
        }

        try {
            switch (level) {
                case CRITICAL -> {
                    // CRITICAL: 电话 + 大象 + 邮件
                    log.error("[ALERT_CRITICAL] {}", message);
                    phoneChannel.send(message);
                    imChannel.send(":rotating_light: [CRITICAL] " + message);
                    emailChannel.send("[CRITICAL] Container Platform Alert", message);
                }
                case WARNING -> {
                    // WARNING: 大象 + 邮件
                    log.warn("[ALERT_WARNING] {}", message);
                    imChannel.send(":warning: [WARNING] " + message);
                    emailChannel.send("[WARNING] Container Platform Alert", message);
                }
                case INFO -> {
                    // INFO: 仅日志
                    log.info("[ALERT_INFO] {}", message);
                }
            }

            // 记录告警发送时间（抑制窗口）
            alertSuppressMap.put(fingerprint, Instant.now());

        } catch (Exception e) {
            // 告警发送本身不能失败导致主流程中断
            log.error("[ALERT_SEND_FAILED] level={}, message={}, error={}",
                level, message, e.getMessage(), e);
        }
    }

    /**
     * 定期清理过期的告警抑制记录
     */
    @Scheduled(fixedRate = 300000) // 每5分钟清理一次
    public void cleanupExpiredSuppressions() {
        Instant cutoff = Instant.now().minus(SUPPRESS_WINDOW.multipliedBy(2));
        int before = alertSuppressMap.size();
        alertSuppressMap.entrySet().removeIf(e -> e.getValue().isBefore(cutoff));
        log.debug("[ALERT_SUPPRESS_CLEANUP] removed {} expired entries",
            before - alertSuppressMap.size());
    }

    public enum AlertLevel { CRITICAL, WARNING, INFO }
}
```
