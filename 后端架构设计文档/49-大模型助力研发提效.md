# 大模型助力研发提效

## 一、问题背景

### 1.1 传统研发效率的瓶颈

在软件研发领域，开发者的时间分配长期存在"二八定律"：写代码可能只占20%的时间，剩下80%分散在需求澄清、拉分支、写PR、出用例、盯部署等"非编码"动作中。即使引入了AI代码补全工具，也只是在编码环节提升了局部效率，流程割裂的问题依然存在，整体效率难以突破。

传统研发流程面临以下核心挑战：

**编码效率瓶颈**
- 重复性代码编写占据大量时间，开发者精力被消耗在模板代码上
- 跨技术栈开发门槛高，后端开发者编写前端代码效率低下
- 代码质量依赖个人经验，缺乏统一的编码规范约束

**流程协作低效**
- 需求从PRD到代码实现需要多轮澄清，理解偏差导致返工
- 技术方案设计与代码实现脱节，方案文档写完后往往束之高阁
- 测试用例编写、代码审查等环节依赖人工，效率和质量不稳定

**知识传承困难**
- 业务领域知识散落在个人头脑中，新成员上手周期长
- 内部基建组件和最佳实践缺乏有效传递渠道
- 历史项目的设计决策和经验教训难以沉淀复用

### 1.2 大模型带来的机遇

随着大语言模型（LLM）在代码生成领域能力的不断提升，以及AI IDE（如Cursor、CatPaw等）的出现，AI在研发全流程中的应用从简单的代码补全扩展到了需求分析、技术方案设计、代码生成、代码审查、测试用例生成等全链路环节。

大模型助力研发提效的核心理念是：通过AI主动推动研发流程执行，开发者只需在关键决策点介入。开发者的角色从"逐行写代码"转变为"做三个关键决策"——需求理解对不对？技术方案行不行？最终代码要不要？

### 1.3 AI Coding的两种范式

**Vibe Coding（氛围编程）**
- 核心理念：通过自然语言描述需求，由AI直接生成代码
- 优势：交互方式自然直观，代码生成速度快
- 局限性：适合产品原型和辅助开发，难以胜任企业级端到端交付；上下文限制导致缺乏规范约束与业务领域知识；大量时间消耗在多轮对话迭代对齐上

**Spec-Driven Development（规范驱动开发）**
- 核心理念：通过结构化的规范文档来指导AI生成代码
- 工作流程：Requirements → Design → Task List → Coding
- 优势：稳定性和质量保障显著优于Vibe Coding
- 局限性：单Agent模式存在Token上限和失焦问题；缺乏垂直领域深度定制；模型与业务缺少有效连接

### 1.4 核心名词定义

| 名词 | 解释 |
|------|------|
| Completion（补全） | 根据编辑器中的输入文本和光标位置，生成后续代码的过程 |
| Chat（对话） | 与LLM进行多轮交互式对话的模式，保持上下文连续性 |
| Agent | 具有自主决策能力的AI系统，能够理解任务、制定计划、调用工具并执行复杂操作 |
| Prompt（提示词） | 发送给LLM的指令或问题，用于引导AI生成期望的输出结果 |
| Context（上下文） | LLM处理当前请求时能够访问和参考的所有相关信息 |
| Rule（规则） | 约束AI行为和输出的预设条件，确保生成内容符合特定标准 |
| Function Call（函数调用） | LLM调用预定义函数或API来执行特定任务的能力 |
| MCP（Model Context Protocol） | 标准化协议，用于AI应用程序与外部系统进行通信 |

## 二、整体架构设计

### 2.1 AI Coding全流程架构

基于规范驱动开发范式，AI Coding全流程架构将软件研发生命周期编排为可调度、可自愈、可自进化的工作流：

```
┌─────────────────────────────────────────────────────────────────┐
│                        输入层                                     │
│   AI友好型技术文档 | 业务术语表 | 模块关联关系 | 上下游依赖       │
├─────────────────────────────────────────────────────────────────┤
│                    需求复杂度分析                                  │
│   L1(单模块修复) | L2(跨模块修改) | L3(完整模块) | L4(系统架构)  │
├─────────────────────────────────────────────────────────────────┤
│                    多Agent协作层                                   │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ 需求分析  │→│ 任务规划  │→│ 设计     │→│ 编码实施  │          │
│  │ Agent     │ │ Agent    │ │ Agent    │ │ Agent    │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐                        │
│  │ 代码审查  ││ 测试验证  ││ 复盘落档  │                        │
│  │ Agent     ││ Agent    ││ Agent    │                        │
│  └──────────┘ └──────────┘ └──────────┘                        │
├─────────────────────────────────────────────────────────────────┤
│                    知识与规范层                                    │
│   Rule分层体系 | MCP(基建组件知识) | 项目上下文(本地文档)         │
├─────────────────────────────────────────────────────────────────┤
│                    度量与反馈层                                    │
│   结果指标(覆盖率/生成率/耗时/成本) | 过程指标(阶段成功率/Token)  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 需求复杂度分级

不同复杂度的需求走不同的AI Coding工作流，实现精准的流程管控：

| 级别 | 定义 | 典型场景 | 工作流 |
|------|------|----------|--------|
| L1 | 单一模块内的代码修改 | Bugfix、配置变更 | 直接编码实施 → 复盘 |
| L2 | 跨模块的代码修改 | 表单字段添加、样式更新、组件扩展 | 任务规划 → 编码实施 → 复盘 |
| L3 | 完整模块的实现 | 创建表单页面、开发搜索功能、可视化看板 | 任务规划 → 设计 → 编码实施 → 复盘 |
| L4 | 系统架构实现类 | 搭建完整系统、底层架构升级 | 任务规划 → 设计 → 编码实施 → 复盘 → 落档 |

### 2.3 AI友好型技术文档

以技术方案（而非PRD）作为AI Coding的输入起点，因为技术方案更贴近代码实现，减少产品术语带来的理解偏差。AI友好型技术文档在传统技术方案基础上增加以下要素：

- **业务术语表**：明确定义业务专有名词，消除AI的理解歧义
- **模块关联关系**：描述各模块间的依赖和调用关系
- **上下游依赖**：标注服务间调用链路和数据流向
- **完整的表结构信息**：提供数据库表的完整DDL
- **结构化图示**：使用PlantUML或Mermaid绘制时序图和架构图

#### 3.1.2 多Agent协作架构

```java
/**
 * 多Agent协作体系核心设计
 * 每个研发节点配置独立的Agent，在独立上下文中专注完成单一职责
 */
public class MultiAgentCollaborationSystem {

    private final Map<String, Agent> agents;
    private final ProjectContextManager contextManager;

    public MultiAgentCollaborationSystem() {
        agents = new LinkedHashMap<>();
        agents.put("requirement-analysis", new RequirementAnalysisAgent());
        agents.put("task-planning", new TaskPlanningAgent());
        agents.put("design", new DesignAgent());
        agents.put("coding", new CodingAgent());
        agents.put("code-review", new CodeReviewAgent());
        agents.put("testing", new TestingAgent());
        agents.put("retrospective", new RetrospectiveAgent());
    }

    /**
     * 执行研发流程
     * 根据需求复杂度级别选择对应的Agent工作流
     */
    public WorkflowResult executeWorkflow(RequirementRequirement req) {
        // 1. 需求复杂度分析（所有级别必须执行）
        ComplexityLevel level = analyzeComplexity(req);
        contextManager.initContext(req);

        WorkflowResult result = new WorkflowResult();

        // 2. 根据复杂度级别执行不同的工作流
        switch (level) {
            case L1:
                // L1: 直接编码 → 复盘
                executeAgent("coding", req, result);
                executeAgent("retrospective", req, result);
                break;
            case L2:
                // L2: 任务规划 → 编码 → 复盘
                executeAgent("task-planning", req, result);
                executeAgent("coding", req, result);
                executeAgent("retrospective", req, result);
                break;
            case L3:
            case L4:
                // L3/L4: 任务规划 → 设计 → 编码 → 代码审查 → 测试 → 复盘
                executeAgent("task-planning", req, result);
                executeAgent("design", req, result);
                executeAgent("coding", req, result);
                executeAgent("code-review", req, result);
                executeAgent("testing", req, result);
                executeAgent("retrospective", req, result);
                if (level == ComplexityLevel.L4) {
                    executeAgent("documentation", req, result);
                }
                break;
        }

        return result;
    }

    /**
     * 执行单个Agent
     * 每个Agent在独立上下文中工作，通过项目上下文共享信息
     */
    private void executeAgent(String agentName, RequirementRequirement req,
                               WorkflowResult result) {
        Agent agent = agents.get(agentName);
        AgentContext context = new AgentContext(
                contextManager.getProjectContext(),
                req,
                result.getPreviousOutput()
        );

        // 等待人工确认
        AgentOutput output = agent.execute(context);
        if (output.requiresHumanReview()) {
            boolean approved = waitForHumanApproval(output);
            if (!approved) {
                // 人工指正后重新执行
                output = agent.execute(context.withFeedback(output.getFeedback()));
            }
        }

        // 将产出写入项目上下文（供下一个Agent读取）
        contextManager.saveOutput(agentName, output);
        result.addOutput(agentName, output);
    }
}
```

```java
/**
 * 项目上下文管理器
 * 解决多Agent之间上下文隔离的问题
 * 每个Agent将产出以结构化文档形式写入项目本地目录
 */
public class ProjectContextManager {

    private static final String CONTEXT_DIR = ".ai-coding/context/";

    private final Map<String, ProjectDocument> contextCache;

    /**
     * 初始化项目上下文
     */
    public void initContext(RequirementRequirement req) {
        // 创建项目上下文目录
        createContextDir();

        // 写入需求基本信息
        ProjectDocument reqDoc = ProjectDocument.builder()
                .type("requirement")
                .content(req.getDescription())
                .metadata(Map.of("level", req.getComplexityLevel().name()))
                .build();
        saveDocument("requirement.md", reqDoc);
    }

    /**
     * 保存Agent产出到项目上下文
     */
    public void saveOutput(String agentName, AgentOutput output) {
        String filename = agentName + "-output.md";
        ProjectDocument doc = ProjectDocument.builder()
                .type(agentName)
                .content(output.getContent())
                .metadata(output.getMetadata())
                .timestamp(Instant.now())
                .build();
        saveDocument(filename, doc);
    }

    /**
     * 读取前序Agent的产出
     */
    public ProjectDocument getOutput(String agentName) {
        String filename = agentName + "-output.md";
        return loadDocument(filename);
    }

    /**
     * 获取完整项目上下文
     */
    public String getFullContext() {
        StringBuilder sb = new StringBuilder();
        for (Map.Entry<String, ProjectDocument> entry : contextCache.entrySet()) {
            sb.append("## ").append(entry.getKey()).append("\n");
            sb.append(entry.getValue().getContent()).append("\n\n");
        }
        return sb.toString();
    }
}
```

```java
/**
 * 需求复杂度分析Agent
 * 评估需求复杂度，决定后续工作流
 */
public class RequirementAnalysisAgent implements Agent {

    private final RuleEngine ruleEngine;

    @Override
    public AgentOutput execute(AgentContext context) {
        String techDoc = context.getProjectContext().getTechDocument();
        RequirementRequirement req = context.getRequirement();

        // 1. 分析技术方案，评估复杂度
        ComplexityAssessment assessment = assessComplexity(techDoc);

        // 2. 识别涉及的模块和服务
        List<ServiceInfo> involvedServices = identifyServices(techDoc);

        // 3. 评估改动量、依赖深度、风险度
        RiskAssessment risk = assessRisk(involvedServices, techDoc);

        // 4. 确定复杂度级别
        ComplexityLevel level = determineLevel(assessment, risk);

        // 5. 生成需求分析报告
        String report = generateAnalysisReport(req, assessment, involvedServices, risk, level);

        return AgentOutput.builder()
                .content(report)
                .metadata(Map.of(
                        "complexityLevel", level.name(),
                        "involvedServices", involvedServices.size(),
                        "riskScore", risk.getScore()
                ))
                .requiresHumanReview(true)  // 需求分析必须人工确认
                .build();
    }

    private ComplexityLevel determineLevel(ComplexityAssessment assessment,
                                             RiskAssessment risk) {
        if (assessment.getModifiedFiles() <= 3 && risk.getScore() < 20) {
            return ComplexityLevel.L1;
        } else if (assessment.getModifiedFiles() <= 10 && risk.getScore() < 50) {
            return ComplexityLevel.L2;
        } else if (assessment.getNewModules() <= 3 && risk.getScore() < 80) {
            return ComplexityLevel.L3;
        } else {
            return ComplexityLevel.L4;
        }
    }
}
```

```java
/**
 * 任务规划Agent
 * 将整体需求分解为可追踪的任务列表
 */
public class TaskPlanningAgent implements Agent {

    @Override
    public AgentOutput execute(AgentContext context) {
        String techDoc = context.getProjectContext().getTechDocument();
        ComplexityLevel level = context.getComplexityLevel();

        // 1. 识别需要的设计组件类型
        List<DesignComponentType> designComponents = identifyDesignComponents(techDoc, level);

        // 2. 生成设计组件任务列表
        List<DesignTask> designTasks = designComponents.stream()
                .map(type -> new DesignTask(type, getRelevantSections(techDoc, type)))
                .collect(Collectors.toList());

        // 3. 生成编码实施任务列表
        List<CodingTask> codingTasks = generateCodingTasks(techDoc, designComponents);

        // 4. 建立设计组件与编码任务的映射关系
        Map<String, List<CodingTask>> taskMapping = mapDesignToCoding(designTasks, codingTasks);

        // 5. 生成任务计划文档
        String taskPlan = formatTaskPlan(designTasks, codingTasks, taskMapping);

        return AgentOutput.builder()
                .content(taskPlan)
                .metadata(Map.of(
                        "designTaskCount", designTasks.size(),
                        "codingTaskCount", codingTasks.size()
                ))
                .requiresHumanReview(true)
                .build();
    }

    /**
     * 识别需要的设计组件类型
     * 7类设计组件：架构设计、算法设计、数据模型设计、业务流程设计、
     * 系统集成设计、接口协议设计、UI/UX设计
     */
    private List<DesignComponentType> identifyDesignComponents(String techDoc,
                                                                 ComplexityLevel level) {
        List<DesignComponentType> components = new ArrayList<>();

        if (hasArchitectureChanges(techDoc)) {
            components.add(DesignComponentType.ARCHITECTURE);
        }
        if (hasAlgorithmDesign(techDoc)) {
            components.add(DesignComponentType.ALGORITHM);
        }
        if (hasDataModelChanges(techDoc)) {
            components.add(DesignComponentType.DATA_MODEL);
        }
        components.add(DesignComponentType.BUSINESS_FLOW);  // 默认需要
        if (hasIntegrationChanges(techDoc)) {
            components.add(DesignComponentType.SYSTEM_INTEGRATION);
        }
        if (hasApiChanges(techDoc)) {
            components.add(DesignComponentType.API_PROTOCOL);
        }
        if (hasUiChanges(techDoc)) {
            components.add(DesignComponentType.UI_UX);
        }

        return components;
    }
}
```

### 3.3 设计Agent与7类设计组件

```java
/**
 * 设计Agent
 * 对技术方案进行"复述+补充"，实现研发和AI对技术方案的高度对齐
 * 遵循"AI设计 → 研发指正 → AI修复 → 研发确认"的循环迭代模式
 */
public class DesignAgent implements Agent {

    /**
     * 按设计组件类型逐一处理
     * 每轮对话只处理1个设计组件，读取该组件需要的多个章节内容
     */
    @Override
    public AgentOutput execute(AgentContext context) {
        List<DesignTask> designTasks = context.getDesignTasks();
        List<DesignComponentResult> results = new ArrayList<>();

        for (DesignTask task : designTasks) {
            // 1. 读取该设计组件需要的章节
            String relevantSections = loadRelevantSections(task);

            // 2. AI生成设计文档（复述+补充）
            DesignComponentResult result = generateDesign(task, relevantSections);

            // 3. 等待人工确认
            boolean confirmed = waitForConfirmation(result);
            while (!confirmed) {
                // 研发指正后AI修复
                result = refineDesign(result, getFeedback());
                confirmed = waitForConfirmation(result);
            }

            results.add(result);
        }

        // 4. 合并所有设计组件结果
        String fullDesignDoc = mergeDesignResults(results);

        return AgentOutput.builder()
                .content(fullDesignDoc)
                .metadata(Map.of("componentCount", results.size()))
                .requiresHumanReview(false)  // 每个组件已逐个确认
                .build();
    }

    /**
     * 生成单个设计组件的设计文档
     */
    private DesignComponentResult generateDesign(DesignTask task, String sections) {
        String prompt = buildDesignPrompt(task.getType(), sections);

        // AI生成设计内容
        String designContent = llmClient.chat(prompt);

        // 补充技术方案中遗漏的细节
        String supplemented = supplementDetails(designContent, task);

        return DesignComponentResult.builder()
                .type(task.getType())
                .content(supplemented)
                .sourceSections(task.getRelevantSections())
                .build();
    }
}
```

```java
/**
 * 编码实施Agent
 * 读取任务列表中对应的任务并执行编码
 */
public class CodingAgent implements Agent {

    private final RuleEngine ruleEngine;
    private final McpClient mcpClient;

    @Override
    public AgentOutput execute(AgentContext context) {
        List<CodingTask> tasks = context.getCodingTasks();
        List<CodeChange> allChanges = new ArrayList<>();

        for (CodingTask task : tasks) {
            // 1. 加载编码规范
            CodingStandard standard = ruleEngine.getStandard(task.getLanguage());

            // 2. 加载相关上下文（通过MCP获取内部组件使用说明）
            String infrastructureKnowledge = mcpClient.getInfrastructureDocs(
                    task.getRelatedComponents());

            // 3. 读取设计文档中对应的组件设计
            String designDoc = context.getDesignForComponent(task.getDesignComponentType());

            // 4. AI生成代码
            CodeChange change = generateCode(task, designDoc, standard,
                                              infrastructureKnowledge);

            // 5. 应用编码规范约束
            change = applyCodingStandards(change, standard);

            allChanges.add(change);
        }

        // 6. 生成代码变更总结
        String summary = generateChangeSummary(allChanges);

        return AgentOutput.builder()
                .content(summary)
                .metadata(Map.of(
                        "fileCount", allChanges.stream().map(CodeChange::getFilePath).distinct().count(),
                        "totalLines", allChanges.stream().mapToInt(CodeChange::getLineCount).sum()
                ))
                .requiresHumanReview(true)
                .build();
    }

    /**
     * 生成代码
     */
    private CodeChange generateCode(CodingTask task, String designDoc,
                                      CodingStandard standard, String infraKnowledge) {
        String prompt = buildCodingPrompt(task, designDoc, standard, infraKnowledge);

        // 调用LLM生成代码
        GeneratedCode code = llmClient.generateCode(prompt);

        // 验证生成的代码是否符合规范
        ValidationResult validation = validateCode(code, standard);
        if (!validation.isValid()) {
            // 自动修复不符合规范的部分
            code = autoFix(code, validation.getIssues());
        }

        return CodeChange.builder()
                .filePath(task.getFilePath())
                .content(code.getContent())
                .language(task.getLanguage())
                .lineCount(code.getLineCount())
                .build();
    }
}
```

```java
/**
 * 代码审查Agent
 * 对AI生成的代码进行自动化审查
 */
public class CodeReviewAgent implements Agent {

    @Override
    public AgentOutput execute(AgentContext context) {
        List<CodeChange> changes = context.getCodeChanges();
        List<ReviewIssue> allIssues = new ArrayList<>();

        for (CodeChange change : changes) {
            // 1. 安全性检查
            List<ReviewIssue> securityIssues = checkSecurity(change);

            // 2. 编码规范检查
            List<ReviewIssue> styleIssues = checkStyle(change);

            // 3. 业务逻辑检查
            List<ReviewIssue> logicIssues = checkBusinessLogic(change,
                    context.getDesignDoc());

            // 4. 性能检查
            List<ReviewIssue> perfIssues = checkPerformance(change);

            allIssues.addAll(securityIssues);
            allIssues.addAll(styleIssues);
            allIssues.addAll(logicIssues);
            allIssues.addAll(perfIssues);
        }

        // 生成审查报告
        String reviewReport = generateReviewReport(allIssues, changes);

        return AgentOutput.builder()
                .content(reviewReport)
                .metadata(Map.of(
                        "totalIssues", allIssues.size(),
                        "criticalIssues", allIssues.stream().filter(i -> i.getSeverity() == Severity.CRITICAL).count(),
                        "warningIssues", allIssues.stream().filter(i -> i.getSeverity() == Severity.WARNING).count()
                ))
                .requiresHumanReview(allIssues.stream()
                        .anyMatch(i -> i.getSeverity() == Severity.CRITICAL))
                .build();
    }
```

```java
    public Map<ComplexityLevel, LevelExecutionStats> getLevelExecutionStats(TimeRange range) {

        for (ComplexityLevel level : ComplexityLevel.values()) {
            stats.put(level, computeLevelStats(level, range));
        }
        return stats;
    }

    // 4.2 产物质量指标
    // 4.2.3 代码质量 - 缺陷密度
    public double getDefectDensity(String requirementId) {
        int defectCount = defectService.countByRequirement(requirementId);
        int totalLines = codePlatformService.getTotalLines(requirementId);
        return (double) defectCount / totalLines * 1000; // 每千行缺陷数
    }

    // 4.2.6 测试报告质量（TRQI）
    // TRQI = C × (w1×T + w2×CP + w3×A), w1=0.3, w2=0.4, w3=0.3
    public double calculateTRQI(TestReport report) {
        double C = report.isContentComplete() ? 1.0 : 0.0;
        double T = report.getTraceabilityScore();      // 过程可追溯性
        double CP = report.getCompletenessScore();      // 测试完成度
        double A = report.getAccuracyScore();           // 缺陷准确性

        double w1 = 0.3, w2 = 0.4, w3 = 0.3;
        return C * (w1 * T + w2 * CP + w3 * A);
    }
```

## 六、最佳实践

### 6.1 AI Coding工作流最佳实践

1. **以技术方案为输入起点**：不使用PRD直接作为AI输入，而是以技术方案为起点。技术方案更贴近代码实现，减少产品术语的理解偏差和多轮澄清成本。

2. **需求分级机制**：将需求划分为L1-L4四个级别，针对不同复杂度动态调整研发流程。L1直接编码，L2增加任务规划，L3/L4增加设计节点，实现精准的流程管控。

3. **先规划后执行**：在编码前进行任务规划和设计，使AI产出更聚焦，不易自由发挥和遗漏。任务规划形成可追踪的任务列表，编码实施只需读取对应任务执行。

4. **设计节点的人工确认**：L3/L4级别需求的设计节点遵循"AI设计→研发指正→AI修复→研发确认"的循环迭代模式，确保研发和AI对技术方案高度对齐。

5. **复盘机制**：每个需求完成后进行AI复盘，总结经验教训并记录到项目本地目录，为后续需求提供参考，避免重复犯错。

### 6.2 多Agent协作最佳实践

1. **单一职责原则**：每个Agent只专注于完成对应研发节点的工作，独立上下文空间避免上下文污染，使模型输出更稳定可靠。

2. **项目上下文共享**：通过项目本地目录中的结构化文档实现多Agent间的信息共享。每个Agent的产出以Markdown形式保存，下一个Agent启动时读取。

3. **工作流定义在系统提示词**：通过系统提示词定义工作流，确保Agent在整个执行过程中始终明确自身职责和工作步骤，避免因上下文裁剪导致工作流程遗忘。

4. **人工检查确认机制**：每个节点引入人工检查确认，确保产出质量，环环相扣保障整体交付质量。

5. **IDE插件化部署**：将多Agent协作体系打包为IDE插件，提供一键安装能力，实现版本自动检测和更新提醒，极大简化上手成本。

### 6.3 规范约束最佳实践

1. **Rule分层体系**：建立工作流规则、需求复杂度规则、项目上下文规则、细粒度任务规则四层Rule体系，从宏观到微观全面约束AI行为。

2. **不直接生成存储层代码**：不推荐让大模型直接生成entity、mapper、xml等存储层代码，因为大模型存在幻觉且存储层代码量大，容易产生错误。

3. **编码规范集成**：将团队的编码规范（命名规范、异常处理、日志规范等）作为Rule注入AI，确保生成的代码符合团队标准。

4. **MCP知识增强**：通过MCP协议集成内部基建组件文档和知识库文档，让AI能够理解业务上下文，生成符合内部技术栈的代码。

5. **7类设计组件识别**：从功能角度划分架构设计、算法设计、数据模型设计、业务流程设计、系统集成设计、接口协议设计、UI/UX设计7类组件，按需激活，避免不必要的处理。

### 6.4 度量体系最佳实践

1. **结果指标与过程指标并重**：结果指标回答"AI交付了什么"，过程指标回答"AI是怎么交付的"，两者结合才能全面评估AI Coding的效果。

2. **需求复杂度分级为前置维度**：所有指标以L1-L4分级作为前置维度拆分观测，不同规模需求混在一起会掩盖真实规律。

3. **Token消耗作为核心成本指标**：将Token消耗作为AI新范式下独有的度量视角，纵向自比识别Prompt优化效果，横向比较识别异常高消耗需求。

4. **综合成本计算**：将人力成本（PD×日薪）和AI成本（Token×单价）统一折算为货币，计算真实的需求交付成本和ROI。

5. **持续改进闭环**：建立"度量→诊断→优化→验证"的持续改进闭环，通过过程数据识别薄弱环节，驱动Prompt、编排与模板的定向优化。

6. **质量护栏指标**：关注AI相关缺陷占比、缺陷密度等质量指标，不能因为追求AI使用率而忽视代码质量。
