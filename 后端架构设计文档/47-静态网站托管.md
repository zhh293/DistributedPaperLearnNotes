# 静态网站托管

## 一、问题背景

### 1.1 业务痛点

在大型企业内部，前端Web项目的托管和部署长期面临标准化缺失的问题。传统的静态资源托管模式存在以下痛点：

**模式一：采用机器存储静态资源**
- 需要申请和维护物理机或虚拟机，运维成本高
- 机器扩容、容灾等稳定性保障需要业务团队自行处理
- 资源利用率低，静态文件占用了大量计算资源

**模式二：业务独立申请对象存储租户**
- 每个业务团队独立管理存储空间，缺乏统一标准
- CDN配置、缓存策略各团队自行处理，服务质量参差不齐
- 灰度发布、泳道隔离等高级能力需要业务自建，投入成本高

**模式三：业务自建托管服务或CI/CD**
- 各业务线重复建设，功能丰富度差异大
- 稳定性保障不足，缺乏多机房容灾、集群隔离等能力
- 前端项目可观测性差，持续运维优化困难

### 1.2 静态网站托管的定义

静态网站是指全部由HTML代码格式页面组成的网站，所有内容包含在网页文件中，文件名以htm、html、shtml等为后缀。静态网站托管服务为前端Web项目提供一站式的资源存储、管理和访问能力，核心特征包括：

- **无服务器**：静态资源与传统Web服务器分离，由分布在全球/全国的CDN边缘节点提供
- **资源加速**：静态资产在物理上离最终用户更近，文件提供速度更快
- **一站式管理**：涵盖资源存储、部署、访问、灰度、监控等全链路能力

### 1.3 应用场景

- 部署前端静态项目（PC页面、H5页面）
- 部署JS SDK项目
- 统一团队研发流程，提升前端项目整体稳定性
- 为低代码平台、活动营销系统提供页面级托管能力
- 为全站CDN托管场景提供灰度发布解决方案

## 二、整体架构设计

### 2.1 架构总览

静态网站托管服务由资源访问、资源管理、资源部署三大部分组成，整体架构如下：

```
┌──────────────────────────────────────────────────────────────┐
│                        用户访问层                              │
│    浏览器 → DNS解析 → 四层负载均衡(LB) → 七层网关(HTTP-Gateway) → 前端网关       │
├──────────────────────────────────────────────────────────────┤
│                        资源访问层                              │
│  前端网关(Proxy) | 服务发现 | 灰度分流 | 泳道分流 | 认证鉴权   │
│  限流 | 降级容灾 | 重写重定向 | 自定义404 | 自定义插件         │
├──────────────────────────────────────────────────────────────┤
│                        资源管理层                              │
│  控制台(Console) | 灰度管理 | 监控大盘 | 日志查询 | 运维管理    │
│  配置管理 | 版本回滚 | 资源浏览 | 成本统计                     │
├──────────────────────────────────────────────────────────────┤
│                        资源部署层                              │
│  CI/CD流水线 | 构建组件 | 部署组件 | 环境管理 | 回滚            │
│  多环境支持(dev/test/staging/prod) | 泳道部署 | 灰度部署       │
├──────────────────────────────────────────────────────────────┤
│                        存储与分发层                            │
│  对象存储 | CDN加速 | 内存缓存 | Redis缓存                 │
│  多机房容灾 | 集群隔离 | 异地备份                              │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 核心概念

| 概念 | 说明 |
|------|------|
| Appkey | 服务的唯一标识，前端服务通过Appkey进行命名和发现 |
| 项目 | 一个服务即一个Appkey，对应一个托管的前端项目 |
| 前端服务发现 | 通过Appkey即可定位到具体前端服务的能力，无需了解部署拓扑 |
| 泳道(Swimlane) | 通过不同的流量分发实现测试环境隔离，一个泳道即一个测试环境 |
| 灰度(Grayscale) | 在生产环境中划分部分流量为灰度流量，先上灰度流量访问新版本 |
| 灰度策略 | 定义灰度条件的配置，包括策略名、生效路径、环境、有效期、灰度条件 |
| 资源版本 | 每次部署产生的资源快照，支持版本回滚 |

### 2.3 请求链路

完整的请求链路分为HTML请求和静态资源请求两条路径：

**HTML请求链路：**
```
浏览器 → 四层负载均衡(LB) → HTTP网关 → API网关前置组件 → 前端网关(Proxy) → API网关后置组件 → 对象存储
```

**静态资源请求链路（JS/CSS/图片等）：**
```
浏览器 → CDN域名 → CDN边缘节点 → 对象存储
```

前端网关只处理HTML类型的HTTP请求，JS、CSS、图片等类型静态资源通过CDN访问。这种分离设计使得HTML可以灵活进行灰度分流，而静态资源利用CDN的全局加速能力。

### 2.4 稳定性指标

- 服务可用性：99.995%
- 请求成功率：99.9999%
- TP999响应时长：非灰度场景 < 10ms，灰度场景 < 50ms
- 缓存命中率：通过多级缓存优化，大部分请求命中缓存
- QPS限制：每个前端Appkey默认1000 QPS

## 三、核心链路设计

### 3.1 前端服务发现

#### 3.1.1 服务发现架构

前端服务发现使前端可以像后端一样，部署代码后即可完成域名与服务的关联配置。整体架构基于对象存储、七层网关和API网关实现：

```java
/**
 * 前端服务发现核心逻辑
 * 维护Appkey到资源存储位置的映射关系
 */
public class FrontendServiceDiscovery {

    private final ServiceRegistry serviceRegistry;
    private final ConfigManager configManager;

    /**
     * 注册前端服务
     * 为每个服务分配一个对象存储空间
     */
    public void registerService(String appkey, ServiceConfig config) {
        // 1. 分配存储空间
        String storagePath = allocateStorage(appkey);

        // 2. 创建服务注册信息
        ServiceRegistration registration = ServiceRegistration.builder()
                .appkey(appkey)
                .storagePath(storagePath)
                .environments(config.getEnvironments())  // dev, test, staging, prod
                .cdnDomain(config.getCdnDomain())
                .customDomains(config.getCustomDomains())
                .build();

        // 3. 注册到服务注册中心
        serviceRegistry.register(registration);

        // 4. 下发配置到网关
        configManager.publishConfig(appkey, registration);

        log.info("Frontend service registered: appkey={}, storage={}", appkey, storagePath);
    }

    /**
     * 服务发现：根据Appkey找到对应的资源存储位置
     */
    public ServiceRegistration discoverService(String appkey) {
        ServiceRegistration registration = serviceRegistry.get(appkey);
        if (registration == null) {
            throw new ServiceNotFoundException("Frontend service not found: " + appkey);
        }
        return registration;
    }

    /**
     * 解析请求到具体的资源路径
     * 网关层调用，将Appkey + 请求路径映射到对象存储路径
     */
    public ResourceLocation resolveResource(String appkey, String requestPath,
                                             String environment, String swimlane) {
        ServiceRegistration registration = discoverService(appkey);

        // 构建存储路径：{storagePath}/{environment}/{swimlane?}/{requestPath}
        StringBuilder path = new StringBuilder(registration.getStoragePath());
        path.append("/").append(environment);
        if (swimlane != null && !swimlane.isEmpty()) {
            path.append("/").append(swimlane);
        }
        path.append(requestPath);

        return ResourceLocation.builder()
                .appkey(appkey)
                .storagePath(path.toString())
                .cdnUrl(buildCdnUrl(registration, path.toString()))
                .build();
    }

    private String allocateStorage(String appkey) {
        // 将appkey转换为存储路径格式
        return appkey.replace(".", "/") + "/static";
    }
}
```

#### 3.1.2 七层网关集成

七层网关提供"关联前端Appkey"指令，让用户可以快速完成域名与前端服务的关联：

```java
/**
 * 七层网关"关联前端Appkey"指令处理
 * 将业务域名快速关联到前端服务
 */
public class AssociateAppkeyDirective implements GatewayDirective {

    private final FrontendServiceDiscovery discovery;

    /**
     * 执行指令：配置域名转发到前端网关
     */
    @Override
    public DirectiveResult execute(DirectiveContext context) {
        String domain = context.getDomain();
        String path = context.getPath();
        String appkey = context.getParameter("appkey");

        // 1. 验证Appkey是否已注册
        ServiceRegistration registration = discovery.discoverService(appkey);
        if (registration == null) {
            return DirectiveResult.fail("Appkey not registered: " + appkey);
        }

        // 2. 生成Nginx转发配置
        NginxConfig config = NginxConfig.builder()
                .location(path)
                .upstream(FRONTEND_PROXY_UPSTREAM)
                .header("X-Frontend-Appkey", appkey)
                .header("X-Frontend-Storage-Path", registration.getStoragePath())
                .build();

        // 3. 应用配置
        gatewayConfigManager.applyConfig(domain, config);

        return DirectiveResult.success("Appkey " + appkey + " associated with " + domain + path);
    }
}
```

#### 3.2.1 灰度策略模型

```java
/**
 * 灰度策略定义
 */
public class GrayscalePolicy {
    private String policyId;           // 策略唯一标识
    private String policyName;         // 策略名称（快速识别应用场景）
    private String appkey;             // 关联的前端Appkey
    private String path;               // 生效路径（策略只对该路径下的HTML生效）
    private String environment;        // 环境：test, prod
    private Date validFrom;            // 有效期开始
    private Date validTo;              // 有效期结束（到期自动失效）
    private GrayscaleCondition condition; // 灰度条件
    private String associatedBackend;  // 关联的后端灰度（SET或API网关）
    private int trafficPercentage;     // 灰度流量百分比
}

/**
 * 灰度条件类型
 */
public abstract class GrayscaleCondition {
    public abstract boolean match(HttpServletRequest request);

    // 组织架构灰度：根据用户所属组织判断
    // MIS号灰度：根据用户MIS号判断
    // 百分比灰度：根据哈希计算百分比
    // 自定义灰度：提取请求中的args/header/cookie字段进行匹配
}

/**
 * 组织架构灰度条件
 */
public class OrganizationCondition extends GrayscaleCondition {
    private List<String> organizationNodes; // 组织节点列表

    @Override
    public boolean match(HttpServletRequest request) {
        String mis = extractMis(request);
        if (mis == null) return false;

        UserInfo userInfo = userService.getUserInfo(mis);
        for (String node : organizationNodes) {
            if (userInfo.getOrganizationPath().contains(node)) {
                return true;
            }
        }
        return false;
    }
}

/**
 * MIS号灰度条件
 */
public class MisCondition extends GrayscaleCondition {
    private Set<String> misList;

    @Override
    public boolean match(HttpServletRequest request) {
        String mis = extractMis(request);
        return mis != null && misList.contains(mis);
    }
}

/**
 * 百分比灰度条件
 * 同一用户命中灰度后将持续命中，策略变更时重新计算
 */
public class PercentageCondition extends GrayscaleCondition {
    private int percentage; // 0-100

    @Override
    public boolean match(HttpServletRequest request) {
        String identifier = extractIdentifier(request);
        int hash = Math.abs(identifier.hashCode()) % 100;
        return hash < percentage;
    }
}

/**
 * 自定义灰度条件
 * 提取请求中args(query)、header、cookie中的字段进行匹配
 */
public class CustomCondition extends GrayscaleCondition {
    private String source;     // args, header, cookie
    private String field;      // 字段名
    private String operator;   // ==, !=, contains, in
    private String value;      // 比较值

    @Override
    public boolean match(HttpServletRequest request) {
        String actualValue = extractValue(request, source, field);
        if (actualValue == null) return false;

        return switch (operator) {
            case "==" -> actualValue.equals(value);
            case "!=" -> !actualValue.equals(value);
            case "contains" -> actualValue.contains(value);
            case "in" -> Arrays.asList(value.split(",")).contains(actualValue);
            default -> false;
        };
    }
}
```

#### 3.2.2 灰度分流执行

```java
/**
 * 灰度分流执行器
 * 在前端网关层执行灰度策略，返回对应的资源版本
 */
public class GrayscaleRouter {

    private final PolicyCache policyCache;
    private final FrontendServiceDiscovery discovery;

    /**
     * 执行灰度分流
     * @param request HTTP请求
     * @param appkey 前端Appkey
     * @return 资源定位信息（包含版本和路径）
     */
    public ResourceLocation route(HttpServletRequest request, String appkey) {
        // 1. 获取该Appkey的所有有效灰度策略
        List<GrayscalePolicy> policies = policyCache.getActivePolicies(appkey);

        // 2. 按优先级匹配灰度策略
        for (GrayscalePolicy policy : policies) {
            // 检查路径是否匹配
            if (!matchPath(request.getRequestURI(), policy.getPath())) {
                continue;
            }

            // 检查灰度条件是否匹配
            if (policy.getCondition().match(request)) {
                // 命中灰度，返回灰度版本资源
                return discovery.resolveResource(
                        appkey,
                        request.getRequestURI(),
                        "prod",
                        "grayscale/" + policy.getPolicyId()
                );
            }
        }

        // 3. 未命中灰度，返回主干版本
        return discovery.resolveResource(appkey, request.getRequestURI(), "prod", null);
    }
}
```

```java
/**
 * 前后端协同灰度
 * 基于统一的灰度策略ID，将前端灰度与后端灰度串联
 */
public class CollaborativeGrayscaleManager {

    /**
     * 关联前端灰度策略与后端SET
     * 一次策略配置即可完成前后端灰度串联
     */
    public void associateBackend(String policyId, String setId) {
        GrayscalePolicy policy = policyRepository.get(policyId);

        // 将灰度策略关联到后端SET
        policy.setAssociatedBackend(setId);
        policyRepository.update(policy);

        // 同步配置到后端SET路由
        setRouter.associatePolicy(setId, policyId);

        // 同步配置到前端网关
        gatewayConfigManager.updatePolicy(policy);

        log.info("Grayscale policy {} associated with backend SET {}",
                policyId, setId);
    }

    /**
     * 前后端灰度协同执行
     * 当用户请求命中前端灰度时，同时路由到对应的后端SET
     */
    public RouteDecision routeWithBackend(HttpServletRequest request, String appkey) {
        ResourceLocation frontendResource = grayscaleRouter.route(request, appkey);

        if (frontendResource.isGrayscale()) {
            String policyId = frontendResource.getGrayscalePolicyId();
            GrayscalePolicy policy = policyRepository.get(policyId);

            if (policy.getAssociatedBackend() != null) {
                // 同时路由到后端SET
                return RouteDecision.builder()
                        .frontendResource(frontendResource)
                        .backendSetId(policy.getAssociatedBackend())
                        .build();
            }
        }

        return RouteDecision.builder()
                .frontendResource(frontendResource)
                .build();
    }
}
```

```java
/**
 * 泳道管理器
 * 通过不同的流量分发实现测试环境隔离
 */
public class SwimlaneManager {

    private static final String SWIMLANE_PREFIX = "sl";
    private static final String SWIMLANE_DOMAIN_PATTERN = "http://%s-%s-%s/%s";

    /**
     * 解析泳道域名
     * 泳道域名格式：{swimlane}-{appkey}-sl-{businessDomain}/
     */
    public SwimlaneInfo parseSwimlane(String host) {
        // 从域名中提取泳道标识
        Pattern pattern = Pattern.compile("^(\\d+)-([^-]+)-" + SWIMLANE_PREFIX + "-(.+)$");
        Matcher matcher = pattern.matcher(host);

        if (matcher.matches()) {
            return SwimlaneInfo.builder()
                    .swimlaneId(matcher.group(1))
                    .appkey(matcher.group(2))
                    .businessDomain(matcher.group(3))
                    .build();
        }
        return null; // 非泳道请求
    }

    /**
     * 获取泳道资源路径
     * 在对象存储中为每个泳道分配独立的存储空间
     */
    public String getSwimlaneResourcePath(String appkey, String swimlaneId,
                                           String requestPath) {
        ServiceRegistration registration = discovery.discoverService(appkey);
        return registration.getStoragePath() + "/test/" + swimlaneId + requestPath;
    }

    /**
     * 部署资源到泳道环境
     * 通过CI/CD系统设置SWIMLANE环境变量实现
     */
    public void deployToSwimlane(String appkey, String swimlaneId,
                                  List<ResourceFile> files) {
        String basePath = getSwimlaneBasePath(appkey, swimlaneId);
        for (ResourceFile file : files) {
            String fullPath = basePath + "/" + file.getRelativePath();
            objectStorage.upload(fullPath, file.getContent());
        }
        log.info("Deployed {} files to swimlane {} for appkey {}",
                files.size(), swimlaneId, appkey);
    }
}
```

### 3.4 认证与鉴权

#### 3.4.1 配置化认证接入

```java
/**
 * 认证与鉴权管理器
 * 通过配置化方式简化登录认证接入流程
 * 支持SSO（企业员工）、Passport（C端用户）、Epassport（B端商家）三种身份体系
 */
public class AuthManager {

    private final Map<String, AuthProvider> providers;

    public AuthManager() {
        providers = new HashMap<>();
        providers.put("SSO", new SSOAuthProvider());
        providers.put("PASSPORT", new PassportAuthProvider());
        providers.put("EPASSPORT", new EpassportAuthProvider());
    }

    /**
     * 执行认证拦截
     * 在前端网关层作为"第一道入口"拦截未登录请求
     */
    public AuthResult authenticate(HttpServletRequest request, AuthConfig config) {
        AuthProvider provider = providers.get(config.getAuthType());
        if (provider == null) {
            return AuthResult.pass(); // 未配置认证，直接放行
        }

        // 1. 检查是否已登录
        AuthToken token = provider.extractToken(request);
        if (token == null) {
            // 未登录，返回登录跳转
            return AuthResult.redirect(provider.getLoginUrl(config));
        }

        // 2. 验证Token有效性
        UserInfo userInfo = provider.validateToken(token);
        if (userInfo == null) {
            // Token无效或过期，返回登录跳转
            return AuthResult.redirect(provider.getLoginUrl(config));
        }

        // 3. 执行鉴权（如果配置了UPM/UAC）
        if (config.getAuthzConfig() != null) {
            boolean authorized = checkAuthorization(userInfo, config.getAuthzConfig());
            if (!authorized) {
                return AuthResult.forbidden("Access denied");
            }
        }

        // 4. 注入用户信息到请求头
        return AuthResult.success(userInfo);
    }
}

/**
 * SSO认证提供者
 */
public class SSOAuthProvider implements AuthProvider {

    @Override
    public AuthToken extractToken(HttpServletRequest request) {
        // 从Cookie中提取SSO Token
        Cookie[] cookies = request.getCookies();
        if (cookies == null) return null;

        for (Cookie cookie : cookies) {
            if ("SSO_TOKEN".equals(cookie.getName())) {
                return new AuthToken(cookie.getValue());
            }
        }
        return null;
    }

    @Override
    public UserInfo validateToken(AuthToken token) {
        // 调用SSO服务验证Token
        return ssoService.validate(token.getValue());
    }

    @Override
    public String getLoginUrl(AuthConfig config) {
        // 构建SSO登录跳转URL
        return String.format("%s?service=%s",
                SSO_LOGIN_URL, URLEncoder.encode(config.getCallbackUrl(), UTF_8));
    }
}
```

#### 3.4.2 登录回调处理

```java
/**
 * 登录回调处理器
 * 处理登录完成后的回调，设置Cookie并重定向
 */
public class LoginCallbackHandler {

    /**
     * 处理SSO登录回调
     * 路径固定前缀 /api/carrier
     */
    public void handleCallback(HttpServletRequest request,
                                HttpServletResponse response,
                                AuthConfig config) {
        AuthProvider provider = providers.get(config.getAuthType());

        // 1. 获取回调中的Token
        String token = request.getParameter("token");
        if (token == null) {
            response.setStatus(400);
            return;
        }

        // 2. 验证Token并获取用户信息
        UserInfo userInfo = provider.validateToken(new AuthToken(token));
        if (userInfo == null) {
            response.setStatus(401);
            return;
        }

        // 3. 设置登录Cookie
        Cookie authCookie = new Cookie(config.getCookieName(), token);
        authCookie.setPath("/");
        authCookie.setHttpOnly(true);
        authCookie.setMaxAge(config.getCookieMaxAge());
        response.addCookie(authCookie);

        // 4. 重定向回原始页面
        String redirectUrl = request.getParameter("redirect");
        if (redirectUrl == null) {
            redirectUrl = "/";
        }
        response.sendRedirect(redirectUrl);
    }
}
```

```java
/**
 * 资源部署管理器
 * 与主流CI/CD系统集成，提供构建和部署组件
 */
public class DeploymentManager {

    private final ObjectStorage objectStorage;
    private final CacheManager cacheManager;

    /**
     * 部署资源到指定环境
     */
    public DeploymentResult deploy(DeploymentRequest request) {
        String appkey = request.getAppkey();
        String environment = request.getEnvironment(); // dev, test, staging, prod
        String swimlane = request.getSwimlane();
        String grayscalePolicyId = request.getGrayscalePolicyId();
        List<ResourceFile> files = request.getFiles();

        // 1. 确定存储路径
        String basePath = buildStoragePath(appkey, environment, swimlane, grayscalePolicyId);

        // 2. 上传资源到对象存储
        for (ResourceFile file : files) {
            String fullPath = basePath + "/" + file.getRelativePath();
            objectStorage.upload(fullPath, file.getContent(), file.getContentType());

            // 如果是HTML文件，更新缓存
            if (file.getRelativePath().endsWith(".html")) {
                cacheManager.updateHtmlCache(appkey, fullPath, file.getContent());
            }
        }

        // 3. 原子化部署：S3上传与缓存更新的原子化
        cacheManager.commitCacheUpdate(appkey);

        // 4. 记录部署版本（用于回滚）
        versionManager.createVersion(appkey, environment, basePath, files);

        // 5. 触发部署后回调
        eventDispatcher.dispatchDeployEvent(appkey, environment, files.size());

        return DeploymentResult.builder()
                .appkey(appkey)
                .environment(environment)
                .fileCount(files.size())
                .storagePath(basePath)
                .build();
    }

    /**
     * 回滚到指定版本
     * 执行回滚时不清空原有目录，而是直接上传文件并覆盖同名文件
     */
    public DeploymentResult rollback(String appkey, String environment, String versionId) {
        DeploymentVersion version = versionManager.getVersion(appkey, environment, versionId);
        if (version == null) {
            throw new VersionNotFoundException(versionId);
        }

        // 直接上传历史版本文件覆盖当前文件
        List<ResourceFile> files = version.getFiles();
        for (ResourceFile file : files) {
            String fullPath = version.getStoragePath() + "/" + file.getRelativePath();
            objectStorage.upload(fullPath, file.getContent(), file.getContentType());
            if (file.getRelativePath().endsWith(".html")) {
                cacheManager.updateHtmlCache(appkey, fullPath, file.getContent());
            }
        }
        cacheManager.commitCacheUpdate(appkey);

        return DeploymentResult.builder()
                .appkey(appkey)
                .environment(environment)
                .fileCount(files.size())
                .rolledBack(true)
                .build();
    }

    private String buildStoragePath(String appkey, String environment,
                                     String swimlane, String grayscalePolicyId) {
        StringBuilder path = new StringBuilder(appkey.replace(".", "/"));
        path.append("/").append(environment);
        if (swimlane != null) {
            path.append("/").append(swimlane);
        } else if (grayscalePolicyId != null) {
            path.append("/grayscale/").append(grayscalePolicyId);
        }
        return path.toString();
    }
}
```

### 3.6 多级缓存系统

```java
/**
 * 多级缓存管理器
 * HTML资源做两级缓存：机器内存缓存 + Redis缓存
 * 如果对象存储或Redis宕机，HTML页面依然可以正常访问
 */
public class MultiLevelCacheManager {

    private final Cache<String, String> memoryCache;  // L1: 机器内存
    private final RedisClient redisCache;              // L2: Redis
    private final ObjectStorage objectStorage;         // L3: 对象存储

    public MultiLevelCacheManager() {
        this.memoryCache = Caffeine.newBuilder()
                .maximumSize(10_000)
                .expireAfterWrite(5, TimeUnit.MINUTES)
                .recordStats()
                .build();
    }

    /**
     * 获取HTML资源（多级缓存穿透）
     */
    public String getHtmlResource(String appkey, String resourcePath) {
        String cacheKey = appkey + ":" + resourcePath;

        // L1: 内存缓存
        String content = memoryCache.getIfPresent(cacheKey);
        if (content != null) {
            return content;
        }

        // L2: Redis缓存
        try {
            content = redisCache.get(cacheKey);
            if (content != null) {
                memoryCache.put(cacheKey, content);
                return content;
            }
        } catch (Exception e) {
            log.warn("Redis cache access failed, falling through to S3", e);
        }

        // L3: 对象存储
        try {
            content = objectStorage.read(resourcePath);
            if (content != null) {
                // 回填缓存
                memoryCache.put(cacheKey, content);
                try {
                    redisCache.set(cacheKey, content, 300); // 5分钟过期
                } catch (Exception e) {
                    log.warn("Redis cache write failed", e);
                }
            }
            return content;
        } catch (Exception e) {
            log.error("Failed to fetch HTML from S3: {}", resourcePath, e);
            return null;
        }
    }

    /**
     * 更新HTML缓存（部署新版本时调用）
     */
    public void updateHtmlCache(String appkey, String resourcePath, String content) {
        String cacheKey = appkey + ":" + resourcePath;
        memoryCache.put(cacheKey, content);
        try {
            redisCache.set(cacheKey, content, 300);
        } catch (Exception e) {
            log.warn("Redis cache update failed", e);
        }
    }

    /**
     * 提交缓存更新（原子化部署）
     */
    public void commitCacheUpdate(String appkey) {
        // 确保所有缓存更新原子性生效
        memoryCache.cleanUp();
    }
}
```

### 5.1 HTTP 304支持

```java
/**
 * HTTP 304优化
 * 提高端到端缓存命中率，降低业务首屏时长
 */
public class Http304Handler {

    /**
     * 处理条件请求
     */
    public boolean handleConditionalRequest(HttpServletRequest request,
                                             HttpServletResponse response,
                                             String resourceContent) {
        String etag = generateEtag(resourceContent);
        String lastModified = getLastModified(resourceContent);

        // 检查If-None-Match
        String ifNoneMatch = request.getHeader("If-None-Match");
        if (etag.equals(ifNoneMatch)) {
            response.setStatus(304);
            response.setHeader("ETag", etag);
            return true; // 客户端缓存有效，不需要传输内容
        }

        // 检查If-Modified-Since
        String ifModifiedSince = request.getHeader("If-Modified-Since");
        if (lastModified.equals(ifModifiedSince)) {
            response.setStatus(304);
            response.setHeader("Last-Modified", lastModified);
            return true;
        }

        // 设置响应头
        response.setHeader("ETag", etag);
        response.setHeader("Last-Modified", lastModified);
        response.setHeader("Cache-Control", "max-age=300");
        return false;
    }

    private String generateEtag(String content) {
        return "\"" + DigestUtils.md5Hex(content) + "\"";
    }
}
```

## 六、最佳实践

### 6.1 部署最佳实践

1. **多环境管理**：利用CI/CD系统的多环境支持（dev, test, staging, prod），在测试环境充分验证后再部署到生产环境。

2. **泳道部署**：通过设置SWIMLANE环境变量将资源发布到泳道环境，通过`http://{swimlane}-{appkey}-sl-{businessDomain}/`进行访问。

3. **灰度部署**：先在小流量灰度环境验证新版本，确认无误后逐步扩大流量比例，最终全量发布。

4. **版本回滚**：回滚时不清空原有目录，而是直接上传文件覆盖同名文件，确保回滚快速且不影响其他版本。

5. **原子化部署**：S3上传与缓存更新原子化，部署过程中不会出现新旧版本混用的状态。

### 6.2 灰度最佳实践

1. **精细化策略配置**：利用组织架构、MIS号、百分比、自定义四种灰度条件，覆盖大部分灰度场景。

2. **策略有效期**：为灰度策略设置有效期，到期自动失效，避免遗忘导致灰度策略长期残留。

3. **前后端协同灰度**：基于统一灰度策略ID串联前后端灰度，一次配置即可完成前后端灰度，保证策略一致性和实时性。

4. **灰度监控**：查看灰度流量分钟级流量监控、Appkey+灰度版本级别的Web异常，快速发现灰度版本问题。

5. **阶梯灰度**：通过CI/CD系统支持阶梯灰度发布，按指定时间节奏和比例逐步放量生效。

### 6.3 稳定性最佳实践

1. **多级缓存**：HTML资源做两级缓存（内存+Redis），对象存储不可用时仍可正常访问。

2. **Nginx降级**：配置error_page降级，前端网关集群异常时直接访问对象存储获取HTML。

3. **集群隔离**：为大流量业务提供独立集群（如金融、优选），避免业务间互相影响。

4. **多机房容灾**：每个集群保证多机房均衡分布，单机房故障不影响整体服务。

5. **QPS限制**：每个前端Appkey默认1000 QPS限制，防止异常流量冲击。

6. **监控告警**：默认提供HTML请求一分钟达到两个错误数的监控告警，请求成功率、调用延迟等指标超过阈值自动告警。

### 6.4 认证鉴权最佳实践

1. **配置化接入**：通过控制台配置即可完成SSO/Passport/Epassport登录认证接入，无需前后端分别开发。

2. **统一日志监控**：接入认证后生成统一的日志与监控指标，多个服务使用统一标准。

3. **登录逻辑下沉**：登录逻辑下沉到托管服务网关层，不侵入业务代码，架构更优雅。

4. **域名配置**：配置固定前缀`/api/carrier`的路径映射用于登录回调，推荐只配置一次。

### 6.5 CDN最佳实践

1. **静态资源CDN加速**：JS、CSS、图片等资源通过CDN访问，利用全球边缘节点加速。

2. **缓存策略分级**：HTML短缓存（支持灰度切换），JS/CSS长缓存（文件名含hash）。

3. **CDN预热**：部署后主动推送到CDN节点，减少首次访问延迟。

4. **全站CDN托管**：支持整站CDN托管能力，包括CDN灰度访问能力。

5. **HTTP 304**：网关支持HTTP 304，提高端到端缓存命中率，降低首屏时长。
